## Goal
A closed single `select` opens a list the engine paints, in every document and through every renderer that paints with blitz-paint. Its rows are the select's own `option` elements, so each keeps its stable id open and closed. A person or an agent chooses one by pointer and by key through the one write path `apply_select_choice`, closes the list with no choice, and the select then reads the choice (per architecture §Established Decisions → Scrolling and input; `v030-17`).

The list is an engine overlay on the shape of the overlay scrollbar: one geometry that paint, hit and the snapshot all read, painted last in `paint_scene`, above the page and past any clip, and hit first in `hit_with_scrollbar`. Its state is one field of `BaseDocument`, naming DOM nodes only. It lays out nothing, so both layout modes read one layout. No verb, node key, cause, session error, exit status, carrier, listener, port, env var, crate or dependency is added.

- **A second OS window or a list in `blitz-shell` or `dioxus-native`.** Rejected: it splits the one engine model (architecture §Design Philosophy → Radically modular).

## Implementation notes
