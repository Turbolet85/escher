## Overview
<!-- GENERATED:setup:overview start -->
escher is a fork of Blitz being turned into an agent-first UI framework — a headless driver (CLI + MCP), stable ids for every element, a compact semantic snapshot of the screen, proven on an internal 7GUIs stand. Development Style is agent-driven: the framework's own driver is meant to become the harness.

**Stack:** Rust 2024 Cargo workspace (MSRV 1.91) · Stylo CSS · Taffy layout · Parley text · anyrender/Vello paint · winit shell · AccessKit · Dioxus 0.7 · Boa JS — a native-API engine library with no server and no database (the browser app keeps a rusqlite history).

**Key directories:**
- `packages/` — the engine and integration crates (DOM, paint, shell, traits, Dioxus bridge, test harness) and escher's own crates: the telemetry bootstrap and the driver's session, command schema, command line and MCP server
- `tests/blitz-tests/` — integration tests, one file and one test target per behaviour (upstream's `tests/all.rs` is declared and never built); the stand checks share `tests/common/`, the checks that hold a session `tests/session_common/` and the checks on fixture pages `tests/fixtures/` (the fixture boot and hold, the shared pages, the held network stand-in `HeldNet`), and `checks/` holds the two committed kept checks `stand_replay` replays (data, no target)
- `examples/` — example crates and root examples; `examples/seven_guis/` is the 7GUIs stand
- `apps/` — reference browser (`blitz`), markdown viewer (`rdme`)
- `wpt/runner/` — the Web Platform Tests conformance runner
- `scripts/` — the agent-run test contract, the cold-agent run pipe, the code-graph tooling

## Architecture
<!-- GENERATED:setup:architecture start -->
Blitz is a radically modular, embeddable web engine: a headless DOM (`BaseDocument` in blitz-dom) that external code drives and any renderer paints, with parsing, networking, painting and windowing in separate crates. Embedder services — net, navigation, shell, HTML parsing — reach the DOM only through provider traits in `DocumentConfig`, defaulting to `Dummy*` no-ops; web behaviour is written against named specs and named engines. Style, damage, box construction, layout and paint topology run one incremental pipeline over versioned node ids.

The engine is already exercised headlessly — `blitz-test-harness` synthesizes input through the real event-dispatch pipeline with no window or GPU, and the WPT runner renders to CPU buffers; the seven_guis stand boots through it (`seven_guis::stand`) at a pinned viewport with its bundled font, every boot offline but the load page's, whose one stylesheet fetch the in-process stand-in `LoadNet` answers. escher builds on that: stable element ids (built — `DioxusDocument::element_id(s)`, the author's HTML `id`, else a path anchored at the nearest keyed element of the same component, else the element's component path; proven the same across a re-render, a remount, a fresh process and edits of the code around an element; every element an agent can act on is keyed, checked by `DioxusDocument::unkeyed_actionable`; and the id is carried on every element's accessibility node as AccessKit `author_id`), a semantic snapshot (its data model built — `DioxusDocument::snapshot`, every element the accessibility tree keeps as a node of id · role · name · state · bounds, each field from a reader the engine already had; its state proven per control through real input — enabled, checked, value and focused — with a password's or a file input's value read as the fixed mask `MASKED_VALUE`, and selected, pressed and invalid read from what the app states in its markup: the engine's builder writes them on the accessibility node from `aria-selected` · `aria-pressed` (or `aria-checked` on a checkable role, ratified by the founder, 2026-10-18) · `aria-invalid`, a third direct engine change for every document, ratified by the founder (2026-10-10), and the stand's flight booker and CRUD state invalid and selected — the stand states no `aria-pressed`, the flight booker's mode a `select#flight-type` whose options state its choice, and `accessibility_states` pins the pressed reading on a fixture; its text form built — `Snapshot::to_text`, one line per node nested by indent, every lean stand screen under the 10,000-byte `SNAPSHOT_TEXT_BUDGET` (the Cells screen the stand serves beside them passing it), returned to its caller in process and, through the command line, in a hosted `snapshot`'s answer, and a screen over the budget read in parts — `Snapshot::text_parts`, consecutive pre-order lines never split, the driver's `snapshot` taking an optional `part` (a whole number, 1 to `MAX_PART` = 1000) and answering one part's text with the closed counts `part` and `parts`, part 1 by default, a part past the last the empty text, a screen within the budget answering whole as before, proven on an over-budget fixture page in both layout modes, in process and through `serve_mcp` (a ratified boundary widening); its diff built — `Snapshot::diff`, a comparison of the snapshots taken before and after a step that names exactly the nodes added, removed or changed, by stable element id, and is empty for a step that changes nothing, proven on the stand in both layout modes — beside an engine change flag that now tells the truth, `has_changes` reading true from a tracked write until `take_changed_nodes` drains it; the driver's acting verbs return that diff), a driver session (built — `escher_driver::Session` holds one headless instance across commands, one process hosts it until it is stopped or has answered no request for its 30-minute idle expiry, and `start` · `attach` · `stop` · `call` drive it over a local socket that carries its lifecycle and its calls; the stand hosts its own through the `escher-session` binary; since 2026-10-19-session-recording a session whose launcher names a recording directory (`--record`, `Session::recording_into`) keeps its answered calls as one owner-only replayable check — the calls as they crossed, a masked `type` as one fixed stand-in, each answer a 64-bit digest and kept whole — masked as on every carrier, a shot's without its pixels, so the screens' ids, names, values, snapshot text, diffs and a lint's findings at rest — read back strictly by `Check::from_bytes` and replayed through `Session::run` alone by `Check::replay`, which stops at the first step whose acceptance or kept answer differs, ratified by the founder (2026-10-19); the repository's own two scripted Counter checks committed under `tests/blitz-tests/checks/`, the one exception to owner-only, replayed by `stand_replay` and kept fresh by seven_guis `recording`), settle detection (built — `Harness::settle` runs every pass that is due and returns `Settled`, or `NotSettled` naming the busy class: render and layout driven to quiet, a load in flight reported at once and never waited on, a timer or an animation neither waited on nor advanced; `Session::act` runs one step on the held instance and returns once it has settled, a load in flight waited for up to `LOAD_WAIT` (5 s of wall time, settled again every 10 ms, no time moving on the held instance) and one still loading at the bound `NotSettled(Loads)`; proven on the stand's Timer and on minimal fixtures in both layout modes, and every acting driver verb returns only once the instance has settled), the driver's command and refusal schema (built — one verb table of twelve verbs in three levels, `snapshot` · `click` · `type` · `press` · `advance` · `scroll` · `screenshot` · `lint` asked of the held instance, `start` · `status` · `stop` of the session and `help` of the tool itself, each with its argument and result shapes, a validation that turns a call into a typed command or a refusal before anything runs, and eight refusal causes each with a fixed remedy, all eight returned today (ratified by the founder, 2026-10-18); time on a held instance moves by `advance`, in milliseconds, and an acting driver command waits on a load in flight for at most `LOAD_WAIT` (5 s of wall time), `snapshot`, `screenshot` and `lint` waiting on none), act by id (built — `Session::run` runs a call on the held instance: `click`, `type` and `scroll` name their target by the stable id a snapshot lists, `type` replaces what its control holds (on a select it chooses the first option whose label starts with the text), `press` acts on what holds focus, `advance` moves the session's clock — the harness's `VirtualClock` every harness-built document reads — by exactly `ms` on every session and the app's own time through the step the session's caller supplies where there is one (ratified by the founder, 2026-10-18), and each returns once the instance has settled, with the diff of the screen before and after; proven on the four lean stand tasks in both layout modes — the Timer's range input moved by `click` and the arrow, `Home` and `End` keys since the range interaction model, a direct engine change for every document ratified by the founder (2026-10-13), the diff naming the slider's `value` and its display's `name`, and, since the keyboard harness, `press enter` and `press space` on a Tab-focused button each counting as its click — keyboard activation, a direct engine change for every document ratified by the founder (2026-10-13)), refusal detection (built — an id the screen does not read is refused `stale` when an earlier screen of the session read it and `not-found` when none did, and a `click` or a `type` on a target that reads not enabled, lies out of view or is covered by another element is refused `disabled`, `off-screen` or `covered`, in that order, with nothing run and the instance unchanged; `scroll` brings its target into view through every scrolling box that holds it — the engine's `scroll_into_view`, widened for every document on the founder's ratification — and says in its result whether it then is; proven on the stand and on minimal fixtures beside it, in both layout modes), driver command spans (built — every call handed to `Session::run` leaves one `tracing` span holding fixed words and counts only: its verb, a refused call's cause, an acting call's settle reading and the lengths of its diff; escher's sink prints it as one line per closed span, a record class ratified by the founder (2026-10-09), who ruled with it that a diff's content never reaches a log while its three sizes may; proven on the stand in both layout modes, with no id, name or typed text in the capture), the driver's command line (built — every driver command as one run of a binary that boots apps: `escher_driver::command_line`, a closed argv reader over the one verb table, a call checked before any session is touched, one uncoloured line of JSON on stdout and exit `0` accepted · `1` refused · `2` usage · `3` session error, nothing the caller typed written back;
