## Overview
<!-- GENERATED:setup:overview start -->
escher is a fork of Blitz being turned into an agent-first UI framework — a headless driver (CLI + MCP), stable ids for every element, a compact semantic snapshot of the screen, proven on an internal 7GUIs stand. Development Style is agent-driven: the framework's own driver is meant to become the harness.

**Stack:** Rust 2024 Cargo workspace (MSRV 1.91) · Stylo CSS · Taffy layout · Parley text · anyrender/Vello paint · winit shell · AccessKit · Dioxus 0.7 · Boa JS — a native-API engine library with no server and no database (the browser app keeps a rusqlite history).

**Key directories:**
- `packages/` — the engine and integration crates (DOM, paint, shell, traits, Dioxus bridge, test harness) and escher's own crates: the telemetry bootstrap and the driver's session, command schema, command line and MCP server
- `tests/blitz-tests/` — integration tests, one file and one test target per behaviour (upstream's `tests/all.rs` is declared and never built); the stand checks share `tests/common/`, the checks that hold a session `tests/session_common/` and the checks on fixture pages `tests/fixtures/` (the fixture boot and hold, the shared pages, the held network stand-in `HeldNet`), and `checks/` holds the two committed kept checks `stand_replay` replays (data, no target)
- `examples/` — example crates and root examples; `examples/seven_guis/` is the 7GUIs stand
- `apps/` — reference browser (`blitz`), markdown viewer (`rdme`)
- `wpt/runner/` — the Web Platform Tests conformance runner
- `scripts/` — the agent-run test contract, the cold-agent run pipe, the code-graph tooling

- `cargo build --workspace` — build every crate (Linux needs `libfontconfig1-dev`; Arch: `fontconfig`)
- `bash .github/scripts/ci-leg.sh fast` — the local pre-push gate: fmt → clippy → workspace tests → CI scripts → `embolden` (the `blitz-paint/font-embolden` witness, a leg with no CI job of its own), as CI runs them

- `bash .github/scripts/ci-leg.sh {leg}` — one CI leg exactly (`fmt` · `clippy` · `test` · `build` · `doc` · `audit` · `a11y` · `coverage` · `stand-repeat` — the stand checks, seventeen named blitz-tests targets outside the `stand_` prefix and seven_guis' process checks three rounds under a zero-failure budget, not a fast leg · …); log in `target/ci-logs/{leg}.log`; the mutation tier is no leg — run on the dev host alone, never in CI: cargo-mutants `--test-tool nextest --baseline=skip` under `NEXTEST_PROFILE=mutants` (the root `.config/nextest.toml`'s `mutants` profile), each unit's mutant test command first read green on the unmutated tree (`.andromeda/test-plan.md` §10)
- `just seven_guis` — run the 7GUIs stand natively (windowed)
- `target/debug/escher-session {verb} … --session {dir}` — the driver's command line (`cargo build -p seven_guis --bin escher-session` first): `start {task} [--record {dir}]` (a recording directory keeping the session as one owner-only replayable check), then `snapshot [--part]` · `click --id` · `type --id --text` · `press --key` · `advance --ms` · `scroll --id` · `screenshot [--id]` · `lint` · `graph` · `actions` · `status` · `stop`, and `help` (the tool's self-description, its `--session` optional and unread, reaching no session); one line of JSON on stdout, exit `0` · `1` · `2` · `3`; `target/debug/escher-session coverage {app} {check}...` (no `--session`, no `--record`) replays each named kept check on a fresh session and prints the coverage line `{"unexercised":[…],"checks":n,"held":m}`, the handlers no check exercised
- `target/debug/escher-session mcp [--record {dir}]` — the same binary as an MCP server over stdio (an MCP client spawns it; server name `escher`, its tools the fourteen verbs, `graph` after `lint`, `actions` after `graph`, `help` last)

## Architecture
<!-- GENERATED:setup:architecture start -->
Blitz is a radically modular, embeddable web engine: a headless DOM (`BaseDocument` in blitz-dom) that external code drives and any renderer paints, with parsing, networking, painting and windowing in separate crates. Embedder services — net, navigation, shell, HTML parsing — reach the DOM only through provider traits in `DocumentConfig`, defaulting to `Dummy*` no-ops; web behaviour is written against named specs and named engines. Style, damage, box construction, layout and paint topology run one incremental pipeline over versioned node ids.

The engine is already exercised headlessly — `blitz-test-harness` synthesizes input through the real event-dispatch pipeline with no window or GPU, and the WPT runner renders to CPU buffers; the seven_guis stand boots through it (`seven_guis::stand`) at a pinned viewport with its bundled font, every boot offline but the load page's, whose one stylesheet fetch the in-process stand-in `LoadNet` answers. escher builds on that: stable element ids (built — `DioxusDocument::element_id(s)`, the author's HTML `id`, else a path anchored at the nearest keyed element of the same component, else the element's component path; proven the same across a re-render, a remount, a fresh process and edits of the code around an element; every element an agent can act on is keyed, checked by `DioxusDocument::unkeyed_actionable`; and the id is carried on every element's accessibility node as AccessKit `author_id`), a semantic snapshot (its data model built — `DioxusDocument::snapshot`, every element the accessibility tree keeps as a node of id · role · name · state · bounds, each field from a reader the engine already had; its state proven per control through real input — enabled, checked, value and focused — with a password's or a file input's value read as the fixed mask `MASKED_VALUE`, and selected, pressed and invalid read from what the app states in its markup: the engine's builder writes them on the accessibility node from `aria-selected` · `aria-pressed` (or `aria-checked` on a checkable role, ratified by the founder, 2026-10-18) · `aria-invalid`, a third direct engine change for every document, ratified by the founder (2026-10-10), and the stand's flight booker and CRUD state invalid and selected — the stand states no `aria-pressed`, the flight booker's mode a `select#flight-type` whose options state its choice, and `accessibility_states` pins the pressed reading on a fixture; its text form built — `Snapshot::to_text`, one line per node nested by indent, every lean stand screen under the 10,000-byte `SNAPSHOT_TEXT_BUDGET` (the Cells screen the stand serves beside them passing it), returned to its caller in process and, through the command line, in a hosted `snapshot`'s answer, and a screen over the budget read in parts — `Snapshot::text_parts`, consecutive pre-order lines never split, the driver's `snapshot` taking an optional `part` (a whole number, 1 to `MAX_PART` = 1000) and answering one part's text with the closed counts `part` and `parts`, part 1 by default, a part past the last the empty text, a screen within the budget answering whole as before, proven on an over-budget fixture page in both layout modes, in process and through `serve_mcp` (a ratified boundary widening); - 2026-10-05: This checkout carries an `upstream` remote (DioxusLabs/blitz) and no `gh repo set-default`, so a bare `gh run` / `gh cache` / `gh api` call reads upstream — pass `-R Turbolet85/escher` on every read of the fork. (confidence 0.8)
