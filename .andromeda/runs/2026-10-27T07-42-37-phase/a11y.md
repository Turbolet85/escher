## Constraints
- The a11y target is tier 0, SC 2.1.1 · 1.4.3 · 2.4.3. Whatever the founder's delegate takes must leave each of the three re-proven by its standing witness, and must not merely compile (per a11y-plan §1 A11y Scope Summary).
- a11y-plan §2 A11y Strategy (Accessibility tree lifecycle) requires the tree to be built and refreshed through the `Document::accessibility_tree` trait method, so that DioxusDocument's stable-id override reaches it, and requires the refresh to fire on a poll that takes a non-empty changed set. `6587e7e79` reroutes the shell's redraw requests through the event loop, and `7fc9ee3af` edits `dioxus_document.rs`. Whether either resolution bypasses the override or the poll's drain-then-rebuild is research's question.
- a11y-plan §2 A11y Strategy (Accessibility tree lifecycle) also requires the changed set's contract to hold. Mutations, focus or checked changes, text input and a select's changed choice mark it. Creation, hover, active, scroll and layout do not. `mutator.rs` is a predicted conflict file (`53e9d81c6`, `ebacd68bd`), so the resolution keeps this contract.
- a11y-plan §5 Keyboard Navigation (Focus order per layout) requires the focusability rule to stand. That means no element that is inert or under `inert`, no disabled form control, and `disabled` read only by its presence on `button` · `input` · `select` · `textarea`. a11y-plan §5 Keyboard Navigation (Keyboard handling) requires Enter or Space on a focused `summary`, and on the other listed controls, to dispatch a Click. `53e9d81c6` adds `:open` state for `<details>` in `node/element.rs` and `stylo.rs`. Whether it changes how a `summary` toggles under keyboard activation is research's question.
- a11y-plan §6 Visual Design Verification (Visibility and hit-testing) requires a hit to answer nothing at an element carrying `inert`, before any other test, and requires a node dropped since the last resolve to be skipped. It also requires elements with `visibility: hidden`/`collapse` never to be hit targets, and requires `pointer-events: none` to pass hits through to descendants. `ebacd68bd` (a hit on an element with no computed styles yet) and `0980cce5f` both edit `node/node.rs`'s hit path. Whether upstream's new early exit lands ahead of the `inert` test is research's question.
- a11y-plan §7 Screen Reader Support (Input method (IME); detail `sr-ime` in `.andromeda/a11y-plan-detail/screen-reader-support.md`) records the expected behaviour for a text input. Focusing it enables IME and sets the cursor area to its content box, and blurring it disables IME. `7fc9ee3af` also enables IME when a focused text input is constructed, and `a09f46792` touches `node/text.rs`, where commit, preedit and disable are applied. That behaviour must survive the resolution.
- a11y-plan §6 Visual Design Verification (Color contrast) requires `stand_contrast` to assert all three tables row for row in both layout modes, with a row exempt only where the snapshot's `enabled` reads `Some(false)`. A Taffy or winit move can shift layout and hover or active state. A moved row is re-measured and recorded, never loosened.

## Patterns to follow
- The last sync's re-read pattern, per a11y-plan §9 CI Integration. Run `stand_keyboard`, `stand_contrast` and `stand_accessibility_ids` green in the leg, per package and in each `stand-repeat` round. Leave `tab_order`, `ENABLED_TAB_ORDER`, `controls`, `TEXT_ROWS` and `STATE_ROWS` unedited, re-baseline nothing, and name each engine change with its witness, by test function (precedent `escher-0.2.0/chunks/2026-10-24-a11y-re-read/evidence/re-read.md`).
- Tree checks are Rust tests in blitz-tests. Each calls `build_accessibility_tree()` after `resolve` and reads the tree's nodes. Upstream's tree tests become their own targets and join the leg only by a recorded decision, as `accessibility_label` and `accessibility_description` did at the 2026-10-17 sync (per a11y-plan §3 A11y Assertion Harness Contract).
- Keyboard checks drive the harness's `press` / `press_with` headlessly and read the focused node back at every step. The engine's focus, the snapshot's `focused` and the tree's focus must agree (per a11y-plan §3 A11y Assertion Harness Contract (Keyboard test harness), a11y-plan §5 Keyboard Navigation (Test harness pattern)).
