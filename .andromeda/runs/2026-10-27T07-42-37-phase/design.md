## Constraints
- design-system §Depth Strategy → Engine depth behavior requires a hit test to stop at the padding box of a node that paint clips, whether by `overflow` or by a computed `contain` that includes `paint`. The root element is the exception, and the node itself is still answered inside its border box. Its detail also requires the hit walk to skip a node dropped since the last resolve. `ebacd68bd` (hit testing an element with no computed styles yet) and `0980cce5f` both edit `node/node.rs`'s hit path, so every conflict resolution has to keep these stops. Whether upstream's new code already reaches the same answers is research's question (per design-system §Depth Strategy → Engine depth behavior).
- design-system §Motion → This project's values requires a programmatic into-view scroll never to animate a nested scrolling box: every box that holds the target is written at once, innermost first, and only the viewport takes the requested behaviour (`Smooth` included). The driver's `scroll` is instant everywhere. Its detail records that smooth scrolls run 300 ms on a cubic ease-in-out and that a wheel event cancels one. `0980cce5f` rewrites `scrolling.rs` through Taffy's `ScrollableOverflow` with reversed scroll origins, and this behaviour has to survive that rewrite. Whether the rewrite moves the timing or the into-view order is research's question (per design-system §Motion → This project's values).
- design-system §Motion → Animation runtime requires a harness settle to answer every member of the animating set the same way: it returns `Settled`, waits on none and advances none. Animation time is read only through the harness's `VirtualClock`, and only `advance` moves that clock. The driver's load wait moves no clock. The overlay scrollbar fade (`FADE_DELAY` 500 ms then `FADE_DURATION` 200 ms, read off the document's clock) is a member of that set. A take that touches `scrolling.rs`, `document.rs` or the scrollbar code has to keep those reads on the document's clock (per design-system §Motion → Animation runtime).
- design-system §Iconography → Cursors and favicons (engine) requires this cursor order: the CSS `cursor` keyword first, then Text for text inputs, Pointer inside links, Text over selectable text, and Default otherwise, including a pointer over no box. This is upstream's #1220, ratified by the founder. `0980cce5f` reaches `events/pointer.rs` and `document.rs`, where the rule lives, and `a09f46792` / `527394724` reach blitz-shell's winit cursor and event conversion. The rule must read the same after the take (per design-system §Iconography → Cursors and favicons (engine)).
- design-system §Typography → Loading requires blitz-dom to be built with `system-fonts` for the blitz-tests crate, because without it text measures 0×0 and font-dependent assertions pass vacuously. Upstream's targets that the take carries (`pseudo_element_flow_classification.rs` with `2963b65a2`, `clipboard.rs` with `527394724`) must run under it. The same section requires a driver `screenshot` of an app with no `sans-serif` family to be refused `fonts-unavailable` with nothing painted (per design-system §Typography → Loading).
- design-system §Color Palette → Engine-painted defaults (detail: Core Colors, Border Progression) and §Surface: desktop-native → Tokens (platform-specific) record the user-agent sheet's values, which reach every document through `DocumentConfig::default()`. These are the `a[href]` link colour, the input focus outline `#4D90FE`, the button background `#EFEFEF`, the scrollbar thumb palettes by scheme, and the `select` box defaults with its chosen-option-alone rule. If `53e9d81c6` (`<details>` `:open`) or another take edits `default.css` or the form-control paint, the moved value is recorded, not silently absorbed. Whether any taken commit edits `default.css` is research's question (per design-system §Color Palette → Engine-painted defaults).
- design-system §Surface: cli → Component Patterns requires `escher-session` and its `mcp` role to write only JSON on stdout, with no colour dependency, no ESC byte and no terminal test. A take that adds upstream crates or `tracing` sites (the clipboard `tracing::error!` with `527394724`) must leave that stdout unchanged (per design-system §Surface: cli → Component Patterns).

## Patterns to follow
- The design-system detail records each engine value with its `file:line` citation and its "as measured at" chunk. Where the take moves a cited body, for example `node/node.rs:1534-1567` (the hit stop), `scrolling.rs:655-734` (into-view), `document.rs:2390-2450` (cursor) or `scrolling.rs:112-122` (smooth timing), the moved citation is a reading for the wrap's re-point, and the value is never restated from memory (per design-system §Depth Strategy → Engine depth behavior; §Motion → This project's values; §Iconography → Cursors and favicons (engine)).
- The stand's colours, shadows and radius live in layout-templates §Surface: desktop-native → Primary screens, not in design-system. A stand pixel, contrast or bounds reading moved by a Taffy, Stylo or winit take is re-measured against those rows and `stand_contrast`, never loosened (per design-system §Color Palette → Core Colors, the "seven_guis stand" row).
- The disclosure list markers (`disclosure-open` ▾, `disclosure-closed` ▸) are the engine's recorded text mapping for `<details>`. Upstream's `:open` pseudo-class (`53e9d81c6`) is read against them, so that `:open` styling and the marker choice agree (per design-system §Typography → Engine text mapping).
- A hit answer is measured at an element's own box in both layout modes: an `img`, an `iframe`'s sub-document answered as the `iframe`, a filled text `input`, and a transformed-and-scrolled box hit where its rows show. `hit_clipped_at_scrolling_box` pins these, and a hit-path conflict is resolved against that check (per design-system §Depth Strategy → Engine depth behavior).

## Anti-patterns to avoid
- Never let a merged scroll path animate a nested scrolling box or make the driver's `scroll` non-instant (per design-system §Motion → This project's values).
- Never let a take reintroduce a wall-clock time read into the fade, smooth-scroll, fling or double-click timing that the virtual clock drives (per design-system §Motion → Animation runtime).
- Never paint a shot with its text skipped. An app whose font context resolves no `sans-serif` family stays refused before anything is painted (per design-system §Typography → Loading).

- Hit, scroll and into-view behaviour ↔ architecture §Standard Contracts → Scrolling, selection, tree, together with the residual line 36 merge-surface rows (hit stops, scrolled-box bounds, the clock), which this chunk re-reads.
- Motion's virtual clock ↔ architecture's document clock invariant (no `Instant::now()` / `SystemTime::now()` in blitz-dom outside `clock.rs`), re-read on the take's tree.
- Reduced motion ↔ a11y-plan (SC 2.3.3): design-system §Motion → Reduced motion records it as observed absent. That is a recorded absence, and this chunk neither adds nor claims it.
- Typography's headless font ↔ architecture §Standard Contracts → Headless stand (`font_ctx()`, the bundled font), which a pixel or text-extent reading moved by the take depends on.
