## Relevance
relevant — the take carries upstream code and test files into the engine every stand check, leg and tally reads; the chunk builds no new test surface of its own beyond carrying upstream's.

## Constraints
- Every blitz-tests file stays its own auto-discovered target: an upstream test file the take carries (`pseudo_element_flow_classification.rs` with `2963b65a2`, `clipboard.rs` with `527394724`) lands as one target with no manifest line, upstream's `tests/all.rs` takes its `mod` line and stays declared at `test = false`, unbuilt, and `[package]` sets no `autotests` (per test-plan §2 Directory pattern; per test-plan §4 blitz-tests targets — `BlitzTestsTargetsTest`). Whether each file `0980cce5f` edits (`inline_box_scrollable_overflow.rs`, `display_contents.rs`, `pre_overflow_scroll.rs`) is a standing target on our branch is research's question.
- Incremental and non-incremental layout stay identical after the take: the differential oracle compares every node's `final_layout()`, `layout_children` and paint tree per step and asserts no damage remains, and the pipeline checks run in both layout modes (per test-plan §2 Differential oracle).
- The stand checks keep a zero-failure budget: the `stand-repeat` leg runs the `stand_*.rs` files, its ten named blitz-tests targets and seven_guis' process checks three rounds with no retry, no `--ignored` and no env var, the first red ending the leg (per test-plan §10 Flakiness budget; per test-plan §9 Legs).
- The headless-stand checks assert unconditionally under the bundled DejaVu Sans with system fonts off — no skip path — so a layout, style or text number a moved Taffy, Stylo or winit shifts is re-measured and recorded, never skipped (per test-plan §2 Font-dependent tests); a shot is compared byte for byte on one host only, its PNG bytes differing between OSes (per test-plan §2 Pixel tests).
- A green per-package run is not the workspace leg's green: `--workspace` and `-p blitz-tests` build the same test file against different engine features (`tracing`, `writing-mode` on in the workspace build only), so a sink capture counts lines by target, never in total, and each body of the engine's bounds reader holds a check (per test-plan §9 Engine features by runner).
- The coverage leg's three per-crate floors stand (`packages/escher-driver` 97 %, `packages/dioxus-native-dom` 83 %, `packages/blitz-test-harness` 90 %), and both `cargo llvm-cov` lines' `keyboard_compat.rs` exclusion lifts only when escher takes upstream's retirement of that file (`286874cc1`) — a take of it drops the two `--ignore-filename-regex` lines and is re-read against the floors, any other take leaves them (per test-plan §10 Coverage floors; per test-plan §9 Coverage).
- The per-OS tallies are re-read from the take's own green CI run's test-bearing job logs — linux above macOS by the doc-test result lines, macOS above windows by the unix-gated binaries, ios and android build only — and each moved count is explained (per test-plan §9 Per-OS test tallies).

## Patterns to follow
- Earlier upstream takes recorded each carried test file as "its own auto-discovered target with no manifest line, upstream's `all.rs` gaining its `mod` line and staying unbuilt", with the before/after `.rs`-file and target counts (147 files, 146 targets at the last reading) and 0 `Running tests/all.rs` lines in the run (per test-plan §2 Directory pattern).
- The agent-run contract is the local driver for blitz-tests: `bash scripts/agent-run.sh boot`, then `run stand` and `run all`, its `run.end` passed · failed · ignored re-counted against the last reading with `scripts/agent-run.sh` unchanged — upstream's new files picked up by `run all` with no script change, a file with no `stand_` prefix absent from `run stand` (per test-plan §3 Agent-run contract).
- Upstream's script tests build a `ScriptDocument` from inline HTML and assert DOM text by selector; `cee6b8731` and `efdc5472a` extend blitz-vibey-script's `tests/dom.rs` in that style and run as they arrive (per test-plan §2 Script tests; per test-plan §5 Script ↔ DOM).
- The sink checks stay the re-read's standing witness: `host_log` and `mcp_log` drive the real `escher-session` binary at `RUST_LOG=trace` and read 0 id, 0 name and 0 typed-sentinel needles on stderr under the `-p seven_guis` and the workspace build (per test-plan §5 Session host ↔ what it writes; per test-plan §3 Stand log format).

## Anti-patterns to avoid
- Loosening a stand check's exact bound, snapshot byte size or pixel expectation so a moved Taffy, Stylo or winit number passes — the number is re-measured and recorded, and a check compared across OSes holds no shot (per test-plan §2 Pixel tests; per test-plan §2 Font-dependent tests).
- Reading a gate's verdict through a pipe or retrying a red stand round: the `stand-repeat` leg takes no retry and the first red ends it (per test-plan §10 Flakiness budget).
- Building upstream's `all` target or setting `autotests = false` to take upstream's manifest shape — the fork's two-line difference is pinned (per test-plan §4 blitz-tests targets).
