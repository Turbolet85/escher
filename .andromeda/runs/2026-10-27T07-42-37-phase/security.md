## Constraints
- The root manifest must hold no git dependency, and each upstream sync either takes upstream's dependency set whole or, by cherry-pick, enters no package, its `Cargo.lock` read name by name against upstream's or against the tree before it (per security-plan §Dependency Security → Pinning). A take that brings in git Taffy `c2560562…`, git Stylo `d6502e00…` or Dioxus `0.8.0-alpha.3` reverses that recorded state. It is the founder's fork, answered PROVISIONAL by his delegate, and the plan's Pinning line moves at the wrap.
- The audit (`bash .github/scripts/ci-leg.sh audit`, cargo-deny over the whole workspace's graph, advisories and licences) must read green, with ignores by ID only, each with a written reason, `unmaintained`/`unsound` at their defaults, and each ignore re-read (per security-plan §Dependency Security → Audit tool). Two things are research's to answer: whether RUSTSEC-2026-0192 (ttf-parser, recorded as reached only through winit 0.31.0-beta.3) is still encountered under `a09f46792`'s winit `=0.31.0-beta.4`, and whether the `yanked` clipboard-win warning leaves with `arboard` under `527394724`. A no-longer-encountered ignore is dropped with its record, never left silent.
- Any crate that enters the lock is reviewed by hand for licence, repository, build script, proc-macro flag and direct dependent, and passes the licence gate (per security-plan §Dependency Security → Supply chain integrity, licence compliance). Every cargo leg keeps `--locked` (per security-plan §Dependency Security → Supply chain integrity, lockfile verification).
- The script fetcher is a recorded trust boundary: the default fetcher takes only `file:` and `data:` URLs (per security-plan §Threat Model Summary, script-execution vector; detail `.andromeda/security-plan-detail/threat-model-summary.md`). Script fetch input is checked at its boundary (per security-plan §Input Validation, Script fetch). `cee6b8731` ("only a `file:` document may load `file:` URLs") must only narrow that path. Whether it widens nothing, and how the boundary's text reads after it, is research's reading for the wrap's amendment.
- Engine crates log through `tracing` behind each crate's `tracing` feature (per security-plan §Logging & Monitoring, Log format and backends). escher's sink prints only the seven safe fields of an engine target and drops every record from a target outside its allowlist (per security-plan §Logging & Monitoring, escher's own sink; detail `.andromeda/security-plan-detail/logging-monitoring.md`). Two of the delta's added sites can carry page or OS content in their message: `"Failed to set clipboard: {_error}"` (blitz-shell, `527394724`) and `"Uncaught JS error in {what}: {error}"` (blitz-vibey-script, `e6f4615ec`). Whether each falls under an allowlisted engine target, so its message reads `[redacted]`, and whether it is gated on the feature, is research's question.
- The take must add no environment read beyond the recorded list (per security-plan §Secret Management, Environment values read). Whether the delta's added lines hold any `std::env::var`/`env!` is research's reading.
- The clipboard records move with a take of `527394724`: the clipboard read/write through `arboard` behind the `clipboard` feature (per security-plan §Data Protection, Local user data handled) and the `arboard::Clipboard::new` unwrap and `ClipboardError` mapping (per security-plan §Error Handling, Error format). Whether winit's clipboard API keeps or removes that panic path is research's question.

## Patterns to follow
- The per-sync lock evidence: a chunk `evidence/lock.md` that reads the lock's `name@version` set against upstream's at the pin (or against the tree before it), names every package that enters, leaves or moves, and records the audit leg's verdict with `deny.toml` changed or unchanged, as each prior sync's line under security-plan §Dependency Security (detail `.andromeda/security-plan-detail/dependency-security.md`) records it.
- The founder's last shape: no-commit cherry-picks of upstream's text, merge base staying `23b9b26a9`, `Cargo.toml` and `deny.toml` byte-identical where no pin moves. Edges re-pointed to versions already locked are listed, not hidden (per security-plan §Dependency Security → Pinning, the sync at `f9cbb2756`).
- An advisory that turns the audit red outside the change is fixed by a semver-compatible update or ignored by ID with a written reason and a `.andromeda/residuals.md` owner (the External decay pattern recorded under security-plan §Dependency Security → Audit tool).
- The sink's standing capture checks (`stand_act_spans`, seven_guis `host_log` and `mcp_log`) are re-run on the take's tree at 0 id, name, sentinel and base64 needles. They are the re-read's measurement (per security-plan §Logging & Monitoring, escher's own sink).

## Anti-patterns to avoid
- A lone bump of a coupled pin. The ttf-parser ignore records that no fix is reachable without a lone bump of winit. A take moves winit only with upstream's own set at the measured sha (per security-plan §Dependency Security → Audit tool).
- A blanket allow, or `unmaintained`/`unsound` set to none, to turn the audit green after the take (per security-plan §Dependency Security → Audit tool).
- Routing an agent- or user-supplied URL through a path the delta touches (the script fetcher, `@font-face` sources, `blitz-net`'s `file:` reads) without a recorded decision (per security-plan §Input Validation, `file:` URLs and `@font-face` source).

## Contract bindings
- Audit leg ↔ tests CI Integration: `ci-leg.sh audit` is ci.yml's `audit` job, run on every push (security-plan §Dependency Security → CI integration). The fork CI's green run carries it.
- Sink allowlist re-read ↔ obs-plan §3 (the telemetry capture contracts) and the session checks `host_log`, `mcp_log` and `stand_act_spans`, which measure the 0-needle reading.
- Script fetcher narrowing ↔ `.claude/rules/security.md` §Untrusted input ("The default `ScriptFetcher` accepts only `file:` and `data:`"). That rule text and the threat model's script-execution boundary move together at the wrap.
- Dependency pins ↔ architecture §Occupied Resources / its `Upstream sync:` line. A moved pin or a new package is recorded in both plans.
