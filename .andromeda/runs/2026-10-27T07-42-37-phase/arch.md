## Patterns to follow
- The last syncs took upstream's text by no-commit cherry-picks, each with its `(cherry picked from commit …)` trailer, and left the merge base unmoved at `23b9b26a9` (per architecture §Project Intent → Upstream sync). The taken set and the new "last read" sha are recorded on that line at the wrap.
- A conflict in a merge-surface file is resolved to upstream's text plus escher's addition, as `construct.rs`'s import list was resolved to upstream's list plus `RangeInputData` at `f9cbb2756` (per architecture §Established Decisions → [Scrolling and input], detail dec-scrolling-and-input "as measured at …/evidence/take.md").
- At an upstream sync, an upstream change to `README.md` resolves to escher's version (per architecture §Project Intent → Front page). Under `docs/`, upstream's files never conflict with `capabilities.md` (per architecture §Infrastructure Patterns → Directory structure).
- Upstream's new test files enter blitz-tests one target per file, and upstream's `tests/all.rs` stays declared at `test = false` (per architecture §Conventions → Tests). Scenarios run in both layout modes, and both layout modes must produce identical layouts (per architecture §Design Philosophy → One incremental pipeline).
- Engine tracing call sites stay gated per call site with a `cfg(not(feature = "tracing"))` fallback (per architecture §Conventions → Feature gating). escher's sink drops every record outside the engine and escher prefix sets (per architecture §Cross-cutting Patterns → Logging and timing). Upstream's new `tracing::error!` sites in blitz-shell and blitz-vibey-script are read against both rules.

## Anti-patterns to avoid
- A one-sided pin bump, or a git dependency in the root manifest, without the founder's (delegate's PROVISIONAL) answer at P4 (per architecture §Established Decisions → [Dependency pinning]).
- A conflict resolution that drops one side's intent, for example upstream's `0980cce5f` scroll-origin body overwriting escher's second `physical_unrounded_geometry` body in `writing_mode.rs`, or reverting the hit stops in `node/node.rs` (per architecture §Established Decisions → [Scrolling and input]).
- Reaching through `DocumentMutator::doc` instead of extending the mutator while merging upstream's `mutator.rs` hunks (`53e9d81c6` `:open`, `ebacd68bd`) (per architecture §Conventions → DOM API patterns).
