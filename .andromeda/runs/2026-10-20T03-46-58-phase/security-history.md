## Relevant amendment history
- **2026-10-06-headless-stand** — split `disabled` into a parsed reading (focus) and a presence reading (DISABLED state, pointer selection, click default actions). This is the origin of the presence rule that a select's gates must follow.
- **2026-10-06-snapshot-state-fidelity** — the snapshot's `enabled` follows the `disabled` presence reading. A password's snapshot value reads `MASKED_VALUE`. The Dioxus bridge removes a falsy boolean attribute instead of writing it. Why it matters: a select's chosen value in `NodeState.value` is an unmasked control value, and an `option`'s `selected` written from Dioxus goes through the falsy-clear path.
- **2026-10-06-compact-snapshot-serialization** — the snapshot's one text form writes a value as a quoted `Debug` string. The mask covers only `password` and `file` inputs, compared ASCII-case-insensitively. Why it matters: a select's value would be written in that form, in the clear, and the mask list does not grow silently.
- **2026-10-07-sink-target-allowlist** — escher's sink drops any record from an outside target at every level and redacts content-named fields on `escher_*` targets. Trap it records: a "nothing in the logs" check has to run against a host that installs the sink (`host_log`). The chunk's sentinel option value and label at `trace` is that kind of check.
- **2026-10-07-command-and-refusal-schema** — created the Driver command schema row: a closed verb table with argument kinds and bounds, one answer per call in a fixed order, no `unwrap`/`expect`/`panic!`/index on what a call supplies, no `Session` in `validate`. A `Refusal` holds nothing of the call and no `String` field. Why it matters: any option argument has to fit this shape.
- **2026-10-07-act-by-id** — an id taken in is looked up by a linear search of `element_ids()` and read through `get_node`, never by index, anew on every call. `Outcome` is `Debug`-printed and never logged. This is the id path a select choice reuses.
- **2026-10-07-refusal-detection** — the sixth verb (`scroll`) widened the validated surface and needed the founder's ratification. The detected causes come after `validate` in a fixed order (`stale`/`not-found`, then `disabled`, `off-screen`, `covered`), and nothing runs on a refusal. This is the precedent for a new verb and the order a select choice inherits.
- **2026-10-07-driver-command-spans** — set the command span at eight fields (`verb`, `cause`, `settled`, `busy`, `passes`, `added`, `removed`, `changed`). An argument, `Refusal`, `Fault` or screen text is never a field. An option value or label must stay out of it.
- **2026-10-09-founder-rulings** — the founder's standing rule: a diff's counts may reach a log, but no node, id, name or value of a diff may. A select value change in a diff is subject to it.
- **2026-10-10-driver-cli** (the command line is an external input surface) — the verb set widened to nine and a sixth argument kind, `name`, was added, bounded at 1 to 32 bytes of `a-z0-9-`. Both are under the founder's ratification. Standing rule: every surface's input passes `validate` before anything runs, and a usage line or refusal writes back nothing the caller typed. This is the precedent for a new argument kind and its bound.
- **2026-10-10-driver-cli** (ids, names and values leave in an answer) — control values cross out in answers on the socket and stdout. Typed text was measured at 0 in a host's `trace` stderr. A refusal is written from fixed strings only. A select's chosen value rides this ratified value crossing.
