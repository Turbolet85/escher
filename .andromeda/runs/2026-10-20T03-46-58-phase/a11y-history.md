## Relevant amendment history
- **2026-10-05-ci-gate-legs** — created the named `a11y` CI leg (`ci-leg.sh a11y`) as a fixed list of test files with per-file counts. That list is the binding this chunk rests on: a new select fixture check lands in the workspace `test` leg unless the leg is widened, and a test added to one of its files moves the recorded counts.
- **2026-10-06-accessibility-tree-identity** — set the name sources. A non-empty trimmed `aria-label` names any element. A `<label>` names only its bound `<input>` (by `for`, else the first nested), through `labelled_by`. This is the reason a select named by `<label for>` may read an empty name. A fixture select should be named by `aria-label` (or `aria-labelledby`), or research must show that the label loop admits `select`.
- **2026-10-06-snapshot-model** — the snapshot takes role, name and focus from the tree that `accessibility_tree` returns, with no second role or name mapping. A select's `ComboBox` role and its name must come from the tree, never from a special case in `snapshot.rs`.
- **2026-10-06-id-stability-across-code-edits** — added the actionable-key rule and its check, `DioxusDocument::unkeyed_actionable`. Actionable means focusable, an interactive role or a listener, with the role read from the tree. Trap: never satisfy the check by adding a `tabindex` or a role, because that moves the pinned Tab order; key the element instead. Whether the select's options count as actionable (they carry an interactive role, `ListBoxOption`) is decided under this rule.
- **2026-10-06-snapshot-state-fidelity** — the snapshot reads `enabled` (the presence of `disabled`), `checked` and `value` from the element, because the tree gives none of them. This is where a select's chosen value must be read. It also set the key-press focus-check pattern: at each Tab and Shift+Tab, exactly the focused control reads `focused`, equal to the tree's focus.
- **2026-10-06-compact-snapshot-serialization** — `Snapshot::to_text` reads only the snapshot model, one line per node, and adds a value mask for file inputs. A select's value reaches the text form only through the snapshot node's `value`. Also a precedent for a per-control value rule added in `snapshot.rs` (password, then file input).
- **2026-10-07-change-tracking-and-diff** — defined the engine's changed set and what marks it: in-document mutations, focus and checked changes, and a text control's input; not hover or layout. The shell's refresh and the diff depend on it. A select's chosen-option change must mark this set, as `apply_range_move` later did, or the diff and the tree refresh will miss it.
- **2026-10-07-audit-corrections** — the stand's role, name and rendered tables are stated once, in `tests/blitz-tests/tests/common/mod.rs`, as stated expectations and never a second mapping. A select kept on a fixture page leaves these stand tables unmoved.
- **2026-10-07-settle-detection** — a harness settle and the driver's `act` neither read nor drain the changed set, and a freshly booted document's set is non-empty. A check that reads `has_changes()` as "this select step changed something" must drain first.
- **2026-10-07-command-and-refusal-schema** — the driver's `disabled` cause is worded on the presence reading, and the schema defines no role or name set of its own. Rule: whatever detects `disabled` reads the snapshot's `enabled`, never the attribute's value.

- **2026-10-18-engine-debts** (§5, §6: `inert` and `disabled` …) — `disabled` is read by presence on a form control alone (`ElementData::is_disabled`: `button`, `input`, `select`, `textarea`), and that reading keys the focus, pointer, click and activation gates. An inert node is not focusable, takes no hit and leaves the tree. So a `disabled` select is skipped by Tab and gated, an inert one leaves the tree, and `stand_keyboard` and `inert_subtree` pin both.
