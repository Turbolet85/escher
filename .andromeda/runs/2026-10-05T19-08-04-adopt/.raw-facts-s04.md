## architecture §Design Philosophy
- The browser crate describes itself as a web browser whose UI is powered by Dioxus Native and whose content rendering is powered by Blitz (apps/browser/src/main.rs:5)
- The persistence crate declares every write path best-effort: in-memory fallback when the data dir is unavailable, in-memory only on mobile, per-statement sqlite errors logged at `warn` and swallowed, callers never see a `Result` (apps/browser/persistence/src/lib.rs:5-19)
- The persistence crate states history is UX state, not load-bearing, and a transient disk failure must not propagate into a navigation error (apps/browser/persistence/src/lib.rs:17-19)
- The persistence crate is synchronous and runtime-agnostic; callers keep disk work off latency-sensitive threads (apps/browser/persistence/src/lib.rs:21-25)
- Disk writes with no bound tokio runtime are dropped rather than run synchronously on the UI thread, with a `debug_assert!` to surface the bug in development (apps/browser/src/browser_history.rs:147-164)
- History dedupe policy folds only consecutive same-URL visits, keeping the list a chronological log rather than a most-recently-visited set (apps/browser/src/browser_history.rs:51-56)
- Favicon cache stores only positive results so a transient probe failure does not poison the entry for the process lifetime (apps/browser/src/favicon.rs:9-13)
- Chrome writes on document commit run as a straight-line block so a render cannot sample a half-applied state (apps/browser/src/tab.rs:126-129)
- accesskit_xplat is a cross-platform AccessKit adapter that does not depend on Winit so it can be used with any Winit version (packages/accesskit_xplat/src/lib.rs:5-7)
- The transparent example states transparency requires a transparent winit window, an alpha-aware renderer composite mode, and CSS that paints no opaque background (examples/transparent/src/main.rs:4-13)

## architecture §Established Decisions
- History schema migrations are append-only; the list index is the version stamped into `PRAGMA user_version` and released entries are never edited (apps/browser/persistence/src/lib.rs:35-50)
- `MAX_HISTORY_ENTRIES` is 1000 and both the in-memory deque and the on-disk table are pruned to it (apps/browser/persistence/src/lib.rs:52; apps/browser/src/browser_history.rs:68-70; apps/browser/persistence/src/lib.rs:247-256)
- Upsert and prune of a visit run in one sqlite transaction (apps/browser/persistence/src/lib.rs:206-259)
- On-disk favicon patch updates every row for the URL whose `favicon_url IS NULL`; the in-memory side patches by entry id (apps/browser/persistence/src/lib.rs:134-148; apps/browser/src/browser_history.rs:130-138)
- Mobile (Android, iOS) always opens an in-memory sqlite connection (apps/browser/persistence/src/lib.rs:277-303)
- Browser history is loaded synchronously on startup, a single query capped at MAX_HISTORY_ENTRIES rows (apps/browser/src/main.rs:110-119)
- Favicon success is inferred by decoding the response body because the net layer does not surface HTTP status or Content-Type (apps/browser/src/favicon.rs:44-56; apps/browser/src/favicon.rs:59-68)
- Non-URL urlbar input containing a dot and no space is retried with an `https://` prefix; anything else becomes a DuckDuckGo HTML search (apps/browser/src/nav.rs:5-32)
- Opening in an external browser is limited to GET requests with http, https or mailto schemes (apps/browser/src/nav.rs:34-40)
- about: pages are about:newtab, about:settings, about:history, about:bookmarks; Settings and Bookmarks render a "Coming soon." stub (apps/browser/src/about_pages.rs:20-58; apps/browser/src/about_pages.rs:69-77; apps/browser/src/about_pages.rs:189-198)
- An empty response body renders the bundled 404 page; a fetch error renders the bundled error page with the error text (apps/browser/src/document_loader.rs:131-137; apps/browser/src/document_loader.rs:151-177)
- Synthesized error pages skip history recording and the favicon probe (apps/browser/src/document_loader.rs:31-33; apps/browser/src/tab.rs:134-143)
- Starting a new load aborts the previous load via an AbortController (apps/browser/src/document_loader.rs:105-115)
- The app always keeps at least one tab open; Ctrl/Cmd+W and the close button are disabled at one tab (apps/browser/src/tab.rs:116-123; apps/browser/src/tab_strip.rs:62-65; apps/browser/src/tab_strip.rs:91-97)
- Browser default features: hybrid, cookies, cache, screenshot, apple-font-embolden, scrollbars; Android defaults: skia, cookies (apps/browser/Cargo.toml:13-14)
- On Android a fallback safe area of 30px top and 44px bottom is hardcoded because winit lacks safe-area support (apps/browser/src/main.rs:147-158)
- Windows builds do not open a console window (apps/browser/src/main.rs:1-2; examples/counter/src/main.rs:1-2; examples/todomvc/src/main.rs:1-2; examples/seven_guis/src/main.rs:1-2; examples/transparent/src/main.rs:1-2)
- The blitz and anyrender package groups are each versioned together by the bump tool (apps/bump/src/main.rs:5-23)
- accesskit_xplat on Unix requires exactly one of the `async-io` (default) or `tokio` features, enforced with `compile_error!` (packages/accesskit_xplat/src/lib.rs:97-125)
- blitz-dom depends on objc2 with `disable-encoding-assertions` on Apple targets to prevent debug-build panics, labelled a HACK (packages/blitz-dom/Cargo.toml:97-100)
- wasm builds bundle DejaVu Sans because browsers do not expose system fonts to wasm (examples/seven_guis/Cargo.toml:30; examples/seven_guis/src/lib.rs:9-14; examples/todomvc/src/wasm.rs:4-9; examples/wasm_hello/src/lib.rs:21-23; examples/wasm_hello/src/lib.rs:75-100)
- wasm_hello intentionally omits `with_surface_size` so host CSS sizes the canvas (examples/wasm_hello/src/lib.rs:132-134)
- The UA stylesheet maps the `dir` attribute with attribute selectors because the engine's selector parser does not know Gecko's internal pseudo-classes (packages/blitz-dom/assets/default.css:14-36)
- rdme renders Markdown via comrak (default) or pulldown_cmark, selected by feature (apps/readme/Cargo.toml:13; apps/readme/Cargo.toml:29-30; apps/readme/src/main.rs:3-16)

## architecture §Standard Contracts

- `visited_at` is stored as whole seconds since the Unix epoch (apps/browser/persistence/src/lib.rs:209-213; apps/browser/persistence/src/lib.rs:189)
- `HistoryService` is the single entry point for visit and favicon writes, owning the in-memory Store and the on-disk store (apps/browser/src/browser_history.rs:104-145)

- `LoadedDocument` carries document, html_source, title, favicon_candidate, is_error (apps/browser/src/document_loader.rs:21-34)

- `blitz_dom::Widget` is implemented with requires_redraw, destroy_surfaces and paint returning an `anyrender::Scene` (apps/browser/src/fps_overlay.rs:68-92; examples/wgpu_texture/src/demo_renderer.rs:21-80)
- URL suggester worker messages are `SetQuery(String)` and `ReplaceEntries(Vec<HistoryEntry>)` over an unbounded tokio mpsc channel (apps/browser/src/url_suggestions.rs:49-68)
- Suggestion order is fixed: Literal row, up to 6 history rows, then a Search row (apps/browser/src/url_suggestions.rs:15; apps/browser/src/url_suggestions.rs:102-135; apps/browser/src/url_suggestions.rs:244)
