## architecture §Design Philosophy
- blitz-traits states it holds types and traits enabling interoperability between the other Blitz crates "without circular or unnecessary dependencies" (packages/blitz-traits/src/lib.rs:1-2)
- the `blitz` crate states it collects the most important functionality in one place, brings no unique functionality, and re-exports the other crates as modules (packages/blitz/src/lib.rs:7-9)
- networking is abstracted "so that custom networking implementations can be provided" via the `NetProvider` trait (packages/blitz-traits/src/net.rs:1; packages/blitz-traits/src/net.rs:16-20)
- navigation is abstracted so embedders can hook link clicks and form submissions via `NavigationProvider` (packages/blitz-traits/src/navigation.rs:1; packages/blitz-traits/src/navigation.rs:8-12)
- windowing/OS functionality is abstracted via `ShellProvider` so a document can use it "without depending on a specific shell environment" (packages/blitz-traits/src/shell.rs:9-11)
- `BlitzImeEvent` is a copy of the Winit IME event "to avoid lower-level Blitz crates depending on winit" (packages/blitz-traits/src/events.rs:734-736)
- blitz-vibey-script wraps a `BaseDocument` in a `ScriptDocument` that executes `<script>` JavaScript with the Boa engine and exposes DOM APIs backed by blitz-dom (packages/blitz-vibey-script/src/lib.rs:1-8)
- external scripts are fetched synchronously because the HTML spec requires classic scripts to execute in document order (packages/blitz-vibey-script/src/fetch.rs:28-34)
- uncaught JS errors are captured rather than printed; the embedder drains them and decides how to surface them (packages/blitz-vibey-script/src/document.rs:251-261)

## architecture §Established Decisions
- `NodeId` packs a 32-bit slot index (low bits) and 32-bit version (high bits) so ids of dropped nodes no longer resolve; the Default value is a null id (packages/blitz-traits/src/node_id.rs:3-12)
- `NodeId` orders by slot index then version, to roughly match node creation order (packages/blitz-traits/src/node_id.rs:47-54)
- each DOM node is represented by a single cached JS wrapper so object identity and expando properties persist (packages/blitz-vibey-script/src/state.rs:67-72; packages/blitz-vibey-script/src/dom/mod.rs:61-103)
- removed nodes are detached rather than dropped so JS wrappers referencing them remain valid (packages/blitz-vibey-script/src/dom/node.rs:341-345; packages/blitz-vibey-script/src/dom/element.rs:866-873)
- boa_runtime extensions registered: Base64, Encoding, StructuredClone, Microtask, Url; TimeoutExtension and FetchExtension/AbortControllerExtension are deliberately not registered (packages/blitz-vibey-script/src/runtime.rs:1305-1325)
- setTimeout/setInterval/requestAnimationFrame are implemented by the crate's own `TimerQueue` (packages/blitz-vibey-script/src/timers.rs:1-81; packages/blitz-vibey-script/src/runtime.rs:1358-1369)
- `requestAnimationFrame` approximates the next frame as 16ms away (packages/blitz-vibey-script/src/runtime.rs:2097-2107)
- interval timers reschedule with a minimum interval of 1ms (packages/blitz-vibey-script/src/timers.rs:65-76)
- the script clock has a real mode and a virtual mode that advances only via `advance_to`, shared with Boa so `Date` observes the same time (packages/blitz-vibey-script/src/clock.rs:8-23; packages/blitz-vibey-script/src/clock.rs:62-100; packages/blitz-vibey-script/src/runtime.rs:1292-1299)
- `window.history` is an in-memory implementation; `popstate` events are never fired (packages/blitz-vibey-script/src/runtime.rs:38-76)
- `fetch()` supports only GET and HEAD, with text-only bodies, on top of the synchronous `__blitz_fetch_sync` native (packages/blitz-vibey-script/src/runtime.rs:84-86; packages/blitz-vibey-script/src/runtime.rs:164-168)
- there is only ever a single frame: `parent` and `top` are the window, `opener` is null (packages/blitz-vibey-script/src/runtime.rs:1338-1342)
- `navigator.userAgent` is "Mozilla/5.0 (compatible; Blitz)" (packages/blitz-vibey-script/src/runtime.rs:1348-1356)
- all elements share a single prototype; tag-specific interface constructors are stubs whose `instanceof` checks answer false (packages/blitz-vibey-script/src/runtime.rs:360-385)
- documents are treated as always no-quirks mode (packages/blitz-vibey-script/src/dom/document.rs:115-119; packages/blitz-vibey-script/src/dom/element.rs:976-977)
- DocumentFragments are represented as detached elements named `#document-fragment` (packages/blitz-vibey-script/src/dom/node.rs:402-409)
- `document.fonts` is a stub where all fonts report as loaded (packages/blitz-vibey-script/src/runtime.rs:1057-1071)
- the module loader caches modules by resolved URL to break import cycles (packages/blitz-vibey-script/src/runtime.rs:1180-1190)
- the default `ScriptFetcher` supports only `file:` and `data:` URLs (packages/blitz-vibey-script/src/fetch.rs:36-58)
- `DummyNetProvider` reports `is_noop`, and callers must not register resources as pending-critical for a no-op provider (packages/blitz-traits/src/net.rs:22-29; packages/blitz-traits/src/net.rs:165-173)
- `debug_timer` swaps a real timer for a zero-cost dummy depending on its `enable` feature (packages/debug_timer/Cargo.toml:11-12; packages/debug_timer/src/lib.rs:84-127)
- blitz-vibey-script allows `clippy::collapsible_if` crate-wide (packages/blitz-vibey-script/src/lib.rs:30)

## architecture §Infrastructure Patterns
- `launch_url` parses the URL, enters a tokio runtime, creates the event loop, shell proxy, net provider and application, fetches the page with `fetch_async`, then launches (packages/blitz/src/lib.rs:44-80)
- `launch_internal` builds an `HtmlDocument` with base_url, UA stylesheets and net provider, wraps it in a `WindowConfig` with a renderer, and runs the event loop (packages/blitz/src/lib.rs:106-131)
- the net provider is `blitz_net::Provider` with the `net` feature and `DummyNetProvider` without it (packages/blitz/src/lib.rs:133-152)
- the timer thread receives deadlines over an mpsc channel and calls the stored `Waker` when due; a disconnected channel causes a respawn next time (packages/blitz-vibey-script/src/document.rs:340-400)
- `poll` stores the task waker, executes scripts on first poll, then runs due timers (packages/blitz-vibey-script/src/document.rs:423-446)
