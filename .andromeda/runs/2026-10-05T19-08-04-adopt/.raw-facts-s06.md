## architecture §Design Philosophy
- Scrolling has a single primitive: user-initiated and programmatic scrolls differ only in the `ScrollRequest` they build (packages/blitz-dom/src/scrolling.rs:126-130)
- Stylo `Device` changes (resize, zoom, color-scheme, media type) are coalesced so the stylist device is rebuilt at most once per `resolve` (packages/blitz-dom/src/stylo_device.rs:1-5; packages/blitz-dom/src/stylo_device.rs:22-42)
- Decoration styles (underline, strikethrough) are deliberately kept out of the Parley text style; the `NodeId` is carried in the `brush` field and those styles are read lazily at render time so they can change without rebuilding the Parley layout (packages/blitz-dom/src/stylo_to_parley.rs:506-521)
- Nodes are addressed by a versioned `NodeId` so ids of dropped nodes stop resolving instead of aliasing a reused slot (packages/blitz-dom/src/tree.rs:27-33)
- The default action is always run on the pointer event so the shell layer and default actions stay pointer-based; mouse/touch compatibility events are generated only for script (packages/blitz-dom/src/events/driver.rs:288-310)
- Behaviour is written against web specs cited in comments: CSS Transforms current transformation matrix (packages/blitz-dom/src/stylo_to_kurbo.rs:11-24), CSS Fonts feature precedence (packages/blitz-dom/src/stylo_to_parley.rs:264-273), HTML rules for parsing dimension values (packages/blitz-dom/src/stylo.rs:917-923), Pointer Events `touch-action` (packages/blitz-dom/src/events/pointer.rs:158-166), HTML implicit form submission (packages/blitz-dom/src/events/keyboard.rs:138)
- Prefer a default over a panic when a conversion receives an unexpected value (packages/blitz-dom/src/stylo_to_cursor_icon.rs:6-11)

## architecture §Established Decisions
- Documents are always treated as HTML documents in no-quirks mode (packages/blitz-dom/src/stylo.rs:245-251; packages/blitz-dom/src/stylo_device.rs:74)
- Shadow DOM is not implemented: `host`/`style_data` are `todo!`, `as_shadow_root`/`shadow_root`/`containing_shadow` return `None` (packages/blitz-dom/src/stylo.rs:275-284; packages/blitz-dom/src/stylo.rs:356-359; packages/blitz-dom/src/stylo.rs:825-831)
- Container queries are disabled by returning a default size (packages/blitz-dom/src/stylo.rs:1210-1216)
- Visited-link styles are disabled (`visited_styles_enabled: false`, `:visited` never matches) (packages/blitz-dom/src/stylo.rs:133; packages/blitz-dom/src/stylo.rs:490)
- Only 2D transforms are applied; 3D rotations and non-2D matrices are dropped, and the `offset` property is unsupported (packages/blitz-dom/src/stylo_to_kurbo.rs:40-46; packages/blitz-dom/src/stylo_to_kurbo.rs:64-73; packages/blitz-dom/src/stylo_to_kurbo.rs:81-82)
- The root element scrolls the viewport (CSS overflow propagation); the viewport offset lives on `NodeTree`, not on the node (packages/blitz-dom/src/scrolling.rs:28-32; packages/blitz-dom/src/scrolling.rs:272-283; packages/blitz-dom/src/tree.rs:41-43)
- `overflow: hidden` axes are scrollable for programmatic scrolls but not user scrolls (packages/blitz-dom/src/scrolling.rs:58-67; packages/blitz-dom/src/scrolling.rs:479-485)
- User scrolls chain unconsumed delta to the parent and then the viewport; programmatic scrolls clamp to one scroller (packages/blitz-dom/src/scrolling.rs:48-56; packages/blitz-dom/src/scrolling.rs:551-554)
- A user-initiated scroll aborts a smooth scroll in progress (packages/blitz-dom/src/scrolling.rs:425-427)
- Smooth scroll duration is 300 ms with a cubic ease-in-out curve (packages/blitz-dom/src/scrolling.rs:433-434; packages/blitz-dom/src/scrolling.rs:113-123)
- Fling deceleration is "0.95 @ 60fps normalized to actual frame times" and stops below 0.1 velocity on both axes (packages/blitz-dom/src/scrolling.rs:732-746)
- Fling velocity is computed from pan samples of the last 100 ms, dominant axis only, multiplied by 2.0 (packages/blitz-dom/src/events/pointer.rs:110-155)
- A drag starts after a 2 px threshold (packages/blitz-dom/src/events/pointer.rs:218-222)
- Click count increments within 500 ms and 2 px of the previous mousedown; count 2 selects a word and 3+ a hard line in text inputs (packages/blitz-dom/src/events/pointer.rs:395-405; packages/blitz-dom/src/events/pointer.rs:529-539)
- A wheel line delta is scaled by 20 px (packages/blitz-dom/src/events/pointer.rs:835-838)
- The action modifier is `SUPER` on macOS and `CONTROL` elsewhere (packages/blitz-dom/src/util.rs:7-10)
- `line-height: normal` is approximated as 1.2 × font size when resolving `baseline-shift` percentages; `baseline-shift: center` is approximated with `middle` (packages/blitz-dom/src/stylo_to_parley.rs:373-388)
- Generic font family `None` maps to sans-serif (packages/blitz-dom/src/stylo_to_parley.rs:50-52)
- `-apple-system` (Apple targets) and `BlinkMacSystemFont` (macOS) map to the `SystemUi` generic family (packages/blitz-dom/src/stylo_to_parley.rs:68-76; packages/blitz-dom/src/stylo_to_parley.rs:444-456)
- The default document URL is a `data:text/css;charset=utf-8;base64,` URL (packages/blitz-dom/src/url.rs:34-37)
- A link differing from the document URL only by fragment scrolls to the fragment instead of navigating (packages/blitz-dom/src/url.rs:23-31; packages/blitz-dom/src/events/pointer.rs:738-750)
- Empty and `top` fragments scroll to the top of the document (packages/blitz-dom/src/scrolling.rs:674-678)
- Programmatic scrolls do not yet dispatch `scroll` events (packages/blitz-dom/src/scrolling.rs:574; packages/blitz-dom/src/scrolling.rs:768)
- Animations of nodes no longer in the document are dropped during style resolution (packages/blitz-dom/src/stylo.rs:87-101)
- Pseudo-element (`::before`/`::after`) style changes that need no reconstruction are synced during the style traversal (packages/blitz-dom/src/stylo.rs:1380-1400)
- `pointercancel` has no mouse compatibility event but does generate `touchcancel` (packages/blitz-dom/src/events/driver.rs:234-244)
- Scrollbar thumb drags take precedence over content and are not dispatched to the page; a faded-out thumb does not capture (packages/blitz-dom/src/events/pointer.rs:419-436)
- Implicit form submission is blocked when the form owns more than one blocking text-like field (packages/blitz-dom/src/events/keyboard.rs:138-173)
- `<input type=image>` is the only input type taking embedded-content presentational attributes (packages/blitz-dom/src/stylo.rs:980-987)
- `rightmargin`/`bottommargin` on `body` are deliberately not mapped (packages/blitz-dom/src/stylo.rs:1143-1161)
