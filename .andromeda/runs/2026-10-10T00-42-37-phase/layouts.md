## Patterns to follow
- The stand is reached through one boot path and consumers add nothing to it: the headless checks and the session host both boot through `seven_guis::stand` and read the same mount (per layout-templates §Surface: desktop-native → Primary screens). Post-merge proof reuses that path; no second mount is introduced.
- A recorded bound cites the evidence census it was measured at (per layout-templates §Surface: desktop-native → IA notes). A figure re-measured after the merge follows the same shape: measured into this chunk's evidence, the plan's line then amended to cite it.
- Stand layout facts are stated for both layout modes (per layout-templates §Surface: desktop-native → Primary screens); a post-merge reading of the mount or the bounds is taken incremental and non-incremental.
- The repository's script surfaces keep machine output and raw tool output apart: JSON lines on stdout, usage on stderr, raw cargo output in a log file (per layout-templates §Surface: cli → Primary screens). Any change the test-target decision forces in `agent-run.sh` stays inside that split.

## Anti-patterns to avoid
- Editing stand markup, ids, classes, styles, wrappers or element order to bring a post-merge bound or mount check back to its old value — the plan records these as unmoved by every prior chunk (per layout-templates §Surface: desktop-native → Primary screens; §Surface: desktop-native → IA notes).
- Changing a CLI surface's usage line, argv shape or stdout discipline as a side effect of the manifest resolution without the plan's line moving with it (per layout-templates §Surface: cli → Primary screens).
- Hand-editing upstream's WPT runner output to keep the recorded shapes true; the record follows the code, and additivity is the scope's rule (per layout-templates §Surface: cli → Output structure — wpt runner).

The layouts proof is vacuous unless the chunk's by-count evidence shows those files ran (test-plan §3, test-plan §9 baseline).
- layouts ↔ tests: the `agent-run.sh` exit grammar and event schema, and the session contract `escher-session` serves, live in test-plan §3 (per layout-templates §Surface: cli → Primary screens); the run-selection grammar binds to the test-target decision.
- layouts ↔ a11y: layout-templates carries no focus-order section, so upstream #1085 (a bare `autofocus` treated as enabled) and boot focus are not a layouts mandate — the binding is a11y-plan §1 / §3 (SC 2.4.3), re-proven by its standing checks.
- layouts ↔ design: the stand's bounds are measured under the bundled font; a Parley 0.12 metric move is a typography reading first (design-system §Typography) and a bounds reading second.
- layouts ↔ architecture: the into-view scroll and visible-region reader behind the nested-scroller record (per layout-templates §Surface: desktop-native → IA notes) are an arch §Standard Contracts surface; the scope reads `scrolling.rs` as untouched by upstream in this sync.
