## Patterns to follow
- One bundled font for every generic, system fonts off, as the stand's source of repeatable text metrics — per design-system §Typography (Loading). A stand bound or snapshot size that moves under the new pins is re-measured against that same font, not against a host font.
- Colour scheme flows from the viewport to `prefers-color-scheme` and a change forces a full recascade — per design-system §Color Palette (Color model and scheme); the window's theme seeds it, defaulting to Light — per design-system §Surface: desktop-native (Tokens, platform-specific). Both read from files the merge touches; the merged code follows the same path.
- Values in the engine and integration crates are untokenized and recorded as built — design-system §Color Palette (Token sets) records colour tokens as observed absent there. The merge introduces no token layer and no custom property of ours.
- A behaviour the record states is tied to the check or chunk report that measured it (the "as measured at" form in design-system §Motion (This project's values) and §Motion (Animation runtime)). A value this merge moves is re-measured and carried the same way.

## Anti-patterns to avoid
- The plan records no design bans: design-system §Anti-Patterns reads `NO RECORDED INTENT` and nothing is extracted from it. The two items below are hazards read from recorded facts, not bans.
