## Constraints
- **Pins move as one set, never one side.** Arch §Established Decisions → [Dependency pinning] requires the html5ever family to match stylo's web_atoms, skrifa to match parley and vello, svgtypes to match usvg, taffy and parley to be pinned by git `rev`, and winit to stay an exact beta pin. The merge takes upstream's values at `7832c177` for every coupled pair or none; a pair that does not resolve together is a halt. Whether upstream's Parley 0.12 keeps parley a `rev`-pinned git dependency or moves it to a registry version, and what skrifa/vello value travels with it, is research's question. The as-built values this sync moves are recorded per arch §Stack and Technologies (rows Layout, Text and fonts, Accessibility, Markdown app) and are amended at the wrap, not during the merge.
- **MSRV stays 1.91, proven by a build only.** Arch §Stack and Technologies (row Language / runtime) fixes `rust-version` 1.91.0, and arch §Established Decisions → [MSRV] requires the MSRV job to run only `cargo build`, so dev-dependencies are not held to it. Whether upstream's updated dependency set still builds on 1.91 is the MSRV leg's reading, not an inference from the absent `rust-version` delta.
- **The root manifest keeps escher's workspace and adds nothing unregistered.** Arch §Occupied Resources → Names requires `escher-telemetry`, `escher-driver` and `seven_guis` to remain workspace members and `[workspace.dependencies]` path entries, and the `escher-session` binary to remain; arch §Conventions → Manifests requires dependencies declared once at the workspace and consumed `{ workspace = true }`, in-repo crates `default-features = false` except the `seven_guis` entry; arch §Stack and Technologies (row Testing) requires blitz-tests to keep its escher dev-dependencies (the stand, the driver, the telemetry crate) through the `tests/blitz-tests/Cargo.toml` conflict. Whether upstream's 61 commits add a workspace member, an env read or a listener of their own is research's question; any that arrive are registered under arch §Occupied Resources at the wrap, never left silent. In the same file, arch §Established Decisions → [Build profiles] requires the `dev` profile to carry `debug = "line-tables-only"`, inherited by `test`, with the named profiles beside it untouched; upstream #1125 sets line-tables-only debuginfo by its own means, and whether its form and ours collide in the `Cargo.toml` conflict is research's question — the resolution leaves one statement of the debuginfo level, not two.
- **Fork CI keeps its shape through the `ci.yml` conflict.** Arch §Infrastructure Patterns → CI/CD requires: triggers on `main`, `v0.*` and `build/**` with per-ref cancel-in-progress concurrency; workflow-level `permissions: contents: read` with no job-level grant; the fast/slow split (four jobs without `needs`, every other job needing all four); every linux job running its leg as `bash .github/scripts/ci-leg.sh {leg}` with `--locked`; every package install going through `apt-install.sh` with no bare `apt-get` line; every `uses:` pinned to a 40-hex SHA and every toolchain step naming its `toolchain`; linux tested by the fast `test` leg and the matrix covering windows, macos, ios and android. An upstream job change is taken only in a form that keeps each of these.
- **Leg and test-target names are contracts.** Arch §Standard Contracts → CI contracts fixes the leg list of `ci-leg.sh`, names the three integration tests the `a11y` leg runs, states that `scripts/agent-run.sh` drives `cargo test -p blitz-tests --locked`, and pins the whole by `test_ci_workflows.py` and `test_agent_run.py` in the `ci-scripts` leg. Whichever build shape the operator chooses for our test files, each name those contracts carry either still resolves to a runnable target or the contract and its pinning test move in the same chunk.
- **Upstream-only infrastructure stays unreachable from the fork.** Arch §Occupied Resources → CI infrastructure requires every job that uses the "Signed Builds" and "WPT" environments or the WarpBuild runner label to carry `github.repository == 'DioxusLabs/blitz'`; arch §Infrastructure Patterns → Deployment model requires the same of the bundle job. The three upstream-only workflows are overlap files: each merged job is read for that guard. Upstream's WarpBuild Windows test runner (#1128) is a runner label the fork has no registration for under arch §Occupied Resources → CI infrastructure, so the fork's Windows matrix leg does not adopt it.
- **The ratified engine edits survive the four overlapped engine sources and the shell.** Arch §Standard Contracts → Document core requires `has_changes` to read true from the first tracked write until `take_changed_nodes` drains, and node creation to mark nothing; arch §Cross-cutting Patterns → Invalidation and state integrity requires the changed set written at its three kinds of site (the mutator's mutation-flag sites, the focus/checked state snapshot, the typed-text input arm) and by nothing else, and the shell to take the set on every poll that did work and rebuild the platform tree only when it was non-empty. Whether the textual merge of `document.rs`, `mutator.rs`, `node/node.rs` and `window.rs` leaves every such site in place, and whether an upstream-added mutation path (the Selection API, `innerText`, the custom-widget tag override) writes the DOM without passing one, is research's question.

## Patterns to follow
- **Test files: one behaviour per file, shared modules in subdirectories.** Arch §Conventions → Tests requires each integration-test file to cover one behaviour and records the two shared modules (`tests/common/mod.rs`, `tests/session_common/mod.rs`) as no test target, read by `mod common;` / `mod session_common;`. The build-shape decision is weighed against this: whether those `mod` declarations still resolve when a file is compiled as a module of one binary instead of a crate root is research's question.
- **Re-executing checks depend on the binary and the exact test name.** Arch §Occupied Resources → Process-wide state and threads records blitz-tests checks that re-run `std::env::current_exe()` with a fixed argv `--ignored --exact {child} --nocapture` (the telemetry, id-persistence, command-span and session-host children) and state directories under `CARGO_TARGET_TMPDIR`. Under a single-binary shape `current_exe()` is the shared binary and a test's exact name gains a module prefix; whether those children are still found — or silently match zero tests and report success — is research's question and a direct input to the operator's decision.
- **A lock change re-keys every cache.** Arch §Occupied Resources → CI infrastructure records that a `Cargo.lock` change re-mints every `rust-cache` key and evicts under the 10 GB budget, and arch §Infrastructure Patterns → CI/CD that `a11y` restores the test job's `workspace-test` key without saving. The merge's first run is read as a cold-cache run: its wall time is not compared against the warm baseline, and its verdict is read only on a run left to settle (per-ref cancel-in-progress, arch §Infrastructure Patterns → CI/CD).
- **The sync is recorded where the last one was.** Arch §Project Intent carries the `Upstream sync:` line naming the last merged upstream sha, its merge commit and "the next sync's merge base"; it records `23354585`, the base this chunk measures from. The line moves to the new pin and merge commit at the wrap, together with every as-built line of arch the merge falsifies (pin values in §Stack and Technologies; the Taffy trait implementor in §Standard Contracts → Layout if #1099 lands as described; entries of §Established Decisions → [Unsupported features] that upstream's text-indent and writing-mode work overtakes).
- **Edits forced into upstream-owned code follow the engine's own conventions.** Arch §Conventions → Feature gating requires engine tracing gated per call site with a no-op fallback; arch §Conventions → DOM API patterns requires mutations to go through `DocumentMutator`, extending it rather than reaching through `DocumentMutator::doc`. A conflict- or gate-driven edit is written to both.

## Anti-patterns to avoid
- **A one-sided pin fix.** Bumping or holding back one member of a coupled pair to get the lock to resolve (per arch §Established Decisions → [Dependency pinning]); likewise bumping anything beyond upstream's own set.
- **Taking upstream's manifest or workflow whole.** A resolution that lets an escher leg, an escher dev-dependency or a named test target fall out while the leg still reads green — the leg list and target names are contracts pinned by tests, not incidental text (per arch §Standard Contracts → CI contracts); the same for a bare `apt-get` line or an unpinned `uses:` arriving from upstream's side (per arch §Infrastructure Patterns → CI/CD).
- **A silent resource.** A ref-only `if:` on an upstream-only job, an unregistered runner label, or a new crate, port, env var or listener landing without its registration (per arch §Occupied Resources → CI infrastructure; arch §Occupied Resources → Network ports and listeners).
