## Relevant amendment history
- **2026-10-06-stable-element-ids** — Added the §Input Validation `Markup attributes | id` row. A Dioxus document's `element_id` / `element_ids` read the HTML `id` as an author key only when it is non-empty, `/`-free and first in pre-order. Otherwise the element reads its path, so no `id` can make two ids equal. A non-element, stale or detached node reads `None`, and no path panics. The id is computed on demand, written nowhere, and carries no engine id or pointer. It was ruled an in-process reader of an already-admitted attribute, so not a boundary widening. This is the row the extract's constraints rest on. The chunk's remount check (a stale pre-remount `NodeId` reads `None`) and its fresh-process equality prove its clauses. Re-keying CRUD rows or changing the grammar in `element_id.rs` amends this row at wrap, together with arch §Standard Contracts.
- **2026-10-06-stand-test-contract** — Added the §Input Validation `CLI arguments (agent-run.sh)` row: a verb outside `boot run status cleanup logs`, a wrong argument count, or a selection other than `stand`, `all` or an existing `^[a-z0-9_]+$` test-file stem prints usage and exits 2 before any cargo call. Also added the §Logging & Monitoring rule that agent-run events carry harness metadata only, with no content-named field, and raw output stays in gitignored `target/agent-run/run.log`. Its "Kept" recorded no port, socket or env var. This binds the chunk if the fresh-process check runs through `scripts/agent-run.sh`. Ids carry author content and must not become an `events.jsonl` field. Widening the selection or verb set would be an amendment, not a silent change.
- **2026-10-06-telemetry-bootstrap** — Recorded escher's stderr sink with its allowlist scrub: engine targets print only `node_id`, `status`, `waiting_nodes`, `property` and the `log.*` fields, and content-named fields are redacted everywhere. It also added `RUST_LOG` to §Secret Management → Environment values read. That gives the list the extract cites (`WPT_DIR`, `PAINT_TREE_BENCH_HTML`, `HOME`, `CARGO_MANIFEST_DIR`, `RUST_LOG`). This is the precedent for the chunk: a fresh-process handoff that reads a new env var (for example a child-mode flag or an output path) must be registered in that list. And an id or author `id` value logged as a new `tracing` field falls outside the allowlist.
- **2026-10-06-cold-agent-run-pipe** — This is the precedent that a spawned process and its stdio channel are a registered crossing. The `claude` client and its stdio-only MCP stub were recorded as a security-plan amendment first. It was ruled a Boundary widening, ratified PROVISIONAL, with its argv bounded to an allowlist (exit 2 before any call) and no argument value logged. If the fresh-process check spawns a child process (child test binary, re-exec with a filter) and reads an id list back over stdout or a file, this entry is the bar for deciding whether that is a new crossing to register or stays within test-internal process use.
- **2026-10-05-ci-gate-legs** — Set up the cargo-deny audit leg (`deny.toml`; per-ID ignores only with a written reason; `--locked`). It recorded that the audit only reaches cargo-deny's resolved graph, which prunes `http-cache` and `ravif`, so the paste and memmap2 advisories are missed. This applies if the chunk adds a process-spawn or serialization crate for the fresh-process handoff: the audit leg must pass and the crate also needs a hand review.
- **2026-10-06-headless-stand** — Split the `disabled` row. It is parsed as a bool only for focusability. Its presence alone, `disabled="false"` included, sets the DISABLED state and blocks pointer selection and click default actions. This matters because the scope names a `disabled` toggle as a re-render that can change tree shape. A re-render check that toggles `disabled` should expect presence semantics, not the attribute's value.
- **2026-10-06-upstream-sync-element-identity** (root-manifest citations re-pointed after the line-61 insert) — Fixed two root `Cargo.toml` citations that had read one line low, because the headless-stand wrap never re-pointed them after its insert.
