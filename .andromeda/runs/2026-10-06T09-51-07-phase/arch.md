# arch extract

## Relevance
relevant. The chunk proves the §Standard Contracts → Dioxus DOM bridge "stable element ids" contract over time. Its code sits in three places: `tests/blitz-tests`, `seven_guis` (stand/app/crud) and possibly `dioxus-native-dom`'s crate-private `element_id` module (arch §Existing Scopes).

## Constraints
- The id contract the proofs measure is fixed by arch §Standard Contracts → Dioxus DOM bridge (stable element ids). It sets the `element_id(NodeId) -> Option<String>` / `element_ids() -> Vec<(NodeId, String)>` signatures. `element_id` returns `None` for a non-element, stale or detached node and never panics. Ids are pairwise distinct, in document pre-order. They are computed on demand and written to neither the DOM nor the vdom. No `NodeId`, `ElementId`, `ScopeId` or pointer may enter an id. The grammar has three tiers: author key, then component path (`{name}:{k}`, `{tag}[{key}]`, `{tag}:{n}`), then document path. The positional parts (`{tag}:{n}`, `{name}:{k}`) are named there. Any grammar change this chunk forces must be amended into that section at wrap. Otherwise the grammar is this chunk's input.
- arch §Established Decisions → [Node identity] and §Design Philosophy ("One incremental pipeline, safe identities") require `NodeId` to stay a versioned slot id whose dropped ids stop resolving. The remount proof depends on this. arch §Established Decisions → [DOM semantics] records that `node_id_mapping` entries are intentionally left uncleared so dioxus-core can reuse detached nodes. Whether a remount on the stand actually mints fresh `NodeId`s, or reuses detached ones, is research's question. A remount check that does not show a `NodeId` change is vacuous.
- arch §Standard Contracts → Headless stand (seven_guis, native only) requires these `stand` properties to hold: native-only; `boot`/`boot_timer` each build a fresh `VirtualDom` rendering `app::task_in_shell` at the pinned viewport with the bundled font; offline (`net_provider: None`); no telemetry, no env var read, no `blitz_net`. `TaskShell` stays private and `app::task_in_shell(Task, EventHandler<()>)` is the supporting API. A remount affordance has two options. It can be stand-side, inside the native-only module. Or it can go in shared `app.rs`, in which case it must keep the windowed and wasm builds rendering the same tree. Either option amends this contract row at wrap.
- arch §Occupied Resources → Process-wide state and threads registers process spawns (WPT's `git`, cold-agent's `claude`) and process-global statics (document-id and request-id `AtomicUsize`s, `LAYOUT_CTX`). A fresh-process check that spawns a child process (a child test binary or a re-exec) is a new spawn and gets recorded there at wrap. arch §Occupied Resources → Environment variables lists the env vars read. Signalling child mode through a new env var is a registration, never a silent add. Whether any process-global counter leaks into an id is research's question.
- If the fresh-process check runs through `scripts/agent-run.sh`, arch §Standard Contracts → CI contracts requires its contract to stay intact: the five-verb grammar `boot | run {stand|all|name} | status | cleanup | logs`, run from the repo root, exit grammar 0/1/2/3, JSON-line events, state only in `target/agent-run/`, and pinned by `test_agent_run.py` under the `ci-scripts` leg.
- arch §Conventions → Tests requires: one behaviour per integration-test file in `tests/blitz-tests/tests/`, each opening with a `//!` doc naming the behaviour; scenarios run `for incremental in [false, true]`; and each test first asserts that its fixture produces the condition under test.
- arch §Conventions → Manifests and §Inherited Defaults require dependencies declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }`, with `seven_guis` remaining blitz-tests' dev-dependency path entry. arch §Occupied Resources → Names lists the crate names, and adding a new workspace crate is a registration.

## Patterns to follow
- Stand checks boot through `seven_guis::stand::boot(LeanTask, stand::options(incremental))` and read ids via `Harness<DioxusDocument>` (arch §Standard Contracts → Headless stand; §Standard Contracts → Test harness). The timer task drives re-render deterministically through `boot_timer` → `TimerTicks::deliver(n)`, never wall-clock.
- Input is synthesized through the harness's real event-dispatch pipeline (`click`, `type_text`, `pump`) to cause re-renders (arch §Design Philosophy → Headless, measurable, testable; §Standard Contracts → Test harness).
- Stable identity across reconstruction follows the existing in-engine precedent: an identity must not ride on regenerated ids. Selection endpoints store parent plus sibling index because anonymous ids change (arch §Established Decisions → [Selection, animation, pseudo-elements]), and interaction state references DOM nodes only (arch §Design Philosophy → One incremental pipeline, safe identities).
- Lean-task author keys go through the HTML `id` (tier 1 of the grammar). Dioxus list rows use a Dioxus key, read as `{tag}[{key}]` (arch §Standard Contracts → Dioxus DOM bridge).

## Anti-patterns to avoid
- Never let a `NodeId`, `ElementId`, `ScopeId`, pointer or process-global counter enter an id. Never write the id into the DOM or the vdom (arch §Standard Contracts → Dioxus DOM bridge).
- Never index a possibly stale `NodeId` directly. Use `get`/`contains_key`, because stale indexing panics with "invalid SlotMap key used" (arch §Standard Contracts → Scrolling, selection, tree).
- Never add a listener, port, env var or workspace crate silently, including for cross-process id transfer. Any of them is an arch §Occupied Resources registration (arch §Occupied Resources → Network ports and listeners; → Environment variables).

## Contract bindings
- arch §Standard Contracts → Dioxus DOM bridge ↔ tests: the persistence checks in `tests/blitz-tests/tests/stand_*.rs` and the existing `stand_element_ids.rs` assertions consume the id grammar. A CRUD row re-key changes the expected row ids there.
- arch §Standard Contracts → CI contracts (agent-run) ↔ tests (test-plan §3, `test_agent_run.py`): this binding is live only if the fresh-process check is routed through `agent-run.sh`.
- arch §Occupied Resources (process spawns, env vars) ↔ security (security-plan surfaces): a child-process spawn or a new env var for the fresh-process check is registered in both.
- arch §Standard Contracts → Dioxus DOM bridge ↔ a11y: the id on accessibility nodes is v010-03 and out of this chunk. The id stays dioxus-native-dom-only here.

## Acceptance criteria contributions
- Each persistence behaviour has its own `tests/blitz-tests/tests/stand_*.rs` file with a `//!` doc. Each check runs for `incremental in [false, true]` and first asserts the event happened before comparing ids: the DOM changed on re-render, the `NodeId`s differ on remount, and the process ids differ on fresh process (per arch §Conventions → Tests).
- `element_ids()` keeps its contract on every pre- and post-event read: ids pairwise distinct, no id containing a `NodeId`/`ElementId`/`ScopeId` rendering, and `element_id` returning `None` without panic for removed or detached nodes. Any grammar or keying change is recorded in arch §Standard Contracts → Dioxus DOM bridge at wrap (per arch §Standard Contracts → Dioxus DOM bridge).
- `seven_guis::stand` keeps its contract: native-only, fresh `VirtualDom` per boot, pinned viewport, bundled font, offline, no env var, no telemetry. Any remount affordance is recorded in that contract row, and `seven_guis` still builds and renders on its windowed and wasm targets (per arch §Standard Contracts → Headless stand).
- No new port, listener, env var or workspace crate is added. A child-process spawn, if one is used, is registered in arch §Occupied Resources → Process-wide state and threads. If `agent-run.sh` is used, its five-verb grammar and `test_agent_run.py` stay green (per arch §Occupied Resources; §Standard Contracts → CI contracts).
