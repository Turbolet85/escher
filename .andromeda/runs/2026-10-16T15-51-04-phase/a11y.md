# a11y extract

## Relevance
partial — a no-behaviour-change refactor with no new UI, key binding, colour or role; it touches the a11y surface only where the moved `document.rs` test modules prove the accessibility refresh contract and where `mcp.rs` / `schema.rs` carry the snapshot's a11y readings to a client.

## Constraints
- The tier stays `0 — SC 2.1.1 · 1.4.3 · 2.4.3`. A split must not change the `accessibility` feature's reach: escher-driver names `accessibility` on dioxus-native-dom unconditionally and has no `[features]` table of its own, and neither platform adapter (`accesskit_xplat`, `accesskit_winit`) is in the stand graph. So no manifest, feature or lockfile edge may move when `mcp.rs` and `schema.rs` become submodules (per a11y-plan §1 A11y Scope Summary).
- The engine's changed-set contract is proven at the document level by the `changed_set_` unit tests. This contract covers a focus change, a checked change and a rewritten name marking the set, hover and layout not marking it, and `has_changes()` reading true until `take_changed_nodes` drains it. Moving `changed_set_tests` out of `document.rs` must keep every assertion running and passing. Whether those tests reach only public API (and could become an integration target) or need `BaseDocument` internals (and must stay a child module) is research's question (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).
- In the changed-set contract, hover marks nothing. If `hover_state_tests` / `hover_invalidation_tests` move, they keep their assertions unchanged. Whether either one asserts the changed set is research's question (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).
- The plan cites upstream's focus and label-binding code in `document.rs` by line range: `focus_next_node` / `focus_prev_node`, `set_focus_to`'s FOCUS/FOCUSRING states, the focused-node fallback to the root, and focus reset when a node is removed. These are upstream's body and stay byte-for-byte as they are. Whether every cited range lies before the escher test modules being moved, and so keeps its line numbers, is research's question (per a11y-plan §5 Keyboard Navigation).
- An MCP tool result reads the snapshot model and nothing else, with no second role or name mapping. An accepted `snapshot` result is `to_text`'s output byte for byte. The `mcp.rs` split must keep this result path whole. The plan cites it as `packages/escher-driver/src/mcp.rs:460-535`, and the wrap re-points that citation (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- The boolean model's state words and its two limits are fixed text. The words are `selected` / `unselected`, `pressed` / `unpressed` and `invalid`. The limits: a mixed toggle reads not pressed, and a grammar or spelling error reads invalid. The node-key help in `schema.rs` (`NODE_FIELDS`, thirteen keys) states both. The `schema.rs` split moves that table text unchanged and adds no key (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- The `a11y` leg runs six files with fixed per-file test counts: accessibility_hidden 6 · accessibility_roles 6 · focusability_updates 4 · stand_accessibility_ids 8 · stand_contrast 5 · stand_keyboard 14. Its list and counts stay unchanged. A new blitz-tests target for the moved document tests does not join the leg (per a11y-plan §9 CI Integration).

## Patterns to follow
- Accessibility assertions are Rust tests in blitz-tests over the AccessKit tree, built after `resolve` (per a11y-plan §3 A11y Assertion Harness Contract).
- The stand's headless refresh check is `stand_accessibility_ids`: drain first, then step, then read `has_changes()` and the tree through `&dyn Document`, in both layout modes. It is the stand-level partner of the document-level `changed_set_` tests that move (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).
- Pipeline and stand checks run in both layout modes. Moved tests that carry the `for incremental in [false, true]` loop keep it (per a11y-plan §5 Keyboard Navigation, Test harness pattern).

## Anti-patterns to avoid
- Do not add a second role or name mapping anywhere in a moved MCP or schema module. Every reader takes role and name from the tree that `accessibility_tree` returns (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- Do not let a module split pull a platform adapter or a new `accessibility` feature edge into the stand's binaries (per a11y-plan §1 A11y Scope Summary).

## Contract bindings
- a11y ↔ tests CI: the `a11y` leg's file list is pinned by `LegScriptTest`'s a11y tuple in `.github/scripts/test_ci_workflows.py`. Its `stand_*` files also run three times in the `stand-repeat` leg (test-plan §10). A new blitz-tests target touches `.github/scripts/test_blitz_tests_targets.py` and not the a11y tuple (per a11y-plan §9 CI Integration).
- a11y ↔ driver surface: the MCP `snapshot` result equals `Session::run`'s screen text, pinned by `tests/blitz-tests/tests/stand_mcp_tools.rs` (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
