# arch extract

## Relevance
relevant — a no-behaviour-change restructure of two workspace crates' module trees (blitz-dom's `document.rs` test layout; escher-driver's `mcp.rs` and `schema.rs`), bound by the arch Conventions on test placement and by the driver's public-surface contract.

## Constraints
- The work stays inside the two existing crates, `blitz-dom` (`packages/blitz-dom`) and `escher-driver` (`packages/escher-driver`). No new workspace crate, env var, listener or dependency: a new crate name is a registration in the resource registry, never a silent add (per architecture §Occupied Resources → Names; per architecture §Occupied Resources → Network ports and listeners).
- The escher-driver crate root re-exports a fixed set of names from private modules under `#![deny(missing_docs)]`: 45 at the plan's count, among them `serve_mcp`, `VERBS`, `NODE_FIELDS`, `validate`, `validate_session`, `describe` and `EXIT_STATUSES`. A split must keep that set and its paths unchanged, and keep every new submodule private. Whether the count still reads 45 in the code is research's question (per architecture §Standard Contracts → Driver session (escher-driver)).
- The three schema modules (command, refusal, schema) carry no `cfg` gate and use no serialization crate. Every file split out of `schema.rs` has to keep both properties. The MCP server reads requests with `serde_json` and writes nothing with it; every reply goes through the hand-written JSON forms. Splitting `mcp.rs` must leave that unchanged (per architecture §Standard Contracts → Driver session (escher-driver)).
- The MCP server's wire contract stays byte-for-byte: the four handshake revisions, `tools/list` in `VERBS` order with `help` last, each description's `. Returns: ` field text, the result shapes, the protocol errors and the bounds (65,536-byte request line, 1,048,576-byte result). A seam split moves code and does not alter any of these (per architecture §Standard Contracts → Driver session (escher-driver)).
- escher-driver builds its two spans by hand with `tracing::info_span!`: `command` in execute, and `tool_call` in mcp as the parent of `command`. There is no `#[instrument]` and no `cfg(feature = "tracing")` gate. Moving the `tool_call` site into a submodule must keep it ungated, hand-built, and keep the same fields (per architecture §Conventions → Feature gating).
- Upstream's body of `document.rs` stays byte-for-byte. The plan records the upstream merge base the next sync merges from, so a smaller escher-owned diff keeps that sync additive (per architecture §Project Intent → Upstream sync).
- The change passes the code-quality gates that every crate is held to: `cargo fmt --all --check`, workspace clippy `--locked -D warnings`, upstream's blitz-dom clippy line under its feature list with `--all-targets` (which builds blitz-dom's test modules), and rustdoc `-D warnings` over every workspace crate (per architecture §Inherited Defaults → Code quality; per architecture §Conventions → Formatting and lints).

## Patterns to follow
- An existing unit-test module already lives in a file of its own. It is declared at the end of the file under test as `#[cfg(test)] #[path = "…_tests.rs"] mod …;`, a child of the module under test, so it reaches private fields without adding a constructor, `pub` or a `cfg(test)` shim. dioxus-native-dom's `bridge_tests` in `dioxus_document_tests.rs` is the precedent for moving `document.rs`'s escher-owned test modules (per architecture §Conventions → Tests; per architecture §Existing Scopes → dioxus-native-dom).
- The default placement is a `#[cfg(test)] mod tests` at the end of the source file, and `document.rs:2897` is listed among those sites. The split replaces only the inline body of escher's modules; the module stays a child of `document` (per architecture §Conventions → Tests).
- Modules and files open with `//!` docs and public items carry `///`. Each new submodule file of `mcp.rs` and `schema.rs`, and each moved test file, opens with a `//!` line naming its seam (per architecture §Conventions → Documentation).
- Crate internals use `pub(crate)` / `pub(super)`. Items that move into submodules widen only as far as their sibling modules need, never to `pub` (per architecture §Conventions → Visibility and naming).
- Upstream's paint crate is split one module per concern. Use the same shape for the seams of `mcp.rs` (framing and bounds · tool listing · tool-result writing) and `schema.rs` (verb table · help texts); research verifies those seams in the code (per architecture §Conventions → Visibility and naming).

## Anti-patterns to avoid
- Do not move escher's document tests into a new `[[test]]` table or a non-discovered target. The blitz-tests manifest holds exactly one `[[test]]` table (`all`, `test = false`) with autotests on, and that is pinned by `test_blitz_tests_targets.py`. A new auto-discovered integration file changes that leg's discovered count, which must then be re-read (per architecture §Standard Contracts → CI contracts).
- Do not make a private `BaseDocument` item `pub` so that a moved test can reach it. The child-module pattern exists so that no `pub` or `cfg(test)` shim is added (per architecture §Conventions → Tests).

## Contract bindings
- arch ↔ obs: the `command` and `tool_call` span sites and their fixed fields are an obs-plan contract. A move between files must keep the span names, the target `escher_driver`, the parent and child nesting, and the field sets (per architecture §Conventions → Feature gating; per architecture §Standard Contracts → Driver session (escher-driver)).
- arch ↔ tests: the blitz-tests target contract (`test_blitz_tests_targets.py`, the `ci-scripts` leg) binds wherever the document tests land outside `src/`. The stand and MCP checks (`stand_mcp_*`, `mcp_server`, `mcp_log`) are the external proof that the MCP wire and results did not change (per architecture §Standard Contracts → CI contracts; per architecture §Standard Contracts → Driver session (escher-driver)).
- arch ↔ security: the MCP bounds and the rule that `serde_json` writes nothing are also security-plan §Input Validation rows. A split must not loosen either (per architecture §Standard Contracts → Driver session (escher-driver)).
- arch ↔ docs: the plan's §Existing Scopes row lists escher-driver's fourteen private modules by name. New submodules change that row and the CLAUDE.md module and pointer rows at the wrap's reconcile (per architecture §Existing Scopes → escher-driver).
