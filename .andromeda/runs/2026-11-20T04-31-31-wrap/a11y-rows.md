decision/a11y-tree-refresh-on-change · Accessibility tree refreshed on change — The accessibility tree is built from the document when first requested and pushed again in a redraw, after style resolve, only when the changed set is non-empty, the set then cleared; a poll pushes no tree. · why: Ratified, one item with the engine's changed-set contract. · guard: stand_accessibility_ids · r2
decision/a11y-tree-through-document-trait · Accessibility tree through the document trait — Both the initial build and the refresh of the platform accessibility tree go through the document trait's accessibility tree method. · why: So a wrapper's override, such as DioxusDocument's stable ids, reaches the platform tree. · r1
decision/agent-readers-behind-accessibility · Snapshot readers behind the accessibility feature — The snapshot, its text and diff, the unkeyed-actionable check, the UI graph reader and the actionable-node reader stand behind dioxus-native-dom's accessibility feature; the signal registry and the reached-handler record are not gated. · r1
decision/aria-description-to-adapter · ARIA description to the platform adapter — The aria-describedby and aria-description attributes reach the platform adapter as the node's description; the snapshot reads no description. · why: Ratified as upstream's behaviour. · guard: accessibility_description · r1
decision/aria-labelledby-outranks-label · aria-labelledby outranks label and aria-label — The aria-labelledby attribute sets the accessible name from the referenced nodes' text, outranking a label element and aria-label, with aria-label the fallback when the targets hold no text. · why: Upstream's behaviour, kept and ratified (accname 2B). · guard: accessibility_label · r1
decision/aria-state-lower-case-closed-values · ARIA state values matched in lower case — Each ARIA state value is trimmed of ASCII whitespace and compared exactly in lower case against its closed set; an unrecognized value sets nothing, but for aria-invalid, where any value other than absent, empty or false reads true. · why: The lower-case match is a choice, the specification as read stating no case rule; aria-invalid follows WAI-ARIA 1.2's rule. · guard: accessibility_states · r1
decision/aria-states-on-every-element · ARIA states written on every element — The accessibility builder writes the selected, toggled and invalid states from ARIA state attributes on every element, and an element whose role does not support an attribute reads it as one whose role does. · why: Ratified. · guard: accessibility_states · except: A select's option, whose selected state is its chosen state, with no aria-selected read. · r1
decision/changed-set-marks · What the engine's changed set marks — The engine's changed set marks a mutation of an in-document node, a focus or checked change, a text control's input, a select's changed choice and a single select's list opening or closing, a scroll that closes a list included; node creation, hover, active, any other scroll and layout do not. · why: Ratified, one item with the accessibility tree's refresh on change. · r2
decision/harness-settle-leaves-changed-set · Harness settle leaves the changed set — A harness settle neither reads nor drains the changed set, and a freshly booted harness document holds a non-empty set, so a check that reads the set as what one step changed drains it first. · why: A settled step leaves the refresh and a later diff exactly what the step marked. · guard: stand_settle · r1 · stale
decision/native-checkable-toggle · Native checkbox toggle from its checked state — A native checkbox or radio on a checkable role writes toggled true or false from its own checked state, and under any other role writes nothing. · guard: a_click_and_a_space_move_a_native_control_in_the_tree · r1
