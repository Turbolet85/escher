@task_prose part=chunk
Builds one exploration command over a held app: from boot it enumerates the actions available on the screen and drives them breadth-first, each path re-reached from a fresh session, the frontier ordered by path length, until a step budget is spent, then returns a closed report.
Every step runs as a validated call through the driver's one run path; refusals are caught by their closed cause and panics inside a step as a closed word, the path kept, neither stopping the exploration.
Each explored path is left as an owner-only kept check in the recorded-check format, with no screenshot step, that replays green; that step format is versioned and can carry a verb with more than one target as an addition.
Exploration reads the default seed alone; navigation and the carriers that reach the command are the founder's forks, held at their most conservative provisional reading.
Proven on the stand's served tasks in both layout modes, on a fixture whose handler panics and on one holding a refusing control.
@task_item n=1 part=needs
The available actions come from the driver's own readers, never a hand list: the actions answer offered on a node and the schema's verb table; a verb exploration drives is one the table holds and the actions answer offers.
@task_item n=2 part=needs
Actions are decided by the verbs' own checks: what exploration treats as available is exactly what the actions reader reports, and the actions line's nodes, content and stale markers are read as that reader gives them.
@task_item n=3 part=needs
Every explored step is a validated call through the session's one run path, as the reach call does; no second executor.
@task_item n=4 part=needs
A refusal met on a step is caught and reported by its closed cause from the driver's refusal set; the exploration continues.
@task_item n=5 part=needs
A panic raised inside a step's handler is caught and reported as a closed word with the path that led to it kept; the exploration continues.
@task_item n=6 part=needs
Breadth-first order within a step budget: each path re-reached from a fresh session from boot, the frontier ordered by path length, the report closed when the budget is spent.
@task_item n=7 part=needs
Each explored path is kept as a recorded check in the existing recording format: owner-only (0600 file in a 0700 launcher-named directory), a group- or other-open directory refused the same way as for kept checks today, and the check replays green.
@task_item n=8 part=needs
No screenshot step in an explored path and no pixel at rest: exploration never drives the screenshot verb.
@task_item n=9 part=needs
The recorded-check step format is versioned: a kept check states its format version, and a step can carry a verb with more than one target as an addition to the format, not a redefinition.
@task_item n=10 part=needs
The verbs exploration drives are read from the schema's verb table, never a closed list in exploration's own code, so a future verb such as drag is driven with no reshaping; drag and any two-target verb's production are not built here.
@task_item n=11 part=needs
Exploration reads the default seed alone, as every driver session does: no seed argument on any carrier; a later seed argument is an addition to the command's arguments with no rework.
@task_item n=12 part=needs
Navigation is a boundary fork held provisionally at its most conservative reading: an action that would navigate the document (a link, a form submission to another URL) is not driven or the step not taken, and nothing new is loaded.
@task_item n=13 part=needs
Which carriers reach the command (in process only, a binary role, a driver verb on the command line, MCP and the socket) is a founder's fork; a new verb or role on a carrier is a widening, held at the most conservative provisional reading.
@task_item n=14 part=needs
Untrusted input to the command (the step budget, the check directory) is refused as typed values, with no panic path.
@task_item n=15 part=needs
No new log field carrying content; a span, if any, holds fixed words and counts only.
@task_item n=16 part=needs
Driven verbs run on the driver's virtual clock as click, press and type do today, so an explored path replays to the same state.
@task_item n=17 part=needs
Proof on the stand's served tasks (counter, crud, cells, flight-booker, timer and the rest) in both layout modes, and on a fixture that panics in a handler and one that holds a refusing control.
@task_item n=18 part=needs
