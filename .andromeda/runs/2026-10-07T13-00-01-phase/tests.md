## Constraints
- Test tier is `0`; the tier justification, critical-path list and coverage triggers read NOT YET MEASURED, so the tier sets no breadth floor for this chunk — breadth comes from the scope's owed proofs (per test-plan §1 Test Scope Summary → Test tier).
- Every new stand check that reads a screen is required to hold in both layout modes and to call no sleep and no clock read of its own; a session-held check boots through `seven_guis::stand` on one `escher_driver::Session` (per test-plan §5 Integration Test Strategy → Session ↔ held instance).
- A stand check has no font-skip path: it asserts unconditionally under the bundled font with system fonts off, passed through the stand's pinned options (per test-plan §2 Test Strategy → Font-dependent tests; per test-plan §7 Test Data & Fixtures → Builders and options, `seven_guis::stand::options`).
- Timer time in a check moves only through the `TimerTicks` stand-in: a delivery is applied on the next pass, and settle neither advances the timer nor waits on an undelivered tick — the wiring of `advance` (CARRY 7) and the Timer proof (CARRY 6) are required to stay inside that model; whether `Harness::tick` moves with it is research's question (per test-plan §8 Mocking & Stubbing Discipline → Time (seven_guis timer)).
- A check that needs a session process (the socket answer, or CARRY 4's typed sentinel) is required to start and stop its own host, bound every wait, hold the host behind a kill-and-reap guard, keep its state directory under `CARGO_TARGET_TMPDIR`, send the child's streams to null unless it reads them, and be `cfg(unix)`-gated; a capture of a sink-installing host drains its pipes while the host runs (per test-plan §2 Test Strategy → Process-lifecycle checks; per test-plan §3 Session lifecycle → `session-checks`).
- The keyed contract states the lifecycle wire as `hello` and `stop` only and `act` as in process, with nothing of the screen crossing the socket; a chunk answer that carries a command across it changes `session-wire`, `session-start` and `session-binary` and must be proven by the session checks, not assumed (per test-plan §3 Session lifecycle → `session-wire`; per test-plan §3 Session lifecycle → `session-start`).
- The plan's as-written statements this chunk's delivery moves are re-derivation targets, not facts to build on: "no test drives the schema through a `Session`" (per test-plan §4 Unit Test Strategy → escher-driver), "typed text is not measured" (per test-plan §5 Integration Test Strategy → Session host ↔ what it writes; per test-plan §3 Test Harness Contract → Stand log format), "none drives the UI through that binary" (per test-plan §6 E2E Test Strategy → Observed absent), and the `session-proof` counts (per test-plan §3 Session lifecycle → `session-proof`). ## Patterns to follow
- Executor unit tests sit inline in a `#[cfg(test)] mod tests` beside the code, each table stated in its test with its row count asserted, and every assertion over a call carrying a row index only, so a failing log prints no argument value (per test-plan §4 Unit Test Strategy → Conventions, Test file location; per test-plan §4 Unit Test Strategy → escher-driver).
- New integration checks are one test-target file per behaviour named `stand_*.rs` under `tests/blitz-tests/tests/`, so `run stand` selects them by prefix with no script change (per test-plan §2 Test Strategy → Directory pattern; per test-plan §3 Agent-run contract → `run {selection}`).
- Session-held checks read the shared modules rather than restating them: `session_common` for `slug` · `hold` · `change` and the process-side `state_dir` · `host_command` · `Host` guard, `common` for the control tables and `by_id` / `tree_node` helpers — the tables are stated expectation, never a second role or name mapping; whether `hold` and `change` fit a command executor as they stand is research's question (per test-plan §3 Test Harness Contract → Crate-local test helpers, blitz-tests (session checks); per test-plan §3 Test Harness Contract → Crate-local test helpers, blitz-tests (stand checks)).
- A case the four lean tasks lack (a checkbox, a password, a hidden element) is an in-file fixture booted with the stand's options, not a new stand task (per test-plan §1 Test Scope Summary → tests/blitz-tests; per test-plan §7 Test Data & Fixtures → Seed strategies, Inline HTML).
- The typed-sentinel proof, if owed here, follows `host_log`'s shape: the real `escher-session` binary at `RUST_LOG=trace`, needles read from the stand booted in the test's own process, both streams drained from the spawn on, the session reached with `attach` under a bound and never `start`, a failure printing a kind and a count only (per test-plan §5 Integration Test Strategy → Session host ↔ what it writes).

## Anti-patterns to avoid
- test-plan §11 Test Anti-Patterns reads NO RECORDED INTENT, so nothing is drawn from it; the bans below are stated in other sections.
- Never wait for a sink-installing host's exit before reading its stderr, and never let a host child's own libtest lines reach the parent's output, where `agent-run.sh` would count them as tests (per test-plan §2 Test Strategy → Process-lifecycle checks).
- Never read a zero from a host that installs no log sink as proof about one that does — `stand_session_quiet`'s host is inert to `RUST_LOG`, so an in-process `type` proves nothing about the `escher-session` binary's stderr (per test-plan §3 Session lifecycle → `session-checks`; per test-plan §5 Integration Test Strategy → Session host ↔ what it writes).
- Never let a test wait on or advance Timer time by a sleep, a clock read or an undelivered tick; and never assert only inside a condition on a measured value, which passes without asserting (per test-plan §8 Mocking & Stubbing Discipline → Time (seven_guis timer); per test-plan §4 Unit Test Strategy → Conditional assertions).

## Contract bindings
- tests ↔ obs: the stand log format and the target allowlist the `escher-session` binary's stderr is checked against are obs-plan §3 and §8; CARRY 4's typed-sentinel proof is where the "typed text is not measured" clause is first measurable (per test-plan §3 Test Harness Contract → Stand log format).
- tests ↔ obs: the agent-run events are harness metadata, not an escher-telemetry sink, and nothing between a `failures:` line and the next `test result:` reaches an event — so a failing executor check's panic text stays in `run.log` (per test-plan §3 Agent-run contract → Events).
- tests ↔ security: the wire's grammar and its "no id, name, value, snapshot text or diff crosses" clause are asserted by the session checks; a command that crosses is a security-plan §Input Validation / §API Security amendment before a check pins it (per test-plan §3 Session lifecycle → `session-wire`).
- tests ↔ security: the row-index-only assertion rule is the test-side half of "a refusal holds nothing of the call" (per test-plan §4 Unit Test Strategy → escher-driver).
- tests ↔ architecture: the session API the checks drive is architecture §Standard Contracts → Driver session; the keyed contract cites it and moves with it (per test-plan §3 Session lifecycle).
- tests ↔ a11y: snapshot- and diff-reading unit tests in `dioxus-native-dom` compile only under the crate's default `accessibility` feature, so CARRY 5's feature decision in `escher-driver` decides whether the executor's own tests can read a snapshot at all; the a11y CI leg's three files are unchanged by this chunk (per test-plan §1 Test Scope Summary → dioxus-native-dom; per test-plan §9 CI Integration → Legs).
