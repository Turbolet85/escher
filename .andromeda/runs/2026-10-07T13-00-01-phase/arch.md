# arch extract

## Relevance
relevant — the chunk lands the first code that runs a `Command`, inside a crate, a contract and a resource boundary the plan states in full (architecture §Standard Contracts → Driver session; §Established Decisions → [Driver session]; §Occupied Resources → Network ports and listeners).

## Constraints
- **Placement and dependency direction.** architecture §Established Decisions → [Driver session] requires the session library to take the app's boot from its caller and depend on no app: the executor belongs in `packages/escher-driver`, no manifest under `packages/` may name an example, and the one edge stays `seven_guis → escher-driver`. So the `advance` step is handed to the session by its caller, and the stand's mapping of milliseconds onto Timer ticks belongs in the host binary — the place architecture §Existing Scopes → seven_guis names as the one where a lean task, the stand's boot, the tick handle and a `Session` meet. The library must name no Timer, no `TimerTicks` and no stand type (architecture §Standard Contracts → Driver session).
- **The socket carries lifecycle only.** architecture §Occupied Resources → Network ports and listeners requires that no element id, accessible name, control value, snapshot text or diff crosses `session.sock`, and records the listener itself as a boundary widening that took the founder's choice. A verb, a result or a busy reply on the wire is therefore a registration in that section (and in architecture §Standard Contracts → Driver session, which states the wire's grammar and its 64- and 128-byte bounds) before the code lands — never a silent add. Under the in-process answer the section stays as written. The scope's fork is not decided by the plan; the plan only prices each side.
- **No new resource.** architecture §Occupied Resources → Environment variables and architecture §Occupied Resources → Names require a new env var, crate, binary or feature name to be recorded; architecture §Established Decisions → [Driver session] requires the library to read no env var, to have no default state location, and to use no third-party IPC, named-pipe, pid-file or daemonizing crate and no TCP or UDP port. architecture §Standard Contracts → Driver session adds that the schema modules use no serialization crate — a wire form for a result would be the first, and is a dependency decision the plan names.
- **The `accessibility` feature is this chunk's decision.** architecture §Established Decisions → [Driver session] states that `escher-driver` names no `dioxus-native-dom` feature and that the entry that first reads the snapshot through a session decides it. architecture §Standard Contracts → Dioxus DOM bridge states that the snapshot, its diff and the `author_id` override exist only under `accessibility` and that a crate taking the Dioxus crate at the workspace pin (`default-features = false`, architecture §Conventions → Manifests) gets them only by naming the feature — and that `seven_guis` names none. Naming it in `escher-driver` reaches `seven_guis` through the recorded edge (architecture §Occupied Resources → Names); what the windowed stand binary builds today is research's question, and what it should build is the a11y plane's.
- **One schema, validated first.** architecture §Standard Contracts → Driver session requires the verb table to be the single statement of each verb's arguments and result fields, `validate` to receive no `Session` so a refused call changes nothing, the cause set to stay closed at eight, and a `Refusal` to hold nothing a call supplied. The executor takes a `Command`, never a `Call`; each acting verb's result is the fields the table lists and no other; a step that ran and did not go quiet is a result with its busy class, not a refusal — while `Session::act` is stated to map that case onto `SessionError::NotSettled`. Which of the two shapes the new entry point returns, and whether `act`'s own signature moves, is a contract edit the plan must name.
- **The diff is the snapshot's, not the engine's.** architecture §Standard Contracts → Dioxus DOM bridge requires the diff to be a pure function of two `Snapshot` values, with values from the snapshots only (a password's or a file input's value reads the mask) and no `NodeId`, `ElementId`, `ScopeId` or tree id in any field. architecture §Cross-cutting Patterns → Invalidation and state integrity requires the changed set to be treated as engine-touched — a superset, with the flag true beside an empty diff a designed case — and architecture §Standard Contracts → Driver session states that the session neither reads nor drains that set. The same Dioxus DOM bridge contract states the diff leaves the process through the returned value only; the first command that returns it re-opens that ratified answer.
- **Ids are computed, never stored; node ids may be stale.** architecture §Standard Contracts → Dioxus DOM bridge requires the stable id to be computed on demand and written to neither the DOM nor the vdom, and states that a detached node reads no id. architecture §Standard Contracts → Driver session states the session holds a label and the harness only — no `NodeId`. architecture §Established Decisions → [Node identity] and architecture §Design Philosophy → One incremental pipeline, safe identities require a `NodeId` that may be stale to be read through `get`, never by indexing. So an id is resolved to a live node inside the step that uses it, and nothing resolved survives the command.

## Patterns to follow
- **The settled step.** Build on `Session::act` and `Harness::settle` as stated — one step on the held instance, then every due pass, then `Settled` or the busy class — per architecture §Standard Contracts → Driver session and architecture §Standard Contracts → Test harness. The same Test harness contract requires settle to neither wait on nor advance a source only time moves, and states `pump`, `tick` and every input helper settle nothing; time moves only by the caller's step.
- **Input through the real dispatch pipeline.** architecture §Design Philosophy → Headless, measurable, testable requires synthesized input to route through the engine's event dispatch. architecture §Standard Contracts → Events states keyboard and IME events target the focused node and pointer events the hovered node, falling back to the root — the fact `press` (which names no element) and a click on a resolved node both stand on. architecture §Established Decisions → DOM semantics states the pointer click target keys on the `disabled` attribute's presence, the same reading the snapshot's `enabled` field carries.
- **Crate shape.** Private modules re-exported at the crate root under `#![deny(missing_docs)]`, every public item documented, errors as closed enums with `Display` and fixed strings that carry no path, label, id or value — per architecture §Standard Contracts → Driver session, architecture §Conventions → Documentation and architecture §Conventions → Error handling.
- **Checks.** Unit tests inline at the end of the source file; one behaviour per integration-test file under `tests/blitz-tests/tests/`, each scenario in both layout modes, the session checks sharing `tests/session_common/mod.rs`; a check that needs the built `escher-session` binary lives in the seven_guis crate's own test targets beside `host_binary` and `host_log` — per architecture §Conventions → Tests and architecture §Existing Scopes → seven_guis.
- **The host stays one thread.** architecture §Occupied Resources → Process-wide state and threads states the `escher-session` host is one process holding one session and one listener on its main thread and spawning no thread; a time step handed to the session keeps that shape.

## Anti-patterns to avoid
- Deriving the returned diff from `take_changed_nodes`, or draining the changed set inside a session step — the plan assigns the drain to the windowed shell and calls the set a superset of what a snapshot reads (architecture §Cross-cutting Patterns → Invalidation and state integrity; architecture §Standard Contracts → Document core).
- Printing, logging or putting in a field a `Command`, a `Call` or an `ArgValue` — their `Debug` prints the id and the typed text — or giving `escher-driver` a `tracing` dependency, span or event (architecture §Standard Contracts → Driver session; architecture §Established Decisions → [Driver session]).
- A second id or role computation beside `element_ids()` and the accessibility tree, or an id kept in the DOM, the vdom or the session (architecture §Standard Contracts → Dioxus DOM bridge).

## Contract bindings
- **arch ↔ security.** Any change to what crosses `session.sock`, and the first return of a diff from a command, bind architecture §Occupied Resources → Network ports and listeners to security-plan §Input Validation and §API Security; validate-before-run binds architecture §Standard Contracts → Driver session to the same.
- **arch ↔ a11y.** The feature decision binds architecture §Established Decisions → [Driver session] to a11y-plan §1: whether the windowed stand binary builds AccessKit follows from where the feature is named.
- **arch ↔ obs.** `escher-driver` silent, the two seven_guis binaries the only sink installers (architecture §Cross-cutting Patterns → Logging and timing) — a typing command that reaches the host binary's instance is what obs-plan's scrub claim is measured against.
- **arch ↔ tests.** architecture §Standard Contracts → Driver session states the re-export count, the module list and a "Not built" list (anything that runs a `Command`, act by id); a new public name, module or entry point moves all three and the unit-test count the test plan states. Amended at wrap.
- **Not covered by this plan.** The plan holds no statement on a macOS Backspace arm in the text editor or on a range input's interaction model; architecture §Standard Contracts → Nodes and widgets lists the special element data kinds and names none for range. Whether the code takes typed deletion headlessly on every platform, and whether a range input can be driven, are research's questions.

## Acceptance criteria contributions
- (arch) The code that runs a `Command` lives in `packages/escher-driver`; its manifest names no app, no example and no dependency beyond blitz-test-harness and dioxus-native-dom, and any feature it names on either is recorded as the chunk's decision (per architecture §Established Decisions → [Driver session]).
- (arch) After the chunk the workspace has no new listener, port, env var or crate, and the wire reads `hello` and `stop` only — or, under the socket answer, every new request and reply form is registered before the code lands (per architecture §Occupied Resources → Network ports and listeners).
- (arch) An acting verb's return holds exactly the result fields the verb table lists, its `added` · `removed` · `changed` equal to `Snapshot::diff` of the snapshots taken before and after the step, equal across the two layout modes and empty for a step that changes nothing (per architecture §Standard Contracts → Dioxus DOM bridge).
- (arch) No session field, result field or error message holds a `NodeId`, and no step reads or drains the changed set (per architecture §Standard Contracts → Driver session).
