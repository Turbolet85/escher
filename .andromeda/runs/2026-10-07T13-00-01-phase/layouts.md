## Patterns to follow
- One mount, several consumers: the plan records the headless stand, the stand checks and the `escher-session` host as consumers of the same `task_in_shell` mount, each booting through `seven_guis::stand` only (layout-templates §Surface: desktop-native → Primary screens, the seven_guis Home and TaskShell bullet). An in-process executor check and a host-side one boot the same way; neither builds its own markup.
- The stand skips Home: a held instance mounts one lean task in TaskShell and Home's task cards are not on it (layout-templates §Surface: desktop-native → Primary screens, the seven_guis Home and TaskShell bullet). `back-btn` is on the mount, in the header; what a `click` on it does on a held instance with no Home is research's question before any check targets it.
- The harness's default viewport is the stand's pinned one (layout-templates §Surface: desktop-native → IA notes, the test-harness bullet), and every document starts from the fixed `main#main` skeleton the app mounts into (layout-templates §Surface: desktop-native → IA notes, the fixed-skeleton bullet). A minimal fixture for a case the tasks lack inherits both; it pins nothing of its own.
- The agent-facing scripts on this surface keep one stdout grammar — JSON lines only, raw output kept in a file under `target/` — and the host keeps another: no stdout at all (layout-templates §Surface: cli → Primary screens, the `scripts/agent-run.sh`, `scripts/cold-agent.sh` and `escher-session` bullets). A check that drives the host reads stderr and the exit code, as those bullets place them.

## Anti-patterns to avoid
- Giving the host a third argument, a flag or an env-read switch to carry the time step or a command, without the plan naming it: layout-templates §Surface: cli → Primary screens (the `escher-session` bullet) states the argv as closed.
- Printing an action's result, a diff or a snapshot text from the host to stdout as a shortcut for a check: layout-templates §Surface: cli → Primary screens (the `escher-session` bullet) requires an empty stdout on every path. JSON on stdout is "Driver CLI"'s, per scope.md §Boundaries.
- Adding an element, a wrapper, an id or a class to a lean task so an action has something to hit or a check something to read (a range stand-in for `timer-duration` under CARRY 2, a hidden tick button under CARRY 7): layout-templates §Surface: desktop-native → Primary screens (the seven_guis Home and TaskShell bullet) requires ids and the host to add no class, style, wrapper or order.
