# a11y extract

## Relevance
partial — a measured no-op sync edits no a11y surface; the domain's only stake is that its existing assertions are among the gates the chunk must run and read green.

## Constraints
- The a11y tier and target are fixed and the chunk changes neither: a11y-plan §1 (A11y tier) requires the three criteria it names to hold on the engine's accessibility surface, and a sync is a chunk that must leave that surface as it found it.
- Every entity a11y-plan §1 (A11y scope) lists is source, a manifest or a fixture; the scope's "no source edit, no dependency or lock change" boundary is therefore the a11y boundary too. Whether the tree at /implement is in fact unchanged across those entities is the chunk's own measurement, not something this plan attests.
- a11y-plan §9 requires the fork's CI to carry a dedicated accessibility job in the slow tier, behind the fast jobs. "Fork CI green on HEAD" is not satisfied for this domain until that job has concluded green on the same sha; a run still in progress on the fast jobs says nothing about it.
- a11y-plan §3 (A11y testing tool pick) requires accessibility assertions to be Rust tests in blitz-tests over the AccessKit tree, and §3 (Keyboard test harness) / §5 (Test harness pattern) require the stand's key-press focus check in both layout modes. Whether the `fast` leg's workspace tests execute all of these, beyond the three files §9 names for the a11y leg, is research's question.
- a11y-plan §7 (Accessibility tree output) states what of ours an upstream sync must not lose: the stable id carried on every element's accessibility node, the stand controls' roles and names with the Tab order unchanged, the snapshot family reading the tree with no second role or name mapping, and the actionable-key rule. On a 0-ahead sync these are re-proven by the gates, never re-argued.
- a11y-plan §2 (Accessibility tree lifecycle) holds the refresh on change and the changed-set contract as PROVISIONAL pending the founder, with the windowed witness owed to a later working-route entry. This chunk neither ratifies nor discharges either.
- The lean covers 0 ahead only. A non-empty merge would reach the inherited engine files a11y-plan §2, §4, §5 and §7 cite by file:line, which is a different chunk shape for this domain as well; the scope's halt-for-the-operator rule stands.

## Patterns to follow
- Read the accessibility job's conclusion from the fork's CI run on the chunk's sha, as its own job, per a11y-plan §9 — not inferred from the fast jobs.
- Treat the stand checks as the a11y witness for escher's own logic and the three engine files of the a11y leg as the witness for the inherited tree, per a11y-plan §7 (Accessibility tree output) and §9.
- Keep both layout modes in every stand reading that is quoted as proof, per a11y-plan §5 (Test harness pattern).
- Quote a11y expectations from the stand checks' shared tables as stated expectation, never as a second mapping, per a11y-plan §7 (Accessibility tree output).

## Anti-patterns to avoid
- Reading the a11y job's green as stand a11y proof: a11y-plan §9 states that job runs existing engine tests and adds no stand assertion.
- Reading any gate of this chunk as a windowed witness of the platform-tree refresh: a11y-plan §2 (Accessibility tree lifecycle) records that no windowed run witnesses it on the dev host and that it is proven at the document level only.
- a11y-plan §11 reads `NO RECORDED INTENT`; no ban is extracted from it.

## Contract bindings
- CI a11y gate ↔ tests: the accessibility job of a11y-plan §9 runs in the same workflow as the test job and restores its cache; its verdict is part of the one CI verdict the chunk reads.
- Stand a11y checks ↔ tests harness: a11y-plan §3 (Focus management test harness, Keyboard test harness) binds them to the headless harness's input synthesis and focus queries.
- Violation JSON schema ↔ obs: no binding — a11y-plan §3 marks the schema not yet measured.
- Keyed contract `Bootstrap phases`: the chunk does not turn on it; not read.

## Acceptance criteria contributions
- (a11y) The fork's CI run on the chunk's HEAD sha shows the accessibility job concluded green, read as its own job (per a11y-plan §9).
- (a11y) `bash .github/scripts/ci-leg.sh fast` passes with 0 failed, and its log shows the accessibility test files and the stand's a11y checks among the tests run; if the log shows they are not in that leg, `bash .github/scripts/ci-leg.sh a11y` is run and passes (per a11y-plan §3 A11y testing tool pick · §9).
- (a11y) The chunk's diff touches no file among the a11y scope entities — engine accessibility source, adapter crate, feature manifests, stand checks (per a11y-plan §1 A11y scope).
- (a11y) The refresh on change and the changed-set contract still read PROVISIONAL after the chunk; nothing in its record states them ratified or windowed-witnessed (per a11y-plan §2 Accessibility tree lifecycle).
