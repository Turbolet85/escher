- obs-plan §4 Span / Trace Coverage requires the MCP `tool_call` span to keep exactly two closed-word fields (`tool`, the verb table's word, and `ending` = `accepted` · `refused` · `error`); a new MCP tool for the graph read is required to add one verb-table word to `tool` and no field, and its instance call is required to parent one `command` child.
- obs-plan §4 Span / Trace Coverage requires that no `Outcome`, `Command`, `Call`, `ArgValue`, `Refusal` or `Fault` be fielded or printed with `Debug`; a new graph `Outcome` variant (nodes, component names, handler names, state names, values) is required to be written only by `Outcome::to_json` as a command's answer, never logged or fielded.
- obs-plan §6 Log Coverage requires escher-driver to emit no event and install no subscriber, with its only lines being the closed `command` / `tool_call` span lines; the graph reader and signal registry in `dioxus-native-dom`, the driver's carrier code and the stand's registered signals in `seven_guis` are required to add no log site, span, field, log field, print or env read (in line with the scope's «values masked, never logged»).
- obs-plan §8 PII Scrubbing & Compliance requires that the sink read 0 id, name and typed-text needles in process, in the `escher-session` host and in the `mcp` role; graph content (node ids, component names, handler event names, state names, masked values) counts as needle-class content and is required to stay out of every stderr line.
- obs-plan §8 PII Scrubbing & Compliance records that the probe target `dioxus_runtime_probe` read components, listeners and reader scopes with no read value leaving it, its failure messages naming only mode, task/page and link/index; the graph's checks are required to keep that discipline: no component name tied to a node, listener, signal value or node id in an assertion message.
