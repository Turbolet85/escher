@extract_section name=constraints
- a11y-plan §7 Screen Reader Support (sr-snapshot) requires the snapshot to take role, name, focus and states from `accessibility_tree`, never the element, and its text form, parts, diff, MCP results and node-key help to read that model alone, never a second role or name mapping; the graph keyed on the agent-visible node, and the new «reacts to a click» field, must sit inside that rule.
- a11y-plan §7 Screen Reader Support (sr-actionable-keys) requires every element an agent can act on to read an author key with `DioxusDocument::unkeyed_actionable` as the check, no second role mapping; it says no snapshot field reports that an element reacts to a click, a reading measured by link 2 and owed as a field to the route entry «The UI graph» (founder's C3, 2026-10-14). The new field is how this chunk meets that owed reading.
- a11y-plan §7 Screen Reader Support (sr-actionable-keys) records the starting count of elements that react to input and state no interactive role (`stand_non_lean_tasks`) as 0 on the four lean tasks, Home and Temperature Converter, Circle Drawer 1, Cells 677 (676 data cells plus `cells-grid`). The scope says "Cells 676". Which number is right is research's question, and the pin the field moves must match the measured one.
- a11y-plan §7 Screen Reader Support (sr-actionable-keys) states that the listener mark over-includes (a listener removed on re-render keeps its mark) and that a `mounted` listener writes no mark; per the same section, the probe's link 2 reading (Cells 677 = 676 `click` + `cells-grid` `keydown`; Counter `counter-increment` `click`; CRUD `crud-list` `keydown`) is the measured basis the field's reading must agree with.
- a11y-plan §7 Screen Reader Support (sr-tree) requires each element node of a Dioxus document to carry its stable element id as AccessKit `author_id` (no TextRun, root or Window node carries one). A reserved virtual-node id form must not collide with the author ids the tree carries, and whether today's ids already exclude the separator is research's question.
- a11y-plan §7 Screen Reader Support (sr-snapshot) requires a password's value to read as `MASKED_VALUE` (a file input with a value reads the same marker) and its typed text to appear in no snapshot field or tree node; a control value the graph carries must read the same.

- An unmasked password or file-input value must not appear in any graph output or snapshot field (per a11y-plan §7 Screen Reader Support).
