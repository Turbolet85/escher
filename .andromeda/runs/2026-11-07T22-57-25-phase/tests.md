@extract_section name=constraints
- The graph reader and signal registry land in `dioxus-native-dom`, whose unit tests build a `DioxusDocument` from a plain `fn() -> Element` app, call `initial_build`, re-render by flipping a signal inside `vdom.in_runtime`, and `resolve(0.0)` through `inner_mut()` before reading the snapshot. Graph unit tests are required to follow the same construction (per test-plan §3 Test Harness Contract, Crate-local test helpers, dioxus-native-dom).
- The new snapshot field, «reacts to a click», moves `NODE_FIELDS` from thirteen. Every pin that counts node keys must move with it: `test_capability_statement.py`'s `{word} node keys` count over `docs/capabilities.md`, and the schema's stated node fields (per test-plan §4 Unit Test Strategy, Capability statement). A new verb moves the twelve-verb pins: the schema's verb-table test, `the_listing_is_the_twelve_verbs_of_the_table`, the cold-agent `valid_step` and `isolated` sets, and the session command line (per test-plan §4 Unit Test Strategy, escher-driver; per test-plan §3 Test Harness Contract, Cold-agent run pipe; per test-plan §3 Session lifecycle). Whether a new verb is added at all is the founder's carrier fork.
- `stand_non_lean_tasks` pins the starting reading of the click field: 0 on the four lean tasks, Home and Temperature Converter, Circle Drawer 1, Cells 676, in both layout modes. The new field's reading must be asserted on stand tasks in both layout modes, through the shared `tests/common/mod.rs` tables and helpers, which are stated expectation and never a second mapping (per test-plan §3 Test Harness Contract, Crate-local test helpers, blitz-tests stand checks).
- «Values masked, never logged»: at the default level and at `info`, `debug` and `trace`, stderr must carry no stable id, no accessible name and no typed text, and each `Session::run` call must leave exactly one `escher_driver` `command` line holding fixed words and counts only. Graph content (component names, handler names, state names, values) must be held to the same needle-0 readings (per test-plan §3 Test Harness Contract, Stand log format; per test-plan §5 Integration Test Strategy, The driver's log line).
- The per-crate coverage floors bind the touched crates: `packages/dioxus-native-dom` 83 % (with `keyboard_compat.rs` excluded) and `packages/escher-driver` 97 % (per test-plan §10 Quality Gates & Coverage Targets, Coverage floors).
- The stand checks hold a zero-failure flakiness budget under `stand-repeat`: three rounds, no retry. A new `stand_*` graph check falls under it (per test-plan §10 Quality Gates & Coverage Targets, Flakiness budget).
- A check that reads a sink's capture counts lines by target, never in total, because the workspace build and the `-p blitz-tests` build differ in engine features (per test-plan §9 CI Integration, Engine features by runner).
@extract_section name=patterns
- Session checks hold a `Session` through `session_common`'s `hold(task, incremental)` and its call builders (`act`, `refused`, `snapshot`). A graph read crossing the driver would add a builder and a reader there in the same way (per test-plan §3 Test Harness Contract, Crate-local test helpers, blitz-tests session checks).
- A multi-reader fixture page is stated once in `tests/fixtures/mod.rs` as an `rsx!` component booted through `fixtures::boot`. An owner element serving sub-targets, if pinned beyond the stand, would follow this pattern, and a page with one reader stays in its check's file (per test-plan §7 Test Data & Fixtures, tests/blitz-tests/tests/fixtures).
- `dioxus_runtime_probe` in blitz-tests already reads what Dioxus 0.7 exposes (the vdom walk, `subscribers()` → `origin_scope()`) and is picked up by `run all` with no script change. A new non-`stand_` target is reached only through `run all` / `run {name}`, and a `stand_` target through `run stand` (per test-plan §1 Test Scope Summary, dioxus-native-dom; per test-plan §3 Test Harness Contract, Proof, the newest reading).
- The in-process sink capture of `stand_act_spans` (0 of the ids, names and typed texts at `RUST_LOG=info`, in each layout mode) and `host_log` / `mcp_log` at `RUST_LOG=trace` under both builds are the existing instruments for the never-logged rule (per test-plan §3 Test Harness Contract, Stand log format).
@extract_section name=anti_patterns
- No sleep and no wall-clock read in session checks except the two whose subject is wall time. A graph check advances time only through the driver's pass (per test-plan §5 Integration Test Strategy, Wall time in the session checks).
- No `cfg(test)` shim, new `pub` or constructor added only so a test can reach private state. The bridge tests' child-module pattern is the precedent. This matters because a scope's hooks are `pub(crate)` in dioxus-core (per test-plan §3 Test Harness Contract, Crate-local test helpers, dioxus-native-dom; per test-plan §4 Unit Test Strategy, Conventions).
@extract_section name=bindings
- tests ↔ obs: the never-logged readings (needle counts on stderr per level, one `command` / `tool_call` span line per call, closed `verb` set) are tests §3 Stand log format's measurement of obs-plan §3/§4/§6/§8. A new verb word in `command`'s `verb` and `tool_call`'s `tool` closed sets is an obs closed-set move as well as a carrier fork.
- tests ↔ security/arch: a new open value set on a ratified carrier is a boundary widening (the founder's fork). The tests pins (`test_capability_statement.py`, the verb-table and MCP listing tests, cold-agent `valid_step`) follow whatever the fork decides.
- tests ↔ a11y: the click field sits on the accesskit-keyed snapshot, and the stand's `controls(task)` / `rendered(task)` tables in `tests/common/mod.rs` are the stated expectation it is read against.
