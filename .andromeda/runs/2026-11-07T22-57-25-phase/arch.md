@extract_section name=constraints
- Stable ids: architecture §Standard Contracts → Dioxus DOM bridge requires `DioxusDocument::element_id` / `element_ids` to compute ids on demand in four tiers (author key, anchored path, component path, document path), written to neither the DOM nor the vdom. The reserved virtual-node form (`{canvas element}` + `{virtual key}`) must use a separator none of those four tiers can produce. Whether today's id grammar leaves such a separator free is research's question.
- No `NodeId` crosses: architecture §Standard Contracts → Dioxus DOM bridge requires the snapshot, its text form and its diff to read the screen read-only and hold no `NodeId`. A graph keyed on the agent-visible node with an optional owner element must keep `NodeId` (`Target.node`) inside the crate and never let it reach a carrier.
- Driver schema: architecture §Standard Contracts → Driver session requires the command and refusal schema to be stated once as `'static` data (twelve verbs, eight closed causes, no refusal holding what a call supplied). It also requires every call to go through `Session::run`, which validates first, and every answer to be written by hand in the crate-private `json` module. A new graph verb or outcome changes that stated schema, so it is the founder's fork.
- Carrier boundary: architecture §Established Decisions → Driver session says ids, names, masked values, snapshot text, diffs, shots and lint findings cross, and never a `NodeId`. It also says a new carrier or exit widens the boundary. Component names, handler event names and registered state names going out on the `v3` wire or over MCP are new content on a ratified carrier, so that content set goes to the founder at P4.
- Identity safety: architecture §Design Philosophy requires versioned node ids, public APIs that take `NodeId`, and persistent interaction state that references DOM nodes only. The owner-element link and any graph state held across reads must follow this rule, and must not key persistent state on accesskit or layout-generated nodes.
- Masking: architecture §Standard Contracts → Dioxus DOM bridge makes `is_masked_input` the one masked-control test (a password or file `input`). Any control value the graph carries must be masked through that one test, with no second masking rule.
- Gating and logging: architecture §Cross-cutting Patterns → Config management puts the `accessibility` feature as the gate on the dioxus-native-dom snapshot modules, which covers the new snapshot field and the graph reader that builds on the snapshot. Architecture §Conventions → Feature gating requires escher-driver's spans to be built by hand with no `#[instrument]`, so no graph content can enter a span field by accident.
@extract_section name=patterns
- Read-only bridge readers on `DioxusDocument` that compute on demand and change nothing, for example `element_id`, `element_ids` and `unkeyed_actionable` with its remedy (architecture §Standard Contracts → Dioxus DOM bridge). The graph reader and the signal registry's reads follow the same shape.
- One validated path: `Session::run` validates first, nothing public runs a `Command` that did not come from `validate`, and the recording replays answered calls through `Check::replay` (architecture §Standard Contracts → Driver session). A graph read gets its verb, its recorded step and its MCP tool through this path.
- Manifests: dependencies are declared once in `[workspace.dependencies]`, in-repo crates use `default-features = false`, and optional capabilities are Cargo features forwarded across crates (architecture §Conventions → Manifests; architecture §Project Intent → Growth model). The registry stays inside dioxus-native-dom on Dioxus "0.7.3" with no fork (architecture §Inherited Defaults).
- Apps and examples: Dioxus examples use `#[component]` with signal and store hooks (architecture §Conventions → Apps and examples). Moving the seven_guis stand's signals onto the registry's wrapper hook keeps that shape.
@extract_section name=anti_patterns
- No serialization crate writes a driver answer. `serde_json` only reads MCP requests and kept checks, and no command's ending writes back anything the caller typed (architecture §Standard Contracts → Driver session).
- No log, event or span carries the snapshot, its text or a diff, except a diff's three counts on the command span (architecture §Standard Contracts → Dioxus DOM bridge). This extends to graph nodes, component names, handlers, states and values.
- No new direct engine change for every document in blitz-dom without ratification. Architecture §Established Decisions lists each such change as ratified and flagged upstreamable, with a merge surface owned by Upstream sync. The scope expects none.
@extract_section name=bindings
- arch ↔ security: adding a verb, an outcome or open-valued content (component, handler or state names) to the ratified `v3` / MCP carriers widens the boundary (architecture §Established Decisions → Driver session). The founder decides it at P4 under security §Surfaces.
- arch ↔ tests: the snapshot field changes `NODE_FIELDS` (thirteen), and a new verb changes the twelve-verb schema (architecture §Standard Contracts → Driver session). Every pin that counts either one, including the capability-statement pin of driver commands exposed as MCP tools (architecture §Project Intent → Front page), must move with the change. Stand scenarios run in both layout modes (architecture §Conventions → Tests).
- arch ↔ obs: escher-driver's ungated `command` / `tool_call` spans must carry no graph content (architecture §Conventions → Feature gating; architecture §Cross-cutting Patterns → Logging and timing).
@extract_section name=acceptance
- (arch) The new code lives in `dioxus-native-dom` (graph reader, signal registry, snapshot field), `escher-driver` (the read's carriers) and `seven_guis` (the stand's signals). blitz-dom gets no engine change, and no Dioxus fork or version change lands (per architecture §Inherited Defaults).
- (arch) No graph answer, snapshot field or recorded step holds a `NodeId`. Every answer is written in the crate-private `json` module through `Session::run` (per architecture §Standard Contracts → Driver session).
- (arch) The reserved virtual-node id form is shown not to collide with any of the four stable-id tiers, by a separator none of them can hold. Nothing in 0.3.0 produces such an id (per architecture §Standard Contracts → Dioxus DOM bridge).
- (arch) Any change to the verb count, the cause set or the carriers' content is handed to the founder as a fork, not landed by the plan (per architecture §Established Decisions → Driver session).
