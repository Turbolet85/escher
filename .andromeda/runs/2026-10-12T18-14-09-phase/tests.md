# tests extract

## Relevance
relevant — a new driver verb on all three surfaces, a pixel-determinism claim and a no-font failure path all land on the stand checks, the session contract and the CI legs that test-plan governs.

## Constraints
- The screenshot checks must keep the stand's font contract: assert unconditionally under the bundled DejaVu Sans (`stand::font_ctx()` through `HarnessOptions.font_ctx`, system fonts off), with no runtime skip path. Upstream's font-dependent tests skip with `eprintln!`; the stand's checks never do. "Fails, never skips" has to read as a red test, never a skipped one (per test-plan §2 → Font-dependent tests; per test-plan §8 → Real dependencies kept).
- A pixel check renders to a CPU buffer and reads pixels. Exact comparison is the plan's form for identity (the WPT reftests compare RGBA buffers exactly). The 1px antialiasing tolerance belongs only to the box-shadow checks against Chromium renders, and is no model for "same pixels on repeat" (per test-plan §2 → Pixel tests; per test-plan §2 → WPT conformance).
- Every stand-held state the screenshot reads comes from `stand::options(incremental)` (800×600, scale 1.0, Light, bundled font, no net provider, no base URL). Each driver-verb check runs in both layout modes, and where it states equality, its readings are equal across the two (per test-plan §7 → Builders and options; per test-plan §5 → Session ↔ held instance).
- The two runners compile different engine features, and the snapshot `bounds` read through a different body of `physical_unrounded_geometry` under each (`writing-mode` is on in the workspace build only). An element screenshot cropped to `bounds` therefore has to be green under `-p blitz-tests` / `-p seven_guis` and under `--workspace`. A green per-package run is not the workspace leg's green (per test-plan §9 → Engine features by runner).
- A refused `screenshot` (an id the screen does not read: `stale` / `not-found`) must leave the instance unchanged, and its refusal must read as a text holding none of the bytes the call supplied. Assertions over a call carry a row index only, so a failing log prints no argument value (per test-plan §5 → Session ↔ held instance; per test-plan §4 → What unit tests cover, escher-driver).
- Each call through `Session::run`, `screenshot` included, leaves exactly one `command` span holding fixed words and counts only. Over MCP, each tool call leaves one `tool_call` parent span. A sink-installing host's stderr at `RUST_LOG=trace` must stay at 0 ids, 0 names and 0 typed-sentinel occurrences (per test-plan §3 → Stand log format; per test-plan §5 → Session host ↔ what it writes).
- An answer crosses the socket and the MCP stdio under 1,048,576 bytes on its JSON line. Past that the wire replies `oversize` and the client reads `AnswerTooLarge`, with the call having run. An image answer has to be checked against that bound wherever the result's form puts bytes on the wire (per test-plan §3 Session lifecycle `session-wire`; per test-plan §3 Session lifecycle `session-host`).

## Patterns to follow
- Fresh-process identity: `stand_id_persistence` re-executes its own test binary on an `#[ignore]` child (`ids_in_a_child_process`) to prove a reading the same in a fresh process. This fits "identical pixels on a repeated run on the same host". The child's streams go to null unless the check reads them, so its libtest lines never reach `agent-run.sh` (per test-plan §1 → tests/blitz-tests; per test-plan §2 → Process-lifecycle checks).
- Surface coverage for a verb: in process through `Session::run` in a new `stand_*` file, using the `session_common` call builders and readers (`act`, `refused`, `refused_unchanged`). The command line goes through seven_guis' `cli_commands` and the shared runner in `tests/common/mod.rs`. MCP goes through `mcp_server` (the `Speaker` child, not unix-gated except its command-line comparisons) and `stand_mcp_tools` in process (per test-plan §3 → Crate-local test helpers, blitz-tests (session checks); per test-plan §6 → Drivers per surface).
- Schema pins flip together: schema.rs (verbs in stated order and level, row count asserted), command.rs (every verb reached; today an unknown verb is refused `unknown-verb`), mcp.rs (the listing is the table's verbs), describe.rs (every text from its tables), cli.rs (rows read in order, usage line built from the table) and `mcp_server`'s `tools/list` order all count ten verbs today (per test-plan §4 → What unit tests cover, escher-driver).
- A masked control is proved on an in-file password fixture booted with the stand's options. The proof is a typed sentinel counted 0 times in what the call returns and the node reading `MASKED_VALUE` (`stand_act_diff`, `stand_act_filled`, `stand_mcp_masked`). The scope's password CARRY needs the pixel-level counterpart of that fixture; how absence is asserted in pixels is P4's to decide (per test-plan §5 → Session ↔ held instance).
- New behaviour is controlled by mutation: each named test reads red under its mutation and green on the restored tree, with sha-equal restores and evidence in `evidence/controls.md`. A new blitz-tests file is auto-discovered with no manifest line and picked up by `run stand` through its `stand_` prefix (per test-plan §4 → What unit tests cover, escher-driver; per test-plan §2 → Directory pattern).

## Anti-patterns to avoid
- Never give a screenshot check an `eprintln!` skip, a host-font fallback or a conditional assertion that passes without asserting when the font or the raster is missing (per test-plan §2 → Font-dependent tests; per test-plan §4 → Conditional assertions).
- Never count a sink capture's lines in total: count by target. The workspace build adds an engine line (`blitz_dom::document` at INFO) that the per-package build lacks (per test-plan §9 → Engine features by runner).
- Never read an empty run as a pass. Never let an id, a name, typed text or a call-supplied argument reach an assertion message or a refusal reading (per test-plan §3 → Agent-run contract `run`; per test-plan §4 → What unit tests cover, escher-driver).

## Contract bindings
- tests ↔ arch: the `screenshot` verb extends the Session lifecycle contract (`session-start` `run` outcomes, `session-wire` answer bound, `session-binary` verb list and endings, `session-proof` counts). Its API is arch §Standard Contracts → Driver session (per test-plan §3 Session lifecycle).
- tests ↔ obs: the `command` span's eight fields and the `tool_call` span's two are fixed. `stand_act_spans` holds a table of every instance verb and each cause, so a seventh instance verb joins that table. `host_log` and `mcp_log` read the needles at `trace` (per test-plan §3 → Stand log format; obs-plan §3/§4).
- tests ↔ security: the password-in-pixels CARRY, and the crossing question for image bytes on the socket, stdout and MCP stdio. The tests prove the mask and the bound; whether an image may cross is the founder's question at P4 (per test-plan §5 → Session ↔ held instance).
- tests ↔ CI: the windows job runs the non-unix-gated MCP checks. The macOS leg is the only witness of the platform-specific path. Whether screenshot pixels are identical across the matrix runners is out of scope (v010-08 says "same host"), so a cross-runner pixel assertion must not be written (per test-plan §9 → Pipeline facts; per test-plan §2 → Process-lifecycle checks).

## Acceptance criteria contributions
- (tests) Two screenshots of the same stand state, the whole screen and one element by id, taken in separate processes (a re-run `#[ignore]` child) on the same host, compare exactly equal in both layout modes (per test-plan §2 → Pixel tests).
- (tests) With the bundled font withheld, the screenshot check reads red with a typed reason. No skip line and no host-font render occur under either build (per test-plan §2 → Font-dependent tests).
- (tests) `screenshot` is accepted and answered on all three surfaces: in process via `Session::run`, via `cli_commands` (status `0`, one JSON line) and via `mcp_server` / `stand_mcp_tools`. A stale or unknown id is refused with nothing run. The schema, listing and describe pins read eleven verbs, the former `unknown-verb` pin flips, and one `command` span is left per call (per test-plan §3 Session lifecycle `session-proof`).
- (tests) `bash .github/scripts/ci-leg.sh fast` and `bash .github/scripts/ci-leg.sh doc` pass. The new checks are green under `cargo test -p blitz-tests --locked` / `-p seven_guis --locked` and under `cargo test --workspace --locked`, and `bash scripts/agent-run.sh run stand` ends `run.end` failed 0 with the new `stand_*` file selected (per test-plan §9 → Engine features by runner).
