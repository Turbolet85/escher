## Constraints
- The whole-screen frame is the headless stand's mount: one lean task in TaskShell (`main#main > #task-shell`, `#task-header > #back-btn + #task-title` above `#task-body`), at the pinned 800 × 600, scale 1.0, Light viewport with the bundled DejaVu Sans. A whole-screen screenshot's extent and scale are bound to that viewport (per layout-templates §Surface: desktop-native → Primary screens).
- Every consumer of the stand's mount, including the `escher-session` host role and the `mcp` role, adds no markup, id, class, style, wrapper or order. A held instance must read as a fresh boot, and the TaskShell mount and pinned viewport must hold after commands, in both layout modes. A screenshot taken through any surface is held to the same rule (per layout-templates §Surface: desktop-native → Primary screens).
- An element screenshot addresses its target by the author `id`s already carried as stable element ids: the lean tasks' controls and value displays, and CRUD rows `crud-person-{person.id}`. These ids add no class, style, wrapper or order, and no task CSS selects by them. The chunk must not add an id or a hook to make an element croppable (per layout-templates §Surface: desktop-native → Primary screens).
- A screen holds scrolling boxes inside the viewport. `visible_region` reads the viewport narrowed to the padding box of every clipping box that holds an element. On the stand, `crud-list` is the box that clips its rows, and `task-body` (0, 46, 800 × 554) is not. So a row's crop and its out-of-view case (the P4 fork) must be read against the clipping box, not the viewport alone (per layout-templates §Surface: desktop-native → IA notes).
- The recorded element bounds are fractional. For example, `crud-list` reads (24, 112.796875, 369 × 419.203125) at boot and the same four figures after its content scrolls. A crop to the snapshot's bounds needs a stated pixel-rounding rule (per layout-templates §Surface: desktop-native → IA notes).
- The command line's shape is `escher-session <verb> [arguments] --session <dir>`, with arguments spelt as the schema spells them (`--id` followed by one value). There are four endings, exit 0 · 1 · 2 · 3. An accepted answer is one uncoloured JSON line on stdout. The usage line is fixed text built from the verb table, and no ending writes back anything the caller typed. A `screenshot` verb and any optional `--id` take this shape (per layout-templates §Surface: cli → Primary screens).
- The `mcp` role lists the verb table's verbs as tools in table order, `help` last. Each tool's description is the verb's help followed by `. Returns: ` and its result fields. Its stdout carries protocol lines only, uncoloured with no ESC byte. The new verb's tool is described and placed by the same rule (per layout-templates §Surface: cli → Primary screens).

## Patterns to follow
- The host and `mcp` roles boot one lean task only through `seven_guis::stand`, the boot `main` hands to the driver's command line. A raster of the held instance hangs off that same boot, not a second one (per layout-templates §Surface: desktop-native → Primary screens).
- `paint_bench` already exposes a CPU raster backend on a CLI: `paint_bench <url> [width] [height] [scale] [iters] [backend]` with `backend: vello (default) | cpu | hybrid`. It is a precedent for a CPU-backend, fixed-dimension raster invoked from the command line (per layout-templates §Surface: cli → Primary screens).
- The `help` addition is the precedent for adding a verb to every place the CLI grammar shows one: the usage line lists it in table order (`help` after `stop`), and the self-description's `verbs` and MCP `tools/list` carry it (per layout-templates §Surface: cli → Primary screens).
- The scrolling-box precedent is to measure readings on the stand and cite them from evidence. The 12- and 14-Create CRUD list cases fix a scrolled-row case to reuse for the element-out-of-view crop (per layout-templates §Surface: desktop-native → IA notes).

## Anti-patterns to avoid
- Adding a class, style, wrapper, id, element or order change to stand markup to serve the screenshot. The plan records every earlier chunk's stand change as adding none (per layout-templates §Surface: desktop-native → Primary screens).
- Writing anything other than the ending's fixed form to stdout. Colour, an ESC byte, the caller's `--id` echoed back, or a usage line on stdout all break the four-ending grammar (per layout-templates §Surface: cli → Primary screens).
- Treating the stand's frame as the windowed one. The windowed stand was not measured, and in the windowed shell the render surface covers the safe area while the viewport excludes it. The headless frame is the pinned viewport only (per layout-templates §Surface: desktop-native → Primary screens; per layout-templates §Surface: desktop-native → IA notes).
