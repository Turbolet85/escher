## Relevant amendment history
- **2026-10-06-headless-stand** — added the §Typography → Loading bullet: the headless stand registers bundled DejaVu Sans for every generic through `build_single_font_ctx(DEJAVU_SANS)` via `HarnessOptions.font_ctx`, with system fonts off, and the woff2 is decoded by seven_guis' native `woff` feature. It was made to pin text measurement to one face across the dev host and CI. This is the font context a deterministic screenshot must rasterise with, and the place a "fails, never skips, without fonts" reading must hang on (the `woff` feature or the font bytes missing).
- **2026-10-07-settle-detection** — §Motion → Animation runtime. Settle answers every member of the keeps-animating set the same way: none is waited on or advanced, it returns `Settled` with `animating` read from the document flag, and settle reads animation time only through the harness's controlled clock, which it never advances. Its Why records a trap: the scrollbar-fade member reads the wall clock, not the harness clock. A screenshot taken after a `scroll` can paint a thumb whose opacity depends on wall time, which threatens pixel identity on repeat (the extract's FADE_DELAY/FADE_DURATION constraint). P3 must measure it, not assume the harness clock covers it.
- **2026-10-07-act-by-id** — §Motion → Animation runtime. The driver's `advance` moves app time only (whole Timer ticks on the stand) and leaves the harness's animation clock where it was, as `click`, `type` and `press` do. A driver click beside a running CSS animation returns settled without waiting. For a repeated screenshot of the same state, this means the animation clock at paint time is whatever the harness holds, unmoved by driver verbs. It is the basis of the extract's clock-at-paint-time check, and it constrains any screenshot verb not to tick the clock itself.
- **2026-10-07-refusal-detection** — §Motion. `scroll_into_view` writes every scrolling box at once, innermost first, and the driver's `scroll` is instant in every box and the viewport within one settled step (the founder's ratified widening). A screenshot after `scroll` therefore reads no smooth-scroll mid-travel position, only the scrollbar-fade timing above. The precedent also stands that an engine method widened for every document needs the founder's ratification, which applies if the raster path needs an engine change (e.g. password masking in paint).
- **2026-10-10-scrolling-box-bounds-and-hit** — §Depth Strategy → Engine depth behavior. The hit walk now stops at the padding box of a node that clips by `overflow`, as paint clips. This bears on cropping an element screenshot to its snapshot bounds when it is partly clipped or out of view: paint and hit agree on `overflow` clipping, and the `contain: paint` hit reading is still off (per the driver's own text). That matters if the screenshot reuses the `off-screen`/`covered` refusals.
- **2026-10-10-driver-cli** — §Surface: cli → Component Patterns. `escher-session` prints exactly one line of JSON on stdout per command, keyed by schema words. A usage error goes to stderr with stdout empty. There is no colour, no colour dependency, no ESC byte and no terminal test, and exit statuses are 0/1/2/3 (the founder's answers, 2026-10-10). The `screenshot` answer must keep this form, so the screenshot example's progress lines (`Screenshot is …`, `Written to …`) must not leak onto stdout. No detector covers output form: the amendment was raised by hand, and a new verb's answer line needs the same hand check.
- **2026-10-10-mcp-surface** — §Surface: cli → Component Patterns (the `escher-session` bullet). The `mcp` role adds newline-delimited JSON-RPC 2.0 protocol lines only on stdout, uncoloured, with no ESC byte. A tool result's text is the screen text for `snapshot` and the JSON line otherwise, asserted on every reply by the shared `Speaker`. A `screenshot` tool result must slot into this rule. If it carries an image (e.g. an MCP image content block or base64), that is a new result form that this bullet does not yet state.
- **2026-10-12-self-description** — §Surface: cli → Component Patterns (the `escher-session` bullet). The exit statuses are read from `EXIT_STATUSES`. `escher-session help` answers the self-description as one uncoloured JSON line, a session error's object carries its `remedy`, and an MCP `help` result is the self-description's line. It is the most recent precedent for adding a verb's answer line to the cli surface while keeping its form. A `screenshot` verb extends the table `help` serves (ten → eleven verbs) and must state its result fields there, and any new failure (fonts unavailable) must map onto `EXIT_STATUSES`.
