- Re-prove the a11y surface with the standing checks, not new ones: the `a11y` leg (`bash .github/scripts/ci-leg.sh a11y`, six files) plus `accessibility_states`, `accessibility_label`, `accessibility_description`, `accessibility_merged_states`, `inert_subtree` and `accessibility_active_descendant_unread` in the workspace test leg, all in both layout modes (per a11y-plan §9 CI Integration; per a11y-plan §3 A11y Assertion Harness Contract).
- Re-read the stand graph for platform adapters on the merged lock, as the 2026-10-10 upstream sync and the mcp-surface chunk did, and record the row count (per a11y-plan §1 A11y Scope Summary).
- Read keyboard activation as the measured rows: Enter and Space on each focused stand button read as its click (20 rows), plus 4 rows on `crud-update` and `crud-delete` reached by keyboard alone; through the driver, `stand_act_keys`' `press enter` / `press space` (per a11y-plan §5 Keyboard Navigation, Keyboard handling).
- Compare against the plan's stated counts. A moved count is explained by its cause, the way the plan restates each chunk's numbers "as measured at" a report (per a11y-plan §9 CI Integration).

## Anti-patterns to avoid
- Loosening an a11y assertion so it passes: a contrast row, a Tab-order table, a role/name table (`controls`, `INPUT_NAMES`, `REGION_NAMES`) or a per-file test count edited to the new value without a recorded cause (per a11y-plan §6 Visual Design Verification, Color contrast; per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- Adding a second role or name mapping. The snapshot, its text, its diff and the MCP results each read the one tree, and the stand's tables are stated expectation, never a mapping (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
