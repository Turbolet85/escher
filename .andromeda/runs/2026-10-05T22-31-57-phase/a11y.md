## Constraints
- The a11y target is tier 0: SC 2.1.1 · 1.4.3 · 2.4.3, per a11y-plan §1 A11y Scope Summary. The named leg is the first CI surface for that target. It wires existing tests and asserts no new SC, per the scope Boundaries.
- a11y-plan §3 A11y Assertion Harness Contract (tool pick) makes accessibility assertions Rust tests in `blitz-tests` over the AccessKit tree. Its named files are `tests/blitz-tests/tests/accessibility_hidden.rs` and `accessibility_roles.rs`. The leg runs these, not a browser-side tool.
- Those tests need the AccessKit tree built. a11y-plan §1 records that `blitz-tests` builds `blitz-dom` with the `accessibility` feature and takes `accesskit` as a dev-dependency. §3 records that `blitz-test-harness` also builds blitz-dom with the feature. The leg's cargo invocation must keep that feature on. Whether the leg's chosen flags (e.g. any `--no-default-features` or a per-test `--test` selection) preserve it is research's question.
- a11y-plan §3 Bootstrap phases names `a11y-ci-gate-wire` as the bootstrap item this chunk discharges. The sibling item `contrast-verification-harness-setup` (§6 Visual Design Verification) is a separate item and not this chunk's.
- a11y-plan §9 CI Integration found no accessibility checks by searching `a11y|accessib|axe` over `.github/workflows/*.yml`. The leg's job name in ci.yml must contain a term that search matches, so §9 can be re-measured as present.
- a11y-plan §5 Keyboard Navigation (Focus order) records `tests/blitz-tests/tests/focusability_updates.rs` as the existing focusability test. Focusability bears on SC 2.1.1 / 2.4.3. Whether that file joins the a11y leg's test set or stays only in the workspace test leg is a P4 lean.

## Patterns to follow
- Build the leg like the existing ones. It is a `.github/scripts/ci-leg.sh {leg}` arm that CI and the host run identically, with its log in `target/ci-logs/{leg}.log`. ci.yml calls it as a named job in the fast/slow `needs` split set up by 2026-10-05-fork-ci-reached (scope §What this chunk builds).
- Select tests by integration-test file (`cargo test -p blitz-tests --test accessibility_hidden --test accessibility_roles …`). This reuses the one-file-per-behaviour layout that a11y-plan §3 (tool pick) cites. It avoids a name filter that could silently match nothing.
- Pin the new job's existence and name in `.github/scripts/test_ci_workflows.py` so the ci-scripts leg guards it (scope §Detailed scope, the workflow-invariant pattern).

## Anti-patterns to avoid
- Do not wire an axe-core, Lighthouse or contrast step as "the a11y leg". a11y-plan §3 (tool pick) makes AccessKit-tree Rust tests the harness, and contrast checks belong to `contrast-verification-harness-setup` (§3 Bootstrap phases, §6).
- Do not build the a11y leg with the `accessibility` feature disabled. A run with the feature off is not an accessibility leg (a11y-plan §1 A11y Scope Summary).

## Contract bindings
- a11y ↔ tests: the CI a11y gate is a step in the same workflow as test-plan §9's legs. Its test files also run in the workspace `test` leg, so the a11y leg should be cheap: it re-runs a subset, not a new compile surface. Its cache key and placement share the ≈ 9.73 GB / 10 GB Actions cache budget recorded in the scope.
- No obs binding: the a11y violation-JSON schema is unrecorded in a11y-plan, so this chunk emits no a11y log format.

## Acceptance criteria contributions
- (a11y) ci.yml has a job whose name contains `a11y` or `accessib`, and it runs on the `build/**` trigger. Re-running the `a11y|accessib|axe` search over `.github/workflows/*.yml` returns that job (per a11y-plan §9 CI Integration; §3 Bootstrap phases `a11y-ci-gate-wire`).
- (a11y) `bash .github/scripts/ci-leg.sh {a11y-leg}` exits 0 on the host. Its log shows `accessibility_hidden` and `accessibility_roles` running with a non-zero passed-test count, and that count equals those files' counts in the workspace test leg (per a11y-plan §3 A11y Assertion Harness Contract, tool pick).
- (a11y) The leg's cargo invocation builds `blitz-dom` with the `accessibility` feature, checked by the leg compiling and running the AccessKit-tree tests rather than skipping them (per a11y-plan §1 A11y Scope Summary).
- (a11y) `test_ci_workflows.py` fails if the a11y job is removed or renamed (per a11y-plan §3 Bootstrap phases `a11y-ci-gate-wire`).
