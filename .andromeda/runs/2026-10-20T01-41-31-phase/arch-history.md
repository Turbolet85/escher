## Relevant amendment history
- **2026-10-07-settle-detection** — Built `Harness::settle`. After a quiet pass, a request in flight or a pending render-blocking resource reads `NotSettled { busy: Loads }` at once. Settle never waits on a load, reads no clock but the harness's and starts no thread. A fetching `net_provider` is wrapped in a crate-private counter, and an offline or `wrap`ped harness carries none. It also built `Session::act` (step, settle, map a not-quiet instance onto `NotSettled(Busy)`, no rollback, nothing crossing the socket). Why: settle reads no clock, so it reports a load and never waits. This is the rule this chunk moves. The wait has to loop over this contract, not amend it, and a load is counted only through a non-noop `net_provider`. The entry also put "a settle verb or busy-source reply on the socket" on the Not built list, which makes it a crossing question.
- **2026-10-07-command-and-refusal-schema** — Stated `VERBS` and the acting result `settled` · `busy` · `added` · `removed` · `changed`, with `busy` a closed class. Rules: a not-settled step is a result, never a refusal; a later entry adds to the one table and never builds a second. The bound's passing has to read as today's `settled: false, busy: "loads"`, with no new cause or field. This chunk's origin residual («no command waits out a network load») dates from this entry's chunk.
- **2026-10-07-act-by-id** — `Session::run` made each acting verb (`click` · `type` · `press` · `advance`, later `scroll`) one settled step returning the diff, and it set `Outcome` as `Screen` · `Acted` · `Advanced`. Rules: nothing resolved outlives a call; an `Outcome` is never fielded. The wait wraps this per-verb settled step in `execute.rs`/`session.rs`.
- **2026-10-07-driver-command-spans** — The `command` span holds exactly eight fields (`verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`). Kept: the crate installs no subscriber and reads no env var and no clock. A wall-clock read for the bound breaks the "reads no clock" statement, and a waited-time field would be a ninth field (a ruling, not an add). `passes` will now count across the wait's loop, so its meaning needs restating.
