# a11y extract

## Relevance
partial — the chunk adds no UI surface, control, key binding, colour or role; it touches the settled step whose screen the accessibility tree, the snapshot and the diff read, and the changed set the shell's tree refresh drains.

## Constraints
- The a11y target is tier 0, SC 2.1.1 · 1.4.3 · 2.4.3 (per a11y-plan §1 A11y Scope Summary); a wait that moves no focus, key or colour leaves those three untouched. Whether the wait loop dispatches nothing beyond the step's own input is research's question.
- a11y-plan §2 A11y Strategy (Accessibility tree lifecycle) requires that a harness settle neither read nor drain the changed set, so a settled step leaves the shell's refresh and the next diff exactly what the step marked. A wait built as a loop over `Harness::settle` must keep that: no `take_changed_nodes` inside the loop, and a load's arrival marking the set as any in-document mutation does. Whether a load's completion marks the changed set today is research's question.
- a11y-plan §5 Keyboard Navigation (Focus restoration) requires the double-click window to be read on the document's clock, the harness's `VirtualClock` on a harness-built document, so that two driver `click`s on one point with no `advance` between them read as a double click. A wall-time wait must move no virtual time, or it would change what a second `click` means.
- a11y-plan §7 Screen Reader Support (Accessibility tree output) requires the snapshot, its text, its diff and an MCP tool result to be readers of the tree's role and name with no second role or name mapping. The fixture's loaded content must be read on screen through `DioxusDocument::snapshot` and `Snapshot::diff`, and never through a reader of its own.
- a11y-plan §9 CI Integration states the `a11y` leg's six files and their per-file counts (accessibility_hidden 6 · accessibility_roles 6 · focusability_updates 4 · stand_accessibility_ids 8 · stand_contrast 5 · stand_keyboard 14). Since the chunk adds no a11y surface, those counts must stay unmoved and the new check must not join that leg.

## Patterns to follow
- Settle stays a single pass that reports `NotSettled { busy: Loads }` at once and reads no clock. The bounded wait is a loop above it, and the changed set's contract is untouched (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).
- A check that reads `has_changes()` as "this step changed something" drains first, because a freshly booted harness document has a non-empty set (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle). Apply this to any fixture assertion that the loaded content changed the screen.
- Run the stand and fixture checks in both layout modes, with each reading taken through the snapshot model, as the stand's accessibility checks do (per a11y-plan §7 Screen Reader Support, Accessibility tree output).

## Anti-patterns to avoid
- Do not drain or read the changed set inside the wait loop. The shell's tree refresh and the step's diff depend on the set holding exactly what the step marked (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).
- Do not move the session's `VirtualClock` while waiting. The double-click window and every engine time read take it, and `advance` is their one mover (per a11y-plan §5 Keyboard Navigation, Focus restoration).

## Contract bindings
- a11y ↔ tests: the `a11y` leg's six-file list and its per-file counts are a CI pin (per a11y-plan §9 CI Integration). The chunk's new check beside `stand_settle.rs` binds to test-plan §3/§8, not to the a11y leg.
- a11y ↔ arch Driver session: the changed-set contract that settle neither reads nor drains, and that the refresh follows (per a11y-plan §2 A11y Strategy), binds to arch §Cross-cutting Patterns (Invalidation and state integrity), where the wait's placement is settled.

## Acceptance criteria contributions
- (a11y) On the load-answered fixture arm, the loaded content reads in the returned diff and the next snapshot through `Snapshot::diff` / `DioxusDocument::snapshot`, its role and name equal to its accessibility node's, in both layout modes (per a11y-plan §7 Screen Reader Support).
- (a11y) After a wait, on either arm, the session's `VirtualClock` reads the same time as before the command (the step's own `advance` aside), so a following `click` pair with no `advance` keeps its double-click reading (per a11y-plan §5 Keyboard Navigation).
- (a11y) After the step on the load-answered arm, `has_changes()` reads true, drained first at the check's start: the wait loop drained nothing the step and the load marked (per a11y-plan §2 A11y Strategy).
- (a11y) `bash .github/scripts/ci-leg.sh a11y` stays green with its per-file counts unmoved (per a11y-plan §9 CI Integration).
