# a11y extract

## Relevance
partial — the chunk adds no UI surface, keys, colours or motion, but the upstream merge rewrites engine files the a11y plan names as a11y surface: blitz-dom `node/node.rs` and `document.rs`, blitz-paint `render.rs`, and blitz-vibey-script `dom/{document,element}.rs`. The a11y obligation is no regression, and the merge must keep the `a11y` CI leg green.

## Constraints
- a11y-plan §1 A11y Scope Summary requires the tier-0 target SC 2.1.1 · 1.4.3 · 2.4.3, with `accessibility` a default feature across blitz-dom, blitz-html, blitz-shell, blitz and both Dioxus crates. The merge takes upstream's Cargo.toml as one set, and that set must not drop or rewire any of those `accessibility` feature forwards. Whether upstream's Cargo.toml delta touches them is research's question.
- a11y-plan §3 A11y Assertion Harness Contract and §7 Screen Reader Support (Accessibility tree output) require the AccessKit tree to be built from the DOM with element ids mapped through `NodeId::as_u64`, a `Window` root at `u64::MAX`, and the focused DOM node reported as tree focus. `accessibility.rs` is not in the upstream file list, but `document.rs` and `node/node.rs` are. Whether the new `Document::children` accessor or the move of inline-fragment rects onto `Node` changes what `build_accessibility_tree` walks is research's question.
- a11y-plan §5 Keyboard Navigation (Focus order per layout · Focus restoration) requires Tab/Shift+Tab focus order, focus and blur state changes, and focus reset on removal of the focused node to survive unchanged. Those cited sites live in `node/node.rs` (focus/blur, the DISABLED/ENABLED states, `synthetic_click_event`) and `document.rs` (`focus_next_node`/`focus_prev_node`, removal reset), which are the overlap files this merge takes. Whether upstream's `node.rs` delta shifts any of them is research's question.
- a11y-plan §5 Keyboard Navigation (Script and framework exposure) requires script `focus()`/`blur()`/`document.activeElement` and the falsy-Dioxus-`disabled` removal to keep their recorded behaviour. Upstream edits blitz-vibey-script `dom/{document,element}.rs`, and the fork's `document.rs` and `mutation_writer.rs` changes are carried as they are.
- a11y-plan §6 Visual Design Verification (Color contrast · Focus ring · Visibility and hit-testing) requires the scrollbar-thumb contrast stroke and focused-input caret painted in blitz-paint `render.rs`, and the `visibility`/`pointer-events` hit-test exclusions in `node/node.rs`, to hold after the merge. Both files are in the upstream delta.
- a11y-plan §9 CI Integration requires the `a11y` job (`ci-leg.sh a11y`: `accessibility_hidden`, `accessibility_roles`, `focusability_updates`, 6 + 6 + 3 tests) to keep running as its own slow-tier leg. The scope lists no `.github/` change, and this chunk must keep that true.

## Patterns to follow
- The a11y regression check uses the existing Rust tests over the AccessKit tree: `build_accessibility_tree()` after `resolve`, `test_that` matchers on `role()`/`is_hidden()`, and the `assert_role` helper (per a11y-plan §3 A11y Assertion Harness Contract). Re-run them as they are, never re-derive them.
- The focus check uses the harness's focused/hovered node queries (per a11y-plan §3, Focus management test harness) together with the `focusability_updates` roving-tabindex and disabled-button tests (per a11y-plan §5, Focus order per layout).
- The not-colour-alone cue is proven by `stand_flight_booker` asserting the `invalid` class and the `disabled` attribute, not colour (per a11y-plan §8 Cognitive Accessibility, Error recovery). It is already in the scope's stand set.

## Anti-patterns to avoid
- Never narrow, skip or re-gate the `a11y` leg's test set, or move it out of its CI job, to get the merge green (per a11y-plan §9 CI Integration). a11y-plan §11 A11y Anti-Patterns carries no recorded intent, so this ban derives from §9.
- Never "fix" the two-way disabled keying (presence-based `:disabled`/click target versus value-parsed focusability) as a side effect of resolving the merge. It is recorded behaviour, not this chunk's change (per a11y-plan §5, Focus order per layout).

## Contract bindings
- a11y ↔ tests: the bootstrap key `a11y-ci-gate-wire` (discharged) binds the a11y assertions to ci.yml's `a11y` job and `ci-leg.sh a11y` (per a11y-plan §3 Bootstrap phases (derive for route / setup-project) · §9 CI Integration). Fork CI on the pushed merge runs this leg, beyond the local `fast` + `doc` gate the scope names.
- a11y ↔ tests: the stand checks carry the a11y-relevant not-colour-alone and disabled-attribute assertions (`stand_flight_booker`, `dioxus_falsy_disabled`) (per a11y-plan §8 Error recovery · §5 Script and framework exposure).
