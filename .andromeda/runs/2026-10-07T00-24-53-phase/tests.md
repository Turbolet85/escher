## Patterns to follow
- **blitz-dom unit tests for the set, the flag and the drain:** build a `BaseDocument` straight from `DocumentConfig`, construct the DOM through `DocumentMutator`, `resolve(0.0)`, then assert — per test-plan §2 blitz-dom pipeline tests; no parsed HTML at this level (the plan records the parser as a circular dev-dependency there). Where a test needs to observe a redraw request, the hand-written counting `ShellProvider` fake is the stand-in (test-plan §8, the Shell rows).
- **dioxus-native-dom unit tests for the diff:** the crate-local helper shape — `DocumentConfig::default()`, `initial_build`, `resolve(0.0)` through `inner_mut()`, a `GlobalSignal` flip inside `vdom.in_runtime` to re-render — per test-plan §3 Crate-local test helpers (dioxus-native-dom). That helper carries the no-op HTML parser, so a case needing parsed markup belongs in blitz-tests, not at unit level (same anchor).
- **Stand check:** boot through `seven_guis::stand::boot(LeanTask, stand::options(incremental))` / `boot_timer`, act through the real input helpers, read after the pump — per test-plan §3 Construction and §7 Builders and options. Cases the lean tasks lack (a node added, a node removed, a value re-written unchanged) go on an in-file fixture booted with the stand's options, the shape `stand_snapshot_state` and `stand_snapshot_text` already use (test-plan §1 Coverage scope, tests/blitz-tests; §7 Seed strategies, Inline HTML).
- **Time as a step source:** the timer's tick is delivered through `TimerTicks.deliver(n)` and applied on the next pump; an undelivered source holds elapsed still — per test-plan §8 (Time, seven_guis timer). That gives a real no-input step (a tick changes nodes) and a real no-op step (a pump with nothing delivered) without a wall clock.
- **A focus step:** test-plan §1 Coverage scope records `focused` proven through a click, a Tab press and Shift+Tab; a focus move changes a snapshot reading without an author-visible DOM mutation. Whether the engine's changed set sees a focus move, a hover or a typed value is research's question — the stand check requires at least one such step so "no changed node missed" is proven on a non-mutation path (cf. test-plan §2 Pure-restyle paths).

## Anti-patterns to avoid
test-plan §11 reads `NO RECORDED INTENT` — no ban is cited from it. The bans below come from measured sections:
- **Do not drive a stand step with `dispatch_recorded`:** per test-plan §5 Harness ↔ event pipeline it runs against the underlying `BaseDocument` and bypasses Dioxus `VirtualDom` forwarding, so the app would never react and every diff would read empty — a false no-op proof.
- **Do not prove "exactly the changed nodes" on attribute mutations alone:** per test-plan §2 Pure-restyle paths, a mutation inserts full damage and masks under-tracking; a set that is merely over-written by every mutation would pass. The proof needs the pure paths (focus, tick, typed value) and an asserted absence of unchanged nodes.
- **Do not let a run with no parsed test line count as green:** per test-plan §3 Agent-run contract → `run {selection}`, an empty run is a failure by contract; a new file that compiles to zero tests under a feature gate must not be read as a pass.

## Contract bindings
- **tests ↔ security (diff content in test output).** Per test-plan §3 Agent-run contract → Events, nothing between `failures:` and the next `test result:` reaches an event, but raw cargo output is kept in `target/agent-run/run.log` (§3 `run` / State), and per test-plan §9 Failure logs each CI leg's merged output is uploaded on failure as an artifact kept 7 days. An assertion message, `println!` or `dbg!` carrying diff content would therefore leave the process through a failing run's log — the scope's CARRY rule (labels of mode and id only) is binding on the new check for that reason; the content rule itself is security-plan §Input Validation's.
- **tests ↔ obs.** The agent-run events are harness metadata, not an escher-telemetry sink (test-plan §3 Agent-run contract → Events, binding to obs-plan §3); the chunk adds no event field and no log field for the diff or the flag.
- **tests ↔ a11y.** Making `has_changes` truthful changes when the windowed shell's AccessKit update fires; the `a11y` CI leg (test-plan §9 Legs — `accessibility_hidden`, `accessibility_roles`, `focusability_updates`) must stay green, and the tree-update wording is a11y-plan's. test-plan §1 lists no blitz-shell entity under test and §6's windowed runs are `NOT YET MEASURED`, so the plan offers no existing harness for the shell's gate — how its behaviour after the fix is proven (a window-less unit, or a proof at the document level that the shell's reads are unchanged) is research's and the plan's question.
- **tests ↔ architecture.** The diff's unit and stand tests exercise `DocumentMutator` and `DioxusDocument` contracts (architecture §Standard Contracts); test-plan §3 Crate-local test helpers names `DocumentMutator::remove_node_if_unparented` as the way a test stales a `NodeId` — the route to a unit case for a tracked id whose node is dropped inside the same step.
