# layouts extract

## Relevance
partial — the chunk creates and modifies no surface element (the diff is an in-process Rust value, no screen, no CLI output); the layout plan binds it only through the stand screens it is proven on: their region structure, their author ids and their pinned viewport.

## Constraints
- The proof surface is the headless stand's TaskShell mount, not Home: layout-templates §Surface: desktop-native → Primary screens (the "seven_guis Home and TaskShell" bullet) requires the stand to skip Home and mount one lean task (Counter, FlightBooker, Timer, Crud) in TaskShell through `task_in_shell`. The chunk's stand check reads its diffs on that mount and adds no other entry path.
- The region hierarchy the diff's nodes sit in is fixed by the same bullet: a header region (back button, title) above a scrolling task-body region, under the `main` mount. The chunk adds no region, wrapper or element to it — a diff is read off the existing hierarchy.
- The diff's subjects on a stand screen are the author ids that bullet enumerates per lean task (controls and value displays), which the plan requires to be the elements' stable element ids. The chunk introduces no new id on a stand screen and renames none; whether every node a stand action changes already reads one of those ids (or only a derived path id) is research's question.
- Ids carry no layout: the same bullet requires that ids add no class, style, wrapper or order and that no task CSS selects by them. Any attribute the chunk might add to make a change observable must hold to that — no structural or visual change to a task screen.
- CRUD rows are the plan's one case of a list whose membership changes: the bullet requires each row's id to be its person's model-assigned author key and to follow its person under filter, Create and Delete. A diff's appeared / disappeared entries on the CRUD screen are keyed by those row ids, never by row position.
- Bounds are a diffed field and are viewport-dependent: the bullet requires the stand's pinned viewport (size, scale, colour scheme, bundled font), and §Surface: desktop-native → IA notes records the test harness's default viewport. A minimal fixture beside the stand is laid out at a stated, fixed viewport so a bounds difference in a diff is caused by the action, not by the environment.
- A fixture document follows the fixed document skeleton with the app mounted into `main` (§Surface: desktop-native → IA notes); arbitrary `index.html` templates are not available to it.

## Patterns to follow
- Address stand nodes by the plan's enumerated author ids (§Surface: desktop-native → Primary screens), as the existing stand checks named there do — a diff assertion names an id from that list, not a tree position or a role-and-index.
- Use the TaskShell header / task-body split (same bullet) as the natural "changed vs untouched" partition when asserting "and no others": an action inside the task body is asserted against the body's ids, with the header region's ids as the unchanged control group. Whether a body action leaves every header reading (focus state included) unchanged in the code today is research's question.
- Use the CRUD row id rule (same bullet) for the added / removed-node cases before reaching for a fixture: Create and Delete are the stand's own membership changes. Whether they cover the scope's "node added / node removed" cases fully, or a fixture is still needed, is research's question.
- Keep the stand read-only: the plan describes `task_in_shell` and the stand boot as the mount contract (same bullet); the chunk consumes it and does not reshape it.

## Anti-patterns to avoid
- Changing a stand screen's structure to make a diff easier to prove — a new wrapper, a reordered control, a class or style hung on an id — against the "ids add no class, style, wrapper or order" requirement (§Surface: desktop-native → Primary screens).
- Giving the diff a screen of its own: no new CLI usage line, verb or stdout shape. §Surface: cli → Primary screens lists the CLI screens that exist and the chunk's scope adds none — the diff is returned to its caller only.
- Proving a diff at an unpinned or differing viewport between the before and after readings, which would put layout-driven bounds changes into a diff the action did not cause (§Surface: desktop-native → Primary screens, the pinned-viewport clause; IA notes, the harness default viewport).

## Contract bindings
- layouts ↔ architecture (stable element ids · snapshot model): the author ids the layout plan enumerates per stand screen are the keys the diff is stated in; a change to that id list is a layout-templates amendment as well as an architecture one. This chunk is expected to cause neither.
- layouts ↔ tests (stand harness): the pinned viewport and the TaskShell mount in the layout plan are what the new `stand_*.rs` check boots; the test plan owns the check's shape and its selection under `agent-run.sh run stand` (§Surface: cli → Primary screens points to test-plan §3 for the grammar).
- layouts ↔ a11y: none through focus order — the chunk adds no focusable element and changes no order, so the Focus Order (SC 2.4.3) binding is not engaged. The shell's accessibility tree update that the truthful flag gates is a11y's and architecture's, not a layout matter.
- layouts ↔ design: none — no token, spacing or breakpoint is touched.

## Acceptance criteria contributions
- (layouts) The chunk's diff leaves the stand screens' structure as the plan states it: no change to the TaskShell hierarchy (`main` mount → shell → header + task body), to the lean tasks' element order, or to the enumerated id list — the stand's source files for app shell, tasks and boot show no structural edit (per layout-templates §Surface: desktop-native → Primary screens).
- (layouts) On each of the four lean stand screens, every diff entry the stand check asserts is named by a stable element id from the plan's enumerated list for that screen (or, for a CRUD row, by its person-keyed row id), and an action inside the task body yields no entry for a header-region id unless research shows a header reading genuinely changes (per layout-templates §Surface: desktop-native → Primary screens).
- (layouts) Before and after readings of every asserted diff are taken at the same pinned viewport — the stand's for stand screens, a stated fixed one for any fixture — in both layout modes, so no diff entry is a viewport artefact (per layout-templates §Surface: desktop-native → Primary screens; §Surface: desktop-native → IA notes).
- (layouts) The chunk adds no CLI screen, verb, usage line or stdout shape for the diff (per layout-templates §Surface: cli → Primary screens).
