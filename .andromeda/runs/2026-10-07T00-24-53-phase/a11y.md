# a11y extract

## Relevance
partial — the chunk adds no UI surface, role, key binding or painted colour, but it turns on two a11y-owned things: the change flag that gates the shell's platform accessibility-tree refresh (a11y-plan §2), and a diff over the snapshot, whose role · name · focus come from the accessibility tree (a11y-plan §7).

## Constraints
- The a11y tier is 0 with the three target criteria of a11y-plan §1 (A11y tier); the chunk introduces nothing those criteria newly bind, so its duty is non-regression: change tracking, the drain and the flag must leave focusability, focus order, roles and accessible names as a11y-plan §5 (Focus order per layout) and §7 (Accessibility tree output) state them.
- a11y-plan §2 (Accessibility tree lifecycle) requires the platform tree to be refreshed on poll when the document has changes, and only through the `Document::accessibility_tree` trait method so a wrapper's override reaches the platform. A truthful flag is what that wording requires; whether the code today refreshes on an untouched document and skips a mutated one — i.e. what the shell actually did before the fix — is research's question, and what it does after is the plan's to state.
- a11y-plan §2 (Accessibility tree lifecycle) records the changed-node set as the set for updating the accessibility tree. A drain therefore has an a11y consumer: the plan must state who drains in the windowed path and that a diff reader's drain cannot starve the shell's refresh (nor a never-drained set leave the flag permanently true). Whether the initial-tree path depends on the flag at all is research's question.
- Per a11y-plan §1 (A11y scope — Dioxus crates; blitz-tests) the stand binary builds no platform adapter while blitz-tests builds with the `accessibility` feature, and a11y-plan §3 (A11y testing tool pick) records no test of the adapter path. So a stand check cannot by itself prove the shell's refresh behaviour; whether the shell's poll path is reachable headlessly is research's question.
- Per a11y-plan §7 (Accessibility tree output) an element's name is derived from other nodes — its text children, and for an input the label bound to it — and text-run nodes carry no stable id. A mutation on one engine node can thus change a different element's snapshot reading; the diff must name the element whose reading changed, and whether the engine's changed set alone reaches that element is research's question.
- Per a11y-plan §7 (Accessibility tree output) focus is read from the tree while enabled · checked · value are read from the element, and per a11y-plan §5 (Focus order per layout; Focus restoration) focus moves — by Tab, by click, by clearing, by removal of the focused node — without any content mutation. A focus move changes two snapshot readings; whether focus, editor-text and checked-state changes pass through a site that marks the set is research's question.
- Per a11y-plan §4 (Per-component pattern catalog — Hidden content) and §5 (Script and framework exposure — the falsy boolean-attribute clear) a node enters or leaves the tree by attribute or style, with its descendants, without being created or dropped. "Appeared / disappeared" in the diff must cover that route, and an `aria-hidden` node stays in the tree marked hidden rather than leaving it.

## Patterns to follow
- A11y assertions are Rust tests in blitz-tests over the AccessKit tree, built after resolve — per a11y-plan §3 (A11y testing tool pick); the diff's stand check belongs in that harness, with the `accessibility` feature on.
- Focus is driven by real input on the stand, in both layout modes, and checked two ways at once — the snapshot node reading focused and the tree's focus — per a11y-plan §3 (Keyboard test harness) and §5 (Test harness pattern); a focus-diff case reuses that shape.
- The snapshot is the single reader of the tree and every later form is a reader of the snapshot model, never of the tree or of a control — per a11y-plan §7 (Accessibility tree output); the diff is one more reader of the model.
- New surface in dioxus-native-dom sits behind its `accessibility` feature and is named in the crate doc beside the snapshot, its text form and the actionable-key check — per a11y-plan §2 (Feature exposure).
- Any change at the shell's refresh site keeps the call on the trait method — per a11y-plan §2 (Accessibility tree lifecycle).

## Anti-patterns to avoid
- (The plan's own anti-pattern section records no intent; these bans are drawn from §2 and §7.) A second role or name mapping inside the diff, or a diff computed from the tree or the DOM beside the snapshot model — against a11y-plan §7 (Accessibility tree output).
- A second reading of a password's or a file input's control to decide or fill a diff entry: the model's fixed mask is the only reading, so a masked value that stays masked is not a changed value to be recovered some other way — against a11y-plan §7 (Accessibility tree output).
- Changing when the platform tree refreshes as a silent by-product of the flag fix, or refreshing it through the base document's builder instead of the trait method (the stable ids would drop out of the platform tree) — against a11y-plan §2 (Accessibility tree lifecycle).

## Contract bindings
- a11y ↔ architecture: the flag, the changed set and `Document::accessibility_tree` are the Document contract (architecture §Standard Contracts); a11y-plan §2 (Accessibility tree lifecycle) states the refresh rule that contract serves.
- a11y ↔ tests: the stand check runs in the blitz-tests harness (a11y-plan §3) under the agent-run contract (test-plan §3); the a11y CI leg's file list is fixed in a11y-plan §9 and carries no stand assertion — whether a new shell-refresh test joins that leg is a tests/CI decision, not assumed here.
- a11y ↔ security: the masked value and the "content never printed" rule of the diff tie a11y-plan §7 (Accessibility tree output) to security-plan §Input Validation.
- a11y ↔ wrap: a11y-plan §2 (Accessibility tree lifecycle) and §7 state today's wording for the refresh and the snapshot's readers; a chunk that changes either leaves them for wrap to amend — phase amends none.

## Acceptance criteria contributions
- (a11y) With the flag truthful, the shell's platform-tree refresh is stated and proven: it fires on a poll after a document change, does not fire on a poll of an unchanged document, and goes through `Document::accessibility_tree` — or the prior behaviour is proven unchanged (per a11y-plan §2 Accessibility tree lifecycle).
- (a11y) After a click, a Tab press and a Shift+Tab press on a stand screen, the diff names exactly the controls whose focused reading changed and no others, in both layout modes, and the control reading focused is the accessibility tree's focus (per a11y-plan §5 Test harness pattern; §7 Accessibility tree output).
- (a11y) A text change is reported on the element whose accessible name it changes, by stable element id, never as a text-run entry; and a node hidden or un-hidden by attribute or style appears in the diff as removed or added with its descendants (per a11y-plan §7 Accessibility tree output; §4 Per-component pattern catalog — Hidden content).
- (a11y) `bash .github/scripts/ci-leg.sh a11y` and the stand's existing accessibility checks pass unchanged — same roles, names, focusability and Tab order before and after the chunk (per a11y-plan §9; §1 A11y tier; §5 Focus order per layout).
