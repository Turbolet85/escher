## Relevant amendment history

- **2026-10-05-ci-gate-legs** — set up the cargo-deny audit gate that the OTel crates must now pass. It runs `cargo deny --locked check advisories` as ci.yml's `audit` job on every push, in the slow tier and uncached, configured by the root `deny.toml`. That config resolves `[graph]` over the six ci.yml platforms with `all-features = true`, so OTel crates behind an optional feature are still audited. Ignores are allowed only per ID with a written reason. There is no blanket allow, and `unmaintained`/`unsound` stay at their defaults. The one standing ignore is RUSTSEC-2026-0192 (ttf-parser 0.25.1, reached only through the exact winit beta pin). It is the precedent for any OTel-chain ignore. RUSTSEC-2026-0285 was fixed by a lockfile-only update to rustls (0.23.43 → 0.23.45), and the entry records that no build graph reaches rustls. If `opentelemetry-otlp`'s transport brings rustls or tonic/hyper into a built graph, that recorded state changes, and the §Data Protection "In transit" TLS record (reqwest `native-tls` only) needs amending. The gate's reach is cargo-deny's resolved graph, not the lockfile, because 0.20.2 prunes `http-cache` and `ravif`, which hides the paste and memmap2 advisories. New OTel crates therefore also need a hand review. The entry extended `--locked` to the audit, a11y and coverage legs. It set ci.yml to `permissions: contents: read`, pinned by a unit test. It required every ci.yml `uses:` to be pinned to a 40-hex SHA, so any new CI step this chunk adds, such as an exporter test, must follow that pin. It also discharged the bootstrap keys `dep-audit-tooling-install` and `dep-security-ci-gate`. This chunk discharges `logging-redaction-wire` the same way, as a §Bootstrap phases key read discharged at wrap.
