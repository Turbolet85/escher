# a11y extract

## Relevance
relevant — the merge's one real-logic conflict is the accessibility builder (`packages/blitz-dom/src/accessibility.rs`), and the keyboard-types 0.8 migration touches the Tab, Enter/Space activation and range-key arms the tier-0 keyboard criteria rest on.

## Constraints
- The a11y target stays tier 0: SC 2.1.1 · 1.4.3 · 2.4.3, so focusability, focus order, keyboard activation and painted colours are a11y surface through the merge and its migrations (per a11y-plan §1 A11y Scope Summary).
- a11y-plan §2 Role derivation requires `aria-selected` · `aria-pressed` · `aria-invalid` to be read on every element, each value trimmed of ASCII whitespace and matched exactly in lower case against a closed set (`true`/`false` for selected; `true`/`false`/`mixed` for pressed; `true`/`grammar`/`spelling`, else `Invalid::True`, for invalid), and `aria-checked` to stay unread. The resolution keeps one `aria-selected` read. Whether upstream's `str::parse::<bool>` read gives the same result as these rows on padded and upper-case values is research's question, and which read survives is the P4 fork the scope names (per a11y-plan §2 Role derivation).
- a11y-plan §7 Accessibility tree output requires an `aria-label` to become the node's `label` only when it is non-empty after trimming, with a whitespace-only one naming nothing. It also requires a `<label>` to name its bound `<input>` (its `for`-target, else its first nested input) by being pushed onto that input's `labelled_by` after the whole tree is built. Upstream's unfiltered `aria-label` read and its `aria-labelledby` loop, which clears `labelled_by`, must not undo either. Whether the merged order keeps both is research's question (per a11y-plan §7 Accessibility tree output).
- a11y-plan §7 Accessibility tree output requires the snapshot to take each node's name from the tree (its `label`, else its `labelled_by` targets' names) with no second role or name mapping. In a Dioxus document every element node carries its stable id as `author_id` through the `Document::accessibility_tree` override, and the tree the shell gets through `&dyn Document` must equal `harness.doc.accessibility_tree()` node for node. A builder change that moves a stand name, role or `author_id` is a regression, not a re-measure (per a11y-plan §7 Accessibility tree output).
- a11y-plan §5 Keyboard Navigation requires these behaviours to survive the `Key::Named(NamedKey::…)` / `Modifiers::META` rename unchanged:
  - Tab and Shift+Tab move focus forward and back.
  - A pressed Enter on the focused `button`, `summary`, `input` of type `submit`/`reset`/`button`, or `a` with `href`, and a released Space on the focused `button`, `summary`, or `input` of type `submit`/`reset`/`button`/`checkbox`/`radio`, dispatch a Click. Each is gated on the `disabled` attribute's presence.
  - A focused range input with no `disabled` attribute steps on the arrows and goes to its minimum on `Home` and its maximum on `End`.
  - The CRUD list's ArrowDown/ArrowUp/Home/End move the selection.

  The stated sequences `tab_order` and `ENABLED_TAB_ORDER` must not move (per a11y-plan §5 Keyboard Navigation).
- a11y-plan §6 Visual Design Verification requires SC 1.4.3 to hold on every measured non-exempt stand row of `stand_contrast`'s three tables (18 control rows, 14 `TEXT_ROWS`, 19 `STATE_ROWS`), with the painted pixel matching the measured background within 1 per channel. Inline-layout edits that move bounds must not move a measured colour pair (per a11y-plan §6 Visual Design Verification).
- a11y-plan §1 A11y Scope Summary records that the stand graph holds neither `accesskit_xplat` nor `accesskit_winit` (`cargo tree --locked -p seven_guis -e normal`, 0 rows), re-read after each lock move at the earlier syncs. The regenerated `Cargo.lock` must keep the stand building no platform adapter, which stays residual-owned on the founder's F1 (per a11y-plan §1 A11y Scope Summary).

## Patterns to follow
- Every a11y check runs in both layout modes, and a state check reads its carriers off the built tree as one stated table per attribute, with the table's row count asserted (per a11y-plan §3 A11y Assertion Harness Contract).
- Expected roles, input names, region names and focus sequences are stated once, in the stand checks' shared module (`controls`, `INPUT_NAMES`, `REGION_NAMES`, `tab_order`, `ENABLED_TAB_ORDER` in `tests/blitz-tests/tests/common/mod.rs`). They are stated expectation, never a second role or name mapping, so the key migration changes how a check presses a key, not what the check expects (per a11y-plan §7 Accessibility tree output; per a11y-plan §5 Keyboard Navigation).
- Keyboard checks drive input through the harness's `press` / `press_with` and read the focused node back at every step. The engine's focus, the snapshot's `focused` node and the tree's focus must agree, with the root dropped from the engine's reading (per a11y-plan §5 Keyboard Navigation).
- The `a11y` leg is read by its per-file log counts (accessibility_hidden 6 · accessibility_roles 6 · focusability_updates 4 · stand_accessibility_ids 8 · stand_contrast 5 · stand_keyboard 14). A sync re-reads those counts on the merged tree and explains any move (per a11y-plan §9 CI Integration).

## Anti-patterns to avoid
- Never let the merged builder set `aria-selected` or `aria-label` twice so that the later, upstream read silently wins. That would replace the trimmed closed-set reading and the blank-label skip that the snapshot's `selected` and `name` rest on (per a11y-plan §2 Role derivation; per a11y-plan §7 Accessibility tree output).
- Never close a residual-owned a11y debt that sits beside upstream's new ARIA reads as part of the merge: the unread `aria-checked`, the missing `aria-activedescendant`, the unhonoured `inert`, and the presence-read `disabled` on any element. Each stays as its pin test records it (per a11y-plan §4 ARIA Patterns & Roles; per a11y-plan §5 Keyboard Navigation).

## Contract bindings
- a11y ↔ tests: the `a11y` leg (`ci-leg.sh a11y`, ci.yml's `a11y` job) and its pin, `LegScriptTest`'s a11y tuple in `.github/scripts/test_ci_workflows.py`, name six files. Upstream's two new files, `accessibility_description.rs` and `accessibility_label.rs`, become blitz-tests targets (`.github/scripts/test_blitz_tests_targets.py` moves by two). Whether they also join the a11y leg, which would move the leg and its pin, is a choice to make explicitly at P4, not by drift (per a11y-plan §9 CI Integration).
- a11y ↔ security: the builder's attribute reads are stated as a closed set that carries no text out (per a11y-plan §2 Role derivation). Upstream's `aria-description` text and its `aria-labelledby`-computed names reach the platform adapter and, through the snapshot's `name`, the driver's carriers. Whether that is a boundary widening is the security domain's call, read against the playbook at P4.
- a11y ↔ design: the stand contrast record reads the accent tokens (`#3a5ce5` / `#2a4cd3` / `#1f3fc1`) in design-system §Color Palette. A merge that moves no stand CSS leaves both records standing (per a11y-plan §6 Visual Design Verification).
