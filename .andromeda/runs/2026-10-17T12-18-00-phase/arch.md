# arch extract

## Relevance
relevant — a workspace-wide upstream merge that moves coupled pins, the workspace version, a member crate (`apps/bump`), the accessibility builder's contract and the key types every escher crate names.

## Constraints
- Coupled pins move as one set, never one side alone. Taffy is recorded as a registry `"0.15"` with "no git dependency left in the manifest". Taking upstream's head `1e5479ae6` (Taffy back on a git `rev`) contradicts that decision as written. Choosing that pin therefore means amending the decision, recorded at P4, not just adding the line silently (per architecture §Established Decisions → [Dependency pinning]).
- The workspace stays edition "2024" with rust-version "1.91.0". The engine crates are pinned together at `=0.3.0-beta.3`, and the merge moves them as one version (beta.4). The MSRV job runs `cargo build` only, so whether the moved dependencies build on 1.91 is that job's reading (per architecture §Inherited Defaults; per architecture §Established Decisions → [MSRV]).
- The merge must add no network port, no second listener and no new env var. It must also add no workspace crate name beyond what the plan already registers. `bump` is in the registered crate names and leaves with upstream, so the Names row shrinks at the wrap and nothing is added to it (per architecture §Occupied Resources).
- The accessibility builder has a contract. It names a node from its text children, from an `aria-label` that is non-empty after trimming, and from a bound `<label>` pushed onto the input's `labelled_by`. It reads `aria-selected` · `aria-pressed` · `aria-invalid` trimmed and in lower case, as a closed set. A conflict resolution that keeps upstream's untrimmed `aria-selected` or unfiltered `aria-label` departs from this contract. It is then a P4 fork plus a contract amendment, never a silent override (per architecture §Standard Contracts → Mutation, query and CSSOM).
- The snapshot's `name` takes a node's non-empty `label`, else its `labelled_by` targets' names. So any change to the builder's labelling order or sources, upstream's `aria-labelledby` included, reaches the driver's readings (per architecture §Standard Contracts → Dioxus DOM bridge).
- blitz-tests keeps one test target per file directly under `tests/`, with no `autotests` override. Upstream's `tests/all.rs` stays the one `[[test]]` table, held at `test = false`. Upstream's new test files become targets of their own, and `BlitzTestsTargetsTest` pins that contract (per architecture §Conventions → Tests; per architecture §Standard Contracts → CI contracts).
- Incremental and non-incremental layout must produce identical layouts after the merge's inline-layout and Taffy edits (per architecture §Design Philosophy, "One incremental pipeline, safe identities").

## Patterns to follow
- The upstream sync is recorded as a merge base plus a merge commit on the build branch. The `Upstream sync:` line names the last merged sha and its merge commit, and that line moves to the new pair at the wrap (per architecture §Project Intent).
- Key types reach escher's crates through blitz-test-harness's re-exports `Key` and `Modifiers` (of `keyboard_types`). The driver's `press` names its keys through them, with no dependency of its own. So the keyboard-types 0.7 → 0.8 migration is made at those sites, and no direct dependency is added (per architecture §Standard Contracts → Test harness; per architecture §Established Decisions → [Driver session]).
- Dependencies are declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }`. In-repo crates use `default-features = false`, except `seven_guis` (per architecture §Conventions → Manifests).
- Engine and upstream crates gate tracing at each call site with `#[cfg(feature = "tracing")]` and a no-op fallback. dioxus-native-dom's crate-local `trace!` macro expands to `tracing::debug!`. Any new upstream call site (`keyboard_compat`, vibey-script) is read against this pattern (per architecture §Conventions → Feature gating).
- The as-built records that this merge moves are amended at the wrap, not before: the Stack row's keyboard-types "0.7", test-that "0.5.2", workspace "0.3.0-beta.3", the Release tooling (bump) row, and the directory tree's `apps/bump/` (per architecture §Stack and Technologies; per architecture §Infrastructure Patterns → Directory structure).

## Anti-patterns to avoid
- A one-sided pin fix: bumping or patching one side of a coupled pair (html5ever family ↔ stylo web_atoms, skrifa ↔ parley/vello, svgtypes ↔ usvg, winit exact beta, taffy) to make the merged set resolve. A set that does not resolve is a halt (per architecture §Established Decisions → [Dependency pinning]).
- A new resource added silently. A listener, port, env var or workspace crate arriving with upstream's delta without first being registered in arch §Occupied Resources is banned (per architecture §Occupied Resources).
- Two reads of one attribute in the accessibility builder, where the later one silently wins. The builder states one reading per attribute (per architecture §Standard Contracts → Mutation, query and CSSOM).

## Contract bindings
- arch ↔ security: the no-git-dependency rule and `--locked` builds (§Established Decisions → [Dependency pinning]) bind to security-plan §Dependency Security and the cargo-deny audit (`deny.toml` has no `[sources]` table). The accessibility builder's closed-set read (§Standard Contracts → Mutation, query and CSSOM) binds to security-plan §Input Validation's "a closed set, no text carried out". The new page text that upstream's `aria-labelledby` and `aria-description` carry to the adapter and to the snapshot `name` is a possible crossing question for the security domain.
- arch ↔ obs: the sink allowlist (`ENGINE_TARGET_PREFIXES` / `ESCHER_TARGET_PREFIXES`; every other target dropped whole at every level, §Cross-cutting Patterns → Logging and timing; §Standard Contracts → Telemetry bootstrap) binds to the obs re-check of each new upstream target and record class.
- arch ↔ tests: the blitz-tests target contract (§Conventions → Tests; §Standard Contracts → CI contracts) binds to the moved target pin and the per-OS tallies. The both-layout-modes convention binds to the stand and oracle re-runs.
- arch ↔ a11y: the builder's naming and state contract (§Standard Contracts → Mutation, query and CSSOM) and the keyboard activation arms (§Established Decisions → [Scrolling and input]) bind to `accessibility_states`, `stand_keyboard` and `range_input_interaction`.

## Acceptance criteria contributions
- (arch) After the merge the coupled pins resolve as one set at the chosen sha. The root manifest holds no git dependency, unless P4 chose `1e5479ae6` and the [Dependency pinning] decision is amended to say so (per architecture §Established Decisions → [Dependency pinning]).
- (arch) The merged tree adds no network port, no listener, no env var read and no workspace member. `members` loses `apps/bump` and gains nothing (per architecture §Occupied Resources).
- (arch) The merged accessibility builder holds exactly one read of each of `aria-label` and `aria-selected`. Which one survives is recorded, and the builder either still matches the contract's trimmed, closed-set readings or the contract is amended for the chosen read (per architecture §Standard Contracts → Mutation, query and CSSOM).
- (arch) escher-driver and the stand checks name keys only through blitz-test-harness's `Key` / `Modifiers` re-exports, so no crate gains its own `keyboard-types` dependency. The driver's key-name words are unchanged (per architecture §Standard Contracts → Test harness).
