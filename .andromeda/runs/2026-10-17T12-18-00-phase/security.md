## Relevance
relevant — the merge moves the dependency graph and a pin rule (Taffy git vs registry), rewrites the accessibility builder's attribute reads, which take untrusted markup and feed ratified crossings, and brings new upstream log call sites under escher's sink.

## Constraints
- Per security-plan §Dependency Security (Pinning), the root manifest holds no git dependency, and Taffy is a crates.io registry version with a checksum in `Cargo.lock`. The `1e5479ae6` pin would put a git `rev` back, against that rule as written. The `23b9b26a9` pin keeps it. Choosing `1e5479ae6` therefore needs a recorded decision and a plan amendment before it lands; it is never a silent change. Also note that `deny.toml` has no `[sources]` table, so the audit leg would not catch a git dependency (scope's own reading; whether the tool would flag it is research's question).
- Per security-plan §Dependency Security (Audit tool), the audit is `cargo deny --locked --workspace --all-features check advisories licenses` over the whole workspace graph. The merged lock must read green. Any advisory it fires on is fixed by a semver-compatible update, or ignored by ID with a written reason. There is no blanket allow, and `unmaintained` / `unsound` stay at their defaults. Five ignores stand today. An ignore the merge drops or adds is named with its reason.
- Per security-plan §Dependency Security (Pinning — the 2026-10-10 and 2026-10-13 sync bullets), a sync takes upstream's dependency set whole, with no `cargo update` beyond it. The two `escher-*` workspace entries are the only lock lines outside upstream's set, and they may only follow the workspace version. Every third-party package that enters, leaves or moves is reviewed by hand: licence, repository, build script, proc-macro flag and direct dependent. Here that means `test-that` / `test-that-macro` 0.5.2 → 0.6.0 and the four `bump`-only crates leaving.
- Per security-plan §Dependency Security (Supply chain integrity — Lockfile verification), every ci.yml cargo leg and every build keeps `--locked`, and `Cargo.lock` stays committed. The lock is regenerated from the resolved manifests at the chosen pin and is never left unlocked.
- Per security-plan §Input Validation (row `aria-selected` · `aria-pressed` · `aria-invalid`), each value is trimmed of ASCII whitespace and matched exactly, in lower case, against a closed set. The builder has no log site and no panic path, and writes closed enums or booleans, never the attribute's text. The conflict resolution in `packages/blitz-dom/src/accessibility.rs` must leave one `aria-selected` read that meets this. Upstream's untrimmed `str::parse::<bool>` read does not.
- Per security-plan §Input Validation (row `aria-label` · `<label for>`), an `aria-label` names the node only when it is non-empty after trimming. A whitespace-only label names nothing. A `<label>` joins `labelled_by` only when both the label and its input have built nodes, and no lookup panics. Names leave the process only by the ratified carriers (socket, client stdout, MCP stdout, platform adapter) and never reach a log. Upstream's unfiltered `aria-label`, its `aria-labelledby`-computed names and its `aria-description` text are new page-text exits. Whether they widen a boundary for the founder is a P4 question, with that row's ratification history and the `@font-face` row as reference.
- Per security-plan §Logging & Monitoring (escher's own sink), a host that installs `escher_telemetry::init` prints engine-prefixed targets (`blitz`, `dioxus_native`, `stylo_taffy`, `accesskit_xplat`, `debug_timer`, `js_console`) with only the safe fields. `escher_*` targets print with the content-named fields redacted. Every other target is dropped whole at every level, and closed spans follow the same rule. Every new `tracing`/`log` site in upstream's delta must fall under this rule: dioxus-native-dom's `keyboard_compat` (under the `dioxus_native` prefix) and the vibey-script runtime (`js_console` / `blitz`). Whether any new site uses a field or target outside the sets is research's question.

## Patterns to follow
- The 2026-10-13 sync's lock evidence (security-plan §Dependency Security, Pinning): compare the merged lock's `name@version` set with upstream's at the pinned sha, with the two `escher-*` entries set aside, and record the audit leg's `advisories ok` (now also `licenses ok`) with `deny.toml` unchanged or each change named. The model is `escher-0.1.0/chunks/2026-10-13-upstream-sync-polish-and-ship/evidence/lock.md`.
- An upstream-brought widening (security-plan §Input Validation, row `@font-face` source): when a merge brings upstream behaviour that widens a boundary, the founder ratifies it "as upstream's behaviour" and an offline check that pins it follows. Use this precedent for `aria-labelledby` / `aria-description` text if P4 rules them a widening.
- Needle captures (security-plan §Input Validation, row `aria-label` · `<label for>`): at `RUST_LOG=trace`, count id, name and typed-sentinel needles on the `escher-session` host's stderr (`host_log`) and on the `mcp` role's stderr (`mcp_log`, `examples/seven_guis/tests/mcp_log.rs`) under both builds, `-p seven_guis` and `--workspace`. These are the standing readings the "sink allowlist re-checked" claim reuses.
- Hand review of a moved crate (security-plan §Dependency Security, Pinning — the 2026-10-10 sync bullet): read licence, repository, build script, proc-macro flag and direct dependent from the lock and the registry metadata, and state that the source beyond the manifest was not read.

## Anti-patterns to avoid
- Fixing a coupled pin on one side, or making the audit pass with a blanket allow, a wildcard ignore, or `unmaintained`/`unsound` set to none (security-plan §Dependency Security, Audit tool).
- Keeping two reads of `aria-selected` or `aria-label`, so that upstream's untrimmed or unfiltered read silently wins, or adding any attribute read that carries the attribute's text into a log, field or new carrier (security-plan §Input Validation, rows `aria-selected` · `aria-pressed` · `aria-invalid` and `aria-label` · `<label for>`).
- Widening the sink's target prefixes or safe-field set to admit a new upstream record, or adding a log field that holds page, call or screen content (security-plan §Logging & Monitoring, escher's own sink).

## Contract bindings
- security ↔ tests: the audit leg is the CI `audit` job (security-plan §Dependency Security, CI integration). `accessibility_states`, `accessibility_names` and `stand_accessibility_ids` re-prove the closed-set and label contracts. `host_log` and `mcp_log` hold the needle captures. Upstream's `accessibility_description.rs` and `accessibility_label.rs` become their own targets and move the blitz-tests target pin (`.github/scripts/test_blitz_tests_targets.py`).
- security ↔ obs: the sink allowlist and scrub sets (`packages/escher-telemetry/src/format.rs`; obs-plan §3) are the one rule the new upstream log sites are judged against.
- security ↔ a11y: the accessibility builder's merged reads feed both the platform adapter crossing and the snapshot's `name` / `selected`. An a11y-driven resolution choice is also a security one.
- security ↔ arch: §Occupied Resources gains nothing (no new crate, port, env var or listener). At the wrap, the plan rows that cite `apps/bump` (security-plan §Input Validation, row "CLI arguments (bump)") and the Pinning sync record go stale and need an amendment, along with architecture's `Upstream sync:` line.
