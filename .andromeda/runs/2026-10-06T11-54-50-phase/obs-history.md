## Relevant amendment history
- **2026-10-06-telemetry-bootstrap** — set the §8 allowlist scrub: engine prefixes `blitz`, `dioxus_native`, `stylo_taffy`, `accesskit_xplat`, `debug_timer` and `js_console` print only `node_id`, `status`, `waiting_nodes`, `property` and the `log.*` location fields, and content-named fields (`url`, `href`, `src`, `html`, `text`, `value`, `attrs`, `path`, `request`, `error`, `panic.payload`) are redacted everywhere. The scrub reaches escher's sink only, and the upstream `fmt::init()` and `env_logger` sinks stay unscrubbed (`pii-scrubbing-wire` is still open for them). It also fixed the §2 rule: engine and upstream crates compile tracing only under the `tracing` feature, while escher-telemetry is ungated. This chunk matters here in three ways. Any log site in `accessibility.rs` or dioxus-native-dom must be cfg-gated. A node may be identified only by `node_id`. A new tracing target must sit under one of these prefixes. And `id`, `author_id`, `name` and `label` are not in the redaction set, so a new field with one of those names would print raw even in escher's sink.
- **2026-10-06-headless-stand** — §3 Logging stack now names `seven_guis_native` (the windowed binary) as the only installer of `escher_telemetry::init`. The headless stand `seven_guis::stand` and its in-process checks install no subscriber, `println!` nothing and read no env. This is the no-sink shape the new `stand_*` accessibility-identity check must keep, and the extract's acceptance grep (`escher_telemetry`, `println!`, `std::env`) checks for it.
- **2026-10-06-stand-test-contract** — added the agent-run harness log (§3, §6, §8, §9). `scripts/agent-run.sh` emits python3-`json` events (`boot`, `run.start`, one `test` per libtest line, `run.end`) to `target/agent-run/events.jsonl`. Nothing inside a `failures:` block is read, and raw output, including assertion text, goes only to the unscrubbed `run.log`. The harness log sits outside escher's scrub and carries no content-named field. This is the binding the new check surfaces through: its `test` events, and the rule that `run stand` and `logs` carry no scrub-set key and no stand id or name text.
- **2026-10-06-id-persistence** — narrowed the headless-stand bullet's "no `println!`" to a single named exception. `stand_id_persistence`'s re-executed child prints its pid and ids to stdout, and the parent captures them and reads them only into its assertion, never into a log. This is the one precedent of stand ids reaching stdout in a stand check. The new accessibility-identity check should not add a second exception: it builds the tree in-process, so it has no child to capture. If it did need one, that would be a fresh §3 amendment, not covered by this one.
- **2026-10-06-upstream-sync-element-identity** (file:line citations re-pointed after the upstream merge) — 20 citations into merged upstream files were re-pointed by a measured line map. This includes the §6 Logged events citations that the extract leans on for blitz-dom and for the dioxus-native-dom `set_attribute` debug `trace!`.
