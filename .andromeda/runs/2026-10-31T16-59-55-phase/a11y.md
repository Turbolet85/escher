## Relevance
relevant — a new interactive painted list on every `select` surface, under the tier-0 target SC 2.1.1 · 1.4.3 · 2.4.3 (per a11y-plan §1 A11y Scope Summary).

## Constraints
- SC 2.1.1: opening the list, moving in it, choosing and closing without a choice must each be reachable by key alone; a11y-plan §5 Keyboard handling requires one `input` then one `change` per changed choice and none for a key that changes nothing, and its detail excludes a disabled select from keys. Its lines "no popup is painted" and "Enter and Space open nothing" are this chunk's to restate. Which keys do what with a list open, and whether a closed select's arrows keep moving the choice, is the founder's P4 fork; the plan does not decide it. Whether the code still reads as those lines say is research's question.
- SC 2.4.3: a11y-plan §5 Focus order per layout requires `select` focusable unless inert or disabled, and the Tab walk must stay as stated with the list open and after it closes. The plan names no focus target for an open list and no return of focus on close: its modal-trap and restoration lines read NOT YET MEASURED, so the focus contract is the P4 fork's and has no plan rule to inherit.
- Pointer: a11y-plan §5 Focus restoration holds "an option of a closed single select takes no click" and a disabled form control stopping the walk first. The first must be restated for an open list's options, and the second must still hold, the list not opening on a disabled select. Whether the walk's gate covers the new opening path is research's question.
- SC 1.4.3: a11y-plan §6 Color contrast requires 4.5 (3.0 for large text) by `contrast_ratio` on every non-exempt text pair, read through `Harness::text_contrast`, which reads `None` under opacity below 1, a filter or a background image. The list's new engine colours (the founder's P4 fork, the engine holding no tokens) must be measurable by it, not `None`. The plan's detail records the user-agent pair as not measured on a single select, so this chunk owes the first such measurement.
- Tree: a11y-plan §4 Hidden content and §6 Visibility and hit-testing require a select's options to stay in the tree under `display: none`, with `hidden`, `inert` and `visibility: hidden` still excluding them; a11y-plan §7 Accessibility tree output requires the select to keep role `ComboBox` and its options `ListBoxOption`, each `selected` from its chosen state, in the detail's reading, open or closed. The snapshot must keep taking role, name, focus and `selected` from the tree (a11y-plan §7 Accessibility tree output).
- Refresh: a11y-plan §2 Accessibility tree lifecycle requires a tree refresh to come from `changed_nodes`, which hover, active, scroll and layout do not mark, and its detail has `apply_select_choice` marking nothing for a choice of the chosen option. An open or closed state the tree reports must mark the changed set or the platform tree goes stale. a11y-plan §2 Role derivation has `aria-expanded` read as an attribute; whether a native select's open state reaches `expanded` without one, as scope's inferred line assumes, is research's question.
- Driver: a11y-plan §7 Accessibility tree output's actionable-key rule requires every actionable element to read an author key, `unkeyed_actionable` returning nothing on every stand task, and has the driver refusing a `click` or `type` as `disabled` where `enabled` reads `Some(false)`. Options become acted on here, so both must be read against them, the flight booker's two options included. `enabled` reads the presence of `disabled` while a disabled group's rows read disabled through `option_disabled` (a11y-plan §5 Keyboard handling detail); whether such a row reads disabled to the refusal and to the contrast exemption is research's question.

## Patterns to follow
- The `multiple` select's rows as the precedent for options with boxes of their own: rows reading their own client rects as `bounds` in both layout modes (per a11y-plan §7 Accessibility tree output detail).
- The engine-default chosen-row pair hardcoded in `packages/blitz-dom/assets/default.css` because the engine holds no tokens, its ratio measured by `select_interaction` in both layout modes (per a11y-plan §6 Color contrast detail).
- Stated-table checks, row count asserted, in both layout modes: `select_interaction`'s keys and typeahead tables with `input`, `change` and `has_changes` per row, and `stand_act_select`'s Tab walk equal before and after a choice (per a11y-plan §5 Test harness pattern detail).
- `stand_keyboard`'s step-by-step agreement of the engine's focus, the snapshot's `focused` node and the tree's focus, driven through `press` / `press_with` (per a11y-plan §5 Test harness pattern).
- Tree states read off the built tree with `test_that` or `verify_that!`, as `accessibility_merged_states` reads `aria-expanded` (per a11y-plan §3 A11y testing tool pick).

## Anti-patterns to avoid
- A second role or name mapping for the list or its options in the snapshot, its text form, the diff, MCP results or the expected-value tables (per a11y-plan §7 Accessibility tree output).
- A second contrast formula, threshold or exempt rule for the list's rows, in the lint or in a test (per a11y-plan §6 Color contrast).
- Restating the lint's `overlaps` exclusion by role: the exclusion reads the element through `closed_select_of`, so that CRUD's `role="option"` rows are not read as a select's (per a11y-plan §6 Color contrast detail).

## Acceptance criteria contributions
- (a11y) SC 2.1.1: on a fixture select and `select#flight-type`, in both layout modes, by key alone, the list opens, a row is chosen and the select reads that choice, and it closes without a choice with the value unchanged; a change fires exactly one `input` and one `change`, no change none; a disabled select opens nothing (per a11y-plan §5 Keyboard handling).
- (a11y) SC 2.4.3: `stand_keyboard` and `stand_act_select` walk the stated Tab orders before opening, after a choice and after a close without a choice, and the engine's focus, the snapshot's `focused` node and the tree's focus agree at every step, including with the list open, as the founder's focus fork states (per a11y-plan §5 Test harness pattern).

- (a11y) Tree: with the list open and closed, in both layout modes, the select reads `ComboBox`, its options `ListBoxOption` with exactly the chosen one `selected`, the snapshot's role and name equal the tree's, and any `expanded` reading the chunk adopts is a stated table with its count asserted (per a11y-plan §7 Accessibility tree output).
