@extract_section name=constraints
- The owed replay test (CARRY cry-sxrivdk3) is the open item test-plan §5 Integration Test Strategy names as owed ("A kept actions step's replay, owed", fct-kzdrls5d); it should be an integration check in tests/blitz-tests/tests/ that measures what is now "by construction, unmeasured". Whether `Check::replay` already holds on a kept `actions` step is what the test has to show, not something to assume (per test-plan §5 Integration Test Strategy).
- Recorded-check replay is required to run as an ordinary `cargo test` target through `Check::from_bytes` then `Check::replay`, every step re-validated through `Session::run`, red at the first step whose acceptance or kept answer (compared as a JSON value) differs (per test-plan §2 Test Strategy, Recorded-check replay).
- The replay contract under test is `Check::replay(&mut Session) -> Replay` with `Replay { holds, another_app, ran, change }` and `Change { step, accepted_then, accepted_now, keys, refused }`, `keys` being the verb's result fields that differ, in table order. The "differing actions answer names the step and the key" assertion reads `Change.step` and `Change.keys`. Recording is unix-only (`Session::recording_into` returns `Unsupported` elsewhere), so the record-then-replay test is `cfg(unix)`-gated or reads a committed check (per test-plan §3 `session-start`, contract doc:test-plan/contracts/session-lifecycle).
- Session checks hold a session through `tests/session_common/mod.rs` (`hold`, `act`, the call builders `graph()` and so on) or through `tests/fixtures/mod.rs` (`boot`, `hold`), in both layout modes (`incremental` true and false). A new builder or reader goes into the shared module and is not redefined in each file (per test-plan §3 Test Harness Contract, blitz-tests (session checks) and blitz-tests (fixtures)).
- The handler-coverage read is required to change nothing on the screen, like `graph` and `actions` (`stand_graph`, `stand_actions`). Its check asserts that the snapshot and focus are unchanged across the call, in both layout modes (per test-plan §5 Integration Test Strategy, Session ↔ held instance).
- The stand checks have a zero-failure flakiness budget: a new `stand_*.rs` file enters `stand-repeat` (three rounds, no retry) through its glob, and it has to stay green there (per test-plan §10 Quality Gates & Coverage Targets, Flakiness budget).
- Coverage floors bind per crate: `packages/escher-driver` 97 %, `packages/dioxus-native-dom` 83 %. Any code added to either crate (a dispatch record or a coverage reader) must keep the crate at or above its floor in the `coverage` leg (per test-plan §10 Quality Gates & Coverage Targets, Coverage floors).

- Stand checks are picked up by the `stand_` prefix: `bash scripts/agent-run.sh run stand` selects every `tests/blitz-tests/tests/stand_*.rs` file with no script change, and `run {name}` runs one file. The newest reading is passed 244 · failed 0 · ignored 7 over 52 files (per test-plan §3 Test Harness Contract, `run {selection}` and Proof, the newest reading).
- `session_common` already has the readers `graphed(session, call)` (a `UiGraph`), `refused`, `refused_unchanged` and `act`. A coverage check reads the graph's `GraphNode.handlers` / `GraphHandler.event` through these readers. `GRAPH_DRIVES` in `tests/common/mod.rs` lists each stand task's drives (seven rows), which makes it a ready-made "set of checks that exercised" fixture (per test-plan §3 Test Harness Contract, blitz-tests (stand checks) and blitz-tests (session checks)).
- Committed checks live under `tests/blitz-tests/checks/` (counter-cli.json, counter-mcp.json), are embedded as bytes by `stand_replay`, and are kept fresh by seven_guis `recording`'s byte-for-byte comparison through `record_checks.sh`. A committed check with an `actions` step would follow this path and hold no typed text, host path, secret or `screenshot` step (per test-plan §7 Test Data & Fixtures, tests/blitz-tests/checks).
- Bridge-level unit tests in dioxus-native-dom sit in the `bridge_tests` child module (`dioxus_document_tests.rs`) and use the `cfg(test)` shim `DioxusDocument::dispatch_to_vdom`. A record of dispatched (element, event) pairs would be pinned there, adding no `pub` or constructor beyond what the test needs (per test-plan §3 Test Harness Contract, Crate-local test helpers, dioxus-native-dom).
@extract_section name=anti_patterns
- No sleep and no wall-clock read in session checks except where wall time is the subject. A replay or coverage check moves time only through the driver's `advance` (per test-plan §5 Integration Test Strategy, Wall time in the session checks).
- Do not add a test framework and do not give stand checks a skip path: the headless-stand checks assert unconditionally under the bundled DejaVu Sans (per test-plan §2 Test Strategy, Font-dependent tests and Command-line checks and shell flows).
- A check compared byte for byte across OSes holds no shot. A committed check that carries an `actions` step must not carry a `screenshot` step (per test-plan §2 Test Strategy, Pixel tests).
