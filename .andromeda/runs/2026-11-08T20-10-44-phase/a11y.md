@extract_section name=constraints
- a11y-plan §7 Screen Reader Support (snapshot model) requires the read-only UI graph (`DioxusDocument::graph`) to hold one node per snapshot node, names and closed words only, never a second role or name mapping; the coverage command reads that graph and must not derive its own node set or role/name mapping.
- a11y-plan §7 Screen Reader Support (actionable-key rule) requires every actionable element to read an author key carried as its AccessKit `author_id`, stable under edits of surrounding code; the coverage output keyed on the graph's node id (and optional `owner`), never on a `NodeId`, must hold to that key.
- a11y-plan §7 Screen Reader Support (actionable-key rule) requires `unkeyed_actionable` and `actionable_nodes` to read one actionable rule whose listener leg is the vdom walk's exact current listeners holding an event other than `mounted`, the `data-dioxus-id` mark serving event dispatch alone; whether the graph's `GraphNode.handlers` already reads that same leg (and so whether `mounted` is excluded from the handler count and a re-render-removed listener uncounted) is research's question.
- a11y-plan §7 Screen Reader Support (snapshot model) requires `clickable` to be read from the vdom walk's current `click` listeners on an element that is no disabled form control, not from the listener mark; a coverage count of click handlers should not contradict that reading.
- a11y-plan §7 Screen Reader Support (password masking) requires a password input's typed text to appear in no snapshot field or tree node (`MASKED_VALUE`); the coverage read carries no control value or typed text, consistent with the scope's read-only boundary.
- a11y-plan §6 Visual Design Verification (visibility and hit-testing) requires nodes under `display: none`, `visibility: hidden` or `inert` to be absent from the tree and so from the snapshot; handlers on such nodes are therefore outside the graph's node set — whether the command reports them as unexercised or not at all is research's question.

- §7 Screen Reader Support: `DioxusDocument::unkeyed_actionable` as the single actionable-rule check, returning nothing on every stand task — the coverage command's handler set can be checked against `actionable_nodes` for agreement on the stand.
- §3 A11y Assertion Harness Contract: headless assertions over the built tree in both layout modes, each a stated table with its row count asserted — the form the owed `actions` replay test and the coverage test can follow.
- §5 Keyboard Navigation (test harness pattern): `stand_keyboard` drives Enter / Space through the harness's `press` / `press_with`; a recorded check exercising a handler by keyboard rather than click is a candidate row for the "exercised" set.
