After a set of kept checks has run on the stand, one command lists exactly the handlers none of them exercised: the command-line role `escher-session coverage <app> <check>…`, over `escher_driver::handler_coverage`, replays each named kept check on a fresh session of the app, reads the UI graph at boot and after every replayed step, and answers one JSON line of the (id, owner, event) handlers no replayed dispatch reached, `mounted` excluded. On the six served tasks in both layout modes, a check of one `snapshot` lists exactly the boot screen's handlers (`HANDLERS_AT_BOOT`, equal to the graph's handlers on a fresh boot), and a check of each task's `GRAPH_DRIVES` lists exactly its `UNEXERCISED_AFTER_DRIVES` row; two checks list only what neither exercised; the reached record holds on the load page, which registers no state; a step refused `disabled` exercises nothing and a keyboard activation exercises the click it dispatches; a handler whose element its own step removes reads exercised. Handlers inside a canvas are not counted: the count reads the UI graph's DOM listeners, and 0.4.0 extends it (`cargo test -p blitz-tests --locked --test stand_handler_coverage`; through the binary `cargo test -p seven_guis --locked --test cli_commands`).
