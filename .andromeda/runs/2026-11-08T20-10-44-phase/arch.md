@extract_section name=constraints
- Every driver call runs through `Session::run`, which validates first; the command and refusal schema is stated once as `'static` data (fourteen verbs, eight closed causes), and the `v3` wire, command line, MCP server and the `command`/`tool_call` spans carry it. A new coverage verb is a schema change that every carrier must carry, and the founder rules on that boundary widening (per architecture §Standard Contracts → Driver session).
- Under §Established Decisions → Driver session, no `NodeId` may cross a session. Only ids, names, closed flag words and booleans, and a UI graph's names cross. The coverage answer must key handlers on the graph's stable node id and its optional `owner`, and a new carrier or exit widens the boundary (per architecture §Established Decisions → Driver session).
- The UI graph (`DioxusDocument::graph`), the snapshot and the stable-id tiers, including the reserved `{owner}///{key}` virtual form, read the screen read-only and hold no `NodeId`. The coverage read must stay read-only and must not redefine the graph's shape (per architecture §Standard Contracts → Dioxus DOM bridge).
- `serde_json` may only read MCP requests and kept checks. Any coverage answer must be hand-written in the crate-private `json` module, and no command's ending may write back anything the caller typed (per architecture §Standard Contracts → Driver session).
- A kept check is a recording directory named only by the launcher's `--record <dir>`. It is never named by a tool call and is held owner-only `0700`. A verb that took a check path from a caller would be a new input class (per architecture §Occupied Resources → Filesystem).
- escher-driver depends on no app, emits no event, installs no subscriber and reads no env var. It builds its spans by hand, ungated, with no `#[instrument]` (per architecture §Established Decisions → Driver session; per architecture §Conventions → Feature gating).
- The snapshot and graph modules of dioxus-native-dom are gated by `accessibility`. `use_graph_state`/`SignalRegistry` stay ungated, and the bridge's `handle_event` sets the registry's dispatch only where a registry stands. Whether a per-(element, event) record of reached handlers holds on every app is research's question (per architecture §Cross-cutting Patterns → Config management; per architecture §Standard Contracts → Dioxus DOM bridge).
@extract_section name=patterns
- `Check::from_bytes` then `Check::replay`, which runs each kept step again through `Session::run`. A masked `type` is kept as its stand-in and a shot is kept without its pixels. This is the path for the owed `actions`-step replay test (per architecture §Standard Contracts → Driver session).
- `DioxusDocument::actionable_nodes` and `unkeyed_actionable` read one actionable rule (focusable, an interactive role, or current listeners holding an event other than `mounted`) and list results in snapshot pre-order. A handler-coverage reader should follow the same read-only, one-rule form (per architecture §Standard Contracts → Dioxus DOM bridge).
- Integration tests use one behaviour per file and open with a `//!` doc. Stand checks share helpers through non-target modules under `tests/`. Tests first assert that the fixture produces the condition, and scenarios run in both layout modes (per architecture §Conventions → Tests).
- The headless stand (`seven_guis::stand`) boots the lean tasks, Cells and the load page offline in a pinned 800x600 Light viewport. It is the "on the stand" ground for both the coverage acceptance and the replay test (per architecture §Standard Contracts → Headless stand).
@extract_section name=anti_patterns
- No `NodeId` in any coverage answer, log or span. Nothing may log an id, a name or a value, and no log may carry the snapshot, its text or a diff beyond its three counts (per architecture §Standard Contracts → Driver session; per architecture §Standard Contracts → Dioxus DOM bridge).
- No serialization crate may write an answer, and no tool call may take a recording or check path (per architecture §Standard Contracts → Driver session; per architecture §Occupied Resources → Filesystem).
- A kept check compared byte for byte across OSes holds no `screenshot` step. The replay test's recorded session must not rely on one (per architecture §Existing Scopes).
@extract_section name=bindings
- arch ↔ tests: a new verb moves the `VERBS` count pins named in scope §Premises (`.github/scripts/test_capability_statement.py`, `docs/capabilities.md`, README's tool count). The README is read by the capability-statement pin (per architecture §Project Intent → Front page).
- arch ↔ obs: the driver's `command`/`tool_call` spans carry the schema, and escher-driver emits ungated spans with no subscriber (per architecture §Cross-cutting Patterns → Logging and timing).
- arch ↔ security: the session boundary (no `NodeId`, no caller-typed write-back, owner-only recording dir) governs what the coverage answer may carry (per architecture §Established Decisions → Driver session).
@extract_section name=acceptance
- (arch) The coverage answer keys each unexercised handler by the graph's stable node id (with optional `owner`) and event name. No `NodeId` crosses any carrier (per architecture §Established Decisions → Driver session).
- (arch) The coverage read mutates nothing. The graph, snapshot, stable-id grammar and `actions` shapes are unchanged (per architecture §Standard Contracts → Dioxus DOM bridge).
- (arch) If a verb is added, it is stated once in the `'static` schema and carried consistently by the `v3` wire, the CLI, MCP and the spans, with the verb count pins updated together. Its answer is hand-written in the `json` module (per architecture §Standard Contracts → Driver session).
- (arch) The owed test replays a kept `actions` step through `Check::from_bytes` and `Check::replay` on the stand in a one-behaviour integration test file opening with `//!` (per architecture §Conventions → Tests).
