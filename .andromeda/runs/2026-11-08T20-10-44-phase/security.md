@extract_section name=constraints
- security-plan §Input Validation (driver session socket, the widening rule) requires that any new verb, argument kind, result field, carrier or exit for handler coverage be treated as a boundary widening (founder-ratified), while a new closed-value field inside an already ratified carrier is not; a verb or argument naming a check path on disk would be a new input class on every carrier (the scope's P4 fork).
- security-plan §Input Validation (driver command schema) requires a new verb, if added, to enter the closed `'static` verb table and pass `validate`/`validate_session` on socket, CLI and MCP alike, with no `unwrap`/`expect`/panic on call-supplied input, no clock read, no `NodeId` kept between calls, and its `command` span holding fixed words, bools and counts only.
- security-plan §Threat Model Summary (local IPC and local stdio vectors) requires the coverage answer to carry only what the UI graph already carries — ids, component and handler event names, closed flag words and booleans, owner ids — and no `NodeId`, typed text, control value or attribute text; whether a coverage answer stays within that set is research's question.
- security-plan §Input Validation (recorded check, `Check::from_bytes`) requires a kept check's bytes to be read as untrusted: strict, bounded in bytes and records, closed keys, anything else refused `malformed` holding nothing of the file, no panic path, and every replayed step re-passing `validate` inside `Session::run` — this binds the owed `actions`-step replay test and any path that feeds checks to the coverage command.
- security-plan §Data Protection (files, kept and committed checks) requires a test-recorded check to live in a `0700` directory as `0600` files, never logged; only the two named stand-Counter checks are committed, so a new kept check holding an `actions` step is not committed unless it is ratified under the same rule (no typed text, host path, name, secret or `screenshot` step).
- security-plan §Error Handling (escher-driver `Refusal`) requires any refusal the coverage command or the replay mismatch path produces to be a typed value from the closed cause set with no `String` field, so it cannot echo call- or file-supplied content; whether a differing-`actions` replay report naming "the step and the differing key" fits this form is research's question.
- security-plan §Input Validation (Dioxus bridge) requires the in-process signal registry to take dioxus-core types alone with no log site, print, env read or `unwrap` on app input; a new per-(element, event) dispatch record holding on every app must keep that, adding no outside input class.
@extract_section name=patterns
- Closed schema gate: every call passes `validate` to a typed `Command` or `Refusal`, the first failure in fixed order (per security-plan §Input Validation, driver command schema).
- Strict kept-check reader `Check::from_bytes` followed by `Check::replay` running each step through `Session::run` (per security-plan §Input Validation, recorded check).
- Recording directory discipline under `--record`/`Session::recording_into`: `0700` directory, `0600` files never replaced, nothing of the path logged (per security-plan §Input Validation, driver recording directory).
- Telemetry sink allowlist: `escher_` targets keep all but the content-named fields; anything new emitted by the coverage read goes through `escher_telemetry::init`'s allowlist (per security-plan §Logging & Monitoring).
@extract_section name=anti_patterns
- No `NodeId`, typed text, control value or attribute text in a coverage answer, a span or a log line (per security-plan §Input Validation, driver session socket).
- No `String` field in a refusal or error carrying caller- or check-supplied content back out (per security-plan §Error Handling).
- No path-on-disk argument, env read or cwd-relative default introduced to locate checks without an explicit founder-ratified widening (per security-plan §Input Validation, driver session state directory and the widening rule).
@extract_section name=bindings
- security ↔ tests: the owed `actions` replay test records into an owner-only directory and must not commit its kept check (security-plan §Data Protection); verb-count pins (`schema_tests.rs`, `cli_tests.rs`, `stand_mcp_tools`, `test_capability_statement.py`) move with any new verb.
- security ↔ obs: any new `command` span or event fields stay fixed words, bools and counts under the escher-telemetry allowlist (security-plan §Logging & Monitoring).
- security ↔ arch: a new verb or result field is a boundary widening the founder ratifies at P4 (security-plan §Input Validation, the widening rule); the cold-agent verb list is «Cold-agent bar»'s.
