# a11y extract

## Relevance
partial — the chunk adds no interactive UI, key binding or colour, but a part is one more reader of the snapshot model, which is the accessibility tree's consumer (role, name, states, focus, masks), so the tree-to-snapshot fidelity rules bind every part

## Constraints
- A part's text must be a further reader of the snapshot model alone, never of the accessibility tree or a control: each line's role and name are the snapshot node's, with no second role or name mapping, one line per snapshot node, as `Snapshot::to_text` is required to be (per a11y-plan §7 Screen Reader Support, Accessibility tree output — the snapshot model bullet).
- The node set the parts cover must be the snapshot's set, which is the accessibility tree's: nodes under `display: none`, `visibility: hidden` or `inert` are out of the tree and so out of the snapshot (a select's options excepted), so no part may add or drop a node the whole snapshot holds; whether the whole snapshot and the union of parts are drawn from one snapshot or from fresh reads is research's and P4's question (per a11y-plan §6 Visual Design Verification, Visibility and hit-testing).
- A part must carry the masks the whole snapshot carries: a password input's value reads `MASKED_VALUE` (or `""` empty) and a file input's the same marker, the typed text or path in no field of any part (per a11y-plan §7 Screen Reader Support, Accessibility tree output — the snapshot model bullet).
- A part must carry the tree-sourced states as the whole snapshot writes them — `selected` · `pressed` · `invalid` taken from the tree with the boolean model's two limits, `focused` from the tree's focus — so exactly the focused node reads `focused` across all parts, never twice and never lost at a cut (per a11y-plan §7 Screen Reader Support, Accessibility tree output — the snapshot model bullet).
- No description text may reach a part: the snapshot reads no description (`aria-description` / `aria-describedby` leave only to the platform adapter), and the part writer must not add that read (per a11y-plan §2 A11y Strategy, Role derivation).
- The stand's a11y surface must not move: tier 0 is SC 2.1.1 · 1.4.3 · 2.4.3 (per a11y-plan §1 A11y Scope Summary), so the fixture page stays test-only and the stand's Tab-order tables (`tab_order`, `ENABLED_TAB_ORDER`) and contrast rows stay as stated — a stand change moves them (per a11y-plan §5 Keyboard Navigation, Test harness pattern).
- A node read in a part must be addressable as one read whole, which rests on the actionable-key rule: every element an agent can act on reads an author key so its stable id holds; whether the fixture page's actionable elements all read author keys (`DioxusDocument::unkeyed_actionable` empty) is research's question (per a11y-plan §7 Screen Reader Support, Accessibility tree output — the actionable-key bullet).

## Patterns to follow
- `Snapshot::to_text` as the model's text reader (packages/dioxus-native-dom/src/snapshot_text.rs), asserted on the stand line-for-node with `focused` read off a Tab press — the shape a part's reader follows (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- A carrier's result asserted byte-for-byte against `Session::run`'s screen text in both layout modes, as `stand_mcp_tools` does for the MCP `snapshot` result — the shape for a part read over a carrier (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- A masked read pinned by a test-only fixture page and a sentinel count of 0, as `fixtures::password_named` and `stand_mcp_masked` do, no stand task gaining the input (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- Assertions as stated tables with their row count asserted, run in both layout modes (per a11y-plan §3 A11y Assertion Harness Contract).

## Anti-patterns to avoid
- A second role or name mapping in the part writer, or a part reading the tree or a control directly instead of the snapshot model (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- A cut that splits a node from its readings so a part holds an unmasked value, a lost `focused`, or a node twice (per a11y-plan §7 Screen Reader Support, Accessibility tree output).

## Contract bindings
- a11y ↔ tests: the `a11y` leg's six files and their per-file counts are stated (accessibility_hidden 6 · accessibility_roles 6 · focusability_updates 4 · stand_accessibility_ids 8 · stand_contrast 5 · stand_keyboard 14) and must not move; a new `stand_*` check runs in the workspace test leg and three times in `stand-repeat` under the zero-failure budget, not in the a11y leg (per a11y-plan §9 CI Integration).
- a11y ↔ driver carriers: every carrier result is a reader of the snapshot model alone (MCP result, `help`'s node-key help, `DiffNode::differs`), so a part carried on the socket, the command line, MCP or a recorded check binds to the same fidelity rules (per a11y-plan §7 Screen Reader Support, Accessibility tree output).

## Acceptance criteria contributions
- (a11y) On the fixture, in both layout modes, every line in every part reads the role and name of its snapshot node, equal to its accessibility node's, and each node's line in a part equals its line in the whole snapshot's text (per a11y-plan §7 Screen Reader Support).
- (a11y) On the fixture, in both layout modes, no line in any part reads `focused` at boot, and after one focus move exactly one line across all parts does, the tree's focus (per a11y-plan §7 Screen Reader Support).
- (a11y) If the fixture holds a password input with typed text, every part holding it reads `MASKED_VALUE` and the typed sentinel occurs 0 times across all parts (per a11y-plan §7 Screen Reader Support).
- (a11y) The `a11y` leg's six files pass with their stated per-file counts unchanged, and `stand_keyboard`'s and `stand_contrast`'s tables do not move (per a11y-plan §9 CI Integration).
