## Relevant amendment history
- **2026-10-10-driver-cli** — Created the §Surface: cli → Component Patterns bullet that every constraint in the extract rests on. `escher-session` prints one line of JSON on stdout per command (the answer, the refusal or a session error's object, keyed by the schema's own words) and nothing else. A usage error goes to stderr with stdout empty. There is no colour, no ESC byte and no terminal test, and the exit status carries the class (0 · 1 · 2 · 3). The founder set this on the shape of stdout and on exit codes (2026-10-10). Why it matters: a part of a large screen, the walk's end, and a stale or past-the-end walk all have to fit this one-line, four-class form. No detector covers an output form; this amendment came from the plan's reviewed list, so this chunk's plan has to raise any amendment to that bullet itself.
- **2026-10-10-mcp-surface** — Added the `mcp` role to the same bullet. Stdout carries newline-delimited JSON-RPC 2.0 lines only, and a tool result's text is the screen text for `snapshot` (not wrapped JSON) and the JSON line otherwise. Replies are uncoloured with no ESC byte, and the shared `Speaker` asserts this on every reply. Why it matters: a part read over MCP keeps this form. The extract's "snapshot result is the screen text, not wrapped JSON" pattern comes from here, so whether a part answer is screen text or a JSON line over MCP is a choice this bullet constrains.
- **2026-10-12-self-description** — The exit status's four classes are now read from the schema's `EXIT_STATUSES` table, which `help` serves. `escher-session help` answers one uncoloured JSON line with status `0`, reaching no session. In the `mcp` role, a `help` result's text is that line. Why it matters: a new verb, argument or result field chosen at the boundary fork shows up in `help`'s line and must keep that form, and any end-of-walk or stale-walk refusal has to map onto the existing `EXIT_STATUSES` classes.
- **2026-10-12-headless-screenshot** — Two changes. In §Surface: cli, `screenshot` answers one uncoloured line `{"width","height","png"}` with status `0`, and over MCP it answers an `image` block then a text block, every reply still one line. In §Typography → Loading, an app whose font context resolves no `sans-serif` family is refused `fonts-unavailable`. Why it matters: this is the precedent the extract names for writing a new answer shape from schema words on the cli surface, and for giving one verb's MCP result a carrier-specific form. The Loading clause also shows that a read can depend on font availability.
- **2026-10-19-session-recording** — The exit-status class line now names two new session errors (`record-dir-not-private`, `recording-failed`) in status `3`, with no new exit, under the playbook's «The program's own fixed text inside a ratified carrier». Why it matters: this is the precedent for adding new refusal or session-error words, for example for a stale or finished walk, inside the existing four classes rather than adding an exit. A new exit stays the founder's fork (inputs#I1).
- **2026-10-06-headless-stand** — Added the §Typography → Loading bullet: the headless stand registers bundled DejaVu Sans for every generic with system fonts off, through `build_single_font_ctx(DEJAVU_SANS)` passed as `HarnessOptions.font_ctx`. The reason was to pin text measurement so layout is the same on the dev host and on CI. Why it matters: the fixture whose snapshot passes 10,000 bytes has to boot this way so its `bounds` and part byte counts are real (not 0x0) and repeatable. That is the extract's fixture-font binding.
- **2026-10-13-upstream-sync-polish-and-ship** — Changed §Surface: desktop-native → Tokens: every document now gets the `DEFAULT_CSS` user-agent sheet once, through `DocumentConfig::default()` (`UserAgentStylesheet::default_sheet()`), no longer by `DioxusDocument::new`'s own call. Why it matters: a fixture boot that builds its own `DocumentConfig` has to start from the default, or the fixture lays out without the UA sheet and its bounds and byte counts move.

- **2026-10-18-one-virtual-clock** — Changed §Motion → Animation runtime. Settle's `animating` reads the scrollbar fade off that clock, and the fade runs for 700 ms after a driver `scroll`. Why it matters: this is the basis of the extract's "a read moves no time" pattern. Reading the parts of one screen must not move the clock between parts. If the walk uses `scroll` to reach a part, the fade can still read `animating` for 700 ms.
