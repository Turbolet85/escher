## Relevant amendment history

- **2026-10-06-snapshot-model** — made `DioxusDocument::snapshot` an in-process reader of ids and names. Each tree id is resolved through `BaseDocument::get_node`, never an index, and an unresolved node is omitted. It set the trap that the snapshot's first wire form is a crossing for ids, names and values. A part reader built over the snapshot inherits this no-index, omit-unresolved discipline.
- **2026-10-06-snapshot-state-fidelity** — added the password row: a non-empty value reads `MASKED_VALUE` and an empty one `""`, never the text or its length. The mask lives in the snapshot reader, so a part cut from a snapshot carries it only if it takes values from that reader. This is the basis of the extract's masking acceptance (a sentinel appears in no part).
- **2026-10-06-compact-snapshot-serialization** — gave the snapshot its one text form, `Snapshot::to_text`. Fields are written in `str`'s `Debug` form, so no field holds a line break or a bare `"`. File inputs are masked too. Standing rule: the first command that exposes the snapshot or its text is a crossing question, and a new way of exposing it (a part) is judged against that rule. The scope keeps the per-line form unchanged, and this entry is where that form's safety properties are recorded.
- **2026-10-07-change-tracking-and-diff** — `Snapshot::diff` reads values only from the snapshots, so a masked value in a diff is `MASKED_VALUE` by construction. This matters if the chunk bounds or splits an over-budget acting diff (scope's open premise): a split diff must still be built from snapshots alone.
- **2026-10-07-driver-session** (the session socket entry) — registered the socket as the one listener, owner-only by file mode. Standing rule: a command that carries an id, a name, a value, snapshot text or a diff reopens the crossing question. A part read is that kind of command.
- **2026-10-07-sink-target-allowlist** — escher's sink drops any record from an outside target at every level, so a sink-installing host's stderr holds 0 id and 0 name needles. Trap: a "nothing in the logs" check over a process that installs no sink passes vacuously. A walk's stderr proof must run on a sink-installing host (`host_log`, `mcp_log`).
- **2026-10-07-command-and-refusal-schema** — created the Driver command schema row. `validate` checks a closed verb table and bounded argument kinds, has no `unwrap`, `expect`, `panic!`, `unreachable!` or index on what a call supplies, and has no `Session` in its signature. A `Refusal` and `Fault` hold no `String`. Rule: keep every refusal text fixed and free of call content. A part index or cursor argument would be a new bounded kind under these rules.
- **2026-10-07-act-by-id** — the executor looks an id up by a linear search of `element_ids()` and `get_node`, never by index, anew on every call, and keeps no id between calls. A node read in a part must be addressable by `click`, `type` and `scroll` through this same lookup, with no `NodeId` held across calls as a cursor.
- **2026-10-07-refusal-detection** — added the session's record of id text: at most 4096 ids, session-lived, private, never printed or logged, fed from the session's own snapshots. It also set the precedent that a new verb widens the validated surface and is ratified by the founder (the sixth verb, `scroll`). This bears directly on whether part reads feed the record, and on how the 4096 cap behaves when one large screen holds more ids than that.
- **2026-10-07-driver-command-spans** (one span, eight fixed-word or count fields) — fixed the `command` span at `verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`. The screen text and its length are explicitly never fielded. A part index, part count or part text is therefore outside the span unless a new ruling admits it.
- **2026-10-09-founder-rulings** — ratified the sink's closed-span record class, and ruled that a diff's three counts may reach a log while no node, id, name or value may. Standing rule: a field that holds any of those is a new crossing question. A part count fielded on the span would be a new log field, which needs a ruling.
- **2026-10-10-driver-cli** (the session socket carries calls and answers) — wire request bound of 16,384 bytes. Answers are `accepted` · `refused` · `oversize`, bounded at 1,048,576 bytes, and an oversize call has already run. Today an over-budget whole snapshot is held only by this bound. The extract's acceptance that each part answers under 1,048,576 bytes with no `oversize` rests on it.
- **2026-10-10-driver-cli** (the command line is an external input surface) — put the schema behind argv and the socket, each through `validate` first. The usage line, refusals and session errors write back nothing the caller typed. This entry also shows that new verbs and a new argument kind (`name`) widen the validated set under a founder ratification. Standing rule: every later surface's input passes `validate` before anything runs.
- **2026-10-10-driver-cli** (ids, names and values leave in an answer) — the snapshot text and the diff became hosted answers on the socket and stdout. The id gained the driver's answers as an exit, while no log, event or file carries the snapshot's text. A part's text rides this same ratified exit.
- **2026-10-10-snapshot-states** (the closed-field rule) — ruled that a new field of a closed value set inside an already ratified carrier is not a widening, while authored text, an open value set, a new carrier or a new exit is. This is the test for a part result field: a count or "more parts" boolean passes, an opaque cursor token may not.
- **2026-10-10-mcp-surface** (the MCP server's input and its crossing) — set the MCP bounds: a 65,536-byte request line, a 1,048,576-byte result, and a tool argument of the wrong JSON kind refused `malformed` before `validate`. The request `id` is echoed only as an integer or a string of at most 128 bytes. A part argument over MCP is checked this way, and each part's MCP result must fit the result bound.
- **2026-10-10-mcp-surface** (`serde_json` reviewed; the `tool_call` span) — `serde_json` reads and never writes, and answers are hand-written by `to_json`. The `tool_call` span holds `tool` and `ending` only, a ratified log field. A walk adds no field to either.
- **2026-10-12-self-description** (`help` and the program's fixed text) — `tools/list` and `help` carry each verb's fixed `'static` help and result fields inside the ratified carriers (the listing grew 2,984 → 8,844 bytes). A new verb, argument or result field lands in that fixed text. Text from a page, a call or a screen, a new carrier or a new exit still widens.
- **2026-10-12-self-description** (a session error's remedy and its table) — the session errors are a fixed table (`SESSION_ERRORS`, 15 since session recording), each with a kind, a meaning and a remedy holding no path. A new session error for a walk, for example a part of a screen that has changed, would be a new row of fixed text and needs the same handling.
- **2026-10-12-headless-screenshot** (the screen's pixels in band) — precedent for adding an instance verb with an optional `id`, ratified as the founder's fork 1. The amendment measured the largest answer against the unchanged 1,048,576-byte bound (22,404 bytes, 2.1 %). That bound and its no-new-bound shape are the template for stating each part's size.
- **2026-10-15-cold-agent-test** — the agent-written check's `valid_step` admits `tool` as one of the verbs (eleven then, twelve since `lint`). A new verb moves the cold-agent validator's verb set and its count, as the extract's security ↔ tests binding says.
- **2026-10-18-one-virtual-clock** — the refusal cause set is closed at eight, two returned by `validate` and six by the executor (ratified 2026-10-18 by **2026-10-18-engine-debts**, the PROVISIONAL batch).
