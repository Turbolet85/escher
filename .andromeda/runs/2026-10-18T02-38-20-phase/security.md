# security extract

## Relevance
partial. Debts 1, 2, 3, 6 and 7 and the CARRY change or test reads of untrusted markup. The `covered` text (debts 5 and 9) is refusal text that leaves the process. Debts 4 and 8 (geometry readers) carry no security mandate beyond the shared bans.

## Constraints
- An engine fix here applies to every document, remote pages included, because remote web content is an untrusted vector that reaches the same builder, focusability and pointer paths (per security-plan §Threat Model Summary, vector "remote web content"). §Input Validation records each earlier such fix as "an engine change for every document and a boundary widening" that needed the founder's ratification (the range-input and keyboard-activation rows). So a fix of debt 1, 2, 3, 6 or 7 needs the same: here the delegate's PROVISIONAL answer, escalated at the wrap.
- Any new attribute read must keep the closed shape (per security-plan §Input Validation, the `aria-selected` · `aria-pressed` · `aria-invalid` row). This covers `aria-checked` (debt 2), `inert` (debt 1) and `aria-activedescendant` (debt 3). The shape: the value trimmed and matched exactly against a closed set, closed enums and booleans written on the node, never the attribute's text, and no log site or panic path. An `aria-activedescendant` IDREF must resolve as `aria-describedby`'s targets do: an id naming no element is ignored, and a target outside the tree is excluded (per security-plan §Input Validation, the `aria-describedby` · `aria-description` row).
- The snapshot reads these states. If a new state reaches it (a checked reading, or focus moving to an active descendant), that state may cross the socket, the CLI stdout and MCP results only as a closed word or boolean inside the ratified carriers. Authored text, an open value set, a new carrier or a new exit is still a widening for the founder (per security-plan §Input Validation, the Driver session socket row's rule of 2026-10-10).
- A narrowing of `disabled` (debt 7) moves every reader that §Input Validation lists for presence: focusability, autofocus, `unkeyed_actionable`, the `DISABLED` element state, pointer selection and click default actions, the range-input key, pointerdown and click arms, the Enter/Space activation arms, and the snapshot's `NodeState::enabled` (per security-plan §Input Validation, the `disabled` row). Each gate must stay a closed element-name and type match with no print, log site, env read or panic path (per security-plan §Input Validation, the keyboard-activation row).
- `inert` (debt 1) is one of the 28 names of upstream's `is_bool_attr` that the bridge clears when falsy. That row records `mutation_writer.rs` as byte-identical to upstream's (per security-plan §Input Validation, the Dioxus mutations "Boolean attributes with a falsy value" row). A bridge change breaks that identity and needs an owner for its upstream merge surface.
- A password caret fix (debt 6) must keep what §Input Validation states for the mask: the snapshot `value` reads `MASKED_VALUE`, the diff reads the mask, equal-length values paint identical frames, and nothing new crosses. The recorded limit is that a click-placed caret reveals the characters' relative widths (per security-plan §Input Validation, the password and file `input` row). Whether the code can already place the caret by the bullet layout is research's question.
- A rewording of `covered`'s meaning or remedy (debts 5 and 9), or a new limit in a verb's help, must stay a fixed `'static` table string holding nothing a call supplies. The cause set stays nine, with fixed names. `describe()` and every refusal's JSON line serve that text as the program's own text inside the ratified carriers (per security-plan §Error Handling, the escher-driver `Refusal` paragraph).

## Patterns to follow
- Closed-set attribute parse: trim ASCII whitespace, compare in lower case, set AccessKit enums or booleans only, and prove with a 5,500-character value that the tree builds and the text appears nowhere, not even in the tree's `Debug` output (per security-plan §Input Validation, the `aria-selected` · `aria-pressed` · `aria-invalid` row).
- IDREF resolution through `referenced_dom_ids_to_node_ids`, keeping only targets that have built nodes (per security-plan §Input Validation, the `aria-label` · `<label for>` row).
- Look nodes up with `get` / `get_node`, never by index, and keep no `NodeId` across a driver call (per security-plan §Input Validation, the `id` (stable element id) row).
- Gate default actions on the `disabled` presence check placed before the action arm, as the range and activation arms do (per security-plan §Input Validation, the range-input row).
- Run a census probe over the added engine lines (print, log site, `unwrap`, `expect`, panic, env read) that reads 0, as earlier engine changes did (per security-plan §Input Validation, the range-input row).

## Anti-patterns to avoid
- Carrying an attribute's text, such as an `aria-activedescendant` IDREF or an `inert` value, onto the adapter, the snapshot, a driver answer or a log as typed (per security-plan §Input Validation, the `aria-selected` · `aria-pressed` · `aria-invalid` row).
- Adding a span field or log field that holds anything a call supplies or a screen reads. The `command` span keeps its eight fixed fields, and `tool_call` keeps `tool` and `ending` (per security-plan §Logging & Monitoring, escher's own sink).
- Adding a dependency without the hand review and a green audit (per security-plan §Dependency Security, Pinning).

## Contract bindings
- security ↔ a11y: a focusability change (debt 1 `inert`, debt 7 `disabled`) moves the `stand_keyboard` Tab tables and its pins `the_engine_honours_no_inert` and `a_disabled_attribute_of_any_value_is_skipped`. The new states (debt 2 checked, debt 3 active descendant) reach the platform adapter's states class, and the windowed witness of that class stays re-carried (per security-plan §Input Validation, the `id` (stable element id) row).
- security ↔ obs: no new log site in the engine lines. The sink's needle readings (0 ids, 0 names, 0 typed text at `trace`) must hold for any refusal-text or state change (per security-plan §Logging & Monitoring).
- security ↔ tests: the CARRY test of `aria-expanded` · `aria-disabled` · `aria-level` closes "no test names any of the three". It should show that the tree holds only closed values and that `aria-disabled` moves no snapshot `enabled` reading (per security-plan §Input Validation, the `aria-expanded` · `aria-disabled` · `aria-level` row).
