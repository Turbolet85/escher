## Constraints
- Under test-plan §2 Differential oracle, incremental and non-incremental layout have to stay identical. test-plan §1 Coverage scope (tests/blitz-tests) records every pin this chunk touches as run in both layout modes, so a rewritten or added check runs `for incremental in [false, true]` too (per test-plan §2 Differential oracle; per test-plan §1 Coverage scope).
- test-plan §9 Engine features by runner says the workspace build and the per-package build compile different engine features. Only the workspace build turns on `writing-mode`, and that feature picks which body of `BaseDocument::physical_unrounded_geometry` gets compiled. `visible_region` and every snapshot `bounds` read through that function. So debts 4 and 8 (the position reader and the client rect) need their checks green under both `cargo test -p blitz-tests --locked` and `cargo test --workspace --locked`, and a per-package green is not the workspace leg's green (per test-plan §9 Engine features by runner).
- test-plan §1 Coverage scope (tests/blitz-tests) names the standing pins each debt moves. An outcome of "fixed" requires its pin to be rewritten to the fixed reading, and an outcome of "pinned" requires the pin to keep holding. The pins: `stand_keyboard::the_engine_honours_no_inert` and `a_disabled_attribute_of_any_value_is_skipped` (debts 1, 7); `accessibility_states`' fourth test, where `aria-checked` sets none of the three states (debt 2); `scrolled_box_absolute_position`, reading (−30, −70) (debt 4); the `contain: paint` test of `hit_clipped_at_scrolling_box` (debt 5); `password_caret_click`, with indices 5 and 2 (debt 6); the fixture condition of the transformed-and-scrolled test in `hit_clipped_at_scrolling_box`, reading (0, 40, 300, 140) (debt 8); and the 7 refused rows of `stand_act_ids`, whose row counts the check asserts (debt 9). Whether the code still reads as these pins state is research's question (per test-plan §1 Coverage scope).
- test-plan §3 Inspection helpers records that the harness's `layout_rect`, `layout_rect_of` and `center_of` are built on `Node::absolute_position` and read a self-scrolled box less its own scroll offset. A debt-4 fix therefore moves harness inspection readings too, and every check that reads them on a scrolled box moves with it (per test-plan §3 Inspection helpers).
- test-plan §3 Crate-local test helpers (blitz-tests (stand checks)) makes `tests/blitz-tests/tests/common/mod.rs` the one statement of `tab_order(task)` and `ENABLED_TAB_ORDER`, and `stand_keyboard` asserts both. A focusability change from debt 1 or debt 7 that reaches a stand control would move those tables, and they hold stated expectation only, never a second mapping (per test-plan §3 Crate-local test helpers).
- Under test-plan §2 Font-dependent tests, stand checks and engine checks that use the bundled DejaVu Sans assert unconditionally, with no skip path. A rewritten debt-6 caret check keeps the bundled font at 20 px and its stated indices (per test-plan §2 Font-dependent tests).
- test-plan §10 Flakiness budget sets a zero-failure budget: the `stand-repeat` leg runs every `stand_*.rs` file and seven_guis' seven process checks three times, with no retry. test-plan §10 Coverage floors sets per-crate line floors: escher-driver 97 %, dioxus-native-dom 83 %, blitz-test-harness 90 %. Changes to dioxus-native-dom's snapshot readers (debts 2, 8) or to escher-driver's refusal text (debts 5, 9) have to keep all three crates at their floors (per test-plan §10 Flakiness budget; per test-plan §10 Coverage floors).

## Patterns to follow
- The CARRY's model is the table-driven attribute check on a parsed page that test-plan §1 Coverage scope (tests/blitz-tests) records for `accessibility_states`: each value read on a role that supports the attribute and on one that does not, row counts asserted, both layout modes. Beside it, upstream's merged `accessibility_label` and `accessibility_description` checks assert through test-that's `verify_that!` under the standard harness (per test-plan §1 Coverage scope; per test-plan §3 Runners and invocation).
- An engine check on parsed pages carries no `stand_` prefix and declares no shared module, like `password_caret_click` and `range_input_interaction`. Each new file under `tests/blitz-tests/tests/` is its own auto-discovered target with no manifest line, so the recorded 127 files / 126 targets move. A `stand_`-prefixed file is picked up by `run stand` and by `stand-repeat` with no script change (per test-plan §2 Directory pattern; per test-plan §3 Agent-run contract).
- Driver refusal checks (debts 5, 9) read through `tests/blitz-tests/tests/session_common/mod.rs`: `refused` gives a call's cause, and `refused_unchanged` gives the cause plus whether the snapshot and both focus readings stayed equal. The executor is tested only at integration level, through `stand_act_*`, because the crate cannot build a held instance in a unit test (per test-plan §3 Crate-local test helpers; per test-plan §1 Coverage scope).
- Each new or rewritten check is proven by a mutation control: red with its fix or reading reverted, green on the restored tree, the restore sha-equal (per test-plan §4 What unit tests cover).
- Unit tests sit in `#[cfg(test)] mod tests` in the source file, or out of line through `#[path]` where the module is long. test-plan §1 records that blitz-dom holds no unit test of the accessibility builder's reads, so a role-aware `aria-checked` reader (debt 2) has no existing unit module to extend (per test-plan §4 Conventions; per test-plan §1 Coverage scope).

## Anti-patterns to avoid
- Do not write an assertion that can pass without asserting. test-plan §4 records two text-input tests that assert only inside an `if` on the measured size, and test-plan §2 records older font-dependent tests that skip with `eprintln!`. A pin of a fixed or kept reading asserts unconditionally (per test-plan §4 Conventions → Conditional assertions; per test-plan §2 Font-dependent tests).
- Do not count an empty or per-package-only run as a pass. `run` treats an empty run as `failed`, and a check reading a sink capture counts lines by target, never in total (per test-plan §3 Agent-run contract; per test-plan §9 Engine features by runner).
- A failing assertion must print no call argument. test-plan §4 records that driver assertions over a call carry a row index only, so a failing log prints no argument value. Refusal checks for debts 5 and 9 keep that rule (per test-plan §4 What unit tests cover).

## Contract bindings
- tests ↔ a11y: the `a11y` leg runs six named files, `stand_keyboard` among them, and `test_ci_workflows.py` pins that list in order. `accessibility_states`, `accessibility_label` and `accessibility_description` are not in it. Whether the CARRY's check joins the a11y leg is a11y's call, and adding it moves the CI-script pin (per test-plan §9 CI Integration → Legs; per test-plan §4 What unit tests cover → CI workflows and leg script).
- tests ↔ driver schema: `covered`'s meaning and remedy are fixed text checked against a stated table in refusal.rs's unit tests. `help` is compared byte for byte between the command line and MCP (`cli_commands`, `mcp_server`), and `stand_mcp_tools` serves each cause with its remedy. A debt-5 or debt-9 text change moves the table and those checks (per test-plan §4 What unit tests cover; per test-plan §6 Drivers per surface).
- tests ↔ obs: the agent-run 5-command contract (harness metadata, not a sink) has recorded `run stand` at passed 168 · failed 0 · ignored 7 over 40 files and `run all` at 546 · 0 · 12. A new or retired check moves those counts. The CI tallies in test-plan §9 Per-OS test tallies move as well (per test-plan §3 Agent-run contract; per test-plan §9 Per-OS test tallies).
- tests ↔ security: the `password_caret_click` pin backs security-plan's known 0.1.0 limit, and `stand_act_screenshot` holds that a typed password never leaves as pixels. A debt-6 fix rewrites the first and keeps the second green (per test-plan §1 Coverage scope).
