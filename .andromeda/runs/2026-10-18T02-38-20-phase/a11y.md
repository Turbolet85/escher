# a11y extract

## Relevance
relevant: five of the nine debts are a11y surface (1 `inert`, 2 `aria-checked`, 3 `aria-activedescendant`, 6 the password caret, 7 `disabled` focusability), and so is the CARRY's tree test. Debts 4, 5, 8 and 9 (position, hit, client rect, `covered`) touch a11y only where a focus or tree reading moves with them.

## Constraints
- a11y-plan §1 sets the target at tier 0: SC 2.1.1 · 1.4.3 · 2.4.3. Debt 3 (`aria-activedescendant`, or a roving focus on `crud-list`) is SC 4.1.2 work outside that target, per a11y-plan §5 (Per-surface keyboard shortcuts, the seven_guis CRUD bullet). A «pinned» or «kept» outcome there leaves the tier-0 target met. A «fixed» outcome goes past the target and needs the fork's word.
- a11y-plan §5 (Focus order) requires one presence-keyed `disabled` reading. Focusability, the Tab walk, autofocus and `DioxusDocument::unkeyed_actionable` all read it. a11y-plan §5 (Focus order, the disabled-ness bullet) ties `:disabled`, the pointer click target and Enter/Space activation to the same presence reading. A debt-7 narrowing to `button` · `input` · `select` · `textarea` has to state which of these readers move with focusability and which keep the any-element presence reading. Whether the code already shares one predicate across them is research's question.
- a11y-plan §5 (Script and framework exposure, the falsy boolean attributes bullet) requires the bridge to keep removing a framework-written `inert: false`. `inert` is one of the 28 names of `is_bool_attr`, and `mutation_writer.rs` is byte-identical to upstream's. A debt-1 fix in the engine therefore leaves the bridge's removal intact. The same bullet records that whether an inert subtree takes a hit is unmeasured. Measuring that is the fork's input, not an attested fact.
- a11y-plan §2 (Role derivation, the three-states bullet) requires the state reads to be a closed-set match on the trimmed lower-case value, with no role consulted. Under it, `toggled` is exactly the `aria-pressed` reading. A debt-2 `aria-checked` read needs a role-aware writer of AccessKit's one `toggled` property, which departs from "no role consulted". a11y-plan §4 (Per-component pattern catalog, ARIA state attributes) names `accessibility_states`' fourth test as the pin that moves if the read is fixed.
- a11y-plan §7 (Accessibility tree output, the snapshot bullet) requires the snapshot to take `selected` · `pressed` · `invalid` from the tree, and `enabled` · `checked` · `value` from the element. A debt-2 fix that writes `toggled` from `aria-checked` therefore moves the snapshot's `pressed` reading for that node, and with it the diff's `differs` and the node keys' help. Whether `checked` should come from the tree instead is the fork's question. What the code reads today is research's question.
- a11y-plan §2 (Role derivation, the upstream-reads bullet) states the merged reads: `aria-expanded` as a boolean, `aria-disabled` `true` → `set_disabled`, and `aria-level` as a number with tag and role defaults. No stand file states any of them, and they leave only to the adapter. So the CARRY's test is of the built tree alone. a11y-plan §7 (Accessibility tree output, the snapshot bullet) requires `enabled` to stay on the `disabled` attribute: `aria-disabled` moves no snapshot reading.
- a11y-plan §7 (Accessibility tree output, the password reading) requires a password input's typed text in no snapshot field, tree field or painted frame. It records debt 6's starting reading, the caret at index 5 after eight narrow characters and 2 after eight wide (`password_caret_click`). a11y-plan §6 (Focus ring, the caret bullet) requires the focused password caret painted at the bullet of its caret index. A fix places the click by the bullet layout, so that both readings agree.

## Patterns to follow
- The state check pattern, per a11y-plan §3 (A11y testing tool pick). It reads each carrier's property off `build_accessibility_tree()`, with one stated table per attribute, its row count asserted, in both layout modes (`tests/blitz-tests/tests/accessibility_states.rs`). This is the shape for the CARRY's three reads and for any debt-2 `aria-checked` rows.
- The upstream `verify_that!` files over the built tree, per a11y-plan §3 (A11y testing tool pick): `tests/blitz-tests/tests/accessibility_label.rs` and `tests/blitz-tests/tests/accessibility_description.rs`. They are the alternative home if the CARRY's test sits beside upstream's reads.
- The stand keyboard walk, per a11y-plan §5 (Test harness pattern). `stand_keyboard` walks `tab_order` and `ENABLED_TAB_ORDER` forward and back, and at each step the engine's focus, the snapshot's `focused` node and the tree's focus agree. Fixture rows cover what no stand task states. The pins `the_engine_honours_no_inert` and `a_disabled_attribute_of_any_value_is_skipped` are rewritten to the fixed reading if debt 1 or debt 7 is fixed. The shared readers live in `tests/blitz-tests/tests/common/mod.rs`.
- Cached focusability is recomputed on a `tabindex` · `href` · `disabled` write, per a11y-plan §5 (Focus order, the mutator bullet), with roving-tabindex tests in `focusability_updates`. A debt-1 `inert` fix (and its subtree) needs the same recompute path. Whether the mutator already watches `inert` is research's question.
- Expected roles, names and focus stops are stated once in the shared tables `controls` · `INPUT_NAMES` · `REGION_NAMES`, per a11y-plan §7 (Accessibility tree output, the stable id bullet). A new expectation joins those tables.

## Anti-patterns to avoid
- A second role or name mapping in a check or a reader. a11y-plan §7 (Accessibility tree output) states that every snapshot, text, diff and MCP reader takes the tree's role and name "with no second role or name mapping", and that the shared tables are "stated expectation, never a second role or name mapping".
- A second read of one attribute. a11y-plan §2 (Role derivation, the upstream-reads bullet) records that upstream's `parse::<bool>` `aria-selected` read was dropped so that "there is still one read per attribute". An `aria-checked` read must not sit beside another one, or parse outside the closed set.
- Reading `has_changes()` as "this step changed something" without draining first, per a11y-plan §2 (A11y Strategy, the `changed_nodes` bullet). This applies to any fix check that leans on the changed set or the refresh, such as an `inert` toggle.

## Contract bindings
- a11y ↔ tests (CI): a11y-plan §9 records the `a11y` leg's six files and their per-file counts (`stand_keyboard` 14, `focusability_updates` 4, `stand_accessibility_ids` 8, `stand_contrast` 5, `accessibility_hidden` 6, `accessibility_roles` 6). A test added or removed in those files moves the recorded count. The CARRY's test runs in the workspace leg alone unless it lands in one of the six. The same section records that `stand_*` files also run in `stand-repeat`.
- a11y ↔ tests-plan: the CARRY closes test-plan §1's observed-absent record for the three merged reads, per a11y-plan §2 (Role derivation, the upstream-reads bullet).
- a11y ↔ layouts: a debt-1 or debt-7 focusability change moves `tab_order` / `ENABLED_TAB_ORDER` and the per-surface focus sequence, per a11y-plan §5 (Test harness pattern). Per the scope, the debt-3 gap is also stated in `.andromeda/layout-templates.md`.
- a11y ↔ driver: the driver's `disabled` refusal reads the snapshot's presence-keyed `enabled`, per a11y-plan §7 (Accessibility tree output, the snapshot bullet). A debt-7 change to focusability alone leaves that cause's meaning as stated, while a change to `enabled` moves it. Which one the fix touches is the fork's question.
- a11y ↔ design (contrast): `stand_contrast`'s exempt class is exactly `enabled == Some(false)`, per a11y-plan §6 (Color contrast). A change to the snapshot's `enabled` moves the exempt rows.

The pin for a fixed debt is rewritten to the fixed reading, and the pin for a pinned or kept debt stands green (per a11y-plan §5 Test harness pattern).
- (a11y) For debt 2, if fixed: a checkbox or switch role carrying `aria-checked` reads its checked state on the built tree, a toggle button still reads `toggled` from `aria-pressed`, `accessibility_states`' fourth test is rewritten, and the stand's snapshot state readings still equal their accessibility nodes' (per a11y-plan §4 Per-component pattern catalog, a11y-plan §7 Accessibility tree output).
