## Relevant amendment history
- **2026-10-06-headless-stand** — added the §Typography → Loading bullet. The headless stand registers bundled DejaVu Sans for every generic, with system fonts off, through `build_single_font_ctx(DEJAVU_SANS)` via `HarnessOptions.font_ctx`. It pins text measurement so names and bounds read the same on the dev host and the CI runner. This is the reason the keyboard harness must boot each task through `seven_guis::stand`, which is the extract's Typography acceptance criterion.
- **2026-10-07-settle-detection** — set the settle rule in §Motion → Animation runtime. No member of the keeps-animating set holds a settle open, and none is waited on or advanced; settle returns `Settled` with `animating` read from the document's flag, and it reads animation time only through the harness's controlled clock, which it never advances. A keyboard step settles under this same never-advance rule, so a Tab or activation step must not wait on an animation or move the clock.
- **2026-10-07-act-by-id** — added a clause to the harness-clock bullet. `advance` moves only the app's own time (whole Timer ticks on the stand), and `click`, `type` and `press` leave the animation clock where it was. This was measured on the Timer, where the clock reads the same before and after every call. It underlies the extract's criterion that no keyboard step advances the clock and the Timer's elapsed reading changes only across an explicit `advance` or tick. `stand_act_timer.rs` and `stand_settle.rs` are the pattern to follow.
- **2026-10-07-refusal-detection** — added a §Motion bullet. `scroll_into_view` writes every nested scrolling box at once, innermost first, whatever behaviour is asked; `Smooth` applies to the viewport alone, and the driver's `scroll` is instant inside one settled step. This engine widening for every document was ratified by the founder on 2026-10-07. It is the rule to follow if a focus step brings its target into view. It is also a precedent: a change to an engine method for every document waits on the founder's word.
- **2026-10-10-scrolling-box-bounds-and-hit** — added the edge rule to §Depth Strategy → Engine depth behavior. The hit walk stops at the padding box of a node that clips by `overflow` (the root excepted), while the node itself is still answered inside its border box. Freight item 7's hypothesis rests on this: an activation key on a scrolled box clicks off its centre, through `synthetic_click_event_data` on the unfixed `absolute_position`. Whether that synthetic click still lands inside the box is to be read against this rule.
