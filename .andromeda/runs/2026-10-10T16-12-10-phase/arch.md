# arch extract

## Relevance
relevant — the chunk edits four contracts the plan states (the engine's accessibility builder, the snapshot model with its text form and diff, the driver's result table and written form, the stand's markup) inside existing crates; it adds no crate, listener, env var or dependency.

## Constraints
- **Workspace placement and edge direction.** The chunk's code belongs in four existing units: the builder in blitz-dom's accessibility file, the model, text form and diff in dioxus-native-dom's crate-private `snapshot` · `snapshot_text` · `snapshot_diff` modules, the result table and JSON in escher-driver, the markup in seven_guis's task files (per architecture §Existing Scopes). No manifest under `packages/` may name an example — the one edge runs `seven_guis → escher-driver` — so nothing stand-specific (a class name, a task's role choice) may enter the engine or the driver (per architecture §Established Decisions → Driver session).
- **The builder is one tree for every document and for the platform.** architecture §Standard Contracts → Mutation, query and CSSOM requires `build_accessibility_tree` to return an AccessKit `TreeUpdate` and requires blitz-shell to build the platform tree through `Document::accessibility_tree`; architecture §Standard Contracts → Document core requires that method's default to be the base builder, with `DioxusDocument` alone overriding it, to add stable ids. A state read in the base builder therefore reaches every `Document` implementor and the platform adapter, not the snapshot alone; the three states belong in the base builder, not in the Dioxus override. The AccessKit in use is the workspace's `0.25` (per architecture §Stack and Technologies → Accessibility); which node properties that version offers for selected, pressed and invalid is research's question.
- **A false state arrives as the text `"false"`.** architecture §Standard Contracts → Dioxus DOM bridge requires the bridge to clear only the 27 names of `BOOLEAN_ATTRIBUTES` on a falsy value and to write any attribute outside that list holding `false` as `"false"` — it names `aria-hidden` as such a case, and `selected` is on the list while no `aria-*` name is. The builder must therefore decide each state from the attribute's value, never its presence; whether the stand's `aria-*` attributes reach the DOM that way is research's question.
- **Snapshot model shape.** architecture §Standard Contracts → Dioxus DOM bridge requires `NodeState` to stay `Debug` · `Clone` · `PartialEq`, re-exported from the crate and through dioxus-native, compiled only under `accessibility`, with every field read from a reader the engine already holds and no field holding a `NodeId`, an AccessKit tree id, an `ElementId`, a `ScopeId` or a pointer. The three new fields fall under each of those rules; the same contract records that `enabled` and `checked` are read from the element while `role`, `name` and `focused` are read from the tree, so both sources have precedent and the choice is decision 1.
- **Text form.** architecture §Standard Contracts → Dioxus DOM bridge requires `Snapshot::to_text` to stay a pure function of the `Snapshot` (no document access, no failure path, no log), to write state tokens in one fixed order with a token absent where the model holds nothing for it, to write a role in its `Debug` spelling with no alias table, and never to truncate or page; `SNAPSHOT_TEXT_BUDGET` is a ceiling a caller compares against. New tokens extend the fixed order, and a role the stand's controls newly take is written as AccessKit spells it.
- **Diff and the driver's one table.** architecture §Standard Contracts → Dioxus DOM bridge requires a node to read `changed` when its role, name, state, bounds or parent's id differ, and a `DiffNode` to carry the node's whole `NodeState` as read after the step. architecture §Standard Contracts → Driver session requires the diff node's keys to be the ones `NODE_FIELDS` names, `Outcome::to_json` to write a node keyed by `NODE_FIELDS` in the table's order with the optional keys left out when absent, by hand and with no serialization crate, under a crate that denies missing docs. A key for a new state is added in that table and nowhere else; the verb, argument-kind and refusal-cause counts the same contract fixes do not move.
- **The crossing and the log.** architecture §Occupied Resources → Network ports and listeners registers what a call's answer carries out — ids, accessible names, control values, the snapshot's text and the diff — as ratified content classes, and architecture §Standard Contracts → Driver session requires the command span to hold eight fields of fixed words and counts only. No log, event or file may carry a snapshot, its text or a diff's content (per architecture §Standard Contracts → Dioxus DOM bridge); the three states reach a caller through the text and the diff only.

## Patterns to follow
- **Cite the spec beside the reading.** The builder's existing readings are written against WAI-ARIA, HTML-AAM and accname and say so in place (per architecture §Design Philosophy → Behave like a browser, and cite the spec); spec URLs sit above or next to the implementation (per architecture §Conventions → Documentation). Each new state's value grammar is cited the same way.
- **A direct engine change, flagged upstreamable, with no upstream pull request.** The precedent is the 2026-10-10 engine fixes — made in the engine for every document and flagged upstreamable against the recorded upstream commit (per architecture §Established Decisions → Scrolling and input); the merge base the flag is cut against is the one architecture §Project Intent records.
- **Stand checks.** One test target per file directly under the integration-test directory, every scenario run `for incremental in [false, true]`, shared stand tables and helpers in `common/mod.rs` and what session-holding checks share in `session_common/mod.rs` (per architecture §Conventions → Tests).
- **A state attribute is a tracked write.** `set_attribute` and `clear_attribute` on an in-document node are among the changed set's marking sites, and the shell rebuilds the platform tree on a poll whose taken set was non-empty (per architecture §Cross-cutting Patterns → Invalidation and state integrity) — so the plan requires no new invalidation site for an `aria-*` attribute that changes; whether the code marks on these attributes as on any other is research's question.
- **Result shapes change in the table, and the written form follows it.** `VERBS` and `NODE_FIELDS` are `'static` data; the JSON writer is keyed by the schema's own words, and help texts are fixed strings in the same table (per architecture §Standard Contracts → Driver session) — the help of `changed` already names "state" as a whole, so whether any help text needs rewording is research's question.

## Anti-patterns to avoid
- **A second form or a second reading of the snapshot.** No `Display` impl, JSON form, parser, second entry point or role alias table in dioxus-native-dom, and no state recomputed in the driver or the stand's checks beside the model's (per architecture §Standard Contracts → Dioxus DOM bridge).
- **State content on the log path.** No new field on the command span and no log line holding a state, a node or a diff's content — the span's three diff figures stay counts (per architecture §Standard Contracts → Driver session).
- **A silent add.** No new workspace crate, cargo feature, dependency or `[features]` table on escher-driver for this work; a new name is a registration, not a by-product (per architecture §Occupied Resources → Names).

## Contract bindings
- **arch ↔ security** — the session socket's and the command line's content classes are ratified by name (architecture §Established Decisions → Driver session; §Occupied Resources → Network ports and listeners). Three state words inside the snapshot's text and the diff read as inside "the snapshot's text and the diff"; that reading is security's to confirm (scope decision 5). A second crossing is touched too: the platform accessibility adapter, whose content classes the plan states as ids and accessible names (architecture §Standard Contracts → Mutation, query and CSSOM) — states on the AccessKit node reach it in a windowed build with `accessibility` on.
- **arch ↔ a11y** — `accessibility` is a default feature of blitz-dom and of both Dioxus crates (architecture §Established Decisions → Default features), so the builder change is in every default build. A role the stand's rows or mode buttons take also enters the actionable-key check, whose closed interactive role list the plan states (architecture §Standard Contracts → Dioxus DOM bridge); the same contract requires every actionable element to read an author key — whether the mode buttons and date inputs do already is research's question.
- **arch ↔ tests** — both-modes equality of readings and of each step's diff (architecture §Design Philosophy → One incremental pipeline, safe identities; §Conventions → Tests). The plan records measured byte figures for each lean task's text at boot and for the hosted `snapshot` line (architecture §Standard Contracts → Dioxus DOM bridge); new tokens or a new role change those figures — whether an existing check pins them is research's question.
- **arch ↔ obs** — the command span's fixed field set and the rule that a diff's content never reaches a log while its three sizes may (architecture §Standard Contracts → Driver session).
- **arch ↔ wrap** — the plan's sentences that state the builder's naming sources, `NodeState`'s four fields, the token order and `NODE_FIELDS`' nine keys describe the state before this chunk; they are amended at the wrap from the chunk's report, never by the chunk (architecture §Standard Contracts → Mutation, query and CSSOM; → Dioxus DOM bridge; → Driver session).
