On the stand, in both layout modes, read through `DioxusDocument::snapshot` after real input: at boot `flight-one-way` reads `pressed: Some(true)` and `flight-return` `Some(false)`, the two readings swap after a click on `flight-return` and swap back after a click on `flight-one-way`, and no other node reads a `pressed`; with no row selected every CRUD row reads `selected: Some(false)`, after a click on a row exactly that row reads `Some(true)`, a click on another row moves the reading, and a filter edit or Delete leaves no row selected; `flight-start` reads `invalid: false` at boot and `true` once what it holds is no date, `flight-return-date` reads the same way under a return flight, and no other node reads invalid; each of these snapshot readings equals the accessibility node's (`is_selected`, `toggled`, `invalid`). Each reading follows the app's state when it changes, and through `escher_driver::Session::run` the step that changes it returns that node among its `changed` nodes as it reads after the step — the click on `flight-return` returns both mode buttons, a click on a row returns that row and the row it leaves, the `type` that makes `flight-start` no date returns it invalid and the `type` that makes it a date returns it not invalid — each returned diff equal to the check's own reading of the two snapshots and equal in both layout modes. Proved by `cargo test -p blitz-tests --locked --test stand_snapshot_state --test stand_act_diff` and `cargo test -p blitz-tests --locked --test accessibility_states --test stand_act_states`, and by the same four files under `cargo test --workspace --locked --test accessibility_states --test stand_act_states --test stand_snapshot_state --test stand_act_diff`.
