## Relevant amendment history

- **2026-10-07-settle-detection** — "a settle reports a load in flight and never waits on one". Added the §API Security row "Settle and loads in flight" beside "Request timeout": settle reports `NotSettled(Loads)` at once, reads no clock, is bounded at 64 passes, and returns a class name only (no URL, request, node, id, name or value); the "Request timeout" row was left unchanged — a request still has no timeout. Its "Rule for later chunks" is this chunk's question 2 verbatim in origin: a driver command that would wait on a load with a clock is a new decision for the plan, not an extension of settle; and a settle verb or a busy-source reply on the session wire is a new crossing question. This is the row the chunk's §API Security amendment lands beside, and the reason the answer must be the operator's and carry a stated bound.
- **2026-10-07-driver-session** — "the driver session socket: threat vector, access, input rows". Created the surface the schema must not widen: the local-IPC attack vector in §Threat Model Summary, the §Authentication & Authorization row (no handshake, token or peer check; `0700` directory, `0600` socket, `StateDirNotPrivate`), four §Input Validation rows (session socket · state directory · label · `escher-session` argv) and the §API Security lead and control row. Recorded bounds the chunk leaves as they are: closed grammar `hello v1` / `stop v1`, 64-byte request, 2 s read and write bound, replies of a pid, the label and a count only, label 1-32 bytes of `a-z0-9-` checked before the boot, argv closed (two arguments, four tasks) exiting 2 before anything boots. Ratified as a boundary widening by the founder's own choice — so any verb reaching the wire is asked of the founder, not leaned. Standing: a command carrying an id, a name, a value, snapshot text or a diff reopens the crossing question. Kept: no idle expiry, no pid check in `start`, TCP/UDP ruled out. It also re-pointed root `Cargo.toml` citations (`:104; :114` → `:106; :116`) and the blitz-tests dev-dependency range — the citations a new dependency line would move again.
- **2026-10-07-driver-session** — "what a sink-installing host logs: the id and name rows and the scrub's reach scoped to the measurement". Rewrote the `id` and accessible-names rows from "written to no log" to "escher's own code writes it to none", and the three "the id's only exit" clauses to "the only exit escher's own code gives the id" — the exact wording the extract's returned-to-caller-only constraint rests on. Trap it records, which bears on this chunk's "adds no log call site" criterion: a "nothing in the logs" check over a process that installs no sink passes vacuously (`stand_session_quiet`'s host is one).
- **2026-10-07-driver-session** — "founder's rulings: the Epoch 3 PROVISIONAL items ratified". Turned eight PROVISIONAL clauses in the `id`, accessible-names and masked-value rows into "ratified by the founder, 2026-10-07": the snapshot, its text and its diff are returned to their caller only. A result shape defined over those types inherits a ratified returned-value-only exit — and nothing wider; an in-process schema stays inside the ruling, a served one does not.
- **2026-10-07-sink-target-allowlist** — "a sink-installing host logs no id and no name at any level: outside-target records dropped". Made the sink three-outcome: engine targets print only the safe fields, `escher_` targets print with the eleven content-named fields redacted, any other target's record is dropped whole at every level. Bears on the obs binding: a later `escher_driver` span field prints unless its name is one of the redacted ones (the list, from the telemetry-bootstrap entry, holds `value`, `text`, `path`, `error` and seven more — it holds no `id`, `name`, `cause`, `remedy` or argument name; read from the amendment text, not re-measured against the code). So the cause set's names should be safe-to-print closed values, and an id or argument must not be handed to a field the sink leaves unredacted. Typed text in a sink-installing host's log is still recorded as not measured. Trap repeated: a no-log check must run against a host that installs the sink (`host_log`).
- **2026-10-07-change-tracking-and-diff** — "the diff as an in-process reader; the platform tree delivered on change". Recorded `Snapshot::diff` as the fourth in-process reader of the id (`DiffNode.id`, `DiffNode.parent`, `SnapshotDiff.removed`; no `NodeId`, `ElementId`, `ScopeId`, AccessKit id or pointer; no text form) and that a diff's values come from the snapshots only, so a masked value stays `MASKED_VALUE` — measured for a password input, by construction and not run for a file input. Standing rule: the first command that returns a diff asks the crossing question again. An acting verb's result shape that names a diff rests on this; the diff has no text form, so a serial shape for it is new in this chunk.
- **2026-10-06-compact-snapshot-serialization** — "the snapshot has one text form, returned to its caller only; a file input's value is masked". Recorded `Snapshot::to_text` as the one serialized form (quoted `id=` field, names and masked values in `str`'s `Debug` form), returned to its caller only, with the explicit statement "There is no JSON form, no `Display` impl and no parser of the text", and extended the mask to `type=file`. Standing rule: the first command that exposes the snapshot or its text is a new crossing for ids, names and values, asked again at that chunk. Two consequences here: a snapshot-read verb's result shape is the point that rule anticipates (in process it crosses nothing, but the row's "no command carries the snapshot" clause changes wording), and a data-readable serial form for results contradicts the recorded "no JSON form" unless the amendment says so. Kept: `unkeyed_actionable` still has no serialized form.
- **2026-10-06-snapshot-state-fidelity** — "a password's snapshot value is masked; the falsy clear and the `disabled` reader recorded". Added the masked-value row (`MASKED_VALUE`, never the text or its length), tied the snapshot's `enabled` to the presence reading of `disabled` (`disabled="false"` and bare `disabled` both read `Some(false)` while staying focusable), and amended §Error Handling (Graceful degradation · Panic paths) — the section this chunk's refusal type is recorded under. Trap: the mask covers the snapshot only; the DOM attribute and the painted text are unmasked, so a result or refusal that states a value must be defined over the snapshot or diff types, never a DOM read — and a typed-text argument is the unmasked text itself.
- **2026-10-06-id-stability-across-code-edits** — "the `id` row states four tiers and a third in-process reader". Stated the id grammar's three-way uniqueness (a key holds no `/`, only an anchored path holds `//`, a component or document path has no empty segment) — what a well-formed id argument can look like — and recorded `DioxusDocument::unkeyed_actionable` as a third reader whose entry holds id, tag and role plus a process-local `NodeId` in `node`. Trap written for this kind of chunk: a wire form of the check is a crossing for ids and must leave `node` behind; escalate it then. If the verb set names the actionable-key check and gives its result a data shape, that shape must not carry `node`.
