## Constraints
- obs-plan §3 Logging stack (subscriber installation) requires the session library `packages/escher-driver` to stay silent: no `tracing` dependency, no subscriber, no env read, no print — `Session::act` included. A schema module, a refusal type and a serial-form dependency added to that crate fall under the same requirement; whether the crate still holds it at this take-up is research's question (per obs-plan §3 Logging stack).
- obs-plan §4 Span / Trace Coverage places the one span per driver command — covering the settle wait — on the route entry "Driver command spans", not on this chunk: the verb set and the cause set are defined here without a span, an `#[instrument]` or an event (per obs-plan §4 Span / Trace Coverage).
- obs-plan §3 Logging stack requires the headless stand, its `stand_*` and `stand_session_*` checks, `stand_settle` and their shared modules to install no subscriber and to print nothing that is a log; a schema check added beside them, in the crate's unit tests or under `tests/blitz-tests/tests/`, installs no sink and prints no id, name or value (per obs-plan §3 Logging stack).
- obs-plan §6 Logged events requires `escher-session`'s own stderr lines to be fixed strings holding no path, label, id or value, and its stdout to carry nothing on any path. If question 1 is answered by a host behaviour (the host delivering ticks) and `session_host.rs` is edited, any line it gains is held to that rule; whether the present three `eprintln!`s are still the whole set is research's question (per obs-plan §6 Logged events).
- obs-plan §8 Scrubbing requires an event under an `escher_` target to print with the content-named fields redacted — `url`, `href`, `src`, `html`, `text`, `value`, `attrs`, `path`, `request`, `error`, `panic.payload`. The chunk emits none; the constraint it leaves is on naming: a refusal's cause is meant to be read by a later span field, and a field named `error` or `value` is redacted by that sink, so a cause or argument name chosen here that a later field would reuse verbatim is checked against that set (per obs-plan §8 Scrubbing).
- obs-plan §8 Values logged as-is records that the chained std panic hook prints the raw panic message to stderr past escher's scrub. A malformed call is therefore refused as a typed value, never by a panic whose message could carry the argument, the verb or the id it was aimed at (per obs-plan §8 Values logged as-is; the hook's chain per obs-plan §7 Panic hooks).
- obs-plan §9 Telemetry artifact handling requires the session state directory to hold the socket file alone while a session is up and nothing after `stop` — no log, event or screen content. A schema held in process writes nothing there; a rendered schema, a refusal record or a verb list is no file in that directory (per obs-plan §9 Telemetry artifact handling).

## Patterns to follow
- Fixed-string messages with no content: obs-plan §6 Logged events states the host's stderr lines as fixed strings holding no path, label, id or value — the shape a remedy text per cause should take if it can ever reach a stream (per obs-plan §6 Logged events).
- Returned to the caller, never logged: obs-plan §3 Logging stack describes checks that read a child's streams "into its assertions only" and a failure that prints a kind and a count, never what the host wrote — the model for a schema or refusal check whose failure message must not echo an argument value or an id (per obs-plan §3 Logging stack).
- A closed cause vocabulary in a call log without argument values: obs-plan §6 Log format (the cold-agent pipe) gives the stub's line as `{seq, tool, outcome: ok|refused, cause}` and "never an argument value" — the existing precedent for recording a refusal by its cause name alone (per obs-plan §6 Log format (the cold-agent pipe)).
- The sink is installed by binaries, not libraries: obs-plan §3 Logging stack records `escher_telemetry::init` at two install sites, both in the seven_guis package's binaries; a library chunk adds no third (per obs-plan §3 Logging stack).

## Anti-patterns to avoid
The plan's own anti-pattern section carries no recorded intent; the bans below are read off the sections named.
- No `println!` / `eprintln!` / `dbg!` and no `tracing` or `log` call in `packages/escher-driver` or in the schema's checks to show a verb, an argument, a refusal or a remedy — the crate's silence is a recorded requirement, not an accident (per obs-plan §3 Logging stack).
- No element id, accessible name, control value or argument text in any log field, harness event or call-log line; a refusal that carries the id it was aimed at is a return value only (per obs-plan §8 Scrubbing; per obs-plan §6 Log format (the cold-agent pipe)).
- No `unwrap` / `expect` / `panic!` on a caller-supplied argument in the validation path: the panic message leaves through the std hook unscrubbed (per obs-plan §8 Values logged as-is).

## Contract bindings
- obs ↔ route ("Driver command spans"): obs-plan §4 Span / Trace Coverage owes one span per driver command; the scope says that span's refusal-cause field reads this chunk's cause set. The cause set is therefore the value domain of a future span field — it should be closed, bounded and free of content (a name per cause, never an id or a label inside it). The plan records no span or field naming convention to bind the names to; the one recorded constraint on a name is the §8 scrub set (per obs-plan §4 Span / Trace Coverage; per obs-plan §8 Scrubbing).
- obs ↔ tests (test-plan §3, the cold-agent pipe): if the plan brings `scripts/cold_agent_stub.py` to the schema's cause names, the values of the call log's `cause` key change while its key set must not — `seq`, `tool`, `outcome`, `cause` and no argument value — and the pipe's marker-string contract test stays the witness (per obs-plan §6 Log format (the cold-agent pipe); per obs-plan §8 Scrubbing).
- obs ↔ security (security-plan §Error Handling / §Input Validation): what a refusal's text may carry is security's to state; obs's side is that any such text reaching a sink-installing binary's stderr is held to the fixed-string rule and that typed text in a sink-installing host's log is recorded as NOT measured — this chunk adds no command that types, so it neither closes nor widens that gap (per obs-plan §6 Logged events; per obs-plan §8 Values logged as-is).
- obs ↔ tests (seven_guis `host_log` / `host_binary`): only if `session_host.rs` is edited for question 1 — the by-level stderr readings of `escher-session` recorded in obs-plan §8 Values logged as-is are then a regression surface those two checks read (per obs-plan §8 Values logged as-is; per obs-plan §3 Logging stack).
