If the refusal type joins `SessionError`, each new variant falls under the message pin; if it is its own type, it needs a pin of the same strength. - Schema unit tests must compile and pass on every platform the matrix tests: only a check that starts a session process is `cfg(unix)`-gated, and the non-unix arms are witnessed by the fork's windows leg alone. - A check that reads a held stand instance boots through `seven_guis::stand` with the pinned options, runs in both layout modes, and calls no sleep, no clock and no skip path (per test-plan §5 Integration Test Strategy — Boundaries covered → Session ↔ held instance; the options per test-plan §7 Test Data & Fixtures — Builders and options; the no-skip rule per test-plan §2 Test Strategy — Test levels observed → Font-dependent tests).

## Patterns to follow
- The message-pin shape: one unit test walks every member of a closed set and asserts its text is non-empty, fixed and free of a path; the settle crate's form adds "distinct". This is the shape for "every cause carries a remedy" and "every verb carries an argument and a result shape" (per test-plan §4 Unit Test Strategy — What unit tests cover → escher-driver; the distinct form per test-plan §4 Unit Test Strategy — What unit tests cover → blitz-test-harness).
- The closed-grammar shape: each admitted form round-trips, and a table of inputs outside the grammar is each refused under one named cause. This is the shape for the malformed-call table — unknown verb, missing, extra and ill-typed argument (per test-plan §4 Unit Test Strategy — What unit tests cover → escher-driver).
- "A refusal changes nothing", proven by observation rather than by trust: the label check shows the boot closure never ran, the stub's tests show the count unchanged after each refusal, and the idle-settle check shows the same snapshot text, a false change flag after a drain and no focus. A refused schema call on a held instance is proven the same way (per test-plan §1 Test Scope Summary — Coverage scope → tests/blitz-tests, the `stand_settle` reading; the stub form per test-plan §4 Unit Test Strategy — What unit tests cover → Cold-agent pipe).
- A check that holds a session reads the shared session module (`hold`, `slug`, `change`) rather than restating a boot, and expectation tables are stated in the check, never derived from the code under test — a table of expected verbs or causes is written out in the test, not read back from the schema (per test-plan §3 Test Harness Contract — Crate-local test helpers → blitz-tests (session checks); the stated-expectation rule per test-plan §3 Test Harness Contract — Crate-local test helpers → blitz-tests (stand checks)).
- A new integration file named `stand_*.rs` is selected by the agent-run `stand` selection with no script change; a shared directory is not selected (per test-plan §3 Test Harness Contract — Agent-run contract → `run {selection}`).

## Anti-patterns to avoid
- An assertion that sits inside a condition on measured data, so the test passes without asserting; every row of a verb, cause or malformed-call table asserts unconditionally, and a table that parses to zero rows is a failure, as an empty run is never a pass (per test-plan §4 Unit Test Strategy — What unit tests cover → Conditional assertions; the empty-run rule per test-plan §3 Test Harness Contract — Agent-run contract → `run {selection}`).
- A constructor, a `pub` or a `cfg(test)` shim added to the code under test so a test can reach it; where a test needs private state it sits in a child module of the code it reads (per test-plan §3 Test Harness Contract — Crate-local test helpers → dioxus-native-dom).
- A real-time sleep or a wait on an undelivered tick to make a timing-dependent answer appear; the stand's checks move time only through the tick stand-in (per test-plan §8 Mocking & Stubbing Discipline — Hand-written fakes and stubs → Time (seven_guis timer)).
