- Boot any check that needs a held instance through the stand's lean-task mount at the pinned viewport, rather than a new fixture shell — the mount hierarchy and viewport are stated in layout-templates §Surface: desktop-native → Primary screens, and the harness default they match in layout-templates §Surface: desktop-native → IA notes.

- Keep usage errors in the shape the existing CLI rows share: usage to stderr, exit 2, nothing on stdout, checked before any precondition — per layout-templates §Surface: cli → Primary screens. This applies only if the plan touches a CLI entry point at all.
- Leave the exit grammar, event schema and session contract where layout-templates points them: it states only the CLI shape and defers the rest to test-plan §3 — per layout-templates §Surface: cli → Primary screens.

## Anti-patterns to avoid

- Letting the session host print, or accept new arguments, as a side effect of answering carried question 1 — banned by layout-templates §Surface: cli → Primary screens.
- Introducing a CLI output layout (verb list, help, schema dump) in this chunk — no row for one exists in layout-templates §Surface: cli → Primary screens, and the scope assigns that surface to later entries.
