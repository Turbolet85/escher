## Constraints
- **The session wire stays closed.** security-plan §Input Validation (Driver session socket row) requires the request grammar to stay the two lifecycle words, with the stated request and reply bounds, and to carry no element id, accessible name, control value, snapshot text or diff. A schema held in process must add no word to it; a verb that has to reach the wire in this chunk is a boundary widening of the kind security-plan §Threat Model Summary (Attack surface — local IPC vector) records as the founder's choice, asked first and never leaned. Whether the plan's module layout leaves `wire.rs` untouched is the plan's; whether any existing code path already forwards a caller string to the wire is research's question.
- **A call the schema does not admit is refused before any effect.** security-plan §Input Validation (Driver session label row) requires a caller-supplied value to be checked before the caller's work runs, with nothing done on a refusal; the schema's malformed-argument refusal (unknown verb, missing, extra or ill-typed argument) must hold the same order — validate, then act — so a refused call leaves the held instance as it was. The refusal itself is a typed value with a named cause, never a panic: security-plan §Error Handling (Error format (typed errors); Graceful degradation (no panic)) requires boundary failures to surface as typed errors, so every cause in the chunk's closed set must be a variant a caller can match, and no malformed input may reach an `unwrap`, `expect` or index. Whether the refusal joins `SessionError` or stands as its own type is the plan's.
- **Remedy and message text is fixed per cause.** security-plan §Input Validation (CLI arguments (escher-session) row) requires an error's text to be a fixed message with no path, label, id or value in it; each cause's remedy must be a constant string, with nothing of the call interpolated. Whether the existing `SessionError` message test can be extended to cover the new texts is research's question.
- **An id or value a refusal or result carries is returned to its caller only.** security-plan §Input Validation (Markup attributes — `id` (stable element id) row) requires that escher's own code give the id no exit beyond the platform accessibility adapter — no log, event, socket or file. If the plan lets a refusal name the id it was aimed at, or a result shape hold an id, that field must exist in the returned value alone; a typed-text argument is user content under the same rule.
- **A result shape that carries a control value takes it from the snapshot model.** security-plan §Input Validation (Markup attributes — password and file `input` value row) requires a password's or file input's value to read as the fixed mask, never the text, its length or a host path; security-plan §Data Protection (Local user data handled) requires the same of the file path. Any verb result that states a value must be defined over the snapshot or diff types, never over a DOM attribute read.
- **Waiting on a load with a clock is a new decision, recorded before any shape depends on it.** security-plan §API Security (Settle and loads in flight row) requires settle to report a load in flight at once, to read no clock, to stay within its pass bound and to return a class name only; security-plan §API Security (Request timeout row; Request size limit row) records no timeout and no size cap on the fetch side. The chunk's answer to question 2 is the operator's, written into §API Security as an amendment; a verb whose shape assumes a wait must state its bound, and its outcome must still name a class only.
- **A serialization crate is a dependency under the audit.** security-plan §Dependency Security (Audit tool; Pinning) requires per-ID ignores only, a committed lockfile, `--locked` builds and workspace-inherited versions, and records that the audit's resolved graph misses optional chains — so a crate added to `escher-driver` is reviewed by hand as well. Whether the candidate crate is already in the workspace's resolved graph (and at which version) is research's question.

## Patterns to follow
- **Closed grammar, two refusal classes.** The lifecycle wire distinguishes a known word at an unsupported version from everything else, and bounds both directions — a precedent for separating "unknown verb" from "malformed arguments" and for stating a size bound on every shape that will later cross (per security-plan §Input Validation, Driver session socket row).
- **Cause-first refusal with no state change, and a call log that never holds an argument value.** The cold-agent stub's refusal form — a named cause leading the result, arguments checked for missing, extra and ill-typed members — is the nearest precedent for the schema's malformed cause; whether the schema's cause names match the stub's is the plan's, read at P3 (per security-plan §Input Validation, Cold-agent MCP stub row).
- **Closed table, then validate, then boot.** The host binary admits its task from a fixed table and creates nothing on any other argv — the shape a verb table should take: membership is a lookup, never a parse of free text (per security-plan §Input Validation, CLI arguments (escher-session) row).
- **A path is a parameter.** Where a verb's argument or result names a filesystem location (the screenshot's, if the plan gives it one), it follows the state directory's discipline: caller-named, never an env read or a cwd-relative default (per security-plan §Input Validation, Driver session state directory row; security-plan §Secret Management, Environment values read).
- **`disabled` follows the presence reading.** The `disabled` cause's definition should rest on the same reading the snapshot's `enabled` uses, so a refusal and a snapshot never disagree about one element (per security-plan §Input Validation, Markup attributes — `disabled` row).

## Anti-patterns to avoid
security-plan §Security Anti-Patterns reads `NO RECORDED INTENT` and nothing is taken from it; the bans below come from the measured sections.
- **Widening the wire as a side effect of defining the schema** — a new request word, a longer line, or a reply field carrying anything of the screen (per security-plan §Input Validation, Driver session socket row; security-plan §API Security, Local session socket row).
- **Echoing the call in what a refusal says or logs** — a remedy, message or log field that interpolates an id, name, value, path or argument; the chunk adds no log call site, and a later one must keep such content out of fields the sink prints (per security-plan §Logging & Monitoring, Log format and backends — escher's own sink; security-plan §Input Validation, Cold-agent MCP stub row).
- **Reading question 2's answer off settle's present behaviour**, or giving a verb an unbounded or clock-reading wait without the decision recorded (per security-plan §API Security, Settle and loads in flight row).
