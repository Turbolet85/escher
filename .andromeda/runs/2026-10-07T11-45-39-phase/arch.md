## Constraints
- **Placement — the existing crate, no new one.** architecture §Existing Scopes → escher-driver requires the driver's code to sit in `packages/escher-driver` as private modules re-exported at the crate root (today session · host · client · wire · error); the schema is a further private module there. A new workspace crate would be a registration under architecture §Occupied Resources → Names first, never a silent add.
- **The crate names no app — this bounds question 1.** architecture §Established Decisions → [Driver session] requires that the session library take the app's boot from its caller and depend on no app: no manifest under `packages/` names an example, and the one edge runs `seven_guis → escher-driver`. A verb set stated in `escher-driver` may therefore name no stand type; architecture §Standard Contracts → Headless stand places `TimerTicks` (`deliver(n)`) in seven_guis, and architecture §Standard Contracts → CLIs places the tick handle in the `escher-session` host ("held until `serve` returns"). An answer that is a verb has to be app-agnostic in the library; an answer that is a host behaviour changes the `escher-session` contract in §Standard Contracts → CLIs.
- **The wire and the one listener stay as registered.** architecture §Occupied Resources → Network ports and listeners requires the socket to serve lifecycle messages only (`hello`, `stop` — no element id, accessible name, control value, snapshot text or diff), and architecture §Standard Contracts → Driver session fixes its grammar (`v1`, request ≤ 64 bytes, reply ≤ 128 bytes, `refused version` / `refused malformed`) and records "a verb set, a settle verb or busy-source reply on the socket" as not built. A schema held in process leaves both rows untouched; a verb that reaches the socket in this chunk is a boundary widening asked of the founder before any code.
- **`SessionError` is a closed, recorded set with fixed-string messages.** architecture §Standard Contracts → Driver session requires `SessionError` to be exactly its twelve variants, each with `Display` and `std::error::Error`, every message a fixed string carrying no path, label, id or value. Joining a refusal to that enum changes the "exactly" set; a separate refusal type is a new public contract on the same row. Either is a contract amendment recorded at wrap, and the plan picks one explicitly — including whether not-quiet stays `NotSettled(Busy)`.
- **A refused call must be decided before the step runs; settle's contract is not the place to answer question 2.** architecture §Standard Contracts → Driver session requires that `Session::act` not roll its step back, so "a refused call changes nothing" can only hold if validation precedes `act` (as `Session::start` validates the label with the boot not run). architecture §Standard Contracts → Test harness requires `Harness::settle` to report a load in flight at once, never wait on one, and read no clock but the harness's own; a driver command that waits on a load with a clock is outside that contract and is a new decision, never a change to `settle`, `pump` or `tick`.
- **Dependencies and manifests.** architecture §Conventions → Manifests requires a dependency to be declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }`. architecture §Occupied Resources → Names records escher-driver as depending on blitz-test-harness and dioxus-native-dom only, with no features and no binary target — a serialization crate added for the schema's data form changes that recorded fact (amended at wrap). architecture §Stack and Technologies lists `serde "1"` in the workspace table and `serde_json` only as the WPT runner's own dependency; whether `serde_json`, or serde's `derive`, is available from `[workspace.dependencies]` today is research's question. architecture §Established Decisions → [Dependency pinning] names the coupled pins; none may move as a side effect.
- **Result shapes that name snapshot, diff or check types force two recorded decisions.** architecture §Established Decisions → [Driver session] requires that the library name no `dioxus-native-dom` feature — "the entry that first reads the snapshot through a session decides it" — and architecture §Cross-cutting Patterns → Config management gates `snapshot`, `snapshot_diff`, `snapshot_text` and `actionable` behind `accessibility`. architecture §Standard Contracts → Dioxus DOM bridge further records that the snapshot has one serialized form (`to_text`), that the diff has no text form, no JSON form and no parser, and that `unkeyed_actionable` has no wire form. A schema that describes those results as data states a shape; building a second serialized form of any of them, or naming the feature on escher-driver, is a contract change this chunk makes knowingly or leaves to the entry that serves it.

## Patterns to follow
- **Closed enum, class-only naming, one fixed message per variant** — the shape architecture §Standard Contracts → Test harness requires of `Busy` / `NotSettled` (names a class only — no node, element, name, URL or value; `Display` with one fixed message per class; `std::error::Error`) and architecture §Standard Contracts → Driver session requires of `SessionError`. The cause set and its remedies follow it; architecture §Conventions → Error handling requires error types to be enums with `Display`.
- **A remedy as a method on the typed value** — architecture §Standard Contracts → Dioxus DOM bridge records `UnkeyedActionable::remedy() -> String`, which names the fix while no field and no text holds the element's content, accessible name or an attribute value.
- **Closed grammar, refuse and change nothing** — architecture §Standard Contracts → Driver session (the wire's `refused malformed`: "a refusal or a broken connection changes nothing") and architecture §Standard Contracts → CLIs (`escher-session`: a closed argv, exit `2` "having booted nothing and created no state") are the two in-tree shapes of a malformed call; architecture §Standard Contracts → CI contracts records the stub's cause names `not-found` · `disabled` · `not-pressable` · `malformed`, the naming precedent the plan matches or departs from on purpose.
- **Documented public surface** — architecture §Standard Contracts → Driver session requires the crate to stand under `#![deny(missing_docs)]`, and architecture §Conventions → Formatting and lints requires rustdoc warnings as errors over every workspace library crate: every public verb, shape, cause and remedy item carries `///`.
- **Test placement** — architecture §Conventions → Tests requires unit tests in `#[cfg(test)] mod tests` at the end of the source file, one behaviour per integration-test file opening with a `//!` doc, scenarios in both layout modes, and anything shared by checks that hold a `Session` in `tests/blitz-tests/tests/session_common/mod.rs`.

## Anti-patterns to avoid
- **Widening the socket by a lean** — no verb, settle reply, refusal cause or screen content on `session.sock`, and no new listener, port or env var, without the registration architecture §Occupied Resources → Network ports and listeners requires first.
- **Reaching into the stand from the library** — no `seven_guis`, `LeanTask` or `TimerTicks` name in `escher-driver`, and no dependency from a `packages/` manifest on an example, to answer the Timer question (architecture §Established Decisions → [Driver session]).
- **Growing the library's ambient surface** — no `tracing` dependency, span or event, no env read, no default state location and no idle expiry added to escher-driver in this chunk (architecture §Established Decisions → [Driver session]); and no per-crate version pin outside the workspace table (architecture §Conventions → Manifests).

## Contract bindings
- **arch ↔ security** — the socket crossing (architecture §Occupied Resources → Network ports and listeners) is the boundary security-plan's driver-session rows validate; the fixed-string, content-free message rule (architecture §Standard Contracts → Driver session) is what a refusal's text may carry; question 2 leaves settle's "never waits on a load, reads no clock but the harness's own" (architecture §Standard Contracts → Test harness) and is recorded on the security side.
- **arch ↔ tests** — the lifecycle and `act` contract (architecture §Standard Contracts → Driver session) is what the keyed `session-lifecycle` contract and the `stand_session_*` / `stand_settle` checks pin; the stub's cause names (architecture §Standard Contracts → CI contracts) are pinned by `test_cold_agent.py`, so bringing the stub to the schema moves a pinned contract.
- **arch ↔ obs** — the library carries no `tracing` dependency (architecture §Established Decisions → [Driver session]) and escher targets print with content-named fields redacted (architecture §Standard Contracts → Telemetry bootstrap); the cause set this chunk names is the value the later command span reads, so a cause name is a class, never content.
- **arch ↔ a11y** — the `disabled` cause's meaning is bound to the snapshot's `enabled` reading, the `disabled`-presence reading (architecture §Standard Contracts → Dioxus DOM bridge; architecture §Established Decisions → [DOM semantics]), not the focusability reading.
- **arch ↔ all domains (crate naming)** — every domain's content for this chunk lives in `escher-driver`, `seven_guis` (`escher-session`) and `blitz-tests` as architecture §Existing Scopes names them.
