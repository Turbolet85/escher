## Constraints
- The root manifest must hold no git dependency, per security-plan §Dependency Security (Pinning). Its Taffy line records a registry "0.15" resolved to 0.15.0 with a checksum. A take that carries upstream's four Taffy-main commits (`upstream/main:Cargo.toml` names a git Taffy rev) reverses that recorded state, so it needs the founder's ruling first. Every earlier sync is recorded the same way: the lock's `name@version` set equals upstream's at the pin, with the two `escher-*` entries set aside. Each package that enters the lock is reviewed by hand for licence, repository, build script and proc-macro flag. Whether the chosen shape moves `Cargo.toml` or `Cargo.lock` at all is research's question.
- The audit is cargo-deny `--locked --workspace --all-features check advisories licenses` over the whole workspace graph, per security-plan §Dependency Security (Audit tool). Ignores are allowed only per ID, each with a written reason. No blanket allow is permitted, and `unmaintained` and `unsound` stay at their defaults. The eight standing ignores are kept as recorded, and a new advisory is either fixed by a semver-compatible update or ignored by ID with its reason.
- Every cargo leg passes `--locked`, and `Cargo.lock` stays committed, per security-plan §Dependency Security (Supply chain integrity, Lockfile verification). `deny.toml`'s `[licenses]` table stays byte-identical to upstream's, and the audit leg's `licenses` check runs on every push, per security-plan §Dependency Security (Supply chain integrity, Licence compliance).
- Escher's sink admits engine-prefix targets with only the safe fields printed, prints `escher_*` targets with content-named fields redacted, and drops every other target whole at every level, per security-plan §Logging & Monitoring (Log format and backends). Upstream's delta must be read for any new `tracing` or `log` call site, new target or new print. Whether it adds any is research's question; the scope's inputs#I1 reports none.
- The host's capture readings are re-read on the merged engine, per security-plan §Logging & Monitoring (Log format and backends). ## Patterns to follow
- Write a per-sync lock record as earlier syncs did, per security-plan §Dependency Security (Pinning). Name the packages that enter, leave or move, and state that `deny.toml` is unchanged. The audit verdicts `advisories ok` and `licenses ok` are evidence in `escher-0.2.0/chunks/{chunk}/evidence/lock.md`. For a partial take, state the excluded commits and the reason, as the 2026-10-18 sync's record does.
- Treat a reading that a merge carries in as upstream's behaviour, recorded as such, per security-plan §Input Validation (the `aria-labelledby` and `aria-describedby` rows of the 2026-10-17 sync). A change that widens a boundary is put to the founder; one that only changes behaviour inside an already ratified carrier is not.
- Re-read the sink by measuring the standing capture checks (`host_log`, `mcp_log`) under both builds at `trace`, with counts by line and bytes, per security-plan §Logging & Monitoring (Log format and backends). Do not re-argue the allowlist itself.

## Anti-patterns to avoid
- Do not bump one side of a coupled pin alone or run a broader `cargo update` to make the take resolve, per security-plan §Dependency Security (Audit tool: no fix reachable "without a lone bump of the coupled winit pin"; Pinning: every sync took "upstream's dependency set whole, with no `cargo update`").
- Do not add a blanket allow, or set `unmaintained` or `unsound` to none, in `deny.toml` to turn the audit green, per security-plan §Dependency Security (Audit tool).
- Do not let the conflict resolution in `packages/blitz-dom/src/mutator.rs`, or any gate fix, add a log site, print or field that holds node text, an id or a name, per security-plan §Logging & Monitoring (Log format and backends).

## Contract bindings
- security ↔ obs: the sink allowlist re-check and the `host_log` and `mcp_log` needle counts are shared with obs-plan's capture contracts. A moved `focussed node` line count is recorded in both places.
- security ↔ tests: the audit leg (`bash .github/scripts/ci-leg.sh audit`, ci.yml's `audit` job) is a CI job whose green state is read with the per-OS tallies of the take's own CI run.
- security ↔ a11y: the `inert` and keyboard-activation rows are pinned by `stand_keyboard` and `inert_subtree`, which are also a11y's focus-order readings.

## Acceptance criteria contributions
- `bash .github/scripts/ci-leg.sh audit` reads `advisories ok` and `licenses ok` on the final tree. `deny.toml` is either unchanged or changed only by per-ID ignores, each with a written reason (per security-plan §Dependency Security).
- `Cargo.toml` holds no `git =` dependency unless the founder's ruling at P4 reverses the recorded state, and the chunk's `evidence/lock.md` records the lock delta against upstream's set at the measured pin (per security-plan §Dependency Security).
- `host_log` and `mcp_log` pass with 0 typed-sentinel occurrences, 0 id needles and 0 name needles at `trace` under both builds. The workspace-built host's line and byte counts are re-read, and any move is recorded (per security-plan §Logging & Monitoring).
- Upstream's added `.rs` lines on the take hold no new env read beyond the recorded list, and no listener or bind. A grep over the take's diff verifies this (per security-plan §Secret Management).
