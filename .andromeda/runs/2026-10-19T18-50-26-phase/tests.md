relevant — a sync's proof is test-side: upstream's two new blitz-tests files to register, the target pin, the re-counted tallies, the oracle and the repeated stand checks.

## Constraints
- blitz-tests keeps one test target per file. Upstream's `tests/all.rs` stays a declared `[[test]]` held at `test = false` and is never built. An upstream file merged in becomes its own auto-discovered target with no manifest line, and `all.rs` gains only its `mod` line. Each run is read as 0 `Running tests/all.rs` lines and no `all` executable. A take carrying `38ca4e777` therefore makes `focus_within.rs` and `focus_redraw.rs` two new targets, moving the file and target counts the section records by +2 (per test-plan §2 Test directory + naming conventions, Directory pattern).
- `BlitzTestsTargetsTest` (`.github/scripts/test_blitz_tests_targets.py`) pins the manifest. `[package]` must not set `autotests = false`, and exactly one `[[test]]` table must stand: `all` at `tests/all.rs`, `test = false`. Whatever upstream's `tests/blitz-tests/Cargo.toml` delta is, the resolution keeps that two-line difference (per test-plan §4 Unit Test Strategy, blitz-tests targets).
- The differential oracle runs the same fixture and mutation sequence in an incremental and a non-incremental document. After each step it compares every node's `final_layout()`, `layout_children` and paint tree, and asserts that no damage remains. It must stay green on the merged engine (per test-plan §2 Test Strategy, Differential oracle).
- Per-OS test tallies are re-read on the take's own green CI run, from its test-bearing job logs: linux, macOS, coverage, windows, the a11y job and the stand repeat, with ios and android build-only. The last recorded reading is CI#39111579925 (2026-10-18-one-virtual-clock). Each moved count is attributed by name, the way earlier syncs attributed upstream's merged files (per test-plan §9 CI Integration, Per-OS test tallies).
- The local `ci-leg.sh fast` count is re-counted as result lines and passed · failed · ignored, from the last recorded 194 · 1001 · 0 · 12. Each added result line and each passed delta is attributed to a named upstream file, with the evidence path cited (per test-plan §9 CI Integration, Local baseline).
- The stand checks have a zero-failure budget. `stand-repeat` runs the 44 `stand_*.rs` files and seven_guis' eight process checks in three rounds with no retry (per test-plan §10 Quality Gates, Flakiness budget).
- Coverage floors stay escher-driver 97 %, dioxus-native-dom 83 % and blitz-test-harness 90 %. Both `cargo llvm-cov` lines keep `--ignore-filename-regex 'keyboard_compat\.rs$'` until upstream retires `keyboard_compat.rs`, which CARRY 2 reads as not yet retired (per test-plan §10 Quality Gates, Coverage floors).

## Patterns to follow
- Earlier syncs registered upstream's merged test files the same way each time: each file its own auto-discovered target with no manifest line, upstream's `all.rs` gaining its `mod` lines and staying unbuilt. The counts were recorded in that chunk's `evidence/counts.md`, as 2026-10-17-upstream-sync-engine-debts did for `accessibility_label.rs` and `accessibility_description.rs` (per test-plan §2 Test directory + naming conventions, Directory pattern).
- Upstream's merged checks may assert through test-that's `verify_that!` and return `TestResult<()>`, run by the standard `#[test]` harness. test-that 0.6.0 is already a blitz-tests dev-dependency. Whether `focus_within.rs` and `focus_redraw.rs` need anything beyond it is research's question (per test-plan §3 Test Harness Contract, Runners and invocation, Rust tests).
- A focus-move redraw is observed by a hand-written `ShellProvider` fake that counts redraw requests, the existing stand-in pattern in blitz-dom's own tests. Whether upstream's `focus_redraw.rs` uses it, and what it asserts about the dropped Tab-arm redraw, is research's question (per test-plan §8 Mocking & Stubbing Discipline, Hand-written fakes and stubs).
- At a sync, `bash scripts/agent-run.sh run stand` is re-read with `scripts/agent-run.sh` byte-identical: the `run.end` totals are compared with the last reading, and new `stand_*` files are picked up by prefix with no script change (per test-plan §3 Test Harness Contract, Agent-run contract, Proof).

## Anti-patterns to avoid
- Never make the stand repeat green with a retry, `--ignored` or an env var. The first red command ends the leg with its status (per test-plan §9 CI Integration, Legs, stand-repeat).
- Never read a green per-package run (`cargo test -p blitz-tests`) as the workspace leg's green. The two builds resolve blitz-dom with different features (`tracing`, `writing-mode`). A check that reads a sink's capture counts lines by target, never in total. This applies to any new engine log line in upstream's focus code (per test-plan §9 CI Integration, Engine features by runner).
