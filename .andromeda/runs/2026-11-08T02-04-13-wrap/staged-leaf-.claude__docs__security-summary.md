# Security Summary — escher

_Distilled from `.andromeda/security-plan.md` (adopted reading — current truth, not intent). wrap-session's cascade re-derives it when the plan changes._

## Posture

escher is a native-API engine library with no served network API, no served TCP or UDP port — two `blitz-net` tests alone binding TCP on loopback, served by no binary — and no authentication; its one listener is local — the driver session's owner-only Unix-domain socket, which carries the session's lifecycle and, since 2026-10-10-driver-cli, driver calls and their answers (ratified by the founder, 2026-10-10); since 2026-10-10-mcp-surface the same calls and answers also cross to an MCP client over the `escher-session mcp` role's own stdio, no listener (ratified by the founder, 2026-10-10). Its risk is in what it ingests: arbitrary remote HTML/CSS/images/fonts/sub-documents, JavaScript run by `blitz-vibey-script`, and CLI arguments of the examples. The application-level threat model is NOT YET MEASURED.

**Tier:** 0
**Auth approach:** none (observed absent in every slice)
