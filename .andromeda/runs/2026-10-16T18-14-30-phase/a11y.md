# a11y extract

## Relevance
partial — a tests-only chunk with no new UI surface, but two of its three mutant sites feed a11y-asserted surfaces: the Timer stand task (a range input, Tab stops, contrast rows) and the Dioxus mutation writer's text nodes (the accessible names in the tree and the snapshot).

## Constraints
- The stand's Tab sequences are asserted per lean task against the shared table `tab_order` and, in enabled states, `ENABLED_TAB_ORDER` (tests/blitz-tests/tests/common/mod.rs). A shipped change to `examples/seven_guis/src/tasks/timer.rs`, allowed only as P4's fork, must not move a Timer focus stop, or those tables move with it (per a11y-plan §5 Test harness pattern).
- `stand_contrast` records the Timer's controls row for row: `timer-reset` (accent, 5.47), `timer-duration` (no-text) and `label[for=timer-duration]` among `TEXT_ROWS`. A Timer markup or CSS change moves that record. The scope bars such a change, and a fork that needs one also has to update the record (per a11y-plan §6 Color contrast).
- The plan records `packages/dioxus-native-dom/src/mutation_writer.rs` as byte-identical to upstream's at `434e0661`. Adding a test inline in that file (a `#[cfg(test)]` module) would break that identity, so a fast-failing check for the `create_text_node` mutant belongs in a separate test file. Whether the file is still byte-identical at HEAD is a question for research (per a11y-plan §5 Script and framework exposure).
- Text nodes become `TextRun` nodes that label their parent, and the snapshot takes each node's name from the tree `accessibility_tree` returns. So a text node that is never created leaves its parent's accessible name empty, and the plan's own readers can observe that. Whether existing name checks (such as `counter-value`'s name) reach `create_text_node` before the hang is a question for research (per a11y-plan §7 Accessibility tree output).
- The `a11y` leg runs a fixed list of six files with recorded per-file counts. Any new `stand_*` file also runs three times in the `stand-repeat` leg under the zero-failure budget, so a watchdog or bound it adds must not be flaky. This chunk adds nothing to the `a11y` leg's list (per a11y-plan §9).
- The Timer's range input `timer-duration` holds a current value separate from its `value` attribute. Each change fires one `input` event and marks the changed set. A move that changes nothing fires no event. A Timer test that reads the slider must read the current value (`range_input_value`), not the attribute (per a11y-plan §5 Keyboard handling).

## Patterns to follow
- The stand checks' shared module states the expected `controls`, `INPUT_NAMES`, `REGION_NAMES`, `tab_order` and `rendered` once. A new stand check reuses those tables and adds no table of its own (per a11y-plan §7 Accessibility tree output).
- `stand_act_range` drives the Timer slider through the driver by click and key and reads it back focused, with role `Slider` and its name unchanged. Use it as the model for a Timer check that goes through the session (per a11y-plan §5 Test harness pattern).
- Stand checks run in both layout modes. Each a11y reading is asserted under incremental and non-incremental layout alike (per a11y-plan §5 Test harness pattern).

## Anti-patterns to avoid
- Computing an expected role or name with a mapping inside the test instead of reading the tree or the snapshot. The plan's readers are "stated expectation, never a second role or name mapping" (per a11y-plan §7 Accessibility tree output).
- Reading `has_changes()` as "this step changed something" without draining the set first. The set is non-empty on a freshly booted harness document, and settle neither reads it nor drains it (per a11y-plan §2 Accessibility tree lifecycle).

## Contract bindings
- a11y ↔ tests: the `a11y` leg's six-file list and counts, and the `stand-repeat` leg that reruns every `stand_*` file under test-plan §10's zero-failure budget (per a11y-plan §9). A new stand file falls under the second but not the first.
- a11y ↔ design: the Timer's contrast rows bind to design-system §Color Palette, and only if a fork touches Timer styling (per a11y-plan §6 Color contrast).
