## Constraints
- A package that enters `Cargo.lock` under any take needs a by-hand review, and the lock is read name by name against upstream's or against the tree before it; the audit leg (`cargo deny --locked --workspace --all-features check advisories licenses`) must read green with ignores per ID only, each with a written reason, no blanket allow (per security-plan §Dependency Security, Audit tool and Pinning; detail `.andromeda/security-plan-detail/dependency-security.md`).
- The plan records no git dependency in the root manifest and every build leg `--locked`; a shape that brings git Stylo, git Taffy or a Dioxus alpha reverses that record, so it is the founder's fork at P4, never an implementer's resolution; which shapes stay within it is research's reading, per shape (per security-plan §Dependency Security, Pinning; per security-plan §Dependency Security, Supply chain integrity, Lockfile verification).
- `91ef65e21` (`URLSearchParams`) reaches the script boundary a remote page can use: the taken API must check or coerce its arguments, throwing a JS error or falling back to a default on a bad call, and must widen neither the default fetcher's `file:`/`data:` limit, nor the `file:`-only-for-a-`file:`-document refusal, nor `fetch()`'s GET or HEAD limit; whether upstream's text does so is research's question (per security-plan §Input Validation, JS API arguments and Script fetch; per security-plan §Threat Model Summary, Vector: script execution).
- The key-press panic at `packages/blitz-dom/src/node/node.rs:1775` is recorded as remote-reachable and not fixed; the plan requires the path to be re-read at this take, its fix an engine change for every document and the founder's fork at this entry's P4; whether upstream's `node.rs` already removes it is research's question (per security-plan §Error Handling, Panic paths, detail `.andromeda/security-plan-detail/error-handling.md`; per security-plan §Threat Model Summary, Vector: remote web content, detail `.andromeda/security-plan-detail/threat-model-summary.md`).
- Each new `tracing`/`log` call site, target, print or env read in the taken delta is judged against escher's sink: an engine target prints only its allowlisted fields, an `escher_` target all but the content-named ones, any other target is dropped whole at every level, and the standing capture checks stay at 0 needles; whether the delta adds such a site is research's reading (per security-plan §Logging & Monitoring, Log format and backends, detail `.andromeda/security-plan-detail/logging-monitoring.md`).
- The taken delta must add no secret read and no env var to escher's own crates: every env value read is a registered, non-secret entry, and the escher-driver library and `escher-session` read none beyond `RUST_LOG` through `escher_telemetry::init`; a read the delta brings is registered with its site or refused (per security-plan §Secret Management, Environment values read).
- Conflict resolutions keep the markup-read and masking boundaries a remote page reaches: the select list's labels and `size` cap, a password's or file input's `MASKED_VALUE`, and no `NodeId` across a carrier; an engine change a take brings that changes what crosses them is named as a boundary widening for ratification (per security-plan §Input Validation, Markup attributes and Markup numeric attributes; per security-plan §Input Validation, Driver session socket, the widening rule).

## Patterns to follow
- The two last takes' form: no-commit cherry-picks of upstream's text, the merge base standing at `23b9b26a9`, `Cargo.toml`, `Cargo.lock`, `deny.toml` and crate manifests compared byte for byte against the tree before it, and a lock evidence file recording what entered, left and moved (per security-plan §Dependency Security, Pinning, detail `.andromeda/security-plan-detail/dependency-security.md`).
- Hand review of a crate that enters: licence, repository, build script, proc-macro flag and direct dependent, recorded with the source-not-read limit stated (per security-plan §Dependency Security, Pinning, detail `.andromeda/security-plan-detail/dependency-security.md`).
- External decay handling: an advisory that turns the audit red with no fix reachable takes a per-ID ignore with its reason, the founder's or operator's word and a `.andromeda/residuals.md` owner; a fix reachable by a lock-only update goes that way with the manifest unmoved (per security-plan §Dependency Security, Audit tool, detail `.andromeda/security-plan-detail/dependency-security.md`).
- A CI action edit, the `matrix_test` free-disk step included, keeps every `ci.yml` `uses:` pinned to a 40-hex commit SHA with its ref as a trailing comment, asserted by `test_ci_workflows.py` (per security-plan §Dependency Security, CI tooling; per security-plan §Dependency Security, Supply chain integrity, CI action, the `matrix_test` free-disk step).
- Sink checks by count: capture readings report needle counts per build and level, never the captured text (per security-plan §Logging & Monitoring, Log format and backends, detail `.andromeda/security-plan-detail/logging-monitoring.md`).

## Anti-patterns to avoid
- A blanket advisory allow, an ignore with no written reason, or dropping `--locked` to get a take through (per security-plan §Dependency Security, Audit tool; per security-plan §Dependency Security, Supply chain integrity, Lockfile verification).
- Widening the sink's allowlist, or passing a content-named field through it, to admit a new upstream target or field (per security-plan §Logging & Monitoring, Log format and backends).
- A new `unwrap`, `expect` or panic path on anything a call supplies in escher-driver while resolving a conflict (per security-plan §Input Validation, Driver command schema).

## Contract bindings
- The audit leg as a CI security gate binds to the test plan's CI Integration: one workflow, the audit a job within it, its green read on the pushed commit with every job settled (security-plan §Dependency Security, CI integration ↔ tests §CI Integration).
- The sink re-check binds to the observability plan's PII Scrubbing: the same allowlist and content-named fields, read by the standing capture checks `stand_act_spans`, `host_log` and `mcp_log` (security-plan §Logging & Monitoring, Log format and backends ↔ obs §PII Scrubbing ↔ tests).
- Upstream's new and edited test fixtures taken by this chunk hold no real PII (security-plan §Data Protection, Local user data handled ↔ obs §PII Scrubbing ↔ tests).
