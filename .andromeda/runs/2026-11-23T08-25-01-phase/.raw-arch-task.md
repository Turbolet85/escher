@task_prose part=chunk
Places a custom widget at its content box (upstream issue #1578): its paint receives the content-box size, and its scene lands at the content-box origin inside the element's own transform, so it covers its content box exactly with padding, border and a transform alike.
Lets a widget draw canvas text from the bundled fonts, so canvas text on the stand reads the same font as the document's own text, in both layout modes; the route by which a widget reaches those fonts is an operator's fork, written to the chunk's founder-forks evidence and never answered by a default.
Every check it adds is run red first, on the tree before its fix or with the fix reverted, and the red reading is kept beside the green with every path respelled.
Re-reads every widget implementor's paint size, the stand's served-task readings and kept checks, and the last wrap's CI verdict before its push.

@task_item n=1 part=needs
The Widget trait's paint receives the content-box size (border-box minus padding and border) times the viewport scale, in place of the border-box size; every widget behind the custom-widget feature changes its paint size.
@task_item n=2 part=needs
A widget's returned scene is appended at the content-box origin inside the element's own transform (the element transform, then the translation to the content origin), not translated in output axes after it; the scale and the content origin are in the same units at the append.
@task_item n=3 part=needs
Whether a widget's scene is clipped to its content box is open: P3 reads it and asks the operator as a dialog; the chunk does not settle it by a default.
@task_item n=4 part=needs
Canvas text drawn by a widget is shaped from the bundled fonts, the same set as the document's own font context, so it reads the same font as the document's text; it never reaches a system or local font.
@task_item n=5 part=needs
The route by which a widget reaches the bundled fonts (a new or widened public API of blitz-dom or of the Widget trait, or the app's own copy of the same bundled bytes) is a public-surface fork of the operator's, never answered by a default; any new public item it adds follows the public API rules of the crate it lands in.
@task_item n=6 part=needs
No font file or other asset enters the tree by default; the stand already bundles DejaVu Sans and blitz-dom its bullet font, and a new one is an operator's fork.
@task_item n=7 part=needs
Canvas content, its text included, crosses only as pixels in a shot on the ratified carriers; whether app-authored canvas text is inside that crossing or a new class is an operator's fork.
@task_item n=8 part=needs
The screenshot's contract stands: an 800 x 600 shot composited over opaque white after paint, byte-identical across processes on one host, refused fonts-unavailable before anything is painted, a password input painted masked, no step run and nothing changed by a shot.
@task_item n=9 part=needs
Headless shots render on the Vello CPU renderer, which paints custom and resource paints transparent with no warning; a widget that paints through a texture or a resource is not made to show, so the canvas paints through the scene API only.
@task_item n=10 part=needs
The headless harness turns on blitz-paint's custom-widget feature; widgets and their paint stay behind that feature gate.
@task_item n=11 part=needs
The placement fix is a direct engine change for every document behind the custom-widget feature: flagged upstreamable, the fork's additions kept in functions of escher's own where they can be, and ratified per change as an operator's fork.
@task_item n=12 part=needs
Paint emits commands to a paint scene and assumes resolved styles and layout; the content box is read from the resolved layout, never recomputed in paint.
@task_item n=13 part=needs
Every check runs in both layout modes, incremental and non-incremental, and both give identical layouts and identical canvas pixels.
@task_item n=14 part=needs
The stand typography is DejaVu Sans, the bundled font the stand shares; canvas text on the stand reads it.
@task_item n=15 part=needs
No new verb, argument, carrier, cause, session error, exit, log field or span unless a fork's ruling adds one; no content in a log field.
@task_item n=16 part=needs
The stand's seven served tasks keep their snapshot, lint and actions digests (the cross-OS readings check), and the committed kept checks and stand checks keep their readings unless a ruling moves one, then re-recorded, never loosened.
@task_item n=17 part=needs

@task_item n=18 part=needs

@task_item n=19 part=needs
