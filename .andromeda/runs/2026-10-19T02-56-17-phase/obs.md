# obs extract

## Relevance
relevant: the entry's «never logged» clause is a rule about the sink and spans, and a kept check is a new file holding call content next to the session state directory that obs §9 describes.

## Constraints
- The `command` span must keep exactly its eight fields of fixed words, bools and counts. It must never field an argument, a `Command`, `Call`, `ArgValue`, `Outcome`, `Refusal` or `Fault`, the record of ids or the session's label. So the act of recording, and whether it is on, add no field to it (per obs-plan §4 Span / Trace Coverage).
- The MCP `tool_call` span must keep its two closed-word fields, `tool` and `ending`, and no other. A recording made over the `mcp` role adds no field to it (per obs-plan §4 Span / Trace Coverage).
- escher-driver installs no subscriber and reads no env var. `Command`, `Call`, `ArgValue` and `Outcome` derive `Debug`, which prints ids, typed text, names and values, and nothing in the crate may log, field or `Debug`-print any of them. Any recording type that holds calls or answers falls under the same ban, and so does an env var that switches recording on (that is also an arch §Occupied Resources registration). Whether the code already keeps these bans for a new type is research's question (per obs-plan §3 Observability Harness Contract, Logging stack).
- A command's answer goes on stdout and is never a log line. The sink writes to stderr only. Every command-line diagnostic is a fixed string that holds no path, label, id or value and writes back nothing the caller typed. That rule covers any recording ending, usage line or session error added here, including the kept file's path (per obs-plan §6 Log Coverage, Logged events → examples).
- Under an `escher_` target the sink prints every field except the content-named set (`url` · `href` · `src` · `html` · `text` · `value` · `attrs` · `path` · `request` · `error` · `panic.payload`). A new escher-driver field with any other name, such as `steps`, `file` or `check`, would print in clear. «Never logged» therefore has to hold by adding no log site, not by relying on redaction (per obs-plan §8 PII Scrubbing & Compliance, Scrubbing).
- The plan currently describes the session state directory as `0700`, holding `session.sock` alone while a session is up and nothing after `stop` or idle expiry, with no log, event or screen content written into it. If a kept check lives there, that row changes and needs a wrap amendment. Where an MCP session's check lives (that role has no `--session`) is a placement the row does not yet cover (per obs-plan §9 CI Integration, Session state directory row).
- The CARRY's clock check, which covers the sub-document's carried clock, pan and the fling, must stay silent like the existing clock checks. That means no subscriber, no env var read and no print, with readings going into assertions only. The document's clock adds no log site, span, field or env read (per obs-plan §3 Observability Harness Contract, Logging stack detail: the clock checks).

## Patterns to follow
- Needle measurement on a sink-installing binary: `examples/seven_guis/tests/host_log.rs` (the host) and `examples/seven_guis/tests/mcp_log.rs` (the `mcp` role) read stderr at `RUST_LOG=trace` under both builds. Each counts the typed sentinel, id needles, name needles and the first 64 base64 characters of a shot, all expected at 0, and a failure prints a kind and a count, never what was written (per obs-plan §8 PII Scrubbing & Compliance, Values logged as-is; obs-plan §3 Observability Harness Contract, Logging stack).
- A precedent for a check kept at rest: the cold-agent pipe's `check.json` is a JSON array of steps written as parsed. It is never printed or copied, sits in a local gitignored state area and is uploaded by no CI leg (per obs-plan §3 Observability Harness Contract, Cold-agent pipe log; obs-plan §9 CI Integration, Cold-agent pipe state row).
- Span field-set pins: `tests/blitz-tests/tests/stand_act_spans.rs` captures the `command` line through `escher_telemetry::init_with_writer` in re-run children. `tests/blitz-tests/tests/stand_mcp_tools.rs` uses a hand-written `Recorder` to assert the `tool_call` → `command` parentage and fields (per obs-plan §4 Span / Trace Coverage).
- The silence probe over new checks and their shared modules reads 0 hits for print, env, subscriber and listener (`println!|eprintln!|print!|dbg!|std::env|env::var|escher_telemetry|tracing_subscriber|UnixListener|TcpListener|bind\(`) (per obs-plan §3 Observability Harness Contract, Logging stack).

## Anti-patterns to avoid
- Fielding a recorded step, an argument by its schema name, or a `Command` / `Outcome` with `Debug` on any span or event. This prints an id, typed text, an accessible name or a control's value, and only `text` among the argument names is in the scrub set (per obs-plan §4 Span / Trace Coverage).
- Writing a sink line, event or screen content into the session state directory, or printing the kept check's content or path on stderr (per obs-plan §9 CI Integration, Session state directory row; obs-plan §6 Log Coverage, Log format (escher's sink)).

## Acceptance criteria contributions
- With recording on, `host_log` and `mcp_log` at `RUST_LOG=trace` under both builds read 0 typed-sentinel occurrences, 0 id needles and 0 name needles. They also read 0 occurrences of the kept file's path or content. The counts stay one `command` line per hosted call and one `tool_call` line per MCP call (per obs-plan §8 PII Scrubbing & Compliance, Values logged as-is).
- The `command` span still carries exactly its eight fields and `tool_call` its two in `stand_act_spans` and `stand_mcp_tools`, with recording on. The recording code adds no `tracing` call site, field or env var read (per obs-plan §4 Span / Trace Coverage).
- Every new or extended check, the round-trip test and the CARRY's clock check included, installs no subscriber, reads no env var and prints nothing. The silence probe reads 0 over them and their shared modules (per obs-plan §3 Observability Harness Contract, Logging stack).
- If the kept check lives in the state directory, the obs-plan §9 Session state directory row is amended at the wrap to name it. Even then, no sink line or event is written into the directory (per obs-plan §9 CI Integration, Session state directory row).
