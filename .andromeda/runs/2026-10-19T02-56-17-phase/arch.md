# arch extract

## Relevance
relevant — the chunk adds a new at-rest resource and a recording path inside `packages/escher-driver/` (session, host, MCP server, command line, JSON writer) and the `escher-session` binary, every one of them governed by the Driver session decision, contract and the occupied-resource registry; the folded CARRY binds to the document-clock contract.

## Constraints
- Placement and dependencies: recording code belongs in `escher-driver`, which arch requires to name no app (the boot and the time step stay the caller's; the one edge runs `seven_guis → escher-driver`), to depend on exactly blitz-test-harness, dioxus-native-dom (`accessibility`), `tracing`, `serde_json` and `png` with no feature and no `[features]` table, to install no subscriber, read no env var and have no default state location. A new dependency, or `serde_json` used as a writer, would change a recorded decision (per architecture §Established Decisions → [Driver session]).
- Written forms: every form the driver writes is one line of JSON, written by hand in the crate-private `json` module, and no serialization crate writes one. `serde_json` reads MCP requests only. A recorded check's file form falls under that rule (per architecture §Standard Contracts → Driver session).
- One entry point: `Session::run` calls `validate` first, and arch requires that nothing public runs a `Command` that did not come from `validate`. A replay of a recorded check has to go through `Session::run`, or for a session verb through `validate_session`. The schema is `'static` data in one table, so a recording that shows up as a verb, an argument, a result field or a self-description key enters `VERBS` and with it `describe()` and the MCP `tools/list`. Arch records each such widening of the validated verb set as the founder's (per architecture §Standard Contracts → Driver session).
- Surfaces stay closed: the wire is `v2`, with three requests (`hello` · `stop` · `call`), a request line of at most 16,384 bytes and an answer of at most 1,048,576. The command line is a closed argv reader with a fixed rule order and four endings that write back nothing the caller typed. The `mcp` role reads `mcp` alone, with no `--session`, and its request line is bounded at 65,536 bytes. A recording switch, a new option or a new request changes one of these stated grammars (per architecture §Standard Contracts → Driver session).
- Filesystem: the state directory is required to be caller-named (never an env read or a cwd-relative default), created `0700`, refused `StateDirNotPrivate` when it is open to group or others, and to hold only the socket file `session.sock` while a session is up. At `stop` or expiry the socket file is removed, then the directory by a non-recursive remove. A kept check written there, or anywhere else, is a new path that §Occupied Resources has to register before it lands. Whether a file left in the state directory survives the remove or blocks it is a question for research (per architecture §Occupied Resources → Filesystem).
- No new resource silently: the registered env vars are `RUST_LOG`, `WPT_DIR`, `PAINT_TREE_BENCH_HTML` and `TMPDIR` (test-only), plus the CI script's own. The single served listener is the session socket, and the `mcp` role has no listener. A new env var, path argument, listener or carrier is a registration here first (per architecture §Occupied Resources → Environment variables; §Occupied Resources → Network ports and listeners).
- The CARRY's mandate: every engine time read goes through `DocumentConfig.clock`, and a sub-document's config carries its parent's clock. That covers the overlay fade, the double-click window, pan and the fling's generation, the smooth-scroll start, and the fling and smooth frames. Whether `iframe.rs`, pan and the fling already read it is a question for research. The scrolling replay's determinism depends on the answer (per architecture §Standard Contracts → Document core; §Established Decisions → [Scrolling and input]).

## Patterns to follow
- Fixed-text error table: `SessionError` is thirteen variants, each a row of `SESSION_ERRORS` holding a kind, a meaning and a remedy. Every message is a fixed string with no path, label, id or value in it. A new failure (for example, a kept check that cannot be written) follows that row shape (per architecture §Standard Contracts → Driver session).
- Bounded private record: the session keeps id text in a crate-private `SeenIds`, bounded at `MAX_SEEN_IDS`. It is behind one private field, has no public reader, and is never printed, logged or fielded. That is the model for any in-session buffer of crossed calls (per architecture §Standard Contracts → Driver session).
- Settled-step determinism: `advance` moves the harness's `VirtualClock` by exactly `ms`. Two `click`s on one point with no `advance` of at least 500 ms between them read as a double click, and the overlay fade reads the session clock, so a whole shot repeats byte for byte. A recorded check keeps the calls in order, `advance` steps included, to replay the same screens (per architecture §Standard Contracts → Driver session; §Standard Contracts → Test harness).
- Check-owned state directories: the session checks use short state directories under `CARGO_TARGET_TMPDIR` (`target/tmp/`), local only and uploaded by no CI leg, so the socket path fits its bound. New checks that keep a recording follow that placement (per architecture §Occupied Resources → Filesystem).

## Anti-patterns to avoid
- Writing a check's file with a serialization crate, or with `serde_json`'s writer (per architecture §Established Decisions → [Driver session]).
- Giving a kept check a default location: an env var, a cwd-relative path or a home-directory path (per architecture §Occupied Resources → Filesystem).
- Adding a span field, or logging or fielding any `Call`, `Command`, `ArgValue`, `Outcome`, id, text or screen content. The `command` span keeps its eight fixed-word and count fields and `tool_call` its two closed words. `Call` and `Outcome` print content under `Debug` and are never logged (per architecture §Standard Contracts → Driver session; §Cross-cutting Patterns → Logging and timing).

## Contract bindings
- arch §Occupied Resources → Filesystem ↔ security §Surfaces: a driver-written file that holds call content is a new at-rest carrier. Arch registers it, and security plus the founder decide on the widening.
- arch §Standard Contracts → Driver session (spans, "never fielded") ↔ obs: escher-telemetry's target allowlist and scrub (§Cross-cutting Patterns → Logging and timing) and the needle census on the `escher-session` host, the `mcp` role and the client's stderr.
- arch §Standard Contracts → Driver session (verb table, `Call` shape) ↔ tests: `tests/session_common/` call builders, `examples/seven_guis/tests/{cli_*,mcp_*,host_*}.rs`, and the cold-agent check form in `scripts/cold-agent.sh`, a JSON array of steps whose `tool` is one of the eleven verbs. The recorded form and that check form should be reconciled, not forked.
- arch §Standard Contracts → Test harness (the harness's `VirtualClock`) ↔ tests: a replay's determinism rests on every document built by the harness reading the harness's clock. That is the CARRY's check, in blitz-tests.

## Acceptance criteria contributions
- (arch) The recording code lives in `packages/escher-driver/`, and `escher-session` is only its caller. `escher-driver`'s dependency list and its one feature are unchanged, no app is named in it, and `serde_json` writes nothing (per architecture §Established Decisions → [Driver session]).
- (arch) Every path a kept check is written to has a §Occupied Resources entry with its owner-only mode and its removal rule before the wrap, and no env var, listener or default location is added (per architecture §Occupied Resources → Filesystem).
- (arch) A replayed step reaches the instance only through `Session::run` (`validate` first), or `validate_session` for a session verb. The `command` span keeps exactly its eight fields and `tool_call` exactly its two, and nothing of a recording is fielded (per architecture §Standard Contracts → Driver session).
- (arch) A blitz-tests check in both layout modes shows that a sub-document's carried clock, pan and the fling read the document's `DocumentConfig.clock` (per architecture §Standard Contracts → Document core).
