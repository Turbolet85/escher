It touches the cli surface (`escher-session`'s command line, host role and `mcp` role), and it relies on the stand's headless TaskShell mount for a replay on a fresh session. The tooling-context, expression-level and signature-placement slots of both surfaces read NOT YET MEASURED, so nothing is taken from them.

## Constraints
- layout-templates §Surface: cli → Primary screens (`escher-session`) requires every command to keep the shape `escher-session <verb> [arguments] --session <dir>` over the eleven verbs of the verb table. `--session` comes exactly once on every verb but `help`, and the instance verbs' flags are spelt as the schema spells them. A recording switch or argument has to fit that grammar. Whether recording appears as a verb, a flag or neither is P4's question.
- layout-templates §Surface: cli → Primary screens (`escher-session`) requires four fixed endings. Accepted is one uncoloured JSON line on stdout with exit 0. Refused is the refusal's JSON on stdout with exit 1. Usage is one fixed stderr line with stdout empty, exit 2, nothing booted and no state created. A session error is the error object with its `remedy` on stdout, its fixed message on stderr and exit 3. No ending writes back anything the caller typed. Recording must not add a line to any ending, and on a usage ending it must not create a file.
- layout-templates §Surface: cli → Primary screens (`escher-session`) requires the `mcp` role to be `mcp` alone, any other shape (`mcp --session d` included) being usage. Its stdout carries protocol lines only, uncoloured with no ESC byte, and its end writes nothing on stdout. So an MCP session's recording cannot be placed by `--session` without changing this grammar, and the role has no stdout channel for it.
- layout-templates §Surface: cli → Primary screens (`escher-session`) requires the host role (`serve <task> --session <dir>`, spawned by `start` with its three streams closed) to end with nothing written, exit 0 after a stop or its idle expiry, and exit 3 on a session error. Its stderr log lines carry `service.name=seven_guis` and nothing more. A recording kept by the host adds nothing to its streams.
- layout-templates §Surface: cli → Primary screens (`escher-session`) requires the usage line to be built from the verb table and the task names, and `help` to answer `describe()`'s seven-key line, every text a fixed string of the schema's tables. The MCP tool list must follow the verb table in order, `help` last. Any recording verb or argument therefore reaches all three through the table, never as hand-written text.
- layout-templates §Surface: desktop-native → Primary screens (seven_guis Home and TaskShell) requires a held instance to read as a fresh boot. Each consumer of the stand's boot (the host role, the `mcp` role) adds no markup, id, class, style, wrapper or order. The TaskShell mount (`main#main > #task-shell`) and the pinned 800 × 600, scale 1.0, Light viewport must hold after commands, in both layout modes. A recorded check replayed on a fresh session depends on this.
- layout-templates §Surface: desktop-native → Primary screens (seven_guis Home and TaskShell) defines the lean tasks' stable element ids (`counter-*`, `flight-*`, `timer-*`, `crud-*`, `crud-person-{id}`) as author `id`s. A CRUD row's id follows its person under filter, Create and Delete. A recorded step addresses its target by these ids.

## Patterns to follow
- layout-templates §Surface: cli → Primary screens (`scripts/cold-agent.sh`) gives the existing replayable-check layout. The agent's check is kept in a file (`target/cold-agent/check.json`) that is never printed, while every verb's stdout is JSON lines only. The kept artefact sits beside the output channel, never in it.
- layout-templates §Surface: cli → Primary screens (`scripts/agent-run.sh`) shows the same split: stdout is JSON lines, one object per event, and the raw output stays in a file under `target/agent-run/`. A recording would follow it: the artefact is a file, the answer stays on stdout.
- layout-templates §Surface: cli → Primary screens (`escher-session`) gives the closed shape for a new carrier. Text is written from fixed tables (`EXIT_STATUSES`, the verb table, `describe()`), and a result's form follows the existing written forms (`to_json`).

## Anti-patterns to avoid
- Writing anything the caller typed back on any ending of the command line or the `mcp` role, including a recorded step's text, an id or a path. This is banned by layout-templates §Surface: cli → Primary screens (`escher-session`).
- Adding colour, an ESC byte or a second line to an answer, a protocol line or the usage line in order to report recording. This is banned by layout-templates §Surface: cli → Primary screens (`escher-session`).
- Adding markup, an id, a class or a wrapper to the stand so that a recording or its replay can address something. This is banned by layout-templates §Surface: desktop-native → Primary screens (seven_guis Home and TaskShell).
