## Constraints
- **Test commands the implementation must pass** — one file: `cargo test -p blitz-tests --test {name}`; agent-driven: `bash scripts/agent-run.sh boot` then `run {name}` / `run stand`; the gate: `bash .github/scripts/ci-leg.sh fast` (and `doc`); a new crate's own unit tests run inside the workspace `test` leg under default features. The plan names the built-in `cargo test` harness, not nextest (per test-plan §3 Runners and invocation · §3 Agent-run contract `run {selection}` · §9 Pipeline facts, Legs and Local pre-push gate).
- **Where a proof check lives** — test-plan §2 Test directory + naming conventions and §5 Boundaries covered (tests/blitz-tests crate) require one test-target file per behaviour under `tests/blitz-tests/tests/`, as Cargo integration tests reaching their subjects through dev-dependencies only. Whether a new session crate can be a dev-dependency of `blitz-tests` without a cycle, and whether its `accessibility`-gated readers compile there, is research's question (per test-plan §1 Coverage scope, dioxus-native-dom — the snapshot, text and diff tests are recorded as compiled only under that feature).
- **The file's name decides its selection** — `run stand` takes every `stand_*.rs` by prefix with no script change, and a `{name}` selection must match the contract's name pattern; a `stand_`-prefixed session check joins the stand count the contract's Proof line re-reads at each chunk (per test-plan §3 Agent-run contract `run {selection}` · Proof). Whether session checks are stand checks by name is P4's call.
- **The instance under test is the pinned stand** — a session check boots through `seven_guis::stand::boot` / `boot_timer` with `stand::options(incremental)`, asserts unconditionally under the bundled font with no skip path, and advances the timer only through the `TimerTicks` stand-in, applied on the next pump (per test-plan §3 blitz-test-harness Construction · §2 Font-dependent tests · §7 Builders and options · §8 Time (seven_guis timer)).
- **What "a command's own work is done" rests on** — dispatch does not pump, the input helpers pump after dispatch, and recorded dispatch bypasses the Dioxus forwarding, so a held instance driven through it would not reach the app (per test-plan §3 Pump semantics · Input helpers · §5 Harness ↔ event pipeline). Whether the session drives the harness's input helpers or its own path is research's question.
- **Both layout modes** — a check that asserts layout, bounds or a snapshot runs in the incremental and the non-incremental document and holds the two equal (per test-plan §2 Differential oracle · §1 Coverage scope, tests/blitz-tests).
- **A process check must hold on every tested platform and must not hang** — the windows and macos matrix runs every test target, so a lifecycle check that spawns a process or opens a crossing passes there or carries a stated `cfg` gate; and a check that waits on another process is bounded, on the plan's recorded hang-guard precedent (per test-plan §1 Surfaces under test, Native platforms · §9 Fast/slow split · Hang guard).
- **No coverage or flakiness threshold binds this chunk** — the coverage leg runs with no threshold (per test-plan §9 Coverage); §10's gate block reads NOT YET MEASURED and contributes nothing.

## Patterns to follow
- **Shared stand tables and helpers, stated once** — a check that needs the stand's controls, rendered ids or the `boot` / `by_id` helpers declares `mod common;` and reads them; per-file data stays per-file (per test-plan §3 Crate-local test helpers, blitz-tests (stand checks)).
- **State and identity proven through real input** — the existing stand checks drive a step with the harness's input helpers and then read the snapshot, its diff and the stable ids; "a later command reads an earlier command's state" and "the same id names the same element after a command" follow that shape on one held instance (per test-plan §1 Coverage scope, tests/blitz-tests · §3 Input helpers · Inspection helpers).
- **A second process from inside a test** — the recorded precedent is a test binary re-executing its own `#[ignore]` child, and process-global behaviour of a binary proven by dedicated integration files; a session process's start, attach, stop and death-without-stop edges have that precedent and no other (per test-plan §1 Coverage scope, tests/blitz-tests and escher-telemetry · §3 Stand log format).
- **Unit tests beside the code** — a new crate's pure pieces (lifecycle state, edge outcomes) take inline `#[cfg(test)] mod tests`; an out-of-line module only where private access forces it (per test-plan §2 Test levels observed, Inline unit tests · §4 Conventions, Test file location).
- **Hand-written stand-ins, script contracts under a shim** — no mocking library is in the workspace; a fake is a small hand-written type, and a lifecycle surfaced through a script is contract-tested in a temp dir with a shim on PATH and a four-value exit grammar where usage is checked before a precondition (per test-plan §8 Hand-written fakes and stubs · §4 What unit tests cover, Agent-run contract and Cold-agent pipe · §3 Exit grammar, every verb).

## Anti-patterns to avoid
test-plan §11 reads NO RECORDED INTENT — nothing is extracted from it. The bans below are the ones the plan's contract sections state:
- **A pass without positive evidence** — an empty run is never a pass, and a verdict passes only on what was actually read; "`stop` leaves nothing" needs an observed absence (the process, the state it created), never the lack of an error (per test-plan §3 Agent-run contract `run {selection}` · §3 Cold-agent run pipe, Verdict).
- **A skip path or a real-time wait in a stand check** — stand checks have no runtime skip, and stand time moves only by delivered ticks (per test-plan §2 Font-dependent tests · §8 Time (seven_guis timer)).
- **A seam added to production code for the test's sake** — the recorded precedent is that no function under test gained a constructor, a `pub` or a `cfg(test)` shim, and that shared tables are stated expectation, never a second role or name mapping (per test-plan §3 Crate-local test helpers, dioxus-native-dom and blitz-tests (stand checks)).

## Contract bindings
- **tests ↔ arch / security** — test-plan §3 Agent-run contract, Invocation states the stand's premise as an in-process library boot with no daemon, PID file, status endpoint, port or socket, and §3 State confines harness state to `target/`. A session that is a process (and any crossing P4's fork opens) changes that premise: the §3 wording and a new session-lifecycle contract key are expected wrap amendments, alongside arch §Occupied Resources and the security plan. Whether the agent-run verbs need any change for the new checks is research's question.
- **tests ↔ obs** — a new session binary's log binds to test-plan §3 Stand log format (stderr only, the scrub applied — obs-plan §3), with the `telemetry_*` files as the proving pattern; agent-run events stay harness metadata, not a telemetry sink (per test-plan §3 Agent-run contract, Events).
- **tests ↔ a11y** — the snapshot, text and diff readers a session check uses exist only under `dioxus-native-dom`'s `accessibility` feature (per test-plan §1 Coverage scope, dioxus-native-dom); the a11y leg's file list is not extended by this chunk (per test-plan §9 Legs).
- **tests ↔ security (dependencies)** — a new workspace crate's dependencies fall under the `audit` leg in the same workflow (per test-plan §9 Legs).
- **tests ↔ CI invariants** — a new crate or binary adds no leg; if a leg is added it must appear in the leg script's list, which the workflow contract tests pin (per test-plan §4 What unit tests cover, CI workflows and leg script).
- **Not coverage** — the test-data bootstrap of the 5-command contract (§3) and the tier justification (§1) read NOT YET MEASURED; nothing is drawn from either.

- `bash .github/scripts/ci-leg.sh fast` passes, and its result-line and passed/failed/ignored counts are read from that run and differ from the last reading recorded in the plan only by this chunk's new targets and tests, with 0 failed (per test-plan §9 Local pre-push gate · Local baseline).
- The lifecycle checks — start, attach, stop, and each edge — observe after `stop` that no session process and no session state remain, are bounded so a regression cannot hang the run, and pass or are `cfg`-gated with the gate stated on the windows and macos legs (per test-plan §1 Surfaces under test, Native platforms · §9 Hang guard · §3 Agent-run contract, State).
