# a11y extract

## Relevance
partial — the chunk renders no markup and binds no key, but the held instance is a reader of the accessibility tree and of the focus state the a11y plan governs, and its crate's feature set decides whether that reading exists at all.

## Constraints
- A11y tier 0, target SC 2.1.1 · 1.4.3 · 2.4.3 (per a11y-plan §1 A11y Scope Summary): the session must leave focusability and focus order of the stand's controls as the stand builds them; it adds no a11y surface of its own.
- a11y-plan §1 (A11y scope, Dioxus crates) requires a crate to name the `accessibility` feature to get it — the workspace takes both Dioxus crates with default features off, and the plan records the stand binary as naming none. A new session crate that needs the snapshot, its text or its diff must name `dioxus-native-dom/accessibility` itself; whether the planned dependency path already carries the feature is research's question.
- a11y-plan §2 (Feature exposure) requires the `accessibility_tree` override, the snapshot model, its text form, its diff and the actionable-key check to exist only behind that feature — a session built without it has none of them, and no fallback reader is sanctioned.
- a11y-plan §7 (Accessibility tree output) requires every element node of a Dioxus document to carry its stable element id as AccessKit `author_id`, with no id on text-run, document-root or window nodes. "An id read in one command names the same element in the next" is a claim on that same id; the session must read it from the tree the document returns, never mint a session-local id.
- a11y-plan §7 (Accessibility tree output) requires the snapshot to be the only consumer between the tree and any later reader, with no second role or name mapping, and a password or file input's value to read the fixed mask. Whatever a session command reads of role, name, state or value must come from that model, and the mask must hold on a held instance exactly as on a fresh one.
- a11y-plan §2 (Accessibility tree lifecycle) requires the changed set to be drained by the shell's poll and marks the changed-set contract and the refresh on change PROVISIONAL pending the founder. A headless session has no shell poll: whether anything drains the set on a held instance, and whether an undrained set across commands distorts a later reading, is research's question; the chunk must not settle the provisional item by implication.
- a11y-plan §5 (Focus order per layout; Focus restoration) requires focus to move only through the engine's own paths (Tab, Shift+Tab, click, removal of the focused node resetting it). Focus is state a command leaves behind, so it must persist between commands on the held instance and be altered by nothing in the session's lifecycle steps themselves.

## Patterns to follow
- The assertion harness is Rust tests in blitz-tests over the AccessKit tree, the crate built with the `accessibility` feature (per a11y-plan §3 A11y testing tool pick; §1 A11y scope, blitz-tests) — the chunk's proof checks belong there, one file per behaviour.
- Focus is checked two ways at once: exactly the focused control's snapshot node reads `focused`, and it is the accessibility tree's focus (per a11y-plan §5 Test harness pattern; §7 Accessibility tree output) — reuse that pairing for the across-commands focus proof.
- Stand expectations for roles, input names and rendered ids are stated once in the stand checks' shared module (per a11y-plan §7 Accessibility tree output) — a session check reads those tables, never restates them.
- Stand a11y readings are proven in both layout modes (per a11y-plan §5 Test harness pattern; §7 Accessibility tree output).
- Focused and hovered node queries exist on the test harness (per a11y-plan §3 Focus management test harness) — the session's focus reading goes through them or through the snapshot, not a new query.

## Anti-patterns to avoid
- a11y-plan §11 (A11y Anti-Patterns) holds no recorded intent, so no ban is drawn from it; the two below follow from the plan's stated requirements.
- A second role, name or id mapping inside the session — a parallel reader of the DOM beside the accessibility tree and the snapshot (per a11y-plan §7 Accessibility tree output).
- A session command that exposes a password's typed text or a file input's path, bypassing the fixed mask (per a11y-plan §7 Accessibility tree output).
- Changing `tabindex`, `disabled`, roles or markup of the stand to make it easier to hold or attach to (per a11y-plan §5 Focus order per layout; §7 actionable-key rule, which keys elements by `id` alone with no focusability or Tab-order change).

## Contract bindings
- a11y ↔ architecture: the new crate's feature list (naming `dioxus-native-dom/accessibility`) is an a11y-surface decision recorded with the crate's registration (per a11y-plan §1 A11y scope, Dioxus crates; §2 Feature exposure).
- a11y ↔ tests: the session's proof checks sit in blitz-tests beside the stand checks and share their tables (per a11y-plan §3; §7). The CI a11y leg runs three named test files and adds no stand assertion (per a11y-plan §9 CI Integration) — the new checks run in the workspace test leg unless the plan chooses to widen the a11y leg, which is a CI-invariant edit.
- a11y ↔ security: the value mask is the a11y plan's reading rule and the security plan's exit rule at once; the scope keeps ids, names and values from crossing a process boundary at this chunk, and the mask must already hold on the in-process reading (per a11y-plan §7 Accessibility tree output).
- a11y ↔ architecture (provisional item): the changed-set contract and the platform-tree refresh are one founder-pending item (per a11y-plan §2 Accessibility tree lifecycle); a session that drains or relies on the set binds to it. The windowed witness of the refresh is owed on another route entry, not here.

## Acceptance criteria contributions
- On one held instance, a control's stable id read before a command equals the `author_id` of the same element's accessibility node after the command (per a11y-plan §7 Accessibility tree output).
- Focus set by one command is read by the next on the same instance: exactly that control's snapshot node reads `focused` and it is the accessibility tree's focus; nothing reads focused on a freshly started session (per a11y-plan §5 Test harness pattern).
- A held instance's forward Tab sequence, and each stand control's role and accessible name, equal those of a fresh boot of the same task — starting, attaching to and holding the session changes none of them (per a11y-plan §5 Focus order per layout; §7 Accessibility tree output).
- The session crate builds with `dioxus-native-dom/accessibility` named and `bash .github/scripts/ci-leg.sh a11y` still passes unchanged (per a11y-plan §1 A11y scope, Dioxus crates; §9 CI Integration).
