# arch extract

## Relevance
relevant — the chunk adds a workspace crate (and probably a binary), a long-lived process, a public session API and possibly the workspace's first inter-process crossing; each is an architecture registration or contract addition.

## Constraints
- **Every new resource is a registration, never a silent add.** architecture.md §Occupied Resources → "Network ports and listeners" reads none and §Inherited Defaults → "API style" restates no network listener; §Occupied Resources also keeps the registers a session can touch — "Names" (crates, binaries, features), "Process-wide state and threads" (spawned processes, global installs, threads), "Filesystem" (state areas and what removes them), "Environment variables". The session's crate name, binary name, any spawned or re-executed process, any state file and any env read each require an entry there, amended at wrap; an `attach` endpoint of any kind (socket, pipe, port, file rendezvous) is a new class of entry and is P4's fork, not this extract's lean.
- **Crate placement and manifest shape.** §Infrastructure Patterns → "Directory structure" requires the crate to sit in one of the listed trees and the tree to be re-rendered at wrap; §Conventions → "Manifests" requires dependencies declared once in `[workspace.dependencies]` and consumed `{ workspace = true }`, in-repo crates pinned `default-features = false`, package metadata inherited; §Inherited Defaults → "Publishability" records which crates are `publish = false` — a crate depending on blitz-test-harness or seven_guis inherits that standing. §Existing Scopes requires a row for the new unit.
- **The instance is the stand's, booted the stand's way.** §Standard Contracts → "Headless stand (seven_guis, native only)" is the contract for the boot path, the pinned viewport, the bundled font, the offline provider and the timer's tick handle; §Standard Contracts → "Test harness" is the contract for `Harness<DioxusDocument>`. The session consumes both and restates neither; a seam the boot does not give is an amendment to that contract bullet. The stand is native-only per the same bullet and §Existing Scopes → seven_guis, so the session crate's target gating must agree with it — whether the cross-platform matrix legs (§Infrastructure Patterns → "CI/CD") compile a new workspace member on windows, macos, ios, android and wasm is research's question.
- **Snapshot-side readers exist only behind a named feature.** §Cross-cutting Patterns → "Config management" and §Standard Contracts → "Dioxus DOM bridge" require a crate that takes either Dioxus crate at the workspace pin to name `accessibility` to get the accessibility-tree override, the snapshot, its text, its diff and the actionable check. Whether the session crate needs any of them at this chunk, and so whether it names the feature, is P4's decision; §Conventions → "Manifests" also records that the seven_guis path entry keeps its default renderer feature, so what a session crate links by depending on it is research's question.
- **One document, one thread, ids resolved per command.** §Cross-cutting Patterns → "Service wiring" records the document shared as `Rc<RefCell<…>>`; §Established Decisions → "[Style threading]" and §Occupied Resources → "Process-wide state and threads" record the multi-document hazards (the global style pool, the thread-local layout context, static id counters). §Established Decisions → "[Node identity]" and §Standard Contracts → "Scrolling, selection, tree" make a `NodeId` a versioned slot id whose stale indexing panics, and §Standard Contracts → "Dioxus DOM bridge" requires that no `NodeId`, `ElementId`, `ScopeId` or pointer enters a stable id. A held instance therefore carries element identity across commands as the stable id and re-resolves it each command; whether `Harness<DioxusDocument>` is `Send` is research's question.
- **Nothing provisional becomes load-bearing or gains an exit.** §Standard Contracts → "Dioxus DOM bridge" records the snapshot text and the diff leaving the process through the returned value only, with no driver, CLI or MCP command exposing them — PROVISIONAL; §Standard Contracts → "Document core" and §Cross-cutting Patterns → "Invalidation and state integrity" record the changed-set contract as PROVISIONAL, drained today by the windowed shell only. The session must keep those sentences true: no session command carries ids, names or values across a process boundary, and the session's lifecycle does not depend on the changed set. A long-lived headless holder that never drains the set is a new case those bullets do not cover — P4 states what the session does with it or leaves it explicitly to the Settle detection entry.
- **A binary installs escher's telemetry, and fails by type.** §Cross-cutting Patterns → "Logging and timing" requires an escher binary to install `escher_telemetry::init` with the caller's service identity at start, stderr only; §Standard Contracts → "Telemetry bootstrap" is that call's contract (a second install changes nothing, a foreign subscriber is a typed error, never a panic). §Cross-cutting Patterns → "Error handling" and §Conventions → "Error handling" require fallible APIs to return typed results — each lifecycle edge (start while up, attach when none, second stop, a dead process) is a named variant, not a panic or a string.

## Patterns to follow
- **The escher-owned crate precedent** — §Occupied Resources → "Names" registers escher-telemetry as a `publish = false` library, workspace member and `[workspace.dependencies]` path entry; the session crate follows that shape. The same entry records seven_guis depending on blitz-test-harness on the native target only — the standing precedent for a non-test crate consuming the harness.
- **The lifecycle-with-a-state-area precedent** — §Standard Contracts → "CI contracts" and §Occupied Resources → "Filesystem" describe the agent-run and cold-agent contracts: state under one `target/` area, recreated by the starting verb, removed by the ending verb with nothing else touched, local only. If the session keeps any on-disk state, it takes that shape; the exit-code grammar of those contracts belongs to the Driver CLI entry and is not pre-empted here.
- **The registered stdio-only crossing precedent** — §Occupied Resources → "Process-wide state and threads" and §Stack and Technologies → "CI/CD" register the cold-agent pipe's spawned client and its stub connected over stdio only, with what ends both and the founder's ratification date. A session crossing, if P4 opens one, is recorded with the same four facts: what is spawned, what connects them, what ends them, whose word ratified it.
- **The registered test re-execution precedent** — §Occupied Resources → "Process-wide state and threads" registers two blitz-tests binaries that re-execute their own test binary with a fixed argv, no socket or port. A proof check that needs a second process (attach, a process that died without `stop`) follows it and is registered the same way.
- **Checks and docs in the house form** — §Conventions → "Tests" (one behaviour per integration-test file, a `//!` header naming it, both layout modes where layout is asserted, shared stand tables read through `mod common;`) and §Conventions → "Documentation" / "Visibility and naming" (`//!` module docs, `///` on public items, internals `pub(crate)`), under the workspace-wide rustdoc gate of §Infrastructure Patterns → "CI/CD".

## Anti-patterns to avoid
- **A crossing or resource that appears without its entry** — a listener, socket, pipe, lock or pid file, env var, spawned process, background thread, crate or binary name landing in code with no §Occupied Resources amendment named in the plan (§Occupied Resources; §Inherited Defaults → "API style").
- **Process-local identity held or exported** — a `NodeId` kept across commands and indexed after a re-render, or any `NodeId` / `ElementId` / `ScopeId` / pointer offered to a caller as an element's name (§Established Decisions → "[Node identity]"; §Standard Contracts → "Dioxus DOM bridge").
- **A second way to do what a contract already does** — a stand boot path beside `seven_guis::stand`, a subscriber or stdout write beside `escher_telemetry::init`, or a serialized snapshot/diff form beside the one the bridge contract names (§Standard Contracts → "Headless stand", "Telemetry bootstrap", "Dioxus DOM bridge"; §Cross-cutting Patterns → "Logging and timing").

## Contract bindings
- **arch ↔ security** — §Occupied Resources ("Network ports and listeners", "Process-wide state and threads", "Filesystem") binds to the security plan's threat model and input validation the moment P4 opens a crossing: the endpoint, who reaches it, what is validated on it and what `stop` removes are one decision recorded in both masters; phase edits neither.
- **arch ↔ obs** — §Cross-cutting Patterns → "Logging and timing" and §Occupied Resources → "Process-wide state and threads" (which names the binaries that install the global subscriber) bind a new binary to the telemetry bootstrap and to the stderr-only rule; if the session speaks to its caller on stdout, stdout stays free of telemetry.
- **arch ↔ a11y** — §Cross-cutting Patterns → "Config management" binds the `accessibility` feature to every snapshot-side reader; the session renders no markup, so the binding is the feature name alone.
- **arch ↔ tests** — §Standard Contracts → "Test harness" and "Headless stand" bind the proof checks' fixture to the same instance type the session holds; §Inherited Defaults → "Publishability" binds the harness's test-only standing to P4's dependency decision; §Stack and Technologies → "Testing" lists blitz-tests' dev-dependencies and gains the session crate if the checks consume it.
- **arch ↔ route** — §Standard Contracts gains a session bullet at wrap, and the "no driver, CLI or MCP command exposes … yet" sentences in §Standard Contracts → "Dioxus DOM bridge" stay true after this chunk; the entries that end them are Driver CLI and MCP surface.

## Acceptance criteria contributions
- The plan names every resource the session lands — crate, binary, spawned process, thread, state path, env var, endpoint — as an expected wrap amendment to its register, and a search of the diff finds none unnamed (per architecture.md §Occupied Resources).
- The session crate is a workspace member with a `[workspace.dependencies]` path entry at `default-features = false`, inherits package metadata, declares no dependency outside `[workspace.dependencies]`, and passes the fmt, clippy, workspace-test, MSRV-build and workspace rustdoc legs `--locked` (per architecture.md §Conventions → "Manifests"; §Infrastructure Patterns → "CI/CD").
- The held instance is built through `seven_guis::stand`'s boot functions and options with no second boot path, and no session API or check names an element across commands by anything but its stable element id (per architecture.md §Standard Contracts → "Headless stand" and "Dioxus DOM bridge").
- Any session binary installs `escher_telemetry::init` before other work and writes no telemetry to stdout; every lifecycle edge returns a typed, named outcome and none panics (per architecture.md §Cross-cutting Patterns → "Logging and timing" and "Error handling"; §Standard Contracts → "Telemetry bootstrap").
