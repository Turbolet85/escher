# a11y extract

## Relevance
partial — the chunk is a log-sink rule and adds no UI surface, focusable element, key binding or painted colour, so no WCAG criterion of the tier is triggered; the a11y plan contributes boundary guards only (the ids and names the chunk searches the log for are the accessibility tree's output, and two of its surfaces — the seven_guis manifest and the windowed stand — carry a11y commitments it must not move).

## Constraints
- a11y-plan §1 (A11y tier) sets the target at SC 2.1.1 · 1.4.3 · 2.4.3; the chunk's scope keeps the stand's tasks, the engine call sites and every painted surface out, and it must stay that way — a change that reaches focusability, focus order or a painted colour is a11y surface and is not this chunk's.
- a11y-plan §1 (A11y scope — Dioxus crates) requires that the seven_guis stand binary and its `escher-session` host name no `accessibility` feature and build no accessibility code, and reserves the feature decision for the entry that first reads the snapshot through a session. The chunk's new check lives in the seven_guis package and spawns that host: it must not add the feature to that manifest to obtain names or ids. Whether the manifests at HEAD still read as the plan records is research's question.
- a11y-plan §2 (Accessibility tree lifecycle) holds the windowed witness of the refresh-on-change as still owed, on the working route's "Stand a11y assertions", and records the windowed stand binary as built without `accessibility`. The chunk's by-level run of `seven_guis_native` is a log reading only: it does not discharge that witness and must not be recorded as one.
- a11y-plan §7 (Accessibility tree output) requires every element node of a Dioxus document to carry its stable element id as `author_id` and the stand's interactive controls to carry a role and a non-empty accessible name. The drop is applied at the sink; it must not change what the tree, the snapshot, its text form or its diff carry — those values are the same before and after the chunk.
- a11y-plan §9 (CI Integration) requires the `a11y` leg to run its three named integration tests as their own leg. The chunk's corrected `telemetry_*` tests and its new host check are not a11y assertions and do not join, replace or rename anything in that leg.
- a11y-plan §3 (A11y testing tool pick) places accessibility assertions in blitz-tests over the AccessKit tree. The chunk's check reads a process's stderr, not the tree — it asserts an absence of a11y-tree content in a log and is not to be counted, cited or registered as an a11y assertion.

## Patterns to follow
- Needles from stated expectation: a11y-plan §7 (Accessibility tree output) keeps the stand's rendered ids, control roles and input names stated once, as tables of the stand checks' shared module, "never a second role or name mapping". A check that searches stderr for a stable id or an accessible name should take its needles from that stated expectation or from literals the report names — whether a seven_guis-package test can reach the blitz-tests shared module, or must state its own literals, is research's question.
- No snapshot read to find a name: a11y-plan §2 (Feature exposure) puts the snapshot model, its text form, its diff and the actionable-key check behind dioxus-native-dom's `accessibility` feature. The seven_guis package is recorded without it (§1), so the check finds names by literal, not by calling an accessibility-gated reader.
- Name source: a11y-plan §7 (Accessibility tree output) derives an accessible name from text runs, `aria-label` and a bound `<label>`. A fixture row's visible text and a labelled input's label text are therefore both "names" for this chunk's reading; the by-level evidence should say which kind each needle is.
- Leg placement: a11y-plan §9 (CI Integration) keeps the a11y tests in the slow tier as a leg of their own; the chunk's check runs in the workspace test leg with the other seven_guis package tests.

## Anti-patterns to avoid
- a11y-plan §11 (A11y Anti-Patterns) reads `NO RECORDED INTENT` — the plan records no ban list; the two items below are derived from the sections they cite.
- Deriving the check's needles through a second role or name mapping, or by re-implementing name computation in the test (against a11y-plan §7, Accessibility tree output).
- Turning on `accessibility` for seven_guis, or building the platform adapter into the host or the windowed stand, as a means to this chunk's check or measurement (against a11y-plan §1, A11y scope — Dioxus crates; and §2, Accessibility tree lifecycle).

## Contract bindings
- a11y ↔ obs / security (log content): the stable ids and accessible names the chunk keeps out of the log are the output a11y-plan §7 specifies; the rule about what a sink may print is the obs plan's and the security plan's, not this plan's. The a11y plan adds no log event, field or target.
- a11y ↔ obs (violation log schema): no coverage — the a11y-plan §3 paragraph that would bind an a11y violation schema to the sink's format is marked `NOT YET MEASURED`; nothing is extracted from it and the chunk defines none.
- a11y ↔ tests (CI): a11y-plan §9's leg binds to the test plan's CI section; the chunk leaves that leg's test list as it stands.
- a11y ↔ working route: the windowed witness owed under a11y-plan §2 stays carried on "Stand a11y assertions"; this chunk's windowed measurement is a separate reading.
- Keyed contract a11y-plan §3 → Bootstrap phases (labels `contrast-verification-harness-setup`, `a11y-ci-gate-wire`): the chunk turns on neither label; the key file was not read.
