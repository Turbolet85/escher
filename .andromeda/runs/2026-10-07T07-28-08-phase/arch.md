# arch extract

## Relevance
relevant — the chunk changes a Standard Contract (the telemetry bootstrap's scrub rule) inside one existing workspace crate, `packages/escher-telemetry`, and proves it through the two seven_guis binaries; it lands no new crate, listener, port, env var or binary.

## Constraints
- **Workspace placement.** The drop and its allowlist belong in `packages/escher-telemetry`, in the modules the plan names for it — `format` (the event formatter and the allowlist scrub) under the `init` entry point in `lib`; the `panic` module stays the chaining hook. No module boundary moves and no crate is added (per architecture §Existing Scopes → escher-telemetry; per architecture §Infrastructure Patterns → Directory structure).
- **The telemetry contract's kept clauses.** architecture §Standard Contracts → Telemetry bootstrap requires: `init(ServiceIdentity) -> Result<InitOutcome, InitError>` and `init_with_writer(ServiceIdentity, W: MakeWriter)`; a second call changing nothing; `InitError::ForeignSubscriber` as a typed error, never a panic; the one-line-per-event shape with the service identity on every line; a bridged `log` record printed under its `log.target`; engine-target records printing only `SAFE_FIELDS`; `CONTENT_FIELDS` redacted at any target. The drop is an addition beside these — it must judge a bridged record by the same resolved target the line shape already prints. Whether the code resolves that target before or after the point where the drop would sit is research's question (per architecture §Standard Contracts → Telemetry bootstrap).
- **The panic event must survive the drop.** architecture §Standard Contracts → Telemetry bootstrap requires an ERROR event at target `escher_telemetry::panic` with its four `panic.*` fields (payload redacted), followed by the previous hook; and architecture §Occupied Resources → Process-wide state and threads names the sink's own two log targets, `escher_telemetry` and `escher_telemetry::panic`. Neither is an engine prefix, so the allowlist has to admit both by name or by prefix. Whether any other escher target emits today is research's question (per architecture §Standard Contracts → Telemetry bootstrap; per architecture §Occupied Resources → Process-wide state and threads).
- **One env read, no new process-wide state.** architecture §Occupied Resources → Environment variables requires `RUST_LOG` to be the filter directives `init` reads, defaulting to `warn` when unset or unparsable — the drop adds no second env var and must not turn `RUST_LOG` into a way to re-admit a dropped target. architecture §Occupied Resources → Process-wide state and threads requires `init` to install one global subscriber, the `log` → `tracing` bridge and one chaining panic hook, to hold its identity in one static behind one init lock, and to spawn no thread — a drop mechanism that adds a static, a second global or a thread is a registration, not a silent add. Whether an `EnvFilter` directive naming a third-party target can out-rank a filter placed elsewhere in the stack at the pinned versions is research's question (per architecture §Occupied Resources → Environment variables; per architecture §Occupied Resources → Process-wide state and threads).
- **Pinned libraries and the enabled feature set.** architecture §Stack and Technologies → Parallelism and misc requires `tracing` "0.1.40", `tracing-subscriber` "0.3" and `tracing-log` "0.2" as the workspace's versions; architecture §Cross-cutting Patterns → Logging and timing names the `tracing-subscriber` features the sink is built on (env-filter · fmt · registry · std · tracing-log). A drop that needs a feature outside that set is a manifest change the plan must name, declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }` (per architecture §Stack and Technologies → Parallelism and misc; per architecture §Cross-cutting Patterns → Logging and timing; per architecture §Conventions → Manifests).
- **The crate stays ungated and feature-less.** architecture §Inherited Defaults → Optional capabilities requires tracing to be gated per call site in the engine crates and escher-telemetry to be ungated; architecture §Occupied Resources → Names requires escher-telemetry to be a `publish = false` library with no features. The drop is unconditional — no cargo feature turns it on or off, and no engine `tracing` feature or call site is touched to achieve it (per architecture §Inherited Defaults → Optional capabilities; per architecture §Occupied Resources → Names; per architecture §Conventions → Feature gating).
- **The fix does not migrate into the session library or the stand.** architecture §Established Decisions → Driver session requires the session library to carry no `tracing` dependency, span or event and to read no env var; architecture §Standard Contracts → Headless stand requires `seven_guis::stand` to install no telemetry and read no env var. The two install sites stay the binaries' own `main`s (per architecture §Established Decisions → Driver session; per architecture §Standard Contracts → Headless stand; per architecture §Cross-cutting Patterns → Logging and timing).

## Patterns to follow
- **The sink's composition.** architecture §Cross-cutting Patterns → Logging and timing requires one `Registry` with an `EnvFilter` and one non-ANSI fmt layer using the escher formatter, writing to stderr only, stamping the service identity, bridging `log`, applying the scrub and chaining the panic hook — installed first thing by `seven_guis_native` and by `escher-session`, each reporting an `Err` with `eprintln!` and continuing. The drop slots into that one composition; the two install sites need no edit. Whether a filter ahead of the formatter or a rule inside it fits that composition better is research's finding and the plan's statement.
- **The caller-given writer as the proof seam.** architecture §Standard Contracts → Telemetry bootstrap requires `init_with_writer(ServiceIdentity, W: MakeWriter)` beside `init` — the seam through which the rule is provable at the sink's own level (native `tracing` record and bridged `log` record alike) without a child process. Whether the existing sink tests already drive this seam, and under which targets, is research's question.
- **Spawning the built host binary.** architecture §Occupied Resources → Process-wide state and threads registers the child-process forms the tree already uses: seven_guis' `host_binary` test spawning the built `escher-session` through `CARGO_BIN_EXE_escher-session`, every parent wait bounded, a guard killing and reaping a host a failing check still holds, the state directory under `target/tmp/`; and `telemetry_stdout_silent` re-executing its own binary with `RUST_LOG` controlled on the child. The new check takes the first form and sets `RUST_LOG=trace` on the child; architecture §Occupied Resources → Filesystem requires the session's state directory to be a path the caller names.
- **Test shape.** architecture §Conventions → Tests requires unit tests in `#[cfg(test)] mod tests` at the end of the source file, each integration-test file covering one behaviour and opening with a `//!` doc naming it, and a test first asserting that its fixture produces the condition under test — which is the "seen red on the unfixed sink" obligation in this chunk's terms. architecture §Existing Scopes → seven_guis names `tests/host_binary.rs` as that crate's one integration-test target; a second file there is a new test target the wrap records.
- **Public surface is named.** architecture §Standard Contracts → Telemetry bootstrap names `ENGINE_TARGET_PREFIXES`, `SAFE_FIELDS` and `CONTENT_FIELDS` as the scrub's public sets, and architecture §Conventions → Visibility and naming requires crate internals to be `pub(crate)` / `pub(super)`. A list of escher's own targets is either internal or a named contract addition — the plan states which; a public item carries `///` and passes the rustdoc gate (per architecture §Conventions → Documentation; per architecture §Conventions → Formatting and lints).

## Anti-patterns to avoid
- **A silent resource add.** No new env var, listener, port, thread, crate, binary or cargo feature to carry the drop or its allowlist — architecture §Occupied Resources (Environment variables · Process-wide state and threads · Names) is a registry, and anything landed outside it is drift.
- **Anything on stdout, or an ungated print.** architecture §Cross-cutting Patterns → Logging and timing requires escher's sink to write to stderr only, and architecture §Standard Contracts → CLIs requires `escher-session` to write nothing on stdout on any path. The upstream `tracing_subscriber::fmt::init()` installs and the WPT runner's `env_logger` (stdout, unscrubbed) are the form not to copy and not to edit here (per architecture §Cross-cutting Patterns → Logging and timing).
- **Silencing the leak at its source instead of at the sink.** Editing or re-gating engine or third-party call sites, or dropping the `log` bridge, to stop the records — architecture §Conventions → Feature gating requires engine tracing to stay gated per call site as it is, and architecture §Standard Contracts → Telemetry bootstrap requires the bridge and the bridged-record line shape to stay.

## Contract bindings
- **arch §Standard Contracts → Telemetry bootstrap ↔ obs and security.** The scrub sentence in this contract is what the obs plan's scrubbing statements and the security plan's logging-redaction statements restate; the drop changes it, so the three move together at the wrap. Phase edits no master.
- **arch §Standard Contracts → CLIs (`escher-session`) ↔ tests.** The contract requires exit `0` after a stop, exit `1` with the error's message on stderr, exit `2` with a usage line on stderr, and nothing on stdout — the new check's "no id and no name on stderr at `trace`" has to hold beside those `eprintln!` lines, which are not sink records and are not subject to the drop.
- **arch §Occupied Resources → Process-wide state and threads ↔ tests.** Every test that spawns a child process is registered there with its argv, its env handling and its stream handling; a check that spawns `escher-session` with `RUST_LOG=trace` and drains its stderr while it runs is a new entry of that kind, amended at the wrap.
- **arch §Stack and Technologies → Testing ↔ tests.** The plan names blitz-tests' dev-dependencies (escher-telemetry, `tracing`, `tracing-log` among them), which is what the `telemetry_*` integration files emit through. Whether seven_guis' own dev-dependencies suffice for the new check without a manifest change is research's question.
- **Workspace crate names bind every domain.** `escher-telemetry`, `seven_guis` (binaries `seven_guis_native`, `escher-session`) and `blitz-tests` are the locked names all other extracts place their content in (per architecture §Occupied Resources → Names).
- **Sections of this plan the chunk restates at the wrap.** architecture §Standard Contracts → Telemetry bootstrap (the scrub clause), §Cross-cutting Patterns → Logging and timing (what the sink applies), §Existing Scopes → escher-telemetry (the `format` module's description), §Occupied Resources → Process-wide state and threads (the sink's own targets, the new child process) — re-derived from the built code, not forecast here.
