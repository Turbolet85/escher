## Constraints
- a11y-plan §1 A11y Scope Summary fixes the tier at `0 — SC 2.1.1 · 1.4.3 · 2.4.3`. Every re-assertion and every file added to the leg must witness one of those three criteria. SC 4.1.2 work stays out of the tier: an `aria-activedescendant` read, or a roving focus on the CRUD rows, is the unread gap that a11y-plan §5 Per-surface keyboard shortcuts pins with `accessibility_active_descendant_unread`. That file may join the leg as a pin of the gap. It must not be re-read as a closed requirement.
- a11y-plan §5 Test harness pattern requires `stand_keyboard` to walk each lean task's stated Tab order (`tab_order`, plus `ENABLED_TAB_ORDER` for the states enabled by keyboard alone) forward and back in both layout modes. At every step the engine's focus, the snapshot's `focused` node and the tree's focus must agree, and every stand control must lie in one of the two orders (detail: .andromeda/a11y-plan-detail/keyboard-navigation.md, keyboard-harness procedure, lines 96–98). When 0.2.0 has moved a sequence, the stated table is edited with the change named. A silent re-baseline is not allowed.
- a11y-plan §5 Focus order per layout defines what is focusable. `inert` on the element or an ancestor takes focusability away. `disabled` counts by its presence on a form control alone (`button` · `input` · `select` · `textarea`). The focus fixup is not built. The re-read reads the stand's Tab stops against this rule. The inert focus fixup stays a residual and is not absorbed, as the scope's boundary says.
- a11y-plan §5 Keyboard handling (engine and shell) is the mandate SC 2.1.1 is measured against. Enter dispatches a Click on a focused `button`, `summary`, `input` of type submit · reset · button, or `a[href]` that is no disabled form control. Released Space dispatches a Click on a `button`, `summary`, or `input` of type submit · reset · button · checkbox · radio. A focused single-choice `select` takes ArrowDown · ArrowUp · Home · End and typeahead. Whether any stand control is a `select` is research's question. a11y-plan §6 Color contrast detail (.andromeda/a11y-plan-detail/visual-design-verification.md line 15) records "the stand holds no select". The scope's flight-booker `select` candidate is marked [inferred], so P3 settles from the code whether a stand row is owed. The alternative is that the select witness stays fixture-side (`select_interaction` / `stand_act_select`).
- a11y-plan §6 Color contrast requires SC 1.4.3 on the stand through `Harness::text_contrast` and `contrast_ratio`: 4.5 for other text, 3.0 for large text. `stand_contrast` asserts three tables (the control rows, `TEXT_ROWS`, `STATE_ROWS`) in both layout modes. A row is exempt exactly where the snapshot's `enabled` reads `Some(false)`, and the rule allows no second formula, threshold or exempt class. Whether 0.2.0's engine changes moved any measured pair is research's question. Examples are the transformed client rect, the `contain: paint` hit stop and the ten cherry-picked upstream commits.
- a11y-plan §9 CI Integration defines the `a11y` job ("Accessibility (a11y) tests", `bash .github/scripts/ci-leg.sh a11y`). It runs the six named `--test` files today, sits in the slow tier behind the four fast jobs and takes no required status check. Widening the leg changes only its `--test` list and its pin. The job keeps its tier, and no new job, required check or repository setting is added (detail: .andromeda/a11y-plan-detail/ci-integration.md line 8).
- a11y-plan §3 A11y Assertion Harness Contract records where each candidate witness runs today. `accessibility_states`, `accessibility_label`, `accessibility_description`, `accessibility_merged_states`, `inert_subtree` and `accessibility_active_descendant_unread` run in the workspace test leg and outside the a11y leg's six files, and some of them also run in `stand-repeat`. ## Patterns to follow
- One shared reader and table per concern, stated once in the stand checks' shared module: `tab_order`, `ENABLED_TAB_ORDER`, `focused` in `tests/blitz-tests/tests/common/mod.rs`. A moved order is edited there and nowhere else, never as a second role or name mapping (per a11y-plan §7 Accessibility tree output; detail keyboard-navigation.md line 97).
- A keyboard row is reached by keyboard alone, as `enable_by_keyboard` does for `crud-update` / `crud-delete`. Each activation row asserts that the screen changed beyond focus (per a11y-plan §5 Keyboard handling (engine and shell); detail keyboard-navigation.md lines 38–39).
- Every check runs `for incremental in [false, true]`. Each stated table's row count is asserted along with its rows (per a11y-plan §3 A11y Assertion Harness Contract).
- The leg selection is a fixed `--test` list on one `cargo test --workspace --locked` line. Its words are pinned by `test_ci_workflows.py`'s `LegScriptTest` a11y tuple, and the leg log is read for per-file test counts, as `stand-repeat`'s ten named targets are (per a11y-plan §9 CI Integration).

## Anti-patterns to avoid
- Re-baselining `tab_order`, `ENABLED_TAB_ORDER` or a contrast row to whatever the code now reads, without naming the 0.2.0 change that moved it (per a11y-plan §5 Test harness pattern).
- Adding a second contrast formula, threshold or exempt class beside `text_contrast` / `required_ratio` / `enabled == Some(false)` (per a11y-plan §6 Color contrast).
- Giving the `a11y` job a required status check or a new job while widening its file list (per a11y-plan §9 CI Integration).

## Contract bindings
- a11y ↔ tests: the `a11y` leg's file list and its pin `LegScriptTest` a11y tuple (`.github/scripts/test_ci_workflows.py`) move together. The `stand-repeat` leg's ten named targets and `stand_requirement_sweep`'s leg check also read these files, so if a file moves into the a11y leg, research must check that `stand-repeat` membership is unchanged (per a11y-plan §9 CI Integration; test-plan §1 / §10).
- a11y ↔ design-system: the contrast rows read the stand's declared colour tokens (the accent `#3a5ce5` / hover `#2a4cd3` / active `#1f3fc1`). If a row moves, the record in design-system §Color Palette moves with it (per a11y-plan §6 Color contrast).
- a11y ↔ layouts: each lean task's Tab sequence is a per-surface focus order. If one moves, layout-templates' focus management for that surface moves with it (per a11y-plan §5 Test harness pattern).
- a11y ↔ driver lint: `Session::lint`'s `contrast` reading shares `stand_contrast`'s exempt rule. A changed contrast reading must agree with `stand_lint`'s zero findings at boot (per a11y-plan §6 Color contrast).
