@extract_section name=relevance
partial — a driver read over the snapshot and UI graph, which a11y-plan models from the accessibility tree; no new UI surface, role, key binding or colour
@extract_section name=constraints
- a11y-plan §7 Screen Reader Support (Accessibility tree output, the snapshot model) requires the snapshot to take role, name, focus and states from `accessibility_tree`, `enabled` from the `disabled` attribute and `clickable` from the vdom walk's current `click` listeners, and the read-only UI graph to hold one node per snapshot node; the actionable-node read must take its node set and its `disabled` reading from that model, never from a second role or name mapping.
- a11y-plan §7 Screen Reader Support (the graph reader, `DioxusDocument::graph`) requires each `GraphNode` to carry ids, its `owner` (an option's or optgroup's select), handler event names, closed flag words and booleans only, never a value; the per-node verbs and refusal causes the read adds must stay ids, verb names and closed cause words, no typed text or value (password `MASKED_VALUE` included).
- a11y-plan §7 Screen Reader Support (the actionable-key rule) requires every element an agent can act on (focusable, an interactive role or an event listener) to read an author key, `DioxusDocument::unkeyed_actionable` being the one check with no second role mapping; if the actionable-key check folds into this read, it must reuse that rule, not restate it.
- a11y-plan §5 Keyboard Navigation (Focus order per layout) requires focusability to follow the engine's rule (not inert, no disabled form control, `tabindex`/native focusable elements, `disabled` by presence); the read's "focusable" leg of the actionable set must read `Node::is_focussable()`, not a list of its own.
- a11y-plan §5 Keyboard Navigation (Focus restoration) states an option of a closed single select takes no click and a driver `click` on one is refused `covered`; the read must report that same cause for owner-served options, agreeing with the call.
- a11y-plan §6 Visual Design Verification (Visibility and hit-testing) requires nodes under `display: none`, `visibility: hidden` or `inert` to be out of the tree and so out of the snapshot, and a hit to pass through an inert element; such nodes must not be listed as actionable, and whether the shared refusal path already reflects this is research's question.
- a11y-plan §9 CI Integration requires the `a11y` leg's fourteen files unchanged unless a chunk states otherwise; a new read check runs in the workspace test leg (as `stand_graph` and `dioxus_runtime_probe` do) unless the plan is amended.
@extract_section name=patterns
- `stand_graph` asserts in both layout modes that every graph node is a snapshot node and that a graph read changes nothing and holds no typed text (per a11y-plan §7 Screen Reader Support); the same shape suits the actionable read's no-mutation, no-value assertions.
- `stand_act_select` and `select_interaction` already pin a driver `click` refused `covered` on a closed select's option (per a11y-plan §5 Keyboard Navigation, Focus restoration); usable as the owner-served refusal case.
- The driver refuses `click`/`type` as `disabled` where the snapshot's `enabled` reads `Some(false)`, nothing dispatched (per a11y-plan §7 Screen Reader Support); the read's `disabled` cause sits on the same reading.
- Stated tables with their row counts asserted, in both layout modes (per a11y-plan §3 A11y Assertion Harness Contract); a per-task table of expected actionable nodes and causes follows that form.
@extract_section name=anti_patterns
- No second role, name or focusability mapping beside the tree, snapshot and `unkeyed_actionable` (per a11y-plan §7 Screen Reader Support).
- No value or typed text in the read's answer, only ids, closed words and booleans (per a11y-plan §7 Screen Reader Support, the graph reader).
@extract_section name=bindings
- a11y ↔ driver/security: the read's answer and the `command` span carry closed words and ids only, per a11y-plan §7 Screen Reader Support's graph-reader rule beside doc:security-plan §Surfaces.
- a11y ↔ tests: a new stand check goes in the workspace test leg; joining the `a11y` leg or `stand-repeat` changes a11y-plan §9 CI Integration and test-plan §10.
@extract_section name=acceptance
- On every stand task, in both layout modes, each listed node is a snapshot/graph node and every `clickable` or focusable snapshot node is listed; no listed node is under `display: none`, `visibility: hidden` or `inert` (per a11y-plan §7 Screen Reader Support and §6 Visual Design Verification).
- A node whose snapshot `enabled` reads `Some(false)` lists cause `disabled`, and a closed single select's option lists `covered`, each matching the refusal an actual `click` returns (per a11y-plan §7 Screen Reader Support and §5 Keyboard Navigation).
- The read changes no snapshot, focus or tree, and its answer holds no typed or masked value (per a11y-plan §7 Screen Reader Support).
- If the actionable-key check folds in, its unkeyed set equals `DioxusDocument::unkeyed_actionable`'s, empty on every stand task (per a11y-plan §7 Screen Reader Support).
