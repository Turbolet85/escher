@extract_section name=constraints
- The read has to go through the driver session's single validated path. Architecture §Standard Contracts (Driver session) requires every call to run through `Session::run`, which validates first. Nothing public may run a `Command` that did not come from `validate`. The command and refusal schema is stated once as `'static` data: thirteen verbs in `VERBS` and eight closed causes, and no refusal holds anything a call supplied. A new verb or cause changes that count and that table, so it is the founder's contract fork.
- No `NodeId` may cross a boundary. Architecture §Established Decisions ([Driver session]) allows a session to carry only ids, names, closed flag words and booleans, and never a `NodeId`. The same section says a new carrier or exit widens the boundary. Answering this read on the socket `call`, the command line, MCP and a kept check is a boundary question for the founder.
- Answers are written by hand. Architecture §Standard Contracts (Driver session) requires every answer to be written in the crate-private `json` module. No serialization crate may write one: `serde_json` only reads MCP requests and kept checks. No command's ending may write back anything the caller typed.
- The node model comes from the UI graph and the snapshot, read-only. Architecture §Standard Contracts (Dioxus DOM bridge) requires `DioxusDocument::graph`, the snapshot and `element_id` to read the screen read-only, under `accessibility`, holding no `NodeId`. It reserves the fifth id form `{owner}///{key}`, spelled by `virtual_node_id`, which no walk writes. The snapshot's `clickable` reads an element's own current `click` listener and never a disabled form control.
- The `disabled` rules have one source each. Architecture §Standard Contracts (Nodes and widgets) requires `ElementData::is_disabled` to be the one disabled reading for a form control, and `option_disabled` the one rule for an option. Architecture §Established Decisions ([DOM semantics]) has focusability, the pointer and click gates, and Enter/Space activation all read that same one reading. A refusal cause in the list must come from these readers and must not re-derive them.
- What counts as visible and what counts as hit stay separate. Architecture §Standard Contracts (Scrolling, selection, tree) makes `visible_region` the read-only reader of what can be seen, and seeing is never read from a hit. A hit stops at the padding box of a box that paint clips, and an open select list answers first in `hit_with_scrollbar`. The off-screen and covered causes have to read these same readers.
- No engine change is expected. Architecture §Established Decisions (direct engine changes) records each engine change as a direct change for every document, with a merge surface owned by Upstream sync. The scope keeps the engine untouched, so any engine change that comes up is the founder's fork.
@extract_section name=patterns
- Read-only verb precedent: `graph` takes no argument (an argument is refused `malformed` and nothing runs) and answers `Outcome::Graphed`. Its node ids feed the session's record of ids, and it is written by hand as `{"nodes":[…],"states":[…]}` with `owner` left out when absent (per architecture §Standard Contracts, Driver session, the UI graph verb). A new read can follow the same shape: no argument, a dedicated `Outcome`, and optional keys left out.
- Schema shape types: each `VerbSpec { name, level, help, args, fields }` is built from `ArgSpec`/`FieldSpec` and found only by an exact-name `verb(name)` lookup (per architecture §Standard Contracts, Driver session). Reading per-node verbs from the table, with no closed list in code, means reading from these types. Whether today's `VerbSpec` already states each verb's target applicability is research's question.
- Self-description and the capability pin read everything from the tables (`VERBS`, `NODE_FIELDS`, `CAUSES`, …), and `tools/list` answers the verbs of `VERBS` in order (per architecture §Standard Contracts, Driver session). The capability-statement test reads verb names from `VERBS` and the verb count from `docs/capabilities.md` and `README.md` (per architecture §Project Intent, Front page).
- The stable-id tiers (author key, anchored path, component path, document path) and `unkeyed_actionable`, which lists, read-only, each actionable element whose stable id holds a `/` (per architecture §Standard Contracts, Dioxus DOM bridge). This is the existing reading the actionable-key fold-in would reuse.
@extract_section name=anti_patterns
- No closed list of verb names or causes in the new read's code. The verb and cause set lives once in the `'static` schema (per architecture §Standard Contracts, Driver session).
- No logging of the read's content. Nothing may log an id, a name or a value (per architecture §Standard Contracts, Driver session). No log or event may carry the snapshot or its text, beyond a diff's three counts (per architecture §Standard Contracts, Dioxus DOM bridge).
- No engine-side refusal logic duplicated in the driver. One disabled reading and one visibility reader stand in the engine (per architecture §Standard Contracts, Nodes and widgets, and §Standard Contracts, Scrolling, selection, tree).
@extract_section name=bindings
- arch ↔ security: the boundary rule (ids, closed words and booleans only, no `NodeId`) and the "a new carrier or exit widens the boundary" rule (architecture §Established Decisions, [Driver session]) bind to security's carrier review. The `command` span keeps `verb` and, when refused, `cause` alone.
- arch ↔ obs: the escher-driver spans are ungated and hand-built, with no `#[instrument]` (architecture §Conventions, Feature gating). No new span field may hold the read's content or size.
- arch ↔ tests: scenarios run in both layout modes, and tests first assert that the fixture produces the condition (architecture §Conventions, Tests). Stand checks share helpers through non-target modules under `tests/`. Recording and replay of a kept check go through `Session::run` (architecture §Standard Contracts, Driver session).
- arch ↔ docs: `docs/capabilities.md`, `README.md` and `.github/scripts/test_capability_statement.py` pin the verb count (architecture §Project Intent, Front page).
@extract_section name=acceptance
- The new read's code lives in `packages/escher-driver`, and the graph and snapshot readers in `packages/dioxus-native-dom`. No new crate, no new dependency outside `[workspace.dependencies]`, and no engine change (per architecture §Existing Scopes and §Conventions, Manifests).
- The read's written form holds no `NodeId`, no value and nothing the caller typed. It is written by hand in the `json` module, with optional keys left out when absent (per architecture §Standard Contracts, Driver session).
- If a verb is added, `VERBS`, `tools/list`, the usage line, `help`, `docs/capabilities.md` and the capability pin all agree on the new count, and that change is recorded as a founder-ratified contract and boundary fork (per architecture §Standard Contracts, Driver session, and §Established Decisions, [Driver session]).
- Each listed refusal cause is one of the existing closed causes. It is decided through the same path the executor uses, so on the stand, in both layout modes, it matches the refusal an actual call returns (per architecture §Standard Contracts, Driver session, and §Conventions, Tests).
