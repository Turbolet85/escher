@task_prose part=chunk
Builds one read-only driver read of the current screen's actionable nodes (capability v030-06): per node its stable id, its optional owner element, its verbs, and per verb accepted-now or the one refusal cause a real call would return.
The node model is the UI graph's GraphNode with an optional owner; nothing is keyed on a DOM NodeId; the verbs are read from the schema's verb table VERBS with no closed list of verb names in this code, which may need VerbSpec to say more (a contract change, the founder's fork).
The refusal reasons come from the same path the executor uses (action_point: disabled, off-screen, covered), so the read agrees with a call by construction; it runs no step, dispatches nothing and changes nothing, like snapshot, lint and graph.
The actionable-key check (residual L12) may fold in as each node saying whether its id is an author key or a positional path, if it fits (a P4 question).
Proven on the stand in both layout modes, with minimal fixtures for a covered, an off-screen and an owner-served target where the stand lacks one.

@task_item n=1 part=needs
The driver command schema: validate over the closed static verb table and bounded argument kinds, returning a typed Command or a Refusal; a new read, or a VerbSpec that says more, changes that table and must still pass every call through validate on the socket, the command line and MCP.
@task_item n=2 part=needs
The typed Refusal: its closed set of causes with fixed names, meanings and remedies and no String field; the read names, per verb, only a cause the call would return (disabled, covered, off-screen), so no new free-text reason may appear.
@task_item n=3 part=needs
The widening rule for the session socket and its carriers: a new field of a closed value set inside a ratified carrier is no widening, while a new carrier, a new exit, an open value set or authored text is; a new verb on every ratified carrier was a ratified widening for lint and graph, and this read's verb, carrier and answer shape are the founder's fork.
@task_item n=4 part=needs
What the session socket's and MCP's bounded replies may carry: ids, names, closed flag words and booleans, a UI graph's ids, component, state and handler event names; never an attribute's text and never a NodeId; the read's answer carries ids, verb names and cause words only.
@task_item n=5 part=needs
The stable element id: an author key when the HTML id is non-empty, slash-free and first, else an anchored, component or document path; the read reports these ids (and, with the L12 fold, which kind each is) and writes them to no log.
@task_item n=6 part=needs
The command span rule: one command span per call recording verb and, refused, cause alone, fixed words, bools and counts only; no field holds the read's content or its size, and the crate installs no subscriber and reads no env var.
@task_item n=7 part=needs
No unwrap, expect or panic on anything a call supplies, no clock read in the schema or validation, and no NodeId kept between calls, in the read's new code in escher-driver.
@task_item n=8 part=needs
Recorded checks: a kept check's bytes read only through the strict Check::from_bytes with closed keys and schema-named arguments; a recorded step of the new read must fit that reader and still pass validate on replay, and the recording directory and file modes stay as they are.
@task_item n=9 part=needs
The escher-session command line: the closed argv reader, validate before the session address is asked for, the four endings with fixed statuses, and no ending writing back anything the caller typed.
@task_item n=10 part=needs
The MCP server's listing and results: bounded results, typed tool arguments through validate, fixed protocol errors with no data; the new read's tool joins under those bounds.
@task_item n=11 part=needs
