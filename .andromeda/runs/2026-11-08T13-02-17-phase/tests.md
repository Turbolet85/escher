@extract_section name=constraints
- test-plan §3 Agent-run contract requires the new read's stand checks to run under `bash scripts/agent-run.sh run stand` (a new `tests/blitz-tests/tests/stand_*.rs` file is picked up by its prefix with no script change); an empty run is never a pass, and a check without the `stand_` prefix is reached only by `run all` or `run {name}`.
- test-plan §5 Session ↔ held instance requires a read-only verb to be driven through a held `escher_driver::Session` on every served screen in both layout modes and to change nothing (the precedent is `graph` in `stand_graph`), and requires a refused call to leave the instance unchanged and its text to hold none of the bytes the call supplied. Whether the new read can share the executor's refusal path is research's question.
- test-plan §2 Test Strategy requires command-line checks to run the package's own `escher-session` binary once per command and read stdout, stderr and exit status through the shared runner, `cfg(unix)`-gated; a check that holds a session over the socket is `cfg(unix)`-gated as well.
- test-plan §4 Capability statement requires `.github/scripts/test_capability_statement.py` to keep `docs/capabilities.md` pinned to the driver schema's tables (every verb and cause as a code span, the verb and cause counts in words, the README's tool count). A new verb or verb-table field moves these pins, and adding either is the founder's fork per the scope.
- test-plan §3 Stand log format requires each new verb to be a word of the closed `tool_call` `tool` set and the `command` `verb` set with no span field added. `host_log` and `mcp_log` must read 0 id, name and content needles on stderr at `RUST_LOG=trace` under both builds.
- test-plan §10 Coverage floors require the `coverage` leg to keep `packages/escher-driver` at 97 % or above and `packages/dioxus-native-dom` at 83 % or above; a `#[path]` test-child file counts toward neither reading.
- test-plan §10 Flakiness budget requires a zero-failure budget: `stand-repeat` runs the `stand_*.rs` files, the named blitz-tests targets and seven_guis' process checks three times with no retry.
@extract_section name=patterns
- `tests/blitz-tests/tests/session_common/mod.rs` builders and readers (`hold`, `act`, `refused`, `refused_unchanged`, `graphed`, call builders such as `graph()` and `lint()`): a new read would add a builder and reader in the same style (per test-plan §3 Crate-local test helpers, blitz-tests session checks).
- `tests/blitz-tests/tests/fixtures/mod.rs` holds shared pages booted through `fixtures::boot` / `fixtures::hold`, among them `covered` (`fx-under` under the `fx-cover` overlay). A page read by more than one check goes here, and a one-reader page stays in its check's file. This matters for the scope's covered, off-screen and owner-served minimal fixtures (per test-plan §7 Fixture sources).
- `tests/blitz-tests/tests/common/mod.rs` holds stated-expectation tables (`controls(task)`, `GRAPH_DRIVES` read by `stand_graph`). These tables are never a second role or name mapping (per test-plan §3 Crate-local test helpers, blitz-tests stand checks).
- escher-driver unit tests pin the verb schema, command validation, the executor's key table, the JSON forms, the command line, MCP, recording and replay. Refusal causes are pinned as a closed set in `refusal.rs`, and the executor's refusals are read by integration checks, not unit tests (per test-plan §4 What unit tests cover; test-plan §1 Test Scope Summary, escher-driver).
@extract_section name=anti_patterns
- No sleep and no wall-clock read in session checks, except where wall time is the subject (per test-plan §5 Wall time in the session checks).
- Headless-stand checks have no font skip path: they assert unconditionally under the bundled DejaVu Sans with system fonts off (per test-plan §2 Test Strategy, font-dependent tests).
- A check that reads a sink's capture counts lines by target, never in total, and a green per-package run is not the workspace leg's green (per test-plan §9 Engine features by runner).
@extract_section name=bindings
- tests ↔ obs: the `command` and `tool_call` span lines and their closed `verb` and `tool` word sets (test-plan §3 Stand log format ↔ obs-plan §3, §4, §6). A refused `command` line records `verb` and `cause` alone.
- tests ↔ security: the span rule that no field holds the read's content or size, checked by `host_log` and `mcp_log` needle counts (test-plan §5 Session host ↔ what it writes ↔ `doc:security-plan` §Surfaces).
- tests ↔ docs: `docs/capabilities.md` and README.md are pinned by the `ci-scripts` leg (test-plan §4 Capability statement).
