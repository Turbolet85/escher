## Patterns to follow
- The merge is checked through the gate script exactly as CI runs it: `bash .github/scripts/ci-leg.sh {leg}`, with `--locked` on every cargo leg, and the fmt → clippy → test → ci-scripts fast path as the local pre-push gate (per architecture.md §Infrastructure Patterns → CI/CD).
- Each dependency is declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }`, with in-repo crates declared `default-features = false` (except seven_guis's `hybrid` path entry) (per architecture.md §Conventions → Manifests). The taffy entry swap and blitz-tests' new `cursor-icon` dev-dependency take this shape, and `cursor-icon "1"` is already a workspace entry (per architecture.md §Stack and Technologies, Windowing and input row).
- Incremental and non-incremental layout run one pipeline and must produce identical layouts after any sequence of mutations (per architecture.md §Design Philosophy → One incremental pipeline, safe identities). Upstream's #1174 anonymous-restyle change is read against that oracle in both modes.
- The changed set is not written by hover, layout or a resource load, and stale slab ids are tolerated by `get` and `contains_key` (per architecture.md §Cross-cutting Patterns → Invalidation and state integrity). Upstream's #1176 (hover end) and #1185 (dropped nodes) are read against both rules.

## Anti-patterns to avoid
- Never resolve a pin that fails to resolve as a set with a one-sided bump or fix (per architecture.md §Established Decisions → [Dependency pinning]).
- Add no listener, port, env var or workspace crate without an Occupied Resources registration (per architecture.md §Occupied Resources). Whether upstream's delta adds a bind site, a workspace member or an env read is research's question.
- Never reach through `DocumentMutator::doc` when resolving the `mutator.rs` / `document.rs` merges; extend the mutator instead (per architecture.md §Conventions → DOM API patterns).
