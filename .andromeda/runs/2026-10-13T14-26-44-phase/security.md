# security extract

## Relevance
partial — no new surface of ours, but the merge moves the dependency graph and the lock, and touches four engine paths the security plan names: the falsy-boolean mutation path, attribute reads by name, the password paint, and the CI workflows' secret guards.

## Constraints
- The sync takes upstream's dependency set whole, with no `cargo update`. Each package that enters `Cargo.lock` is reviewed by hand for licence, repository, build script, proc-macro flag and direct dependent, the way the 2026-10-10 sync's lock review did it (per security-plan §Dependency Security, Pinning). Taffy leaving its git `rev` for the registry's `0.15` changes the plan's "one git dependency pinned by commit rev" reading. That wording moves at the wrap. The phase does not amend it.
- An advisory the audit leg fires on the merged lock is fixed by a semver-compatible update or ignored by ID with a written reason. `unmaintained` and `unsound` stay at their defaults. The standing RUSTSEC-2026-0192 ignore is re-read as a bounded deferral. Whether the merged graph still reaches ttf-parser 0.25.1 only through the winit chain is research's question. The audit sees only cargo-deny's resolved graph, so a crate in a pruned optional chain is reviewed by hand (per security-plan §Dependency Security, Audit tool).
- Builds stay `--locked` in every ci.yml cargo leg, and `Cargo.lock` stays committed. Whether the merged lock resolves under `--locked` is the first reading (per security-plan §Dependency Security, Supply chain integrity → Lockfile verification).
- De-forking `BOOLEAN_ATTRIBUTES` onto upstream's `is_bool_attr` must keep the required behaviour: a falsy value (`None`, Text `"false"`, Bool false, Int 0, Float 0.0) of each of the 27 listed names clears the attribute, on both the dynamic and the static template path. A truthy value, and an unlisted attribute holding `false`, are still written. The path must stay in-process, with no new input class. Whether upstream's predicate covers all 27 names and both paths is research's question (per security-plan §Input Validation, row "Dioxus mutations | Boolean attributes with a falsy value").
- The accessibility builder's reads of `aria-selected` · `aria-pressed` · `aria-invalid` must keep their required shape: a trimmed, lower-case, exact match against a closed set, written out as closed enums or booleans, never as the attribute's text, with no log site and no panic path. #1186 gives Dioxus attributes the empty namespace. Whether that changes how these names, or the HTML `id` that `element_id` reads as an author key, are found by name is research's question (per security-plan §Input Validation, row "Markup attributes | `aria-selected` · `aria-pressed` · `aria-invalid`").
- In every document, blitz-paint must paint a `password` input masked through `draw_masked_input_text` in `render.rs`. Merging upstream's object-fit hunks (#1194, #1195) must leave the password branch, `caret_color` and the masked path whole. Whether any upstream hunk meets them is research's question (per security-plan §Input Validation, row "Markup attributes | password and file `input` value").
- The jobs that reach secrets (publish, WPT, post-results) keep their `github.repository == 'DioxusLabs/blitz'` guard, and ci.yml keeps its workflow-level `permissions: contents: read` with no job-level grant. Whether the delta's CI changes (`wpt_area_changes.py`, `wpt/WPT_COMMIT`) touch any workflow file or guard is research's question (per security-plan §Authentication & Authorization, RBAC / permissions (CI tokens) rows).

## Patterns to follow
- Lock review evidence follows the 2026-10-10 sync's shape (`escher-0.1.0/chunks/2026-10-10-upstream-sync-agent-surfaces/evidence/lock.md`): each name that enters or leaves the lock, its source and checksum, the hand review, and the audit verdict with any ignore added or dropped (per security-plan §Dependency Security, Pinning).
- The `[licenses]` table is a one-off reading that no CI leg runs. The last sync recorded one `cargo deny --locked check licenses` reading, and whether the fork gates on it stays with the route entry "Quality gates". If upstream's delta brings a licences job back, it is not adopted silently (per security-plan §Dependency Security, Supply chain integrity → Licence compliance).
- No served network API exists, and the one listener is the session socket. The delta's bind and listen sites, workspace members and env reads are read before the merge is called surface-neutral (per security-plan §API Security). The env reads of source, upstream's five new test files included, stay limited to the non-secret set (per security-plan §Secret Management, Environment values read).
- Engine crates log through `tracing` behind their `tracing` feature. escher's sink admits engine targets with only the safe fields and drops every record from any other target, so an upstream log site that follows the gate needs no change of ours (per security-plan §Logging & Monitoring).

## Anti-patterns to avoid
- A blanket advisory allow, an ignore with no ID and written reason, or `unmaintained` / `unsound` set to none (per security-plan §Dependency Security, Audit tool).
- Fixing an advisory with a lone bump of one side of a coupled pin. The standing ttf-parser ignore exists because the winit pin cannot be bumped alone (per security-plan §Dependency Security, Audit tool).
- Writing an aria attribute's text, or a password's typed value, anywhere during conflict resolution or a gate fix: in a node, a log or a test assertion (per security-plan §Input Validation, password row).

## Contract bindings
- Dependency audit ↔ tests CI: the `audit` job (`bash .github/scripts/ci-leg.sh audit`) is the security gate on the pushed merge (per security-plan §Dependency Security, CI integration).
- Password mask ↔ a11y and tests: `password_painted_masked`, `stand_act_screenshot` and `stand_mcp_masked` are the standing checks of the mask (per security-plan §Input Validation, password row).
- Control-state reads ↔ a11y and tests: `accessibility_states` holds the closed-set reads, and the a11y plan carries the same accessibility-tree surface (per security-plan §Input Validation, aria row).
- Log redaction ↔ obs: the sink's allowlist and its scrub sets bind to the obs plan's pipeline (per security-plan §Logging & Monitoring).

## Acceptance criteria contributions
- `bash .github/scripts/ci-leg.sh audit` reads `advisories ok` on the merged lock. Any ignore added or dropped carries its ID and written reason, and every package that enters the lock is reviewed by hand and recorded in the chunk's evidence (per security-plan §Dependency Security).
- Every ci.yml cargo leg runs `--locked` and passes on the merged `Cargo.lock`, with no lock edit beyond the merge's own (per security-plan §Dependency Security, Supply chain integrity).
- After the `BOOLEAN_ATTRIBUTES` de-fork, `dioxus_falsy_boolean_attrs` and `dioxus_falsy_disabled` pass in both layout modes. Each of the 27 names, or a named survivor of ours, still clears on a falsy value on both the dynamic and the static template path (per security-plan §Input Validation, Dioxus mutations row).
- `password_painted_masked` (two equal-length values paint byte-identical frames), `stand_act_screenshot` and `stand_mcp_masked` (the typed text appears 0 times in any shot or result) pass in both layout modes on the merged tree (per security-plan §Input Validation, password row).
