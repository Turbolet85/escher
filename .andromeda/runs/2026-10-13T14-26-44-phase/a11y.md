## Constraints
- The a11y tier is `0 — SC 2.1.1 · 1.4.3 · 2.4.3` (per a11y-plan §1 A11y Scope Summary). The same section records, re-read at every earlier sync, that the stand graph holds neither `accesskit_xplat` nor `accesskit_winit` (`cargo tree --locked -p seven_guis -e normal`, 0 rows) and which accesskit family versions the lock pins. The merged lock must be re-read the same way. Whether upstream's `Cargo.lock` delta moves the accesskit family is research's question.
- The accessibility tree refresh on change requires that `View::poll` in `blitz-shell/src/window.rs` drains the changed set and, under `accessibility`, rebuilds the platform tree through `Document::accessibility_tree`, so that DioxusDocument's override reaches it. The changed set must stay unmarked by hover (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle). Upstream's #1176 (hover end) edits `window.rs` and the pointer path. Whether that edit marks the changed set, or moves the refresh, is research's question.
- The builder reads `aria-selected` · `aria-pressed` · `aria-invalid` by name, as a closed set over the trimmed lower-case value, and writes `selected` · `toggled` · `invalid` on the node. `aria-pressed="false"` and `aria-selected="false"` are readings in their own right, not absences (per a11y-plan §2 A11y Strategy, Role derivation). Upstream's #1186 puts Dioxus attributes in the empty namespace. Whether the builder's name lookup and the element-id key read still match after that change is research's question.
- A falsy Dioxus value of one of the 27 boolean attributes must remove the attribute on both the dynamic and the static template path. A truthy value must still be written. An attribute outside the list that holds `false` (`aria-hidden`, a `data-` attribute) must still be written as `"false"` (per a11y-plan §5 Keyboard Navigation, Script and framework exposure). The scope's conflict resolution (upstream's `is_bool_attr` in place of our `BOOLEAN_ATTRIBUTES`) must keep all three properties. Research must answer whether upstream's predicate holds every listed name, covers both paths and leaves `aria-*` out.
- Focus behaviour must hold after the merge. Focusability follows `tabindex` / `href` / `disabled`, and disabled-ness is keyed on presence for state and on the parsed value for focusability. Removing the focused node resets focus to the body and runs its blur side effects. A checkbox or radio click toggles the control and focuses it (per a11y-plan §5 Keyboard Navigation, Focus order and Focus restoration). Upstream's #1185 (removed nodes dropped) and #1187 (checked cleared when the attribute is removed) land on these paths. Whether they change focus reset or the snapshot's `checked` reading is research's question.
- A focused password input must paint its caret at its bullet in the input's caret colour and its bullets in the input's text colour. The UA stylesheet's 2px `#4D90FE` input focus outline is recorded as the engine's focus ring (per a11y-plan §6 Visual Design Verification, Focus ring). Upstream's #1194/#1195 edit `render.rs`, and #1175/#1189 touch UA stylesheet handling. Whether any hunk meets the password caret path or the focus-outline rules is research's question.
- Every element node in a Dioxus document must carry its stable id as AccessKit `author_id` through the `accessibility_tree` override in `dioxus_document.rs`. The stand's 15 interactive controls must keep an HTML-AAM role and a non-empty name. The snapshot, its text, its diff, the MCP result and the screenshot must stay readers of the tree's role and name with no second mapping (per a11y-plan §7 Screen Reader Support, Accessibility tree output). Upstream edits `dioxus_document.rs` by +318 −6. Whether that edit meets the override's hunks is research's question.

## Patterns to follow
- A11y assertions are Rust tests over the built AccessKit tree, matched on `role()` / `is_hidden()`, and the `assert_role` helper maps `NodeId` to AccessKit `NodeId(as_u64())` (per a11y-plan §3 A11y Assertion Harness Contract). Upstream's five new test files that touch focus or checked state (`checked_attribute.rs`, `pointer_leave.rs`) run as their own targets beside these and are not folded into the a11y leg.
- The stand's key-press focus check takes Tab / Shift+Tab through the harness's `press` / `press_with`, in both layout modes, asserting that exactly the focused control reads `focused` and is the tree's focus (per a11y-plan §5 Keyboard Navigation, Test harness pattern). It is the standing proof of SC 2.1.1 / 2.4.3 to re-run, not to rewrite.
- Expected roles and input names are stated once in `controls` / `INPUT_NAMES` of the stand checks' shared module, as stated expectation and never as a second mapping (per a11y-plan §7 Screen Reader Support).
- A measured a11y fact is re-read at each sync and recorded "as measured at {chunk report}", as §1 does for the stand's adapter-free graph and the accesskit versions (per a11y-plan §1 A11y Scope Summary).

## Anti-patterns to avoid
- Never widen falsy-value removal to an attribute outside the boolean list. Writing `aria-hidden` / `aria-pressed` / `aria-selected` `"false"` as an absence flips a stated reading into none (per a11y-plan §5 Keyboard Navigation, Script and framework exposure; per a11y-plan §2 A11y Strategy, Role derivation).
- Never introduce a second role or name mapping while reconciling the merged `dioxus_document.rs` or `mutation_writer.rs`. Every consumer reads the tree `accessibility_tree` returns (per a11y-plan §7 Screen Reader Support).
- Never let a platform adapter (`accesskit_xplat`, `accesskit_winit`) enter the stand graph silently through the merged lock (per a11y-plan §1 A11y Scope Summary).
