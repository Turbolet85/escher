# tests extract

## Relevance
relevant — a sync chunk whose proof is the test suite. It merges upstream's five new blitz-tests files under the fork's one-target-per-file manifest and re-proves every escher check under both builds and in CI.

## Constraints
- `tests/blitz-tests` keeps one auto-discovered test target per `.rs` file directly under `tests/`. `[package]` sets no `autotests`, and upstream's single-binary `all` stays the manifest's one `[[test]]` table at `test = false` (per test-plan §2 Directory pattern). Upstream's five new files must therefore each build and run as a crate root of their own. Whether each one compiles outside `all.rs` (a `super::`/`crate::` path, or a helper only `all.rs` declares) is research's question.
- The manifest's two-line difference from upstream is pinned by `BlitzTestsTargetsTest`. It asserts no `autotests = false` and exactly one `[[test]]` table, `all` at `tests/all.rs` with `test = false` (per test-plan §4 blitz-tests targets). The merged manifest, which gains upstream's `cursor-icon` dev-dependency, must keep it green in the `ci-scripts` leg.
- The two runners build the same check against different engine features. The workspace build resolves blitz-dom with 16 features and `writing-mode` on. The per-package build resolves 10, with a different body of `physical_unrounded_geometry`. So the stand checks, which read `bounds` and `visible_region`, must pass under both, and a green per-package run is not the workspace leg's green (per test-plan §9 Engine features by runner). Taffy 0.15 and #1175 can move layout numbers under either body.
- Incremental and non-incremental runs must agree. The differential oracle compares every node's `final_layout()`, `layout_children` and paint tree after each step and asserts no damage remains (per test-plan §2 Differential oracle). Upstream's #1174 edits incremental damage propagation, so this is the check that reads it.
- The headless-stand checks assert unconditionally under the bundled DejaVu Sans with system fonts off, with no skip path. A shot of a document with no `sans-serif` family is refused, never skipped (per test-plan §2 Font-dependent tests). Upstream's #1189 shares parsed UA stylesheets across documents. Whether that touches the stand's fresh-per-boot font and style state is research's question.
- Every cargo leg runs `--locked`. The twelve linux jobs include `msrv` (`cargo +1.91 build`, build only), `doc`, `audit` (cargo-deny advisories) and `a11y` (three files) (per test-plan §9 Legs; MSRV per test-plan §2 MSRV). CI runs on `build/**` pushes (per test-plan §9 Platform).
- `agent-run.sh run stand` selects only `stand_*.rs` files, and `run all` runs the whole package. An empty run is never a pass (per test-plan §3 `run {selection}`). Upstream's five files carry no `stand_` prefix, so only `run all`, the workspace `test` leg or a per-file run reaches them.

## Patterns to follow
- Re-count by name and number after the merge, as the 2026-10-10 sync did. The plan reads its baseline as 113 `.rs` files, 112 test targets and the unbuilt `all.rs`, with 0 `Running tests/all.rs` lines and no `all` executable at each run. Each new file is recorded as "its own auto-discovered target with no manifest line" (per test-plan §2 Directory pattern). The baseline's current truth at HEAD is research's reading.
- Whole frames are compared exactly. A shot's PNG must equal the harness raster, and `stand_screenshot_repeat`'s 12 shots must be byte-identical across processes in both layout modes and under both builds (per test-plan §2 Pixel tests). If a merge moves a pixel or a bound, re-measure it and record it in the evidence. Never widen the tolerance to make it pass.
- Run the local gate first: `bash .github/scripts/ci-leg.sh fast` runs fmt → clippy → test → ci-scripts and stops at the first red (per test-plan §9 Local pre-push gate). Logs land in `target/ci-logs/{leg}.log` (per test-plan §9 Failure logs).
- Record the merge's own CI run the way the last sync did. That run, CI#38013740580 on `9462a7e4`, read 16 of 16 jobs green at its first attempt, with a 1100 s cold wall against 641 s before it (per test-plan §9 Cache). Expect a cold cache after a lockfile change: the cache is re-keyed and saved on `build/*` (per test-plan §9 Cache).
- Upstream's new files are ordinary integration tests in `tests/blitz-tests/tests/` that depend only on dev-dependencies (per test-plan §5 tests/blitz-tests crate). Any fixture they need follows the inline-HTML seed strategy (per test-plan §7 Seed strategies). Each file's edit to compile alone is the smallest one possible, named non-additive per the scope.

## Anti-patterns to avoid
- Do not read a green `cargo test -p blitz-tests` (the agent-run and per-file runner) as the workspace leg's green, or the reverse. A check that reads a sink's capture counts lines by target, never in total (per test-plan §9 Engine features by runner).
- Do not count an empty or partial run as proof. `run stand` with no stand files, or a run where no test line parsed, is `failed` (per test-plan §3 `run {selection}`). Upstream's non-`stand_` files are proven only by a selection that actually names them.
- Do not add a runtime skip path to a stand check to absorb a moved reading. The stand checks have none by design (per test-plan §2 Font-dependent tests).

## Contract bindings
- tests ↔ obs: the stand log format, stderr only with no ANSI and two record classes (per test-plan §3 Stand log format). It is read by seven_guis' `host_log` and `mcp_log` with 0 id, name, typed-sentinel and shot-prefix needles under both builds (per test-plan §1 apps). The merged engine's log sites must keep them green, and the shape binds to obs-plan §3.
- tests ↔ obs: agent-run's JSON-line events and `status.json` (per test-plan §3 Agent-run contract). The selection grammar is unchanged; it binds to obs-plan §3 status and logs.
- tests ↔ security: the `audit` leg (cargo-deny advisories) sits in the same workflow as the test legs (per test-plan §9 Legs). Any crate the merged `Cargo.lock` adds goes through it, binding to security §Dependencies.
- tests ↔ a11y: the `a11y` leg runs `accessibility_hidden`, `accessibility_roles` and `focusability_updates`, while `accessibility_states` runs in the workspace `test` leg only (per test-plan §9 Legs; test-plan §1 tests/blitz-tests). These re-prove focus order and a11y-tree identity after #1176, #1186 and #1187, binding to a11y-plan §3.
- tests ↔ session lifecycle: the session process checks bound every wait and kill-and-reap their host (per test-plan §3 Session lifecycle `session-checks`). Their proof list (per test-plan §3 Session lifecycle `session-proof`) is what "every escher proof still passes" re-reads.
