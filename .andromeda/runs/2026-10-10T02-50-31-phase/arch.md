# arch extract

## Relevance
relevant — the chunk adds the driver's first out-of-process surface, and the plan locks the session wire, the one listener, the one schema, the crate's dependency set and every binary's stdout/stderr split; several of those locks are what the chunk's decision 1 asks to change.

## Constraints
- **The wire is locked to lifecycle messages.** architecture §Established Decisions → [Driver session] records, as the founder's choice, a `std`-only Unix-domain socket carrying lifecycle messages only with nothing of the screen on it, and bans a third-party IPC, named-pipe, pid-file or daemonizing crate and any TCP or UDP port. Carrying a `Call` in or an `Outcome` out of the host process reverses that record: it needs the founder's ruling first (scope decision 1) and is a wrap amendment of this decision, never a silent grammar growth.
- **The `v1` line protocol cannot hold a call or a screen as stated.** architecture §Standard Contracts → Driver session states the wire as crate-private, versioned `v1`, one request line and one reply line per connection with fixed byte bounds, the host answering one connection at a time on the calling thread under a read and a write bound, and lists a verb on the socket and CLI JSON under "Not built". The same contract bounds an `Id` and a `Text` argument far above the request line's bound, so any form that crosses on this socket is a wire-contract change (version, bounds, grammar) the plan must state whole; whether the code's wire can be extended without a second listener site is research's question.
- **One listener, one bind site, a caller-named private state directory.** architecture §Occupied Resources → Network ports and listeners requires the tree's one listener to stay the session socket, mode `0600` in a `0700` state directory, unix only (`Unsupported` elsewhere in 0.1.0). A second listener, a port, or a second bind site is a registration there before it is code.
- **How a session is addressed may not introduce an unregistered resource.** architecture §Occupied Resources → Filesystem requires the state directory to be a path its caller names — argv, never an env read or a cwd-relative default — refused as `StateDirNotPrivate` when group- or other-open, holding the socket file alone and removed non-recursively at `stop`. A default state location, a session registry file, or an env var naming one (scope decisions 2 and 5) is a new row there and in architecture §Occupied Resources → Environment variables, whose list of env reads the plan treats as closed.
- **One schema, one entry point.** architecture §Standard Contracts → Driver session requires the command and refusal schema to be stated once as `'static` data, `validate` to receive no `Session`, `Session::run` to be the one entry point with nothing public running a `Command` that did not come from `validate`, `Cause` closed at eight with fixed texts, and a `Refusal`, `Fault` or `SessionError` to hold nothing a call supplied (no path, label, id or value). A command-line call must arrive as a `Call` and pass `validate` → `run`; lifecycle commands join the one table, and every count the contract states (re-exported names, verbs, causes, `SessionError` arms) moves only by amendment.
- **Three endings stay three.** architecture §Standard Contracts → Driver session requires an instance that did not go quiet to be a result (`settled` false with its class) — never a refusal and never a `SessionError` from `run` — a refused call to change nothing, `advance` to move time only through the caller's `Session::with_time` step (`time-unavailable` without one), and settling to move no time and wait on no load. The CLI's stdout shape and exit codes (scope decision 4) must keep outcome, refusal and session edge distinguishable and add no wait, poll or clock read.
- **The library's dependency set and direction are locked.** architecture §Established Decisions → [Driver session] requires escher-driver to depend on three crates only, carry no `[features]` table, use no serialization crate, install no subscriber, read no env var, and name no app — no manifest under `packages/` names an example, the one edge running `seven_guis → escher-driver`. A JSON dependency, a binary target on the crate, or a CLI crate under `packages/` that names the stand each changes this record; where the CLI binary lives and how it finds a host to spawn (`start` takes the caller's `std::process::Command`) is the plan's, inside this rule.

## Patterns to follow
- **The existing host binary's shape** — a second binary of its package with a closed argv, the telemetry sink installed first, exit `2` with a usage line on stderr having booted nothing and created no state, the error's fixed message on stderr otherwise, per architecture §Standard Contracts → CLIs (the `escher-session` row). That row also requires nothing on stdout on any path for the host; if the host becomes the process that answers commands, the row is amended at wrap.
- **The repository's one recorded exit grammar** — `0` success · `1` failed · `2` usage, checked before any precondition · `3` precondition unmet, with JSON-line output encoded by a real encoder, per architecture §Standard Contracts → CI contracts (the agent-run and cold-agent rows). A precedent for the options put to the founder, not a ruling.
- **Typed errors with fixed `Display` text** — error types as enums with `Display` per architecture §Conventions → Error handling, fallible paths returning typed results per architecture §Cross-cutting Patterns → Error handling; a JSON form of `SessionError` or `Refusal` renders the fixed names, never a path or an argument.
- **Manifest and crate hygiene for anything added** — dependencies declared once in `[workspace.dependencies]` and consumed `{ workspace = true }`, in-repo crates `default-features = false`, per architecture §Conventions → Manifests; escher's own crates `publish = false` per architecture §Inherited Defaults → Publishability; module `//!` and item `///` docs under the crate's `#![deny(missing_docs)]` and the workspace rustdoc gate per architecture §Conventions → Documentation and §Inherited Defaults → Code quality. Whether `serde_json` is already a workspace dependency is research's question — architecture §Stack and Technologies records `serde` at workspace level and `serde_json` only in the WPT runner's own manifest.
- **How a check drives a built binary** — spawned through `CARGO_BIN_EXE_…`, both streams piped and drained from the spawn on, the session reached by `attach` under a bound, a kill-and-reap guard, state directories under `CARGO_TARGET_TMPDIR`, per architecture §Occupied Resources → Process-wide state and threads; one test target per file with shared helpers in a non-target module per architecture §Conventions → Tests; a script with a contract lives under `scripts/` with its test in the `ci-scripts` leg per architecture §Infrastructure Patterns → Directory structure.

## Anti-patterns to avoid
- A TCP or UDP port, a second listener, or an IPC, named-pipe, pid-file or daemonizing crate to carry commands or to reap an orphaned host — banned by architecture §Established Decisions → [Driver session]; an idle expiry or a list-and-stop command (scope decision 5) is built inside the registered socket and state directory or registered first.
- A second verb table, a hand-kept list of verbs or causes in the CLI, or a path that runs a command without `validate` — banned by architecture §Standard Contracts → Driver session, which also bans printing or fielding a `Command`, `Call`, `ArgValue` or `Outcome` (their `Debug` prints ids, names and values): the JSON form is a written form of its own, not `{:?}`.
- Installing upstream's `tracing_subscriber::fmt::init()` in an escher binary, or any write to stdout that is not the command's answer — architecture §Cross-cutting Patterns → Logging and timing records that install as stdout and unscrubbed, and requires escher binaries to install `escher_telemetry::init` (stderr only, non-ANSI).

## Contract bindings
- **arch ↔ security** — the socket's wire and the state directory are stated in both architecture §Occupied Resources → Network ports and listeners and the security plan's socket rows; a crossing ruled by the founder amends both in the same wrap, and architecture §Inherited Defaults → API style (its one-socket sentence) with them.
- **arch ↔ obs** — any new binary is a new sink install site and service identity (architecture §Occupied Resources → Process-wide state and threads names the two today); the command span stays eight fixed fields under target `escher_driver` (architecture §Standard Contracts → Driver session), and a host that now runs commands is the first sink-installing process to emit it.
- **arch ↔ tests** — new checks land as one target per file (architecture §Conventions → Tests; the blitz-tests target contract in architecture §Standard Contracts → CI contracts, pinned by the `ci-scripts` leg, whose recorded count of discovered test files moves if a script test is added); new session state directories are recorded in architecture §Occupied Resources → Filesystem.
- **arch ↔ a11y** — only if the actionable-key check is exposed (scope decision 6): architecture §Established Decisions → [Driver session] records escher-driver naming dioxus-native-dom's `accessibility` unconditionally, so the check is reachable without a new feature.
- **Wrap amendment sites this chunk makes stale** — architecture §Established Decisions → [Driver session]; §Standard Contracts → Driver session (the "Not built" list, the re-export count, the wire) and → CLIs; §Occupied Resources → Network ports and listeners, Filesystem, Process-wide state and threads, Names (crates, binaries); §Infrastructure Patterns → Directory structure if a crate or script is added; §Existing Scopes → escher-driver, seven_guis, blitz-tests; §Inherited Defaults → API style.

## Acceptance criteria contributions
- (arch) The workspace binds no port and no second listener, reads no new env var and gains no default state location; a session is reached only through a caller-named private state directory — or each addition is registered with the founder's ruling recorded (per architecture §Occupied Resources → Network ports and listeners)
- (arch) Every command-line call reaches the instance as a `Call` through `validate` then `Session::run`; the verb table and the cause set are stated once, and no refusal, fault or session error carries call-supplied text (per architecture §Standard Contracts → Driver session)
- (arch) No manifest under `packages/` names an example or the stand; every crate, binary or dependency added is declared in `[workspace.dependencies]`, `publish = false` where escher's own, with `Cargo.lock` committed and the `--locked` gates green (per architecture §Established Decisions → [Driver session])
- (arch) Every escher binary the chunk adds or changes installs `escher_telemetry::init` first and writes telemetry and diagnostics to stderr only, stdout holding the command's answer alone; the command span keeps its eight fields (per architecture §Cross-cutting Patterns → Logging and timing)
