One snapshot command, `escher-session snapshot --session <dir>`, run through the real binary against each of the four hosted stand tasks (counter, flight booker, timer, CRUD), answers one line of JSON whose `text` field is that task's screen as a tree — the in-process snapshot text of the same task in the same layout mode, one line per node nested by indent, every node carrying its id, role, name, state and bounds (the form `stand_snapshot_text` proves) — and the whole stdout line is at most `SNAPSHOT_TEXT_BUDGET` (10,000) bytes, so it fits in a single tool result — `cargo test -p seven_guis --locked --test cli_commands`.
