Every driver command runs from the command line through the real `escher-session` binary against a hosted stand task: `start`, `status`, `stop` and each of `snapshot`, `click`, `type`, `press`, `advance` and `scroll` answer one line of JSON on stdout, and the process status is `0` when the command was accepted and `1` when it was refused (`2` on a usage error, `3` on a session error) — `cargo test -p seven_guis --locked --test cli_commands`; and the two stand flows `counter.sh` and `flight.sh` each complete with status `0` as a script run under plain `sh`, starting and stopping their own session and using no tool beyond the shell — `cargo test -p seven_guis --locked --test cli_flow`.
