# tests · standing conventions

- S1 · each new test is an integration test target of its own per behaviour, one target per file, with shared helpers in a shared module that is no target · 1-test-scope-summary · test-strategy
  decision/inline-cfg-test-modules · Unit tests in inline test modules — Unit tests sit in cfg(test) modules inside their source files. · except: Eight cfg(test) modules held in files of their own through a path attribute at their parent.
  decision/inline-unit-test-modules · Inline unit test modules — Unit tests are Rust test functions in cfg(test) modules beside the code under test. · except: modules held in files of their own through a path attribute
  decision/one-test-target-per-file · One test target per file — blitz-tests keeps one auto-discovered test target per file under its tests directory, upstream's single all target held unbuilt at test = false. · why: A ratified difference from upstream, whose layout is autotests = false with all the crate's one test target. · guard: BlitzTestsTargetsTest
  decision/session-checks-share-one-module · Session checks share one module — What the checks that hold a session share, in process and by a host process of their own, is stated in one session test module with no test and no test target of its own, beside the stand checks' module. · why: kept beside the stand checks' module because that module was held unchanged
  decision/shared-stand-tables-in-one-module · Shared stand tables in one module — The tables and helpers the stand checks share are stated once in one shared test module with no test and no test target of its own; the tables are stated expectation, never a second role or name mapping. · except: stand_element_ids keeps its own boot (it books the flight), and task_keys, ceiling, component, the cards array and each file's SECRET stay per-file
  decision/shared-test-modules-not-targets · Shared test modules are no target — Shared test modules, the flow scripts directory and the committed checks data directory are no test target; checks read shared modules through mod declarations.
  decision/unit-tests-in-source-file · Unit tests sit in their source file — Unit tests sit in a test-only module inside the source file; a module moved out of line sits in its own file declared test-only by path at its parent, its test paths unchanged. · except: the Dioxus bridge tests are a child of the Dioxus document module, because the event handler's two fields are private to it and it has no constructor
- S2 · each new test data and fixture is stated in code, nothing seeded, with shared fixture pages stated once · 7-test-data-fixtures · test-data-fixtures
  decision/test-data-in-code · Test data stated in code — Test data is stated in code: inline HTML, literals and byte arrays, directly injected images, fixed viewports, embedded fonts and pages generated in the test. · except: one external benchmark page supplied through PAINT_TREE_BENCH_HTML
  decision/test-data-is-code · Test data is code, nothing seeded — Nothing is seeded for the agent-run contract: the fixtures are code compiled into each target by `boot`, so `boot` is the bootstrap.
- S3 · each new check is hand-written with real components and no mocking library; time is driven by the virtual clock, never sleep or wall clock · 8-mocking-stubbing-discipline · mocking-stubbing-discipline
  decision/hand-written-stand-ins · Hand-written stand-ins, no mocking library — Test doubles are hand-written stand-ins; no mocking library is used in CI, the build configuration or the apps.
  decision/harness-virtual-clock · Harness time is a virtual clock — The harness's time is a virtual clock its documents read, moved by tick and advance_time; screenshot, screenshot_rect, text_contrast and settle never move it. · why: ratified
  decision/no-sleep-or-wall-clock-in-checks · No sleep or wall-clock read in checks — Session checks take no sleep and read no wall clock; time moves by `advance` alone. · except: stand_virtual_clock's 800 ms sleep, stand_load_wait's clock reads and 200 ms stand-in sleep, stand_session_lifecycle's idle-expiry wait and stand_contrast's bound on a load's answer.
  decision/no-wall-time-in-session-checks · No wall time in session checks — Session checks hold no sleep and no wall-clock read; a check waits on a load through the driver's load wait, and the Timer flow advances by the driver only. · except: The checks whose subject is wall time: the virtual-clock check's 800 ms sleep, the load-wait check's clock reads and stand-in sleep, and the lifecycle check's wait on the host's idle expiry.
- S4 · each new check is controlled red-before-green, its failure prints no argument value, and a table-driven test asserts its row count · 4-unit-test-strategy · unit-test-strategy
  decision/assertions-print-no-argument-value · Test failures print no argument value — An assertion over a driver call names only its row and index and never an argument value. · why: A failing test log then prints no argument value.
  decision/call-assertions-carry-row-index · Call assertions carry a row index only — The driver's assertions over a call carry a row index only, never an argument value. · why: so a failing log prints no argument value
  decision/mutation-controlled-tests · Tests controlled red-before-green — A new check is controlled: a named mutation of what it guards turns it red, and the restored tree reads green again.
  decision/table-tests-count-their-rows · Table-driven tests assert their row count — Each table a driver test reads is stated in the test itself and its row count asserted.
- S5 · each new CI step runs through the leg script, with SHA-pinned actions, read-only permissions, no secrets and bounded retried package installs · 9-ci-integration · ci-integration
  decision/actions-pinned-to-commit-sha · CI actions pinned to commit SHAs — Every `uses:` in the CI workflows is pinned to a 40-hex commit SHA, and every Rust toolchain step names its toolchain. · guard: WorkflowPinTest
  decision/apt-install-retries · CI package install retried — A failed install attempt is tried again from `update`, a stalled call ends at its bound and is tried again, and an install failed by its bound is repaired before the next attempt. · guard: InstallScriptTest
  decision/bounded-ci-package-installs · Bounded CI package installs — Every package install in the CI workflow is bounded. · guard: test_ci_workflows.py
  decision/bounded-package-installs · Bounded package installs in CI — No CI step runs `apt-get` directly: packages are installed through the install script with package names only, and the one action step that installs packages carries a `timeout-minutes` above 0. · guard: test_o_package_installs_are_bounded
  decision/ci-actions-pinned-to-sha · CI actions pinned to commit SHAs — Every action every CI workflow uses is pinned to a commit SHA. · guard: test_ci_workflows.py
  decision/ci-legs-host-reproducible · Host-reproducible CI legs — Every linux CI job runs one leg of a shared leg script that the dev host also runs, so every linux leg is reproducible on the dev host.
  decision/ci-legs-through-leg-script · CI legs run through the leg script — Each linux CI job runs its leg through `ci-leg.sh`, the leg present in the script's list, with a failure-log upload and no perl rewrite. · guard: CiWorkflowTest in test_ci_workflows.py
  decision/ci-no-secrets · CI uses no secrets — The CI workflow references no `secrets.`. · guard: test_ci_workflows.py
  decision/ci-package-installs-bounded · CI package installs bounded — Every package install of the CI workflow is bounded, a workflow invariant held by the CI scripts' unit tests. · guard: test_ci_workflows.py
  decision/ci-read-only-permissions · CI read-only permissions — The CI workflow grants `contents: read` at workflow level and no job adds a grant. · guard: CiWorkflowTest in test_ci_workflows.py
  decision/ci-rust-cache · SHA-pinned Rust cache — Every compiling CI job uses the SHA-pinned Swatinem/rust-cache. · except: coverage
  decision/ci-shared-test-cache · Shared CI build cache — Every compiling CI job but coverage uses a SHA-pinned Swatinem/rust-cache saved on main and build branches; the a11y and stand-repeat jobs restore the test job's cache without saving.
  decision/ci-uses-no-secrets · CI uses no secrets — No CI workflow step reads a `secrets.` value. · guard: CiWorkflowTest
  decision/package-installs-bounded-and-retried · Bounded, retried package installs — Every CI package install is bounded and retried: up to 3 attempts, each apt-get update then install under a 120 s bound with a kill grace, a bounded dpkg repair before each retry. · why: Answers a CI run whose package-install step hung twice. · guard: test_o_package_installs_are_bounded; InstallScriptTest · except: The matrix job's third-party Install apt deps action step carries timeout-minutes: 10 instead.
  decision/package-installs-bounded-retried · Bounded, retried package installs — Every package install of the CI workflow is bounded and retried: up to 3 attempts under a 120 s bound, each retry opening with a bounded dpkg repair. · why: the bound answers a package-install hang · except: The test matrix's one package install, through a SHA-pinned apt cache action, is bounded by its step timeout and not retried.
