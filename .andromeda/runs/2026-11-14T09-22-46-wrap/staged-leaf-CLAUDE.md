# escher

<!-- GENERATED:setup start -->

## Overview
<!-- GENERATED:setup:overview start -->
escher is a fork of Blitz, a Rust library workspace for an HTML/CSS engine (high-level APIs for rendering HTML, a core DOM abstraction whose primary entry point is `BaseDocument`, a `Document` trait so wrappers around `BaseDocument` can all be driven by blitz-shell), being turned into an agent-first UI framework: a headless driver (CLI and MCP), stable ids for every element, a compact semantic snapshot of the screen, proven on an internal 7GUIs stand. Development is agent-driven: the framework's own driver is meant to become the harness.

**Stack:** Rust 2024 Cargo workspace 0.3.0-beta.4 (rust-version 1.91.0, no `rust-toolchain.toml`) · Stylo 0.22 · Taffy 0.15 · Parley 0.12 · anyrender 0.14 / Vello 0.11 · winit 0.31.0-beta.3 · AccessKit 0.25 · Dioxus 0.7.3 · Boa 0.22 · tokio 1.42 · reqwest 0.13 — a native-API engine library with no server and no database (the browser app keeps a rusqlite 0.32 history); versions as `Cargo.toml` pins them.

**Key directories:**
- `packages/` — the engine and integration crates and escher's own crates (telemetry bootstrap, driver)
- `tests/blitz-tests/` — integration tests, one file and one test target per behaviour; `checks/` holds the two committed kept checks
- `examples/` — example crates; `examples/seven_guis/` is the 7GUIs stand
- `apps/` — the reference browser and the markdown viewer
- `scripts/` — the agent-run test contract, the cold-agent run pipe, the code-graph tooling

## Critical Warnings (universal invariants)
<!-- GENERATED:setup:warnings start -->
- Secrets live only in GitHub Actions secrets and vars — never in source, fixtures, events or committed evidence; never commit `.env*`
- The driver session's Unix socket is the one listener: a new socket, port, IPC endpoint or credential path is a security-plan amendment first
- No panic path on untrusted input — a driver call's arguments — refuse it as a typed value, never `unwrap` · `expect` · `panic!` · `unreachable!`
- `NodeId` is versioned: a dropped node's id stops resolving instead of aliasing a reused slot — a stale id resolves to none on lookup, never a panic
- No content in a log field: `url` · `href` · `src` · `html` · `text` · `value` · `attrs` · `path` · `request` · `error` print `[redacted]` on `escher_*` targets — add no field that carries them
- Every build, test and CI cargo leg passes `--locked` against the committed `Cargo.lock` (`examples/wasm_hello` aside — a standalone workspace)
- The workspace takes no git dependency — every crate a crates.io registry version
- Incremental and non-incremental layout must produce identical layouts after any sequence of mutations — the `incremental_oracle` holds them to it
- DOM mutations go through `DocumentMutator`, which flushes deferred work on drop
- `clippy::unwrap_used` / `clippy::expect_used` are allowed only locally, next to a written justification — never crate-wide

## Workflow
<!-- GENERATED:setup:workflow start -->
**Key commands:**
- `cargo build --workspace` — build every crate (Linux needs `libfontconfig1-dev`; Arch: `fontconfig`)
- `bash .github/scripts/ci-leg.sh fast` — the local pre-push gate: fmt → clippy → workspace tests → CI scripts → `embolden` (the `blitz-paint/font-embolden` witness, a leg with no CI job of its own), as CI runs them
- `cargo test -p blitz-tests --test {name}` — one integration-test file; agent-driven: `bash scripts/agent-run.sh boot`, then `run stand|all|{name}` (JSON-line results; `status` · `logs` · `cleanup`)
- `bash .github/scripts/ci-leg.sh {leg}` — one CI leg exactly (`fmt` · `clippy` · `test` · `build` · `doc` · `audit` · `a11y` · `coverage` · `stand-repeat` — the stand checks, seventeen named blitz-tests targets outside the `stand_` prefix and seven_guis' process checks three rounds under a zero-failure budget, not a fast leg · …); log in `target/ci-logs/{leg}.log`; the mutation tier is no leg — run on the dev host alone, never in CI: cargo-mutants `--test-tool nextest --baseline=skip` under `NEXTEST_PROFILE=mutants` (the root `.config/nextest.toml`'s `mutants` profile), each unit's mutant test command first read green on the unmutated tree (`.andromeda/test-plan.md` §10)
- `just seven_guis` — run the 7GUIs stand natively (windowed)
- `target/debug/escher-session {verb} … --session {dir}` — the driver's command line (`cargo build -p seven_guis --bin escher-session` first): `start {task} [--record {dir}]` (a recording directory keeping the session as one owner-only replayable check), then `snapshot [--part]` · `click --id` · `type --id --text` · `press --key [--shift]` · `advance --ms` · `scroll --id` · `screenshot [--id]` · `lint` · `graph` · `actions` · `status` · `stop`, and `help` (the tool's self-description, its `--session` optional and unread, reaching no session); one line of JSON on stdout, exit `0` · `1` · `2` · `3`; `target/debug/escher-session coverage {app} {check}...` (no `--session`, no `--record`) replays each named kept check on a fresh session and prints the coverage line `{"unexercised":[…],"checks":n,"held":m}`, the handlers no check exercised
- `target/debug/escher-session mcp [--record {dir}]` — the same binary as an MCP server over stdio (an MCP client spawns it; server name `escher`, its tools the fourteen verbs, `graph` after `lint`, `actions` after `graph`, `help` last)

See `.claude/docs/commands.md` for the full reference.

## Architecture
<!-- GENERATED:setup:architecture start -->
Blitz is a radically modular, embeddable web engine: a headless DOM (`BaseDocument` in blitz-dom) that external code drives and any renderer paints, with parsing, networking, painting and windowing in separate crates. Embedder services — net, navigation, shell, HTML parsing — reach the DOM only through provider traits in `DocumentConfig`, defaulting to `Dummy*` no-ops; web behaviour is written against named specs and named engines. Style, damage, box construction, layout and paint topology run one incremental pipeline over versioned node ids.

The engine is already exercised headlessly — `blitz-test-harness` synthesizes input through the real event-dispatch pipeline with no window or GPU, and the WPT runner renders to CPU buffers; the seven_guis stand boots through it (`seven_guis::stand`) at a pinned viewport with its bundled font, every boot offline but the load page's, whose one stylesheet fetch the in-process stand-in `LoadNet` answers. escher builds on that: stable element ids (built — `DioxusDocument::element_id(s)`, the author's HTML `id`, else a path anchored at the nearest keyed element of the same component, else the element's component path; proven the same across a re-render, a remount, a fresh process and edits of the code around an element; every element an agent can act on is keyed, checked by `DioxusDocument::unkeyed_actionable`; and the id is carried on every element's accessibility node as AccessKit `author_id`), a semantic snapshot (its data model built — `DioxusDocument::snapshot`, every element the accessibility tree keeps as a node of id · role · name · state · bounds, each field from a reader the engine already had; its state proven per control through real input — enabled, checked, value and focused — with a password's or a file input's value read as the fixed mask `MASKED_VALUE`, and selected, pressed and invalid read from what the app states in its markup: the engine's builder writes them on the accessibility node from `aria-selected` · `aria-pressed` (or `aria-checked` on a checkable role, ratified by the founder, 2026-10-18) · `aria-invalid`, a third direct engine change for every document, ratified by the founder (2026-10-10), and the stand's flight booker and CRUD state invalid and selected — the stand states no `aria-pressed`, the flight booker's mode a `select#flight-type` whose options state its choice, and `accessibility_states` pins the pressed reading on a fixture; its text form built — `Snapshot::to_text`, one line per node nested by indent, every lean stand screen under the 10,000-byte `SNAPSHOT_TEXT_BUDGET` (the Cells screen the stand serves beside them passing it), returned to its caller in process and, through the command line, in a hosted `snapshot`'s answer, and a screen over the budget read in parts — `Snapshot::text_parts`, consecutive pre-order lines never split, the driver's `snapshot` taking an optional `part` (a whole number, 1 to `MAX_PART` = 1000) and answering one part's text with the closed counts `part` and `parts`, part 1 by default, a part past the last the empty text, a screen within the budget answering whole as before, proven on an over-budget fixture page in both layout modes, in process and through `serve_mcp` (a ratified boundary widening); its diff built — `Snapshot::diff`, a comparison of the snapshots taken before and after a step that names exactly the nodes added, removed or changed, by stable element id, and is empty for a step that changes nothing, proven on the stand in both layout modes — beside an engine change flag that now tells the truth, `has_changes` reading true from a tracked write until `take_changed_nodes` drains it; the driver's acting verbs return that diff), a driver session (built — `escher_driver::Session` holds one headless instance across commands, one process hosts it until it is stopped or has answered no request for its 30-minute idle expiry, and `start` · `attach` · `stop` · `call` drive it over a local socket that carries its lifecycle and its calls; the stand hosts its own through the `escher-session` binary; since 2026-10-19-session-recording a session whose launcher names a recording directory (`--record`, `Session::recording_into`) keeps its answered calls as one owner-only replayable check — the calls as they crossed, a masked `type` as one fixed stand-in, each answer a 64-bit digest and kept whole — masked as on every carrier, a shot's without its pixels, so the screens' ids, names, values, snapshot text, diffs, a lint's findings, a UI graph's names, closed flag words and booleans, and an actions answer's ids, owner ids, verb words, closed cause words and booleans at rest — read back strictly by `Check::from_bytes` and replayed through `Session::run` alone by `Check::replay`, which stops at the first step whose acceptance or kept answer differs, ratified by the founder (2026-10-19); the repository's own two scripted Counter checks committed under `tests/blitz-tests/checks/`, the one exception to owner-only, replayed by `stand_replay` and kept fresh by seven_guis `recording`), settle detection (built — `Harness::settle` runs every pass that is due and returns `Settled`, or `NotSettled` naming the busy class: render and layout driven to quiet, a load in flight reported at once and never waited on, a timer or an animation neither waited on nor advanced; `Session::act` runs one step on the held instance and returns once it has settled, a load in flight waited for up to `LOAD_WAIT` (5 s of wall time, settled again every 10 ms, no time moving on the held instance) and one still loading at the bound `NotSettled(Loads)`;
