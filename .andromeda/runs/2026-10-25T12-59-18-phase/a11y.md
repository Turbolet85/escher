# a11y extract

## Relevance
partial — the stand extension (flight booker's mode toggle turned into a `select`, `cells` served to the driver) moves the stand's tier-0 a11y pins; the cold-agent pipe, its goals, the live run and the wrong-call bar are outside this domain.

## Constraints
- The a11y target is tier 0, SC 2.1.1 · 1.4.3 · 2.4.3; any stand control the chunk adds or replaces stays inside that target (per a11y-plan §1 A11y Scope Summary).
- Focus order is a pinned table: `stand_keyboard` walks each lean task's `tab_order` and `ENABLED_TAB_ORDER` forward and back in both layout modes, and every `controls(task)` id must lie in their union. Replacing `flight-one-way` / `flight-return` with one `select` moves the flight booker's boot order and its six-stop enabled order, and both tables must be re-pinned in `tests/blitz-tests/tests/common/mod.rs` (per a11y-plan §5 Keyboard Navigation — Test harness pattern).
- Keyboard operability (SC 2.1.1): a focused single-choice `select` that is no disabled form control must take ArrowDown / ArrowUp / Home / End and typeahead, with one `input` and one `change` per change. A select is not on the Enter/Space activation list, so the mode buttons' Enter and Space rows in `stand_keyboard` (the 20 rows, plus the 4 enabled-later rows) go away for the select and must be restated. Whether the stand's select already satisfies this is research's question (per a11y-plan §5 Keyboard Navigation — Keyboard handling).
- Contrast (SC 1.4.3): `stand_contrast` asserts the 18 control rows, 14 `TEXT_ROWS` and 19 `STATE_ROWS` row for row. A row is exempt only where the snapshot's `enabled` reads `Some(false)`. `flight-one-way` is one of the five accent rows, and three of the `STATE_ROWS` are "return-chosen". The plan records that the user-agent `select`'s text/background pair is not measured, because the stand holds no select. Swapping in a select therefore moves all three tables and adds a pair the record must measure (per a11y-plan §6 Visual Design Verification — Color contrast).
- Every interactive-role node of the four lean tasks must read a non-empty name. The select needs a name from a `<label for>`, `aria-labelledby` or `aria-label`, and its options are named by their labels. The checks state roles and names once, in the shared module's tables, never in a second role or name mapping (per a11y-plan §7 Screen Reader Support — Accessibility tree output).
- The actionable-key rule: every element an agent can act on reads an author key, and `DioxusDocument::unkeyed_actionable` must return nothing on every stand task. That covers the new select on the flight booker and Cells when it is served (its `cell-{A..Z}{0..25}` and `cell-input` ids), in both layout modes. Whether Cells' 676 click-reacting, role-less cells still read 0 under the driver is research's question (per a11y-plan §7 Screen Reader Support — Accessibility tree output).
- The stand's stated states: today the flight booker's mode buttons state `aria-pressed`, which is one of the stand's three by-attribute state kinds. A select's option reads its chosen state as `selected`, with no `aria-selected` read and no `toggled`. The stand's state checks and their record of the three kinds move with the swap (per a11y-plan §2 A11y Strategy — Role derivation; per a11y-plan §4 ARIA Patterns & Roles — ARIA state attributes).

## Patterns to follow
- Through the driver, `stand_act_select` walks Tab across a select fixture: the disabled select is skipped, and the focus order is the same before and after the choices. A choice is made by click, then by key. Model the stand's select checks on it (per a11y-plan §5 Keyboard Navigation — Test harness pattern).
- `enable_by_keyboard` reaches an enabled state by keyboard alone before the walk against `ENABLED_TAB_ORDER`. The flight booker's return-mode state must stay reachable by keys alone once it is chosen by a select (per a11y-plan §5 Keyboard Navigation — Test harness pattern).
- `stand_contrast`'s one shared reader classifies rows by the snapshot's `enabled`, and a `label[for=…]` row is never exempt. Add the select's rest, hover and active pairs as rows through that reader, never through a second formula or threshold (per a11y-plan §6 Visual Design Verification — Color contrast).
- Error state not carried by colour alone: the flight booker's date inputs state `aria-invalid`, so the invalid cue is in the tree and the snapshot. Keep it intact while the mode control changes (per a11y-plan §8 Cognitive Accessibility — Error recovery).

## Anti-patterns to avoid
- Never a second role or name mapping: the snapshot, its text, diff and MCP results read role, name and state from `accessibility_tree` alone, and the stand checks state roles and names once in the shared tables (per a11y-plan §7 Screen Reader Support — Accessibility tree output).
- No `aria-activedescendant` read or roving focus slipped in alongside the stand edits. It is SC 4.1.2 work outside tier 0, kept unread and pinned by `accessibility_active_descendant_unread` (per a11y-plan §5 Keyboard Navigation — Per-surface keyboard shortcuts).
