# layouts extract

## Relevance
relevant — the chunk changes the seven_guis stand's TaskShell screens (the flight booker's mode control, the set of tasks the driver boots, a load in flight) and the two CLI surfaces that front it (`escher-session start`'s task word and usage line, `scripts/cold-agent.sh`'s task set and prompt).

## Constraints
- The headless stand mounts one task in TaskShell through `task_in_shell` (`main#main > #task-shell`, header above `#task-body`) at the pinned 800 × 600, scale 1.0, Light viewport with the bundled font; any task newly served to the driver (Cells, a load-in-flight screen) is required to mount through that same boot, and a held instance must read as a fresh boot in both layout modes (per layout-templates §Surface: desktop-native → Primary screens).
- Stand changes so far have been made by attributes alone — author `id`s as stable element ids, names by `for`/`aria-label`, roles and states by `aria-*` — adding no element, class, style, wrapper or order and no CSS selecting by an id; the flight booker's one-way / return swap from two toggle buttons (`flight-one-way` · `flight-return`, `aria-pressed`) to a `select` is a structural change to that screen, so the ids it retires or adds, its accessible name and its position in the task body must be stated, not left implicit (per layout-templates §Surface: desktop-native → Primary screens).
- Every actionable element on every task the driver can boot must carry an author key (`unkeyed_actionable()` reads 0 on all seven tasks, the Circle Drawer dialog open included); Cells' controls already hold `cell-{A..Z}{0..25}` and `cell-input` per the plan — whether that still holds on the current code and under the driver's `start` boot is research's question (per layout-templates §Surface: desktop-native → Primary screens).
- The stand's layout is required to read clean to the visual lint at boot — 0 findings on each of the four lean tasks in both layout modes — with the one recorded exception being the clipped last CRUD row after twelve Creates; a newly served task (Cells, whose grid is larger than the viewport) or a changed flight booker screen is new layout under that reading, and whether it reads 0 or a stated, measured set of findings is research's question (per layout-templates §Surface: desktop-native → IA notes).
- On the stand the nested scroller is `crud-list` and the pinned viewport is scrolled by a driver `scroll` only on an in-file fixture taller than it; a Cells screen served to the driver brings a second large scrolling region onto the stand, so its scrolling-box and visible-region readings (which box clips a cell, what `scroll` brings into view) need measuring rather than assuming (per layout-templates §Surface: desktop-native → IA notes).
- `escher-session start` takes the task as one plain word from a closed list (`counter|flight-booker|timer|crud`), and its usage line is built from the verb table and the task names; adding a task to that list changes the usage line and the `start` grammar, with a task the binary does not boot remaining a usage ending (exit 2, nothing booted, no state created) and nothing the caller typed written back (per layout-templates §Surface: cli → Primary screens).
- `scripts/cold-agent.sh` keeps its CLI shape: usage `cold-agent.sh <verb> [task]` with verbs `run · status · cleanup · logs`, usage errors on stderr with empty stdout (exit 2, checked before any precondition), stdout JSON lines only, the transcript and the agent's check never printed, and a fixed prompt that names no element id or app slug; new goals over 0.2.0's capabilities are required to keep that last rule (per layout-templates §Surface: cli → Primary screens).

## Patterns to follow
- Make stand changes as attribute-only edits where possible (`id:` lines, `aria-label`, `for`, `role`, `aria-*` states), as the 2026-10-10 snapshot-states, 2026-10-14 a11y-assertions and 2026-10-14 requirement-sweep changes did, with the edit recorded in the stand's own pins (per layout-templates §Surface: desktop-native → Primary screens).
- New consumers of the stand mount reuse `seven_guis::stand` and nothing else, as the host role and the `mcp` role do. Neither adds markup, ids, classes, styles, wrappers or order (per layout-templates §Surface: desktop-native → Primary screens).
- Give each new stand control a stable author `id` in the task's existing `{task}-{control}` naming (`flight-*`, `cell-*`), and name each input by an existing label's `for` or by `aria-label` (per layout-templates §Surface: desktop-native → Primary screens).
- Record a layout reading with its source and the chunk that measured it (for example `crud-list`'s bounds, or the lint's 0 findings at boot), so that a reading that changes has an earlier baseline to compare against (per layout-templates §Surface: desktop-native → IA notes).

## Anti-patterns to avoid
- Adding CSS that selects by a stable author id, or a wrapper, class or reordering made only to serve the driver or the cold agent (per layout-templates §Surface: desktop-native → Primary screens).
- A cold-agent prompt or goal text that names an element id or an app slug, or a pipe verb that prints the transcript or the check to stdout (per layout-templates §Surface: cli → Primary screens).

## Contract bindings
- layouts ↔ a11y: if the flight booker's mode control becomes a `select`, its Tab sequence changes, which binds to a11y SC 2.4.3 and to the stand's focus-order tables (`stand_keyboard`, `common::tab_order`, `ENABLED_TAB_ORDER`, and the Enter/Space rows of the retired buttons). The new control's accessible name binds to the a11y naming rules (per layout-templates §Surface: desktop-native → Primary screens).
- layouts ↔ design: the new `select` and any newly served screen bring text/background pairs into `stand_contrast`'s rows. The tokens and ratios are design's and a11y's to own, not this extract's (per layout-templates §Surface: desktop-native → IA notes).
- layouts ↔ tests: the 0-findings-at-boot reading is pinned in `stand_lint`. The CLI shapes of `escher-session` and `cold-agent.sh` are pinned in test-plan §3 and its contract tests (`examples/seven_guis/tests/cli_*.rs`, `.github/scripts/test_cold_agent.py`) (per layout-templates §Surface: cli → Primary screens).

- (layouts) The flight booker's mode control renders in `#task-body` of the TaskShell as one stable-id'd, named control. Its ids, its Tab position and the retired `flight-one-way`/`flight-return` entries are re-pinned in the stand's tables, and no other element, class, style or order moves (per layout-templates §Surface: desktop-native → Primary screens).
- (layouts) `lint` at boot reads 0 findings on each lean task in both layout modes after the change. Each newly served task's boot reading (Cells included) is measured and recorded, either 0 or a stated set of findings, and never assumed (per layout-templates §Surface: desktop-native → IA notes).
- (layouts) `escher-session start`'s task list and usage line name exactly the tasks the binary boots, and an unknown task stays a usage ending (exit 2, nothing booted). `cold-agent.sh` keeps its verbs, exit grammar and JSON-lines stdout, and its prompt still names no element id or app slug (per layout-templates §Surface: cli → Primary screens).
