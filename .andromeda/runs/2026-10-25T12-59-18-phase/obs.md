## Constraints
- The wrong-call count is read from the escher server child's stderr at `RUST_LOG=info` in `target/cold-agent/server.log`, counted by ` span="tool_call" ` lines and their ` ending="refused" ` / ` ending="error" ` only, never printed or copied; the two replay children run uninstrumented with stderr to `/dev/null` (per obs-plan §3 Cold-agent pipe log). New goals reaching v020-04 … v020-09 must keep that counting path; whether the moved `cold-agent.sh` still spawns the server child that way is research's question.
- Every event and verdict field of the pipe is a count, a boolean or a closed word: no transcript text, tool argument, tool answer, reply or check enters an event or the verdict, and `counts_agree` ties the server's span lines to the transcript (per obs-plan §6 Log format (the cold-agent pipe); the field list in .andromeda/obs-plan-detail/log-coverage.md, values · log-fields). A goal or verdict field added for the new capabilities stays in that closed shape.
- The driver keeps exactly its two spans: `command` with its eight fields and `tool_call` with `tool` and `ending` (per obs-plan §4 Span / Trace Coverage). A part read leaves `verb="snapshot"`, a lint `verb="lint"`, a recorded or replayed step the same lines, with no part number, part count, finding, screen text or image byte (per obs-plan §6 Logged events, escher-driver). The scope's "no new … log field or span" boundary leaves this unchanged.
- The headless stand and its checks install no subscriber, read no env var and print nothing, their readings going into assertions only. The fixture stand-ins `HeldNet` and `LateNet` hold no print, `tracing` call, env read, socket or `blitz_net` (per obs-plan §3 Logging stack, the headless-stand and absence-of-logs lines). Cells served to the driver, the flight booker's `select` and a load in flight on the stand fall under the same silence requirement, and so does any check those moves add or rewrite.
- `transcript.jsonl` is raw model output and tool I/O, unscrubbed by design. It carries the stand's screen (ids, accessible names, control values) to the model provider and holds host paths. It is never printed or logged, and each committed copy masks the session dir and the home prefix (per obs-plan §8 Values logged as-is, the cold-agent pipe line; .andromeda/obs-plan-detail/pii-scrubbing-compliance.md). New screens (Cells' contents, the select's options) widen what it carries. Whether that carriage needs the founder's word again is a security question bound below, not obs's.
- The cold-agent state `target/cold-agent/{verdict.json, events.jsonl, transcript.jsonl, client.log, server.log, check.json}` stays local and gitignored, and no CI leg uploads it, because CI runs only the shim contract tests (per obs-plan §9 Telemetry artifact handling; .andromeda/obs-plan-detail/ci-integration.md, Cold-agent pipe state row).
- A build that resolves the whole workspace turns `blitz-dom/tracing` on, so a sink-installing child also prints engine events, such as the redacted `INFO blitz_dom::document` line. The pipe's count must therefore stay by span name and never by line count (per obs-plan §2 Feature wiring, the by-invocation line). A load in flight on the stand may add engine load lines under that build. Whether it does is research's question.

## Patterns to follow
- A load in flight held by a silent, in-test network stand-in (`HeldNet`, which answers through `NetHandler::bytes`, or `LateNet`'s own-thread delay), with no `blitz_net`, socket or print (per obs-plan §3 Logging stack, the shared fixtures module and the load-wait check lines). Reuse it for the stand's load rather than a real provider.
- Span assertions in process through a hand-written `tracing::Subscriber` under `with_default` (`stand_mcp_tools`'s `Recorder`), or through re-run children over `init_with_writer` (`stand_act_spans`). Escher's sink is never installed in a stand check otherwise (per obs-plan §3 Logging stack).
- Sink censuses on the real binary at `trace` under both builds (`host_log`, `mcp_log`, with their `Needles` and `stand_needles` readers in `examples/seven_guis/tests/common/mod.rs`). Their assertion messages name a kind and a count, never a needle or a captured line (per obs-plan §3 Logging stack, the out-of-line test files line).
- The pipe's JSON-line events are encoded by the embedded python3 `json` module and never assembled in bash (per obs-plan §3 Cold-agent pipe log).

## Anti-patterns to avoid
- Never print, copy or commit `server.log`, `transcript.jsonl` or `check.json` unmasked, and never fold their content into an event or the verdict (per obs-plan §3 Cold-agent pipe log; §8 Values logged as-is).
- Never field or log what a call supplied or a screen reads, whether a Cells part, a select choice or a load's URL: no new span field, log field or print on the stand or driver path (per obs-plan §4 Span / Trace Coverage).
- Never install a third-party subscriber (`fmt::init()`, `env_logger`) on a stand path. Those stay unscrubbed, outside escher's allowlist sink (per obs-plan §8 Scrubbing).
