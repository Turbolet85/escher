## Bindings
- **Runtime inputs ↔ Occupied Resources (Environment variables · Names · Filesystem)**: a stand task or a held load chosen by argument is no registration, while a new env var, binary, listener or provider resource is an arch §Occupied Resources entry first (.andromeda/architecture-detail/cross-cutting-patterns.md:8).
- **Config management ↔ Standard Contracts → Headless stand / Provider traits**: the stand boots offline and names no `blitz_net`, so a load in flight on it rides a `NetProvider` set in `DocumentConfig` (the fixtures' `HeldNet` shape), the P4 fork the scope names (.andromeda/architecture-detail/cross-cutting-patterns.md:8; .andromeda/architecture-detail/cross-cutting-patterns.md:21).
- **Logging and timing ↔ Standard Contracts → Telemetry bootstrap / Driver session, test-plan §3 cold-agent pipe, security-plan §Surfaces**: the pipe's wrong-call count reads the closed `tool_call` span lines the sink prints on stderr, and no field there may carry a screen's content (.andromeda/architecture-detail/cross-cutting-patterns.md:14; .andromeda/architecture-detail/cross-cutting-patterns.md:15).
- **Event processing ↔ Established Decisions [DOM semantics] / Standard Contracts → Events**: a controlled app writes `selected` from its `input` event's value or a choice reverts, and the engine dispatches `change` only after `input` — the flight booker's handler binds both (.andromeda/architecture-detail/cross-cutting-patterns.md:27).
- **Invalidation and state integrity ↔ Standard Contracts → Document core / Dioxus DOM bridge, CLAUDE.md incremental oracle**: the changed set and the snapshot diff are distinct readers, every stand pipeline check runs both layout modes (.andromeda/architecture-detail/cross-cutting-patterns.md:34; .andromeda/architecture-detail/cross-cutting-patterns.md:35).
- **Development Style ↔ Project Intent**: the founder's agent-driven word is what the cold-agent bar measures (.andromeda/architecture.md:263).
