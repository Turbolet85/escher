## Relevance
partial — the chunk is mostly stand markup, styles and assertions, but four of its parts touch security-plan rows: the platform-adapter crossing (CARRY 1–4, 6), new engine attribute reads (CARRY 11 `aria-activedescendant`, CARRY 12 `inert`), a new accessible name crossing the ratified carriers (CARRY 5), and a CI gate (the a11y leg gating merges).

## Constraints
- Any assertion on the tree the shell hands the platform adapter (CARRY 1) holds `author_id` to the shape security-plan §Input Validation (`id` (stable element id) row) requires. Neither the id nor the snapshot carries a `NodeId`, `ElementId`, `ScopeId` or pointer. `author_id` is set on element nodes only, never on a `TextRun`, the document root or the synthetic `Window` node. Nodes resolve through `BaseDocument::get_node`, never by indexing the slab with a tree id. Today's proof reads `DioxusDocument::accessibility_tree`. Whether the tree the shell actually hands the adapter meets the same shape is research's question.
- security-plan §Input Validation (`id` row and `aria-selected` · `aria-pressed` · `aria-invalid` row) ratifies the platform adapter as an exit for ids, accessible names and the three states only "when an assistive technology is active", and its windowed witness is still owed. Building the adapter into the stand binary (CARRY 2 and 4) widens where that exit exists, so it is the founder's fork (scope boundary inputs#I1). The chunk enables no adapter on seven_guis without his ruling.
- security-plan §API Security names the driver session socket as the one listener. Whether AccessKit's Linux platform adapter (an AT-SPI client over the session D-Bus) is an IPC endpoint that needs registration before the stand builds it is research's question. The plan records no such endpoint.
- A new engine attribute read (CARRY 11 `aria-activedescendant`, CARRY 12 `inert`) takes the shape security-plan §Input Validation (`aria-selected` · `aria-pressed` · `aria-invalid` row) requires: it is read in every document, remote HTML included, with no log site and no panic path, and the attribute's text never leaves the process. `aria-activedescendant` holds an IDREF, which is authored text from an open value set. Under the founder's 2026-10-10 rule in security-plan §Input Validation (Driver session socket row), carrying such a value out is a widening that goes to him. If the read is taken, it may move the tree's focus only, and it carries no attribute text onto the tree, the snapshot or any answer.
- `inert` is one of the 28 boolean names the bridge clears on a falsy value, per security-plan §Input Validation (Dioxus mutations, boolean attributes with a falsy value row). If the engine honours `inert`, it follows the presence-and-closed-match gate that security-plan §Input Validation (`disabled` row) requires for focusability. The plan names a `<div disabled tabindex=0>` as a known limit, owned by "Stand requirement sweep", not by this chunk.
- Naming `crud-list` (CARRY 5) adds an accessible name that crosses the ratified carriers: snapshot text, socket answers and MCP results. security-plan §Input Validation (`aria-label` · `<label for>` row) requires that no escher code logs a name and that a sink-installing host's stderr holds 0 name needles at any `RUST_LOG` level.
- When the a11y leg is made a merge gate, security-plan §Authentication & Authorization (RBAC row for ci.yml) requires ci.yml to keep its workflow-level `permissions: contents: read` and no job-level grant, as asserted by `.github/scripts/test_ci_workflows.py`. security-plan §Dependency Security (Supply chain integrity, Lockfile verification) requires the a11y leg's cargo command to keep `--locked`.

## Patterns to follow
- The closed-set attribute read: trim, then an exact lower-case match against a closed set, with closed enums or booleans written out and never the text. A 5,500-character value builds the tree and is written nowhere. Follow security-plan §Input Validation (`aria-selected` · `aria-pressed` · `aria-invalid` row), `packages/blitz-dom/src/accessibility.rs`.
- The keyboard-activation gate: a closed element-name and type match plus a `disabled` presence check, with census probes reading 0 for print, log site, env read, `unwrap`, `expect` and panic in the added engine lines. Follow security-plan §Input Validation (keyboard activation row), `packages/blitz-dom/src/events/keyboard.rs`.
- The leak census: id needles, name needles and a typed sentinel counted on the `escher-session` host's and `mcp` role's stderr at `RUST_LOG=trace` under both builds (`examples/seven_guis/tests/host_log.rs`, `examples/seven_guis/tests/mcp_log.rs`). See security-plan §Input Validation (`aria-label` · `<label for>` row).
- CI invariants pinned in `.github/scripts/test_ci_workflows.py` (workflow permissions, repository guards), per security-plan §Authentication & Authorization (RBAC rows).

## Anti-patterns to avoid
- Writing an attribute's value as typed (an `aria-activedescendant` IDREF, an `aria-label` text) into a log, a span field, the tree's `Debug` or an answer field. security-plan §Input Validation (`aria-selected` · `aria-pressed` · `aria-invalid` row) and §Logging & Monitoring (escher's own sink) forbid it.
- Resolving an attribute-named or tree id by indexing the node slab instead of `get_node` / `contains_key`. security-plan §Input Validation (`id` row) forbids it.
- Adding a job-level `permissions` grant to ci.yml, or a cargo leg without `--locked`, when making the a11y leg a gate. security-plan §Authentication & Authorization (RBAC row for ci.yml) and §Dependency Security (Supply chain integrity) forbid both.

## Contract bindings
- security ↔ a11y: the owed windowed witness of the refresh on change and of the three states (CARRY 3, 6) is the witness security-plan §Input Validation (`id` row; `aria-*` states row) records as owed for the ratified adapter crossing. a11y-plan §2 holds the witness side.
- security ↔ arch: if enabling the platform adapter on the stand opens an IPC endpoint or adds crates to seven_guis' graph, that is an arch §Occupied Resources registration before it lands (security-plan §API Security). Any new crates are read by the audit leg, cargo-deny over `deny.toml`'s `[graph]` with `all-features = true` (security-plan §Dependency Security).
- security ↔ obs: a new name (CARRY 5) and any new engine read add no log field. The `host_log` / `mcp_log` needle census and obs-plan §3's silent census of stand tests hold the reading.
- security ↔ tests/CI: the merge gate lands in `.github/workflows/ci.yml` and `.github/scripts/ci-leg.sh`, and its invariants are pinned by `.github/scripts/test_ci_workflows.py`.
