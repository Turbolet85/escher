## Relevance
partial — the chunk's substance is a11y, tests, design and CI; arch governs where its code lands (blitz-tests checks, the seven_guis stand, the `a11y` leg), the feature graph behind CARRY 2/4, and how any engine change for every document (CARRY 11, 12) is recorded.

## Constraints
- The `a11y` leg is a contract of `.github/scripts/ci-leg.sh`: today it names three integration tests (`accessibility_hidden`, `accessibility_roles`, `focusability_updates`), it tees to `target/ci-logs/a11y.log` and exits with the leg command's status, and the leg set is pinned by `test_ci_workflows.py` in the `ci-scripts` leg; moving the stand checks into it changes that contract and its pin together (per architecture §Standard Contracts → CI contracts).
- The ci.yml `a11y` job is one of the slow jobs: it `needs` the four fast jobs, runs its leg through `ci-leg.sh`, installs `libfontconfig1-dev` through `apt-install.sh`, restores the test job's `workspace-test` cache key and never saves, and every `uses:` stays SHA-pinned; whether that job blocks a merge on the fork (a required status check, branch protection) is not stated by the plan and is research's question (per architecture §Infrastructure Patterns → CI/CD).
- Enabling the platform adapter on the stand (CARRY 2/4) changes a recorded feature graph: escher-driver names `accessibility` on dioxus-native-dom only, and both seven_guis binaries compile the tree override yet build no platform adapter — `accesskit_xplat` and `accesskit_winit` are in neither graph; seven_guis takes `dioxus-native` with `system-fonts` + `woff` only (per architecture §Established Decisions → [Driver session]; per architecture §Occupied Resources → Names).
- A new dependency edge for that adapter rides the coupled pins — winit is pinned exactly to `=0.31.0-beta.3` and accesskit at "0.25" with per-target platform adapters in `accesskit_xplat` — so no side is bumped alone (per architecture §Established Decisions → [Dependency pinning]; per architecture §Stack and Technologies → Accessibility).
- The shell rebuilds the platform tree, under `accessibility`, on a poll whose taken changed set was non-empty, and its windowed witness is recorded as owed; CARRY 3/6's witness must reach that path (`View::poll` → `AccessibilityState::update_tree(&dyn Document)` → `doc.accessibility_tree()`), not the document-level reader alone (per architecture §Cross-cutting Patterns → Invalidation and state integrity; per architecture §Standard Contracts → Mutation, query and CSSOM).
- `inert` is recorded unimplemented and a fix is an engine change for every document owned by this entry's CARRY; an `aria-activedescendant` read (CARRY 11) would be a further direct engine change beside the eight recorded, each of which is founder-ratified, flagged upstreamable against 434e0661 with its merge surface owned by a CARRY on "Quality gates" (per architecture §Established Decisions → [Unsupported features]; per architecture §Established Decisions → [Scrolling and input]).
- Incremental and non-incremental layout must stay identical; every new or widened stand check runs `for incremental in [false, true]` (per architecture §Design Philosophy → One incremental pipeline, safe identities).

## Patterns to follow
- Integration checks in blitz-tests: one behaviour per test-target file directly under `tests/blitz-tests/tests/`, opening with a `//!` doc, first asserting the fixture produces the condition, both layout modes; the per-task tables (`controls`, `tab_order`, `INPUT_NAMES`, `rendered`) stated once in `tests/blitz-tests/tests/common/mod.rs`, read by `mod common;` — a re-coloured or re-keyed stand moves those tables, not copies (per architecture §Conventions → Tests).
- The contrast reading goes through `Harness::text_contrast` / `contrast_ratio` / `TextContrast::required_ratio` (read-only from computed styles, `None` past opacity < 1, a filter or a background image) and the stand boots through `seven_guis::stand` (`LeanTask::ALL`, pinned 800×600 viewport, bundled DejaVu Sans, offline) — no second reader or boot path (per architecture §Standard Contracts → Test harness; per architecture §Standard Contracts → Headless stand (seven_guis, native only)).
- Stand styles live in each task's `const CSS: &str` emitted in a `style` element; a token re-colour (CARRY 7) is a stand edit in `examples/seven_guis/src/tasks/` (per architecture §Conventions → Apps and examples).
- The stable id reaches the tree as AccessKit `author_id` through `DioxusDocument`'s `Document::accessibility_tree` override, set from `element_ids()` keyed by `NodeId::as_u64()`, with `TextRun`s, the root and the synthetic `Window` carrying none; CARRY 1's assertion reads that crossing — whether the tree the shell hands the adapter is that override's output is research's question (per architecture §Standard Contracts → Dioxus DOM bridge; per architecture §Standard Contracts → Document core).

## Anti-patterns to avoid
- No new env var, listener, port or workspace crate without an §Occupied Resources registration — the chunk's work is stand markup, test code and a leg's test list (per architecture §Occupied Resources → Environment variables; per architecture §Occupied Resources → Network ports and listeners).
- No unrecorded engine change for every document: an `inert` or `aria-activedescendant` fix lands only with the founder's ratification and the [Scrolling and input]-shape record (upstreamable flag, merge surface, CARRY owner) (per architecture §Established Decisions → [Scrolling and input]).
- No `[[test]]` table or `autotests` change in `tests/blitz-tests/Cargo.toml` to fold checks into the leg — the manifest holds exactly one `[[test]]` (`all`, `test = false`), pinned by `test_blitz_tests_targets.py` (per architecture §Standard Contracts → CI contracts).

## Contract bindings
- arch ↔ tests/a11y: the `a11y` leg's test list (`ci-leg.sh`) is the gate a11y-plan §9 counts and test-plan names; changing it moves the `test_ci_workflows.py` pin in the `ci-scripts` leg (architecture §Standard Contracts → CI contracts).
- arch ↔ security: the platform adapter crossing (ids as `author_id`, names, three states) is a ratified carrier whose windowed witness is owed; enabling the adapter on the stand binary is a boundary widening recorded in both plans (architecture §Standard Contracts → Mutation, query and CSSOM).
- arch ↔ design: a stand colour change moves the `stand_contrast` record and `common::controls` (architecture §Conventions → Tests).
