## Patterns to follow
- Shared stand-check tables and readers in `tests/blitz-tests/tests/common/mod.rs` — `tab_order`, `focused`, `controls`, `INPUT_NAMES`, `rendered` — as the single stated expectation every stand assertion reads (per a11y-plan §5 Test harness pattern; a11y-plan §7 Accessibility tree output).
- Every stand check runs `for incremental in [false, true]` and asserts its table row for row, with the row count stated — the state check's "one stated table per attribute with its row count asserted" (per a11y-plan §3 A11y Assertion Harness Contract).
- Contrast is measured read-only through `Harness::text_contrast` beside a painted-pixel witness of each measured background (matched within 1 per channel), the pair and ratio asserted per row of `stand_contrast`'s table (per a11y-plan §6 Visual Design Verification; a11y-plan §3 A11y Assertion Harness Contract).
- Keyboard input is synthesized through the harness's `press` / `press_with`, reading the focused node back per step (per a11y-plan §3 A11y Assertion Harness Contract, Keyboard test harness).
- Tree-level reads go through `Document::accessibility_tree` (the override that carries `author_id`), and the snapshot takes role, name, focus and the three states from that tree, never from the element (per a11y-plan §7 Accessibility tree output; a11y-plan §2 A11y Strategy).

## Anti-patterns to avoid
- Asserting SC 1.4.3 green while any measured row reads below its `required_ratio` — the five accent rows at 4.39 must be re-coloured (moving the record) before a pass assertion, not loosened or exempted; the exempt-inactive class is reserved for `enabled` `Some(false)` rows only (per a11y-plan §6 Visual Design Verification).
- A second role, name or focus-order mapping inside a test — expectations live in the shared module's tables (per a11y-plan §7 Accessibility tree output).
- Reading `has_changes()` on a freshly booted harness document as "this step changed something" without draining first — the boot marks the changed set (per a11y-plan §2 A11y Strategy).
