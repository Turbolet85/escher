## Relevant amendment history
- **2026-10-06-accessibility-tree-identity** — added the defaulted `Document::accessibility_tree()` (under `accessibility`), which only `DioxusDocument` overrides to set each element node's AccessKit `author_id` to its stable id. `TextRun`s, the document root and `Window` get none, and no tree id indexes the slab. It also fixed `build_accessibility_tree`'s three name sources: text children via `labelled_by`, a trimmed `aria-label`, and a bound `<label>` pushed onto the input's `labelled_by` after the visit. And it recorded the feature wiring: dioxus-native-dom `accessibility` = `["blitz-dom/accessibility", "dep:accesskit"]`, blitz-tests names it, seven_guis does not. This is the join the snapshot's id, role and name must read from rather than derive a second time, and the source of the P4 fork on feature gating. Trap: an item behind a feature can pass under `cargo test --workspace` and be compiled out under `-p blitz-tests`. Check with `cargo tree -e features -i`.
- **2026-10-06-stable-element-ids** — registered `DioxusDocument::element_id(NodeId) -> Option<String>` (`None` for a non-element, stale or detached node; never panics) and `element_ids() -> Vec<(NodeId, String)>` (document pre-order, pairwise distinct). Both are computed on demand and written to neither the DOM nor the vdom. The id grammar is author key, then component path, then document path, with no `NodeId`/`ElementId`/`ScopeId` in an id. `element_id` became a crate-private module. A detached node keeps resolving but reads no id. The snapshot id must equal this function's output, so the chunk's walk inherits its pre-order, its distinctness guarantee and the detached-node rule. Later chunks, the snapshot named among them, address elements by this grammar.
- **2026-10-06-id-persistence** — proved the id the same across a re-render, a remount and a new process, in both layout modes. The lean CRUD row is keyed by `person.id` (`…/div[{person.id}]`). It also registered the test-binary re-exec spawns (`stand_id_persistence`, `telemetry_stdout_silent`) under Process-wide state. This chunk relies on it because snapshot ids on CRUD rows follow these keys, and a snapshot proof that re-execs a test binary would need the same registration. Trap: the four skeleton elements (`/html:0`, `/html:0/head:0`, `/html:0/body:0`, `main`) are built outside the VirtualDom and never remounted. Any snapshot built from every element will include them.
- **2026-10-06-headless-stand** — added the Headless stand contract: `seven_guis::stand` with `LeanTask`, pinned at 800×600, scale 1.0 and Light; the `font_ctx()` bundled DejaVu font; `options(incremental)` offline; and `boot` / `boot_timer` with `TimerTicks`. It also added `HarnessOptions.font_ctx` / `incremental` and the edges from blitz-tests to seven_guis. Separately, it recorded that `disabled` is read two ways: focusability parses it as a bool, while `:disabled`/DISABLED and the click target key on presence. The Dioxus writer clears a falsy `checked`/`disabled` but writes every other boolean as `"false"`. This defines the boot path, the viewport the bounds are checked against, and the trap the snapshot's `enabled`/`checked` state fields inherit.
