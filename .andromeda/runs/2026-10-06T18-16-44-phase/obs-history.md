## Relevant amendment history
- **2026-10-06-telemetry-bootstrap** — Set up the rules the extract leans on. §2 says tracing is compiled only under each engine crate's `tracing` feature, while escher-telemetry itself is ungated. §8 sets the allowlist scrub. Engine prefixes (`blitz`, `dioxus_native`, …) print only `node_id`, `status`, `waiting_nodes`, `property` and the `log.*` fields. The keys `url`, `href`, `src`, `html`, `text`, `value`, `attrs`, `path`, `request`, `error` and `panic.payload` are redacted at every target, but only in escher's sink. Upstream `fmt::init()` sinks stay unscrubbed (`pii-scrubbing-wire` is still open for them). For this chunk, any snapshot-build event must fit that allowlist. The snapshot's `name`, `role` and id fields are not in the redact set, so the rule is to emit none of them, not to rely on the scrub. Adding a new field means amending the allowlist sets in `escher-telemetry/src/format.rs`.
- **2026-10-06-headless-stand** — Set the precedent that the headless stand `seven_guis::stand` and its in-process checks install no subscriber, call no `println!` and read no env var, so a headless boot has no escher sink. Only the windowed `seven_guis_native` installs `escher_telemetry::init`. The new `stand_snapshot*` check must keep this shape.

The parent captures them and reads them only into an assertion, never into a log. This is the bar for any stand check that prints. If the snapshot proof needs a fresh-process leg, it must follow this exact shape and amend §3 again. Otherwise it prints nothing.

Assertion messages that quote names or values land only in the unscrubbed `run.log`.
