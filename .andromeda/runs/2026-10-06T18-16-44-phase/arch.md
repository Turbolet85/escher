# arch extract

## Relevance
relevant: the chunk adds a new public in-process contract (snapshot types and builder) across the blitz-dom / dioxus-native-dom boundary, consuming the stable-id, accessibility-tree and layout contracts the plan records.

## Constraints
- **Crate placement and module boundary.** Per architecture §Design Philosophy ("Radically modular, embeddable engine"), blitz-dom is the headless DOM that wrappers such as `DioxusDocument` drive. Per §Standard Contracts → Dioxus DOM bridge and §Existing Scopes (dioxus-native-dom: `element_id` is crate-private), the stable id exists only at the dioxus-native-dom level. A builder that emits the stable id therefore cannot live in blitz-dom alone. Which crate owns the snapshot types and builder (dioxus-native-dom, or blitz-dom types plus a dioxus-native-dom join) is a P4 decision. It must create no new workspace member unless §Occupied Resources → Names registers one first.
- **The id is the stable element id, never a slot id.** §Standard Contracts → Dioxus DOM bridge requires the id to come from `element_id` / `element_ids`: computed on demand, never written to the DOM or the vdom, and with no `NodeId`, `ElementId`, `ScopeId` or pointer inside it. Per §Established Decisions → Node identity and §Standard Contracts → Scrolling, selection, tree (`NodeTree` stale-id indexing panics), any `NodeId` the builder holds while walking must be read through `get`/`contains_key` (§Cross-cutting Patterns → Invalidation and state integrity). It must never be indexed blind or exposed as the snapshot id.
- **Role and name come from the accessibility contract, not a second derivation.** §Standard Contracts → Mutation, query and CSSOM fixes `build_accessibility_tree`'s three name sources (text children via `labelled_by`, a trimmed `aria-label`, and a bound `<label>`). §Design Philosophy ("Behave like a browser, and cite the spec") records the HTML-AAM role mapping in `accessibility.rs`. §Standard Contracts → Document core makes `Document::accessibility_tree` the overridable entry, and `DioxusDocument` alone enriches it. The snapshot's role and name must be read from that contract so the two cannot disagree. Whether reading the built `TreeUpdate` or sharing the derivation is the right join is research's question.
- **The `accessibility` feature wiring constrains where the snapshot compiles.** §Standard Contracts → Dioxus DOM bridge records that dioxus-native-dom's `accessibility` is `["blitz-dom/accessibility", "dep:accesskit"]`. A crate taking either Dioxus crate with `default-features = false` (§Conventions → Manifests) gets the override only by naming the feature: blitz-tests names it and seven_guis names none. §Cross-cutting Patterns → Config management makes optional capabilities forwarded Cargo features. If the snapshot rides `accessibility`, both its gating and its feature-off behaviour must be explicit (the scope's P4 fork).
- **Bounds live in one CSS-px space with known geometry quirks.** §Standard Contracts → Mutation, query and CSSOM fixes `BoundingRect { x, y, width, height }` in f64. §Established Decisions → CSS approximations snaps CSSOM geometry to 1/64 px. §Established Decisions → DOM semantics stores transforms and `scrollable_overflow` in device pixels. §Design Philosophy ("One incremental pipeline") records Taffy output as lazily boxed because inline-level elements are positioned by Parley, and §Established Decisions → Layout says text nodes are never laid out individually. The stand pins `HIDPI_SCALE = 1.0` and an 800x600 viewport (§Standard Contracts → Headless stand). Per §Project Intent (upstream sync `23354585`), the CARRY's inline-fragment APIs come from upstream, and §Existing Scopes lists `inline_fragment_rects.rs` among the tests. Whether an inline element's box comes from those APIs or the block box is research's question.
- **Incremental and non-incremental parity.** §Design Philosophy ("One incremental pipeline, safe identities") requires the two layout modes to produce identical results. §Conventions → Tests runs scenarios `for incremental in [false, true]`. A snapshot derived from layout inherits that obligation.
- **Public-surface hygiene.** §Conventions → Documentation requires `///` on public items, and §Conventions → Formatting and lints holds every workspace library crate to rustdoc `-D warnings` (`cargo doc --workspace --no-deps --locked`). §Conventions → Visibility and naming keeps internals `pub(crate)` / `pub(super)`. §Cross-cutting Patterns → Error handling requires typed results (`element_id` returns `Option` and never panics), not panics, on new APIs.

## Patterns to follow
- **The id join in the accessibility override:** build the base tree, map `element_ids()` by `NodeId::as_u64()`, and attach the stable id to element nodes only. `TextRun`s, the document root and the synthetic `Window` carry none (per §Standard Contracts → Dioxus DOM bridge). The snapshot's id/role/name join can mirror this, and the accessibility nodes the snapshot reads are those same nodes.
- **On-demand, read-only derivation:** like `element_id(s)`, compute the snapshot from a walk at call time and write nothing to the DOM or the vdom (per §Standard Contracts → Dioxus DOM bridge). Any DOM change goes through `DocumentMutator` (§Conventions → DOM API patterns), and a read-only snapshot should need none.
- **Stand boot for the proof:** use `seven_guis::stand::boot(LeanTask, options(incremental))` → `Harness<DioxusDocument>` with the pinned viewport, bundled font and offline `DummyNetProvider`, plus `boot_timer` for the timer (per §Standard Contracts → Headless stand). Use the harness inspection (`layout_rect`, `layout_rect_of`, `base`) as the bounds cross-check (per §Standard Contracts → Test harness).
- **Integration-test shape:** one behaviour per `tests/blitz-tests/tests/stand_*.rs` file opening with a `//!` doc, `#[track_caller]` assertion helpers, a first assertion that the fixture produces the condition under test, and both layout modes (per §Conventions → Tests).
- **Tracing per call site:** any span or event on the snapshot build is `#[cfg(feature = "tracing")]` with a no-op fallback. In dioxus-native-dom that means the crate-local `trace!` macro, whose 4-argument arm passes only two items (per §Conventions → Feature gating).

## Anti-patterns to avoid
- Exposing or deriving the snapshot id from `NodeId` / `ElementId` / `ScopeId`, or indexing a possibly stale `NodeId` (per §Standard Contracts → Dioxus DOM bridge and §Standard Contracts → Scrolling, selection, tree).
- A second role/name derivation beside `build_accessibility_tree`, or persisting snapshot data into the DOM or vdom (for example, reaching through `DocumentMutator::doc`) (per §Standard Contracts → Mutation, query and CSSOM and §Conventions → DOM API patterns).
- A new workspace crate, env var, port or listener for the snapshot without a §Occupied Resources registration first (per §Occupied Resources → Names / Environment variables / Network ports and listeners).

## Contract bindings
- **arch ↔ a11y:** role, name and `author_id` come from the accessibility-tree contract (§Standard Contracts → Document core / Dioxus DOM bridge). `accessibility` is a default feature, and the snapshot's behaviour with it off binds to the a11y plan's surface.
- **arch ↔ tests:** the stand proof uses the headless-stand and harness contracts (§Standard Contracts → Headless stand / Test harness). blitz-tests already names `accessibility` on dioxus-native-dom and seven_guis names none (§Standard Contracts → Dioxus DOM bridge), so the test crate's feature set decides whether the snapshot compiles there.
- **arch ↔ obs:** an accessible name and a control value are user content. Engine tracing is gated per call site (§Conventions → Feature gating), and escher-telemetry's allowlist scrub (§Standard Contracts → Telemetry bootstrap) only redacts what reaches it. A span on the build logs counts only.
- **arch ↔ state fidelity (next chunk):** `disabled` is read two ways: focusability parses it as a boolean, while element state and `:disabled` key on attribute presence (§Established Decisions → DOM semantics). The Dioxus writer clears a falsy `checked`/`disabled` but writes other booleans as the literal `"false"` (§Standard Contracts → Dioxus DOM bridge). The `enabled` and `checked` fields this chunk adds will inherit whichever reading they use. Which one is a P4 decision, and its fidelity is v010-05's to prove.
- **Wrap registration:** the snapshot types and builder are a new public contract, recorded at wrap in §Standard Contracts (for example, beside the Dioxus DOM bridge entry). The §Existing Scopes rows of the touched crates are updated if a module is added.

## Acceptance criteria contributions
- For every snapshot node on each lean task, the id equals `DioxusDocument::element_id` of the same element and that element's AccessKit `author_id`. No id contains a `NodeId`/`ElementId`/`ScopeId`-derived token, and the ids are pairwise distinct (per architecture §Standard Contracts → Dioxus DOM bridge).
- On each lean task, the snapshot is identical for `incremental` false and true (per architecture §Design Philosophy, "One incremental pipeline, safe identities").
- No new workspace member, env var, port or listener: the root `Cargo.toml` members and §Occupied Resources are unchanged by the chunk except for the wrap's §Standard Contracts registration (per architecture §Occupied Resources → Names / Environment variables).
- The new public snapshot types and builder carry `///` docs, and `bash .github/scripts/ci-leg.sh doc` exits 0 (per architecture §Conventions → Documentation / Formatting and lints).
