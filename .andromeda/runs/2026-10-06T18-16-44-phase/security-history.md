## Relevant amendment history
- **2026-10-06-accessibility-tree-identity** — the stable id reaches the platform accessibility API; accessible-name attributes row. The `id` row changed from "written nowhere" to "written to no log, DOM or vdom". It now leaves the process only as AccessKit `author_id`, set on element nodes only, never on a `TextRun`, the document root or `Window`, and never by indexing the slab with a tree id. A new `aria-label` · `<label for>` row says: whitespace-only names nothing, a label associates only when both nodes are built, no lookup panics, and names are logged nowhere. Why it matters here: this is the row the extract's id, role and name constraints rest on. Its **standing rule says "any further consumer of the id beyond the platform accessibility API re-opens this row"**. The snapshot is such a consumer, so the plan must re-open the `id` row at wrap, even as an in-process-only reader, and state that the snapshot adds no second crossing. The ratification also set a CARRY on "Stand a11y assertions": `author_id` never carries a `NodeId`, `ElementId` or pointer form. The snapshot's id-equality assertion should reuse that no-engine-id check. The name-source read was judged not a boundary widening at P4 through a recorded playbook read. That is the precedent for this chunk's role and name read.
- **2026-10-06-stable-element-ids** — the `Markup attributes | id` row was created. `element_id` / `element_ids` read the HTML `id` as an author key only when it is non-empty, `/`-free and the first in pre-order. Otherwise the element falls back to its path, so no two ids are ever equal. Non-element, stale or detached nodes read `None`. No path panics, and there is no engine id or pointer. It was judged "an in-process reader of an already-admitted attribute … not a boundary widening". Why it matters here: the snapshot's id must be this reader's output, so that pairwise distinctness and the `None`-on-stale behaviour are inherited rather than re-derived. This entry is also the precedent for classing the snapshot builder as an in-process reader, not a widening.
- **2026-10-06-id-persistence** — the `id` row gained two facts. Keyed list rows carry `{tag}[{key}]`. The CRUD row key is the model-assigned `u64` (fixture people 0–2, Create from 3), never an index, pointer, hash, clock or process-local value. A dropped pre-remount `NodeId` reads `None` without panic. Why it matters here: the CRUD task is one of the four lean stand tasks the snapshot check boots. Its row ids in the snapshot must be these key-bearing ids. The stale-`NodeId`-reads-`None` guarantee is the one the builder's panic-safety constraint relies on.
- **2026-10-06-telemetry-bootstrap** — escher's sink was added: stderr only. Engine targets print only `node_id`, `status`, `waiting_nodes`, `property` and `log.*`. Fields named `url`, `href`, `src`, `html`, `text`, `value`, `attrs`, `path`, `request`, `error` and `panic.payload` are redacted at any target. `logging-redaction-wire` is discharged only for that sink and stays open for the upstream `fmt::init()` and WPT `env_logger`. Why it matters here: this is the exact allowlist and content scrub set behind the extract's "counts only, never emit content" rule. The snapshot's `value` and `text`-like fields share names with redacted fields. Because the scrub's reach is that one sink only, a census of call sites is the guarantee, not the scrub.
- **2026-10-06-headless-stand** — `disabled` row. It is parsed as a bool for focusability only. Its mere presence, including `disabled="false"`, sets the DISABLED state and blocks pointer selection and click defaults. The change was measured on the stand. Why it matters here: the snapshot's state record fills `enabled` from the engine's current reading, and that reader has a known security-plan-recorded split. Proving the `disabled="false"` case is v010-05's job, per the extract's security ↔ tests binding. Still, this chunk must not record or claim a reading that contradicts this row.
