# arch extract

## Relevance
relevant — the chunk adds a public API and a constant beside the snapshot model in `dioxus-native-dom`, builds the first wire form of a contract the plan records as having none, and may add a dependency edge.

## Constraints
- **Placement.** architecture §Existing Scopes → dioxus-native-dom requires the snapshot code to live in that crate's `snapshot` module (crate-private, compiled only under `accessibility`, its public items re-exported from the crate root); the serializer and the budget constant belong there or in a sibling module of the same crate. No new workspace crate (architecture §Infrastructure Patterns → Directory structure; §Occupied Resources → Names).
- **Feature gate.** architecture §Cross-cutting Patterns → Config management and §Standard Contracts → Dioxus DOM bridge require the snapshot surface to sit behind `dioxus-native-dom`'s `accessibility` feature, which a consumer taking the crate with `default-features = false` gets only by naming it. The serializer inherits that gate. Whether blitz-tests' manifest still names the feature at HEAD is research's question.
- **The model is the only source.** architecture §Standard Contracts → Dioxus DOM bridge fixes the `Snapshot` / `SnapshotNode` / `NodeState` field set and names the one reader behind each field, the password mask included. The text form must be written from those model values alone — no second reading of a control, an id, a role or a rect.
- **Public contract addition in a published crate.** `dioxus-native-dom` is one of the published `packages/` crates versioned together (architecture §Inherited Defaults → Publishability), and its public items also reach `dioxus-native` through that crate's glob re-export (§Standard Contracts → Dioxus DOM bridge). The same bullet records earlier additions of this kind as ratified by the founder, so a new public function and constant is a P4 item, not a silent add. That bullet's sentence that the snapshot has no wire form is the one this chunk falsifies — a wrap amendment, not a phase edit.
- **Dependency edge.** architecture §Conventions → Manifests requires a dependency to be declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }`. The plan lists `serde` in the workspace table (§Stack and Technologies → Media) and `serde_json` only under the WPT runner's own manifest (§Stack and Technologies → Testing); whether the root manifest carries a workspace `serde_json` entry, and whether `dioxus-native-dom` names either, is research's question. A format needing one changes `Cargo.lock`, which every cargo leg reads `--locked` (§Standard Contracts → CI contracts) and which re-mints the fork's CI cache keys (§Occupied Resources → CI infrastructure); the coupled pins stay untouched (§Established Decisions → [Dependency pinning]).
- **No new occupied resource.** architecture §Occupied Resources (Network ports and listeners · Environment variables · Filesystem · Process-wide state and threads) requires every new listener, env var, runtime path, static or spawned process to be registered. A returned value and a Rust constant register nothing. A budget record written to a runtime path, or a fresh-process determinism proof that re-executes the test binary (the registered precedent is under Process-wide state and threads), would be a registration at wrap.
- **Gates.** architecture §Conventions → Formatting and lints requires fmt, clippy `-D warnings` and rustdoc `-D warnings` over every workspace library crate; §Conventions → Documentation requires a `//!` on a new module, `///` on each public item and a stated rationale on a constant — the budget constant's doc names the cap it rests on.

## Patterns to follow
- **On-demand, read-only, argument-light.** The id and snapshot APIs are computed on demand, write to neither the DOM nor the vdom and never panic (architecture §Standard Contracts → Dioxus DOM bridge). A serializer follows the same shape: a pure function of a `Snapshot`, visiting nodes in the pre-order `Snapshot::nodes()` already defines, so the text adds no ordering of its own.
- **Public data types and constants.** The snapshot's types are `Debug`, `Clone`, `PartialEq` and re-exported from the crate root, and `MASKED_VALUE` is the precedent for a public, re-exported constant (architecture §Standard Contracts → Dioxus DOM bridge); a new public type or the budget constant follows it. If the serializer can fail, its error is a typed enum with `Display` (§Conventions → Error handling; §Cross-cutting Patterns → Error handling).
- **Bounds as fixed-precision numbers.** `bounds` is a `BoundingRect` of four `f64` (architecture §Standard Contracts → Mutation, query and CSSOM), and the plan records CSSOM geometry as snapped to 1/64 px (§Established Decisions → [CSS approximations]). Whether the rect the snapshot's reader returns is so snapped is research's question; either way the number formatting must be one fixed rule so the same rect always prints the same bytes.
- **Stand check shape.** One integration-test file per behaviour, opening with a `//!` doc, scenarios run `for incremental in [false, true]`, the fixture's own condition asserted first; unit tests in `#[cfg(test)] mod tests` at the end of the source file (architecture §Conventions → Tests). The screens come from `seven_guis::stand` — `LeanTask::ALL`, `options(incremental)`, `boot` / `boot_timer` — at the pinned viewport, bundled font and no network (§Standard Contracts → Headless stand).
- **One pipeline, two modes, one result.** architecture §Design Philosophy → One incremental pipeline, safe identities requires incremental and non-incremental layout to agree; the serialized text is a new observable of that invariant and must be byte-identical across the two.

## Anti-patterns to avoid
- **Process-local identity in the text.** No `NodeId`, AccessKit tree id, `ElementId`, `ScopeId` or pointer may enter a snapshot field (architecture §Standard Contracts → Dioxus DOM bridge); the wire form carries the stable element id only, and no index or handle minted for the text.
- **Library code that prints or logs the text.** Engine telemetry is `tracing` gated per call site with a no-op fallback, and escher's sink is stderr-only (architecture §Conventions → Feature gating; §Cross-cutting Patterns → Logging and timing). The serializer returns its text; it has no `println!`, and the text is never a `tracing` field.
- **A silent add.** A new crate, dependency, env var, path or process without its registration (architecture §Occupied Resources), or a one-sided bump of a coupled pin to make a format crate resolve (§Established Decisions → [Dependency pinning]).

## Contract bindings
- **arch ↔ security.** The "no wire form" sentence of architecture §Standard Contracts → Dioxus DOM bridge is the architectural twin of the security plan's input-validation rows on ids, accessible names and control text. The first wire form is a boundary widening; security owns the ruling on where the text may go, arch owns the amended contract sentence at wrap.
- **arch ↔ tests.** The stand check binds to the harness and stand contracts (architecture §Standard Contracts → Test harness; → Headless stand) and to the agent-run test contract's `run stand` selection (§Standard Contracts → CI contracts). Whether a new `stand_*` file joins that selection without an edit is research's question.
- **arch ↔ a11y.** The snapshot is built from the `accessibility_tree` override and its roles are `accesskit::Role` values (architecture §Standard Contracts → Dioxus DOM bridge). How a role is spelled in the text binds to a11y's role vocabulary; a spelling taken from the type's `Debug` output would couple the wire form to the accesskit pin (§Stack and Technologies → Accessibility) — a P4 consideration.
- **arch ↔ obs.** The serialized text is content: it stays outside the telemetry line shape and its scrub sets (architecture §Standard Contracts → Telemetry bootstrap).
- **Forward binding.** architecture §Project Intent names the driver (CLI + MCP) as the consumer of the compact snapshot, and §Standard Contracts → Dioxus DOM bridge records that no driver, CLI or MCP command exposes it yet. The form chosen here is the one those surfaces and the diff will carry; this chunk adds none of them.
