## Constraints
- The command and refusal schema is stated once, as `'static` data (`VERBS`, `NODE_FIELDS`, `KEY_NAMES`, `BUSY_CLASSES`, `CAUSES`), and its three schema modules carry no `cfg` gate and use no serialization crate. So any served verb list, help, argument or result shape, node-key help or exit-status meaning must be read from that data, and both surfaces must read the same data (per arch §Standard Contracts → Driver session). Whether a node key or an exit status already has a text of its own in the table is research's question.
- Every answer has one written form: a line of JSON written by hand in the crate-private `json` module, which the command line, client, host and MCP server already read. `serde_json` reads MCP requests and writes nothing, on the founder's word. Any new served JSON (a schema object, a result shape, a cause or error table) must go through `json` and never through `serde_json` (per arch §Standard Contracts → Driver session; per arch §Established Decisions → [Driver session]).
- The MCP contract states exact counts that this chunk could move: `tools/list` answers "the nine verbs of `VERBS` in order"; `initialize` speaks `2025-06-18` · `2025-03-26` · `2024-11-05` only; `initialize`, `ping`, `tools/list` and `tools/call` are answered, and every other method, `server/discover` included, gets `-32601`; a result is `{content:[{type:"text",text}], isError}` with no `structuredContent`. Each of these is moved by any of the following: a `help` row in `VERBS`, a new answered method, a new revision, or a result-field or output schema on a tool (per arch §Standard Contracts → Driver session).
- The command line's endings are fixed. There are four: accepted on stdout with status `0`; refused on stdout with `1`; usage as one fixed line on stderr "built from `VERBS` and the app names", stdout empty, with `2`; session error with `3`. No ending writes back anything the caller typed. The reader's rule order is fixed: `serve` shape, `mcp` alone, verb lookup, `validate`/`validate_session` before `--session`. A served help or schema on the CLI must keep to these rules or restate them explicitly (per arch §Standard Contracts → Driver session; per arch §Standard Contracts → CLIs).
- `Cause` is closed at eight, each with a fixed `name()`, `meaning()` and `remedy()`, and a `Refusal` holds nothing a call supplied. `SessionError` is exactly thirteen, each with a fixed `kind()` word and a fixed message that carries no path, label, id or value. Its JSON is `{"error":{"kind","message"}}`, with no remedy field. Each past rewording of a cause text rode a recorded word. A remedy or a stated bound added to a session error (CARRY 3) must therefore stay a fixed `'static` string and change its written form only explicitly (per arch §Standard Contracts → Driver session).
- The resource registry has no room for silent additions: no network port, and the session socket stays the one listener. The `mcp` role speaks over its own stdio with no listener. The crate names are fixed (escher-driver: four dependencies, `publish = false`, no binary target), and so are the MCP server name `escher` and the env var list (`RUST_LOG`, `WPT_DIR`, `PAINT_TREE_BENCH_HTML`, CI vars). Any new resource is an arch §Occupied Resources registration (per arch §Occupied Resources → Network ports and listeners; per arch §Occupied Resources → Names; per arch §Occupied Resources → Environment variables).
- escher-driver names no app and no stand type, reads no env var, has no default state location, emits no `tracing` event and opens exactly two spans: `command`, with eight fixed-word or count fields, and `tool_call`, with `tool` and `ending` only. A self-description path must add no span field holding what a call supplied or a screen reads. Whether a served-help request produces a `command` or `tool_call` span, and with which `verb`/`tool` word, has to be decided against these field sets (per arch §Established Decisions → [Driver session]; per arch §Standard Contracts → Driver session).

## Patterns to follow
- Limits and behaviour are stated as fixed literals of the verb table, where an agent reads the tool. Examples: `changed`'s help and `snapshot`'s `text` help, which carry the state words and the two limits of the boolean model; `covered`'s meaning carrying the `contain: paint` reading; `type`'s help saying it replaces. This is the operator's rule of 2026-10-10: "a measured limit is stated where an agent reads the tool" (per arch §Standard Contracts → Driver session).
- `tools/list` already derives each tool from a `VerbSpec`: its `help` becomes the `description`, and the `inputSchema` gets a property per `ArgSpec` by its `ArgKind` with bound, the required set, `additionalProperties: false`, and `start`'s `app` as an `enum` of the binary's apps. A served result shape or node-key help should be derived the same way, from `FieldSpec { name, kind, always, help }` (per arch §Standard Contracts → Driver session).
- The usage line is built from `VERBS` and the app names, not hand-written. Any CLI help output follows the same generation-from-table shape (per arch §Standard Contracts → Driver session).
- Unit tests go inline in `#[cfg(test)] mod tests` at the end of the source file. Each integration-test file covers one behaviour. Stand scenarios run `for incremental in [false, true]`. Checks that hold a `Session` share `tests/blitz-tests/tests/session_common/mod.rs`, and seven_guis' process checks share `examples/seven_guis/tests/common/mod.rs` (`Speaker` for the `mcp` role) (per arch §Conventions → Tests; per arch §Occupied Resources → Process-wide state and threads).
- escher-driver is `#![deny(missing_docs)]` and every library crate is held to rustdoc `-D warnings`. Any new public item, such as a schema constant or a help accessor, carries `///` docs, and the crate re-export count (41 today) moves explicitly (per arch §Standard Contracts → Driver session; per arch §Conventions → Documentation).

## Anti-patterns to avoid
- Restating schema text outside the table, for example a hand-written help string in `cli.rs` or `mcp.rs`, or exit-status meanings kept only in a `cli.rs` doc comment. Equally banned: a second verb table or a parallel serde-derived schema (per arch §Standard Contracts → Driver session).
- Letting a `NodeId` cross either surface. This applies to exposing `DioxusDocument::unkeyed_actionable()`, whose `UnkeyedActionable.node` is a process-local `NodeId`, as a command (CARRY 2). "no `NodeId` crosses" is a stated invariant of the socket and MCP crossings (per arch §Established Decisions → [Driver session]; per arch §Occupied Resources → Network ports and listeners).
- Adding a dependency, crate, `[features]` table or `cfg` gate to escher-driver or its schema modules to serve the schema. Its four dependencies and the "no serialization crate in the schema modules" rule are recorded decisions (per arch §Established Decisions → [Driver session]; per arch §Standard Contracts → Driver session).
