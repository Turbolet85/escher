# arch extract

## Relevance
relevant — the chunk adds behaviour to three recorded contracts (the headless `Harness`, the `Document` trait's `poll`, the driver `Session`) and fills an item architecture §Standard Contracts → Driver session lists under "Not built" (settle).

## Constraints
- **Placement: existing crates only.** architecture §Occupied Resources → Names fixes the workspace's crate, binary and feature names, and architecture §Infrastructure Patterns → Directory structure fixes the `packages/` set; settle lands in crates already listed there (blitz-test-harness, blitz-dom, dioxus-native-dom, escher-driver, seven_guis, blitz-tests). A new crate, binary or feature name is a registration in architecture §Occupied Resources → Names first, not a silent add.
- **Dependency direction: the driver names no app.** architecture §Established Decisions → [Driver session] requires that no manifest under `packages/` names an example and that the one edge runs `seven_guis → escher-driver`; so nothing settle adds to escher-driver or blitz-test-harness may name a stand type (`TimerTicks`, `LeanTask`). If the timers decision has settle advance ticks, the tick source is supplied by the caller (the host or the check), never imported by the library. The same decision requires that the library read no env var, carry no `tracing` dependency, span or event, and name no `dioxus-native-dom` feature — it reserves that last choice for the entry that first reads the snapshot through a session, so settle must not need `accessibility`; whether it can be built without it is research's question.
- **The session's recorded shape changes only by amendment.** architecture §Standard Contracts → Driver session requires that a `Session` hold a label and the harness only, that it neither read nor drain the changed set, that `SessionError` be exactly its eleven listed variants with fixed-string messages carrying no path, label, id or value, and that the wire stay `hello` / `stop` under `v1`. A settle entry point on the session, a settle outcome type (new, or a variant added to `SessionError`), and any read or drain of the changed set by settle are each a contract change to state in the plan and record at wrap; the outcome that names a still-busy source must name the source class only — no id, name or value.
- **`Document::poll` is a five-implementor trait contract.** architecture §Standard Contracts → Document core records `poll` as a default-`false` trait method implemented for `PlainDocument`, `BaseDocument`, `Rc<RefCell<BaseDocument>>`, `HtmlDocument`, `ScriptDocument` and overridden by `DioxusDocument`. Any quiescence reader added at trait level needs a default that keeps every other implementor's behaviour, and a change to what `poll` returns changes behaviour for every Blitz document — the class of change that contract records as founder-ratified for the changed set. Whether the existing `poll` return value already carries the render signal the scope infers is research's question.
- **The changed set is not a quiescence signal.** architecture §Cross-cutting Patterns → Invalidation and state integrity requires that the changed set be written only by tracked mutations, focus / checked changes and typed text, and not by a resource load, an animation, layout, scroll or hover; three of the entry's four sources (layout, timers-as-animation, pending loads) therefore leave it empty while still busy. Settle reads its own per-source signals; `has_changes` may corroborate render work at most.
- **Loads are applied inside `resolve`, behind a gate.** architecture §Infrastructure Patterns → Runtime threading and event flow records that each document's message channel is drained at the start of `resolve` and fixes the resolve order (messages, critical-resource gate, …, sub-documents last); architecture §Established Decisions → [Resource loading] records that `resolve` returns before styling while a render-blocking stylesheet is pending. A settle loop must treat "resolve returned" as not-yet-laid-out while that gate holds, and must count a sub-document's work. Whether the three pending collections the scope names cover every in-flight request is research's question; architecture §Standard Contracts → Provider traits adds that a provider reporting `is_noop()` registers no pending-critical resource, which is what the offline stand relies on.
- **The windowed path keeps its poll contract.** architecture §Standard Contracts → Mutation, query and CSSOM requires that `View::poll` take the changed set on every poll that reported work and refresh the platform accessibility tree when that set was non-empty ("refresh, then drain"); settle is a headless caller of the same `Document` methods and must leave that sequence, and what `poll` reports to the shell, unchanged.

## Patterns to follow
- **The existing headless load loop** — architecture §Infrastructure Patterns → Headless loading records the prior art: resolve repeatedly until the net provider reads empty, then resolve once more, with tests answering loads through a pluggable `NetProvider`. It is the shape the loads leg generalises; note it reads the provider, not the document, so it is a starting point and not the settle rule.
- **Virtual time, never the wall clock** — architecture §Design Philosophy → Headless, measurable, testable records JS timers run on virtual time in the WPT runner, architecture §Standard Contracts → JavaScript the `ScriptDocument` seam for it (`with_virtual_time`, `advance_clock_to`, `next_timer_deadline`), and architecture §Standard Contracts → Headless stand the stand's own seam (`TimerTicks::deliver`, `boot_timer` returning the handle beside the harness). The timers decision should be stated in terms of these seams: a source is advanced by its caller-held handle, and settle answers for what has been delivered.
- **A poll can queue more work** — architecture §Cross-cutting Patterns → Event processing records that `mounted` listeners fire after `initial_build` and after each `poll`, and architecture §Cross-cutting Patterns → Invalidation and state integrity that animations, transitions and smooth scrolls advance via `resolve(time)` and `is_animating()`. The settle loop is therefore poll → resolve → re-check, bounded, not a single pass; a periodic source is excluded by rule, as the scope's timers decision requires.
- **Typed, content-free edges** — architecture §Cross-cutting Patterns → Error handling requires fallible APIs to return typed results, and architecture §Standard Contracts → Driver session shows the house form: an enum with `Display` and `std::error::Error`, fixed-string messages, every wait bounded and ending in a named variant. The not-quiet-inside-the-bound outcome follows it; new public items in escher-driver also fall under that contract's `#![deny(missing_docs)]`.
- **Check layout** — architecture §Conventions → Tests requires one behaviour per integration-test file opening with a `//!` doc, scenarios run `for incremental in [false, true]`, shared stand tables and helpers stated once in `tests/common/mod.rs`, and each test first asserting that its fixture produces the condition under test — here, that the delayed update has not landed before settle is called.

## Anti-patterns to avoid
- **Waiting by thread, clock or wire.** architecture §Occupied Resources → Process-wide state and threads records the `escher-session` host as one process, one session, one listener on its main thread, spawning no thread; architecture §Occupied Resources → Network ports and listeners limits the socket to lifecycle messages. A helper thread, a wall-clock sleep or timeout inside settle, or a new verb to ask "settled?" across the socket is out of this chunk and would be a registration there first.
- **Reaching the stand from the library.** A `seven_guis` dependency, a `TimerTicks` import or a task-specific branch inside escher-driver or blitz-test-harness breaks architecture §Established Decisions → [Driver session].
- **Ungated or content-bearing logging.** architecture §Conventions → Feature gating requires engine-crate tracing behind `#[cfg(feature = "tracing")]` with a no-op fallback; architecture §Established Decisions → [Driver session] keeps escher-driver free of any `tracing` dependency. A `println!`, an unconditional event, or a field naming an element id or accessible name in the settle path is banned; the settle-wait span belongs to a later entry.

## Contract bindings
- **arch ↔ tests** — architecture §Standard Contracts → Test harness (the `Harness` surface: `pump`, the `HarnessOptions` fields including `net_provider` and `incremental`) binds to test-plan §3 and its keyed contracts `session-lifecycle` and `session-proof`: a settle entry point on the harness or session is a public addition both sides record, and the no-sleep rule is test-plan's while the virtual-time seams are arch's.
- **arch ↔ security** — architecture §Occupied Resources → Network ports and listeners (one listener, `hello` / `stop` only) binds to security-plan §Surfaces: settle staying in process is what keeps this chunk from opening a crossing question; the loads fixture's hand-written provider touches architecture §Standard Contracts → Provider traits (`NetProvider::fetch`, `NetHandler::bytes`) and security-plan's untrusted-input notes only as a test double.
- **arch ↔ obs** — architecture §Cross-cutting Patterns → Logging and timing (the sink admits engine and `escher_*` targets only; `debug_timer!` times resolve phases) binds to obs-plan §4 · §8: anything this chunk logs must sit under an admitted target with no content field, and the per-command span over the settle wait is left to the "Driver command spans" entry.
- **arch ↔ a11y** — architecture §Standard Contracts → Mutation, query and CSSOM (the shell's refresh-on-change reads the changed set) binds to a11y-plan §3: if settle drains the changed set headlessly, the plan must say so and confirm the windowed refresh still receives its own drain; if settle only reads, no binding arises.
- **Wrap-time amendments owed to arch** — architecture §Standard Contracts → Driver session (the "Not built: … settle" clause and the session's shape), → Test harness, → Document core (only if the trait is touched), → Headless stand and → CLIs (only if the host or stand gains tick-advancing behaviour), and the blitz-tests / seven_guis rows of architecture §Existing Scopes (the new stand and fixture checks).
