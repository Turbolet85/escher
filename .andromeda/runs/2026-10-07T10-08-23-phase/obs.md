# obs extract

## Relevance
partial — obs tier 0 (per obs-plan §1); the chunk adds no telemetry of its own by its scope, but its settle loop runs inside surfaces whose silence, feature-gating and scrub obs-plan records (§2 · §3 · §4 · §6 · §8), and it builds the wait a later span is owed over.

## Constraints
- The span over the settle wait is not this chunk's: obs-plan §4 Span / Trace Coverage records `packages/escher-driver` as carrying no span, no event and no `tracing` dependency, "silent by its chunk's constraint", with one span per driver command owed by the route entry "Driver command spans". Adding a span, an event or a `tracing` dependency to the session library here would change what §4 records — a plan amendment, not a silent add. Whether the settle call lands in `escher-driver` or below it (harness, document) is research's question.
- Any log call this chunk adds in an engine or upstream crate must be compiled only under that crate's `tracing` cargo feature, with a no-op path when the feature is off (per obs-plan §2 Telemetry Strategy → Telemetry mechanism). Whether the files the chunk touches already follow that shape at every existing call site is research's question.
- The headless stand, its `stand_*` checks, the session library, the `stand_session_*` checks and their shared modules install no subscriber, read no env and print nothing but what an assertion reads (per obs-plan §3 Observability Harness Contract → Logging stack). The new settle checks and the loads fixture check fall under the same record: no `escher_telemetry::init`, no env read, no `println!` as a log.
- `escher-session` writes nothing to stdout on any path, and its own stderr lines are fixed strings holding no path, label, id or value (per obs-plan §3 Observability Harness Contract → Logging stack; per obs-plan §6 Log Coverage → Logged events, examples). If a not-settled outcome can reach that binary's stderr, its text must stay a fixed string — naming a busy source by kind is in bounds, naming an element, a URL of a pending load or a control value is not.
- escher's sink prints two target families only and drops every other record whole; an `escher_*` event prints every field except the content-named set, an engine-prefixed event prints only the safe set (per obs-plan §8 PII Scrubbing & Compliance → Scrubbing). A field this chunk adds to any event must be judged against those two sets before it is named: a pending-load URL or path under a content-named key is redacted, under any other key on an `escher_*` target it prints.
- The engine `tracing` features stay off in the two sink-installing binaries, `seven_guis_native` and `escher-session`; engine events reach the sink only when one is turned on (per obs-plan §8 PII Scrubbing & Compliance → Scrubbing, the sink's reach). This chunk must not turn one on in the seven_guis package to observe the settle loop — the by-level readings §8 records were taken with them off.
- The session state directory holds the socket file alone while a session is up; no log, event or screen content is written into it (per obs-plan §9 CI Integration → Telemetry artifact handling, Session state directory). Settle writes no trace, counter or state file there or anywhere else under `target/`.

## Patterns to follow
- A recoverable failure in the engine is logged as a `tracing` event behind the feature and answered with a fallback or a typed value, not a panic (per obs-plan §7 Error Capture & Reporting → Error classes captured). The settle bound ending without quiet is that class: a typed outcome the caller reads, with the busy source in the value rather than in a log line.
- Timing in this workspace is opt-in and printed only under `log-phase-times` / `log-frame-times` / `debug_timer/enable`; no metrics exporter exists (per obs-plan §5 Metric Coverage). A count of polls or resolves the settle loop took, if the chunk wants one, is a field of its return value, not a counter, a gauge or a printed line. (Extractor's reading of §5's absence list, not a mandate it states.)
- The check that reads a sink-installing host is `host_log` (seven_guis): it spawns the real `escher-session` at `RUST_LOG=trace`, drains both streams from the spawn on, and a failure of it prints a kind and a count, never what the host wrote (per obs-plan §3 Observability Harness Contract → Logging stack). If settle changes what the host does between `hello` and `stop`, that check is the one to re-read, in that failure-reporting shape.
- Harness logs stay harness metadata: the agent-run events carry `event`, `ts`, outcome and counts, one `test` line per libtest result, and no captured test output (per obs-plan §3 Observability Harness Contract → Agent-run harness log; per obs-plan §6 Log Coverage → Log format, the agent-run harness). The new checks surface through `agent-run.sh run stand` as ordinary `test` events with no new event kind.

## Anti-patterns to avoid
- An unconditional print or log on the settle path — a `println!`, an `eprintln!` or a `tracing` call outside the feature gate — in the harness, the document, the Dioxus document or the session library (per obs-plan §2 Telemetry Strategy → Telemetry mechanism; per obs-plan §3 Observability Harness Contract → Logging stack).
- Reporting a settle that did not go quiet as a panic whose message carries an element id, an accessible name or a load's URL: the chained std hook prints the raw panic message to stderr past escher's scrub, in both sink-installing binaries (per obs-plan §7 Error Capture & Reporting → Panic hooks; per obs-plan §8 PII Scrubbing & Compliance → Values logged as-is).
- A new user-content log field on any event — text-node content, an attribute value, a request URL — on the polls and resolves settle now drives; the plan records such values as already logged as-is by the upstream subscribers, which stay unscrubbed (per obs-plan §8 PII Scrubbing & Compliance → Values logged as-is; → Scrubbing).

## Contract bindings
- **obs ↔ route ("Driver command spans")** — the span covering the settle wait is owed by that entry (per obs-plan §4 Span / Trace Coverage). This chunk's binding is forward only: the settle outcome should be readable by that later span without a second measurement. What the outcome type carries is the plan's decision; obs-plan states no field list for it.
- **obs ↔ tests (test-plan §3, the stand and session checks; keyed `session-proof`)** — tests consume obs's silence record: checks install no sink, and `host_log` is the one reader of a sink-installing host at `trace` (per obs-plan §3 Observability Harness Contract → Logging stack). Whether `host_log`'s recorded line counts still hold once the host's instance settles is research's question, and a changed count is a §8 reading to re-take, not to assume.
- **obs ↔ security (security-plan §Surfaces; its logging section)** — the scrub sets and the drop are the logger-side half of "nothing of the screen leaves the process" (per obs-plan §8 PII Scrubbing & Compliance → Scrubbing; keyed contract `pii-scrubbing-wire`, per obs-plan §3 Bootstrap phases). The chunk adds no wire verb by its scope, so this binding is exercised only if an event or a stderr line is added.
- **obs ↔ a11y** — (none): no violation record is emitted by this chunk.

## Acceptance criteria contributions
- The new settle checks and the loads fixture check install no subscriber, read no env var and print nothing that is not read into an assertion (per obs-plan §3 Observability Harness Contract → Logging stack).
- `host_log` passes unchanged in what it asserts: the real `escher-session` binary at `RUST_LOG=trace` writes no stable id and no accessible name to stderr, and 0 bytes to stdout (per obs-plan §8 PII Scrubbing & Compliance → Values logged as-is; per obs-plan §3 Observability Harness Contract → Logging stack).
- Every `tracing` call site added by the chunk, if any, is under `#[cfg(feature = "tracing")]` with a no-op fallback, sits under an engine or `escher_*` target, and names no field that carries screen content outside the redacted set (per obs-plan §2 Telemetry Strategy → Telemetry mechanism; per obs-plan §8 PII Scrubbing & Compliance → Scrubbing).
- `packages/escher-driver` ends the chunk with no span and no `#[instrument]`; if it gains a `tracing` dependency or an event, the report says so as a change to what the plan records, for the wrap to amend (per obs-plan §4 Span / Trace Coverage).
