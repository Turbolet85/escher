## Constraints
- obs-plan §3 (Logging stack) requires every headless stand and engine check to install no subscriber, read no env var, print nothing and bind no listener, its readings going into assertions only, with the silence probe `println!|eprintln!|print!|dbg!|std::env|env::var|escher_telemetry|tracing_subscriber|UnixListener|TcpListener|bind\(` reading 0. The only exceptions are the ones the section enumerates (`stand_act_spans`' two re-run children, `stand_mcp_tools`' `Recorder`, `stand_id_persistence`'s and `stand_screenshot_repeat`'s re-executed children). A new sweep check or fixture file (C6, C11, C12, C13, C4/C5 fixtures, a sweep record check) that departs from this is a new exception that §3 must record.
- obs-plan §3 (Logging stack) also requires a check that reads a sink-installing binary's streams (`host_log`, `mcp_log`, `cli_commands`, …) to read them into assertions only, and on failure to print a kind and a count, never what the host wrote. Where a check reads an accepted command's empty stderr, it removes `RUST_LOG` from the child's environment. This binds C9's `cli_commands` check at 90/91 bytes, if one is added.
- obs-plan §4 requires the driver's `command` span to keep its eight fields (`verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`) and `tool_call` its two (`tool` · `ending`). Neither may field an argument, an id, a name, a value, `in_view`, a shot, or any `Command` / `Outcome` by `Debug`. A sweep driven through `Session::run`, the command line or the `mcp` role must add no field, and C3, if taken (a snapshot saying an element reacts to a click), adds a snapshot reading, never a span field.
- obs-plan §6 (Logged events) records the readings C16 says may have moved: blitz-dom's `info: focussed node` (packages/blitz-dom/src/document.rs:1776-1777 as cited); pointer.rs's `warn` with the unparseable href and the document URL and its `info` with the element's attributes (packages/blitz-dom/src/events/pointer.rs:792 / :797 as cited); and the `mcp` role's 9 lines (built alone) / 10 lines (workspace build, the tenth `INFO blitz_dom::document … message=[redacted]`) over one CRUD flow at `info`, with 5 `tool_call` and 3 `command` lines. Whether a click's focus now fires `focussed node` on more steps, and whether Enter on a focused `a href` now reaches the pointer.rs href sites, is research's question (C16: "read from the code at that wrap, not measured"). The cited line numbers are hypotheses too.
- obs-plan §2 (Feature wiring) requires every such reading to be taken per build. A workspace-wide build turns `blitz-dom/tracing` on and a `-p seven_guis` / `-p blitz-tests` build leaves it off. The dated host reading (one `blitz_dom::document` INFO line from `info` up on a snapshot · click · type flow, none built alone) is one of the counts C16 re-reads.
- obs-plan §8 (Values logged as-is) records the host's by-level reading C16 may move. Built alone, the host writes 4 lines at `info` / `debug` / `trace` (742 B); built with the workspace it writes 5 (860 B). Both read 0 of 15 id needles, 0 of 6 name needles and 0 sentinel occurrences, with stdout 0 B. A re-measure must keep the needle counts at 0 under both builds. Only the line and byte counts may move, and §2, §6 and §8 are amended to the measured truth if they read wrong.
- obs-plan §8 (Scrubbing) requires an engine-target record under escher's sink to print only `node_id`, `status`, `waiting_nodes`, `property`, `log.module_path`, `log.file` and `log.line`, every other field `[redacted]`. So pointer.rs's href, URL and attribute fields reach `escher-session`'s stderr only as `[redacted]`, and stay unscrubbed in the upstream apps' `fmt::init()` and the WPT runner. Any engine fork answered "change" must leave the scrub sets and the rule unchanged.

## Patterns to follow
- Each engine log site is compiled only under `#[cfg(feature = "tracing")]`, with a no-op fallback (per obs-plan §2, Telemetry mechanism). Any call site an engine fork adds or moves (hit walk, visible region, accessibility builder, scrollbar fade, pointer path, `absolute_position`, focusability) follows it.
- For C16, take a stand capture through `host_log` (the `escher-session` host on `crud` at `RUST_LOG=trace`, both streams drained from spawn) and `mcp_log` (the `mcp` role at `trace`), under both builds, counting lines, `tool_call` / `command` lines and the id, name, sentinel and base64 needles (per obs-plan §3, Logging stack; §8, Values logged as-is). The dated by-level form is `escher-0.1.0/chunks/2026-10-10-driver-cli/evidence/by-level.md` (per obs-plan §8).
- To assert on spans in process, use a hand-written `tracing::Subscriber` under `with_default` (the `stand_mcp_tools` `Recorder`) or `escher_telemetry::init_with_writer` over an in-memory capture in an ignored re-run child (`stand_act_spans`), never a printed capture (per obs-plan §3, Logging stack).
- When a span reading moves, record it by name and verb words only, e.g. `span="command" verb="click" … message="close"` (per obs-plan §6, Log format).

## Anti-patterns to avoid
- Never field or log an `Outcome`, `Command`, `Call`, `ArgValue`, `Refusal` or `Fault`, the session's record of ids, or a shot's bytes, size or dimensions (per obs-plan §4).
- Never let a failing check echo a captured log line or host output; report a kind and a count (per obs-plan §3, Logging stack).
- Never add a log field carrying a user-content value (href, URL, attributes, text, value) at a new engine site (per obs-plan §8, Values logged as-is). The sink redacts it, but the upstream apps print it raw (CLAUDE.md invariant: "add no new user-content log fields").

## Contract bindings
- obs ↔ tests: `host_log`, `mcp_log` (and `cli_commands` for C9) consume escher's sink line format and its needle census (obs-plan §3, Logging stack; §6, Log format). The per-runner engine-feature split binds to test-plan §9 → Engine features by runner (cited by obs-plan §2, Feature wiring).
- obs ↔ security: §8's scrub sets and the "0 id · 0 name · 0 typed sentinel at `trace`" readings are the same guarantee as security-plan §Surfaces (no id, name or typed text in a log; the span field bans). An engine fork's new attribute read (C7 `aria-checked`) must keep security's closed-set, no-log-site shape.
- obs ↔ a11y: (none beyond the above). C3 and C7 change snapshot or accessibility readings, not log records.
