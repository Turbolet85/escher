relevant — the chunk's product is checks: a requirement-to-check record over the stand plus new fixture checks (C6, C13, C11, C4/C5, C12), a possible macOS-leg check (C9) and a re-read of two log checks (C16).

## Constraints
- Every new check is one file with one test target under `tests/blitz-tests/tests/`, picked up by auto-discovery with no manifest line. `tests/all.rs` stays declared at `test = false` and is never built. The shared modules `tests/common/mod.rs` and `tests/session_common/mod.rs` stay non-targets (per test-plan §2 Test directory + naming conventions → Directory pattern). The shape is pinned by `BlitzTestsTargetsTest` (per test-plan §4 What unit tests cover → blitz-tests targets).
- A file's prefix decides whether `run stand` selects it. `run stand` runs one `--test` per `tests/blitz-tests/tests/stand_*.rs`. An engine check without the `stand_` prefix (like `range_input_interaction` and `hit_clipped_at_scrolling_box`) runs only under `run all`, the workspace `test` leg and per package. A run that parses no test line, or that has no `stand_*.rs` to run, is `failed` with exit 1 (per test-plan §3 Agent-run contract → `run {selection}`). The sweep's record has to say which selection proves each requirement.
- Stand checks and fixtures placed beside the stand boot through `seven_guis::stand` with `stand::options(incremental)`: 800×600, scale 1.0, Light, the bundled DejaVu Sans, no net provider (per test-plan §7 Builders and options). They have no font-skip path and assert unconditionally (per test-plan §2 Test levels observed → Font-dependent tests).
- The per-package build and the workspace build compile different engine features. `writing-mode` is on only in the workspace build, and it selects which of the two `physical_unrounded_geometry` bodies is compiled. `tracing` is also on only there and adds an engine INFO line. So C6(2), a scrolled box under a vertical writing mode, has to be read under the workspace build. A green per-package run does not stand in for the workspace leg, and a sink capture is counted by target, never in total (per test-plan §9 Pipeline facts → Engine features by runner).
- Requirement proofs taken "by an agent" go through `Session::run`, the `escher-session` command line or its `mcp` role. A check that needs a session process starts and stops its own host, bounds every wait, holds the host behind a guard that kills and reaps it, and sends the child's streams to null unless it reads them. A check that holds a session over the socket is `cfg(unix)`-gated (per test-plan §3 Session lifecycle → session-checks). A check's state directory is `{CARGO_TARGET_TMPDIR}/{short name}`, because the socket address leaves about a hundred bytes for the whole path (per test-plan §3 Session lifecycle → session-state).
- C9's bound is stated as 94 bytes on Linux, where `cli_commands` already checks it: a 94-byte directory holds a session and a 95-byte one ends `state-dir-too-long` with status `3` (per test-plan §6 Drivers per surface → Command line). §4 What unit tests cover → escher-driver records the off-Linux bound as 90 bytes only as the text of the error message. The macOS leg runs `test --all --tests --locked` (per test-plan §1 Surfaces under test → Native platforms). Whether the code's 90 is what macOS actually enforces is research's question.
- Driver-call assertions identify a call by its row index only, so a failing log prints no argument value. Each table is stated inside its test and its row count is asserted (per test-plan §4 What unit tests cover → escher-driver).

## Patterns to follow
- The stand's shared tables live in `tests/common/mod.rs`: `controls(task)`, `rendered(task)`, `tab_order(task)`, `ENABLED_TAB_ORDER`, `REGION_NAMES`. They are a stated expectation, never a second role or name mapping, and a check declares `mod common;` after its `use` block (per test-plan §3 Crate-local test helpers → blitz-tests (stand checks)). This is the natural home for a requirement-to-task table, if P4 picks that form for the record.
- The session builders and readers live in `tests/session_common/mod.rs`. Builders: `hold(task, incremental)`, `click`, `type_into`, `press`, `advance`, `scroll`, `snapshot`, `screenshot`, `screenshot_of`. Readers: `act` → `Acted`, `shot`, `refused`, `refused_unchanged`, `focused` (per test-plan §3 Crate-local test helpers → blitz-tests (session checks)). Each step's returned diff is compared with the check's own `before.diff(&after)` and must be equal across the two layout modes (per test-plan §5 Boundaries covered → Session ↔ held instance).
- Where the four lean tasks lack a case, an in-file fixture is booted with the stand's options. This is how `stand_snapshot_state`, `stand_act_obstructed` and `stand_act_scroll` cover their extra cases (per test-plan §1 Coverage scope → tests/blitz-tests).
- When a reading is measured but not fixed, a check pins it as it reads and names that limit. Examples are `scrolled_box_absolute_position`, the last test of `hit_clipped_at_scrolling_box` and `stand_actionable_keys`' pinned 2 · 3 · 676 (per test-plan §3 blitz-test-harness → Inspection helpers; §1 Coverage scope → tests/blitz-tests). C2, C4, C5, C7 and C14 either move these pins or leave them standing.
- Mutation controls: each new check is turned red by a named mutation, then read green on the restored tree with the restored file's sha256 compared, and the record is kept under the chunk's `evidence/controls.md` (per test-plan §4 What unit tests cover → escher-driver).

## Anti-patterns to avoid
- An empty run never counts as a pass, and an `#[ignore]` child's own libtest lines must never reach the parent's output, because `agent-run.sh` would count them as tests (per test-plan §3 Agent-run contract → `run {selection}`; §2 Test levels observed → Process-lifecycle checks).
- No sleep, no wall-clock read, and no pump or tick of a check's own in a driver or settle check. Time moves only through `advance` / `TimerTicks` (per test-plan §5 Boundaries covered → Session ↔ held instance; §8 Hand-written fakes and stubs → Time (seven_guis timer)). C10 follows from this: no check shoots inside the 0.7 s fade window that runs on wall time (per test-plan §9 Pipeline facts → Engine features by runner).
- No id, name, value or typed text from a call in an assertion message or in a failing check's output (per test-plan §4 What unit tests cover → escher-driver; §5 Boundaries covered → Session host ↔ what it writes, where a failure prints a kind and a count only).

## Contract bindings
- tests ↔ obs (C16): `host_log` and `mcp_log` read stderr against the stand log format. That format is one `command` line per call and one `tool_call` line per MCP call, plus the engine INFO line the workspace build adds (per test-plan §3 Stand log format). The dated line counts those checks hold up are obs-plan's §2, §6 and §8.
- tests ↔ a11y / CI: the `a11y` leg's six files are pinned in order by `LegScriptTest` (per test-plan §4 What unit tests cover → CI workflows and leg script; §9 Pipeline facts → Legs). A sweep check added to that leg moves both `ci-leg.sh` and that pin.
- tests ↔ CI (C9): a macOS-only check runs in the matrix job. Any edit to ci.yml stays under the `CiWorkflowTest` invariants (per test-plan §4 What unit tests cover → CI workflows and leg script).
- tests ↔ architecture: the driver session's lifecycle, wire and binary (per test-plan §3 Session lifecycle → session-start, session-binary; architecture §Standard Contracts → Driver session).
