# a11y extract

## Relevance
partial. The sweep's a11y-bearing freight is C2 and C8 (keys and a selected cell on the non-lean tasks), C3 (an element that reacts to a click but states no role), C7 (`aria-checked`) and C15 (`disabled` focusability). The other CARRYs (C4–C6, C9–C14, C16) are hit, bounds, paint, CLI and log work with no a11y mandate. The tier is `0 — SC 2.1.1 · 1.4.3 · 2.4.3`, per a11y-plan §1.

## Constraints
- a11y-plan §7 (Accessibility tree output, the actionable-key rule) requires every element an agent can act on to read an author key: focusable, with an interactive role, or with a listener. `DioxusDocument::unkeyed_actionable` is the check, with no second role mapping. The plan records Temperature Converter 2 · Circle Drawer 3 · Cells 676, and 0 on the four lean tasks and Home. Keying a task (C2) moves the `stand_actionable_keys` pin. Whether keying changes any role, focusability or Tab order is research's question; the lean-task precedent changed none of them.
- a11y-plan §2 (Role derivation) fixes how the builder reads ARIA states. Three attributes are read, by value, on every element, with no role consulted: `aria-selected`, `aria-pressed`, `aria-invalid`. Each value is trimmed, lower-cased and matched exactly against a closed set. `aria-checked` is not read, so a node's `toggled` is exactly its `aria-pressed` reading. Any C7 read must keep this shape. Reading `aria-checked` into `toggled` breaks that "exactly" equation, and it is an engine change for every document (the founder's fork).
- a11y-plan §4 (Per-component pattern catalog, ARIA state attributes) records that an ARIA checkbox or switch states no checked reading, and that a route entry owns that reading. C7 is that owner. The `checked`-or-`pressed` choice must be stated against the snapshot's seven-field `NodeState` order, per a11y-plan §7.
- a11y-plan §5 (Focus order) reads `disabled` by presence on any element, as ratified. `stand_keyboard` pins the `<div disabled tabindex=0>` limit, and a CARRY on this entry owns narrowing it to `button` · `input` · `select` · `textarea` (C15). A narrowing must keep the other presence readings consistent: the `DISABLED`/`ENABLED` state, the pointer click target, Enter and Space activation, autofocus and `unkeyed_actionable` all read the same presence today.
- a11y-plan §5 (Test harness pattern) fixes the stand's keyboard record: `tab_order` and `ENABLED_TAB_ORDER` in the shared module, and every `controls(task)` id over `LeanTask::ALL` asserted to lie in their union. A stand change that adds or re-orders a focusable control moves those tables. The non-lean tasks are outside `LeanTask::ALL`.
- a11y-plan §6 (Color contrast) has `stand_contrast` assert 18 control rows, 14 `TEXT_ROWS` and 19 `STATE_ROWS`, row for row, in both layout modes, over the four lean tasks. Any stand colour change (for example a C12 rule that newly applies, if it reaches a lean task) moves that record. Whether C12 reaches any lean-task row is research's question.
- a11y-plan §7 (Accessibility tree output) records that the CRUD list's missing `aria-activedescendant`, the windowed AT witness and `inert` belong to `.andromeda/residuals.md` lines (target: next) under F1–F3, and the `inert` line is also recorded in §5 (Keyboard navigation, Script and framework exposure). The sweep must not fold or re-decide them.

## Patterns to follow
- State-attribute checks (a11y-plan §3, Assertion harness): `accessibility_states` reads `selected` / `toggled` / `invalid` off the built tree. It keeps one stated table per attribute, asserts the row count, and runs in both layout modes. This is the model for a C7 or C8 check.
- Stating a role or state by attribute alone (a11y-plan §7, the stand's three control kinds): CRUD's `role="listbox"` / `role="option"` + `aria-selected`, and the flight booker's `aria-pressed` and `aria-invalid`. No element, class, style, key, id or order moved. This is the model for Cells' selected cell (C8).
- Shared expectation tables (a11y-plan §7): `controls`, `INPUT_NAMES`, `REGION_NAMES` and `INTERACTIVE_ROLES` in `tests/blitz-tests/tests/common/mod.rs` state expected values and never a second role or name mapping. The interactive-role sweep asserts a non-empty name per node, and is the reader to extend if non-lean tasks join a sweep.
- Keyboard fixture rows (a11y-plan §5, Test harness pattern): `stand_keyboard` has fixture rows beside the stand, `enable_by_keyboard`, and the `tab_order` / `focused` readers. This is the shape for a C15 fixture: one file and one target per behaviour, both layout modes.

## Anti-patterns to avoid
- A second role or name mapping in any reader (snapshot, text, diff, MCP, a C3 "reacts to a click" reading) is ruled out: every reader takes role and name from the tree `accessibility_tree` returns (per a11y-plan §7).
- Do not read `has_changes()` as "this step changed something" without draining first. A freshly booted harness document's changed set is non-empty (per a11y-plan §2, Accessibility tree lifecycle).
- Do not read `Harness::focused()` falling back to the root element as a focused control. Drop the root, as `stand_keyboard` does (per a11y-plan §5, Test harness pattern).

## Contract bindings
- a11y ↔ tests: the `a11y` CI leg (`bash .github/scripts/ci-leg.sh a11y`) runs six files. Adding a file is a leg change pinned by `LegScriptTest`'s a11y tuple in `.github/scripts/test_ci_workflows.py` (per a11y-plan §9).
- a11y ↔ design-system §Color Palette: `stand_contrast`'s rows are the SC 1.4.3 record of the stand's colour tokens (per a11y-plan §6).
- a11y ↔ layout-templates (focus order): `tab_order` and `ENABLED_TAB_ORDER` are the per-surface Tab sequence (per a11y-plan §5).
- a11y ↔ security-plan §Input Validation: a new ARIA attribute read (C7) carries out closed enums and booleans only, never the attribute's text (per a11y-plan §2, Role derivation).

## Acceptance criteria contributions
- If C2 keys a non-lean task: `DioxusDocument::unkeyed_actionable` returns nothing for that task in both layout modes, and the `stand_actionable_keys` pin moves to 0 for it (per a11y-plan §7).
- If C7 is taken: an `aria-checked` row set on `role="checkbox"` / `role="switch"` is asserted with its row count in both layout modes. The snapshot's reading equals the tree node's (per a11y-plan §2 and §7).
- If C15 is taken: a fixture shows `<div disabled tabindex=0>` focusable and reached by Tab, while a disabled `button` / `input` / `select` / `textarea` stays unfocusable and takes no Enter or Space. The stand's `tab_order` and `ENABLED_TAB_ORDER` stay unchanged unless a stand control moved (per a11y-plan §5).
- After any stand change, `bash .github/scripts/ci-leg.sh a11y` passes with `stand_keyboard`, `stand_contrast` and `stand_accessibility_ids` green in both layout modes (per a11y-plan §9).
