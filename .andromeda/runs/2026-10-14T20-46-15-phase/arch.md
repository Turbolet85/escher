# arch extract

## Relevance
relevant — the sweep runs through the driver surface over the stand and its fixtures, and the CARRYs it carries touch named engine readers and the stand's id/snapshot contracts. Code stays in existing units: `examples/seven_guis`, `tests/blitz-tests`, and `packages/blitz-dom` only where a fork answers "change".

## Constraints
- "By an agent" maps onto the driver's one entry point: architecture §Standard Contracts → Driver session requires every call to run through `Session::run`, with `validate` first. It also says nothing public runs a `Command` that did not come from `validate`. The three ways in from outside are the socket `call`, the `escher-session` command line and the `serve_mcp` role. Whether every requirement in reach is reachable through those surfaces is research's question.
- architecture §Standard Contracts → Driver session fixes the schema as `'static` tables: eleven `VERBS` in three levels, nine `CAUSES` and thirteen `NODE_FIELDS`. `describe()` counts are read from those tables. That section requires an added verb, cause or carrier to be a widening ratified by the founder. A new closed-set field inside a ratified carrier is not a widening, by the 2026-10-10 rule recorded in architecture §Established Decisions → Driver session. C3 has to sit inside that rule: a snapshot reading that says an element reacts to a click.
- architecture §Standard Contracts → Headless stand limits `seven_guis::stand` to the four `LeanTask`s: `boot`, `boot_timer` and the pinned viewport, bundled font and offline options. `escher-session start` boots only those four. Its `start` `app` is an MCP `inputSchema` `enum` of the binary's apps, per architecture §Standard Contracts → Driver session. Temperature Converter, Circle Drawer and Cells have no stand boot. Whether C2/C8 or the sweep needs them booted through the driver is research's question. Widening `LeanTask` or the binary's app list would move those contracts.
- architecture §Standard Contracts → Dioxus DOM bridge sets the author key: an HTML `id` that is non-empty, `/`-free and the first claim in pre-order. It records `unkeyed_actionable()` at Temperature Converter 2 · Circle Drawer 3 · Cells 676, pinned by `stand_actionable_keys`. The same section requires the check to have no wire form: no driver, CLI or MCP command exposes it. It also holds the snapshot text under `SNAPSHOT_TEXT_BUDGET` (10,000 bytes per screen). Whether a keyed Cells screen fits that budget is research's question.
- architecture §Standard Contracts → Dioxus DOM bridge reads snapshot `checked` from `checkbox_input_checked()` and `pressed` from the accessibility node's `toggled()`. architecture §Standard Contracts → Mutation, query and CSSOM requires the builder to read only `aria-selected` · `aria-pressed` · `aria-invalid`, by a closed lower-case match, and states that nothing else writes `toggled`. So for C7, a builder read of `aria-checked` into `toggled` would surface as `pressed`, not `checked`. Either read is an engine change for every document.
- architecture §Established Decisions → Scrolling and input records each of these as a ratified engine change for every document: the hit-walk stop at `overflow` and not at `contain: paint` (C4), the one-axis-clip divergence from `visible_region` (C5), and the range model's attribute write and removal rules (C13). Its merge surface is owned by a CARRY on "Quality gates". Moving any of these is the founder's fork, not a lean.
- architecture §Established Decisions → DOM semantics requires focusability to read `disabled` by presence on any element. The `<div disabled tabindex=0>` limit is pinned by `stand_keyboard` (C15). The Tab walk, autofocus and `unkeyed_actionable` move with any narrowing.

## Patterns to follow
- One behaviour per integration-test file, each its own target under `tests/blitz-tests/tests/`, opening with a `//!` doc. Scenarios run in `for incremental in [false, true]`. A test first asserts that its fixture produces the condition under test. Stand checks share `common/mod.rs`, and checks that hold a `Session` share `session_common/mod.rs` (per architecture §Conventions → Tests).
- HTML fixtures beside the stand use `HtmlDocument::from_html` with a `DocumentConfig` (a `ColorScheme::Light` viewport, `HtmlProvider`), then `resolve(0.0)`. Assertion helpers are `#[track_caller]` (per architecture §Conventions → Tests).
- A reading left as it reads is pinned by a test that goes red by design when the reading is fixed, and is rewritten then, not deleted. Examples: `scrolled_box_absolute_position` (C14) and the `contain: paint` and one-axis tests of `hit_clipped_at_scrolling_box` (C4/C5). architecture §Standard Contracts → Scrolling, selection, tree has each of these readings owned by a route entry.
- A measured limit is stated where an agent reads the tool: a fixed literal in the verb table's help, as the `covered` meaning and the `screenshot` scrollbar-fade limit (C10) do (per architecture §Standard Contracts → Driver session).
- Attribute removal and type change go through `DocumentMutator` (`clear_attribute`, `set_attribute`), which flushes on drop (per architecture §Conventions → DOM API patterns). This applies to the C13 fixtures.

## Anti-patterns to avoid
- A `NodeId` must not appear in anything a call answers, in the session's record of ids or in a span field (per architecture §Standard Contracts → Driver session). `UnkeyedActionable.node` stays process-local (per architecture §Standard Contracts → Dioxus DOM bridge).
- A new listener, port, env var or workspace crate must not appear without a registration (per architecture §Occupied Resources → Network ports and listeners). Fixtures "beside the stand" are test fixtures, not a new crate.
- A possibly stale id must not be indexed: `NodeTree` indexing panics on one, so read through `get`/`contains_key` (per architecture §Standard Contracts → Scrolling, selection, tree).

## Contract bindings
- arch ↔ tests:
  - The `a11y` CI leg runs a named list of six files, pinned by `LegScriptTest`.
  - The blitz-tests target contract (one `[[test]]`, `all` with `test = false`) is pinned by `BlitzTestsTargetsTest` (architecture §Standard Contracts → CI contracts).
  - The matrix tests windows and macOS with `--all --tests` (architecture §Infrastructure Patterns → CI/CD). Whether a C9 check at 90/91 bytes in `examples/seven_guis/tests` runs on the macOS leg is research's question. `StateDirTooLong`'s 94/90 bound is stated in architecture §Standard Contracts → Driver session.
- arch ↔ security: an engine read of `aria-checked` (C7) or a narrowed `disabled` (C15) applies to remote pages too. architecture §Established Decisions → Scrolling and input cross-cites security-plan §Input Validation, so such a change is also a security-plan boundary item.
- arch ↔ a11y: focusability changes move `stand_keyboard`'s Tab tables and the `ENABLED_TAB_ORDER` (architecture §Established Decisions → DOM semantics). The `inert` pin stays with its residuals line (architecture §Established Decisions → Unsupported features).
- arch ↔ obs: each sweep call through `Session::run` leaves one `command` span with its eight fixed fields, and each MCP call a `tool_call` parent (architecture §Standard Contracts → Driver session). C16's dated log counts are obs-plan's.
- arch ↔ build: the C6 vertical-writing-mode check needs the `writing-mode` feature, which is in no default list (architecture §Established Decisions → Default features). Whether the workspace build enables it for blitz-tests is research's question.

## Acceptance criteria contributions
- Each new stand or fixture check is its own test-target file, runs in both layout modes, and adds no `[[test]]` table to `tests/blitz-tests/Cargo.toml` (per architecture §Conventions → Tests).
- The workspace gains no listener, port, env var or workspace crate (per architecture §Occupied Resources → Network ports and listeners).
- If C2 is taken: `unkeyed_actionable()` reads empty on Temperature Converter, Circle Drawer and Cells in both layout modes, and `stand_actionable_keys`' pinned counts move to 0 (per architecture §Standard Contracts → Dioxus DOM bridge).
- `describe()` still reports 11 verbs · 13 node keys · 9 causes · 13 session errors unless a founder-ratified widening adds one, and the schema's help states any newly measured limit (per architecture §Standard Contracts → Driver session).
