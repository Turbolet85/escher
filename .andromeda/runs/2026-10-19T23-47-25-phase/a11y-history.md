## Relevant amendment history
- **2026-10-05-ci-gate-legs** — created the named `a11y` CI leg (`ci-leg.sh a11y`, its own job in the slow tier) running fixed named test files. This is where the leg's explicit file list comes from, and a new lint check widens that list only by a deliberate edit.
- **2026-10-06-telemetry-bootstrap** — recorded that the structured a11y violation schema and the WCAG mapping stay unmeasured against the obs log line. A lint finding (class, id, measured reason) is the first violation-shaped record, so it should not be pushed into a log field without the plan defining that schema.
- **2026-10-06-accessibility-tree-identity** — every element node of a Dioxus document carries its stable id as AccessKit `author_id`; no `TextRun`, document-root or `Window` node does. A finding's id is that carried id, so a text-run box can never be a finding's subject.
- **2026-10-06-snapshot-model** — the snapshot takes role, name and focus from the tree `accessibility_tree` returns, with no second role or name mapping. The lint, as one more snapshot reader, inherits that rule: a finding's role or name comes from the snapshot node only.
- **2026-10-06-id-stability-across-code-edits** — added the actionable-key rule and `unkeyed_actionable` as its check. Trap: never satisfy keying by adding a `tabindex` or role, because that moves the pinned Tab order. Planted fixture elements that a finding must name need author keys or HTML ids, not focusability changes.
- **2026-10-06-snapshot-state-fidelity** — a falsy `hidden` no longer drops a node, and a truthy `hidden` still excludes it and its subtree from the tree and the snapshot. This is what the acceptance criterion "a `hidden` planted element reads no finding" rests on, and the falsy case must still be linted.
- **2026-10-06-compact-snapshot-serialization** — `Snapshot::to_text` reads only the model, one line per node, under the `accessibility` feature that also gates the snapshot. It also extended the value mask to a file input. Precedent: a lint written form is another reader under the same feature gate, and it must not unmask a password or file value.
- **2026-10-07-change-tracking-and-diff** — made `has_changes` and the changed set truthful: marked by mutations, focus and checked changes and typed text; not by hover, scroll or layout. The read-only acceptance ("`has_changes()` as before, next diff empty") is read against that contract, so a lint that hovers, focuses or mutates would mark it.
- **2026-10-07-audit-corrections** — the stand's expected roles and input names are stated once, as `controls` and `INPUT_NAMES` in `tests/blitz-tests/tests/common/mod.rs`, as stated expectation and never a second mapping. A lint check reading stand ids takes them from there.
- **2026-10-07-settle-detection** — settle neither reads nor drains the changed set, and the set is non-empty on a freshly booted harness document. Trap for the lint's no-change proof: drain first, then read `has_changes()` around the lint call.
- **2026-10-07-command-and-refusal-schema** — the driver's schema defines no role or name set of its own (`role` and `name` are only result field names), and `disabled` is stated on the snapshot's presence reading. A lint verb's finding shape follows the same rule.
- **2026-10-07-refusal-detection** — `disabled` is read from the snapshot's `enabled` (`Some(false)`), never from the attribute's value, focusability or a driver role list. The lint's contrast exempt class (`enabled == Some(false)`, as `stand_contrast` reads it) must use that same reading.
- **2026-10-07-act-by-id** — `escher-driver` names `accessibility` on `dioxus-native-dom` unconditionally because its executor reads the snapshot, and §1 records the stand graph re-read (no platform adapter, lockfile unchanged) when the driver's dependencies change. If the lint makes the driver read `blitz-test-harness`'s contrast reader or adds a dependency, §1's graph statement is re-read.
- **2026-10-07-sink-target-allowlist** — §3's note: a future a11y violation record reaches the log only under an engine or an `escher_*` target, and content-named fields are redacted. A lint record that logged findings would hit that scrub and drop rule.
- **2026-10-07-driver-command-spans** — §3 restates the sink as two record classes (event lines and closed-span lines), with no a11y violation schema defined against either. The lint's `command` span holds fixed words and counts only, so any findings count is a new field, governed in obs-plan §6.
- **2026-10-10-mcp-surface** — an MCP tool result is one more reader of the snapshot model, with no second role or name mapping, and §1 was re-read for escher-driver's added dependency. A `lint` MCP result follows the same reader rule and the same §1 re-read if dependencies move.
- **2026-10-12-self-description** — the node keys' help (served by `help`) and `DiffNode::differs` were added as model readers carrying closed words only, and a password typed over MCP reads `MASKED_VALUE`. - **2026-10-12-headless-screenshot** — the read-only precedent the extract binds: `screenshot` is one more reader of the model's bounds (an element's bounds rounded outward and cropped to what can be seen), and a shot changes nothing. No focus moves, `has_changes` stays false and the next diff is empty, in both layout modes. The lint's off-screen and zero-size readings and its read-only proof copy this.
- **2026-10-13-stand-contrast-harness** — built `Harness::text_contrast` → `TextContrast` (`contrast_ratio` WCAG 2.x, `required_ratio` 3.0 large text, else 4.5) and discharged `contrast-verification-harness-setup`.
