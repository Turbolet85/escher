# a11y extract

## Relevance
partial — one of the lint's six readings (text contrast) is the tier-0 SC 1.4.3 reading; the other five are layout readings over the snapshot model this plan records as an accessibility-tree consumer.

## Constraints
- The tier's contrast criterion is SC 1.4.3 (per a11y-plan §1 A11y Scope Summary); a lint "contrast" finding is a reading against that criterion, so its threshold is `TextContrast::required_ratio` (3.0 large text, else 4.5) and its ratio `contrast_ratio`, the WCAG 2.x formula — no second formula or threshold (per a11y-plan §3 Contrast verification harness).
- `Harness::text_contrast` is required to stay read-only (no mutation, input, pump or settle) and to read `None` past an `opacity` below 1, a non-empty `filter` or a `background-image` layer on its walk; whether the lint reports such an element as a defect, as "not measured", or not at all is a fork the plan does not settle — the stand's record never counts a `None` as a fail (per a11y-plan §6 Color contrast).
- "As `stand_contrast` reads it" binds the lint to that check's classification: the exempt class is exactly a snapshot node whose `enabled` is `Some(false)`, a `label[for=…]` row is never exempt, and a node with no text (the range input `timer-duration`) is no-text, not a fail (per a11y-plan §6 Color contrast). Whether the lint's reader is that shared reader or a second one is research's question.
- The stand at boot is required to read no contrast defect where the record reads pass: 14 pass, 0 fail, 3 exempt-inactive, 1 no-text over the 18 control rows, and every `TEXT_ROWS` row passing (per a11y-plan §6 Color contrast).
- The snapshot is a consumer of the accessibility tree with no second role or name mapping; a lint that walks the snapshot's nodes is one more reader of that model, its ids the stable element ids the tree carries as `author_id` (per a11y-plan §7 Accessibility tree output).
- An element carrying `inert`, `hidden`, `display: none` or `visibility: hidden` (and its subtree) is out of the accessibility tree and the snapshot, and a hit passes through an inert element; a lint over snapshot nodes therefore reads no finding on such elements, and an overlap/covered reading built on hit-testing inherits those hit rules (per a11y-plan §6 Visibility and hit-testing).
- A read-only driver verb is required to move no focus: the plan records the `screenshot` precedent — no focus moved, `has_changes` false, the next diff empty — and the lint, if read-only, must keep the focused node and the tree's focus as they were (per a11y-plan §7 Accessibility tree output).

## Patterns to follow
- `stand_contrast`'s one shared reader classifying stated tables (control rows, `TEXT_ROWS`, `STATE_ROWS`) row for row in both layout modes — the stand-at-boot half of the lint's proof compares against those recorded rows, never restates the colours (per a11y-plan §6 Color contrast).
- `Harness::text_contrast` → `TextContrast` (`ratio`, `required_ratio`) as the one contrast reader; the bootstrap item `contrast-verification-harness-setup` is discharged, so the lint builds on it rather than adding a harness (per a11y-plan §3 Contrast verification harness).
- Stated expectation tables live once in the stand checks' shared module (`controls`, `INPUT_NAMES`, `REGION_NAMES`) — a lint check reading stand ids takes them from there (per a11y-plan §7 Accessibility tree output).
- Readers of the snapshot model (`to_text`, `diff`, `differs`, the MCP result, `screenshot`'s bounds) each read the model and nothing else, proven on the stand in both layout modes (per a11y-plan §7 Accessibility tree output).

## Anti-patterns to avoid
- A second role or name mapping in the lint (a finding's role or name taken anywhere but the snapshot node) (per a11y-plan §7 Accessibility tree output).
- A contrast exempt rule other than `enabled == Some(false)`, or a fail counted where `text_contrast` reads `None` or the node holds no text, without the fork being taken (per a11y-plan §6 Color contrast).

## Contract bindings
- Contrast verification ↔ design-system §Color Palette: the stand's accent (`#3a5ce5` rest, 5.47) and the recorded pairs are the stand-at-boot baseline the lint must not contradict (per a11y-plan §6 Color contrast).
- a11y CI leg ↔ test-plan: the `a11y` leg runs six named files (`stand_contrast` among them) and `stand_*` files also run three rounds in `stand-repeat`; a new `stand_*` lint check lands in `stand-repeat` by its name, while adding it to the `a11y` leg is a widening of that leg's file list and its pin in `.github/scripts/test_ci_workflows.py` (per a11y-plan §9 CI Integration).
- Visibility/hit rules ↔ the driver's `covered` / `off-screen` refusals: the lint's overlap and off-screen readings share the hit-test and inert rules recorded for the tree and the snapshot (per a11y-plan §6 Visibility and hit-testing).

## Acceptance criteria contributions
- On the stand at boot (each lean task, both layout modes) the lint names no contrast finding on any `stand_contrast` control row the record reads pass, nor on its exempt-inactive or no-text rows (per a11y-plan §6 Color contrast).
- On the planted-defect fixture the contrast finding's element is named by its stable id and its measured reason carries the ratio and required ratio `Harness::text_contrast` reads for that element, below the required ratio (per a11y-plan §3 Contrast verification harness).
- Every finding's id is one a `snapshot` of the same screen lists, and an `inert` or `hidden` planted element reads no finding (per a11y-plan §6 Visibility and hit-testing).
- After a lint call the focused node, the tree's focus and `has_changes()` read as before it and the next diff is empty, in both layout modes (per a11y-plan §7 Accessibility tree output).
