## Relevant amendment history
- **2026-10-06-snapshot-model** — made `DioxusDocument::snapshot` an in-process reader of ids and names, which added no crossing. It left a trap: the first wire form of a reader of ids, names or a control's text is a crossing to escalate. A lint that reports on the snapshot's nodes by stable id is a new reader of that data, and its answer is a new form of it on the carriers.
- **2026-10-06-snapshot-state-fidelity** — added the password `MASKED_VALUE` mask: never the text and never its length. That trap still applies: the mask covers only what goes through the masked reader. A lint finding on a password `input` (for example truncated text or contrast) must not carry the value or its length.
- **2026-10-06-compact-snapshot-serialization** — extended the mask to file inputs, where the `value` attribute still holds the host path. It also set the standing rule that the first command exposing these readings is a new crossing. A finding on a file `input` must carry neither the path nor its length.
- **2026-10-07-change-tracking-and-diff** — kept a diff's values to the snapshot's (masked), by construction, and set a standing rule: the first command that returns a new reading re-asks the crossing question. This is the precedent for a lint answer built only from snapshot readings.
- **2026-10-07-sink-target-allowlist** — has escher's sink drop every outside-target record and redact content-named fields in `escher_*` records. `host_log` is the check that runs against a sink-installing host. The trap: a "nothing in the logs" check on a process with no sink passes vacuously, so the lint's stderr needle runs must use the `escher-session` host and the `mcp` role.
- **2026-10-07-settle-detection** — settle never waits on a load and has no clock. A driver command that waits on a load is a new decision for this plan. A read-only `lint` should, like `screenshot`, wait on nothing and move no time.
- **2026-10-07-command-and-refusal-schema** — created the Driver command schema row. `validate` checks a closed verb table, fixed argument kinds and bounds, and a fixed refusal order, with no panic path and no `Session` in its signature. Refusal texts are fixed and hold nothing of the call. A `lint` verb and its arguments go through this.
- **2026-10-07-act-by-id** — `Session::run` validates first, and an `id` is taken in (1 to 1024 bytes), found by a search of `element_ids()` and resolved through `get_node`, never by index. `Outcome` prints content under `Debug` and is never printed, logged or fielded. A lint `Outcome` variant inherits all of this.
- **2026-10-07-refusal-detection** — set the precedent that adding a verb (the sixth, `scroll`) widens the validated surface and needed the founder's ratification. It also brought `stale` / `not-found` id resolution and the session's private record of id text. A `lint` with an optional `id` would resolve the same way and feed nothing new into that record.
- **2026-10-07-driver-command-spans** — set one `command` span with eight fixed-word or count fields. Never fielded: any argument, `Outcome`, `Refusal`/`Fault`, screen text or its length. A `lint` call records `verb` (and `cause` if refused) only. A findings count would be a new field.
- **2026-10-09-founder-rulings** — the founder ratified that a diff's three sizes may reach a log while no node, id, name or value may. His standing rule: a field holding any of those is a new crossing question. This is the precedent for asking whether a lint findings count may be fielded: a count is allowed only by a ruling like this one.
- **2026-10-10-driver-cli** (socket entry) — the socket carries calls and answers (ids, names, masked values, snapshot text, diff), ratified as the second widening. It set the 1,048,576-byte answer bound (`oversize`, call not rolled back). A lint answer rides this carrier under that bound.
- **2026-10-10-driver-cli** (command-line entry) — the `escher-session` command line became an external surface, with four endings and statuses 0 to 3 and nothing the caller typed written back. Standing rule: every later surface's input passes `validate` before anything runs. `lint` on the CLI follows this.
- **2026-10-10-driver-cli** (answers entry) — ids, names and values leave in an answer. Typed text was measured at 0 in a host's stderr at `trace` under both builds. This is the measurement shape a lint stderr acceptance repeats.
- **2026-10-10-scrolling-box-bounds-and-hit** — restated the `covered` meaning once the engine fixed scrolled-box bounds and the hit at a clipping box. A lint `clipped` / `off-screen` reading builds on those readers, and the refusals' limit texts are fixed program text.
- **2026-10-10-snapshot-states** (closed-field rule entry) — the founder's rule: a new field of a closed value set inside an already-ratified carrier is not a widening. A field holding authored text, an open value set, a new carrier or a new exit still is. This rule decides whether a lint finding (defect-class words, booleans, numbers, ids) needs a ruling, and whether a truncated string or colour would.
- **2026-10-10-mcp-surface** (crossing entry) — ratified MCP as the third carrier: a 65,536-byte request line, a 1,048,576-byte result, a fixed set of protocol errors, and arguments of the wrong kind refused `malformed` before `validate`. "The next carrier is a new question." A lint tool is listed and answered under these bounds.
- **2026-10-10-mcp-surface** (`tool_call` entry) — the `tool_call` span holds only `tool` and `ending`, ratified as a new log field. `serde_json` is reading-only and the replies are hand-written. A lint MCP result keeps both.
- **2026-10-12-self-description** (help entry) — `help` became the tenth verb with the founder's ratification. The program's fixed `'static` table text may cross on ratified carriers, while text from a page, a call or a screen still widens. The `tools/list` grew with each verb. A lint verb adds its help and result-field text to `describe()` and the MCP listing.
- **2026-10-12-self-description** (session-error entry) — set the session-error table (`SESSION_ERRORS`) with a fixed kind, meaning and remedy for each error. A lint adds no error row unless the founder rules one.
- **2026-10-12-headless-screenshot** (pixels entry) — `screenshot` is the template for a read-only instance verb, ratified as the founder's fork. It has an optional `id` looked up as `click`'s is, a new result field kind, a refused shot leaving the instance unchanged, and the bound measured (largest answer 2.1%). Pixels, an open value set, were a widening. Likewise, any lint field carrying open page content would be.
- **2026-10-12-headless-screenshot** (mask and log entry) — never fielded: a shot's image, size or dimensions. The first 64 base64 characters were measured at 0 in stderr. This is the precedent for keeping a lint finding's measured boxes and contrast pairs out of every log field.
- **2026-10-13-stand-contrast-harness** — blitz-test-harness took `color` as the luminance source of `Harness::text_contrast` (reviewed, no package entering the lock). If the lint reuses that reader inside escher-driver, it brings a dependency edge to review under Pinning.
- **2026-10-14-stand-requirement-sweep** — `covered`'s meaning gained its measured one-axis-clip limit. These are the readings a lint `clipped`/`overlap` reading may differ from. The stand's recorded readings are what the "no false defect at boot" acceptance holds against.
- **2026-10-18-engine-debts** (`inert` entry) — an inert subtree leaves the accessibility tree and the snapshot through a presence read that carries no text out. A lint over the snapshot's nodes therefore reads no inert element. That presence-only shape is also the model for any new read-only blitz-dom reader such as truncated text.
- **2026-10-18-engine-debts** (`disabled` / password caret / refusal-texts entry) — `off-screen` gained the transformed-scrolling-box limit and `covered` the no-area limit, as fixed `'static` texts. The password caret now runs by the bullets, so no real-character width reaches a reading. A lint truncation or box reading on a password field must likewise reveal no character width.
- **2026-10-18-one-virtual-clock** — cut the cause set to eight (`time-unavailable` retired) and made `advance` act on every session. The overlay fade now reads the document's clock, so two readings of one state are equal until an `advance`. A read-only lint reads no clock. A ninth cause would reopen the closed set.
- **2026-10-18-engine-debts** (Epoch 2 batch ratification) — the founder ratified the eight-cause closed set, the `inert` read and the presence-only `disabled` reading. A lint relies on that set staying closed.
- **2026-10-19-session-recording** (kept-check entry) — created the Recorded check row. `Check::from_bytes` takes `tool` only from the seven instance verbs, so an eighth instance verb is refused `malformed` unless it is added. This entry also covers `MASKED_STAND_IN`, the recording directory's `0700`/`0600` modes, and the 400-record and 1,048,576-byte bounds. It is the basis for the choice between recording `lint` and naming it as not recorded.
- **2026-10-19-session-recording** (wire v3 entry) — set wire `v3` with the fixed `ok v3 recording-failed`, fifteen session errors, and `call_of` in `command.rs` building each replayed `Call`. Here `serde_json` reads kept checks and writes nothing. A recorded `lint` call crosses these paths.
- **2026-10-19-recorded-check-replay** — each kept `answer` is kept whole at rest, masked as on every carrier, a shot's without `png`. `answer` is required and a JSON object. `Check::replay` stops at the first differing answer. The two committed Counter checks (`tests/blitz-tests/checks/`, `100644`) are the one exception to owner-only. If `lint` joins the recorded set, its findings are kept at rest and must be stable across a replay.
