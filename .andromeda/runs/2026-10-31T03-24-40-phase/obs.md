## Constraints
- obs-plan §3 Logging stack (subscriber installation) requires each check this chunk adds or edits (the served pages' rows, the three CARRY 2 checks, any fix's fixture, `stand_keyboard`, `stand_contrast`, `inert_subtree`, `select_interaction`, `transformed_client_rect`) to install no subscriber, read no env var and print nothing, its readings going into assertions only; whether each file reads so after the edit is the chunk's own census to take.
- obs-plan §4 Span / Trace Coverage requires the `command` span to keep its eight fields and the `tool_call` span its two, with `cause` one of the eight closed names; a fix that moves what `off-screen` or `covered` means moves fixed schema text only, and `escher-driver` stays at its two `info_span!` sites and no event (.andromeda/obs-plan-detail/span-trace-coverage.md, values · spans).
- obs-plan §4 Span / Trace Coverage requires a `lint` line to hold `verb` (with `cause` when refused) and no finding, id, bound or count, so a change to `lint.rs`'s `overlaps` (debt 5) leaves that line as it is; the same section's never-fielded list holds for any `Outcome` or argument the fix touches.
- obs-plan §6 Logged events (.andromeda/obs-plan-detail/log-coverage.md, values · logs) records blitz-dom's sites, the INFO `focussed node` line among them; whether an `inert` focus fixup goes through that site, and so prints a further line where a sink admits engine events, is research's question, and a site the fix adds or re-routes is stated in the report.
- obs-plan §2 Feature wiring requires any log site added in blitz-dom to compile only under `#[cfg(feature = "tracing")]` with a no-op path off, and its by-invocation line makes the two builds differ: a workspace build turns `blitz-dom/tracing` on, a `-p blitz-tests` or `-p seven_guis` build leaves it off, so a reading of the sink is taken under both.
- obs-plan §8 Scrubbing limits the scrub to escher's sink: an engine target prints only the safe fields, and the upstream apps' `fmt::init()` subscribers and the WPT runner's `env_logger` stay unscrubbed, so a new engine site's content is exposed there whatever the allowlist does; a checked state, option text or an attribute value is not fielded.
