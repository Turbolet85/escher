## Constraints
- Placement: arch names the crates each debt's surface belongs to. The engine readers (`visible_region`, `inert` focus, the builder's `toggled`, the select model) are blitz-dom's, and the option-overlap reading is escher-driver's `packages/escher-driver/src/lint.rs` `overlaps`; a fix that moves the overlap reading into the engine or the snapshot changes that recorded owner and is a fork, not a placement detail (per architecture §Standard Contracts → Driver session; §Existing Scopes).
- The driver's schema is closed: arch §Standard Contracts → Driver session requires twelve verbs, thirteen `NODE_FIELDS` keys, eight causes and six lint `Defect`s, with no `NodeId` crossing and no refusal holding what a call supplied. A debt whose fix would add to any of these is a boundary question, and a moved `off-screen` or `covered` meaning moves the text the capability-statement pin reads (per architecture §Standard Contracts → Driver session; architecture §Standard Contracts → CI contracts).
- `visible_region` is a read-only reader, and seeing is never read from a hit. arch records the transformed-box reading as a measured limit beside `get_client_bounding_rect`, which maps through transforms, and records the own-box, one-axis and transformed-and-scrolled readings as standing as measured; a fix must name what it moves among these. Its readers include the act gate's `off-screen`, the shot's crop and the lint's clip region (per architecture §Standard Contracts → Scrolling, selection, tree; architecture §Standard Contracts → Driver session).
- `inert` is specified as an ancestor walk through `Node::is_inert` with `ElementData::is_focussable` cached per element and no mutator hook. A focus fixup needs a trigger that this design does not state, so its placement is a design question for P3 to measure and the founder to rule on. arch also states the focus-move rule: `FOCUS_WITHIN` moved by the ancestor chain, and exactly the node that lost focus and the node that gained it marked in the changed set (per architecture §Established Decisions → DOM semantics; architecture §Cross-cutting Patterns → Invalidation and state integrity).
- The `toggled` write is specified per role, each attribute read once, with `is_native_checkable` reading neither `aria-pressed` nor `aria-checked`. arch states the snapshot's `checked` as a separate reading of `checkbox_input_checked()`, and what crosses to the platform adapter as closed enums and booleans. Whether a native-checkedness fix moves any snapshot reading, `pressed` included, is research's question (per architecture §Standard Contracts → Mutation, query and CSSOM; architecture §Standard Contracts → Dioxus DOM bridge).
- arch requires every choice that changes a select's chosen option to go through the one path `apply_select_choice`, a choice of the chosen option to fire nothing, and `change` to be dispatched only after `input` on a select's choice; the rules stay in the crate-private `node::select`, with no public type. A `multiple`, `optgroup`, popup, option-click or checkbox `change` fix each departs from these stated rules (per architecture §Established Decisions → Scrolling and input; architecture §Standard Contracts → Events; architecture §Standard Contracts → Nodes and widgets).
- Incremental and non-incremental layout must produce identical layouts through a single code path, and scenarios run in both layout modes, `pseudo_element_flow_classification` being the one stated exception, so CARRY 2's edit to it moves that clause (per architecture §Design Philosophy; architecture §Conventions → Tests).

## Patterns to follow
- A direct engine change is recorded with the founder's ratification and his word, an upstreamable flag with no upstream pull request open, and a by-file merge surface owned by the `.andromeda/residuals.md` line whose owner is Epoch 3's «Upstream sync ahead of the UI graph» (per architecture §Established Decisions → Scrolling and input).
- The client-rect reader is the named precedent for reading under a transform: the private `is_transformed_chain` and `transformed_bounds` map corners through each containing block's transform in device pixels and read the axis-aligned bounding box. Whether that reach covers `visible_region` under a scale as well as a translate is research's question (per architecture §Standard Contracts → Scrolling, selection, tree).
- A widened behaviour widens the method itself for every caller, with no second method beside it, as `scroll_into_view` was on the founder's ruling (per architecture §Standard Contracts → Scrolling, selection, tree).
- A state change writes the changed set at its named site only and marks nothing for a move that changes nothing, as `apply_range_move` and `apply_select_choice` are specified to do (per architecture §Cross-cutting Patterns → Invalidation and state integrity).
- Each integration file covers one behaviour, opens with a `//!` doc naming it and first asserts the fixture produces the condition; served-page checks holding a `Session` share `session_common`, and a page with one reader stays in its check's file (per architecture §Conventions → Tests).

## Anti-patterns to avoid
- Reading whether an element can be seen from a hit, or letting a fix to one reader silently re-pin another's measured reading (per architecture §Standard Contracts → Scrolling, selection, tree).
- An `Instant::now()` or `SystemTime::now()` in blitz-dom outside `clock.rs`: any timed behaviour reads `DocumentConfig.clock` (per architecture §Standard Contracts → Document core).
- Indexing `NodeTree` with an id that may be stale, such as a remembered focus: stale-id indexing panics, and changed-set ids are read through `get_node` (per architecture §Standard Contracts → Scrolling, selection, tree; architecture §Standard Contracts → Document core).
