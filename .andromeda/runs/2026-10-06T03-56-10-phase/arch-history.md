## Relevant amendment history
- **2026-10-06-stand-test-contract — the agent-run contract and its state area registered** — Added the agent-run test contract to §Standard Contracts → CI contracts. Its surface is `bash scripts/agent-run.sh {boot | run … | status | cleanup | logs}` with exit grammar 0 / 1 (failed, an empty run included) / 2 (usage, checked before 3) / 3 (precondition unmet). Events are JSON lines encoded by an embedded python3 `json`, and `agent-run.ps1` is a pass-through with no logic. `test_agent_run.py` pins the contract in the existing `ci-scripts` leg. The same amendment registered `target/agent-run/` (`status.json`, `events.jsonl`, `run.log`) under §Occupied Resources → Filesystem: raw output, unscrubbed like `target/ci-logs/`, recreated by `boot`, removed by `cleanup`, and local only. Why it matters: this is the direct precedent for the pipe's invocation surface. A new verb amends this contract and its test. A sibling script must keep its own state area disjoint from this one, and the pipe's transcript, call log and verdict need a Filesystem registration of the same shape. The amendment's Why records "no port, socket, env var, crate or dependency"; this chunk is likely to break that pattern, and each break is a registration. The Kept clause says `target/agent-run/` is never uploaded, so "the one fork-CI artifact outside `target/ci-logs/`" stays true. A CI-uploaded transcript would falsify that clause.

The process-wide installs show how a spawned stub process's state is recorded.
