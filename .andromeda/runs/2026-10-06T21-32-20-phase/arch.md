# arch extract

## Relevance
relevant — the chunk changes the readings behind a registered public contract (`DioxusDocument::snapshot` / `NodeState`) in `dioxus-native-dom`, may touch the Dioxus bridge's boolean-attribute handling, and adds a fixture next to the registered headless stand.

## Constraints
- **Workspace placement.** The state readers live in `dioxus-native-dom`'s crate-private `snapshot` module, compiled only under the crate's `accessibility` feature, with the three snapshot types re-exported from the crate and through `dioxus-native` (per architecture §Existing Scopes → dioxus-native-dom; §Cross-cutting Patterns → Config management; §Standard Contracts → Dioxus DOM bridge). A consumer taking the crate with `default-features = false` gets the snapshot only by naming the feature — any new test or fixture crate consuming it must name it (per architecture §Standard Contracts → Dioxus DOM bridge).
- **`NodeState` is a registered contract, shape and readers both.** Architecture §Standard Contracts → Dioxus DOM bridge registers the four fields, their types, the derive set, and — field by field — which existing engine reader each one follows, and requires that no field hold a `NodeId`, an AccessKit tree id, an `ElementId`, a `ScopeId` or a pointer. A reading this chunk changes (which `disabled` reader `enabled` follows, what a `range` or `select` reads as `value`, a masked password `value`) departs from the registered reader list and is a contract change to be recorded at wrap; a fifth field or a changed field type is a shape change, not a reading change.
- **`disabled` has two engine readers; the snapshot must name the one it follows.** Architecture §Established Decisions → DOM semantics records that focusability parses `disabled` as a boolean while the `DISABLED`/`ENABLED` element state, `:disabled` and the pointer click target key on the attribute's presence, and §Standard Contracts → Dioxus DOM bridge registers the snapshot's `enabled` as the presence reading on a `can_be_disabled()` element. Whether the code's readers still disagree, and on which inputs (`disabled="false"`, bare `disabled=""`), is research's question; the choice is this chunk's and must be stated against the spec it follows (per architecture §Design Philosophy → Behave like a browser, and cite the spec).
- **The bridge's falsy-boolean handling is a registered contract of its own.** Architecture §Standard Contracts → Dioxus DOM bridge registers which two attributes a falsy value clears and that the other seven boolean attributes are written as a literal value a presence read takes as set. A state reading that keys on one of those seven must not read a Dioxus `false` as set; widening the clear list changes the bridge contract for every Dioxus app and is a recorded amendment, not a side effect. Whether the code still writes those seven that way is research's question.
- **`focused` follows the tree's focus, not the document's focus getter.** Architecture §Standard Contracts → Dioxus DOM bridge requires the `focused` reading to come from the `TreeUpdate`'s `focus` and never from the getter that falls back to the root element; §Established Decisions → DOM semantics records that focus on a removed node resets to the body, and §Standard Contracts → Events that keyboard input targets the focused node, falling back to the root. "Nothing focused reads no node focused" must hold against those fallbacks — whether the tree's `focus` ever names a kept node when nothing is focused is research's question.
- **Node identity.** `NodeId` is a versioned slot id and indexing a stale one panics (per architecture §Established Decisions → Node identity; §Standard Contracts → Scrolling, selection, tree); the snapshot resolves elements through `BaseDocument::get_node` and skips what does not resolve (per architecture §Standard Contracts → Dioxus DOM bridge). No state reader indexes the tree by an id taken from the accessibility tree.
- **No new occupied resource.** Architecture §Occupied Resources registers no port or listener, a closed env-var list and a closed crate-name list; the chunk adds none of these — a fixture is a module or a test file inside an existing crate (per architecture §Infrastructure Patterns → Directory structure), and the snapshot keeps having no wire form (per architecture §Standard Contracts → Dioxus DOM bridge).

## Patterns to follow
- **Every field from a reader the engine already has.** The snapshot contract is built on existing readers, never a second computation of id, role or state (per architecture §Standard Contracts → Dioxus DOM bridge). A control whose value has no existing reader is surfaced, not given a private re-derivation; if a new reader is unavoidable it belongs on the engine side behind the same feature gate (per architecture §Conventions → Feature gating).
- **Value and checked state live on box-construction data.** Architecture §Established Decisions → Layout records that text inputs get their editor and checkbox/radio their checkbox data during box construction, so a typed value and a toggled check are readable only after the document has resolved; a state check pumps before it snapshots (per architecture §Standard Contracts → Test harness, `pump`). Whether an unconstructed control (not displayed) reads a value at all is research's question.
- **Real input through the harness.** Proof drives `click`, `type_text` and key events through `Harness<DioxusDocument>` — the real event-dispatch pipeline (per architecture §Standard Contracts → Test harness; §Design Philosophy → Headless, measurable, testable) — and the stand boots through `stand::boot` / `stand::options(incremental)` at the pinned viewport, bundled font and no network (per architecture §Standard Contracts → Headless stand).
- **Bridge writes go through the mutator.** If the falsy-boolean fix lands in the bridge, it uses the mutator's `set_attribute` / `clear_attribute` as the existing clear does (per architecture §Standard Contracts → Mutation, query and CSSOM; §Conventions → DOM API patterns), and respects the bridge's ordering-sensitive block (per architecture §Conventions → Known gaps).
- **Test shape.** Unit tests sit in `#[cfg(test)] mod tests` at the end of the source file; each integration file covers one behaviour, opens with a `//!` doc naming it, first asserts the fixture produces the condition under test, and runs `for incremental in [false, true]` (per architecture §Conventions → Tests).

## Anti-patterns to avoid
- **A process-local value in a state field or a masked value.** No `NodeId`, tree id, `ElementId`, `ScopeId` or pointer enters the snapshot (per architecture §Standard Contracts → Dioxus DOM bridge) — a mask must not be derived from one either.
- **Reaching through `DocumentMutator::doc`, or an ungated engine log.** Extend the mutator rather than using its escape hatch (per architecture §Conventions → DOM API patterns); any trace added in `dioxus-native-dom` uses the crate-local `trace!` macro under the `tracing` feature, never an unconditional print (per architecture §Conventions → Feature gating).
- **Growing the stand's registered surface silently.** `LeanTask` is registered as four variants with `ALL`, and `boot` as the lean tasks' entry (per architecture §Standard Contracts → Headless stand); a fixture added as a fifth `LeanTask` variant changes what every `ALL`-iterating stand check covers. A fixture boot target is a separate, named addition to that contract, or lives in the test crate on `Harness::from_component` / `from_vdom` (per architecture §Standard Contracts → Test harness).

## Contract bindings
- **arch ↔ a11y** — the snapshot is built from the `accessibility_tree` override, so what the accessibility tree excludes never appears in it (per architecture §Standard Contracts → Dioxus DOM bridge; §Standard Contracts → Mutation, query and CSSOM for the tree's naming sources). The `hidden: false` hypothesis and the password accessible-name path are both a11y-tree behaviour first and snapshot behaviour second; a fix in `blitz-dom`'s tree builder changes the platform tree the shell builds as well (per architecture §Standard Contracts → Mutation, query and CSSOM).
- **arch ↔ security** — a masked password value is a new property of the registered snapshot contract; the snapshot has no wire form today (per architecture §Standard Contracts → Dioxus DOM bridge), so the mask is the contract any later serialization inherits. The masked form and its threat reasoning are the security plan's.
- **arch ↔ tests** — proof runs on the registered harness and stand contracts (per architecture §Standard Contracts → Test harness; §Standard Contracts → Headless stand) and under the agent-run contract's `stand` selection, which a `stand_`-prefixed file joins (per architecture §Standard Contracts → CI contracts).
- **arch ↔ obs** — tracing is gated per call site and forwarded as a feature (per architecture §Conventions → Feature gating; §Cross-cutting Patterns → Logging and timing); which fields may be logged is the obs plan's.
- **Wrap amendments this chunk raises** — §Standard Contracts → Dioxus DOM bridge (the per-field reader list; the bridge's boolean-attribute list if changed), §Established Decisions → DOM semantics (if the two `disabled` readers are reconciled), §Standard Contracts → Headless stand and §Existing Scopes → seven_guis (if a fixture boot target is added there).
