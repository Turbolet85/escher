# a11y extract

## Relevance
partial — the chunk adds no UI surface, role, name, key binding or painted colour; it changes two engine readings (a scrolled box's geometry, the pointer hit walk) that the a11y surface stands on: pointer-driven focus, the hit-testing visibility rules, the scrollbar's pointer states and the snapshot that reads the accessibility tree.

## Constraints
- The a11y tier is `0 — SC 2.1.1 · 1.4.3 · 2.4.3`; a change to the hit walk or the geometry reader must leave keyboard operability and focus order as they read, and paints no new colour, so SC 1.4.3 is triggered only if research finds a painted change (per a11y-plan §1 A11y Scope Summary).
- The focusability rule and the Tab / Shift+Tab traversal (`focus_next_node` / `focus_prev_node`) are required to read the same after both fixes — neither fix may add, drop or reorder a focusable node, a scrolling box included; whether a scrolling box is itself focusable today is research's question (per a11y-plan §5 Keyboard Navigation, Focus order per layout).
- Pointer-driven focus follows the hit target: a click on a non-interactive area clears focus, a checkbox or radio click moves focus to the control, a label click runs its bound input's default click, a `summary` activation focuses the summary. The hit fix changes which node answers a point beside a scrolling box, so each of these must be re-read at the points whose answer changes — which points and which callers is research's question (per a11y-plan §5 Keyboard Navigation, Focus restoration).
- The hit walk's visibility rules are required to hold through the change: `visibility: hidden` / `collapse` is never a hit target, and `pointer-events: none` makes an element transparent to hits while its descendants are still tested — a clip at a box's edge must not cut the second rule's descendant walk short inside the box's own area (per a11y-plan §6 Visual Design Verification, Visibility and hit-testing).
- The scrollbar's pointer states are a11y surface: a default thumb carries a contrast stroke, and a near-white author thumb must still visibly change on hover and on drag. Whether a hit clipped at a scrolling box's edge alters what a pointer over or dragging a thumb answers is research's question (per a11y-plan §6 Visual Design Verification, Color contrast).
- The changed set is required to stay as ratified: scroll, layout, hover and active do not mark it; a focus move, a checked change and a rewritten accessible name do. Neither fix may make a scroll step mark the set, and neither may stop a focus move from marking it (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).
- The snapshot stays a consumer of the accessibility tree — role, name and focus from the tree `accessibility_tree` returns, `author_id` on every element node — so the bounds fix changes a node's box and nothing else of it. The plan states no source for a snapshot node's bounds and does not say whether an accessibility node carries a box of its own; whether the tree reads the fixed geometry function is research's question (per a11y-plan §7 Screen Reader Support, Accessibility tree output).

## Patterns to follow
- A11y assertions are Rust tests in blitz-tests over the AccessKit tree, matched on the tree's own readers; the harness exposes the focused and the hovered node as queries — a regression check of the hit fix reads focus and hover through those, not through a private reader (per a11y-plan §3 A11y Assertion Harness Contract, A11y testing tool pick and Focus management test harness).
- The stand's key-press focus check is the model for asserting focus beside a scrolling box: after each step exactly the focused control's snapshot node reads `focused` and it is the accessibility tree's focus, in both layout modes (per a11y-plan §5 Keyboard Navigation, Test harness pattern).
- Expected roles, input names and rendered ids are stated once, in the stand checks' shared tables (`controls`, `INPUT_NAMES`, `rendered`); a new stand or fixture check reads those tables or states its own expectation in file, never a second mapping (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- A check that reads `has_changes()` as "this step changed something" drains the set first — a freshly booted harness document reads it non-empty, and a settle neither reads nor drains it (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).
- A refused `click` or `type` is asserted with the ids reading `focused` and the tree's focus as they were before the call; the restated `covered` and `off-screen` checks keep that reading on both sides of the fix (per a11y-plan §7 Screen Reader Support, Accessibility tree output).

## Anti-patterns to avoid
- No second role or name mapping: a fix or its check never derives a role or an accessible name beside the tree's (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- No clip that turns a hidden or `pointer-events: none` element into a hit target, or that stops the walk reaching a visible descendant inside the box's own area (per a11y-plan §6 Visual Design Verification, Visibility and hit-testing).
- No widening of what marks the changed set to make a scrolled box's reading settle — a scroll is not a change the platform tree's refresh answers (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).

## Contract bindings
- a11y ↔ tests: the `a11y` CI leg (`bash .github/scripts/ci-leg.sh a11y` — `accessibility_hidden`, `accessibility_roles`, `focusability_updates`) runs in the workflow's slow tier behind the fast jobs and adds no stand assertion, so the chunk's focus and hit assertions land in the stand and fixture checks the tests domain owns, each in both layout modes (per a11y-plan §9 CI Integration; the tests extractor names its own anchor).
- a11y ↔ layouts: the tab sequence per stand surface is asserted through `focus_next_node` and must read unchanged on the CRUD screen, the one stand surface the scope names a scrolling box on (per a11y-plan §8 Cognitive Accessibility, Error recovery; the layouts extractor names its own anchor).
- a11y ↔ driver schema: the driver's screen-level refusals are stated on the snapshot's readings, `disabled` the first of three; restating `Cause::Covered`'s sentence changes no role, name or state reading and no order of those checks (per a11y-plan §7 Screen Reader Support, Accessibility tree output).

## Acceptance criteria contributions
- `bash .github/scripts/ci-leg.sh a11y` passes after both fixes with its three test targets and their counts unchanged, 6 + 6 + 3 (per a11y-plan §9 CI Integration).
- The stand's Tab / Shift+Tab focus check (`stand_snapshot_state`) and the lean tasks' forward focus sequence (`stand_accessibility_ids`) pass unedited in both layout modes — the Tab order is the same before and after the fixes (per a11y-plan §5 Keyboard Navigation, Test harness pattern).
- The hit fix's regression check asserts focus as well as the handler: after a pointer click on a control lying where scrolled-out content extends, no row of the box reads `focused` or is the accessibility tree's focus, and the control clicked reads as its own kind requires — focused where a click focuses it, focus cleared where the point is non-interactive — in both layout modes (per a11y-plan §5 Keyboard Navigation, Focus restoration).
- The bounds fix's regression check asserts that across a step scrolling a box the box's snapshot node keeps its id, role and name and no node's `focused` reading moves unless focus moved, in both layout modes (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
