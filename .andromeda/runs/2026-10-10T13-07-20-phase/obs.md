# obs extract

## Relevance
partial — the chunk adds no telemetry surface (no span, event, field, sink or binary); obs binds it only where the two engine fixes and the three restated sentences touch what is already instrumented: the engine's feature-gated log sites, the driver's command span and its `changed` count, and the sink's zero-content readings.

## Constraints
- obs-plan §2 Telemetry Strategy (Telemetry mechanism) requires every engine `tracing` call site to be compiled only under `#[cfg(feature = "tracing")]` with a no-op path when the feature is off — it binds any diagnostic the fixes would add in `packages/blitz-dom` (the geometry reader, both copies; the hit walk). Whether the fixes need a log site at all is the plan's to decide; the chunk's scope names none.
- obs-plan §2 Telemetry Strategy (Feature wiring) requires the two builds to be read apart: a workspace-wide build turns `blitz-dom/tracing` on, while `cargo test -p blitz-tests` and a `-p seven_guis` build leave it off — so an engine edit near a gated call site must compile and pass under both, and a check run package-alone says nothing of the gated path.
- obs-plan §4 Span / Trace Coverage requires the driver's command span to keep its eight fields (`verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`) and to field nothing else — the fixes change what a step's diff holds, so the *value* `changed` records for a step that scrolls a box may differ, while the field set, the span's name, target and level do not.
- obs-plan §4 Span / Trace Coverage requires `cause` to be one of the eight names `Cause::name` returns, a fixed class word — restating `Cause::Covered`'s meaning sentence must leave the name `covered` as it is, and the restated sentence itself is never fielded.
- obs-plan §3 Observability Harness Contract (Logging stack) requires the headless stand, its `stand_*` checks, the engine's fixture checks and their shared modules (`tests/common/mod.rs`, `tests/session_common/mod.rs`) to install no subscriber, read no env var and print nothing — it binds the regression checks the chunk adds and the two pinned checks it restates (`stand_act_scroll`, `stand_act_obstructed`); `stand_act_spans`'s two re-run children stay the one exception.
- obs-plan §8 PII Scrubbing & Compliance (Scrubbing) requires an engine-target event to print only its safe fields (`node_id`, `status`, `waiting_nodes`, `property`, `log.module_path`, `log.file`, `log.line`) with every other field, the message included, redacted — a new engine event in the geometry or hit path may carry a `node_id` and nothing content-named; bounds, a hit's answer, an element id or an accessible name are not log fields.
- obs-plan §3 Observability Harness Contract (Logging stack) requires the three restated sentences to stay what they are today — schema help texts and a cause's meaning, written only as part of a command's answer on stdout, never a log line; the driver's private modules `schema` and `refusal` print nothing and log nothing.

## Patterns to follow
- The gated call-site shape with its no-op fallback, as the engine's existing sites carry it (per obs-plan §2 Telemetry Strategy → Telemetry mechanism) — the hit path already holds one such site, the warn on a hit test with no DOM (per obs-plan §6 Log Coverage → Logged events, blitz-dom document / resolve / mutator / net).
- Span fields created unrecorded and recorded only where they apply, counts and fixed words only — the diff reaches the log as its three list lengths, never as its nodes (per obs-plan §4 Span / Trace Coverage).
- A check that reads a sink-installing process reads its streams into assertions only, and a failure of it prints a kind and a count, never what was captured (per obs-plan §3 Observability Harness Contract → Logging stack) — the shape to keep if a restated or new check touches `stand_act_spans` or `host_log`.
- `hit()`'s cost has one in-process reading, the `paint_tree_bench` test's printed medians (per obs-plan §5 Metric Coverage → In-process timing and counting) — the place a before/after reading of the changed hit walk would be taken if the plan wants one; it is a printed reading, not a gate. The WPT runner's per-run counts are printed the same way (per obs-plan §5 Metric Coverage → In-process timing and counting), which bears on scope decision 4.
- A fork CI hang in the package-install step is read from the job's step log: no `target/ci-logs/` file and no uploaded artifact holds that step's output (per obs-plan §9 CI Integration → Telemetry artifact handling) — the reader for the chunk's `WATCH:`.

## Anti-patterns to avoid
- Fielding or logging what the fixes compute — a node's bounds, a scroll offset, a hit's answering element, an element id — on the command span or on a new engine event: the span's never-fielded list and its fixed-words-and-counts rule exclude it (per obs-plan §4 Span / Trace Coverage).
- An unconditional `println!` or an ungated `tracing` call left in the edited engine functions as a debugging aid: every blitz-dom log site is feature-gated (per obs-plan §2 Telemetry Strategy → Telemetry mechanism), and the engine's existing `println!` dumps are recorded as current truth of named debug helpers, not as a pattern for new sites (per obs-plan §6 Log Coverage → Logged events, blitz-dom node).
- Printing an `Outcome`, a `Command` or a `Call` with `Debug` from a new or restated check's failure path in a way that reaches a log: `Debug` on them prints ids, names and values, and nothing in the crate logs or fields one (per obs-plan §3 Observability Harness Contract → Logging stack).

- **obs ↔ tests (engine features by runner):** which runner compiles the gated engine sites is stated on the tests side as test-plan §9 → Engine features by runner, cited from obs-plan §2 Telemetry Strategy (Feature wiring); the chunk's both-modes regression checks inherit that split.
- **obs ↔ tests (the host's line count):** the session host's stderr by level is a measured reading — per flow, per build — that `host_log` and the by-level evidence hold (per obs-plan §8 PII Scrubbing & Compliance → Values logged as-is; §2 Telemetry Strategy → Feature wiring). Whether the fixes change which engine events fire on those flows under the workspace build (the one `blitz_dom::document` INFO line) is research's question.
- **obs ↔ security:** the scrub sets and the rule that no call-supplied or screen-read value becomes a log field are the security domain's logging boundary as well (per obs-plan §8 PII Scrubbing & Compliance → Scrubbing); the security extract names its own anchor.

Whether the edits shift them is the wrap's to re-read, never this phase's.
- **Keyed contracts:** the one key, Bootstrap phases, is not what this chunk turns on — it adds no SDK and no sink, and its scrub wiring is untouched.
