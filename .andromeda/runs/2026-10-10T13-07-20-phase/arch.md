## Relevance
relevant — both fixes sit in engine functions the plan's contracts name (the CSSOM View geometry reader behind a snapshot's `bounds`, and the hit walk), and the driver contract's texts state the two limits the chunk removes.

## Constraints
- **Workspace placement.** architecture §Existing Scopes puts the geometry reader and hit testing in `blitz-dom` (rows "blitz-dom: interaction", "blitz-dom: node", "blitz-dom: layout" for the `writing_mode` module), the three limit sentences in `escher-driver`, and the checks in `blitz-tests`; the chunk's code belongs in those three units and nowhere else. architecture §Occupied Resources → Names requires that no crate, feature, binary or script name appears unregistered — this chunk needs none.
- **The two layout modes stay identical.** architecture §Design Philosophy → One incremental pipeline, safe identities requires incremental and non-incremental layout to produce the same result after any sequence of mutations; a geometry or hit reading that differs by mode after either fix is a defect of the fix.
- **The geometry reader has two bodies.** architecture §Standard Contracts → Dioxus DOM bridge names the reader's two bodies — one compiled without the `writing-mode` feature, one with it — and architecture §Established Decisions → Default features states `writing-mode` is in no default list. The bounds fix is required in both bodies; which builds and CI legs compile the gated body, and whether any check of ours runs under it, is research's question.
- **`visible_region` is coupled to the reader being fixed.** architecture §Standard Contracts → Scrolling, selection, tree specifies `visible_region` as cancelling a clipping box's own scroll offset where that box is positioned. If the bounds fix changes what the shared geometry reader returns for a scrolled box, that cancellation must be re-derived so the visible region does not move; whether the code's cancellation depends on the shifted reading is research's question.
- **The driver contract stands but for three texts.** architecture §Standard Contracts → Driver session requires `Cause` closed at eight, the fixed refusal order (`disabled`, `off-screen`, `covered`), the click point taken from the centre of the snapshot's `bounds`, the `off-screen` reading taken from `visible_region` and the `covered` reading from the raw hit; the chunk changes none of these, only what `covered`'s meaning and the helps of `changed` and of `snapshot`'s `text` say. Whether escher-driver's logic already needs no change once the engine reads true is research's question.
- **Hit-walk rules that must survive the clip.** architecture §Established Decisions → Layout requires out-of-flow boxes to be hit-tested by their containing block; architecture §Established Decisions → Scrolling and input requires that the root element does not clip its own overflow and that `overflow: hidden` axes scroll programmatically; architecture §Established Decisions → DOM semantics requires hit results canonicalized from anonymous blocks and pseudo-element subtrees to their element; architecture §Design Philosophy → One incremental pipeline, safe identities requires overlay scrollbar geometry shared between painting and hit-testing. Which boxes stop a hit (the scope's decision 2) is chosen inside these four.
- **A fix writes nothing to the changed set.** architecture §Cross-cutting Patterns → Invalidation and state integrity requires that scroll and layout mark nothing and that bounds-only movement changes a reading without a mark; neither fix adds a changed-set write, and a geometry memo is invalidated through the generation counter that section names.

## Patterns to follow
- **Fix the function itself, for every caller.** The `scroll_into_view` precedent — the method widened for every document, no second method beside it, the behaviour change recorded with the founder's ratification — per architecture §Established Decisions → Scrolling and input. The chunk's CARRY 1 asks the same shape.
- **Cite the spec at the change.** Web behaviour is written against a named specification with its URL beside the implementation, per architecture §Design Philosophy → Behave like a browser, and cite the spec and architecture §Conventions → Documentation; public items carry `///` and rustdoc warnings are errors, per architecture §Conventions → Formatting and lints.
- **A snapshot field is an existing engine reader's.** `bounds` is the engine's client bounding rect, viewport-relative and unclamped, with no second derivation in the bridge, per architecture §Standard Contracts → Dioxus DOM bridge — so the true reading reaches the snapshot, the diff and the driver through the reader.
- **Test shape.** One test target per file directly under the integration-test directory, scenarios run `for incremental in [false, true]`, a fixture first asserted to produce the condition under test, session helpers shared through the `session_common` module, per architecture §Conventions → Tests.
- **A schema text is fixed data amended on a recorded word.** The driver's cause meanings and field helps are `'static` texts, each amendment carrying who ruled it and the cause set left standing, per architecture §Standard Contracts → Driver session.

## Anti-patterns to avoid
- **No compensation outside the engine.** A correction of a scrolled box's bounds in the snapshot, the diff or the driver — a second reader beside the engine's — is ruled out by architecture §Standard Contracts → Dioxus DOM bridge (every field an existing reader's) and by the no-second-method precedent of architecture §Established Decisions → Scrolling and input.
- **Visibility is never read from a hit.** architecture §Standard Contracts → Scrolling, selection, tree requires whether an element can be seen to be read from geometry; the hit fix does not turn the hit into a visibility reader, and `off-screen` stays a `visible_region` reading.
- **No manifest change for a new check.** architecture §Standard Contracts → CI contracts pins the integration-test manifest to exactly one declared test table with auto-discovery left on; a new check is a new file, never a `[[test]]` entry, a new feature or a new dependency.

## Contract bindings
- **tests** — the both-modes rule and the one-target-per-file rule (architecture §Conventions → Tests) bind every regression check; the manifest pin is held by a CI script (architecture §Standard Contracts → CI contracts); the two checks that pin the limits as they read today are named in architecture §Standard Contracts → Driver session and are restated with their fix.
- **tests / conformance** — the blast radius beyond the driver: script geometry and hit-test reads resolve style and layout first, and sub-document and custom-widget events are forwarded with adjusted coordinates (architecture §Cross-cutting Patterns → Event processing); the conformance runner is the plan's named validation source (architecture §Project Intent → Validation sources). What each of these callers reads after the fix is research's list.
- **security** — a refusal's texts hold nothing a call supplied (architecture §Standard Contracts → Driver session); the restated `covered` meaning stays a fixed text.
- **obs** — the command span's fields are fixed words and counts (architecture §Standard Contracts → Driver session); the fix can lower a scroll step's `changed` count and changes no field.
- **wrap** — the plan records both limits as measured and unfixed at three sites (architecture §Standard Contracts → Scrolling, selection, tree · → Driver session · → Dioxus DOM bridge); these are the wrap's amendment targets, never edited by this phase.
- **upstream sync** — the fixes edit files inherited from upstream, and the next sync's merge base is the one architecture §Project Intent records.

## Acceptance criteria contributions
- (arch) Each fix's regression check reads the same in both layout modes, `incremental` false and true (per architecture §Design Philosophy → One incremental pipeline, safe identities)
- (arch) A scrolled box reads the same `bounds` from both bodies of the geometry reader — the build with `writing-mode` and the build without it (per architecture §Standard Contracts → Dioxus DOM bridge)
- (arch) An element inside a scrolled box reads the same `visible_region`, and so the same `off-screen` answer, before and after the bounds fix (per architecture §Standard Contracts → Scrolling, selection, tree)
- (arch) `Cause` is still closed at eight with its order unchanged, no verb, argument or result field is added, and exactly the three named texts differ in escher-driver's schema (per architecture §Standard Contracts → Driver session)
