On each of the four lean stand tasks (counter, flight booker, timer, CRUD), in both layout modes (stand::options(false) and stand::options(true)), DioxusDocument::element_ids() reads the same id for each element across a re-render, a remount and a restart in a new process. Witness: cargo test -p blitz-tests --locked --test stand_id_persistence.
- Re-render: after each task's scripted re-renders (counter increments; flight booker's return toggle and Book, which inserts #flight-booked; delivered timer ticks; CRUD filter, Delete and Create), every element node present before and after reads the same id, and the DOM verifiably changed. A CRUD person's row keeps its id under a filter, after another person's Delete, and after a Create.
- Remount: in seven_guis::app::app booted with stand::options, after the task's card → Back → the same card, the id list equals the pre-remount list in order. Every element's NodeId differs from its pre-remount NodeId, except the four document-skeleton elements DioxusDocument builds outside the VirtualDom (/html:0, /html:0/head:0, /html:0/body:0, main), which keep theirs; every dropped pre-remount NodeId reads None. The pre-remount list equals stand::boot's for that task.
- Fresh process: a child process with a pid distinct from the parent's re-executes the test binary and reads, for each task and mode, a non-empty id list equal to the parent's.
