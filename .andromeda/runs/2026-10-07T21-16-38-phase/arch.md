# arch extract

## Relevance
relevant — the chunk edits `escher-driver` (a new dependency edge and the executor's first telemetry call site), reads through `escher-telemetry`'s sink contract, and moves recorded clauses in arch §Established Decisions, §Standard Contracts, §Occupied Resources and §Existing Scopes.

## Constraints
- **Placement: the span sits on the executor's one entry point.** arch §Standard Contracts → Driver session requires `Session::run` to be the one entry point that executes a `Call`, to call `validate` first and to return its refusal before anything else runs; a span that is to carry all eight causes therefore wraps `run` itself, in the `execute` module of `packages/escher-driver` (arch §Existing Scopes → escher-driver). The same contract requires that a refused call changes nothing and that the session hold a label, the harness, the optional time step and the record of ids only — "no subscriber": the span adds no field to `Session` and feeds nothing into the record of ids.
- **The dependency edge is a recorded decision this chunk moves.** arch §Established Decisions → [Driver session] records the library as depending on blitz-test-harness and dioxus-native-dom only, naming no app, reading no env var, and carrying "no `tracing` dependency, span or event". The chunk widens exactly that clause: the one new edge is `tracing`, the workspace dependency arch §Stack and Technologies → Parallelism and misc lists, declared as arch §Conventions → Manifests requires (once in `[workspace.dependencies]`, consumed `{ workspace = true }`). No edge to escher-telemetry, to an app or to a serialization crate is licensed by that decision; the clause is amended at wrap.
- **Gating is an open fork the plan does not settle for this crate.** arch §Conventions → Feature gating states two forms — engine and upstream crates gate each tracing call site behind a `tracing` feature with a no-op fallback, while escher-telemetry has no `[features]` and emits ungated — and names escher-driver under neither. arch §Inherited Defaults → Optional capabilities repeats the split. Whichever the plan picks moves recorded text: a `[features]` table on escher-driver contradicts arch §Established Decisions → [Driver session] ("no `[features]` table of its own") and arch §Occupied Resources → Names ("no features of its own"), and a `#[cfg(feature = …)]` in `execute` contradicts arch §Standard Contracts → Driver session, which records one `cfg` gate in that module and none in the three schema modules.
- **Four types are never fielded; the span reads fixed words and counts.** arch §Standard Contracts → Driver session requires that nothing in the crate print, log or field a `Command`, a `Call`, an `ArgValue` or an `Outcome` (each `Debug` prints ids, typed text, accessible names or control values). What the same contract offers as content-free readings: `Cause::name()` (closed at eight), `Outcome`'s `settled` flag and its `busy` class, and the lengths of the diff's three lists. arch §Standard Contracts → Test harness states `Busy` names a class only and `Settled` carries a pass count; arch §Standard Contracts → Dioxus DOM bridge states `SnapshotDiff` as three lists whose elements hold ids, names and state — so only their lengths are fieldable.
- **The record reaches a log only through the sink's own judgment.** arch §Standard Contracts → Telemetry bootstrap requires one line shape per printed event, admission by target prefix (an `escher_` target prints every field not in the content set; a target outside both prefix sets is dropped whole at every level) and five public scrub constants. arch §Cross-cutting Patterns → Logging and timing requires one fmt layer with the escher formatter, stderr only, no filter layer — the drop sits in the formatter. The plan states a line per printed event and no line for a span: whether the sink as built prints anything for a span, and whether a span's own fields pass the scrub judgment, is research's question. If the chunk has the sink print a span's record, that record is bound by the same line shape, allowlist and scrub, and both of these sections are amended at wrap.
- **The settle contract is read, not edited.** arch §Standard Contracts → Test harness requires that `Harness::settle` log nothing, start no thread and read no clock but the harness's own; arch §Standard Contracts → Driver session requires each acting verb to be one settled step (snapshot before, the step, one settle, snapshot after, one diff), moving no time and waiting on no load. The span reads what that step already returns and adds no settle, pass or snapshot. The plan records no wall-clock read anywhere in the driver; a duration reading would be the crate's first and is the plan's decision, from research.
- **No new resource of a registered class without its registration.** arch §Occupied Resources → Environment variables lists `RUST_LOG` as the one tracing filter; arch §Occupied Resources → Network ports and listeners holds the one listener, lifecycle messages only. The chunk adds no env var, listener, port or workspace crate. What it does add is registered at wrap under arch §Occupied Resources → Process-wide state and threads: a new log target emitted by a library (that entry lists the tree's named log targets) and any test binary that installs the global subscriber or re-executes itself; and under arch §Occupied Resources → Names, the changed dependency list of escher-driver.

## Patterns to follow
- **Emit from the library, install from the caller.** arch §Cross-cutting Patterns → Logging and timing places the subscriber install in escher binaries; arch §Standard Contracts → Headless stand states the stand installs no telemetry. The driver emits and installs nothing; the check installs the sink itself.
- **A caller-given sink, once per process.** arch §Standard Contracts → Telemetry bootstrap offers `init_with_writer` for a caller's writer, with a second install changing nothing (`AlreadyInstalled`) and a foreign global subscriber a typed error. A check that reads captured text is therefore its own integration binary with one install, and its two layout modes share that one writer; where a fresh process is needed, arch §Occupied Resources → Process-wide state and threads records the precedent (a test binary re-executing itself with a fixed argv).
- **Escher's own events as the field-naming precedent.** arch §Standard Contracts → Telemetry bootstrap → Panic event shows an escher target with dotted, fixed field names and a redacted content field — the form a driver record's names follow, none colliding with the content set or with a schema argument name.
- **Stand boot and shared builders.** arch §Standard Contracts → Headless stand gives the boot (`options(incremental)`, `boot`, `boot_timer`, `timer_step` for `Session::with_time`); arch §Existing Scopes → blitz-tests places the driver's call builders and refusal readers in `tests/session_common/mod.rs`, read through `mod session_common;` — a new shared builder goes there, and the reader count that row states moves with a new reader.
- **Private module, documented root.** arch §Standard Contracts → Driver session records 33 re-exported names under `#![deny(missing_docs)]`, all from private modules; span internals stay private, and any public item the plan adds moves that count and needs its doc (arch §Conventions → Documentation).

## Anti-patterns to avoid
- Fielding a `Command`, `Call`, `ArgValue` or `Outcome`, an id, a name, a value or a caller-supplied verb — by hand or through any form that fields a function's arguments (arch §Standard Contracts → Driver session).
- A subscriber install, a second sink path or a print fallback inside `escher-driver` or `seven_guis::stand`, or a filter layer that judges a record outside the formatter (arch §Cross-cutting Patterns → Logging and timing; arch §Standard Contracts → Headless stand).
- Reaching the readings by editing what the plan holds fixed: a call site in `Harness::settle` (arch §Standard Contracts → Test harness), or anything of a call, an outcome or a span on the session socket (arch §Established Decisions → [Driver session]).
