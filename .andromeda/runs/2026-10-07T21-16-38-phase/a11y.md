# a11y extract

## Relevance
partial — the chunk adds no UI surface, markup, focusable element, key binding or painted colour, so no WCAG criterion of the tier is newly triggered; it binds only where a11y-plan states invariants about the driver, the settle and the snapshot readers that a span on `Session::run` must leave as they are.

## Constraints
- a11y-plan §1 (A11y Scope Summary, A11y tier) sets the target as tier 0 — SC 2.1.1 · 1.4.3 · 2.4.3. The chunk must change no focusability, focus order or painted colour; a span is a reader of a call, never a writer of the screen.
- a11y-plan §2 (Accessibility tree lifecycle) requires that a harness settle — `Harness::settle`, the driver session's `act` — neither reads nor drains the engine's changed set, so the accessibility refresh and a later diff receive exactly what the step marked. A span that reads the settle wait must take its reading without a `take_changed_nodes` call or any other drain. Whether the settle wait (went quiet · busy class · duration · passes) can be read from the driver without touching the set is research's question.
- a11y-plan §7 (Accessibility tree output) requires that a `click` or a `type` refused `disabled` dispatches nothing and leaves the ids reading `focused` and the tree's focus as they were before the call. A span opened around a refused call — in front of `validate`, as the scope infers — must add no dispatch, no focus move and no settle on that path.
- a11y-plan §7 (Accessibility tree output) requires that the snapshot, its text form and its diff stay readers of one model with no second role or name mapping, and that the driver's schema defines no role or name set of its own. The span's diff-size reading must be counts taken from the `SnapshotDiff` the call returned — no role, name or node derived in the driver for the span's sake.
- a11y-plan §7 (Accessibility tree output) states the `disabled` cause on one reading only — the snapshot node's `enabled` being `Some(false)`, the presence of the `disabled` attribute. The span's refusal-cause field must report the cause the executor returned, never re-derive disabled-ness from a second reading (the element state or the parsed attribute value, which a11y-plan §5 (Focus order per layout) records as keyed differently).
- a11y-plan §1 (A11y Scope Summary, Dioxus crates) records `escher-driver` as naming `accessibility` on `dioxus-native-dom` unconditionally, with no `[features]` table of its own, and neither stand binary building a platform adapter. The `tracing` edge must leave that feature edge unconditional and bring no `accesskit_xplat` or `accesskit_winit` into either seven_guis binary's graph. If the plan puts the driver's call site behind a `tracing` cargo feature, the crate gains a `[features]` table and that §1 clause becomes a statement for the wrap to amend — flag it as drift, not as a blocker.

## Patterns to follow
- a11y-plan §3 (A11y testing tool pick) and §1 (A11y Scope Summary, blitz-tests): assertions over the accessibility output are Rust tests in `tests/blitz-tests`, built with the `accessibility` feature on `blitz-dom` and `dioxus-native-dom`. The chunk's new stand check belongs in that crate and needs no new feature wiring for the snapshot or the diff.
- a11y-plan §7 (Accessibility tree output): the stand's expected roles, input names and rendered ids are stated once, in the shared tables `controls`, `INPUT_NAMES` and `rendered` of the stand checks' common module. A check that proves no accessible name or id reached the captured log should take its "must not appear" words from those tables rather than restate them.
- a11y-plan §7 (Accessibility tree output): the stand already holds the not-enabled cases the `disabled` refusal is proven on (the two controls the existing `stand_act_disabled` check uses). They are the ready case for a refused call's span; whether the new check reuses that file's setup is the plan's.
- a11y-plan §5 (Test harness pattern) and §7 (Accessibility tree output): every stand reading of focus, snapshot and diff is stated "in both layout modes". The span check follows the same form.

## Anti-patterns to avoid
- Draining or resetting the changed set from span instrumentation to make a reading cheaper — it would starve the accessibility refresh a11y-plan §2 (Accessibility tree lifecycle) describes.
- A second role, name or disabled-ness mapping in the driver, built to label a span — a11y-plan §7 (Accessibility tree output) keeps one mapping, the tree's, with the snapshot as its only reader chain.
- Counting the new span check as an a11y assertion or wiring it into the a11y CI leg — a11y-plan §9 (CI Integration) fixes that leg to three named test files and records that it adds no stand assertion.

## Contract bindings
- a11y ↔ obs: the accessible names and the stable ids carried as `author_id` are the accessibility tree's output per a11y-plan §7 (Accessibility tree output); they are the content the scope's "through the scrub layer" clause (obs-plan §4 · §8, as the scope cites them) keeps out of a span's record. The a11y plan owns where a name comes from; obs owns that it is never fielded.
- a11y ↔ obs: the settle the span reads is the same settle a11y-plan §2 (Accessibility tree lifecycle) constrains — one reading point, two domains; the a11y side is "no drain".
- a11y ↔ tests: the a11y CI leg per a11y-plan §9 (CI Integration) must pass unchanged beside the new check; the new check itself rides the workspace test leg.
- Keyed contract `Bootstrap phases (derive for route / setup-project)` (labels `contrast-verification-harness-setup`, `a11y-ci-gate-wire`): the chunk does not turn on it; not read.
- No a11y-violation-schema binding is extracted: a11y-plan carries no measured coverage for one.

## Acceptance criteria contributions
- (a11y) With the span in place, a call refused `disabled` on the stand leaves the snapshot's `focused` reading and the accessibility tree's focus identical to their reading before the call, in both layout modes — the existing `stand_act_disabled` check passes unedited (per a11y-plan §7 Accessibility tree output).
- (a11y) An acting command run with the span in place leaves the document's changed set as the same command leaves it without the span — the span's settle reading drains nothing (per a11y-plan §2 Accessibility tree lifecycle). Whether `Session::run` already drains the set for its own diff is research's question; the check compares against that baseline, not against "non-empty".
- (a11y) The existing stand focus and identity checks — `stand_snapshot_state`, `stand_accessibility_ids`, `stand_diff` — pass unedited in both layout modes (per a11y-plan §5 Test harness pattern).
- (a11y) `bash .github/scripts/ci-leg.sh a11y` passes with its three test files unchanged, and after the `tracing` edge `escher-driver` still names `accessibility` on `dioxus-native-dom` with no platform adapter in either seven_guis binary's graph (per a11y-plan §9 CI Integration and §1 A11y Scope Summary).
