- A probe check kept in `tests/blitz-tests/tests/` is a target of its own, one file per behaviour. `run stand` selects it only through a `stand_` prefix; without the prefix it is reached through `run {name}` and `run all` alone (per test-plan §2 Test Strategy, directory pattern; per test-plan §3 Test Harness Contract, `run {selection}`).
- A stand run boots through `seven_guis::stand::boot(LeanTask, HarnessOptions)` for Counter or Crud and through `stand::boot_cells` / `stand::boot_load` for a served task, with `stand::options(incremental)` as the pinned options. A reading that layout touches runs under both values of `incremental` (per test-plan §3 Test Harness Contract, Construction; per test-plan §7 Test Data & Fixtures, Builders and options).
- A bridge-level probe inside `packages/dioxus-native-dom` builds a `DioxusDocument` from `DocumentConfig::default()`, calls `initial_build`, and drives it with `mark_dirty` and `poll(None)`. State changes come from a `GlobalSignal` flipped inside `vdom.in_runtime`. `DioxusEventHandler` is reached only from the `cfg(test)` child module `bridge_tests`, with no new constructor, `pub` or `cfg(test)` shim added to a function under test (per test-plan §3 Test Harness Contract, Crate-local test helpers; per test-plan §4 Unit Test Strategy, Conventions).
- A fixture page that more than one check reads goes in `tests/blitz-tests/tests/fixtures/mod.rs`, booted through `fixtures::boot`. A page with one reader stays in its own file. Test data is stated in code; nothing is seeded (per test-plan §7 Test Data & Fixtures, fixture sources; per test-plan §7 Test Data & Fixtures, Seed strategies).
- A probe moves time only through the harness's `VirtualClock` (`tick`, `advance_time`) or, for the Timer, `TimerTicks`. `settle`, `screenshot` and `text_contrast` never move it (per test-plan §3 Test Harness Contract, Core; per test-plan §8 Mocking & Stubbing Discipline, Time).

- If probe code is kept in a crate with a coverage floor, that floor still holds: `packages/dioxus-native-dom` 83 %, `packages/blitz-test-harness` 90 % (per test-plan §10 Quality Gates & Coverage Targets, Coverage floors).

Whether the reproduction is kept as a check or as evidence is the plan's choice, weighed against the zero-failure budget (per test-plan §2 Test Strategy, Test function naming; per test-plan §10 Quality Gates & Coverage Targets, Flakiness budget).
