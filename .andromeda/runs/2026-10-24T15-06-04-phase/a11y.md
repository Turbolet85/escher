## Patterns to follow
- Each check states one table per reading, asserts the table's row count, and runs `for incremental in [false, true]`. This applies to any new fixture check the sweep adds to fill a gap (per a11y-plan §3 A11y Assertion Harness Contract).
- The stand's roles, names and Tab orders are stated once, in the shared module (`tests/blitz-tests/tests/common/mod.rs`: `tab_order`, `ENABLED_TAB_ORDER`, `focused`). A sweep row or a new `stand_*` carrier reads these tables and never restates them (per a11y-plan §7 Screen Reader Support, Accessibility tree output; per a11y-plan §5 Keyboard Navigation, Test harness pattern).
- A check that reads `has_changes()` as "this step changed something" drains the changed set first, because a fresh harness document's set is non-empty (per a11y-plan §2 A11y Strategy, Accessibility tree lifecycle).

## Anti-patterns to avoid
- A second role or name mapping in a sweep check or a `stand_*` carrier. The snapshot and every reader built on it take role, name and focus from `accessibility_tree` alone (per a11y-plan §7 Screen Reader Support, Accessibility tree output).
- A second contrast formula or threshold beside `contrast_ratio` / `TextContrast::required_ratio`, including in a C1 lint fixture (per a11y-plan §6 Visual Design Verification, Color contrast).
