relevant — the chunk is a test-surface chunk: a requirement-to-check record, new fixture checks, the `stand-repeat` selection, the coverage floors and the stderr needle checks are all this plan's subjects.

## Constraints
- The stand checks' zero-failure budget is the `stand-repeat` leg (job `Stand checks repeated`): three rounds over every `tests/blitz-tests/tests/stand_*.rs` target plus seven_guis' eight process checks, no retry, no `--ignored`, no env var, the first red command ending the leg; a witness outside that selection is not under the budget (per test-plan §10 Flakiness budget; per test-plan §9 CI Integration → Legs). Whether each 0.2.0 witness already sits inside it is research's question.
- The `coverage` leg ends with `coverage_floor.py` over three per-crate line floors (escher-driver 97, dioxus-native-dom 83, blitz-test-harness 90), `keyboard_compat.rs` excluded on both `cargo llvm-cov` lines; a `#[path]` test-child file is no record of a crate's reading, so moving a test module out of line moves the reading with no code changed (per test-plan §10 Quality Gates & Coverage Targets → Coverage floors). A floor raised or a crate added is a CI gate change, pinned by `test_coverage_leg_reaches_the_floor_on_each_crate` (per test-plan §9 CI Integration → Coverage).
- The mutation tier (cargo-mutants, `--test-tool nextest`, `NEXTEST_PROFILE=mutants`, `--baseline=skip`, each unit's test command first read green on the unmutated tree) runs on the dev host alone, never in CI — so v020-02's witness cannot be placed inside any CI leg (per test-plan §10 Quality Gates & Coverage Targets → Mutation tier).
- `tests/blitz-tests` keeps one test-target file per behaviour, auto-discovered with no manifest line, the single `[[test]]` table `all` pinned by `BlitzTestsTargetsTest`; a new fixture check is its own file and target (per test-plan §2 Test Strategy → Test directory + naming conventions; per test-plan §4 Unit Test Strategy → blitz-tests targets).
- The stderr measurement of a sink-installing `escher-session` host and its `mcp` role is at `RUST_LOG=trace` under both the `-p seven_guis` and the `--workspace` build, reading 0 id, 0 name and 0 typed-sentinel needles, each check draining both pipes while the child runs; a zero read from a host that installs no sink says nothing of one that does (per test-plan §5 Integration Test Strategy → Session host ↔ what it writes; per test-plan §3 `session-checks`). The plan states `host_log` and `mcp_log` already drive one `lint` and one `snapshot` part read and a recording host; whether that covers every 0.2.0 verb surface the entry names is research's question.
- The two builds differ in engine features (`tracing`, `writing-mode` on in the workspace build only), so a check reading a sink's capture counts lines by target, never in total, and a green per-package run is not the workspace leg's green (per test-plan §9 CI Integration → Engine features by runner).
- Session checks hold no sleep and no wall-clock read except the two whose subject is wall time (`stand_virtual_clock`, `stand_load_wait`); stand checks run in both layout modes (per test-plan §5 Integration Test Strategy → Wall time in the session checks; per test-plan §5 Integration Test Strategy → Session ↔ held instance).

## Patterns to follow
- 0.1.0's requirement-to-check record: `stand_requirement_sweep`'s `WITNESSES` table, one row per requirement in requirement order, each naming at least one witness test found as `fn {test}(` through `include_str!` (`every_requirement_names_its_witness`), the file declaring `mod common;` and `mod session_common;` (per test-plan §1 Test Scope Summary).
- Shared fixture pages live once in `tests/blitz-tests/tests/fixtures/mod.rs` (`boot(app, incremental)` over `stand::options(incremental)`, `hold(label, app, incremental)`), a page with one reader staying in its check's own file; the module holds no print, `tracing` call, env read, file or socket (per test-plan §3 Test Harness Contract → Crate-local test helpers; per test-plan §7 Test Data & Fixtures → Fixture sources).
- Driver calls and their readers come from `tests/session_common/mod.rs` — `hold`, `lint()`/`linted`, `snapshot_part(n)`/`part`, `act`, `refused` — never re-stated per file (per test-plan §3 Test Harness Contract → Crate-local test helpers).
- A new `stand_*` file is picked up by `agent-run.sh run stand` and by the `stand-repeat` leg through its prefix with no script change; a non-`stand_` file runs only in the `test` leg, `run {name}` and `run all` (per test-plan §3 Test Harness Contract → Agent-run contract; per test-plan §9 CI Integration → Legs).
- The headless-stand and fixture checks assert unconditionally under the bundled DejaVu Sans with system fonts off — no skip path (per test-plan §2 Test Strategy → Font-dependent tests; per test-plan §8 Mocking & Stubbing Discipline → Real dependencies kept).

## Anti-patterns to avoid
- No retry, `--ignored` or env var to get a witness green inside `stand-repeat`, and no font skip in a stand or fixture check (per test-plan §9 CI Integration → Legs; per test-plan §2 Test Strategy → Font-dependent tests).
- No mutation run placed in CI (per test-plan §10 Quality Gates & Coverage Targets → Mutation tier).
- No `screenshot` step in a check compared byte for byte across OSes (per test-plan §2 Test Strategy → Pixel tests).
