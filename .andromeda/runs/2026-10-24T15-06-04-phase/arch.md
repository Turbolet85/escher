# arch extract

## Relevance
partial — the chunk is a test/CI sweep (no new crate, surface or resource); arch binds its placement (blitz-tests targets, shared test modules), the CI leg contracts it may touch (`stand-repeat` selection, `coverage` floors), the telemetry sink it re-measures, and the read-only contracts of `text_extent` and `Session::lint` that C1's checks assert.

## Constraints
- Every new check is one integration-test file and one test target per behaviour directly under `tests/blitz-tests/tests/`, opens with a `//!` doc naming the behaviour, asserts first that its fixture produces the condition, and runs its scenario in both layout modes; the manifest keeps exactly the one `[[test]]` table (`all`, `test = false`) and no `autotests` override (per architecture §Conventions → Tests; detail `architecture-detail/conventions.md` conv-tests).
- Shared helpers go in the non-target modules `tests/common/`, `tests/session_common/` and `tests/fixtures/` — a fixture page with one reader stays in its check's file; a new module there must not become a test target (per architecture §Conventions → Tests, second and third conv-tests groups).
- `.github/scripts/ci-leg.sh {leg}` is the one leg runner for CI and the dev host; `stand-repeat` is a three-round zero-failure-budget leg (no retry, no `--ignored`, no env var) whose selection is the `stand_*.rs` glob plus a named seven_guis target list, and `coverage` chains `coverage_floor.py` over named crate floors — a change to either selection or floor list is a change to a pinned CI contract (`test_ci_workflows.py`, `test_coverage_floor.py`) and, for floors, a gate direction (per architecture §Standard Contracts → CI contracts; detail `architecture-detail/standard-contracts.md` contract-ci-contracts).
- `BaseDocument::text_extent` is a read-only reader that mutates nothing, and `get_client_bounding_rect` reads an element where its transforms move it while `visible_region` reads a scrolling box under a transform untransformed (a measured limit) — C1's checks assert these as stated limits; changing `text_extent` is an engine change for every document (per architecture §Standard Contracts → Scrolling, selection, tree).
- `Session::lint` reads the screen and changes nothing, and every driver answer is written by the crate-private `json` module and crosses the ratified carriers (socket, command line, MCP, kept check) — so a change to the lint's findings moves an answer on every carrier, a boundary question, not a test change (per architecture §Standard Contracts → Driver session; architecture §Established Decisions → Driver session).
- escher binaries install `escher_telemetry::init`, a stderr-only sink that drops every record outside the engine and escher target prefix sets at every level and redacts content-named fields of escher's own; escher-driver's spans (`command`, `tool_call`) carry fixed words and counts only — the stderr measurement of `lint`, `snapshot --part` and `--record` is against this mandate; whether those 0.2.0 paths already hold it on the `escher-session` host and `mcp` role is research's question (per architecture §Cross-cutting Patterns → Logging and timing; architecture §Standard Contracts → Telemetry bootstrap).
- A recording directory is launcher-named by `--record <dir>`, never an env read or a default, created `0700`; a measurement run that records must not add an env var or default path (per architecture §Occupied Resources → Filesystem; architecture §Occupied Resources → Environment variables).

## Patterns to follow
- The 0.1.0 record `stand_requirement_sweep.rs` — a stated `WITNESSES` table, one row per requirement naming its witness tests, each found in its file through `include_str!`, held through `Session::run` alone and read via `mod common;` and `mod session_common;` (per architecture §Conventions → Tests; detail `architecture-detail/existing-scopes.md` scopes).
- Fixture checks boot through `tests/fixtures/mod.rs` (fixture boot and hold, shared pages, `HeldNet`), the stand through `seven_guis::stand` (pinned 800x600 Light viewport, bundled font, offline, fresh per boot) (per architecture §Conventions → Tests; architecture §Standard Contracts → Headless stand).
- Time on a held instance moves only through the harness's `VirtualClock` (`advance`, `tick`, `advance_time`); `screenshot`, `text_contrast` and `settle` never move it — a sweep check that needs time uses those, not wall time (per architecture §Standard Contracts → Test harness).
- The stderr needle runs follow `host_log` / `mcp_log`: a test binary re-executing itself with a fixed argv as a session host on its Unix-domain socket, the sink installed by the binary (per architecture §Occupied Resources → Process-wide state and threads).

## Anti-patterns to avoid
- No new env var, listener, port or workspace crate to steer a sweep or a measurement — each is an arch §Occupied Resources registration before it lands (per architecture §Occupied Resources → Environment variables; architecture §Occupied Resources → Network ports and listeners).
- Never log, print or add a span field holding an id, name, value, the snapshot text, a part number or a lint finding (or its count) to make a check observable (per architecture §Standard Contracts → Driver session; architecture §Standard Contracts → Dioxus DOM bridge).
- No `screenshot` step in a check compared byte for byte across OSes — a shot's PNG bytes differ between linux x86_64 and macOS aarch64 (per architecture §Existing Scopes).

## Contract bindings
- arch ↔ tests: the `stand-repeat` leg's selection and `test_blitz_tests_targets.py`'s target pin decide whether a non-`stand_*` fixture witness runs inside `stand-repeat` (architecture §Standard Contracts → CI contracts ↔ test-plan §3).
- arch ↔ obs: the stderr id-free measurement of the new verbs reads escher-telemetry's sink contract and the driver's span field rule (architecture §Cross-cutting Patterns → Logging and timing ↔ obs-plan §3).
- arch ↔ security: a fork answering "change" on `Session::lint`'s findings or on `text_extent` is a boundary widening / engine change for every document (architecture §Standard Contracts → Driver session; architecture §Established Decisions → Driver session ↔ security-plan §Surfaces).

## Acceptance criteria contributions
- (arch) Every new check is its own auto-discovered target under `tests/blitz-tests/tests/`, runs both layout modes, and `test_blitz_tests_targets.py` still reads exactly one `[[test]]` table (per architecture §Conventions → Tests).
- (arch) `bash .github/scripts/ci-leg.sh stand-repeat` ends `3 of 3 rounds green` with every witness the record names inside its selection, and `bash .github/scripts/ci-leg.sh coverage` ends with every listed crate at or above its floor; any change to either leg is matched in `test_ci_workflows.py` / `test_coverage_floor.py` (per architecture §Standard Contracts → CI contracts).
- (arch) No new env var, listener, port, crate or binary appears in the diff (`git diff` over `Cargo.toml`s and `.andromeda/architecture-detail/occupied-resources.md` unchanged unless registered) (per architecture §Occupied Resources → Environment variables).
- (arch) C1's checks call `text_extent` and `Session::lint` read-only and assert no change in the held screen across the call (per architecture §Standard Contracts → Scrolling, selection, tree; architecture §Standard Contracts → Driver session).
