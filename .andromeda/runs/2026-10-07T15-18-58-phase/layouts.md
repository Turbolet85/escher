## Patterns to follow
- A held instance reads as a fresh boot: the plan records the session host as a consumer of the stand's mount that adds no markup, id, class, style, wrapper or order, with the mount and the pinned viewport holding after commands in both layout modes — a refused action is held to the same reading (per layout-templates §Surface: desktop-native → Primary screens).
- Name a fixture's elements the way the lean tasks are named: an author `id` that is the element's stable element id, carrying no layout of its own (per layout-templates §Surface: desktop-native → Primary screens).
- One element laid over another is an existing recorded layout shape — an absolutely positioned overlay beside an underlay in the custom_widget example, and absolutely positioned popovers in the browser frame — the shape a `covered` fixture reproduces at minimal size, in a test file (per layout-templates §Surface: desktop-native → Primary screens, the custom_widget bullet; §Surface: desktop-native → Component — Footer).

## Anti-patterns to avoid

- Reading `off-screen` against the window or render surface where a viewport is meant: the plan distinguishes the viewport from the render surface and from scrolled page coordinates (per layout-templates §Surface: desktop-native → IA notes).
