# arch extract

## Relevance
relevant — the chunk changes the executor half of the Driver session contract (architecture §Standard Contracts → Driver session) inside one existing crate, and two of its reserved decisions each amend a clause that section records.

## Constraints
- **Workspace placement and the crate's edges.** architecture §Existing Scopes → escher-driver places the executor in the crate's private `execute` module and the session in `session`; architecture §Established Decisions → Driver session requires the crate to depend on blitz-test-harness and dioxus-native-dom only, to name one feature (`accessibility` on dioxus-native-dom) with no `[features]` table of its own, to name no app, to read no env var and to carry no `tracing` dependency, span or event. Every reading the detection needs therefore has to arrive through those two dependencies. Whether a hit test at a point, an element's bounds and the viewport's size are all reachable that way without a third manifest edge is research's question.
- **The refusal contract is closed and holds nothing of the call.** architecture §Standard Contracts → Driver session requires `Cause` to stay closed at eight, listed in `CAUSES`, each with a fixed name, meaning and remedy, and requires that `Cause`, `Fault` and `Refusal` have no `String` field. A detected cause is one of the eight existing values; the chunk adds no ninth and no payload (no id, coordinate, covering element or bounds).
- **One entry point, validation first, a refusal runs nothing.** architecture §Standard Contracts → Driver session requires `Session::run` to be the one entry point, to call `validate` before anything else, and states the executor's refusals as returned "with nothing run". The four causes this chunk detects take the same property: the reading that decides a refusal sits ahead of the dispatch, and a refused call leaves the held instance as it was. The same section requires a step that ran and did not go quiet to stay a result (`settled` false with its class), never a refusal — the new causes do not absorb it.
- **`disabled` is the snapshot's presence reading.** architecture §Standard Contracts → Dioxus DOM bridge defines `NodeState.enabled` as the `disabled`-presence reading on an element that can be disabled, and names it the reading that decides whether a click acts; architecture §Established Decisions → DOM semantics records that the engine reads `disabled` two ways, the focusability reader differing from the presence reading. The cause is told from `enabled`, never from the focusability reader or the attribute's value. What the reading is for an element that cannot be disabled (`enabled` absent) and how the detection treats it is the plan's, from research.
- **Decision 1 amends a recorded clause, and the memory may hold ids only.** architecture §Standard Contracts → Driver session records that the session holds a label, the harness and the optional time step only, and keeps no id and no `NodeId` between calls. A session that remembers ids changes that clause (a wrap amendment, the operator's at P4). If it lands, architecture §Established Decisions → Node identity and architecture §Design Philosophy → One incremental pipeline, safe identities bound what may be kept: a stable id string, never a `NodeId`, whose slot stops resolving once its node is dropped. architecture §Standard Contracts → Dioxus DOM bridge also records that a node a re-render removes is detached, keeps resolving for a while and reads no id — so "no element reads it now" is a statement about `element_ids()`, not about whether a remembered node still resolves.
- **Decision 2 touches the one verb table or a fixed text.** architecture §Standard Contracts → Driver session records `VERBS` as five verbs in a fixed order with their argument and field shapes, and each cause's remedy as fixed. A sixth verb, or a reworded `off-screen` remedy, is a change to that stated contract and is the operator's at P4. For the reading itself: architecture §Standard Contracts → Dioxus DOM bridge defines a snapshot node's `bounds` as viewport-relative and unclamped; architecture §Standard Contracts → Headless stand pins the stand's viewport; architecture §Standard Contracts → Driver session records that the session holds no viewport setting, so the viewport is read from the held instance. architecture §Standard Contracts → Scrolling, selection, tree lists the engine's programmatic scroll API (`scroll_into_view` among it) and architecture §Established Decisions → Scrolling and input its scroll semantics; whether the harness reaches that API for an action that brings its own target into view is research's question.
- **No new occupied resource.** architecture §Occupied Resources → Network ports and listeners requires the session socket to stay the one listener and to carry lifecycle messages only; architecture §Occupied Resources → Environment variables and architecture §Occupied Resources → Names list the env reads and the workspace's crates, binaries and features. The chunk adds no listener, port, env var, crate, binary or feature, and nothing of a `Call`, an `Outcome` or a `Refusal` goes on the wire.

## Patterns to follow
- **One answer per call, in a stated fixed order** — architecture §Standard Contracts → Driver session records `validate` answering once per call with the first failure in a written order; the detection states its own order over the five screen-level causes the same way, so two causes that hold at once always name the same one.
- **Resolve, then read, never index** — architecture §Standard Contracts → Driver session records the id lookup as the first pair of `DioxusDocument::element_ids()` whose id matches, its node read through `get_node`; architecture §Cross-cutting Patterns → Invalidation and state integrity records stale ids as tolerated through `get` / `contains_key`. New readings on the resolved node follow that route.
- **Existing readers, no second computation** — architecture §Standard Contracts → Dioxus DOM bridge records every snapshot field as an existing reader's; architecture §Standard Contracts → Test harness lists the harness's inspection surface (`hit`, `hit_node`, `layout_rect_of`, `center_of`, `base`); architecture §Existing Scopes → blitz-dom: interaction places hit testing in blitz-dom; architecture §Established Decisions → DOM semantics records that hit-test results canonicalize anonymous blocks and pseudo-element subtrees to their element. The `covered` reading is a hit test at the point the executor already clicks, compared against the target through those readers; architecture §Standard Contracts → Driver session records that each acting verb already takes a snapshot before its step — whether that snapshot can serve the `enabled` and bounds readings is research's question.
- **Typed, content-free errors** — architecture §Cross-cutting Patterns → Error handling and architecture §Conventions → Error handling record fallible APIs as typed results over enums with `Display`; architecture §Standard Contracts → Driver session records `Refusal` as that shape with private fields. A detected cause is returned as `Err(Refusal)`, not a panic, a `SessionError` or a new `Outcome` variant.
- **Test shape** — architecture §Conventions → Tests requires one behaviour per integration-test file opening with a `//!` doc, both layout modes (`for incremental in [false, true]`), a fixture that first asserts it produces the condition under test, and the session checks' shared helpers kept in `tests/session_common/mod.rs`; architecture §Existing Scopes → blitz-tests records in-file fixtures beside the stand checks as the standing form for a case the tasks lack.

## Anti-patterns to avoid
- **A refusal, a log line or a test name that carries call data.** architecture §Standard Contracts → Driver session requires that nothing in the crate prints, logs or fields a `Command`, `Call`, `ArgValue` or `Outcome`, whose `Debug` prints ids, names and values; the detection adds no print, no `tracing` call and no data-bearing variant.
- **Holding or indexing a `NodeId` across calls.** architecture §Standard Contracts → Scrolling, selection, tree records that indexing a stale id panics; architecture §Established Decisions → Node identity records the versioned slot. A session memory keyed by `NodeId`, or a detection that indexes one, is banned.
- **Widening the crate to reach a reading.** architecture §Established Decisions → Driver session bans a third dependency, a feature table, an app name and an env read in escher-driver; a reading the two dependencies lack is added to the harness or to dioxus-native-dom as an extension of their recorded surface (architecture §Standard Contracts → Test harness; architecture §Standard Contracts → Dioxus DOM bridge), not taken by a new manifest edge.
