## Patterns to follow
- Shared stand helpers: `boot`, `node`, `by_id`, `tree_node` and `name` come from `tests/common/mod.rs`, with per-file items kept per file (per test-plan §3 Crate-local test helpers, blitz-tests stand checks).
- Computed-style reads go through `primary_styles()`, the existing integration pattern for style assertions (per test-plan §5 Boundaries covered, Style assertions). Pixel reads follow the CPU-buffer pixel tests, which sample a rendered buffer, and the whole-frame raster comparisons (per test-plan §2 Pixel tests).
- A pure helper (a relative-luminance / WCAG ratio function, wherever it lives) gets an inline `#[cfg(test)] mod tests` next to it (per test-plan §4 Conventions). Its rows are a table stated in the test with the row count asserted, the way the driver's and harness's unit tests pin their tables (per test-plan §4 What unit tests cover).
- Inspection uses the harness's helpers (`query`, `node`, `layout_rect`, `center_of`). Per test-plan §3 blitz-test-harness (Inspection helpers), `layout_rect` / `center_of` of a box that is itself scrolled read its position less its own scroll offset, while `get_client_bounding_rect` and snapshot `bounds` read where the box stands. Choose the reader that matches what is painted.
- A new `stand_*.rs` file is counted in by its prefix with no script change, and the chunk records the new `run stand` totals (per test-plan §3 Agent-run contract, Proof).

## Anti-patterns to avoid
- Asserting only inside an `if` on a measured value, so the test passes without asserting anything. test-plan §4 Conditional assertions records this as an observed weakness in two text-input tests. A measure-and-record check must still assert unconditionally that every stated control yields a pair or a stated no-text/exempt record (per test-plan §4 Conditional assertions).
- An `eprintln!` skip when fonts are unavailable. That is the pre-existing font tests' path, and stand checks have none (per test-plan §2 Font-dependent tests).
- A second role, name or control mapping beside `controls(task)` (per test-plan §3 Crate-local test helpers, blitz-tests stand checks).

A per-pair record the check prints to stdout therefore reaches no event. The recorded per-pair result has to land in committed evidence or a stated in-file table, not in harness output.
