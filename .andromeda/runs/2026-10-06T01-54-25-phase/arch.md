# arch extract

## Relevance
relevant — the chunk lands a headless boot on the `seven_guis` crate, may widen the `blitz-test-harness` public contract, and may add a workspace dependency edge (blitz-tests → seven_guis, harness → font asset).

## Constraints
- Headless means no window, GPU or compositor, with synthesized input routed through the real event-dispatch pipeline; integration checks belong in blitz-tests' `tests/` directory (per architecture §Design Philosophy → "Headless, measurable, testable"; §Existing Scopes rows `blitz-tests` / `blitz-test-harness` / `seven_guis`). Whether the stand's checks live there or in a `seven_guis` test target is P3's question; the plan names only the blitz-tests location.
- Embedder services reach the DOM only through `DocumentConfig` provider traits, which fall back to `Dummy*` no-ops; `NetProvider::is_noop()` is the contract a refusing or no-op net provider must honour (callers do not register pending-critical resources when it is true). "No live network" must be met through this injection seam, not by a stand-side bypass (per architecture §Design Philosophy → "Embedder services are injected, with no-op defaults"; §Standard Contracts → Provider traits; §Inherited Defaults → API style). Whether the `Harness`/`DioxusDocument` boot path already passes a no-op net provider is research's question.
- The pinned viewport is a `Viewport` value (color_scheme · window_size · hidpi_scale · zoom, `scale()` = hidpi_scale × zoom); the plan records `ColorScheme::Light` for headless documents and an 800×600 · scale 1.0 render target for WPT as the existing headless precedent, and `HarnessOptions { width, height }` with `Default` as the harness's viewport surface (per architecture §Standard Contracts → Provider traits / Test harness; §Established Decisions → Document defaults / WPT runner). The stand pins one named value shared by every check; whether it equals `HarnessOptions::default()` is a P4 decision.
- Bundled fonts go through the font-context seam: `DocumentConfig` carries `font_ctx`; dioxus-native exposes `Config::with_font_ctx` and `build_single_font_ctx`, the standard WASM setup where system-font discovery is disabled; the seven_guis wasm entry ships bundled DejaVuSans.woff2; `woff` is the feature that lets callers bundle compressed fonts, and `dioxus-native-dom` defaults include `system-fonts` (per architecture §Standard Contracts → Document core / High-level launch; §Cross-cutting Patterns → Config management; §Infrastructure Patterns → Deployment model; §Established Decisions → Default features / Fonts). Whether the harness can accept a font context today is research's question; a new `HarnessOptions` field is a public addition to the §Standard Contracts → Test harness contract (an arch amendment at wrap).
- Fresh-per-check runs several documents in one test process: `StyleThreading::Parallel` is documented to panic when two documents resolve concurrently on Stylo's global pool (issue 430), `Sequential` bypasses that pool, and the derive default and the field doc disagree on which is default; a thread-local `LAYOUT_CTX` carries a multi-document FIXME; document and request ids come from process-wide atomics (per architecture §Established Decisions → Style threading; §Occupied Resources → Process-wide state and threads). The checks must stay correct under cargo test's parallel threads; which threading mode the harness boot actually selects is research's question.
- No new port, listener, outbound host, env var or workspace crate without an §Occupied Resources registration; the plan records network ports as none and lists the stand's crate `seven_guis` and binary `seven_guis_native` as occupied names — a new dependency edge or new crate is a registration fact (per architecture §Occupied Resources → Network ports and listeners / Outbound hosts / Environment variables / Names; §Inherited Defaults → API style).
- Incremental and non-incremental layout must produce identical layouts; where a stand check asserts layout it runs `for incremental in [false, true]` (per architecture §Design Philosophy → "One incremental pipeline, safe identities"; §Conventions → Tests).

## Patterns to follow
- Integration-test shape: one behaviour per file opening with a `//!` doc naming it, descriptive snake_case test names, `#[track_caller]` assertion helpers, and a first assertion that the fixture produces the condition under test (per architecture §Conventions → Tests).
- Deterministic time through a virtual clock, not real sleeps: `ScriptDocument::with_virtual_time` / `advance_clock_to` and the WPT runner's virtual-time JS timers with a real-time backstop are the engine's existing time seams — a stand- or harness-side seam for the timer task should follow that consuming-builder shape (`with_*`) (per architecture §Standard Contracts → JavaScript; §Design Philosophy → "Headless, measurable, testable"; §Conventions → Visibility and naming).
- No-op providers are named `Dummy*`; a refusing net provider for the stand follows that naming and the `is_noop` contract (per architecture §Conventions → Visibility and naming; §Standard Contracts → Provider traits).
- Harness constructors `from_component` / `from_vdom` over a generic `Harness<DioxusDocument>`, with inspection (`query`, `text_content`, `attr`, `center_of`, …) and input (`click`, `type_text`, `pump`) as the drive surface (per architecture §Standard Contracts → Test harness).
- Manifest discipline for any new edge: dependencies declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }`, in-repo crates with `default-features = false`, example crates `publish = false` (per architecture §Conventions → Manifests).

## Anti-patterns to avoid
- Copying the headless-loading loop's `blitz_net::Provider::new(None)` into the stand boot — that path does live HTTP/file fetching; the stand must not reach a network or add an outbound host (per architecture §Infrastructure Patterns → Headless loading; §Occupied Resources → Outbound hosts).
- Sharing process-wide state across checks: no shared `VirtualDom`/harness, no reliance on global atomics' values, and no `escher_telemetry::init` in a check (it installs the global subscriber, `log` bridge and panic hook once per process — `InitOutcome::AlreadyInstalled` / `InitError::ForeignSubscriber` on repeat) (per architecture §Occupied Resources → Process-wide state and threads; §Standard Contracts → Telemetry bootstrap).
- Resolving concurrent documents under `StyleThreading::Parallel` (per architecture §Established Decisions → Style threading).

## Contract bindings
- arch §Standard Contracts → Test harness ↔ tests (test-plan §3 harness): any `HarnessOptions` font/net/viewport field or new constructor is a public contract change both plans record.
- arch §Standard Contracts → Provider traits (`NetProvider::is_noop`, `Dummy*`) ↔ security (security rules §Untrusted input: blitz-net has no timeout or size cap) — the no-live-network guarantee is carried by the injected provider.
- arch §Occupied Resources → Names / workspace dependency edges ↔ CI legs (§Infrastructure Patterns → CI/CD: `ci-leg.sh fast`, `doc` over every workspace library crate) — a new pub item on `seven_guis` or the harness is held to rustdoc `-D warnings` and clippy `-D warnings`.
- arch §Cross-cutting Patterns → Logging and timing ↔ obs: `seven_guis_native` installs `escher_telemetry::init` before `dioxus_native::launch`; the headless entry must leave that binary path intact and keep telemetry out of the check path.
- arch §Established Decisions → Default features (`accessibility` default in `dioxus-native-dom`) ↔ a11y: the headless boot runs the same feature set the windowed stand ships, so TaskShell's focus surface is unchanged.
