## Relevance
relevant. The chunk's proof is four headless stand checks in `tests/blitz-tests/tests/stand_*.rs`, run by the workspace test leg and the agent-run `run stand` selection. It may also add a public Harness inspection call. Test tier `0` (per test-plan §1).

## Constraints
- The proof checks are Cargo integration tests in `tests/blitz-tests/tests/`, one file per behaviour, with plain `#[test]` and `assert!`/`assert_eq!`. A `stand_` prefix puts a file in the agent-run `stand` selection, so the file name decides whether `run stand` picks the check up (per test-plan §2 Test directory + naming conventions · §5 Boundaries covered · §3 `run {selection}`).
- Each lean task boots through `seven_guis::stand::boot(LeanTask, HarnessOptions)`, or `boot_timer(HarnessOptions)` for the timer, with the pinned `stand::options(incremental)`. That gives a fresh `VirtualDom` over `from_vdom` in TaskShell at 800×600, scale 1.0, Light, with the bundled font and no network or base URL. A check must not build its own `HarnessOptions` literal (per test-plan §3 blitz-test-harness Construction · §7 Builders and options).
- The stand checks use the bundled DejaVu Sans with system fonts off and assert unconditionally. They have no skip path, so they measure the same on every runner, including the `-p blitz-tests` package-alone build (per test-plan §2 Font-dependent tests · §8 Real dependencies kept · §9 Fonts).
- Timer state is driven only through `TimerTicks` `deliver(n)` plus a pump, never through the real 100 ms delay. With no ticks delivered, elapsed stays at 0.0 s (per test-plan §8 Time (seven_guis timer)).
- The existing stand checks already prove that `dom_string` is identical between a fresh boot and incremental mode. Wherever layout or the tree is asserted, the plan's differential-oracle discipline runs both modes. A per-task id check therefore boots under `stand::options(false)` and `stand::options(true)` (per test-plan §1 Coverage scope tests/blitz-tests · §2 Differential oracle).
- Gates are `bash .github/scripts/ci-leg.sh fast` (fmt → clippy → test → ci-scripts, stopping at the first red) and the `doc` leg (`cargo doc --workspace --no-deps`). Every cargo leg runs `--locked`. The workspace test count is a recorded baseline that each chunk re-counts: 431 passed · 0 failed · 4 ignored at the last re-count (per test-plan §9 Legs · Local pre-push gate · Local baseline).
- A new public read surface on `Harness` joins the inspection-helper set the plan enumerates (query, node, query_all, attr, dom_string, …). Whether the harness, `DioxusDocument` or `BaseDocument` already exposes anything id-like is research's question (per test-plan §3 blitz-test-harness Inspection helpers).

## Patterns to follow
- The existing headless-stand checks `stand_boot.rs`, `stand_counter.rs`, `stand_flight_booker.rs`, `stand_timer.rs` and `stand_crud.rs` are the shape to follow: boot a lean task, then inspect through the harness. Use one file per behaviour, with test names that state the behaviour they guard (per test-plan §1 Coverage scope tests/blitz-tests · §2 Test function naming).
- Walk the elements through the harness inspection helpers (`query_all`, `node`, `attr`, `dom_string`). Synthesized input goes through the document's real event pipeline with no window, and `dispatch`/`dispatch_recorded` do not pump (per test-plan §3 Inspection helpers · Pump semantics · §5 Harness ↔ event pipeline).
- If the id is derived in `dioxus-native-dom`, unit-test it in an inline `#[cfg(test)] mod tests`. Follow the crate's document-test shape: `DioxusDocument` over `DocumentConfig::default()`, `initial_build`, then `mark_dirty` + `poll(None)`. `keyed_nodes_do_not_crash` (a real `VirtualDom`, 100 keyed inserts) is the existing keyed-list precedent for author-key cases (per test-plan §3 Crate-local test helpers dioxus-native-dom · §5 Dioxus VirtualDom ↔ DioxusDocument · §4 Test file location).
- If the id is stored on blitz-dom nodes, pipeline tests build a `BaseDocument` from `DocumentConfig`. They build the DOM through `DocumentMutator`, by hand rather than through blitz-html because of the circular dev-dependency, then call `resolve(0.0)` and assert (per test-plan §2 blitz-dom pipeline tests).

## Anti-patterns to avoid
- No runtime font skip (an `eprintln!` plus early return when text measures 0×0) in a stand check. The stand's pinned font removes the need for one (per test-plan §2 Font-dependent tests · §8 Real dependencies kept).
- No vacuous pass. The plan records text-input tests that assert only inside an `if` and so pass without asserting. It also holds that an empty run is never a pass. An id walk that visits zero elements, or that asserts inside a guard, must fail rather than pass (per test-plan §4 Conditional assertions · §3 `run {selection}`).
- No real-time sleeps to advance the timer task. The plan records sleep-then-poll only for blitz-vibey-script, while the stand replaces the delay with `TimerTicks` (per test-plan §2 Script tests · §8 Time (seven_guis timer)).

## Contract bindings
- tests ↔ arch §Standard Contracts: `Harness` construction and inspection are enumerated in test-plan §3 blitz-test-harness. A public id read call on the harness changes both, and both are amended at wrap.
- tests ↔ obs §3: agent-run events (`run.start`, `test`, `run.end`) are harness metadata, not an escher-telemetry sink. No captured stdout or panic text reaches an event. New `stand_*.rs` files join `run stand` without any script change, and no content-named field (an author key is author content) is added to an event (per test-plan §3 Events · `run {selection}`).
- tests ↔ arch incremental invariant: the stand's fresh-boot vs incremental identity checks and the `incremental_oracle` differential test carry it. Id checks run under both `stand::options` modes (per test-plan §2 Differential oracle).
- tests ↔ a11y: the `a11y` leg's three files (`accessibility_hidden`, `accessibility_roles`, `focusability_updates`) stay green unchanged. Ids on accessibility nodes are v010-03, not this chunk (per test-plan §9 Legs).

## Acceptance criteria contributions
- For each lean task (counter, flight booker, timer, CRUD), a `tests/blitz-tests/tests/stand_*.rs` check boots it with `stand::boot` / `boot_timer` and `stand::options`. It walks every element, chrome and task body alike, and asserts unconditionally that the walk is non-empty and that each element reads exactly one id. Keyed elements must read their key, every other element its component path, and no two elements in the document may share an id (per test-plan §3 blitz-test-harness Construction · §2 Font-dependent tests · §4 Conditional assertions).
- Each per-task id check passes under both `stand::options(false)` and `stand::options(true)` and reads the same id set in both (per test-plan §2 Differential oracle).
- `bash scripts/agent-run.sh boot`, then `bash scripts/agent-run.sh run stand`, exits 0. Every new stand check shows as an `ok` `test` event, and `run.end` reads `outcome: passed` (per test-plan §3 `run {selection}` · Events).
- `bash .github/scripts/ci-leg.sh fast` and `bash .github/scripts/ci-leg.sh doc` exit 0. The chunk report re-counts the workspace test line against the 431 · 0 · 4 baseline: the new checks raise the passed count, with 0 failed (per test-plan §9 Local pre-push gate · Legs · Local baseline).
