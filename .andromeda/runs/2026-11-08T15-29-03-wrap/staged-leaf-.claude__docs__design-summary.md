### Typography · spacing · depth · radius · motion
> NOT YET MEASURED / NO RECORDED INTENT — no project-wide type scale, spacing unit, elevation, radius or motion tokens. Engine facts: `mix-blend-mode` other than `normal` makes a stacking-context root and, with `isolation`, paints through `blitz-paint`'s `blend` module in a viewport-wide layer, no test painting a blended element to a frame; default generic size 16px (13px monospace); an open select list's row height is the select's font on one line, a larger authored font clipping, a standing limit, and a group's `label` there paints as a header heavier than a row on every build; WASM builds bundle DejaVu Sans for every generic family (the native headless stand's font registration is held in architecture §Standard Contracts → Headless stand, not as a design-system typography value); since 2026-10-12-headless-screenshot a driver `screenshot` of an app whose font context resolves no `sans-serif` family is refused `fonts-unavailable` with nothing painted — a shot never paints text skipped — and the stand's bundled font passes that check; the stand's Cells grid brings its current cell into view with no animation, its arrow keys' handler calling `MountedData::scroll_to(ScrollBehavior::Instant)` synchronously; a programmatic into-view scroll never animates a nested scrolling box — each is written at once, the requested behaviour applying to the viewport alone — and the driver's `scroll` is instant in every box and in the viewport (ratified by the founder, 2026-10-07); into view on a row of an open select list writes that list's own scroll at once, moving no other box and no viewport, and the list has no motion and needs no `advance`; since 2026-10-18-one-virtual-clock the harness's documents read one `VirtualClock` — the overlay scrollbar fade, smooth scrolling and the fling read it headlessly — and the driver's `advance` moves it by exactly its `ms` together with the app's own time (ratified by the founder, 2026-10-18), while `click`, `type` and `press` leave it where it was, so after a driver `scroll` a settle reads `animating` true until 700 ms of that clock pass, and the shown overlay scrollbar takes a main-button pointerdown in its band as a thumb drag, so a driver `click` on a Cells cell in that band right after a `scroll` lands on the scrollbar and an `advance` past the fade comes first; since 2026-10-20-load-wait the driver's load wait moves no clock — while an acting step waits on a load in flight, for at most `LOAD_WAIT` (5 s of wall time), the `VirtualClock` stands still, so a timer or an animation does not run during the wait; an inline box holding only block children paints no shadow, background or border of its own, unit tests reading the flag and no frame test reading the skip.

## Component patterns
- Each Dioxus document starts as `<html><head></head><body><main id="main"></main></body></html>`; the app mounts into `main`.
- Viewport = window surface minus safe-area insets; the test harness defaults to 800×600 @1 light.
- Devtools overlays (content/padding/border/margin) and layout outlines exist as `DevtoolSettings`.
- Browser controls are clickable `div`s, not buttons (an a11y gap noted in a11y-plan §4). A single select's list is painted, an engine overlay reaching the screen through `paint_scene` alone and no second OS window: a click, Enter, or a Space with no typed text standing opens it, a group's `label` is named in the accessibility tree and painted as a header, and `size` is read on a `multiple` select and stays unread on a single select; a `multiple` select lays out as `display: block`, `white-space: nowrap` rows padded 0 2px and a single-choice select's group is transparent to layout (`display: contents`) — engine defaults, no design token.
