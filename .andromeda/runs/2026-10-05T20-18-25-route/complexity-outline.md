## Epoch outline (6 epochs)

### Epoch 1 — Foundation

- **Scope:** as-built baseline green on this host + fork CI reached + the headless harness booting the 7GUIs stand + each growing gate's reachability run + absent plan bootstraps
- **Drilldown depth:** 1
- **Estimated chunks:** 4
- **Concerns:**
  - as-built baseline: workspace build + blitz-tests green on this host (calibration §Adopted project; intent §Principles order step 1)
  - fork CI reached: the pipeline runs on the escher fork's build branch (intent §Principles)
  - headless stand boot: the chosen 7GUIs tasks (counter · flight booker · timer · CRUD) mounted headless with no display (intent §Principles "the stand is the proof")
  - reachability chunks for gates that grow with the code, plus bootstrap items the plans list absent (Phase 1 resolves these from the 6 plans)

### Epoch 2 — Element identity

- **Scope:** stable semantic ids for every stand element: assignment, persistence and cross-surface coherence
- **Drilldown depth:** 1
- **Estimated chunks:** 3
- **Concerns:**
  - id assignment: author key, else component path (v010-01)
  - persistence across re-render, remount and fresh process (v010-02)
  - coherence: the same id in snapshot, accessibility tree and driver (v010-03; the a11y side lands here, the snapshot/driver sides verify later)

### Epoch 3 — Observation model

- **Scope:** the snapshot data model and its compact serialization, plus change tracking that yields a post-action diff
- **Drilldown depth:** 1
- **Estimated chunks:** 4
- **Concerns:**
  - snapshot tree model id · role · name · state · bounds (v010-04)
  - state fidelity: enabled, checked, value, focused (v010-05)
  - compact serialization, readable whole in one tool result (v010-04)
  - change tracking + diff: exactly the changed nodes, empty for a no-op, fixing the inverted `has_changes()` (v010-06)

### Epoch 4 — Driver core

- **Scope:** settle detection, act-by-id, and the single command + refusal schema the surfaces will expose
- **Drilldown depth:** 1
- **Estimated chunks:** 4
- **Concerns:**
  - settle detection: an action returns once the UI is quiescent, including delayed updates (v010-10)
  - act by stable id (v010-09)
  - refusal model: not found · stale · disabled · covered · off-screen, each with its remedy (v010-11, v010-14 remedy half)
  - one command schema: verb set + argument/result shapes (v010-14 verb-set half)

### Epoch 5 — Agent surfaces

- **Scope:** the driver exposed as a CLI and as MCP tools, self-describing through help + schemas, plus the display-free screenshot command
- **Drilldown depth:** 1
- **Estimated chunks:** 4
- **Concerns:**
  - CLI: JSON output, accepted/refused exit codes, a shell-scriptable stand flow (v010-12)
  - MCP surface over the same commands (v010-13)
  - self-description: help + schemas served by the tool (v010-14)
  - screenshot of the screen or one element, deterministic on the same host (v010-07, v010-08)

### Epoch 6 — Polish & ship

- **Scope:** the cold-agent test last, the stand coverage sweep across all requirements, and the full assertions of gates reached in Foundation
- **Drilldown depth:** 1
- **Estimated chunks:** 3
- **Concerns:**
  - cold-agent test: a fresh agent with only the tool completes a stand task + writes a passing check, wrong calls counted (v010-15)
  - stand coverage: every requirement exercised headless across the chosen 7GUIs tasks (intent §Principles)
  - full gate assertions for gates whose reachability landed in Foundation (Phase 1 resolves from the plans)

## Notes for Phase 1 synthesis

- intent §Principles fixes the order: baseline+CI → stand harness → stable ids → snapshot model+serialization →
  change tracking → settle detection → command/refusal schema → CLI → MCP → screenshot → cold-agent test. The
  linearized route must respect it. Every chunk sits on an abstraction an earlier chunk built.
- v010-03 (id coherence) spans three epochs. Its owning chunk should come after the driver acts by id (Epoch 4), so
  only a late chunk can fully prove it. Earlier chunks partially advance it.
- The stand harness chunk (Foundation) is what every later acceptance runs on. Place it before any identity work.
- The screenshot comes after MCP per the intent order, even though a CPU raster + PNG writer already exist (intent §4 OBSERVED).
