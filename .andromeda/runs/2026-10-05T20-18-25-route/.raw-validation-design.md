# Design validation — route draft

## Rewrite
- `Headless stand`: "counter, flight booker, timer, CRUD mounted with no display, booted fresh per check" → "seven_guis counter, flight booker, timer, CRUD in TaskShell, no display, fixed viewport, scale and light scheme, booted fresh per check"
  Reason: The stand is escher's only per-surface scaffold. It should name its layout template (layout-templates §Surface: desktop-native, Primary screens, seven_guis Home/TaskShell) and pin the harness defaults (§IA notes, 800x600, scale 1, light), because snapshot bounds and screenshot pixels depend on them. No tokens or brand chunk is needed: design-system records no project-wide token set (§Color/§Typography/§Spacing/§Border Radius say NOT YET MEASURED) and no brand intent (§Brand Identity says NO RECORDED INTENT).
- `Headless screenshot`: "identical pixels on repeat" → "identical pixels on repeat using the stand's bundled font, independent of host fonts"
  Reason: Pixel identity depends on the font stack, and design-system §Surface: web-spa Tokens records that bundled DejaVu Sans covers all generic families, while §Typography records no project type scale to fall back on.
- `Driver CLI`: "every command with JSON output" → "every command with uncoloured JSON on stdout, diagnostics on stderr"
  Reason: Per design-system §Surface: cli, existing binaries only use colour and hyperlinks when stdout is a terminal (Tokens) and send errors to stderr (Component Patterns), and the agent-readable output should follow the same convention.
