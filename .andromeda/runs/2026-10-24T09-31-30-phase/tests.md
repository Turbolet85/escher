## Patterns to follow
- Record a sync's count moves the way earlier syncs did. `run stand`'s `run.end` should be unmoved, from 195 · 0 · 7 over 48 files. `run all` gains upstream's new non-`stand_` files with no change to `scripts/agent-run.sh`, each addition named by file and count (per test-plan §3 Test Harness Contract, Agent-run contract Proof).
- Upstream's merged checks keep upstream's assertion form, test-that's `verify_that!` / `TestResult<()>` under the standard `#[test]` harness. test-that 0.6.0 is a reviewed dev-dependency. A new or bumped test-only crate a take brings is reviewed by hand at the bump, as test-that's was (per test-plan §3 Test Harness Contract, Rust tests and Third-party test frameworks).
- The stand checks have no skip path: they assert unconditionally under the bundled DejaVu Sans with system fonts off. A take that moves layout or style numbers shows up as a moved assertion to re-measure, not as a skip (per test-plan §2 Test Strategy, Font-dependent tests).
- The escher-telemetry capture checks are the sink allowlist's standing readings, at 0 id, name and typed-text needles under both builds: `host_log`, `mcp_log`, `stand_act_spans` and the `telemetry_*` files (per test-plan §3 Test Harness Contract, Stand log format).

## Anti-patterns to avoid
- Never count a sink capture's lines in total. A check that reads one counts lines by target, because the workspace build adds engine lines (per test-plan §9 CI Integration, Engine features by runner).
- Never treat an empty run as a pass. `run.end` is `passed` only on cargo exit 0, no failure and at least one parsed test line (per test-plan §3 Test Harness Contract, Agent-run contract `run {selection}`).
- Never compare a screenshot byte for byte across OSes. A shot's PNG bytes differ between linux x86_64 and macOS aarch64 (per test-plan §2 Test Strategy, Pixel tests).
