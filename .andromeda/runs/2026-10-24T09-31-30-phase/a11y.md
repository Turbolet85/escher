## Constraints
- The a11y target stays tier 0, SC 2.1.1 · 1.4.3 · 2.4.3. `accessibility` is a default feature of both Dioxus crates, and the workspace takes them with `default-features = false`. It reaches seven_guis through escher-driver, which names it unconditionally (per a11y-plan §1 A11y Scope Summary). A take of `286874cc1` (Dioxus `0.8.0-alpha.3`, the dioxus-native(-dom) manifests synced) must keep that wiring. Whether the synced manifests still carry it is research's question.
- a11y-plan §2 A11y Strategy (Accessibility tree lifecycle) requires two things. The tree is built and refreshed through the `Document::accessibility_tree` trait method, so DioxusDocument's override (stable ids) reaches the shell. The changed set is marked by in-document mutations, focus and checked changes, text input and a select's changed choice, and by nothing else. The predicted `packages/blitz-dom/src/mutator.rs` conflict and upstream's new `mutation_buffer.rs` must resolve with both intact.
- a11y-plan §2 A11y Strategy (Role derivation) requires the builder's reads to stand as recorded: `aria-selected` · `aria-pressed`/`aria-checked` by role · `aria-invalid`, a select's option reading its chosen state, and upstream's six merged reads. `06ecec886` touches `packages/blitz-dom/src/accessibility.rs`. Whether that hunk moves any read is research's question.
- a11y-plan §5 Keyboard Navigation (Focus order, Keyboard handling) requires several behaviours to hold on the merged engine. Focusability: no inert node is focusable, and `disabled` counts by its presence on a form control alone. Enter and Space dispatch a Click on the named elements. The range input and the single-choice select take their keys. Upstream's delta reaches `node/node.rs`, `events/pointer.rs` and `document.rs`.
- a11y-plan §5 Keyboard Navigation (Script and framework exposure) requires a falsy Dioxus value of one of the bridge's 28 boolean attributes (`is_bool_attr`, `disabled` · `hidden` · `inert` among them) to remove the attribute on both attribute paths. `286874cc1` re-syncs `mutation_writer.rs` and `events.rs`, through which keyboard and focus events reach Dioxus. Whether the predicate and the event forwarding survive is research's question.
- a11y-plan §6 Visual Design Verification (Color contrast) requires `stand_contrast`'s three tables to be asserted row for row in both layout modes. A row is exempt exactly where the snapshot's `enabled` reads `Some(false)`. A Stylo move (`06ecec886`, `3954ecb85`) can change computed colours or font metrics.
- a11y-plan §6 Visual Design Verification (Visibility and hit-testing) requires an element carrying `inert`, and its subtree, to be passed through by a hit and left out of the tree, and removing `inert` to restore both. `f102663b8` changes hit testing (`hit_inner`) to skip dropped nodes. That ground must keep the inert pass-through.

## Patterns to follow
- Each assertion is a Rust test in blitz-tests over the built AccessKit tree, with one stated table per attribute and its row count asserted, run in both layout modes (per a11y-plan §3 A11y Assertion Harness Contract).
- The stand's keyboard proof drives Tab, Shift+Tab, Enter, Space and the CRUD list keys through the harness's `press` / `press_with`. At every step the engine's focus, the snapshot's `focused` node and the tree's focus must agree (per a11y-plan §5 Keyboard Navigation, Test harness pattern).
- The `a11y` leg's file set is stated and closed (per a11y-plan §9 CI Integration). Upstream's new targets (`hit_test_dropped_nodes`, `stale_node_mapping`) join the workspace test leg, not that leg.
- On the stand, every element node carries its stable id as `author_id`, and the tree the shell hands the adapter equals the harness's tree node for node (per a11y-plan §7 Screen Reader Support). `stand_accessibility_ids` is the reading after a `dioxus_document.rs` re-sync.

## Anti-patterns to avoid
- Never add a second role or name mapping. The snapshot, its text, parts, diff and MCP results read the tree's role, name and states and nothing else (per a11y-plan §7 Screen Reader Support), so a conflict resolution in `dioxus_document.rs` must not re-derive them from the element.
- Never widen the contrast exempt rule beyond `enabled` reading `Some(false)`, and never add a second contrast formula or threshold, including in the lint's `contrast` reading (per a11y-plan §6 Visual Design Verification).

## Contract bindings
- a11y ↔ tests: the `a11y` leg's three `stand_*` files also run three times in the `stand-repeat` leg under the zero-failure budget (per a11y-plan §9 CI Integration ↔ test-plan §10). The per-OS tally re-read covers the `a11y` job's log.
- a11y ↔ design: `stand_contrast`'s rows are the stand's token pairs (per a11y-plan §6 Visual Design Verification ↔ design-system §Color Palette). A Stylo-moved colour reading moves both records together.
- a11y ↔ layouts: `stand_keyboard`'s `tab_order` / `ENABLED_TAB_ORDER` tables are the per-surface tab sequences (per a11y-plan §5 Keyboard Navigation ↔ layout-templates focus order).
