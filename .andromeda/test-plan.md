## 2. Test Strategy

Detail: .andromeda/test-plan-detail/test-strategy.md — read whole.

**Test levels observed:**

- **Inline unit tests:** Rust `#[test]` functions inside `#[cfg(test)]` modules next to the code under test (packages/blitz-dom/src/stylo_to_parley.rs:525-528; packages/blitz-dom/src/util.rs:180-182; packages/blitz-dom/src/node/scrollbar.rs:224-229; packages/blitz-dom/src/node/element.rs:1071-1089; packages/blitz-dom/src/node/node.rs:2078-2084; packages/dioxus-native-dom/src/dioxus_document.rs:419-420; packages/dioxus-native-dom/src/events.rs:677-678)
- **blitz-dom pipeline tests:** tests build a `BaseDocument` directly from `DocumentConfig` and construct the DOM through `DocumentMutator` (packages/blitz-dom/src/mutator.rs:1665-1681); DOM fixtures are built manually because the HTML parser lives in blitz-html, which the comment says would be a circular dev-dependency (packages/blitz-dom/src/document.rs:3196-3201; packages/blitz-dom/src/document.rs:3670-3675); pipeline tests call `resolve(0.0)` and assert on resulting layout or computed styles (packages/blitz-dom/src/mutator.rs:1876-1901; packages/blitz-dom/src/document.rs:3349-3381)
- **Browser app:** persistence tests target the inner SQL functions with a freshly migrated in-memory connection rather than the `HistoryStore` wrapper (apps/browser/persistence/src/lib.rs:306-326); in-memory history tests call `record_visit_inner` directly on a `VecDeque` (apps/browser/src/browser_history.rs:178-207); URL suggestion tests split a synchronous nucleo driver from worker-level tokio tests covering the command state machine (apps/browser/src/url_suggestions.rs:390-406; apps/browser/src/url_suggestions.rs:547-549)

- **Harness-driven tests:** the harness wraps any blitz_dom Document, such as HtmlDocument or DioxusDocument, with deterministic construction defaults, a pump/tick loop, `settle`, inspection helpers and input synthesis, and paints a frame with no display and reads a text-bearing element's contrast; `dom_string` produces a stable one-node-per-line tree serialization suitable for snapshot-style assertions

- **Integration tests (tests/blitz-tests):** two styles — direct `HtmlDocument` + `DocumentConfig` construction, and the `blitz_test_harness::Harness` wrapper over `HtmlDocument` and `DioxusDocument` (tests/blitz-tests/tests/comment_layout.rs:14-25; tests/blitz-tests/tests/harness_smoke.rs:1-3)

- **Process-lifecycle checks:** a check that needs a session process starts and stops its own host with every wait bounded, a guard that kills and reaps a host a failing check still holds, its state directory removed at `stop`, and the child's streams sent to null unless the check reads them, so the child's libtest lines never reach `agent-run.sh`'s count; a check holding a session over the socket is `cfg(unix)`-gated

- **Waiting on a host:** a check that waits for an expiry watches the state directory, because an `attach` is an answered request and starts the count again; a check that captures a host which installs escher's sink drains its pipes while the host runs, or captures to a file, so it cannot wait for exit before it reads

- **Command-line checks and shell flows:** seven_guis' checks run the package's own `escher-session` binary once per command as a client process and read its stdout, its stderr and its exit status through the shared runner, which bounds the run and drains both streams; the POSIX `sh` flow scripts are assets of a `cargo test` target, not a runner of their own, and no test framework is added; the targets are `cfg(unix)`-gated

- **Recorded-check replay:** a check a session recorded is committed as data under `tests/blitz-tests/checks/` and run as an ordinary `cargo test` target through `Check::replay`, red at the first step whose acceptance or kept answer differs, and kept fresh by a byte-for-byte comparison with what the binary records

- **Differential oracle:** the same fixture and mutation sequence runs in an incremental and a non-incremental document, comparing every node's `final_layout()`, `layout_children` and paint tree after each step and asserting no damage remains (tests/blitz-tests/tests/incremental_oracle.rs:1-19; tests/blitz-tests/tests/incremental_oracle.rs:314-347)

- **Pixel tests:** render to a CPU buffer and sample pixels, box-shadow expectations coming from Chromium renders with a 1px antialiasing tolerance; frames are also compared whole, a shot's PNG equal to the harness's raster and byte-identical across runs on one host; a shot's PNG bytes differ between OSes, so a check compared byte for byte across OSes holds no shot

- **Randomized stress:** deterministic pseudo-random template swaps (an LCG) run 1000 steps to shake out slab/ElementId reuse bugs (tests/blitz-tests/tests/stale_node_mapping.rs:176-217)
- **Pure-restyle paths:** driven by `:hover` rather than attribute mutation because mutations insert full damage and mask under-damaging bugs (tests/blitz-tests/tests/oof_dynamic_cb.rs:143-145; tests/blitz-tests/tests/anonymous_block_cache_invalidation.rs:6-9)

- **Font-dependent tests:** the pre-existing ones skip at runtime when no usable font is available; the headless-stand checks have no skip path — they assert unconditionally under the bundled DejaVu Sans with system fonts off; a shot of a document whose font context resolves no `sans-serif` family is refused, `fonts-unavailable` at the driver, with nothing painted and no skip path

- **Script tests (blitz-vibey-script):** tests build a `ScriptDocument` from inline HTML, run its scripts, then assert DOM text via selector queries (packages/blitz-vibey-script/tests/dom.rs:8-21); events are driven with synthetic click events and `UiEvent::KeyDown` rather than real input (packages/blitz-vibey-script/tests/dom.rs:179-190; packages/blitz-vibey-script/tests/preact.rs:68-100); timer tests sleep in real time before polling (packages/blitz-vibey-script/tests/dom.rs:278-280; packages/blitz-vibey-script/tests/dom.rs:299-300)

- **WPT conformance:** reftests render test and reference to RGBA buffers at 800x600 and compare them exactly, by fuzzy tolerance or by dify diff; attr tests check element layout against `data-expected-*` attributes; harness tests run real testharness.js and collect per-subtest results; a conformance reading on the fork's dev host is report-only and grades no criterion

- **WPT scoring:** partial passes are counted fractionally (pass/total per test) in addition to whole-test counts (wpt/runner/src/main.rs:144-150; wpt/runner/src/main.rs:679-680; wpt/runner/src/main.rs:814-817); failures are bucketed by the first matching feature flag (grid-lanes, subgrid, writing-mode, direction, intrinsic size, calc, float, script) else "other" (wpt/runner/src/main.rs:652-671); WPT results are diffed against the main-branch report and summarised per test as gained/lost subtests (.github/workflows/wpt.yml:68-79; .github/scripts/wpt_diff_to_pr.py:192-249)
- **WPT ports:** WPT script tests are ported to Rust when the WPT runner cannot run them (tests/blitz-tests/tests/oof_dynamic_cb.rs:7-12)
- **MSRV:** verified by build only, not test (.github/workflows/ci.yml:28-33)
- **Example fixtures (human-read):** fixture prose states the expected rendering for a human viewer: frame navigation replaces only the sub-document (examples/assets/iframe_navigation.html:33-36; examples/assets/iframe_navigation.html:58-61); fixture comments state what a case checks: correct alpha with no double-paint, and per-run ascent/descent (examples/assets/inline-backgrounds.html:40; examples/assets/inline-backgrounds.html:47; examples/assets/inline-backgrounds.html:84-86); the hr fixture's first case is left unstyled to show the UA stylesheet only (examples/assets/hr.html:33-36; examples/assets/hr.html:195); full real-page snapshots are paired with reduced variants (examples/assets/google_reduced.html:1-9; examples/assets/gosub_reduced.html:1-12; examples/assets/servo-new-reduced.html:1-51; examples/assets/servo-new-reduced-1.html:1-31)
- **Slice s03:** no test functions — observed absent · searched: `#\[test\]` and `#\[cfg\(test` over the 32 files of slice s03

**Test directory + naming conventions:**

- **Directory pattern:** inline `#[cfg(test)]` modules in source files, bar the modules held in files of their own through `#[path]`; `tests/blitz-tests` holds one test-target file per behavior, three shared modules that are no target and the unbuilt `tests/all.rs` — upstream's layout is one `all` target, the fork keeps one target per file, pinned by `BlitzTestsTargetsTest` (§4); `examples/seven_guis` holds its integration-test targets, a shared module and the flow scripts under `tests/`

**Agent-run contract (the 5-command discipline, for the stand checks and blitz-tests):**

- **Invocation:** `bash scripts/agent-run.sh {boot | run {selection} | status | cleanup | logs}` from the repository root (scripts/agent-run.sh:8; scripts/agent-run.sh:163-226); `scripts/agent-run.ps1` is the Windows entry — it passes every argument unchanged to `bash scripts/agent-run.sh` and exits with its code, holding no contract logic, and is not run on the dev host (`pwsh` absent) (scripts/agent-run.ps1:1-4). The script itself starts, polls and listens on nothing: no daemon, PID file, status endpoint, port or socket, and it reads no environment variable of its own. The stand checks it runs boot in process — bar two of the `run stand` selection, `stand_session_lifecycle` and `stand_session_quiet`, which start and stop a session host process of their own and its Unix-domain socket: a surface of the session library and of those checks (§3 → Session lifecycle), not of this contract
- **Exit grammar, every verb:** `0` success · `1` the verb ran and failed (a cargo build failure, a failing run, an empty run) · `2` usage (a missing or unknown verb, a wrong argument count, an unknown selection) · `3` a precondition is unmet (not booted; `logs` with no events file); a usage error is checked before not-booted (scripts/agent-run.sh:12-17; scripts/agent-run.sh:176-195)
- **`boot`:** runs the no-op `ensure_fresh_artifacts` first, recreates `target/agent-run/` (a fresh `events.jsonl`), builds every blitz-tests test binary with `cargo test -p blitz-tests --locked --no-run` (merged output to `run.log`), writes `status.json` (`booted`, `boot_ts`, `head` — `git rev-parse HEAD`, null outside a work tree) and emits the `boot` event; exit 0 ready, 1 failed with `booted` false (scripts/agent-run.sh:165-174)
