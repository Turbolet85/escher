## 2. Test Strategy

**Test levels observed:**

- **Browser app:** persistence tests target the inner SQL functions with a freshly migrated in-memory connection rather than the `HistoryStore` wrapper (apps/browser/persistence/src/lib.rs:306-326); in-memory history tests call `record_visit_inner` directly on a `VecDeque` (apps/browser/src/browser_history.rs:178-207); URL suggestion tests split a synchronous nucleo driver from worker-level tokio tests covering the command state machine (apps/browser/src/url_suggestions.rs:390-406; apps/browser/src/url_suggestions.rs:547-549)

**Agent-run contract (the 5-command discipline, for the stand checks and blitz-tests):**

- **Invocation:** `bash scripts/agent-run.sh {boot | run {selection} | status | cleanup | logs}` from the repository root (scripts/agent-run.sh:8; scripts/agent-run.sh:163-226); `scripts/agent-run.ps1` is the Windows entry — it passes every argument unchanged to `bash scripts/agent-run.sh` and exits with its code, holding no contract logic, and is not run on the dev host (`pwsh` absent) (scripts/agent-run.ps1:1-4). The stand is an in-process library boot, so nothing is started, polled or listened on: no daemon, PID file, status endpoint, port or socket, and the script reads no environment variable of its own
- **Exit grammar, every verb:** `0` success · `1` the verb ran and failed (a cargo build failure, a failing run, an empty run) · `2` usage (a missing or unknown verb, a wrong argument count, an unknown selection) · `3` a precondition is unmet (not booted; `logs` with no events file); a usage error is checked before not-booted (scripts/agent-run.sh:12-17; scripts/agent-run.sh:176-195)
- **`boot`:** runs the no-op `ensure_fresh_artifacts` first, recreates `target/agent-run/` (a fresh `events.jsonl`), builds every blitz-tests test binary with `cargo test -p blitz-tests --locked --no-run` (merged output to `run.log`), writes `status.json` (`booted`, `boot_ts`, `head` — `git rev-parse HEAD`, null outside a work tree) and emits the `boot` event; exit 0 ready, 1 failed with `booted` false (scripts/agent-run.sh:165-174)
- **`run {selection}`:** `stand` = one `--test {stem}` per `tests/blitz-tests/tests/stand_*.rs` present · `all` = the whole package, no `--test` · `{name}` = one file, matching `^[a-z0-9_]+$` with `tests/blitz-tests/tests/{name}.rs` present; anything else exits 2. It runs `cargo test -p blitz-tests --locked [--test …]` with merged output to `run.log` (truncated at the run's start), sets `status.json`'s run state `running` then `passed` or `failed`, and parses libtest's pretty lines into events. The outcome is `passed` only when cargo exited 0, no test failed and at least one test line parsed — otherwise `failed`, exit 1: an empty run is never a pass. `run stand` with no `stand_*.rs` present is an empty run — no cargo call, `cargo_exit` null, exit 1 (scripts/agent-run.sh:176-210; scripts/agent-run.sh:126-138)
- **`status`:** prints one `status` object from `status.json` and builds or runs nothing; exit 0 booted, 3 not (no `status.json`, or `booted` false) (scripts/agent-run.sh:111-116; scripts/agent-run.sh:211-213)
- **`cleanup`:** removes `target/agent-run/` if present and prints the `cleanup` event; idempotent (exit 0 on a clean tree), touching nothing else under `target/` (scripts/agent-run.sh:215-218)
- **`logs`:** prints `events.jsonl` verbatim, one JSON object per line; exit 3 when it is absent. Raw cargo output stays in `run.log`, never printed (scripts/agent-run.sh:220-226)
- **Events (JSON lines, encoded by python3's `json` module embedded in the script):** `boot {ts, outcome: ready|failed, cargo_exit, head}` · `run.start {ts, selection, files}` (`files` the `--test` stems passed — `[]` under `all`) · `test {file, test, outcome: ok|failed|ignored}` (one per libtest line; `file` the target binary's stem with its hash stripped, or `doc:{crate}`) · `run.end {ts, selection, passed, failed, ignored, cargo_exit, outcome: passed|failed}` — each printed to stdout and appended to `events.jsonl`; `status {booted, boot_ts, head, run: {selection, state: none|running|passed|failed, passed, failed, ignored}}` and `cleanup {outcome: done}` are printed only. Nothing between a `failures:` line and the next `test result:` is read, so captured stdout and panic text never reach an event. This is harness metadata, not an escher-telemetry sink (obs-plan §3) (scripts/agent-run.sh:34-36; scripts/agent-run.sh:80-98; scripts/agent-run.sh:100-142)
- **State:** `target/agent-run/{status.json, events.jsonl, run.log}` only, gitignored under `target/`; one driver at a time — a killed run leaves `running` behind, which the next `run` overwrites
- **Proof:** the contract tests `test_agent_run.py` (§4) and a live run — `run stand` 13 `ok` stand events, `run all` 15 `ok` over the three a11y-leg files, cleanup idempotent, health check 13 ✓ — as measured at escher-0.1.0/chunks/2026-10-06-stand-test-contract/report.md; re-counted at 2026-10-06-stable-element-ids: `run stand` 17 `ok` stand events (+4 `stand_element_ids`, picked up by its `stand_` prefix with no script change) — as measured at escher-0.1.0/chunks/2026-10-06-stable-element-ids/report.md; re-counted at 2026-10-06-id-persistence: `run stand` 20 `ok` stand events (+3 `stand_id_persistence`, picked up by its `stand_` prefix with no script change) — as measured at escher-0.1.0/chunks/2026-10-06-id-persistence/report.md; re-counted at 2026-10-06-accessibility-tree-identity: `run stand` 25 `ok` stand events (+5 `stand_accessibility_ids`, picked up by its `stand_` prefix with no script change) — as measured at escher-0.1.0/chunks/2026-10-06-accessibility-tree-identity/report.md; re-counted at 2026-10-06-snapshot-model: `run stand` 33 `ok` stand events (+8 `stand_snapshot`, picked up by its `stand_` prefix with no script change) — as measured at escher-0.1.0/chunks/2026-10-06-snapshot-model/report.md
