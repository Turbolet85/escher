### Session lifecycle

The contract the session checks drive: one headless app instance held by one process, and the lifecycle another process drives, with the calls it sends, over a Unix-domain socket (`packages/escher-driver`; the API in full is architecture §Standard Contracts → Driver session). It is not part of the 5-command agent-run contract, which starts and binds nothing.

- **session-start:** `Session::start(label, boot)` takes a label of 1 to 32 bytes of `a-z`, `0-9` and `-`, checked before the caller's boot runs once on the calling thread; an invalid label is `InvalidLabel` with nothing booted. A check boots through `seven_guis::stand`, reads the held harness through `harness()` / `harness_mut()`, and runs one step and waits for quiet through `act(step) -> Result<Settled, SessionError>` — the closure runs on the held harness, the harness is settled, and an instance that did not go quiet is `NotSettled(Busy)`; the step is not rolled back, and `act` is in process: nothing it reads or returns crosses the socket. A check runs a driver call through `run(&Call) -> Result<Outcome, Refusal>`: the call is validated first and a refused one has run nothing; the id of a `click`, a `type` or a `scroll` is looked up on the screen as it reads now, and one that names no element there is refused with nothing run — `stale` when the session's record of the ids its screens have read holds it, `not-found` when not (the record: id text only, at most 4096 ids, for the session's life, read by nothing outside the crate); a `click` or a `type` on an element that cannot take it is refused with one answer, the first that holds in the order `disabled` · `off-screen` · `covered`, and a refused call leaves the snapshot and both focus readings as they were; each acting verb (`click` · `type` · `press` · `advance` · `scroll`) is one settled step and returns `Outcome::Acted`, `Outcome::Advanced` or `Outcome::Scrolled` with the diff of the snapshots before and after it — `scroll` adding `in_view`, whether its element is in view after the step — `snapshot` returns `Outcome::Screen` with the screen's text, and an instance that did not go quiet is a result — `settled` false with its `busy` class — not rolled back. Since 2026-10-12-headless-screenshot `run` also takes `screenshot`, the seventh instance verb, its `id` optional, and returns `Outcome::Shot { width, height, png }` — a PNG of the harness's raster, the whole screen or the element's bounds cropped to the part that can be seen and rounded outward — with no diff, a shot changing nothing (`has_changes` false, focus and the next snapshot unchanged); its `id` is looked up as a `click`'s is, refused `stale` or `not-found`, a crop of no pixel is refused `off-screen`, and an app with no font it can paint text with is refused `fonts-unavailable`, the ninth cause, with nothing painted (packages/escher-driver/src/execute.rs:63-71; packages/escher-driver/src/execute.rs:382-403). `with_time(step)` hands the session its caller's time step; a session without one refuses `advance` as `time-unavailable`. Since 2026-10-10-driver-cli: a session-level verb (`start`, `status`, `stop`) handed to `run` is refused `unknown-verb`; `type` replaces — after the focusing click, where the snapshot reads a `value` for the target (an empty text input reads the empty string), the driver presses the engine's select-all and then types, and with an empty text deletes the selection, so an empty text clears the control; and the record of ids holds no id longer than `MAX_ID_BYTES`. `act` and `with_time` are in process; `run` is also the one thing a host does with a `call` request, so that call and its answer cross the socket (session-wire), and since 2026-10-10-mcp-surface what the MCP server does with an instance verb's tool call, so that call and its result cross the `mcp` role's stdio (architecture §Standard Contracts → Driver session) (packages/escher-driver/src/session.rs:25-161; packages/escher-driver/src/execute.rs:93-232).
- **session-host:** `serve(state_dir, session, idle_expiry)` holds one session until a `stop` request or, since 2026-10-10-driver-cli, until no request has been answered for the expiry (`IDLE_EXPIRY`, 1,800 s, for a host a command line starts), ending then exactly as on `stop`; every answered request, a refused or malformed one included, counts toward `served` and starts the count again; `start(state_dir, host, ready)` spawns the host command and returns its first answer, `attach(state_dir)` returns `Hello { pid, label, served, idle_expiry_s }`, `stop(state_dir)` returns when the state directory is gone (5 s bound), and `call(state_dir, &Call) -> Result<Answer, SessionError>` with `Answer { accepted, json }` sends one call — it runs `validate` first and answers a schema refusal itself, reaching no session, and reads the answer under 30 s per read (pinned since 2026-10-14-quality-gates by `client::imp::tests::an_answer_read_past_its_bound_is_a_timeout`, a read past the bound being `Timeout`). The edges: `AnswerTooLarge` for a call's answer over the socket's bound — read from an `oversize` reply, the call having run — `NoSession` with no socket file, `Dead` with a socket nothing answers on, `AlreadyRunning` when one answers, `HostExited`, `Timeout`, `Protocol`, `StateDirTooLong`, `StateDirNotPrivate`, `Io`, and `Unsupported` on a non-unix target (packages/escher-driver/src/host.rs:35; packages/escher-driver/src/client.rs:53-119; packages/escher-driver/src/error.rs:12-190).
- **session-wire:** one request line and one reply line per connection, version `v2` on every request since 2026-10-10-driver-cli — `hello v2` → `ok v2 pid={pid} label={label} served={n} idle_expiry_s={s}`, `stop v2` → `ok v2 stopping`, `call v2 <verb> [<name>=<kind>:<value>]…` → `ok v2 accepted <json>` · `ok v2 refused <json>` · `ok v2 oversize`, a known word with another version → `refused version`, anything else → `refused malformed`; a request line is at most 16,384 bytes (was 64), a lifecycle reply at most 128, an answer at most 1,048,576 on its JSON line; a call's answer is read under 30 s per read — pinned since 2026-10-14-quality-gates by escher-driver's unix-only unit test `client::imp::tests::an_answer_read_past_its_bound_is_a_timeout`, `ANSWER.0 == wire::ANSWER_BOUND == 30 s`, a listener that accepts and never answers ending the read as `SessionError::Timeout` — every other read and write under 2 s; a call carries the element id and the typed text in, and an answer carries ids, accessible names, control values (a password's or a file input's as the fixed mask), the snapshot's text and the diff out — ratified by the founder (2026-10-10, relayed verbatim by the overseer as his chosen option label «Сокет несёт команды»; the English wording is the overseer's), where until then none of them crossed; since 2026-10-12-headless-screenshot a `screenshot` call's answer also carries the screen's pixels out — a PNG as padded base64 inside its one JSON line `{"width":…,"height":…,"png":"<base64>"}` — in band under the unchanged answer bound (the largest whole-screen answer on the stand 22,404 bytes, 2.1 % of it), ratified by the founder (2026-10-12, «В самом ответе», relayed verbatim by the overseer); no `NodeId` crosses (packages/escher-driver/src/wire.rs:15-299).
- **session-state:** a state directory the caller names, mode `0700`, holding `session.sock` (mode `0600`) alone while a session is up and absent after `stop` or the host's idle expiry; a check's own is `{CARGO_TARGET_TMPDIR}/{short name}` — a socket address leaves about a hundred bytes for the whole path (packages/escher-driver/src/host.rs:59-125; tests/blitz-tests/tests/session_common/mod.rs:260-272).
- **session-binary:** since 2026-10-10-driver-cli `escher-session <verb> … --session <dir>` is the whole command line, eleven verbs — the seven instance-level ones with their arguments as flags spelt as the schema spells them (`--id`, `--text`, `--key`, `--ms` each with one value, `--shift` bare; `screenshot` the seventh since 2026-10-12-headless-screenshot, its `--id` optional, its accepted answer one line `{"width":…,"height":…,"png":"<base64>"}`, `png` padded base64, status `0`), then `start <task>`, `status`, `stop`, then, since 2026-10-12-self-description, `help` — the task one of `counter` · `flight-booker` · `timer` · `crud`; the host role is `serve <task> --session <dir>`; since 2026-10-10-mcp-surface the `mcp` role is `mcp` alone (anything after it usage), an MCP server on the binary's standard streams holding its session in process and ending with nothing on stdout — `0` on `Ok`, `3` with the error's fixed message on stderr on `Err`; the two-argument form `<task> <state-dir>` now reads as an unknown verb (refused, status `1`); since 2026-10-12-self-description `help` takes no argument and at most one `--session <dir>`, not read, and answers `describe()`'s line on stdout, status `0`, reaching no session — `help` with an argument refused `malformed`, status `1`, `help --session` with no directory or given twice usage, status `2` — and the usage line lists `help` after `stop`. Four endings, their statuses read from `EXIT_STATUSES` since that chunk: accepted, the answer as one uncoloured line of JSON on stdout, status `0`; refused, the refusal on stdout, `1`; usage, one fixed line on stderr with stdout empty, nothing booted and no state created, `2`; session error, the error object on stdout — `kind`, `message` and, since 2026-10-12-self-description, `remedy` — and its fixed message on stderr, `3`; the host role ends with nothing written and `0` after a stop or an expiry, and `3` on a session error (was `1`). No ending writes back anything the caller typed; `main` installs the sink first, then hands argv, the four slugs and the stand's boot to `escher_driver::command_line`; the host's stderr lines carry `service.name=seven_guis`; the `timer` task's session is given the stand's time step — `stand::timer_step` over its tick handle, through `Session::with_time` — and the other three tasks' sessions carry none; `host_timer` boots the `timer` branch and drives a hosted `advance`, and `cli_commands` starts each of the four tasks — until that chunk the branch was booted by hand only (escher-0.1.0/chunks/2026-10-07-act-by-id/evidence/timer-host-boot.md) (examples/seven_guis/src/session_host.rs:8-46).
- **session-checks:** a check that needs a session process starts and stops its own host, bounds every wait, holds the host behind a guard that kills and reaps it, sends the child's streams to null unless it reads them, and, holding a session over the socket, is `cfg(unix)`-gated — since 2026-10-10-mcp-surface a check driving the `escher-session mcp` stdio child (`mcp_server`, `mcp_log`, through the shared `Speaker`) bounds every read, kills and reaps the child in its guard's `Drop` and is not unix-gated but `mcp_server`'s command-line comparison, so the windows job runs it; a zero read from a host that installs no log sink says nothing about a host that does (§5 Session host ↔ what it writes).
