### Session lifecycle

The contract the session checks drive: one headless app instance held by one process, and the lifecycle another process drives over a Unix-domain socket (`packages/escher-driver`; the API in full is architecture §Standard Contracts → Driver session). It is not part of the 5-command agent-run contract, which starts and binds nothing.

- **session-start:** `Session::start(label, boot)` takes a label of 1 to 32 bytes of `a-z`, `0-9` and `-`, checked before the caller's boot runs once on the calling thread; an invalid label is `InvalidLabel` with nothing booted. A check boots through `seven_guis::stand`, reads the held harness through `harness()` / `harness_mut()`, and runs one step and waits for quiet through `act(step) -> Result<Settled, SessionError>` — the closure runs on the held harness, the harness is settled, and an instance that did not go quiet is `NotSettled(Busy)`; the step is not rolled back, and `act` is in process: nothing it reads or returns crosses the socket. A check runs a driver call through `run(&Call) -> Result<Outcome, Refusal>`: the call is validated first and a refused one has run nothing; the id of a `click`, a `type` or a `scroll` is looked up on the screen as it reads now, and one that names no element there is refused with nothing run — `stale` when the session's record of the ids its screens have read holds it, `not-found` when not (the record: id text only, at most 4096 ids, for the session's life, read by nothing outside the crate); a `click` or a `type` on an element that cannot take it is refused with one answer, the first that holds in the order `disabled` · `off-screen` · `covered`, and a refused call leaves the snapshot and both focus readings as they were; each acting verb (`click` · `type` · `press` · `advance` · `scroll`) is one settled step and returns `Outcome::Acted`, `Outcome::Advanced` or `Outcome::Scrolled` with the diff of the snapshots before and after it — `scroll` adding `in_view`, whether its element is in view after the step — `snapshot` returns `Outcome::Screen` with the screen's text, and an instance that did not go quiet is a result — `settled` false with its `busy` class — not rolled back. `with_time(step)` hands the session its caller's time step; a session without one refuses `advance` as `time-unavailable`. Both are in process: nothing they read or return crosses the socket (packages/escher-driver/src/session.rs:24-155; packages/escher-driver/src/execute.rs:81-179).
- **session-host:** `serve(state_dir, session)` holds one session until a `stop` request; `start(state_dir, host, ready)` spawns the host command and returns its first answer, `attach(state_dir)` returns `Hello { pid, label, served }`, `stop(state_dir)` returns when the state directory is gone (5 s bound). The edges: `NoSession` with no socket file, `Dead` with a socket nothing answers on, `AlreadyRunning` when one answers, `HostExited`, `Timeout`, `Protocol`, `StateDirTooLong`, `StateDirNotPrivate`, `Io`, and `Unsupported` on a non-unix target (packages/escher-driver/src/host.rs:20; packages/escher-driver/src/client.rs:37-62; packages/escher-driver/src/error.rs:12-37).
- **session-wire:** one request line and one reply line per connection — `hello v1` → `ok v1 pid={pid} label={label} served={n}`, `stop v1` → `ok v1 stopping`, a known word with another version → `refused version`, anything else → `refused malformed`; a request line is at most 64 bytes, a reply at most 128; no element id, accessible name, control value, snapshot text or diff crosses it (packages/escher-driver/src/wire.rs:16-141).
- **session-state:** a state directory the caller names, mode `0700`, holding `session.sock` (mode `0600`) alone while a session is up and absent after `stop`; a check's own is `{CARGO_TARGET_TMPDIR}/{short name}` — a socket address leaves about a hundred bytes for the whole path (packages/escher-driver/src/host.rs:35-96; tests/blitz-tests/tests/session_common/mod.rs:228-240).
- **session-binary:** `escher-session <task> <state-dir>`, the task one of `counter` · `flight-booker` · `timer` · `crud`; exit `0` after `stop`, `1` on an error with its message on stderr, `2` on any other argv with nothing booted and no state created; stdout empty on every path; its stderr lines carry `service.name=seven_guis`; the `timer` task's session is given the stand's time step — `stand::timer_step` over its tick handle, through `Session::with_time` — before `serve`, and the other three tasks' sessions carry none; no standing check boots the `timer` branch (`host_binary` boots `counter`, `host_log` `crud`) — it is booted by hand only (escher-0.1.0/chunks/2026-10-07-act-by-id/evidence/timer-host-boot.md) (examples/seven_guis/src/session_host.rs:5-59).
- **session-checks:** a check that needs a session process starts and stops its own host, bounds every wait, holds the host behind a guard that kills and reaps it, sends the child's streams to null unless it reads them, and is `cfg(unix)`-gated; a zero read from a host that installs no log sink says nothing about a host that does (§5 Session host ↔ what it writes).
