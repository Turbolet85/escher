### Session lifecycle

The contract the session checks drive: one headless app instance held by one process, and the lifecycle another process drives over a Unix-domain socket (`packages/escher-driver`; the API in full is architecture §Standard Contracts → Driver session). It is not part of the 5-command agent-run contract, which starts and binds nothing.

- **session-start:** `Session::start(label, boot)` takes a label of 1 to 32 bytes of `a-z`, `0-9` and `-`, checked before the caller's boot runs once on the calling thread; an invalid label is `InvalidLabel` with nothing booted. A check boots through `seven_guis::stand`, reads the held harness through `harness()` / `harness_mut()`, and runs one step and waits for quiet through `act(step) -> Result<Settled, SessionError>` — the closure runs on the held harness, the harness is settled, and an instance that did not go quiet is `NotSettled(Busy)`; the step is not rolled back, and `act` is in process: nothing it reads or returns crosses the socket (packages/escher-driver/src/session.rs:35-78).
- **session-host:** `serve(state_dir, session)` holds one session until a `stop` request; `start(state_dir, host, ready)` spawns the host command and returns its first answer, `attach(state_dir)` returns `Hello { pid, label, served }`, `stop(state_dir)` returns when the state directory is gone (5 s bound). The edges: `NoSession` with no socket file, `Dead` with a socket nothing answers on, `AlreadyRunning` when one answers, `HostExited`, `Timeout`, `Protocol`, `StateDirTooLong`, `StateDirNotPrivate`, `Io`, and `Unsupported` on a non-unix target (packages/escher-driver/src/host.rs:20; packages/escher-driver/src/client.rs:37-62; packages/escher-driver/src/error.rs:12-37).
- **session-wire:** one request line and one reply line per connection — `hello v1` → `ok v1 pid={pid} label={label} served={n}`, `stop v1` → `ok v1 stopping`, a known word with another version → `refused version`, anything else → `refused malformed`; a request line is at most 64 bytes, a reply at most 128; no element id, accessible name, control value, snapshot text or diff crosses it (packages/escher-driver/src/wire.rs:16-141).
- **session-state:** a state directory the caller names, mode `0700`, holding `session.sock` (mode `0600`) alone while a session is up and absent after `stop`; a check's own is `{CARGO_TARGET_TMPDIR}/{short name}` — a socket address leaves about a hundred bytes for the whole path (packages/escher-driver/src/host.rs:35-96; tests/blitz-tests/tests/session_common/mod.rs:66-78).
- **session-binary:** `escher-session <task> <state-dir>`, the task one of `counter` · `flight-booker` · `timer` · `crud`; exit `0` after `stop`, `1` on an error with its message on stderr, `2` on any other argv with nothing booted and no state created; stdout empty on every path; its stderr lines carry `service.name=seven_guis` (examples/seven_guis/src/session_host.rs:5-55).
- **session-checks:** a check that needs a session process starts and stops its own host, bounds every wait, holds the host behind a guard that kills and reaps it, sends the child's streams to null unless it reads them, and is `cfg(unix)`-gated; a zero read from a host that installs no log sink says nothing about a host that does (§5 Session host ↔ what it writes).
- **session-proof:** `stand_session_state` 3 · `stand_session_ids` 2 · `stand_session_fresh` 2 · `stand_session_lifecycle` 1 (+1 ignored host child) · `stand_session_quiet` 1 (+1 ignored host child) · seven_guis `host_binary` 2 · seven_guis `host_log` 1 (the `escher-session` binary at `RUST_LOG=trace`: no stable id and no accessible name on stderr) · `stand_settle` 8 (`Session::act` in four of them) · escher-driver's lifecycle unit tests 13 (error.rs 3 · session.rs 2 · wire.rs 8; the crate's other 12 pin the command and refusal schema, which is no part of this contract) — as measured at escher-0.1.0/chunks/2026-10-07-driver-session/report.md, `host_log` at escher-0.1.0/chunks/2026-10-07-sink-target-allowlist/report.md, `stand_settle` at escher-0.1.0/chunks/2026-10-07-settle-detection/report.md, the crate's 25 at escher-0.1.0/chunks/2026-10-07-command-and-refusal-schema/report.md; the fork's CI run 37580856074 on `91484eb0` is the witness of the macOS, windows, iOS and android legs, its run 37592418443 on `25d9b72d` (16 of 16 jobs green, read by conclusion only) of `host_log` on them, and its run 37610657363 on `0e4434ec` (16 of 16 jobs green, read by conclusion only) of `stand_settle` on them.
