### Session lifecycle

The contract the session checks drive: one headless app instance held by one process, and the lifecycle another process drives, with the calls it sends, over a Unix-domain socket (`packages/escher-driver`; the API in full is architecture §Standard Contracts → Driver session). It is not part of the 5-command agent-run contract, which starts and binds nothing.

- **session-start:** `Session::start(label, boot)` takes a label of 1 to 32 bytes of `a-z`, `0-9` and `-`, checked before the caller's boot runs once on the calling thread; an invalid label is `InvalidLabel` with nothing booted. A check boots through `seven_guis::stand`, reads the held harness through `harness()` / `harness_mut()`, and runs one step and waits for quiet through `act(step) -> Result<Settled, SessionError>` — the closure runs on the held harness, the harness is settled, a load in flight waited for up to `LOAD_WAIT` (5 s of wall time, settled again every 10 ms, no time moving on the held instance) since 2026-10-20-load-wait, and an instance that did not go quiet is `NotSettled(Busy)`, one still loading at the bound `NotSettled(Loads)`; the step is not rolled back, and `act` is in process: nothing it reads or returns crosses the socket. A check runs a driver call through `run(&Call) -> Result<Outcome, Refusal>`: the call is validated first and a refused one has run nothing; the id of a `click`, a `type` or a `scroll` is looked up on the screen as it reads now, and one that names no element there is refused with nothing run — `stale` when the session's record of the ids its screens have read holds it, `not-found` when not (the record: id text only, at most 4096 ids, for the session's life, read by nothing outside the crate); a `click` or a `type` on an element that cannot take it is refused with one answer, the first that holds in the order `disabled` · `off-screen` · `covered`, and a refused call leaves the snapshot and both focus readings as they were; each acting verb (`click` · `type` · `press` · `advance` · `scroll`) is one settled step, waiting on a load in flight as `act` does on every carrier while `snapshot`, `screenshot` and `lint` run no step and wait on nothing, and returns `Outcome::Acted`, `Outcome::Advanced` or `Outcome::Scrolled` with the diff of the snapshots before and after it — `scroll` adding `in_view`, whether its element is in view after the step — `snapshot` returns `Outcome::Screen` with the screen's text, or, for a screen over the snapshot budget or a `part` asked, `Outcome::Part` with one part's text and the counts `part` and `parts`, and an instance that did not go quiet is a result — `settled` false with its `busy` class — not rolled back. Since 2026-10-12-headless-screenshot `run` also takes `screenshot`, the seventh instance verb, its `id` optional, and returns `Outcome::Shot { width, height, png }` — a PNG of the harness's raster, the whole screen or the element's bounds cropped to the part that can be seen and rounded outward — with no diff, a shot changing nothing (`has_changes` false, focus and the next snapshot unchanged); its `id` is looked up as a `click`'s is, refused `stale` or `not-found`, a crop of no pixel is refused `off-screen`, and an app with no font it can paint text with is refused `fonts-unavailable`, the eighth cause, with nothing painted (packages/escher-driver/src/execute.rs:78-86; packages/escher-driver/src/execute.rs:460-481). `with_time(step)` hands the session its caller's time step, the step moving the app's own time; every session accepts `advance`, which moves the session's clock by exactly `ms` and then runs the step where one was handed, `advanced_ms` reading `ms` (ratified by the founder, 2026-10-18). Since 2026-10-10-driver-cli: a session-level verb (`start`, `status`, `stop`) handed to `run` is refused `unknown-verb`; `type` replaces — after the focusing click, where the snapshot reads a `value` for the target (an empty text input reads the empty string), the driver presses the engine's select-all and then types, and with an empty text deletes the selection, so an empty text clears the control; and the record of ids holds no id longer than `MAX_ID_BYTES`. `act` and `with_time` are in process; `run` is also the one thing a host does with a `call` request, so that call and its answer cross the socket (session-wire), and since 2026-10-10-mcp-surface what the MCP server does with an instance verb's tool call, so that call and its result cross the `mcp` role's stdio (architecture §Standard Contracts → Driver session); since 2026-10-19-session-recording `Session::recording_into(dir)` (unix only, `Unsupported` elsewhere) creates `dir` `0700` or refuses `RecordDirNotPrivate`, then `check-{n}.json` `0600` with `create_new`, never replacing a file, and `run` records each answered call of the eight instance verbs, a `lint` among them — `tool` · `arguments` in schema order · `masked` (a `type` on a masked or unresolved target, its text the stand-in `MASKED_STAND_IN`) · `accepted` · `digest` (`answer_digest`, FNV-1a 64 over the whole written line, a shot's PNG included) · `answer` (since 2026-10-19-recorded-check-replay: the kept line as its own JSON object, masked as on every carrier, a shot's without `png`, `{"width":…,"height":…}`) — rewriting the check whole through a `0600` temporary and a rename; past 400 records or 1,048,576 bytes, or on a failed write, the recording ends, its check removed, and `recording_failed()` reads true once, the call not rolled back; `Check::from_bytes` reads a kept check strictly, `answer` required as a JSON object, anything else refused `malformed`; since 2026-10-19-recorded-check-replay `Check::replay(&mut Session) -> Replay` runs nothing on a session whose label is not the check's app, otherwise runs each step's call through `Session::run`, validated again, and stops at the first step whose acceptance differs or whose live kept line, parsed as a JSON value, is not equal to the kept `answer` — `Replay` (`holds` · `another_app` · `ran` · `change`) and `Change` (`step` · `accepted_then` · `accepted_now` · `keys`, the verb's result fields that differ in table order, then `refused`) holding no reading and no `serde_json` type; `run`'s signature and its `command` span are unchanged — ratified by the founder (2026-10-19, F1 A · F2 B, F3 B) (packages/escher-driver/src/recording.rs:134-136; packages/escher-driver/src/replay.rs:40-70; packages/escher-driver/src/recording.rs:145-190; packages/escher-driver/src/session.rs:66-244; packages/escher-driver/src/execute.rs:113-298).
- **session-host:** `serve(state_dir, session, idle_expiry)` holds one session until a `stop` request or, since 2026-10-10-driver-cli, until no request has been answered for the expiry (`IDLE_EXPIRY`, 1,800 s, for a host a command line starts), ending then exactly as on `stop`; every answered request, a refused or malformed one included, counts toward `served` and starts the count again; `start(state_dir, host, ready)` spawns the host command and returns its first answer, `attach(state_dir)` returns `Hello { pid, label, served, idle_expiry_s }`, `stop(state_dir)` returns when the state directory is gone (5 s bound), and `call(state_dir, &Call) -> Result<Answer, SessionError>` with `Answer { accepted, json }` sends one call — it runs `validate` first and answers a schema refusal itself, reaching no session, and reads the answer under 30 s per read (pinned since 2026-10-14-quality-gates by `client::imp::tests::an_answer_read_past_its_bound_is_a_timeout`, a read past the bound being `Timeout`). The edges: `AnswerTooLarge` for a call's answer over the socket's bound — read from an `oversize` reply, the call having run — `NoSession` with no socket file, `Dead` with a socket nothing answers on, `AlreadyRunning` when one answers, `HostExited`, `Timeout`, `Protocol`, `StateDirTooLong`, `StateDirNotPrivate`, `Io`, `Unsupported` on a non-unix target and, since 2026-10-19-session-recording, `RecordDirNotPrivate` (a recording directory open to its group or others) and `RecordingFailed` (a recording that ended, read from an `ok v3 recording-failed` reply) — fifteen session errors, each with a fixed meaning and remedy (packages/escher-driver/src/host.rs:36; packages/escher-driver/src/client.rs:53-121; packages/escher-driver/src/error.rs:12-211).
- **session-wire:** one request line and one reply line per connection, version `v3` on every request since 2026-10-19-session-recording (`v2` from 2026-10-10-driver-cli) — `hello v3` → `ok v3 pid={pid} label={label} served={n} idle_expiry_s={s}`, `stop v3` → `ok v3 stopping`, `call v3 <verb> [<name>=<kind>:<value>]…` → `ok v3 accepted <json>` · `ok v3 refused <json>` · `ok v3 oversize` · `ok v3 recording-failed` (sent in place of the answer when the host's recording ended after the call, read as `SessionError::RecordingFailed`), a known word with another version → `refused version`, anything else → `refused malformed`; a request line is at most 16,384 bytes (was 64), a lifecycle reply at most 128, an answer at most 1,048,576 on its JSON line; a call's answer is read under 30 s per read — pinned since 2026-10-14-quality-gates by escher-driver's unix-only unit test `client::imp::tests::an_answer_read_past_its_bound_is_a_timeout`, `ANSWER.0 == wire::ANSWER_BOUND == 30 s`, a listener that accepts and never answers ending the read as `SessionError::Timeout` — every other read and write under 2 s; a call carries the element id and the typed text in, and an answer carries ids, accessible names, control values (a password's or a file input's as the fixed mask), the snapshot's text and the diff out — ratified by the founder (2026-10-10, relayed verbatim by the overseer as his chosen option label «Сокет несёт команды»; the English wording is the overseer's), where until then none of them crossed; since 2026-10-12-headless-screenshot a `screenshot` call's answer also carries the screen's pixels out — a PNG as padded base64 inside its one JSON line `{"width":…,"height":…,"png":"<base64>"}` — in band under the unchanged answer bound (the largest whole-screen answer on the stand 22,404 bytes, 2.1 % of it), ratified by the founder (2026-10-12, «В самом ответе», relayed verbatim by the overseer); no `NodeId` crosses (packages/escher-driver/src/wire.rs:15-303).
