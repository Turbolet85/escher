## 2. A11y Strategy

<!-- detail: values · strategy -->

- The accessibility tree is built from the document on InitialTreeRequested and refreshed on change: on a poll that reported work the shell's `View::poll` takes the document's changed set (`BaseDocument::take_changed_nodes` — outside the `accessibility` cfg, so a shell built without the feature still drains it) and, under `accessibility`, rebuilds the platform tree when the set it took was non-empty; both paths go through the `Document::accessibility_tree` trait method, so a wrapper's override (DioxusDocument's stable ids) reaches the platform tree (packages/blitz-shell/src/application.rs:77-83; packages/blitz-shell/src/window.rs:377-383; packages/blitz-shell/src/window.rs:522-525; packages/blitz-shell/src/accessibility.rs:44-46; packages/blitz-dom/src/document.rs:190-198). Before 2026-10-07-change-tracking-and-diff the poll-time refresh did not run — the flag the poll read, `has_changes()`, read false after an in-document write on a document nothing had drained, and nothing drained the set — so the platform tree was built once (as measured at escher-0.1.0/chunks/2026-10-07-change-tracking-and-diff/evidence/control-changed-set.txt). The refresh on change is ratified by the founder (2026-10-07) — one item with the engine's changed-set contract in the next bullet.
 Its windowed witness is still owed: no windowed run witnesses the refresh on the dev host — its AT-SPI bus reads inactive, and the stand's windowed binary builds blitz-shell without `accessibility` — so it is proven at the document level (the `changed_set_` unit tests) and by both feature builds of blitz-shell — as measured at escher-0.1.0/chunks/2026-10-07-change-tracking-and-diff/report.md; since 2026-10-14-stand-a11y-assertions both halves are proven headlessly on the stand, in both layout modes: on Counter, after a drained changed set, each Tab of the whole `tab_order` leaves `has_changes()` true and the focus of the tree read through `&dyn Document` — the tree the shell hands the adapter — reads the new stop, and Enter on the focused `counter-increment` then leaves `has_changes()` true and `counter-value`'s name reads `0` → `1` in that tree (tests/blitz-tests/tests/stand_accessibility_ids.rs:363-410 — as measured at escher-0.1.0/chunks/2026-10-14-stand-a11y-assertions/report.md); its windowed witness, at the platform adapter, is still owed — the stand builds no adapter, kept so on the founder's F1 «Пока нет, перенести (Рекомендую)» (2026-10-14, by question dialog in the overseer session, relayed by the overseer as his chosen option label) — and is owned by a `.andromeda/residuals.md` line that reads `re-carried:0.2.0`, the witness at an active assistive technology, which this version does not reach
- `changed_nodes` is the engine's changed set, the nodes written since the last `take_changed_nodes`: a mutation of an in-document node, a focus or checked change, a text control's input and a select's changed choice mark it — `apply_select_choice` marking nothing for a choice of the chosen option (packages/blitz-dom/src/events/keyboard.rs:271-297); node creation, hover, active, scroll and layout do not; `has_changes()` reads true while it is non-empty. So a focus move, a checked change and a rewritten accessible name each reach the refresh above, and a pointer move alone does not (packages/blitz-dom/src/document.rs:366-369; packages/blitz-dom/src/document.rs:1119-1132) — ratified by the founder (2026-10-07), the same item — as measured at escher-0.1.0/chunks/2026-10-07-change-tracking-and-diff/report.md. A harness settle (`Harness::settle`, the driver session's `act`) neither reads nor drains the set, so a step settled through it leaves the refresh above, and a later diff, exactly what the step marked; and the set is non-empty on a freshly booted harness document — the boot's own in-document mutations mark it and nothing has drained it — so a check that reads `has_changes()` as "this step changed something" drains first (packages/blitz-test-harness/src/settle.rs:129-191; tests/blitz-tests/tests/stand_settle.rs:78-119; as measured at escher-0.1.0/chunks/2026-10-07-settle-detection/report.md and its evidence/red-first.md)
- AccessibilityDeactivated and ActionRequested events are unhandled TODOs (packages/blitz-shell/src/application.rs:84-89)
- Window focus and outer/inner bounds are forwarded to the adapter on every window event before it is handled (packages/blitz-shell/src/accessibility.rs:48-74; packages/blitz-shell/src/window.rs:586-589)

- Role mapping follows the HTML-AAM spec, linked in the test doc; previously links, lists, tables, labels and landmarks arrived as `Role::Unknown` (tests/blitz-tests/tests/accessibility_roles.rs:1-7)
- A semantic page asserts that only `<html>` and `<body>` map to `Role::Unknown` (tests/blitz-tests/tests/accessibility_roles.rs:182-198)
- The builder writes three states on an element node from its ARIA state attributes, on every element — a select's option excepted, its `selected` its chosen state (`select::is_chosen`), true or false, with no `aria-selected` read, and its non-empty `label` attribute its `label` where it has no `aria-label` (packages/blitz-dom/src/accessibility.rs:157-162; packages/blitz-dom/src/accessibility.rs:171-181) —, the toggle by role, since 2026-10-10-snapshot-states — each value trimmed of ASCII whitespace and compared exactly, in lower case: `aria-selected` `true` / `false` sets `selected`, anything else nothing; `aria-pressed` `true` / `false` / `mixed` sets `toggled` True / False / Mixed, anything else nothing, on every role but the five checkable ones; `aria-checked` `true` / `false` / `mixed` sets `toggled` on a `CheckBox` · `Switch` · `RadioButton` · `MenuItemCheckBox` · `MenuItemRadio` role alone (`role="switch"` mapping to `Switch`), and a native `input` whose `type` is exactly `checkbox` or `radio` reads neither (HTML-AAM / ARIA in HTML) — the toggle read per role ratified by the founder (2026-10-18); `aria-invalid` `true` / `grammar` / `spelling` sets `invalid` True / Grammar / Spelling, an absent, empty or `false` value nothing, and any other value `Invalid::True` (WAI-ARIA 1.2's rule; the lower-case match is a choice, the specification as read stating no case rule and no browser measured, so `TRUE` reads unrecognized); each attribute is read once and nothing else writes `toggled`; the builder writes no `toggled` from a native checkbox's or radio's own checked state, so the tree the shell hands the adapter never states it checked while the snapshot's `checked` reads the element — a measured absence, its fix owned by a `.andromeda/residuals.md` line (target: next);
 an element whose role does not support an attribute reads it as one whose role does (packages/blitz-dom/src/accessibility.rs:169-213; tests/blitz-tests/tests/accessibility_states.rs:134-151; tests/blitz-tests/tests/accessibility_states.rs:153-171; tests/blitz-tests/tests/accessibility_states.rs:173-192; tests/blitz-tests/tests/accessibility_states.rs:245-316; packages/blitz-dom/src/accessibility.rs:395-415) — ratified by the founder (2026-10-10, by question dialog in the overseer session, relayed verbatim by the overseer as his chosen option label «Ратифицировать», the English wording is the overseer's: the builder writes the three states on the node); what an assistive technology reads of them is not measured — no stand binary builds a platform adapter and the dev host's AT-SPI bus reads inactive — and the windowed witness, at an active assistive technology, is owned by a `.andromeda/residuals.md` line that reads `re-carried:0.2.0`, which this version does not reach, on the founder's F1 «Пока нет, перенести (Рекомендую)» (2026-10-14), the headless half — the tree the shell hands the adapter — proven on the stand since 2026-10-14-stand-a11y-assertions (§7) — as measured at escher-0.1.0/chunks/2026-10-10-snapshot-states/report.md
- Since 2026-10-17-upstream-sync-engine-debts the builder also holds upstream's six reads, as upstream wrote them (merged at `23b9b26a9`, merge `3eda07bc`): `aria-labelledby` — after the `<label>` → input loop it clears `labelled_by`, pushes the referenced nodes and sets their computed text as the `label`, so it outranks a `<label>` and an `aria-label` (accname 2B), an id that names no built node ignored, a self-reference and nested text included, hidden targets read for the label without being referenced, the `aria-label` the fallback when the targets hold no text; `aria-describedby` (the referenced nodes as `described_by`); `aria-description` (its own text into AccessKit's description field); `aria-expanded` (a boolean); `aria-disabled` (`true` → `set_disabled`); `aria-level` (a number, with the tag and role defaults); then `set_html_tag` last; the trimmed non-empty `aria-label` read and the three closed-set state reads above are kept, upstream's own `parse::<bool>` `aria-selected` and unfiltered `aria-label` reads dropped in the merge, so there is still one read per attribute; the snapshot reads no description and its `enabled` reads the `disabled` attribute, so `aria-disabled` moves no snapshot reading; no stand file states any of the six; the description and the three new closed values leave only to the platform adapter, which no stand binary builds (§1), so what an assistive technology reads of them is not measured; `aria-labelledby` names inside the ratified name crossing and the description to the adapter ratified as upstream's behaviour by the founder (2026-10-17, by question dialog in the overseer session, relayed by the overseer, «Утвердить оба (Рекомендую)»; both description sources confirmed by his «Подтвердить все 10 (Рекомендую)», 2026-10-18) (packages/blitz-dom/src/accessibility.rs:42-47; packages/blitz-dom/src/accessibility.rs:62-103;
 packages/blitz-dom/src/accessibility.rs:119-126; packages/blitz-dom/src/accessibility.rs:214-241; packages/blitz-dom/src/accessibility.rs:276-327; packages/blitz-dom/src/accessibility.rs:417-438; tests/blitz-tests/tests/accessibility_label.rs:30-297; tests/blitz-tests/tests/accessibility_description.rs:8-93) — as measured at escher-0.2.0/chunks/2026-10-17-upstream-sync-engine-debts/report.md
