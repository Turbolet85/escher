## 5. Keyboard Navigation

<!-- detail: values · keyboard-focus-order -->

- An element is focusable if it holds a sub-document, or if it is not inert (by presence on itself or an ancestor element, `Node::is_inert`), is no disabled form control and either has `tabindex >= 0` or, with no tabindex, is an `<a>`/`<area>` with `href` or a `button`, `input`, `select`, `textarea`, `frame`, `iframe` or `summary` (packages/blitz-dom/src/node/element.rs:732-764) — `disabled` read by its presence on a form control alone (`ElementData::is_disabled`: `can_be_disabled()` and the attribute present), any value, bare, `"false"` or `"true"`, so a `<div disabled tabindex=0>` takes focus; the Tab walk (`focus_next_node` / `focus_prev_node`), autofocus (a disabled form control or an inert candidate skipped) and `DioxusDocument::unkeyed_actionable` read it (packages/blitz-dom/src/node/element.rs:514-518; packages/blitz-dom/src/node/element.rs:733; packages/blitz-dom/src/node/node.rs:563-580; tests/blitz-tests/tests/stand_keyboard.rs:614-655) — the presence reading ratified by the founder (2026-10-13, «По наличию (Рекомендую)», confirmed on the wrap's answer card on 2026-10-14 «Подтвердить (Рекомендую)», each by question dialog in the overseer session, relayed verbatim by the overseer as his chosen option label), its narrowing to form controls and the `inert` read ratified by the founder (2026-10-18); a known limit stands: HTML's focus fixup is not built, so a node that holds focus when it becomes inert keeps it until focus moves (tests/blitz-tests/tests/inert_subtree.rs:68-93; tests/blitz-tests/tests/inert_subtree.rs:144-194), its fix owned by a `.andromeda/residuals.md` line (target: next)
- Tab moves focus to the next node and Shift+Tab to the previous, dispatching focus events (packages/blitz-dom/src/events/keyboard.rs:29-44); `focus_next_node` / `focus_prev_node` move focus to the next/previous focussable node (packages/blitz-dom/src/document.rs:1824-1837)
- Cached focusability is recomputed when `tabindex`, `href` or `disabled` is set or removed (packages/blitz-dom/src/mutator.rs:346-355; packages/blitz-dom/src/mutator.rs:503-510); tests assert focusability follows `tabindex` set or cleared after creation (roving tabindex) (tests/blitz-tests/tests/focusability_updates.rs:1-6; tests/blitz-tests/tests/focusability_updates.rs:34-57)
- `button`, `input`, `select` and `textarea` can be disabled, which toggles the `DISABLED`/`ENABLED` states (packages/blitz-dom/src/node/element.rs:479-486; packages/blitz-dom/src/node/element.rs:510-512; packages/blitz-dom/src/node/node.rs:828-850); setting `disabled` removes a button's focusability (tests/blitz-tests/tests/focusability_updates.rs:63-76)
- Disabled-ness is keyed one way since 2026-10-13-stand-keyboard-harness: the `DISABLED`/`ENABLED` element state (hence `:disabled`) reads the attribute's PRESENCE, and the pointer-move gate, `ClickTarget::Disabled`, `handle_click`'s walk gate, the Enter and Space activation and focusability read `ElementData::is_disabled` — that presence on a `button`, `input`, `select` or `textarea` alone (ratified by the founder, 2026-10-18) — so `disabled="false"` and a bare `disabled=""` on a form control match `:disabled` and are not focusable, and a bare `disabled` set after creation takes its focusability away (packages/blitz-dom/src/node/element.rs:480-485; packages/blitz-dom/src/node/element.rs:514-518; packages/blitz-dom/src/node/element.rs:733; packages/blitz-dom/src/events/pointer.rs:326; packages/blitz-dom/src/events/pointer.rs:459; packages/blitz-dom/src/events/pointer.rs:757; packages/blitz-dom/src/events/keyboard.rs:205; packages/blitz-dom/src/events/keyboard.rs:222; tests/blitz-tests/tests/focusability_updates.rs:59-62; tests/blitz-tests/tests/focusability_updates.rs:78-96; tests/blitz-tests/tests/stand_keyboard.rs:614-655) — as measured at escher-0.1.0/chunks/2026-10-13-stand-keyboard-harness/report.md; before it focusability parsed the value as a bool and both stayed focusable (as measured at escher-0.1.0/chunks/2026-10-06-headless-stand/evidence/disabled-false-probe.txt)
- The file input's generated inner button gets `tabindex="-1"` (packages/blitz-dom/src/mutator.rs:1438-1452)
- Under the `autofocus` feature, the latest mounted focussable node whose `autofocus` attribute is present with any value but "false" — bare, empty or "true" — is focused on flush, and `autofocus="false"` is ignored (packages/blitz-dom/src/mutator.rs:1114-1126; packages/blitz-dom/src/mutator.rs:1029-1034; tests/blitz-tests/tests/autofocus_attribute.rs:27-50) — as measured at escher-0.1.0/chunks/2026-10-10-upstream-sync-agent-surfaces/report.md
- Focusing sets the `FOCUS` and `FOCUSRING` element states; blurring removes them (packages/blitz-dom/src/document.rs:1883-1888; packages/blitz-dom/src/node/node.rs:764-802)
- `:focus` matches the focus element state and `:focus-within` the focused element and its ancestors by the `FOCUS_WITHIN` element state, while `:focus-visible` never matches (packages/blitz-dom/src/stylo.rs:488-492)
- focus and blur do not bubble; focusin and focusout bubble (packages/blitz-traits/src/events.rs:451-454)
