## Design Philosophy

Detail: .andromeda/architecture-detail/design-philosophy.md — read whole.

- **Radically modular, embeddable engine** — the engine is a set of separately usable crates around a headless DOM that external code drives and any renderer can paint; painting assumes styles and layout are already resolved, and CI guarantees only latest stable, keeping an MSRV check and making an effort not to raise the MSRV in a patch version.

- **Embedder services are injected, with no-op defaults** — networking, navigation, shell and parsing reach the DOM only through provider traits the embedder supplies; script fetches go through the embedder's net provider, never an internal HTTP client.

- **Behave like a browser, and cite the spec** — web semantics are written against named specifications and named browser engines.

- **One incremental pipeline, safe identities** — style, damage, box construction, layout and paint topology are invalidated incrementally through a single code path, over versioned node ids: both layout modes produce identical layouts, a dropped node's id stops resolving instead of aliasing a reused slot, the slotmap key is used only at the storage boundary and every public API takes `NodeId`, and persistent interaction state references DOM nodes only, never layout-generated nodes.

- **Headless, measurable, testable** — the engine is exercised without a window through a headless harness, a WPT runner and phase-split benchmarks; the reference browser keeps its own state best-effort, `HistoryService` the single entry point for its visit and favicon writes, and a loaded document's chrome writes run as one straight-line block so a render cannot sample a half-applied state.

## Stack and Technologies

Detail: .andromeda/architecture-detail/stack-and-technologies.md — read whole.

The stack: a Rust 2024 Cargo workspace (rust-version 1.91.0) on Servo Stylo, html5ever and xml5ever, Taffy, Parley with ICU4X, anyrender over Vello and Skia, winit, AccessKit, Boa, Dioxus 0.7, tokio and reqwest, with rusqlite in the browser app and Trunk for wasm; GitHub Actions CI runs fmt, clippy, rustdoc, cargo-deny and coverage gates, beside a host-run mutation tier and a Nix flake.

Two keyboard-types versions stand in the graph, Dioxus carrying its own 0.7, so a module that glob-imports `dioxus::prelude::*` names the workspace's crate as `::keyboard_types`; the `ci-scripts` leg needs Python 3.11 or later; mimalloc is the global allocator of two upstream-only binaries, the browser app (by default) and the WPT runner.

Example fixtures under `examples/assets` are standalone HTML documents with no build manifest, source module or config, referencing external assets; the Preact TodoMVC page loads vendored, unmodified Preact builds.

## Established Decisions

Detail: .andromeda/architecture-detail/established-decisions.md — read whole.

- **[Dependency pinning]** the parser crates match stylo's web_atoms version, skrifa matches parley and vello and svgtypes usvg; taffy and parley are registry versions, so no git dependency is left in the manifest; winit is pinned exactly to a beta, and examples pin `idna_adapter` to disable unicode URL support.

- **[Build profiles]** `dev` sets `debug = "line-tables-only"`, one debuginfo level for the dev host and CI that the `test` profile inherits; named profiles `profile`, `production`, `p2`, `small`, `small-panic` and `tiny`, five crates kept at opt-level 3.

- **[MSRV]** The MSRV job runs only `cargo build`, to avoid requiring dev-dependencies to build with the MSRV (.github/workflows/ci.yml:32-33)

- **[Release versioning]** main is always a prepatch until 1.0, the version in git one minor bump ahead of the actual release; blitz packages are versioned together through the one workspace version and the in-repo `=` pins, and no in-repo release tool remains.

- **[Nix packaging]** The flake builds deps and crate in one derivation (`cargoArtifacts = null`), commenting that the workspace root is a virtual manifest with no root `[package]` (flake.nix:96-99), while the root manifest declares a `[package]` named blitz-examples (Cargo.toml:254-255); checks are disabled in package builds "to avoid building deps for them" (flake.nix:103)
- **[Cross-compilation]** `cross` is installed from a git rev because the latest release does not work with recent Rust when targeting Android (.github/workflows/ci.yml:380-384)

- **[Renderer backends]** `paint_bench` runs vello (default), vello_cpu or vello_hybrid; `screenshot` and the test harness's `screenshot` render through `VelloCpuImageRenderer`, the harness compositing over opaque white; wpt defaults to cpu; rdme selects one renderer per feature; `dioxus-native` raises a `compile_error!` when no renderer is enabled.

- **[Default features]** each crate fixes its default feature set in its manifest — blitz-dom: svg, woff, accessibility, system-fonts, file-input, custom-widget, text-transform-icu; `writing-mode` is in no default list; `woff` is default-on in dioxus-native so wasm callers can bundle compressed fonts; the `net` feature is a no-op on wasm32.

- **[Style threading]** `StyleThreading` derives `Default` with `#[default] Sequential` (packages/blitz-dom/src/config.rs:18-27), and the `style_threading` field doc names `Sequential` the default (packages/blitz-dom/src/config.rs:53-55); `Parallel` traversals are serialised process-wide by the static `PARALLEL_TRAVERSAL_LOCK`, its poison recovered with no panic path, so two documents resolving `Parallel` concurrently on Stylo's global pool no longer panic (blitz issue 430) (packages/blitz-dom/src/config.rs:11-17; packages/blitz-dom/src/stylo.rs:29-35; packages/blitz-dom/src/stylo.rs:157-163); the windowed `dioxus_native::launch` and the browser's document loader and toolbar build their documents `Parallel`, and no headless document — harness, stand or driver — sets `style_threading` (packages/dioxus-native/src/lib.rs:63; packages/dioxus-native/src/lib.rs:222; apps/browser/src/document_loader.rs:62; apps/browser/src/toolbar.rs:203); `Sequential` bypasses Stylo's global thread pool (packages/blitz-dom/src/stylo.rs:156-165); a thread-local `LAYOUT_CTX` carries a FIXME that it is not necessarily correct in a multi-document context (packages/blitz-dom/src/resolve.rs:15-19)

- **[Document defaults]** incremental layout on, CSS media type `screen`, documents always HTML in no-quirks mode, a fixed set of Stylo prefs enabled, an empty `data:` default `DocumentUrl`, and headless documents and the WPT viewport in `ColorScheme::Light`.

- **[Resource loading]** `<head>` stylesheets are render-blocking and `resolve` returns before styling while any are pending; iframe nesting is capped at 10 and nested `@import` at 16; `srcdoc` takes precedence over `src`; loaded images are cached by URL, concurrent requests queued on one fetch; author stylesheets are ordered by owner node id.

- **[Fonts]** `@font-face` fonts are registered under the CSS-declared family, weight and style rather than the file's metadata (packages/blitz-dom/src/net.rs:37-55; packages/blitz-dom/src/document.rs:1503-1520); `local()` sources are not supported (packages/blitz-dom/src/net.rs:444-445); SVG and EOT fonts are skipped, and WOFF/WOFF2 without `woff` (packages/blitz-dom/src/net.rs:474-492); default generic base size is 13px monospace, 16px otherwise (packages/blitz-dom/src/font_metrics.rs:167-176); `font-feature-settings` is appended after `font-variant-*` features so it takes precedence (packages/blitz-dom/src/stylo_to_parley.rs:274-289); generic family `None` maps to sans-serif (packages/blitz-dom/src/stylo_to_parley.rs:50-53); `-apple-system` and `BlinkMacSystemFont` map to system-ui on Apple targets (packages/blitz-dom/src/stylo_to_parley.rs:68-76; packages/blitz-dom/src/stylo_to_parley.rs:444-456)

- **[CSS approximations]** where Stylo or Taffy lack a feature the engine approximates it — CSSOM geometry snapped to 1/64 px, `display: table` laid out as Taffy grid, `overflow: auto` as scroll, `scrollbar_width` 0, sizing keywords on min/max size as auto, baseline alignment falling back to start/end, and like mappings.

- **[Unsupported features]** Shadow DOM, container queries, 3D transforms (a z-axis rotate applied as planar), CSS `offset` in transforms, visited-link styling, anchor positioning, grid subgrid and masonry, non-string pseudo-element `content` and anonymous table wrapper boxes; `:focus-visible`, `:valid`, `:invalid`, `:required` and `:target` always match false, while `:focus-within` matches by element state.

- **[Scrolling and input]** root scroll applies to the viewport; `overflow: hidden` scrolls programmatically only; user scrolls chain to the viewport, `scroll_to` and `scroll_by` clamp to one box; `scroll_into_view` writes every scrolling box on the chain, nested ones instantly, so it never animates a nested box; a box's client rect never subtracts its own scroll offset, and a hit stops at the padding box of every box paint clips.

- Those two fixes, the accessibility builder's state writes and the range input, keyboard activation and focus rules are direct engine changes for every document, each flagged upstreamable with no upstream pull request open.

- Beside those, seven more direct engine changes for every document, the document's clock — every engine time read goes through `DocumentConfig.clock`, wall time when it is unset — and the select model of keys, typeahead and click, each flagged upstreamable with no upstream pull request open.

- The select model: every choice that changes the chosen option goes through the one path `apply_select_choice`, and a choice of the chosen option fires nothing; no popup is painted, an option is not clicked, and a `multiple` select or an `optgroup`'s options are not modelled.

- **[Selection, animation, pseudo-elements]** Anonymous-block selection endpoints store parent id plus sibling index because anonymous ids change across reconstruction (packages/blitz-dom/src/selection.rs:1-5; packages/blitz-dom/src/selection.rs:9-24); animations of detached nodes are cleared so an infinite animation cannot force a redraw every frame (packages/blitz-dom/src/stylo.rs:94-108); pseudo-element style changes needing no reconstruction are flushed during traversal (packages/blitz-dom/src/stylo.rs:1387-1407)

- **[Layout]** HTML tables are laid out by Taffy's grid; replaced elements are `img`, `svg`, `canvas`, `video`, `embed` and `iframe`, `<object>` excluded; text nodes are never laid out individually; text, checkbox, radio and range inputs get their control data at construction; damage bits over Servo's `RestyleDamage` decide relayout and reconstruction; only non-zero z-index stacking contexts are hoisted.

- **[Inline SVG]** Inline `<svg>` is re-parsed from its outer HTML into an image and rebuilt when its subtree's style changes (packages/blitz-dom/src/layout/construct.rs:452-483; packages/blitz-dom/src/layout/damage.rs:119-129; tests/blitz-tests/tests/inline_svg_serialize.rs:1-2; tests/blitz-tests/tests/inline_svg_restyle.rs:1-2), serialized with `currentColor` resolved and `xmlns:xlink` added (packages/blitz-dom/src/node/serialize.rs:102-114; packages/blitz-dom/src/node/serialize.rs:173-180), while `outer_html` does not resolve `currentColor` (tests/blitz-tests/tests/inline_svg_serialize.rs:68-76); SVG `width`/`height` are presentation attributes at the lowest cascade level (tests/blitz-tests/tests/svg_attr_sizing.rs:3-5; tests/blitz-tests/tests/svg_attr_sizing.rs:92-106)

- **[DOM semantics]** `lang`/`xml:lang` and `dir` set language and direction; `disabled` is read one way, by its presence, on a form control alone — focusability, the pointer and click gates and the Enter and Space activation read it; a node the Dioxus bridge removes is dropped with its descendants and no longer resolves; interaction state on removed nodes is cleared or retargeted.

- `inert` is honoured by its presence on the element or an ancestor — not focusable, not hit, out of the accessibility tree and the snapshot; focus keeps `:focus-within` on its ancestors; a `select`'s choice is held as its options' `CHECKED` state, settled by HTML's selectedness algorithm, and a controlled app writes `selected` from its `input` event's value or a choice reverts.

- A known limit: HTML's focus fixup is not built, so a node that holds focus when it becomes inert keeps it until focus moves, its fix owned by a `.andromeda/residuals.md` line.

- **[HTML parsing]** html5ever runs with scripting off, the doctype dropped and no-quirks mode; XHTML is sniffed and parsed as XML; `HtmlDocument` uses the configured `ua_stylesheets` as given; `<template>` children parse into a detached fragment; file input, custom widgets, svg and scrollbar thumb hit-testing are feature-gated.

- **[Networking]** Every request carries a fixed Firefox-on-Linux `User-Agent` (packages/blitz-net/src/lib.rs:21; packages/blitz-net/src/lib.rs:199-202; examples/screenshot.rs:21; examples/screenshot.rs:48; examples/paint_bench.rs:24; examples/paint_bench.rs:77); in-flight requests capped per host by a tokio `Semaphore` of 6 (packages/blitz-net/src/lib.rs:24; packages/blitz-net/src/lib.rs:181-197); with `cache` the client uses reqwest-middleware with `http_cache_reqwest::Cache`, `CacheMode::Default`, `CACacheManager`, `shared: false` (packages/blitz-net/src/lib.rs:92-116); `data:` decoded locally, `file:` read from disk, every other scheme HTTP (packages/blitz-net/src/lib.rs:153-173)

- **[Shell and windowing]** windows are created invisible and shown after AccessKit initialises; the renderer is suspended before its window drops, and windows are dropped before the event loop exits; the default event loop waits; iOS redraws, wasm32 resizes and macOS safe areas are handled in the shell; winit's IME event is copied so lower-level Blitz crates do not depend on winit; accesskit_xplat forbids neither or both of `async-io` and `tokio` on Unix.

- **[Painting]** layers are capped at 1024, non-finite transformed boxes culled and gradient layers needing more than 500 tiles not painted; a password input paints masked in every document, a direct engine change whose merge surface is `packages/blitz-paint/src/render.rs` and `packages/blitz-dom/src/document.rs`.

- **[JavaScript]** classic external scripts are fetched synchronously, in document order; Boa's timers are replaced by timers tied to the document event loop; `annex-b` is enabled; DOM wrappers are cached per node, preserving `===` identity; all elements share one prototype; `window.history` is in-memory with no `popstate`; a single frame only.

- **[Node identity]** `NodeId` packs a 32-bit slot index and 32-bit version (packages/blitz-traits/src/node_id.rs:3-12), ordered by index then version to roughly match creation order (packages/blitz-traits/src/node_id.rs:47-54)

- **[Dioxus integration]** `DioxusDocument` defaults its `base_url` to `dioxus://index.html` and adds no stylesheet of its own, the default user-agent sheet reaching it once through `DocumentConfig::default()` and a config that sets `ua_stylesheets` used as given; hot reload only under `hot-reload` with `debug_assertions` off wasm32; in-memory `MemoryHistory` navigation; JS `eval` delegated to `NoOpDocument`; custom content as an `object` whose `data` carries a `CustomWidgetAttr`.

- **[Browser app]** history persists to `history.sqlite3` in the project data dir, in memory where that fails and always on Android and iOS, migrations append-only, at most 1000 entries; disk writes go through tokio `spawn_blocking`; non-URL input becomes a DuckDuckGo search; about pages are Dioxus components; at least one tab is always open.

- **[WPT runner]** an 800x600 render target at scale 1.0; suites default to css-flexbox and css-grid, `full` running every top-level directory but `encoding`; blocked, quarantined, non-UTF-8, testdriver and worker-only tests are skipped; a test's kind decides its runner, under fixed timer budgets; a reftest passes on any match and no mismatch, fuzzy matching allowed.

- **[Driver session]** a session crosses processes on a `std`-only Unix-domain socket in an owner-only state directory and on the `mcp` role's stdio — no third-party IPC crate and no TCP or UDP port; ids, names, masked values, snapshot text, diffs, shots and lint findings cross, never a `NodeId`; the library depends on no app, emits no event, installs no subscriber and reads no env var; a hosted session expires when idle; a new carrier or exit widens the boundary.

- A session whose launcher names a recording directory keeps its answered calls at rest as one owner-only replayable check, never logged and never named by a tool call; the repository's two committed stand checks are the one exception to owner-only.

## Conventions

Detail: .andromeda/architecture-detail/conventions.md — read whole.

- **Formatting and lints:** `cargo fmt --all --check` and `cargo clippy --workspace --locked -- -D warnings`, then upstream's blitz-dom clippy line only when that is green, each a `.github/scripts/ci-leg.sh` leg in CI and on the dev host; rustdoc warnings are errors workflow-wide, over every library crate; `collapsible_if` allowed crate-wide in four crates and `module_inception` in blitz-dom's node module, the rest locally, `clippy::expect_used` / `clippy::unwrap_used` next to a justification.

- **Manifests:** dependencies declared once in `[workspace.dependencies]` and consumed as `{ workspace = true }`; in-repo crates declared with `default-features = false`, except the `seven_guis` path entry, which keeps its renderer feature; package metadata inherited with `*.workspace = true`; example and app crates set `publish = false`.

- **Licensing exceptions:** `wasm_hello` takes its licence from the workspace, `license.workspace = true` (examples/wasm_hello/Cargo.toml:1-6); `wgpu_texture` declares `license = "MIT"` with a SixtyFPS header (examples/wgpu_texture/Cargo.toml:1-8; examples/wgpu_texture/src/demo_renderer.rs:1-2); `accesskit_xplat` declares `license = "Apache-2.0"` with AccessKit Authors headers (packages/accesskit_xplat/Cargo.toml:4; packages/accesskit_xplat/src/lib.rs:1-3); blitz-dom's `assets/default.css` carries an MPL 2.0 header (packages/blitz-dom/assets/default.css:1-3); `stylo_taffy` declares `license = "MIT OR Apache-2.0 OR MPL-2.0"` — the workspace's dual licence plus MPL 2.0 (packages/stylo_taffy/Cargo.toml:3)

- **Documentation:** modules and files open with `//!` docs, public items carry `///`, spec URLs are cited above or next to implementations, doc comments state the rationale for constants, and examples open with a `//!` comment describing what they demonstrate.

- **Known gaps:** marked with `TODO`/`FIXME`; an ordering-sensitive block is marked "WARNING: DO NOT REORDER"; sections delimited with `// === … ===`.

- **Visibility and naming:** crate internals are `pub(crate)` / `pub(super)`; no-op implementations are prefixed `Dummy` and internal JS natives `__blitz_`; consuming builder methods `with_…` / `without_…`; `#[non_exhaustive]` on `NavigationOptions` and `Request`; Stylo and Parley types aliased under `stylo` / `parley` modules; paint rendering split one module per concern.

- **Feature gating:** optional functionality gated by cargo features; in the engine and upstream crates tracing is gated per call site with a `cfg(not(feature = "tracing"))` fallback, while escher's own two crates take `tracing` ungated — escher-telemetry emits its startup and panic events ungated and escher-driver builds its spans by hand, with no `#[instrument]`; desktop-only code gated by a repeated cfg list.

- **Unsafe and borrowing:** `unsafe` blocks carry `allow unsafe_code` or `// SAFETY:` comments; borrow conflicts worked around by taking a child list or layout out and restoring it; let-chains in `if` conditions; a macro generates forwarding accessors for `ElementData`/`DocumentData` fields.

- **Error handling:** error types are enums with `Display` and `From` per wrapped error (packages/blitz-net/src/lib.rs:363-422); mutex locks recover from poisoning with `unwrap_or_else(|err| err.into_inner())` (wpt/runner/src/net_provider.rs:177-180; wpt/runner/src/net_provider.rs:194; wpt/runner/src/net_provider.rs:203); examples fail with `.unwrap()`, `.expect(..)`, `panic!` (examples/inner_html.rs:20; examples/inner_html.rs:33; examples/screenshot.rs:41-51; examples/preact_script.rs:18-23)
- **DOM API patterns:** mutations go through `DocumentMutator`, which flushes deferred work on `Drop` and requests a redraw only for in-document mutations (packages/blitz-dom/src/mutator.rs:47-80); `DocumentMutator::doc` is a public escape hatch with a request to prefer extending the mutator (packages/blitz-dom/src/mutator.rs:48-50); a Stylo snapshot is taken before attribute mutation of in-document nodes (packages/blitz-dom/src/mutator.rs:279-282; packages/blitz-dom/src/document.rs:1597-1602); event-producing functions take a `dispatch_event` callback (packages/blitz-dom/src/scrolling.rs:130-134; packages/blitz-dom/src/events/keyboard.rs:23-28; packages/blitz-dom/src/events/focus.rs:5-9); repeated regexes held in `LazyLock<Regex>` or compiled per worker (wpt/runner/src/main.rs:191-201; wpt/runner/src/test_runners/fuzzy.rs:12-16; wpt/runner/src/test_runners/mod.rs:92-95; wpt/runner/src/main.rs:561-579)

- **Tests:** unit tests in `#[cfg(test)] mod tests` at the end of the source file, or in a `#[path]` child file of their own; each integration test file covers one behavior and opens with a `//!` doc naming it; scenarios run in both layout modes; stand checks share helpers through modules under `tests/` that are no test target; tests first assert the fixture produces the condition; blitz-tests keeps one test target per file, except upstream's `tests/all.rs`, declared and held at `test = false`.

- Unit-test modules moved to files of their own keep their test paths; `tests/blitz-tests/tests/fixtures/mod.rs` states the fixture boot and hold, the shared fixture pages and `HeldNet` once, and a page with one reader stays in its check's file.

- **Apps and examples:** binaries set `windows_subsystem = "windows"` outside tests; Android entry points are `android_main` calling `set_android_app`; reactive state uses `#[derive(Store)]`; assets come through `asset!`; Dioxus examples declare `dioxus_native::launch(app)` with `#[component]` components and signal and store hooks, their CSS in `const` raw strings.

- **HTML fixtures:** reduced variants sit beside full pages; feature fixtures group numbered cases under h2/h3 headings with a CSS comment per case; sibling assets referenced with `./`-relative URLs; graphite.html is minified, and some captures stand as captured, without a closing head, body or html tag or a doctype.

## Standard Contracts

Detail: .andromeda/architecture-detail/standard-contracts.md — read whole.

- **Document core (blitz-dom):** the `Document` trait every document wrapper implements; `DocumentConfig` carrying the viewport, providers, user-agent sheets, fonts, media type, threading, incremental flag, abort signal, depth and clock; resource loading; the changed set read by `has_changes` and drained by `take_changed_nodes`, its ids read through `get_node`, never by indexing; the read-only `can_paint_text` and `layout_as_text_input`.

- The document's clock: `DocumentConfig.clock`, the config's clock or else a fresh `WallClock`; the crate root re-exports `Clock`, `WallClock` and `VirtualClock`, every clone of a `VirtualClock` reading one time; no `Instant::now()` or `SystemTime::now()` stands in blitz-dom outside `clock.rs`; `BaseDocument::select_value` reads a select's value, public and read-only, its writers crate-private.

- **Mutation, query and CSSOM:** mutations through `doc.mutate()`; selector queries returning `Result`, never matching the scope node; CSSOM by owner `NodeId` and an index path; `build_accessibility_tree` returns an AccessKit `TreeUpdate`, naming nodes from text children, `aria-labelledby`, `aria-label`, a bound `<label>` and option labels, and writing state attributes each read once; blitz-shell refreshes the platform tree when a poll took a non-empty changed set.

- Two measured limits: the accessibility tree states no native checkbox's or radio's checked state, its fix owned by a `.andromeda/residuals.md` line, and the platform-tree refresh's windowed witness is still owed, the refresh held by the document-level tests and both feature builds of blitz-shell.

- **Events:** `EventHandler` and `EventDriver` dispatch DOM events — mouse compatibility and touch events from pointers, non-bubbling events to the target only, a focus change as `blur`, `focusout`, `focus`, `focusin`; a range input's default actions dispatch `input`; Enter and a released Space dispatch a Click the driver queues, so the app's handlers run before the default action; the engine dispatches `change` only after `input` on a select's choice.

- **Scrolling, selection, tree:** the `BaseDocument` scroll API; `scroll_into_view` scrolls every scrolling box on the target's chain, nested ones instantly with no `scroll` event, then the viewport; `visible_region` is the read-only reader of what can be seen, and seeing is never read from a hit; a hit stops at the padding box of a box paint clips and skips a node dropped since the last resolve; `Node::absolute_position` subtracts only ancestors' scroll offsets; stale-id `NodeTree` indexing panics.

- `get_client_bounding_rect` reads an element where its transforms move it, while `visible_region` reads a scrolling box under a transform where it stands untransformed (a measured limit); `BaseDocument::text_extent` is a read-only reader that mutates nothing.

- **Layout:** the crate-private `LayoutPassState` implements Taffy's traversal and layout traits for one pass — `BaseDocument` implements none; the table, replaced-element and paint-tree APIs; `stylo_taffy` exports `to_taffy_style`, `TaffyStyloStyle`, `StyleFlags`, `Atom`, `WritingMode` and `WritingModeExt`.

- **Nodes and widgets:** `NodeData` and `SpecialElementData` (not `#[non_exhaustive]`, `RangeInput` among its variants); `RangeInputData` read through the `ElementData` range accessors; serialization and CSSOM View accessors; the `Widget` trait, a widget's resources unregistered when its node drops.

- `ElementData::is_disabled` is the one disabled reading — a form control with a `disabled` attribute present; the select's rules live in the crate-private `node::select`, with no public type.

- **Provider traits (blitz-traits):** `NetProvider` (a no-op one registering no pending-critical resources), `NetHandler`, `NetWaker`, `Request`, `Body`, `FormData`, `AbortController`/`AbortSignal`, `NavigationProvider`, `ShellProvider` with no-op defaults, `HtmlParserProvider`, `DevtoolSettings` and `Viewport`, its `scale()` hidpi_scale × zoom.

- **HTML and networking crates:** blitz-html's `HtmlDocument`, `DocumentHtmlParser` (an html5ever `TreeSink`) and `HtmlProvider`; blitz-net's `Provider` implementing `NetProvider::fetch`, with typed `ProviderError`s and byte, form or empty request bodies.

- **Paint and shell:** `paint_scene` paints a document into a `PaintScene`; blitz-shell's application, proxy, view, window config and shell provider, the embedder completing a resume; a password `input` paints its value masked in every document and through every renderer that paints with blitz-paint, its caret placed by the bullets, so no width of the real characters reaches a frame or the caret.

- **Test harness:** blitz-test-harness's `Harness`, generic over the document, with constructors, inspection and input helpers that pump and never settle; `screenshot` and `screenshot_rect` paint a raster through blitz-paint, printing, panicking and logging nothing; `text_contrast` reads a WCAG contrast and changes nothing; `settle` drives render and layout to quiet, reports a load in flight and never waits on one or moves time.

- The harness holds one `VirtualClock` its documents share; `tick` and `advance_time` move it, and `screenshot`, `screenshot_rect`, `text_contrast` and `settle` never do.

- **Headless stand (seven_guis, native only):** `seven_guis::stand` boots the four lean tasks and, beside them, Cells (`boot_cells`, no `LeanTask`) and a load page (`boot_load`) in a pinned 800x600 Light viewport with one bundled font, every boot offline but the load page's, whose one stylesheet fetch the in-process stand-in `LoadNet` answers after `LOAD_ANSWER_DELAY` (200 ms); `timer_step` hands the Timer its ticks for a driver session; it installs no telemetry, reads no env var and names no `blitz_net`.

- **Telemetry bootstrap (escher-telemetry):** `init` installs one stderr sink once, `ForeignSubscriber` (never a panic) when another is global; one line per event and per closed span, stamped `service.name` and `service.version`; a target outside the engine and escher prefix sets is dropped whole at every level, an engine target prints only `SAFE_FIELDS`, `CONTENT_FIELDS` always redacted; the panic hook chains.

- **Driver session (escher-driver):** a `Session` (one booted app) runs every call through `Session::run`, which validates first; nothing public runs a `Command` that did not come from `validate`; the command and refusal schema stated once as `'static` data — twelve verbs, eight closed causes, no refusal holding what a call supplied; the `v3` wire, the command line, the MCP server and the `command` and `tool_call` spans carry it; no `NodeId` crosses, and nothing logs an id, a name or a value.

- Every answer is written by hand in the crate-private `json` module — no serialization crate writes one, `serde_json` only reading MCP requests and kept checks — and no command's ending writes back anything the caller typed.

- The recording keeps a session's answered calls as a kept check, a masked `type` as its stand-in and a shot without its pixels; `Check::replay` runs them again through `Session::run`; `Session::lint` reads the screen and changes nothing; `LOAD_WAIT` (5 s) bounds an acting step's wait for a load, moving no time.

- **JavaScript (blitz-vibey-script):** `ScriptFetcher` and the `ScriptDocument` API run a document's scripts on Boa, JS listeners before Blitz default actions; `__blitz_` globals carry messages and synchronous fetches; a JS bootstrap defines history, fetch, DOMException and the CSSOM classes; escher uses none of the script text-selection and `innerText` readers.

## Cross-cutting Patterns

Detail: .andromeda/architecture-detail/cross-cutting-patterns.md — read whole.

- **Development Style signal:** agent-driven

- **Config management:** documents configured through `DocumentConfig`; optional capabilities are compile-time Cargo features forwarded down the crates, `accessibility` also gating the dioxus-native-dom snapshot modules; launch configs downcast at launch; platform behaviour gated by `cfg(target_os = ...)` and `IS_MOBILE`; runtime inputs are CLI arguments and environment variables.

- **Logging and timing:** escher binaries install `escher_telemetry::init` at start — a stderr-only sink stamping the service identity, bridging `log`, dropping every record outside the engine and escher prefix sets at every level whatever `RUST_LOG` names, scrubbing what prints and chaining the panic hook; escher-driver emits its spans ungated and installs no subscriber; the upstream `fmt::init()` installs run only under `tracing` and write stdout unscrubbed.

- **Error handling:** fallible APIs return typed results — `Result<_, CssomError>` (packages/blitz-dom/src/cssom.rs:445-451), `Result<_, ParseError>` (packages/blitz-dom/src/query_selector.rs:62), `Result<Resource, String>` (packages/blitz-dom/src/net.rs:309); uncaught JS errors go through `report_js_error`, firing a window `error` event with a re-dispatch guard (packages/blitz-vibey-script/src/runtime.rs:1097-1116; packages/blitz-vibey-script/src/state.rs:89-96), capped at 256 between drains (packages/blitz-vibey-script/src/state.rs:103-121); DOMException errors built through the bootstrap's global, falling back to TypeError (packages/blitz-vibey-script/src/dom/mod.rs:420-446); WPT drains JS errors and logs them with `warn!` (wpt/runner/src/test_runners/attr_test.rs:38-40; wpt/runner/src/test_runners/ref_test.rs:240-242; wpt/runner/src/test_runners/harness_test.rs:150-153)

- **Service wiring:** shell and navigation providers carry redraw, clipboard, file dialogs and link navigation; redraws are requested after mutations, loads, hover, device changes and a focus set or cleared, and skipped while critical resources are pending or the window is occluded; Dioxus services are root contexts; shared state is `Rc<RefCell<…>>`.

- **Event processing:** default-action events are queued and processed in order, handlers before the default action unless cancelled; sub-document and custom-widget events forwarded with adjusted coordinates; Dioxus skips event kinds with zero handlers; JS microtasks drained after eval, timers and dispatch; style and layout resolved before JS geometry reads; shortcuts use Cmd on macOS, Ctrl elsewhere.

- **Invalidation and state integrity:** interaction state on a removed node is cleared or retargeted before the node is freed; damage propagates up the DOM and to anonymous ancestors and is cleared in one visit; geometry memoisation is invalidated by a generation counter; the changed set is written at four kinds of site and by no node creation, hover, scroll, resize, load, animation or layout; the shell rebuilds the platform tree only when a poll took a non-empty set.

- **Rendering details:** legacy presentational attributes map to CSS at the presentational-hints level (packages/blitz-dom/src/stylo.rs:874-1204); `display: contents` handled by hoisting children into the nearest non-contents container (packages/blitz-dom/src/layout/construct.rs:191-268); viewport scale applied to Parley measurements and divided back out (packages/blitz-dom/src/layout/inline/layout.rs:236; packages/blitz-dom/src/layout/inline/layout.rs:877-880)
- **Unsafe aliasing:** `Node` holds a raw `*mut NodeTree` commented "This is unsafe!!" with `unsafe impl Send` and `Sync` (packages/blitz-dom/src/node/node.rs:86-88; packages/blitz-dom/src/node/node.rs:139-140; packages/blitz-dom/src/node/node.rs:1002-1005)
- **WPT bucketing:** feature-usage flags are computed by regex over test sources to bucket failures (wpt/runner/src/test_runners/mod.rs:215-240; wpt/runner/src/test_runners/ref_test.rs:145-165; wpt/runner/src/main.rs:652-671)

## Project Intent

Detail: .andromeda/architecture-detail/project-intent.md — read whole.

Origin: adopted at 0f60502ea724ef703b34220b3847bb3483f70b5f

Upstream sync: DioxusLabs/blitz `main` last merged at 23b9b26a9b6af5947b8f003d2c2cc768bff10b8a — the next sync's merge base; upstream `main` last read at `f9cbb2756`, thirteen of its commits taken by no-commit cherry-picks with the merge base unmoved; git Stylo 0.23-pre, the six Taffy-main commits and Dioxus 0.8.0-alpha.3 wait for escher's next version, so Stylo stays "0.22.0", Taffy the registry "0.15" and Dioxus "0.7.3".

escher is a fork of Blitz being turned into an agent-first UI framework — a headless driver (CLI + MCP), stable ids for every element, a compact semantic snapshot of the screen, proven on an internal 7GUIs stand. Development Style agent-driven is the founder's word: the framework's own driver is meant to become the harness.

- **Product type:** a Rust library workspace for an HTML/CSS engine — high-level APIs for rendering HTML with Blitz, the core DOM abstraction with `BaseDocument` its primary entry point, the `Document` trait letting blitz-shell drive every wrapper around it; homepage and repository `https://github.com/Turbolet85/escher`.

- **Front page:** the root `README.md` is escher's own page, not upstream Blitz's — what escher is, its status, how the driver's command line and MCP surface are run, its Blitz lineage, licence and contact, and a link to `docs/capabilities.md`, the statement of what Escher can do and its limits, the name spelled «Escher» in its prose and title, crate, binary and path names, URLs and the e-mail unchanged; no build or doc step reads it, one test does — the capability-statement pin reads its count of the driver commands an MCP client gets as tools — and at an Upstream sync an upstream change to `README.md` resolves to escher's version.

- **Crate purposes:** each crate as its own description states it — blitz-html the HTML parser, blitz-net networking, blitz-paint painting through anyrender, blitz-shell the application shell, blitz-test-harness the headless test harness, blitz-vibey-script JavaScript on Boa, blitz-traits the shared traits, debug_timer timings, blitz-dom the DOM, accesskit_xplat the cross-platform AccessKit adapter, and the Dioxus crates.

- **Apps and demonstrators:** `apps/browser` is "The example browser app", binary `blitz` (flake.nix:117-121); rdme "Markdown renderering app" (apps/readme/Cargo.toml:5); seven_guis "Seven benchmark tasks for GUI frameworks" (examples/seven_guis/src/app.rs:127-128); todomvc "The typical TodoMVC app, implemented in Dioxus."
