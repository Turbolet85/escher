 The wire is crate-private and versioned `v3`: one request line and one reply line per connection, `\n`-terminated — requests `hello v3`, `stop v3` and `call v3 <verb> [<name>=<kind>:<value>]…` (kinds `t` text · `n` whole number · `f` flag; the verb, the names and a text value percent-escaped byte for byte — every byte but an ASCII letter, a digit, `-`, `_`, `.` and `~` — and decoded strictly: uppercase hex only, no escape of a byte that needs none, the decoded bytes UTF-8, a number in its one spelling), at most 16,384 bytes where `v1` admitted 64, the widest call the schema admits being 15,360 bytes of values; replies `ok v3 pid={pid} label={label} served={n} idle_expiry_s={s}`, `ok v3 stopping`, `refused version` (a known word with another version) and `refused malformed` (anything else, a call the decoder does not read included), at most 128 bytes — the widest `hello` measures 122 — and, to a call, `ok v3 accepted <json>`, `ok v3 refused <json>`, `ok v3 oversize` or `ok v3 recording-failed` — sent in place of the answer when the host's recording ended after the call, the client reading it as `RecordingFailed` — an answer bounded at 1,048,576 bytes on its JSON line alone and `frame` the one function that turns an answer into its reply; `{n}` counts every request the host answered before this one, refusals included; a refusal or a broken connection changes nothing, an `oversize` reply is no refusal — the call ran and what it did stands — and a `stop` takes effect once its reply is written (packages/escher-driver/src/wire.rs:12-303).
