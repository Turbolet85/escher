## Goal
The 0.1.0 version-end audit scored six mutants `timeout`: no test failed on them, and each ran into the 300 s
per-mutant bound. This chunk makes each of the six fail a named test fast, and proves it with one mutation run per file
that reads 0 missed and 0 timeout. The run stays inside the operator's limits (inputs#I1): only the three files that
hold the six, `-j 2`, `taskset -c 12-15,28-31` and a 600 s test timeout.

P3 measured where each mutant hangs and why a unit test beside the code cannot catch it under `cargo test`.
cargo runs test binaries package by package in name order, so a blitz-tests integration binary reaches each mutated
site first (`stand_accessibility_ids`, `stand_act_diff`, `stand_mcp_masked`, `harness_smoke`). Each of those binaries
spins on its own test thread, so a later binary never runs (research.md §Patterns detected). The operator chose the
instrument at P4: «nextest profile (Recommended)». The chunk adds three direct unit tests, one per mutated function.
Each catches its mutants deterministically, in milliseconds, with no poll, resolve or clock. A committed nextest
`mutants` profile runs those three tests first and ends a run at its first failure. nextest runs each test in its own
process, so the hung siblings are terminated rather than waited on. Nothing shipped changes, and `mutation_writer.rs`
stays byte-identical to upstream (architecture §Standard Contracts → Dioxus DOM bridge).

baseline tests only the mutated package but still passes every `--cargo-test-arg`, so the audit's per-unit test set

mutant ran (research.md §Files inspected, `lab.rs:179-190`). The runs now take the audit's own form, `--baseline=skip`.

## Constraints & rejected approaches
- Plain `cargo test` with the hangs removed where escher owns the code (the Timer's tick wait rebuilt in shipped stand
  code, a read budget on every in-process `serve_mcp` caller) — rejected at P4 by the operator's word. It would make
  three of the six cease to exist rather than fail a test, and it leaves `create_text_node` timing out, because its
  file and first hanging binary are upstream's.
- A direct test inside `mutation_writer.rs` — not done: the file is upstream's byte for byte, and its identity is a
  recorded contract.
- A time-based watchdog thread in the hanging integration checks — not done: about twenty `stand_*` binaries boot the
  Timer (graph: `boot_timer` and `session_common::hold` callers), each spin runs on its own test thread, and a clock in
  a stand check would join the `stand-repeat` zero-failure budget's flakiness risk.
- A mutation run wider than the three files, or with other limits than inputs#I1 — not done: the operator's directive.
- A shorter `--timeout` to prove "fast" — not done. The directive sets 600 s, so "fast" is read from each of the six's
  recorded test phase (under 120 s).
- Under plain `cargo test`, the six still read `timeout`, because the hung binaries come first. This chunk does not
  change that: the property holds under the `mutants` profile, and the next audit's mutation tier must run with it
  (Expected amendments).
- cargo-mutants' default baseline — not possible in 27.1.0 with this test set: `run_baseline` tests the mutated package
  alone and still passes every `--cargo-test-arg`, so the blitz-tests targets are refused (`lab.rs:179-190`, the stopped
  run). `--test-workspace` changes only what a mutant tests, not the baseline (`options.rs:294-310`).
- Dropping the `--test=` targets so the default baseline can run — not done: the mutants would then test the five
  packages' whole suites while the baseline tests the mutated package alone, so the baseline would still not read the
  set the mutants run, and the audit's test set would be lost.
- Firing the three runs by hand with `--baseline=skip` outside the plan — rejected by the operator at implement's halt
  («Re-plan the entries (Recommended)», the stopped run's outcome).
