## Goal
One lint reads the current screen of a held instance and returns a finding for each element that overlaps another,
is clipped, has truncated text, lies off-screen, has zero size or fails text contrast. Each finding names the
element's stable id, one of six closed defect words, and the measured reason (intent §Findings 4, E1; v020-05). The
lint is read-only, like `screenshot`: no step, nothing dispatched, no time moved (arch §Standard Contracts → Driver
session). Contrast is read as `stand_contrast` reads it: `Harness::text_contrast` against `required_ratio`, a control
reading not enabled exempt, `None` not measured (a11y-plan §6 Color contrast).

The crossing is the founder's call. The operator answered F1 as delegate, «In process only (Most conservative)»,
PROVISIONAL until the founder's own word on `.andromeda/runs/2026-10-19T23-47-25-phase/founder-forks.md` (inputs#I2).
So this chunk builds the lint in process: `Session::lint` and the types it returns, a new read-only blitz-dom text
extent reader, and the fixture and stand proofs. Nothing new crosses the socket, the command line, MCP, a kept check
or a log. v020-05 asks for one command, so the in-process reader does not prove it on its own: the cap is claimed
GATED on the founder's F1 word (the operator's note, inputs#I2), as v020-03 was. The carriage his word sets is the
gated criterion (step 12), built only once his word is recorded.

The edge-case definitions are the operator's answers to three technical forks (inputs#I2). T1: `zero-size` only where
the element holds content. T2: `truncated` is text cut from view. T3: the lint itself reads `contain: paint` clips,
which `visible_region` does not.

## Implementation Steps
1. **The text extent reader (blitz-dom).** Add `packages/blitz-dom/src/text_extent.rs` with a public read-only
   `BaseDocument::text_extent(node_id) -> Option<TextExtent>`, re-exported from `packages/blitz-dom/src/lib.rs`.
   `TextExtent` holds two `BoundingRect`s in CSS px, relative to the viewport like `get_client_bounding_rect`:
   - `content`: the element's content box (its client rect less border and padding).
   - `text`: the box the laid-out lines take. It starts at the content box's top-left, offset down by the inline
     layout's `block_offset`. It spans the lines' width and height at the layout's scale (Parley `Layout::width()` /
     `height()`, the reading `layout/inline.rs:884` takes as `content_width`).

   It returns `None` for an id that does not resolve (`get`, never an index), a node that is not an inline root
   (`Node::is_inline_root`, node/node.rs:65), or one with no inline layout data. It mutates nothing, has no log site,
   print, env read or panic path, and reads the same in both layout modes and under both builds (`writing-mode` on in
   the workspace build). Its rustdoc states its limit: right-to-left and vertical text are read as left-to-right,
   horizontal lines.

2. **The reader's check.** Add `tests/blitz-tests/tests/text_extent.rs`, three tests, each `for incremental in
   [false, true]`, over pages booted with the stand's options (bundled DejaVu Sans):
   - `a_line_that_cannot_wrap_reads_wider_than_its_box`: a `white-space: nowrap` paragraph 80 px wide, holding a line
     the bundled font lays out wider than 80 px. `text.width > content.width`, and `content.width` equals 80.
   - `a_wrapped_paragraph_reads_inside_its_box`: the same text with wrapping on. `text.width <= content.width`.
   - `an_element_with_no_inline_content_reads_none`: an empty block and a stale id both read `None`.

   Each test asserts its precondition (the line measured wider than its box), never branching on it (test-plan §4).

3. **The lint's types (escher-driver).** Add `packages/escher-driver/src/lint.rs`, its module and re-exports in
   `packages/escher-driver/src/lib.rs`:
   - `Defect` is a closed enum of six with `ALL` in this order: `Overlap`, `Clipped`, `Truncated`, `OffScreen`,
     `ZeroSize`, `Contrast`. `Defect::name()` gives the words `overlap` · `clipped` · `truncated` · `off-screen` ·
     `zero-size` · `contrast`.
   - `Finding` holds:
     - `id`: the element's stable element id, as its snapshot node lists it.
     - `defect`.
     - `bounds`: the snapshot node's `BoundingRect`.
     - `reason`, an enum of six variants carrying only measured numbers and stable ids:
       - `Overlap { other, area }`: the other element's id and the intersection.
       - `Clipped { visible }`: the part that can be seen.
       - `Truncated { text, visible }`: the text box and the part of it that can be seen.
       - `OffScreen`.
       - `ZeroSize`.
       - `Contrast { ratio, required }`: the measured ratio and `TextContrast::required_ratio`.

   Neither type holds a `NodeId`, page text, a colour or a value, and both derive `Debug`, `Clone` and `PartialEq`
   like `Outcome` (nothing prints, logs or fields them, per obs-plan §4).

4. **The six readings.** In `lint.rs`, `Session::lint(&mut self) -> Result<Vec<Finding>, Refusal>` reads the held
   instance's snapshot. It records its ids in the session's record of ids read, as `snapshot` does
   (`execute.rs:318-328`). It runs no step, no settle, no pump and no time move.
   - It refuses `Refusal::new(Cause::FontsUnavailable)` before any reading when `BaseDocument::can_paint_text` reads
     false, as `screenshot` does (`execute.rs:238-241`). That cause's meaning names no verb (`refusal.rs`), so no text
     changes.
   - Each element is a snapshot node, its box its `bounds`. Each node's **clip region** is `visible_region` (the
     viewport cut by every `overflow` clip on its containing-block chain, scrolling.rs:744). That region is cut further
     by the padding box of every ancestor whose computed `contain` includes `paint` (T3). This is the lint's own walk
     up the DOM parents; `visible_region` is unchanged.

   The readings, each over nodes whose `bounds` has positive width and height except `zero-size`:
   - **overlap**: two nodes, neither an ancestor of the other in the snapshot tree, whose boxes intersect with
     positive area. A pair is reported once, at the highest level it occurs: not when an ancestor of either, below
     their nearest common ancestor, already overlaps the other. The finding names the earlier node in document order,
     with `other` the later. Geometry only, never a hit (arch §Standard Contracts → Scrolling, selection, tree).
   - **clipped**: the box intersects its clip region with positive area but is not wholly inside it. `visible` is the
     intersection.
   - **off-screen**: the box has no positive-area intersection with its clip region.
   - **truncated** (T2): a node that `text_extent` reads, that is no text control (`ElementData::text_input_data` is
     `None`, so a password's or file input's value is never measured), and whose `text` box is not wholly inside the
     region its text can be seen through. That region is the node's clip region, cut by its own padding box when it
     clips by `overflow` or `contain: paint`. `visible` is the part of the text box inside it.
   - **zero-size** (T1): a node whose `bounds` width or height is 0 and which holds content. Content means a
     non-empty `name`, a `value` (`state.value` is `Some`), an `enabled` reading (`Some`: a form control), a focusable
     element (`Node::is_focussable`, node/node.rs:553), or a non-whitespace text node among its DOM descendants. An
     empty layout box reads nothing.
   - **contrast**: a node that holds a non-whitespace text node as a direct child, or is a text control. Not when its
     snapshot `enabled` reads `Some(false)` (exempt, inactive). Not when `Harness::text_contrast` reads `None` (not
     measured). Reported when `ratio < required_ratio()`.

   Findings come in document order (the snapshot's pre-order). One node's findings follow `Defect::ALL`'s order.

     - `fx-inert` (carrying `inert`) and `fx-hidden` (carrying `hidden`), each over `fx-overlap-b`'s box.
