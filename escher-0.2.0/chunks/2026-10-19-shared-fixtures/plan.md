## Goal
State once, in a third blitz-tests shared module `tests/blitz-tests/tests/fixtures/mod.rs`, what the checks beside the
stand now repeat file by file: the boot of a fixture page with the stand's own options, the hold of such a page in a
driver session, the three fixture pages more than one check reads, and one held network stand-in. Nineteen checks read
them from there; each asserts exactly what it asserted before, in both layout modes, with every test name unchanged
(per test-plan §3 Crate-local test helpers, architecture §Conventions). This is the infrastructure the rest of
Epoch 4 proves on: Visual lint, Load wait, Select by id and Large screen in parts each prove «on a fixture»
(requirements v020-05 · v020-07 · v020-08 · v020-09), and Load wait's fixture needs a held load.

The held network stand-in is in process: a `NetProvider` keeping every request with its handler until the check
answers it. It opens no listener, socket or file, reads no environment variable and fetches nothing (per
security-plan §API Security, §Secret Management; architecture §Occupied Resources). It replaces escher's three
copies (`stand_settle`, `font_face_sniffed_source`, `stand_boot`). Upstream's own two copies
(`render_blocking_stylesheet`, `link_rel_attribute`) stay as upstream wrote them (per architecture §Project Intent →
Upstream sync).

«Run through agent-run» is met by the existing selections, on the operator's answer at this P4 (below): the fixtures
are compiled into each target by `agent-run.sh boot` (`cargo test --no-run`), nothing is seeded, `run stand` runs
every fixture-holding `stand_*` check and `run font_face_sniffed_source` the one non-stand reader that holds a load.
That reading closes test-plan §3's «NOT YET MEASURED — the test-data bootstrap mechanism» at the wrap. No script
changes.

   - `HeldNet`, the held network stand-in. It derives `Default` and holds a `Mutex<Vec<(String, Box<dyn
     NetHandler>)>>`. It implements `NetProvider::fetch` by pushing the request's url and its handler, and does not
     override `is_noop`, so the harness wraps it in its load counter (research.md §Mechanism equalities). Its
     readers: `held() -> usize` (how many requests are held) and `urls() -> Vec<String>` (their urls, in request
     order). Its one writer is `answer(&self, body: &'static [u8]) -> String`, `#[track_caller]`: it takes the last
     held request (`expect("a request is held")`), answers it with `body` through `NetHandler::bytes`, and returns its
     url. No print, `tracing` call, env read, file, socket or `blitz_net` (per obs-plan §8 Values logged as-is,
     security-plan §API Security).
