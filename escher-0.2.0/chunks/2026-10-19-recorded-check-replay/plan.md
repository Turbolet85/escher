## Goal
A recorded driver session becomes a regression check that runs as an ordinary test. This finishes v020-04: the
previous chunk built the recording, and this chunk builds the replay.

**The kept answer.** Each kept step now keeps its answer whole, as the driver wrote it, under an `answer` key after
`digest`. A shot keeps its width and height but never its pixels. This is F3 B, the founder's widening of
2026-10-19 (`escher-0.2.0/chunks/2026-10-19-session-recording/inputs/I4-relay-1.md.txt`; inputs#I1).
`Check::from_bytes` stays strict and requires the new key.

**The replay API.** escher-driver gains a public replay, `Check::replay(&mut Session)` (T1, the operator's answer):
- every kept call runs through `Session::run`, which validates first;
- each step is compared on its acceptance and its kept answer, a shot on its acceptance and size alone;
- the result says whether the check holds and, where it does not, the first step that changed and the answer keys
  that differ, as closed schema words;
- it never holds or prints a reading.

**The committed checks.** On the founder's own word, F1 A «Коммитить две проверки (Рекомендую)» (inputs#I2), two
checks of Counter sessions are committed to the repository exactly as the binary wrote them:
- one recorded through `escher-session start counter --record`;
- one recorded through `escher-session mcp --record`.

A new `stand_replay` target replays both on freshly booted stands in both layout modes. It runs under
`agent-run.sh run stand`, the CI `test` leg on three OSes and `stand-repeat`. Each check holds on the unchanged
Counter. Each turns red at its first activation step against a test-only variant Counter whose click adds 2. The
variant is mounted in the stand's own chrome through `TaskShell`, now `pub` (T2, the operator's answer: a visibility
change, no markup moved). A seven_guis freshness check re-records both sessions through the binary and reads the
committed bytes, which proves no hand edit.

2. **The kept answer, read** (`recording.rs`, `step_of` at `:391-421`, `Step` at `:296-303`).
   - The closed key list (`:392-395`) adds `answer`, and every step must carry it. A step without `answer`, or with
     an `answer` that is not a JSON object, is refused `Cause::Malformed`, holding nothing of the file.
   - `Step` keeps the answer as a private parsed value (`serde_json::Value`, read, never written). No public accessor
     returns a `serde_json` type.
   - The bounds (`MAX_CHECK_STEPS` 400, `MAX_CHECK_BYTES` 1,048,576) are unchanged, and a recording that would pass
     them still ends `recording-failed`.
   - `Check::from_bytes`' doc (`:306-315`) states the new key.
3. **The replay** (new `packages/escher-driver/src/replay.rs`, re-exported from `lib.rs:138`).
   - `Check::replay(&self, session: &mut Session) -> Replay`. A session whose `label()` (`session.rs:173`) is not
     `self.app()` runs nothing, and the replay reads not held for another app.
   - Otherwise each step's `call()` runs through `Session::run` in order, so it is validated again. The run stops at
     the first step that differs.
   - A step differs when its acceptance differs, or when the live answer's line, parsed by `serde_json::from_str`
     (with a shot's line taken without `png`), is not equal as JSON to the kept answer.
   - `Replay` reads:
     - whether the check holds;
     - how many steps ran;
     - the first `Change`, which holds the step's index, the acceptance then and now, and the answer's top-level keys
       that differ.
   - Each key is given as the schema's own `&'static str` word: a result field of the step's verb, or `refused`. A key
     no table holds is not named, and nothing of a reading is kept.
   - Nothing in the module prints, logs, reads an env var or opens a span. The `command` span each `Session::run`
     opens is the only record.
   - Unit tests in the module, on an in-process session over a small fixture, cover:
     - a check holds;
     - an acceptance flip;
     - a changed answer naming its keys;
     - a shot holding at the same size whatever its pixels;
     - another app running nothing.

- A replay verb or a `replay` role on `escher-session` is rejected. It is a new CLI shape and a new carrier

- `serde_json` as the writer of `answer` or of a replay report, or a `raw_value` feature, is rejected (arch [Driver
  session]; security §Dependency Security, «serde_json, только чтение»).
- A changed stand task for the red witness (markup, ids, colours or a behaviour switch in `examples/seven_guis/src/`)
  is rejected. It would move the a11y and layouts records. The variant lives in the test file.
- Pixel comparison of shots is out of this version (F3 B).
- A committed check of any session but the two scripted Counter sessions is rejected. F1 A covers these two, recorded
  by the repository's own script. A launcher's recording stays owner-only and is never committed.
- A replay report that names an id, a name, a value or answer text, or `Debug`-prints an `Outcome` or a `Step`, is
  never written (obs-plan §4; the founder's 2026-10-09 ruling).
- A loosened reader (unknown keys tolerated, `answer` optional) is rejected. A malformed check is refused, never
  replayed.
