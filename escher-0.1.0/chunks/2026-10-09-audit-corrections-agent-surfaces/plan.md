### 3. The install script
New file `.github/scripts/apt-install.sh`, committed executable like `ci-leg.sh` and called through `bash`.
- **Call form.** `apt-install.sh` followed by one or more package names. Each name must match
  `^[a-z0-9][a-z0-9+.-]+$`. No name, a name outside that form, an unknown option or a malformed option value
  prints a usage line to stderr and exits 2 before any command runs.
- **What it does.** Up to 3 attempts. An attempt is `apt-get update` and then `apt-get install -y` of the named
  packages, each call run as root under a bound of 120 seconds with a kill 10 seconds after the bound's signal if
  the call has not ended. The bound wraps the package manager inside the privilege (`sudo timeout … apt-get …`),
  so the process the bound signals is the one that is stuck. An attempt whose update or install ends non-zero —
  the bound's expiry included — is a failed attempt: one line naming the attempt, the phase and the exit is
  printed, the script waits 10 seconds, and the next attempt starts from `update`.
- **Exits.** 0 when an attempt completes; 1 when every attempt failed; 2 on a usage error. Never the bound's own
  124 or 137.
- **The three numbers are the script's constants** — attempts 3, bound 120, pause 10 — stated once at its head.
  The script also accepts them as options (`--attempts`, `--bound`, `--pause`, each a non-negative integer,
  attempts and bound at least 1) so that its tests run in seconds; the workflow passes none.
- It reads no environment variable of its own, names no secret, token or GitHub context variable, writes no file
  and uploads nothing: its output is the job's step log.
- A header comment in the form of `ci-leg.sh:2-5` says what it is, why it exists (the stall, by tracker number)
  and what the numbers are.

Basis of the numbers: a healthy install step read 12 s and 31 s whole, update and install together
(`escher-0.1.0/chunks/2026-10-07-refusal-detection/evidence/operator-pass.md:246-247`), so 120 s per call is about
four times the slowest healthy whole step; the two stalls ran 30 min 54 s and 26 min 36 s
(`.andromeda/runs/2026-10-09T19-31-04-phase/ci-37673662374-install-hang.md`). With these constants a mirror that
stays stalled in `update` turns the job red in about 7 minutes (3 × 120 s, the kill grace, 2 pauses), and the
worst case — every call of every attempt running to its bound — is about 13 minutes.
