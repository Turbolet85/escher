## Goal
Build what intent §Findings 3 expects and its three observed defects deny: a changed-node set that is drained, a
change flag that tells the truth, and a diff that names exactly the nodes an action changed — empty for an action
that changed nothing (requirements v010-06).

Research found the engine's flag is not merely inverted but constant: the document's own constructor marks the set,
nothing drains it, and `has_changes()` answers `false` for every document at all times, so the windowed shell's
accessibility refresh has never run (research.md §Patterns detected). It also found that no per-node engine set can
equal "the nodes whose snapshot changed": a node's name is drawn from other nodes and its bounds from layout. So the
chunk is two parts with one seam between them. **The engine part** (blitz-dom, and the flag's one caller in
blitz-shell): the set is written where the engine writes something an agent reads as role, name or state — the
mutation writers, a focus or checked change, a typed character — and no longer by node creation, which layout also
performs; a drain takes it; the flag reads true exactly while the set is non-empty. **The observation part**
(dioxus-native-dom): the diff is a pure comparison of two `Snapshot` values, keyed by stable element id, exact by
construction and a reader of the model only (per architecture §Standard Contracts → Dioxus DOM bridge; a11y-plan §7).
The seam: the flag is the engine's cheap "something was written", the diff is the truth of what changed; a written
node whose reading did not move (an attribute re-written to itself, a further character in a masked password) reads
flag true, diff empty.

Both are proven on the stand in both layout modes through real input (intent §Principles, "The stand is the
proof"), with an in-file fixture for the cases the four lean tasks lack. The diff is an in-process Rust value
returned to its caller only — the CARRY's content rule, carried unchanged (security-plan §Input Validation, the `id`
row; PROVISIONAL, pending the founder at the Epoch 3 boundary).

6. **The diff in a new `packages/dioxus-native-dom/src/snapshot_diff.rs`**, crate-private module, compiled only
   under `accessibility`, its types re-exported from `lib.rs` beside the snapshot's and named in the crate doc's
   feature list (`lib.rs:7-9`, `:20-23`, `:30-33`).
   - `Snapshot::diff(&self, after: &Snapshot)` returns a `SnapshotDiff`: a pure function of its two arguments — no
     document access, no failure path, no log, no print.
   - `SnapshotDiff` holds three lists and an `is_empty()`: `added` and `changed` are `DiffNode`s, `removed` is ids.
     `DiffNode` is a node's reading after the step, flat: `id`, `parent` (the id of its parent snapshot node, `None`
     for a root), `role`, `name`, `state`, `bounds` — no children. Both types derive `Debug`, `Clone`, `PartialEq`.
     (The entry shape is the operator's choice at P4's question round, 2026-10-07.)
   - A node is **added** when its id is in `after` and not in `self`; **removed** when in `self` and not in `after`;
     **changed** when in both and any of role · name · state · bounds · parent differs. A node whose own reading is
     equal is never named because a descendant's changed. `added` and `changed` follow `after`'s pre-order,
     `removed` follows `self`'s (`Snapshot::nodes()`).
   - No field of either type holds a `NodeId`, an `ElementId`, a `ScopeId`, an AccessKit id or a pointer, and the
     module names none of them; values come from the two snapshots only, so a password's or a file input's value is
     whatever the model holds — `MASKED_VALUE`.
   - Unit tests in the file's own `#[cfg(test)] mod tests`, over `Snapshot` values built by hand from the model's
     public fields — eight: two equal snapshots give an empty diff · a changed name · a changed state · changed
     bounds — each naming that node alone, with its after-reading · an added subtree names every node of it, each
     with its parent's id · a removed subtree names every id of it in the before order · a node moved under another
     parent is changed · `added` and `changed` are in the after snapshot's pre-order.

## Constraints & rejected approaches
- A diff derived from the engine's changed set — rejected: the set holds text nodes and anonymous blocks, which read no stable id, and cannot name an element whose name or bounds moved because another node was written; only the comparison of two snapshots is exact.
- Keeping the mark in `create_node` — rejected: layout calls it, so an idle resolve would read as a change and the flag could differ between the two layout modes.
- Marking hover, active, scroll or viewport resize — rejected: hover and active fire on every pointer move, and bounds-only movement is the diff's to report, not the flag's (the operator's choice of reach, 2026-10-07).
- A second reading of any control, of the DOM or of the accessibility tree inside the diff — do not: the diff reads two `Snapshot` values and nothing else, which is what keeps the mask and the single role and name mapping.
- A `Document` trait method, a `DioxusDocument` entry point, a `Display` impl, a text or JSON form, or a parser for the diff — not in this chunk.
- A `tracing` call, a print or a panic message carrying the set or the diff in library code — do not; `assert_eq!` / `assert_ne!` in `stand_diff.rs` — do not (both print their operands).
- Editing a stand task, the shell markup, `stand.rs` or `agent-run.sh` to make a change observable — do not; a missing case goes on an in-file fixture.
- Reaching the set through `DocumentMutator::doc` from outside blitz-dom — do not; the drain is the public door.
- Staying additive is the preference in blitz-dom and blitz-shell: steps 2, 3 and 5 add lines beside existing ones; step 1's two direct upstream-line changes (`create_node`, `has_changes`) are the named exceptions.

## Implementation notes
- **Order:** step 4's control needs the tests and `take_changed_nodes` before the rest of step 1; step 5 needs step 1; step 7 needs steps 1–3 and 6.
- **After boot the set is non-empty** — the initial build writes through the mutator — so every step drains before it acts; a check that reads the flag without draining first reads the boot.
- **`toggle_radio` marks every radio of the set**, changed or not (`document.rs:686-703`): engine-touched is a superset of snapshot-changed by design, and the diff, not the flag, says which reading moved.
- **A click can move focus** (`events/pointer.rs:813-817`): after a Tab press, a click on a control the click handler does not match clears focus and that control's neighbour appears in the diff. The literals of step 7 are stated for a fresh boot or for the sequence named; the check's own oracle decides every other id.
- **Bounds can move with a name**: a longer text can re-wrap or widen a box, so a sibling may legitimately appear as changed. Where a literal expectation meets that, the oracle is the authority and the literal asserts membership, not the whole set — recorded in the report where it happens.
- **Stale ids:** `take_changed_nodes` returns ids as written; a dropped node's id stays in the returned set and reads `None` — never index the slab with one (CLAUDE.md invariant).
