## Goal
The driver's fourth piece, after the session, settle and the schema: **a call runs on a held instance**. A
caller hands a `Session` a `Call`; the session validates it against the one verb table, runs the verb, settles
the instance and returns a typed result — for an acting verb whether the instance went quiet and the diff of
the screen before and after, named by stable element id (intent §5, §3; architecture §Standard Contracts →
Driver session; architecture §Standard Contracts → Dioxus DOM bridge). `click` and `type` name their target
by the id a snapshot lists; `press` acts on what holds focus; `advance` moves the app's time through a step
the session's caller supplies; `snapshot` returns the screen's text.

Everything runs **in process** (the operator, 2026-10-07, at the P4 forks): the session socket stays `hello`
and `stop`, nothing of the screen crosses it, and the diff and the snapshot text leave through the returned
value only, inside the founder's standing ruling (security-plan §Input Validation, the `id` row; §API
Security, the Local session socket row). The typed-sentinel reading in a sink-installing host's log is
therefore not owed here and stays "not measured".

The chunk also closes five of the entry's carried items: the three-way id check (v010-03), the returned diff
(v010-06), a settled Timer flow through a driver action (v010-10), the `accessibility` feature decision for
the session library, and the wiring of `advance`. Of the two carried engine defects, typed deletion is made
to work headlessly on every platform without an engine edit, and the range input is measured through the

4. **Hand the session its time step** — in `packages/escher-driver/src/session.rs`, `Session` holds an
   optional time step, and a new method `Session::with_time(self, step)` returns the session carrying it. The
   step is a caller's closure taking the held harness and the milliseconds asked and returning the
   milliseconds the app actually moved. `Session::start`, `harness`, `harness_mut` and `act` keep their
   signatures and behaviour (`Session::start @ session.rs:35`, 10 outside reference sites; `Session::act @
   session.rs:70`, 7 call sites — research.md §Graph impact); a session started without `with_time` has no
   step. The library names no app, no Timer and no tick.
5. **Run a call** — new private module `packages/escher-driver/src/execute.rs`, re-exported from the crate
   root, holding:
   - the public result type `Outcome`, one variant per result shape of the verb table: `Screen` holding the
     snapshot `text`; `Acted` holding `settled`, `busy` (the `Busy` class, present only when not settled) and
     the `SnapshotDiff`, unchanged; `Advanced` holding those three and `advanced_ms`;
   - the public method `Session::run(&mut self, call: &Call) -> Result<Outcome, Refusal>`, the one entry
     point. It calls `validate(call)` first and returns its refusal before anything else runs; nothing public
     runs a `Command` that did not come from `validate`.
   Per verb:
   - `snapshot` — the text of `DioxusDocument::snapshot` through `Snapshot::to_text`; nothing is dispatched.
   - `click` — the id is resolved (below); then one settled step that clicks at the centre of the node's
     border box through `Harness::click_at`, the same arithmetic `Harness::click` applies to a selector
     (`input.rs:97-108`).
   - `type` — the id is resolved; then one settled step that clicks the node the same way, which focuses a
     text input (`pointer.rs:547`), and types the text through `Harness::type_text`.
   - `press` — one settled step that presses the key through `Harness::press_with`, with the shift modifier
     when `shift` is true. Each of the schema's twelve keys maps to one keyboard key. On macOS only
     (`target_os = "macos"`), a `backspace` press also dispatches `deleteBackward:` through step 3's helper —
     the binding a window delivers there, where the editor's own Backspace arm is compiled out
     (`text.rs:329-331`, `:430-433`).
   - `advance` — a session with no time step returns `Refusal::new(Cause::TimeUnavailable)` and runs nothing;
     otherwise one settled step that calls the time step with `ms`, and `advanced_ms` is the step's return,
     never above `ms` (the lesser of the two).
   A settled step is: the snapshot before, the step, `Harness::settle`, the snapshot after, and
   `before.diff(&after)`. A not-quiet instance is a result — `settled` false with its `Busy` class — never a
   refusal and never a `SessionError`; the step is not rolled back.
   Resolving an id: the first pair of `DioxusDocument::element_ids()` whose id equals the argument, its node
   read through `get_node`. An id no pair carries, or a node that does not resolve, returns
   `Refusal::new(Cause::NotFound)` with nothing run. Nothing resolved outlives the call; the session keeps no
   id and no `NodeId`. No path indexes a node, calls `Harness::layout_rect_of` (it panics on an unresolved
   node, `inspect.rs:59`), or uses `unwrap`, `expect`, `panic!` or `unreachable!` on anything a call supplied.
   The module prints and logs nothing, reads no env var and no clock, and never formats a `Call`, a `Command`
   or an `ArgValue`.
6. **Root and docs** — `packages/escher-driver/src/lib.rs` declares the module, re-exports `Outcome`, and its
   crate doc states that a call runs through a session in process and that nothing of it crosses the socket;

## Constraints & rejected approaches
- A command on the session socket — rejected by the operator at the P4 forks: the playbook's "Boundary widening" class, and the route places the first crossing on "Driver CLI". No request, reply or bound of `wire.rs` changes.
- A time step added as a parameter of `Session::start` — rejected: it threads through 10 outside reference sites in six files (research.md §Graph impact); `with_time` threads through none.
- Changing `Session::act`'s return type so that not-settled is a result — rejected: 7 call sites pin it; the executor reads `Harness::settle` itself.
- `keyboard-types` as a third dependency of `escher-driver` — rejected: architecture §Established Decisions → [Driver session] records the crate's two dependencies; the harness re-exports the types its own API takes.
- Removing the macOS `cfg` from the editor's Backspace arm — rejected: a window on macOS delivers the delete as a standard key binding, so an ungated arm would delete twice there; and `text.rs` is upstream-owned merge surface.
- A range interaction model in the engine, or a stand-in element for `timer-duration` — rejected by the operator at the P4 forks: measured, not built; layout-templates bars adding an element so an action has something to hit.
- Deriving the diff from `take_changed_nodes`, or draining the changed set in a step — banned: the set is engine-touched and the drain is the windowed shell's (architecture §Cross-cutting Patterns → Invalidation and state integrity).
- Telling `stale` from `not-found`, and detecting `disabled`, `covered` and `off-screen` — not here: "Refusal detection" owns them; a click on a disabled or covered target runs and its diff says what changed.
- No deleting key in any check but `stand_act_keys`' one (`.claude/rules/testing.md` §Session Additions, 2026-10-06).
