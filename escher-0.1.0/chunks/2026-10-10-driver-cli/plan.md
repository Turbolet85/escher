## Goal
The driver gets its first surface: **a command an agent runs**. Every driver command — the six verbs and the
session's own `start` · `status` · `stop` — runs as `escher-session <command> --session <dir> …`, answers one line
of uncoloured JSON on stdout, writes diagnostics to stderr only, and ends with a status that tells accepted (`0`)
from refused (`1`), usage (`2`) and a session error (`3`). A stand flow runs as a plain `sh` script (intent §7;
requirement v010-12), and the snapshot command proves the compact snapshot's last leg (v010-04).

Everything a command needs already runs in process; what is missing is the path between a short-lived client
process and the host that holds the instance. The founder ratified that path on 2026-10-10 (`inputs#I3`): the one
registered session socket carries a call in and its answer out. The library carries the whole command line and the
stand's own binary both hosts and drives (per architecture §Established Decisions → [Driver session]; security-plan
§Threat Model Summary, the local IPC vector; test-plan §3 → Session lifecycle).

Along with the surface the chunk lands what the route pinned on its first hosted command: the typed-sentinel proof
in a host's log under both builds, the timer host's standing boot, a bound on the session's record of ids, `type`
replacing what a control holds (the founder's answer to fork 8), and the measurement — not the fix — of the two
engine findings (fork 9).

### 5. The record of ids is bounded in bytes (`packages/escher-driver/src/session.rs`)

### 6. The written JSON forms (`packages/escher-driver/src/json.rs`, new)
A hand-written, output-only writer (`inputs#I2`): no dependency enters. Every form is exactly one line.
- **An outcome** — an object whose keys are the verb's result fields, in the table's order: the screen as
  `{"text":"…"}`; an acting verb as `settled`, `busy` (present only when not settled, one of `BUSY_CLASSES`),
  `added`, `removed`, `changed`, then `advanced_ms` or `in_view` where the verb has it.
- **A node** — an object with the fields `NODE_FIELDS` names, in that order: `id`, `parent` (left out when the node
  has none), `role` (the spelling `Snapshot::to_text` writes), `name`, `enabled` and `checked` (each left out when the
  node has none), `value` (left out when the node has none), `focused`, and `bounds` as an array of four numbers —
  x, y, width, height — each the shortest decimal that reads back the same; a number that is not finite is `null`.
- **A refusal** — `{"refused":{"cause":…,"meaning":…,"remedy":…}}` from the cause's three fixed strings, with
  `"fault"` (the fault's fixed sentence) beside a malformed one.
- **A session error** — `{"error":{"kind":…,"message":…}}`: a fixed kebab-case word per `SessionError` variant and
  its fixed message.
- **A session command's answer** — the fields step 2 names.
- **Strings** — `"` and `\` escaped, U+0000 to U+001F as `\n`, `\r`, `\t` or `\u00XX`, everything else as its UTF-8.
- Nothing is written by `Debug` of a `Call`, a `Command`, an `Outcome` or a `Refusal`. Unit tests over built values,
  each table stated with its row count: the escaping rows, one row per `Outcome` variant, per cause, per
  `SessionError` variant, a node with every optional field present and one with none, a masked value written as the
  mask.

### 7. The wire carries a call (`packages/escher-driver/src/wire.rs`)
- The version word becomes `v2` for every request; a known word with another version is still `refused version`.
- A third request: `call v2`, the verb, then one word per argument — the argument's name, `=`, a one-letter kind
  (`t` text, `n` whole number, `f` flag), `:`, the value. Verb, names and text values are escaped: every byte that is
  not an ASCII letter, a digit or one of `-`, `_`, `.`, `~` is written as `%` and two uppercase hex digits. A line
  that does not decode — a bad escape, bytes that are not UTF-8, a kind letter outside the three, a number or flag
  that does not parse — is `refused malformed` and changes nothing.
- Bounds: a request line at most 16,384 bytes (the widest validated call — a `type` with a 1024-byte id and a
  4096-byte text, every byte escaped — is 15,360 bytes of values); a lifecycle reply keeps a small bound, restated
  for its widest case; a call's answer at most 1,048,576 bytes.
- Replies: `ok v2 accepted` or `ok v2 refused` followed by the JSON line; `ok v2 oversize` when the answer is over
  its bound (the step ran and is not rolled back); `hello`'s reply gains the host's idle expiry in seconds. The
  answer's bound is on the JSON line alone, without the words in front of it, and framing an answer is one function
  of the wire that takes the line and returns the reply, so the bound is testable on a made value.
- **The answer bound's witness** (`inputs#I4`; no stand screen can reach it): unit rows on that function — a made
  answer of exactly 1,048,576 bytes is framed as an ordinary accepted answer and round-trips, one of 1,048,577 bytes
  is framed `ok v2 oversize`; and `ok v2 oversize` parses to its own reply.
- Read bounds: 2 s on each read and write as today; a client reads a call's answer under 30 s (`inputs#I2`).
- The eight unit tests are restated for the grown grammar and joined by: every request and reply round-trips; the
  escape table; a decoded call equals the encoded one for every argument kind, an id holding `/`, `:`, `[`, `]`, a
  space and a line break among them; the widest validated call fits its bound; each undecodable line is refused.

### 8. The host runs calls and expires; the client sends one
- `packages/escher-driver/src/host.rs` — `serve` gains the idle expiry as a parameter and hands the session to its

  refusal is written by step 6's forms and framed by step 7's replies. The loop waits on the listener without
  blocking, polling as the client does (25 ms), and when no request has been answered for the expiry it ends exactly
  as `stop` does: session dropped, socket file and state directory removed, `Ok`. An accepted connection is read and
  written under the standing 2 s bounds. A broken or undecodable connection changes nothing.
- `packages/escher-driver/src/client.rs` — a public `call` sends one call to the session in a state directory and
  returns its answer: whether it was accepted, and the JSON line as text, never decoded. `Hello` gains the expiry.
- `packages/escher-driver/src/error.rs` — a thirteenth variant for an answer over the wire's bound, with a fixed
  message; the standing message test covers it.
- The rest of the answer bound's witness: the client's reading of a reply is one function from the reply to the
  caller's result, and a unit row holds that the `oversize` reply reads as the thirteenth variant; step 9's ending

### 9. The command line (`packages/escher-driver/src/cli.rs`, new; `packages/escher-driver/src/lib.rs`)
One public entry takes the arguments after the program's name, the names of the apps the binary boots, and a boot
function from an app's name to a `Session`; it writes the answer and returns the process status. It installs no
subscriber and reads no environment variable.
- **Reading a line**, in this order:
  1. No first word, or an argument that is not UTF-8: usage.
  2. `serve`: the host role, exactly `serve <app> --session <dir>`; anything else is usage. It boots the app, serves
     it with `IDLE_EXPIRY`, and returns `0` after a stop or an expiry.
  3. Any other first word is looked up in the verb table; a word the table does not hold is the refusal
     `unknown-verb`.
  4. `start` takes the app as its one positional word (the form the founder's fork 2 shows). Every other argument of
     every command is a named flag spelt as the table spells the argument: `--id`, `--text`, `--key`, `--ms` with
     one value, `--shift` bare. A flag the verb's row does not name, a flag given twice, a value that is missing or
     not of its kind and a stray word are the `malformed` refusal with the fault the schema already has for it.
  5. The call is checked (`validate`, or `validate_session`) before the session address is asked for: a refused call
     never touches a session.
  6. `--session <dir>` exactly once, else usage. For `start`, an app the binary does not boot is usage, naming the
     apps.
- **Running it**: `start` spawns the running binary itself in the host role with stdin, stdout and stderr closed,
  waits up to 30 s for it to answer (`client::start`), and prints the session's facts; `status` is `attach`; `stop`
  is `stop`; an instance verb is `client::call`.
- **The four endings**: accepted — the answer on stdout, status `0` (an instance that did not go quiet is accepted:
  `settled` reads false); refused — the refusal on stdout, status `1`; usage — one fixed usage line on stderr built
  from the table's words and the app names, stdout empty, status `2`; session error — the error object on stdout,
  its fixed message on stderr, status `3`. No ending echoes anything the caller typed.
- stdout is written as one line and a line break; a write to a closed pipe is not a panic. No path that reads argv
  can panic, index or unwrap on what the caller supplied.
- Unit tests over the argv reader alone (no session): one row per rule above, the rows counted; and over the
  endings as a table from a result to what is written and returned — an accepted answer, a refusal, each
  `SessionError` variant (the thirteenth among them), a usage error — the rows counted.
- `lib.rs`: the crate doc's sentences that this chunk makes false (`lib.rs:13-16`, `:32-33`) are rewritten to what
  is built; the new public items are re-exported (the count of re-exported names is read before and after — 33 at
  the base per architecture §Standard Contracts; record what the edit makes it).

## Constraints & rejected approaches
- A single long-lived process reading commands on stdin (fork 1's second option) — rejected by the founder: a command would have no exit code of its own.
- Named sessions under a per-user root, an environment variable for the address, a generic `escher` client crate (fork 2) — rejected: each registers a new resource or a new crate; the address stays a caller-named path.
- A `list` command (fork 3) — rejected with named sessions; the idle expiry is the answer to an orphaned host.
- Positional arguments and `name=value` pairs (fork 4) — rejected: the flags are the schema's own words.
- A JSON list of nodes for `snapshot`, both forms, or a `--nodes` flag (fork 5) — rejected: the screen is the text in one string field.
- A distinct exit code for a step that did not go quiet, two classes only, or one code per cause (fork 6) — rejected.
- A command for the actionable-key check (fork 7) — not in this chunk.
- `type` appending, inserting where the click lands, or a `--replace` flag (fork 8) — rejected: `type` replaces.
- Editing `get_client_bounding_rect`, the bounds reader or the hit walk (fork 9) — rejected for this chunk: measure and state.
- `serde_json` or any serialization crate (`inputs#I2`) — rejected for this chunk.
- Do not print, log or field a `Call`, `Command`, `ArgValue`, `Outcome`, `Refusal` or `Fault` with `Debug`; do not add a span field; do not put an id, a name, a value or typed text in a test name or an assertion message.
- Do not add a wait, a poll or a clock read to a command: the one clock this chunk adds is the host's idle expiry, on its accept loop.
- Do not add an `[[test]]` table for a new check, and do not edit a prior chunk's evidence files: this chunk's instrument is its own copy.
- Do not use a deleting key in a check; the one deleting step is the driver's own empty-text path of `type`.

## Implementation notes
- A listener set non-blocking hands out accepted streams that are non-blocking on some platforms: the host sets each accepted stream blocking before applying its read and write bounds.
- `start` drops the spawned host's handle without killing or reaping it; the host's streams are closed so a caller's `$(…)` returns. The host's log is visible by running `serve` in the foreground.
- The two builds overwrite one path, `target/debug/escher-session`: a reading taken from that path belongs to whichever build ran last. The two `host_log` entries and the by-level instrument each build what they read.
- An id holds `/`, `:`, `[` and `]`, and typed text holds spaces and line breaks: both cross argv, the wire and the JSON writer as opaque bytes.
- The select-all in step 4 reaches the app as a key event before the engine acts on it; the standing six driver-action checks and `stand_act_range` are the witness that no stand task reads differently for it.
- Decided at the review — the operator's technical answers, 2026-10-10 (`inputs#I4`), recorded beside the two usage cases the founder's fork 6 names: an app the binary does not boot is a usage error (status `2`), a third usage case; the host role exits `3` on a session error where the built host exits `1`; `start` takes the app as a positional word, as fork 2's example shows; a session-level verb handed to `Session::run` in process is refused `unknown-verb`, whose fixed meaning ("the call names no verb of the verb set") is loose for that one in-process case, which no command-line path reaches.
