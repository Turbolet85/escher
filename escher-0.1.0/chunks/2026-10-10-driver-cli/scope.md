## What this chunk builds
The first surface of the driver: **a command an agent runs**. intent §7 states the gap and the expectation — "the headless harness is a Rust API in a test-only crate (`publish = false`) — no command an agent runs" → "every driver command runs from a CLI with JSON output and an exit code that means accepted or refused; a stand flow is scriptable in shell alone" (`escher-0.1.0/intent.md:60-63`). Everything a command needs is built and runs in process today: the session, settle, the verb table and its validation, the executor, refusal detection and the command span (`packages/escher-driver/src/lib.rs:1-48`). No binary reaches any of it but the host `escher-session`, whose argv is `<task> <state-dir>` and which only serves (`examples/seven_guis/src/session_host.rs:24-49`).

The founder's purpose for this surface, as the operator relayed it with the take-up (`inputs#I1`): "the CLI is the first surface an agent meets, and the founder stated the purpose again on 2026-10-09 — an agent sees, drives and verifies a UI and learns the tool from the tool."

- **Every command runs from the command line** — the six verbs of the one table (`snapshot` · `click` · `type` · `press` · `advance` · `scroll`, `packages/escher-driver/src/schema.rs:290`) and the commands of a session's life (bringing one up, reaching it, stopping it — today the library functions `start` · `attach` · `stop`, `packages/escher-driver/src/client.rs:37-64`).
- **Uncoloured JSON on stdout** — every command's answer is JSON on stdout and nothing else is written there: an accepted command's result (the screen for `snapshot`; for an acting verb whether the instance went quiet and the diff of the screen before and after, `scroll` adding whether its target is in view), a refused command's refusal (its cause and the cause's fixed remedy), a lifecycle command's answer. No colour, no escape sequence, in a terminal or out of one.
- **Diagnostics on stderr** — what is not a command's answer goes to stderr: usage, an error of the tool itself, the telemetry sink's lines (escher binaries install `escher_telemetry::init`, stderr only — CLAUDE.md §Critical Warnings).
- **An exit code that tells accepted from refused** — a script branches on the process status alone, without reading stdout.
- **A stand flow is scriptable in shell alone** — a shell script, with no other tooling, starts a session on a stand task, reads its screen, acts on ids the screen lists, checks what came back and stops the session; it is run as a check and passes (v010-12's acceptance: "a stand flow completes as a shell script with no other tooling").
- **A call reaches a held instance from another process** — verified at P3: `serve` takes the `Session` and hands its loop the label alone (`packages/escher-driver/src/host.rs:48`), no code outside a test calls `Session::run` (12 call sites, all under `tests/blitz-tests/tests/` — research.md §Graph impact), and the built wire cannot hold a call: a request is two words in at most 64 bytes and a reply at most 128, read under a 2 s bound (`packages/escher-driver/src/wire.rs:13-20`, `:65-68`), while an `id` admits 1024 bytes and `text` 4096 (`packages/escher-driver/src/schema.rs:5`, `:8`) — a command-line process ends when its command returns, and a session is one instance held across commands, so the instance lives in a host process and each command's call and outcome cross between the two. Today "nothing of the schema, of a call or of an outcome crosses the socket: they are passed and returned as values" (`packages/escher-driver/src/lib.rs:32-33`); the wire is `hello` and `stop` (`lib.rs:13-16`). Carrying a call in and an outcome out puts element ids, accessible names, control values, typed text and the snapshot's text on a process boundary for the first time. That is the playbook's "Boundary widening" (`.andromeda/playbook.md:36-37`, verdict `escalate`): the widening is asked, never leaned (decision 1 below). How it crosses — the session socket's grammar grows, or another form — is the plan's, from research.
- **JSON is produced from the one schema's data** — verified at P3, and the table already names every key an answer needs: each verb's result fields (`text`; `settled` · `busy` · `added` · `removed` · `changed`, with `advanced_ms` and `in_view`) and a node's nine fields (`NODE_FIELDS`), each with its kind and help (`packages/escher-driver/src/schema.rs:33-35`, `:147-210`); `serde` is a workspace dependency and `serde_json` is not, though the lock holds it for other packages (research.md §Files inspected) — the schema is `'static` Rust data and `escher-driver` depends on no serialization crate (`packages/escher-driver/Cargo.toml:13-16`: `blitz-test-harness`, `dioxus-native-dom`, `tracing`); an `Outcome`, a `Refusal`, a `SessionError` and a lifecycle answer each need a JSON form, and a call needs a form in which it arrives from argv. How (written by hand, or a dependency) is the plan's; a new workspace crate or dependency is registered, never silent (CLAUDE.md §Critical Warnings).
- **The cases that are neither accepted nor refused** — verified at P3 (`SessionError` has 12 variants, `packages/escher-driver/src/error.rs:12-37`; `Session::run` returns a not-quiet step as an `Outcome`, `packages/escher-driver/src/execute.rs:15-16`; the host exits `0` · `1` · `2` today, `examples/seven_guis/src/session_host.rs:31`, `:51-56`) — a command line has more endings than the entry's two: a session edge (`SessionError` — no session, a dead one, a timeout, an unsupported platform), a usage error, a client that waited past its bound for an answer (a command's reply is read under the lifecycle's 2 s bound as built, `packages/escher-driver/src/client.rs:165-173`), and an accepted acting verb whose instance did not go quiet (`NotSettled` naming the busy class — an outcome, not a refusal). What each exits with and what it prints is part of decision 4.
- **v010-04's command leg** — "one snapshot command returns each stand task's screen as a tree where every node carries id, role, name, state and bounds, and the whole result fits in a single tool result": the tree, its text form and its 10,000-byte budget are built and proven in process (`Snapshot::to_text`, `SNAPSHOT_TEXT_BUDGET`, `packages/dioxus-native-dom/src/snapshot_text.rs:16`, `:36`; `tests/blitz-tests/tests/stand_snapshot_text.rs`); the command is this chunk's (CARRY 2).
- **Two proofs the first hosted command owes** — a typed sentinel read absent from the host's stderr at `RUST_LOG=trace` (CARRYs 5 and 11), and a standing check that boots the timer host and moves its time by `advance` (CARRY 6).
- **The claim** — the entry names v010-12; CARRY 2 names v010-04. Whether each becomes fully verifiable here is read at P4 from the matrix; none is assumed.
