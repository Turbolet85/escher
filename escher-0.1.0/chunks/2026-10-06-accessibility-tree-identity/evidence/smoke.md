# P3 smoke: the windowed stand with accessibility on

- **When:** 2026-10-06T12:39Z, at /implement P3, by hand (not a plan entry).
- **Why this form:** the plan names `just seven_guis` as the windowed boot. seven_guis enables no `accessibility` feature, though (the workspace pins dioxus-native with `default-features = false`). So that recipe never compiles the shell's AccessKit path. The smoke built the same binary with the feature forced: `cargo build -p seven_guis --bin seven_guis_native --features dioxus-native/accessibility`, exit 0. `cargo tree` with the same flag shows `dioxus-native-dom feature "accessibility"` on, through the dioxus-native companion edge.
- **Boot:** `timeout -s TERM -k 5 15 ./target/debug/seven_guis_native` exited 124 (it stayed up for the whole bound). Its stderr is one line, a winit Wayland `WARN` that `xdg_toplevel_icon_manager_v1` is not supported. It has 0 `panic` / `already borrowed` / `BorrowMutError` lines. Afterwards the process list had no `seven_guis_native`.
- **What it does not prove:** the host's AT-SPI bus read `org.a11y.Status IsEnabled = false` (`busctl --user get-property`, read-only). So the AccessKit adapter was inactive, and `update_if_active` never ran `Document::accessibility_tree` in the window. The smoke proves the windowed boot with the re-threaded `update_tree` callers compiled in. It does not prove a platform tree build. That output is proved headlessly by `stand_accessibility_ids` through the same trait method. The bus flag was left untouched, because it is the operator's desktop state.
