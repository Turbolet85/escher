## Goal
Build the Foundation reachability pipe for the cold-agent gate (route 1A tree, `1a-tree.md:8`; `[GATE_REACHABILITY]`).
One command starts a fresh, isolated agent session whose only tools are a stub's. It gives the session a small task,
captures the whole session as a transcript, counts the session's wrong calls from the stub's own log and cross-checks
them against the transcript, and writes a machine-readable verdict. The pipe is proven twice:
- by contract tests that replace the agent client with a scripted shim, so no live model is involved
  (test-plan §4 shim pattern);
- by ONE live run on this host whose passing verdict, transcript and token usage are committed as evidence
  (test-plan §3 Proof).

The Epoch 6 "Cold-agent test" (v010-15) will drive the real driver and a stand task through this same pipe. So the
client invocation, isolation check, transcript capture, wrong-call count and verdict are built as reusable plumbing.
The stub tool and its task are the swappable parts. This chunk claims no capability: v010-15 needs the real tool and a
stand task (`matrix.py show --id v010-15`).

The pipe follows the stand test contract's grammar, which arch §Standard Contracts → CI contracts and test-plan §3
spell out:
- one verb script with python3-encoded JSON lines on stdout;
- exits 0/1/2/3, with usage checked before any precondition;
- state confined to its own `target/` directory, disjoint from `target/agent-run/`;
- a no-logic `.ps1` pass-through.

Two isolation rules follow from research. Isolation is checked in every run, never assumed. And the session runs from a
working directory whose path does not name the project, because research probe 1 showed the cwd path reaching the
session (research.md §Live probe; scope.md premise correction).

## Implementation Steps
1. **The stub tool — `scripts/cold_agent_stub.py`.** A python3 stdlib-only MCP server speaking newline-delimited
   JSON-RPC 2.0 over stdin/stdout. It opens with a module docstring stating what it is (arch §Conventions →
   Documentation).
   - **Protocol.** It answers `initialize` with its protocol version, `capabilities.tools` and `serverInfo` name
     `stub`. It accepts `notifications/initialized`. `tools/list` returns exactly three tools, `list`, `read` and
     `press`, each with an `inputSchema`. `tools/call` dispatches them. Any other method gets a JSON-RPC error. Nothing
     but protocol frames goes to stdout; any diagnostic goes to stderr.
   - **Model.** A toy counter held in memory: a display `count` (starts at 0), buttons `inc`, `dec` and `reset`. `dec`
     is disabled while the count is 0.
     - `list` takes no arguments and returns every element as id · role · enabled.
     - `read {id}` returns the display's number, or a button's label and enabled state.
     - `press {id}` acts on an enabled button.
   - **Refusals.** Each is a tool result with `isError: true` and a cause token as the first word, and none changes
     state:
     - `not-found`: the id is unknown;
     - `disabled`: the button is disabled;
     - `not-pressable`: `press` on the display;
     - `malformed`: a missing, extra or non-string argument.
   - **Call log.** Every `tools/call` appends one JSON line to the call-log file named by `--calls`: seq · tool · ok |
     refused · cause. It never records the argument values. After every call the stub rewrites the state file named by
     `--state` with the current count. Both paths come from argv; the stub reads no env var.
2. **The pipe — `scripts/cold-agent.sh`.** A bash script with the agent-run layout: a `VERBS` array, `usage()` to
   stderr exiting 2, and an embedded python3 program in a quoted heredoc that does every JSON read and write. Verbs:
   - `run <task>`: the only task is `counter`, checked against an allowlist before anything else.
   - `status`, `logs` and `cleanup`: each takes no argument.
   State lives in `STATE_DIR=target/cold-agent` only. Run it from the repository root.
   - `run counter`, in order:
     1. **Usage** (exit 2): a bad verb, a wrong argument count, or a task outside the allowlist.
     2. **Preconditions** (exit 3, with a stderr message): `claude` and `python3` on PATH.
     3. Recreate `target/cold-agent/` (`rm -rf` then `mkdir`).
     4. Make a per-run session directory with `mktemp -d`. Copy the stub into it and write the MCP config JSON there:
        one server, `stub`, whose command runs `python3` on the copied stub with `--state` and `--calls` pointing
        into the session directory.
     5. Emit `run.start` (task, ts).
     6. Run the client from the session directory, with stdout to `target/cold-agent/transcript.jsonl` and stderr to
        `target/cold-agent/client.log`:
        `claude -p "{the counter task prompt}" --output-format stream-json --verbose --tools "" --strict-mcp-config
        --mcp-config {session dir}/mcp.json --allowedTools mcp__stub --setting-sources "" --disable-slash-commands
        --no-session-persistence --max-budget-usd 1`.
        Bound the client with `timeout 600`. A timeout or any non-zero client exit becomes a `failed` outcome with
        exit 1, never a propagated 124.
     7. Copy the stub's call log and state into `target/cold-agent/` as `calls.jsonl` and `stub-state.json`. Remove the
        session directory.
     8. Compute the verdict (step 3) and write `target/cold-agent/verdict.json`.
     9. Emit `run.end` carrying the verdict's fields. Exit 0 on `passed`, 1 on `failed`.
   - **The task prompt.** It names only the goal: operate the counter through your tools until its display reads 3,
     then reply with the display's final reading. It names no element id, so the session must discover the ids
     through `list`.
   - `status`: prints the last verdict as one `status` event. Exit 0 when a verdict exists, 3 when none does.
   - `logs`: prints `target/cold-agent/events.jsonl`. Exit 3 when it is absent.
   - `cleanup`: `rm -rf target/cold-agent`, emits `cleanup`, exits 0, and is idempotent. It touches nothing else under
     `target/`. `target/agent-run/` and `target/ci-logs/` survive it.
   - Every event is printed and appended to `target/cold-agent/events.jsonl`, except `status` and `cleanup`, which are
     printed only (as in agent-run).
   - No event, and no verdict field, takes a scrub-set name (`url href src html text value attrs path request error
     panic.payload`, test_agent_run.py:15 plus obs-plan §8).
   - No transcript text, tool argument, tool result or the session's final reply is ever copied into an event or the
     verdict.
3. **The verdict** (computed by the embedded python from `transcript.jsonl`, `calls.jsonl` and `stub-state.json`;
   field names fixed here):
   - **`isolated`** is true only when all of the following hold in the transcript's `system/init` event:
     - `tools` is exactly the stub's three tools, `mcp__stub__list`, `mcp__stub__read` and `mcp__stub__press`, in any
       order;
     - `mcp_servers` is exactly one server named `stub`, with status `connected`;
     - `skills` and `slash_commands` are empty;
     - `apiKeySource` is `none`;
     - neither `cwd` nor any `memory_paths` value contains the repository root's directory name, compared
       case-insensitively. That name is `basename` of `git rev-parse --show-toplevel`, falling back to the basename of
       the root the script runs from.
     `session_tools` (the init tool list) and `client_version` (`claude_code_version`) and `model` are recorded beside
     it.
   - **`tool_calls`** is the number of `tool_use` blocks in `assistant` events.
   - **`wrong_calls`** is the stub call log's `refused` count, plus the transcript's `tool_use` blocks naming a tool
     outside `mcp__stub__*`, plus the `result` event's `permission_denials` entries.
   - **`transcript_errors`** is the transcript's `tool_result` blocks with `is_error: true`.
   - **`counts_agree`**: the `tool_result` errors on stub tool_use ids equal the stub log's `refused` count, and the
     transcript's stub `tool_use` count equals the stub log's call count. A disagreement means a call the stub never
     saw, such as a client-side denial.
   - **`final_count`** is read from `stub-state.json`. It is the stub's state, never the agent's reply.
   - **Usage** comes from the `result` event: `num_turns`, `duration_ms`, `cost_usd` (from `total_cost_usd`),
     `input_tokens`, `output_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens`.
   - **`transcript_file`** is `target/cold-agent/transcript.jsonl`.
   - **`outcome`** is `passed` only on positive evidence: the client exited 0, the `result` event has `subtype`
     `success` and `is_error` false, `isolated`, `counts_agree`, `tool_calls` ≥ 1, and `final_count` == 3. Anything
     else is `failed`, with `reasons` listing each failed condition by a fixed token (`client-exit`, `no-result`,
     `not-isolated`, `counts-disagree`, `no-tool-call`, `task-unmet`).
     - A missing or unparsable transcript reads `failed` (`no-result`), never passed.
     - `wrong_calls` does not decide the outcome. It is a count the gate records (v010-15 "wrong calls counted").
4. **`scripts/cold-agent.ps1`** — a 4-line pass-through, the `scripts/agent-run.ps1` shape (comment lines, then
   `& bash "$PSScriptRoot/cold-agent.sh" @args` and `exit $LASTEXITCODE`). It holds no logic.
5. **Contract tests — `.github/scripts/test_cold_agent.py`** (python `unittest`, discovered by the `ci-scripts` leg;
   helpers carry no `test_` prefix, per testing.md Session Additions).
   - **`ColdAgentStubTest`** drives `cold_agent_stub.py` directly over a subprocess pipe:
     - `initialize` then `tools/list` returns exactly `list`, `read` and `press`;
     - `inc` ×3 reaches a count of 3;
     - each refusal cause (`not-found`, `disabled` on `dec` at 0, `not-pressable`, `malformed` for a missing `id`)
       comes back with `isError: true` and the count unchanged;
     - the call log holds one line per call, and no line holds an argument value;
     - stdout carries only JSON-RPC frames.
   - **`ColdAgentPipeTest`** runs `cold-agent.sh` in a temp root holding a copy of the two scripts. A `claude` shim is
     first on PATH, written by the test the way `test_agent_run.py:101-109` writes its cargo shim.
     - **The shim.** It records its argv and cwd. It reads `--mcp-config`, starts the configured stub command, and
       acts as a minimal MCP client: initialize, tools/list, then the `tools/call` sequence the test's scenario file
       lists. It then prints a stream-json transcript built from what the stub returned: a `system/init` with the
       stub's tools and the cwd it ran in, an `assistant` `tool_use` and a `user` `tool_result` per call, and a
       `result` event with fixed usage numbers. Scenario knobs let a test override `init` fields, add a non-stub
       `tool_use`, set `subtype`, or exit non-zero.
     - **Cases:**
       - pass (`inc` ×3: exit 0, outcome `passed`, `wrong_calls` 0, `final_count` 3);
       - wrong calls counted (unknown id, `dec` at 0, missing argument, then `inc` ×3: passed, `wrong_calls` 3,
         `transcript_errors` 3, `counts_agree` true);
       - task unmet (`inc` ×2: exit 1, `task-unmet`);
       - empty session (no calls, `result` success: exit 1, `no-tool-call`);
       - isolation breach, two cases (init `cwd` containing the repo root name, and an extra `Bash` tool: each exit 1,
         `not-isolated`);
       - client failure (non-zero shim exit: exit 1, `client-exit`);
       - a non-stub `tool_use` counted as a wrong call;
       - usage errors (no verb, unknown verb, `run` with no task, `run` with an unknown task: each exit 2 with empty
         stdout);
       - precondition (`claude` absent from PATH: exit 3);
       - `status` and `logs` before any run (exit 3);
       - the client argv carries `--tools ""`, `--strict-mcp-config`, `--setting-sources ""`,
         `--disable-slash-commands`, `--no-session-persistence` and `--max-budget-usd`;
       - the shim's recorded cwd is outside the temp root and no longer exists after the run;
       - events census (every stdout and `logs` line parses as one JSON object, none carries a scrub-set key, and a
         marker string the shim puts in a tool result never appears in any event or the verdict);
       - cleanup is idempotent, and a pre-made `target/agent-run/` sentinel survives it.
6. **The one live run — operator host, ONCE** (the `leg = 'operator'` entry in Test Commands, fired once by /implement
   and never re-run by the wrap). After `bash scripts/cold-agent.sh run counter` reads `passed`:
   - copy `target/cold-agent/{verdict.json,transcript.jsonl,calls.jsonl,events.jsonl}` into this chunk's `evidence/`
     as `live-verdict.json`, `live-transcript.jsonl`, `live-calls.jsonl` and `live-events.jsonl`;
   - record in `evidence/live-run.md` the command, exit, outcome, `wrong_calls`, `tool_calls`, the usage numbers
     (`input_tokens`, `output_tokens`, the two cache counts, `cost_usd`), `client_version`, `model` and wall-clock.
   The founder's budget ruling is that the run happens once and its token cost is recorded from the session's own
   usage report. A red live run is a finding, read from its own transcript. It is fixed and re-run only on the
   operator's word, never looped.

## Constraints & rejected approaches
- `claude --bare` — rejected: it authenticates only by `ANTHROPIC_API_KEY` or an `apiKeyHelper` (`claude --help`), and the host has an OAuth login with no key. Adding one is a credential path the operator ruled out at P4.
- A direct Messages-API driver loop — rejected at P4: it needs an API key and puts egress code in escher's own scripts.
- A stub CLI behind a Bash allowlist — rejected at P4: the session would hold a shell tool, which is not "only the
  tool".
- A fork-CI live job — rejected at P4: it would need the fork's first secret, against the `test_ci_workflows.py:151`
  pin, and an API key. CI runs only the shim tests.
- A new `agent-run.sh` verb — rejected: it would change the measured 14-test contract. arch §Standard Contracts → CI
  contracts says a separate script following the same grammar leaves that contract unchanged.
- An MCP SDK or any new dependency — rejected: the stub is stdlib python, and nothing enters `Cargo.lock` or a
  requirements file.
- Do not run the live session from the repository, the session scratchpad or any path naming the project: probe 1
  showed the cwd path reaching the session (research.md §Live probe).
- Do not take the outcome from the agent's reply: `final_count` is the stub's own state.
- Do not loop the live run. Once is the founder's budget. A red is read from its transcript and re-run only on the
  operator's word.
- Do not print the transcript, tool arguments, tool results or the final reply to stdout or into any event. The
  verdict carries counts and identities only.
