## Goal
The driver takes a screenshot with no display: the whole screen of the held instance, or one element by its stable id.
It is the eleventh verb of the one table, `screenshot`, served in process, on the command line and over MCP. The image
is a PNG of what blitz-paint paints, rasterised on the CPU (`VelloCpuImageRenderer`), the path the screenshot example and
the pixel tests already use (research.md, Files inspected). This is v010-07, and with the same pixels on a repeated run
on the same host, v010-08 (intent §4).

The founder ruled both forks of this chunk (`inputs#I1`, `inputs#I2`):
- **Fork 1, In-band.** The PNG travels base64 inside the one JSON answer on the socket and the command line's stdout, and
  over MCP as a native `image` content block. There is no new carrier, no new exit and no path argument. The
  1,048,576-byte answer bounds stay, and an image past them ends `oversize` / `AnswerTooLarge`.
- **Fork 2, Engine masks.** blitz-paint draws a password input's characters as U+2022 for every document, so a typed
  password never leaves as pixels and the windowed app stops painting it in the clear. The caret and selection follow
  the bullets.

The raster hangs off the held instance in `blitz-test-harness`, which owns the document. The intent names the gap
there: "the harness has no screenshot" (intent §4). The driver encodes the PNG and its base64 by hand, as it writes
every answer. "Fails, never skips, without fonts" becomes a typed refusal: an instance whose document has no usable
font is refused `fonts-unavailable` with nothing painted. The checks never skip; they assert that text paints (scope,
premise-corrected at P3).

2. **A reading of whether a document can paint text** — `packages/blitz-dom/src/document.rs`. Add a public, read-only
   method on `BaseDocument` answering whether its font context resolves at least one font family for the sans-serif
   generic. It reads the context's collection through fontique's `generic_families` (fontique 0.12.0, Cargo.lock:3319).
   It changes no state and no behaviour. On the stand's context it reads true. On a context built from bytes that do not
   decode as a font (`build_single_font_ctx` over 16 zero bytes, which registers no family, `packages/blitz-dom/src/lib.rs:143-156`)
   it reads false. Add a unit test of both readings.
3. **A password input paints masked** — `packages/blitz-paint/src/render.rs`, `draw_text_input_text` (render.rs:890-945).
   For an `input` whose `type` is `password`, paint one U+2022 per character of the editor's text, in the input's own
   text style, in place of the editor's layout. Paint the caret and the selection at the positions of the bullets that
   stand for the same characters. Every other input paints as today. The editor, the DOM value, the snapshot and the
   accessibility tree are untouched: the snapshot still reads `MASKED_VALUE`. This holds for every document and every
   renderer that goes through blitz-paint (founder fork 2, `inputs#I1`, `inputs#I2`). If the bullet layout needs state

## Constraints & rejected approaches
- A file written by the driver, or an `--out` path: rejected by the founder at fork 1 (`inputs#I1`). No path argument,
  no filesystem exit.
- Refusing a shot while a password holds a value: rejected by the founder at fork 2 (`inputs#I1`). The engine masks.
- The raster inside `escher-driver`: rejected. The harness owns the document, and the intent names the harness's gap.
  The driver keeps one new dependency, the encoder.
- A caller-supplied raster hook, as `with_time` supplies time: rejected. Painting is the engine's and is the same for
  every app, while time is the app's own.
- The `base64` crate, or `serde_json` writing the answer: rejected. The crate's answers are hand-written (security-plan
  §Input Validation, MCP server row).
- A span field for the image's size or dimensions: rejected. arch's driver-command-spans entry never fields the screen
  or its length, and a new field would need a ruling this chunk has not asked for.
- A host-font fallback, or a skip, when no font paints: rejected (test-plan §2; design-system §Typography).
- Moving the scrollbar fade onto the harness clock: out of scope. It is an engine change for every document that the
  founder has not been asked for. The limit is stated in the verb's help, and its owner is on the card.
- Pixel comparison across the CI matrix: not written (v010-08 is "the same host").
