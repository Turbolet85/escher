## Patterns detected
- **The library owns the surface; the binary hands over argv, app names and a boot** (`cli.rs:67-79`, `session_host.rs:23-43`): `escher-driver` names no app, installs no subscriber and reads no environment variable; the binary installs the sink before anything else.
- **A role word beside the verb table** (`cli.rs:32`, `:112-124`): `serve` is matched before `schema::verb`, takes a closed argv shape and falls to usage otherwise. A second role word is admitted the same way or ends as `unknown-verb`.
- **A span's parent is the span current when it is made** (`execute.rs:74`, `:111`): the `command` span is built with no `parent:` argument, which in `tracing` means its parent is the span entered on that thread at that moment. The equality the entry's third clause needs: a `command` span made inside `Session::run` while a tool-call span T is entered on the same thread has T as its parent. Read from the code and from `tracing`'s rule for a span macro without `parent:`; **not run** — the plan's first check runs it. The frame that produces the reading is a subscriber's `new_span`, which is handed the new span's attributes and reads the current span itself; the sink's lines cannot show it (`format.rs:162-173`).
- **One written form per answer** (`json.rs:208-306`): every answer of the driver is one line of JSON from this module, and its string writer leaves no raw line break — the property a newline-delimited protocol line needs.
- **`serde_json` is already compiled into the driver** — `cargo tree --locked -p escher-driver -e normal -i serde_json` reads `serde_json v1.0.151 ← dioxus-html v0.7.10 ← dioxus-native-dom`, and the same for `-p seven_guis` (through `dioxus-document` and `dioxus-html`). Naming it as a direct dependency adds no package to either graph; the lock gains one line in `escher-driver`'s own list. Its lock entry depends on `itoa`, `memchr`, `serde`, `serde_core`, `zmij` (`Cargo.lock`, the `serde_json` package block). `rmcp` is not in the lock (`grep -c '^name = "rmcp"' Cargo.lock` reads 0).
- **The pipe is bound to its stub** (`cold-agent.sh:92-110`): running the real server through it changes the tool set, the server name, the task list and what `final_count` is read from, each pinned by `.github/scripts/test_cold_agent.py` (27 tests).

## Conventions to follow
- **Private module, `//!` opening, public names re-exported at the root under `#![deny(missing_docs)]`** (`lib.rs:74-101`).
- **Unit tests inline, each table stated with its row count, an assertion over a call carrying a row index only** (the pattern of `cli.rs` and `wire.rs` test modules; test-plan §4).
- **A check that holds a process owns it**: the package's binary through `CARGO_BIN_EXE_escher-session`, bounded waits, a kill-and-reap guard, both streams drained from the spawn on, `cfg(unix)` where a session crosses processes (`common/mod.rs:30-51`; `examples/seven_guis/tests/host_log.rs`).
- **A stand check reads its expected ids and names from the stand itself or from the shared tables**, never from a hand-kept list; the shared tables of `tests/blitz-tests/tests/common/mod.rs` belong to that package and are not reachable from `examples/seven_guis/tests/`.
