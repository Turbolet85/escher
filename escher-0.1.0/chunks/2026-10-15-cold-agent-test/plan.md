## Goal
Prove the 0.1.0 thesis end to end: a fresh agent given only escher's own tool completes the stand's tasks and writes a
check that passes, its wrong calls counted (v010-15; intent §9). The cold-agent run pipe built on 2026-10-06 is swapped
from its toy stub to the driver's real MCP surface — the built `escher-session mcp` role, its eleven verbs as tools —
keeping the pipe's isolation check, wrong-call count and positive-evidence verdict (test-plan §3, Cold-agent run pipe;
arch §Standard Contracts, CI contracts). The second call count becomes the server's own `tool_call` span lines
(obs-plan §4), and completion is read from the tool's answers, never the agent's reply — both exactly as the 2026-10-11
live trial measured them (research.md, Patterns detected).

The founder shaped the run (inputs#I2, inputs#I3): ONE live run on the dev host under the operator's own login, at most
$3, with all four lean tasks — counter, flight booker, timer and CRUD — in that one session («Один запуск, до $3
(Рекомендую)», «Все четыре в одной сессии»); the agent's check is a JSON list of tool calls that the pipe replays on a
fresh session with no model («JSON-проверка с повтором (Рекомендую)»); `covered` on the zero-height
`task-header-spacer` is observed in the run and its decision deferred to 0.2.0 («Отложить на 0.2.0, наблюдать
(Рекомендую)»). The wrong-call count decides nothing — it is the baseline a 0.2.0 bar reads (the founder's ruling,
2026-10-06; `.andromeda/residuals.md:9`).

No engine, driver, schema, telemetry, harness or stand change: the change surface is `scripts/cold-agent.sh`, the
retired stub and the contract tests, plus the live run's evidence. No mutation runs (inputs#I1).

## Implementation Steps

1. **The task and the preconditions** (`scripts/cold-agent.sh`, the bash part). The task allowlist becomes the one
   task `stand` (`TASKS=(stand)`), the usage line naming it; `counter` is no longer a task. Usage stays checked first
   (exit 2, stdout empty, before any lookup). The preconditions, each exit 3 with one stderr line and no state written:
   `claude` on PATH, `python3` on PATH, and the built server `target/debug/escher-session` present and executable (its
   line names the build command `cargo build --locked -p seven_guis --bin escher-session`). The pipe builds nothing.

2. **The server, behind a stderr-capturing wrapper** (the embedded python's `config` verb). The per-run `mcp.json`
   names exactly one server, `escher`: `{"type": "stdio", "command": "sh", "args": ["-c", "exec env RUST_LOG=info
   \"$1\" mcp 2>\"$2\"", "sh", <absolute path of target/debug/escher-session>, <absolute path of
   target/cold-agent/server.log>]}` — the 2026-10-11 trial's form without its request `tee` (live-trial.py:138). The
   pipe itself reads no environment variable; `RUST_LOG` is set on the child only, the registered value its sink reads
   (arch §Occupied Resources, Environment variables).

3. **The client line.** From the per-run `mktemp -d` directory, stdin `/dev/null`, stdout → `transcript.jsonl`,
   stderr → `client.log`: `timeout 600 claude -p "$STAND_PROMPT" --output-format stream-json --verbose --tools ""
   --strict-mcp-config --mcp-config "$session/mcp.json" --allowedTools mcp__escher --setting-sources ""
   --disable-slash-commands --no-session-persistence --model claude-opus-5-5 --max-budget-usd 3` — the founder's cap
   and the model of the 2026-10-06 run (inputs#I2). A timeout or non-zero exit stays a `client-exit` failure, never a
   propagated 124.

4. **The fixed prompt** (`STAND_PROMPT`, a constant; nothing the operator passes reaches it). It names goals and no
   element id (security-plan §Input Validation, CLI arguments row). Its content, in this order:
   - use only the tools; the stand has four apps — counter, flight booker, timer, CRUD — one app session at a time,
     each stopped before the next is started;
   - the four goals: the counter's display reads 3; a return flight booked departing 24.12.2026 and returning
     31.12.2026; the timer's duration set to 10 seconds and time passed until the elapsed time reads 10.0s; in CRUD,
     the person Ada Lovelace added, Roman Tisch's surname changed to Tischler, and Hans Emil deleted;
   - before stopping each app, take a snapshot of its final screen;
   - finally, reply with the check as the LAST thing in the reply, one fenced ```json block: a JSON array of steps,
     each `{"tool": <a tool name without its server prefix>, "arguments": {…}, "expect": [texts]}` (`arguments` and
     `expect` optional), that redoes all four tasks from fresh sessions when run in order; each app's part ends with a
     `snapshot` step whose `expect` lists texts from that screen which prove the task is done.

5. **The verdict** (the embedded python's `verdict`). The stub-bound terms are restated; every field stays a count, a
   boolean or a closed word (obs-plan §6, the cold-agent pipe):
   - `isolated` — the init tools are exactly the eleven `mcp__escher__{verb}` for the verbs of `VERBS` (`snapshot`
     `click` `type` `press` `advance` `scroll` `screenshot` `start` `status` `stop` `help`), one MCP server `escher`
     `connected`, skills and slash commands empty, `apiKeySource` none, and neither the init cwd nor its memory paths
     naming the repository root;
   - `tool_calls` — the transcript's tool uses; `server_tool_calls` — the lines of `server.log` holding
     ` span="tool_call" ` (counted by span name, never raw lines — obs-plan §6); `refused_calls` · `error_calls` —
     those lines holding ` ending="refused" ` · ` ending="error" `;
   - `wrong_calls` = `refused_calls` + `error_calls` + tool uses naming a tool outside the escher server + the
     result's `permission_denials` — recorded, never deciding (test-plan §3, Verdict);
   - `counts_agree` — `server_tool_calls` equals the escher tool uses, and `refused_calls` + `error_calls` equals the
     escher tool results marked `is_error`;
   - `spacer_calls` — escher tool uses whose `id` argument is `task-header-spacer` (the founder's «Отложить на 0.2.0,
     наблюдать (Рекомендую)»: the observation the deferral's residuals line reads);
   - `tasks_met` — the app slugs whose done state reads in the text of the LAST `snapshot` tool result taken while
     that app was the one started (the app of the latest accepted `start` tool use), by the atoms of step 6;
   - `check_steps` · `check_expects` · `check_passed` · `check_can_fail` — step 7;
   - kept: `task`, `client_exit`, `session_tools`, `client_version`, `model`, `transcript_errors`, `num_turns`,
     `duration_ms`, `cost_usd`, the four token counts, `transcript_file`, `outcome`, `reasons`, `ts`; retired:
     `final_count`.
   `outcome` is `passed` only on positive evidence: client exit 0, a successful `result`, `isolated`, `counts_agree`,
   `tool_calls` ≥ 1, all four slugs in `tasks_met`, `check_passed` and `check_can_fail`. Otherwise `failed`, `reasons`
   from `client-exit` · `no-result` · `not-isolated` · `counts-disagree` · `no-tool-call` · `task-unmet` ·
   `no-check` · `check-failed` · `check-cannot-fail`.

6. **The done-state atoms** (a table in the embedded python, one row per app; recorded at P4 from real screens,
   research.md §Done-state screens). A row reads met when every `contains` text is in the snapshot text and no
   `lacks` text is:
   - `counter` — contains `Paragraph "3" id="counter-value"`;
   - `flight-booker` — contains `Paragraph "Booked return flight: 24.12.2026 → 31.12.2026" id="flight-booked"`;
   - `timer` — contains `Paragraph "Elapsed: 10.0s" id="timer-elapsed"` and `Unknown "10.0s" id="timer-duration-value"`;
   - `crud` — contains `ListBoxOption "Lovelace, Ada"` and `ListBoxOption "Tischler, Roman"`, lacks `id="crud-person-0"`.

7. **The check: extraction, validation, replay** (the embedded python; no model, no agent-written code run).
   - Extraction: the last fenced ```json block of the result's reply text; none, or more than 65,536 bytes, or not a
     JSON array → `no-check`. Written to `target/cold-agent/check.json` as parsed (`json.dump`), never printed.
   - Validation: at most 400 steps; each step an object with only `tool` (one of the eleven verbs), optional
     `arguments` (an object) and optional `expect` (a list of strings) — anything else → `check-failed` with nothing
     replayed.
   - Replay: the pipe spawns `target/debug/escher-session mcp` directly (stderr to `/dev/null`), speaks the handshake
     (`initialize`, `notifications/initialized`) and sends each step as a `tools/call`, every reply read under a 30 s
     bound (the shared `Speaker`'s `REPLY_BOUND`, test-plan §3 `session-checks`), the child killed and reaped at the end
     and on any failure. A step's answer text is the join of its result's text blocks. `check_passed` is true when no
     step's result is `isError`, every `expect` text is in its step's answer, the check holds at least one acting step
     (`click` `type` `press` `advance` `scroll`) and at least one expectation, and it starts all four apps.
   - Power to fail (no mutation — inputs#I1): the same check is replayed a second time, on a fresh child, with its
     acting steps left out; `check_can_fail` is true when, for each of the four apps, at least one `expect` text of a
     `snapshot` step taken while that app was started is absent from that second replay's answer.
   - `check_steps` and `check_expects` are the counts of steps and expectation texts.

8. **The stub retires.** `scripts/cold_agent_stub.py` is deleted; the pipe copies no stub into the session dir.

## Constraints & rejected approaches
- A task per app (`run counter` … `run crud`) — the founder chose all four in one session; a single `stand` task keeps
  the allowlist to what runs.
- Re-firing the live run on a failure, or a second live run — the founder's «Один запуск, до $3 (Рекомендую)»: the
  result stands as read.
- Reading completion or the check's truth from the agent's reply — the reply only carries the check; its truth is the
  replay, completion the tool's own `snapshot` answers (test-plan §3, Verdict).
- A Write tool, a shell flow or an agent-written script run on the host — the founder chose the replayable JSON check;
  the replay sends only tool calls the server validates.
- Rewording `covered`, or taking the spacer off the screen — deferred to 0.2.0 on the founder's word; no refusal text
  and no stand markup moves.
- A field added to `tool_call` or `command` for the count — obs-plan §4 holds both at their ratified fields.
- The stub kept as the contract tests' fake — the fake must speak the eleven tools and write span lines; the stub does
  neither.
- Any CI job, secret or upload for the live run — no CI secret exists and none is added (security-plan §Secret
  Management).
- A mutation control to show a check can fail — inputs#I1; the ablated replay and the shim cases show it instead.
