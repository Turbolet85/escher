## What this chunk builds
The **snapshot data model**: the screen of a booted stand task, read as a tree whose every node carries **id · role · name · state · bounds** (intent §Findings 2; requirements v010-04). It is the abstraction the rest of Epoch 3 and the driver rest on (intent §Principles, "the snapshot data model and its serialization → change tracking → …"): state fidelity (v010-05), compact serialization and its size budget (v010-04's "readable whole in one tool result"), and the diff (v010-06) all consume it.

- **Tree, not list** — the snapshot keeps parent/child structure, so a consumer can read the screen hierarchically (a form, its fields, its buttons). Verified feasible: the AccessKit `TreeUpdate` the snapshot reads carries each node's `children` in document order (accessibility.rs:12-36, 106 — research.md §Files inspected).
- **id** — each node's id is the stable element id already built (`DioxusDocument::element_id(s)`: author key → component path → document path; v010-01/02) and already carried as AccessKit `author_id` (dioxus_document.rs:289-304). The snapshot id must equal both for the same element — this chunk builds the snapshot leg of v010-03's three-way coherence (snapshot · accessibility node · driver); the driver leg is Epoch 4, so v010-03 cannot be claimed whole here. Verified (research.md §Files inspected; `matrix.py show --id v010-03` acceptance names the driver).
- **role and name** — the same role and accessible name the accessibility tree carries for the element, not a second derivation that could disagree. Verified: role is the node's AccessKit `role()`; the name is AccessKit's consumer-side model — the node's `label`, else the joined names of its `labelled_by` targets (a `TextRun`'s `value`, a bound `<label>`'s own name) — the resolution `stand_accessibility_ids.rs:100-114` already applies (research.md §Patterns detected).
- **state** — the node carries a state record with the fields intent §2 names: enabled, checked, value, focused. This chunk builds the field and fills it from the engine's current readers; the *fidelity* of each reading (disabled reads disabled, typed value reads back, password masked, the Dioxus `"false"` boolean-attribute pitfall) is the next entry's (Snapshot state fidelity, v010-05) and is not proven here. Verified — a reader exists for each: enabled ← the `DISABLED` state set from `disabled` presence on `can_be_disabled()` elements (element.rs:445-451, 476-478); checked ← `checkbox_input_checked()` (element.rs:588); value ← the form reader's rule, `text_input_data().editor.text()` else the `value` attribute (form.rs:316-319); focused ← the tree's `focus` (accessibility.rs:60). `[premise-corrected: the harness's focused() / BaseDocument::get_focussed_node_id falls back to the ROOT ELEMENT when nothing is focused (document.rs:616-618), so it is not a "focused" reading — the tree's focus (focus_node_id, else the window) is]`
- **bounds** — `[premise-corrected: each node carries the engine's getBoundingClientRect box — BaseDocument::get_client_bounding_rect, CSS px, VIEWPORT-relative (viewport scroll subtracted), snapped to 1/64 px (document.rs:2238-2256) — one coordinate space for every node, equal to document coordinates while the viewport is unscrolled (a fresh stand boot); not a "document/viewport-absolute" hybrid]`.
