## Goal
Build escher's **snapshot data model**: one call on a booted `DioxusDocument` returns the screen as a tree whose every
node carries the element's **stable id, role, accessible name, state (enabled · checked · value · focused) and bounds**
(intent §Findings 2; requirements v010-04). It is the in-process abstraction that state fidelity (v010-05), compact
serialization and its size budget (v010-04's second half), the post-action diff (v010-06) and the driver (Epoch 4)
rest on (intent §Principles, "the snapshot data model and its serialization → change tracking → …").

The model invents no new reading. Every field comes from a reader the engine already has
(research.md §Patterns detected — "One reader per fact"):
- **id and role** are the AccessKit node's `author_id` and `role()`. They come from `Document::accessibility_tree`,
  which `DioxusDocument` already overrides to carry each element's stable id (per architecture §Standard Contracts →
  Dioxus DOM bridge; a11y-plan §2 · §7).
- **name** is AccessKit's consumer-side name model over that same tree: the node's `label`, else the joined names of
  its `labelled_by` targets.
- **bounds** is the engine's `getBoundingClientRect` reader, `BaseDocument::get_client_bounding_rect`. It already
  unions the carried inline-fragment rects (scope.md CARRY, premise-corrected).
- **state** reads `disabled` presence, `checkbox_input_checked`, the form reader's value rule, and the tree's focus.

The snapshot is therefore coherent with the accessibility tree by construction, and its ids are the ids v010-03
will hold the driver to.

The code lands in dioxus-native-dom, the only crate where the stable id exists (per architecture §Standard Contracts
→ Dioxus DOM bridge). It goes in a new `snapshot` module behind the existing `accessibility` feature, because role
and name need AccessKit. blitz-dom, the harness, the stand and every manifest stay untouched (research.md §Files to
modify). The proof is a new headless stand check over the four lean tasks in both layout modes (per test-plan §2 ·
§3 · §5; a11y-plan §7).

## Implementation Steps
1. **Types** — in the new `packages/dioxus-native-dom/src/snapshot.rs`, define the public model. The whole module
   is under `#[cfg(feature = "accessibility")]`, and every public item carries `///` docs. All types derive `Debug`,
   `Clone` and `PartialEq`.
   - `Snapshot` holds the top-level nodes as `roots: Vec<SnapshotNode>`. In a stand document that is the single
     `/html:0` node. It offers a pre-order iterator over every node (`nodes()`) and a lookup by stable id
     (`get(&str) -> Option<&SnapshotNode>`).
   - `SnapshotNode` has these fields: `id: String` (the stable element id), `role: accesskit::Role`, `name: String`,
     `state: NodeState`, `bounds: blitz_dom::BoundingRect` and `children: Vec<SnapshotNode>`.
   - `NodeState` has these fields: `enabled: Option<bool>`, `checked: Option<bool>`, `value: Option<String>` and
     `focused: bool`.

   No field holds a `NodeId`, an AccessKit tree id, an `ElementId`, a `ScopeId` or a pointer
   (per security-plan §Input Validation, the `id` row; architecture §Standard Contracts → Dioxus DOM bridge).
2. **Node set and structure** — build from `self.accessibility_tree()`, the `DioxusDocument` override, so `author_id`
   is set. Walk from the tree's root (`TreeInfo.root`, the `Window`) down the `children` lists in order.
   - **Membership:** a tree node carrying an `author_id` becomes a snapshot node. Every other node (the `Window`, the
     document root, `TextRun`s) is not a node, and its kept descendants attach to the nearest kept ancestor.
   - **Order:** children keep the tree's order, which is document order (accessibility.rs:106).
   - **Inclusion rule:** every element the accessibility tree keeps becomes a node, generic containers included —
     the operator's P4 answer (Provenance). Elements the tree excludes (`display:none`, `visibility:hidden`, their
     subtrees, `<head>` among them per default.css:854) never appear. An `aria-hidden="true"` element the tree keeps
     marked hidden stays a node.
3. **id and role** — `id` is the node's `author_id`, carried verbatim. `role` is the node's `role()`.
4. **name** — the node's `label` when it is non-empty. Otherwise it is the names of its `labelled_by` targets joined in
   order, where a `TextRun` target contributes its `value` and any other target contributes its own resolved name.
   Then trim the result. The resolution follows the AccessKit model the existing oracle uses
   (stand_accessibility_ids.rs:100-114), never a second role or name mapping (per a11y-plan §2 Role derivation · §7
   Accessibility tree output). It is guarded against cycles (a visited set), so it always terminates and never
   panics. An element with no name source reads `""`.
5. **bounds** — each node resolves its live element with `BaseDocument::get_node(NodeId::from_u64(tree id))`, an
   `Option` and never an index (CLAUDE.md `NodeId` invariant; security-plan §Error Handling). Its bounds are
   `get_client_bounding_rect` of that element.
   - That rect is viewport-relative CSS px, snapped to 1/64 px. A non-atomic inline element gets the union of its
     line-box fragments (document.rs:2238-2256).
   - A node whose element no longer resolves is omitted, never a panic. It cannot occur on a consistent document,
     and step 9's checks prove none is lost on the stand.
   - The rect is reported as computed, with no clamping.
6. **state**:
   - `enabled` is `Some(!disabled-attribute-present)` for an element where `can_be_disabled()` is true (button ·
     input · select · textarea), and `None` otherwise. This is the presence reading that sets the `DISABLED` state,
     `:disabled` and click targeting (element.rs:445-451). It is named here per the a11y and arch extracts, and its
     fidelity is v010-05's.
   - `checked` is `checkbox_input_checked()`, which is `Some` for checkbox/radio inputs only.
   - `value` follows the form reader's rule (form.rs:316-319): `text_input_data().editor.text()`, else the `value`
     attribute. It applies to `input` elements whose `type` is not checkbox, radio, button, submit, reset or hidden,
     and to `textarea`. It is `None` for every other element.
   - `focused` is true exactly when the node's tree id equals the `TreeUpdate`'s `focus`, which is the document's
     focused node (accessibility.rs:60). It never uses `get_focussed_node_id`, which falls back to the root element
     (document.rs:616-618).
7. **Entry point** — an inherent `pub fn snapshot(&self) -> Snapshot` on `DioxusDocument`, in snapshot.rs or as a
   one-line delegate in dioxus_document.rs's inherent impl. The plan's file list is snapshot.rs, so the impl block
   lives in snapshot.rs. It is under `#[cfg(feature = "accessibility")]`, read-only (no mutation, no `DocumentMutator`),
   and adds no tracing call site (per obs-plan §2 · §8).
8. **Module wiring** — `packages/dioxus-native-dom/src/lib.rs` declares `mod snapshot`, gated by
   `#[cfg(feature = "accessibility")]`. It re-exports `Snapshot`, `SnapshotNode` and `NodeState` under the same gate,
   and adds an `accessibility` line naming the snapshot to the crate doc's feature list. `dioxus-native` re-exports
   them through its existing `pub use dioxus_native_dom::*` (packages/dioxus-native/src/lib.rs:27).
9. **Unit tests** — an inline `#[cfg(test)] mod tests` in snapshot.rs, built like the `element_id` unit tests: a
   `DioxusDocument` from a small plain app (per test-plan §3 · §4). It covers these cases:
   - an `aria-label`ed button reads that label as its name;
   - a `<label for>`-bound input reads the label's text;
   - a text-only `p` reads its text;
   - a `display:none` subtree is absent;
   - a disabled button reads `enabled: Some(false)`;
   - a checkbox reads `checked: Some(…)`;
   - a text input reads its value;
   - text runs are never nodes;
   - every id equals `element_id` of its element.
10. **Stand proof** — the new `tests/blitz-tests/tests/stand_snapshot.rs` opens with a `//!` doc. It boots every
    `LeanTask` through `seven_guis::stand::boot(task, stand::options(incremental))` for `incremental in [false, true]`,
    with no options literal, no font skip and no sleep (per test-plan §2 · §7 · §8). It has eight tests:
    - **every_node_carries_the_five_fields** — the node count is > 0; every id is non-empty; every rect is finite
      with width and height ≥ 0; the state record is present (per security-plan §Error Handling · §Input Validation
      "Layout values").
    - **ids_are_the_accessibility_tree_ids** — the snapshot's ids, in pre-order, are pairwise distinct and equal, as
      a set, the `author_id`s that `doc.accessibility_tree()` carries. Each id equals `DioxusDocument::element_id`
      of its element. No id contains a `NodeId`-derived token (per architecture §Standard Contracts → Dioxus DOM
      bridge; security-plan §Input Validation `id` row).
    - **role_and_name_match_the_accessibility_tree** — for every node, its role equals its AccessKit node's
      `role()` and its name equals that node's resolved name. The 15 stand controls carry their expected roles, and
      the six inputs carry the `INPUT_NAMES` names: Departure date, Return date, Duration:, Filter prefix:, Name:,
      Surname: (per a11y-plan §7).
    - **tree_follows_the_task_shell** — the root is `/html:0`. `task-shell` nests `task-header` (holding `back-btn`
      and `task-title`) and `task-body`, and `task-header`'s top is above `task-body`'s top. No node descends from
      `<head>`. The CRUD snapshot carries three row ids ending `div[0]`, `div[1]` and `div[2]` (per
      layout-templates §Surface: desktop-native → Primary screens).
    - **controls_lie_inside_the_viewport** — every author-id control and value display that the task renders at
      boot has non-zero width and height inside the 800×600 viewport. `flight-booked` is not rendered at boot, so
      it is excluded. Each rect equals `get_client_bounding_rect` of its element (per design-system §Surface:
      desktop-native §Tokens · §Typography Loading; test-plan §4 "Conditional assertions").
    - **state_reads_the_engine** — at boot, no node is focused. After `focus_next_node`, exactly one node is
      focused, and its id is `element_id` of the node `focus_next_node` returned (`back-btn`, document.rs:1644-1648 sets focus) (per a11y-plan §3 · §5). Flight
      booker reads `flight-return-date` `enabled: Some(false)` and `flight-start` `enabled: Some(true)`, with a
      `value` equal to its editor text. Every button reads `checked: None` and `value: None`.
    - **snapshot_is_deterministic** — two consecutive snapshots of one boot are equal, and the snapshots for
      `incremental` false and true are equal (per architecture §Design Philosophy "One incremental pipeline";
      test-plan §2 "Differential oracle").
    - **snapshot_follows_a_rerender** — after a counter increment, `counter-value`'s name reads `"1"`. After CRUD
      Create, a node with id ending `div[3]` appears under `crud-list`.

    The helpers carry `#[track_caller]`, the fixture condition is asserted first, and every bounds assertion is
    unconditional (per testing.md).

## Acceptance Criteria

  node's id equals its element's `element_id` and its AccessKit `author_id`. The snapshot's id set equals the tree's
  carried `author_id` set, and the ids are pairwise distinct. Proved by `cargo test -p blitz-tests --locked --test
  stand_snapshot` (ids_are_the_accessibility_tree_ids) (per architecture §Standard Contracts → Dioxus DOM bridge;
  a11y-plan §7).
- (a11y) Every node's role and name equal those of its AccessKit node. The 15 stand controls carry their HTML-AAM
  roles, and the six inputs carry their attribute-sourced names (role_and_name_match_the_accessibility_tree) (per
  a11y-plan §2 · §7).
- (layouts · design) The tree follows the TaskShell structure. Every control rendered at boot has a non-zero,
  finite rect inside the 800×600 viewport, equal to `get_client_bounding_rect` (tree_follows_the_task_shell ·
  controls_lie_inside_the_viewport) (per layout-templates §Surface: desktop-native → Primary screens; design-system
  §Surface: desktop-native §Tokens).

  The disabled `flight-return-date` reads `enabled: Some(false)`. `flight-start`'s `value` is its editor text

## Constraints & rejected approaches
- A snapshot module or type in blitz-dom was rejected. blitz-dom holds no stable id, and "snapshot" there already
  names Stylo's element-snapshot invalidation (17 symbols, research.md §Graph impact query 2).
- A second role or name derivation (re-mapping tags, or reading `aria-label` / `<label>` directly) was rejected. It
  could disagree with the accessibility tree (a11y-plan §2 · §7; arch extract anti-pattern).
- Pruning generic containers was rejected, per the operator's answer. The CRUD rows are generic `div`s the user
  clicks. Size trimming belongs to Compact snapshot serialization.
- `get_focussed_node_id` / `Harness::focused()` as the `focused` source was rejected. It reads the root element when
  nothing is focused (document.rs:616-618).
- `Harness::layout_rect_of` as the bounds source was rejected. It reads page coordinates unsnapped, while
  `get_client_bounding_rect` is the engine's one bounding-box reader that Dioxus `onmounted` and script already use
  (research.md §Graph impact).
- The chunk adds no tracing span, log, `println!` or "dump the snapshot" path. Spans belong to the driver (obs
  history, 2026-10-06-founder-rulings), and names and values are user content (obs-plan §8).
- No markup, class, id, wrapper or order is added to the stand tasks to serve the snapshot (layout-templates
  §Primary screens), and no manifest changes (a new dependency would be an audit and a review).
- Password masking, `select` values, the `hidden`/`"false"` boolean pitfall and fieldset-disabled inheritance are
  out of scope: state fidelity is v010-05's (the next entry). The model must not claim them.
