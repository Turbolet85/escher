How much of the vocabulary the set holds now is a fork for the operator. **Decided (the operator, 2026-10-07, at the P4 forks):** the core verbs now — `snapshot`, `click`, `type`, `press` and `advance` — in one table the later entries extend with their own verbs at their promotions.
- **Argument and result shapes** — each verb's arguments and its result have a stated shape.
- **The shapes must be readable as data, not only as Rust signatures**: later entries serve them — "uncoloured JSON on stdout" (working-route.md:71), "driver commands as MCP tools" (working-route.md:73), "verb list, help and schemas served by CLI and MCP from the one schema" (working-route.md:75). `escher-driver` depends on two crates today, `blitz-test-harness` and `dioxus-native-dom`, and on no serialization crate (`packages/escher-driver/Cargo.toml`). - **Malformed arguments refused** — a call the schema does not admit is refused with a named cause.
- **What "malformed" covers and what a refusal leaves behind**: an unknown verb, a missing, extra or ill-typed argument; a refused call changes nothing on the held instance. Two precedents exist in the repository and neither is this schema: the lifecycle wire's `RefusedMalformed` — "a request line over 64 bytes or outside the grammar is refused and changes nothing" (`.claude/rules/security.md` §Surfaces; `wire.rs:61-81`) — and the cold-agent stub, a toy counter whose causes are `not-found` · `disabled` · `not-pressable` · `malformed` (`scripts/cold_agent_stub.py:6`), pinned by nine rows of `.github/scripts/test_cold_agent.py:163-171`. Three of the stub's names have a counterpart here; `not-pressable` has none, and the stub refuses an unknown tool as `not-found`. Whether the stub is brought to the schema is the plan's.
- **Refusal causes, each with a remedy** — a closed set of causes; every cause carries a remedy.
- **The cause set**: the five intent §6 names — not found · stale · disabled · covered by another element · off-screen — and malformed. An instance that does not go quiet is today `SessionError::NotSettled(Busy)` (`packages/escher-driver/src/error.rs:35-36`), and `Session::act` does not roll its step back (`session.rs:66-67`): a step that ran and did not settle was not refused. Whether it is a cause is the plan's, read against that. **Amended at validation-1 (the plan surfaced two causes the entry does not list):** the set is eight — the six above, `unknown-verb` (a call naming no verb of the set, kept apart from malformed arguments so each has its own remedy) and `time-unavailable` (an app with no time seam refuses the time verb "with a named cause and a remedy" — the operator, 2026-10-07, at the P4 forks). Not settled is a result field, not a cause.
- **The remedy is a fixed text per cause.** `[premise-corrected: only one of the two precedents is a fixed text — actionable.rs:38-43 formats the tag and the id into its remedy]` The fixed-text precedent is `SessionError`: every message "is a fixed string: none carries a path, a label, an id or a value" (`error.rs:10`), pinned by a unit test that lists the variants by hand (`error.rs:78-96`). `UnkeyedActionable::remedy()` is the precedent for a remedy as a method on the typed value, not for its text being fixed. Whether a refusal also carries the id it was aimed at is the plan's; anything that does is returned to its caller only and is no log field (CLAUDE.md §Critical Warnings — "add no new user-content log fields").
- **Where the refusal type stands beside `SessionError`** — the lifecycle's one outcome type has twelve variants, each a lifecycle edge (`error.rs:12-37`); no site outside the crate matches it exhaustively (research.md §Graph impact). Whether a command's refusal joins that enum or is its own type is the plan's.

### The carried questions (the entry's one CARRY, from 2026-10-07-settle-detection)
- **The mechanism the CARRY states, verbatim:** "settle is built in process only (`Harness::settle`, `Session::act`): it advances no time and waits on no load — time on a held instance moves only when its caller delivers ticks, and a load in flight is reported at once as `NotSettled(Loads)`." Re-derived at HEAD: `settle` takes the harness's clock value once and reads no other (`packages/blitz-test-harness/src/settle.rs:152`), returns `NotSettled { busy: Busy::Loads }` at once for a load in flight (`settle.rs:164-171`), and `Session::act` maps a not-quiet instance to `SessionError::NotSettled(busy)` (`packages/escher-driver/src/session.rs:70-78`). One addition: a held instance has two clocks, both the caller's — the Timer's ticks (`TimerTicks::deliver`, `examples/seven_guis/src/tasks/timer.rs:20-26`) and the harness's animation clock (`Harness::tick`, `packages/blitz-test-harness/src/harness.rs:152-155`).
- **Question 1 — how an agent moves the Timer's time through a driver session.** The CARRY: "the session host holds the tick handle and delivers nothing, examples/seven_guis/src/session_host.rs:34-45". Re-read: the host binds `ticks` at line 35, stores the handle the Timer boot returns at line 39 and drops it after `serve` returns at line 45; nothing between delivers a tick. This chunk answers the question in the verb set — a verb, a host behaviour, or a recorded "not in this version" — and the answer is a fork for the operator, not a lean. Three constraints bear on it: intent §Out of this version lists "virtual time everywhere" (`escher-0.1.0/intent.md:77`); the tick handle is the stand's own seam, while `escher-driver` "names no app" (`lib.rs:4`); and the host cannot reach the handle while it serves — `serve` consumes the session and blocks in `accept` (`host.rs:48`, `:107-123`), so a host that delivers ticks needs a change inside the library or a step its caller hands the session. **Answered (the operator, 2026-10-07, at the P4 forks):** a verb the caller steps — and "the schema itself must say what one step is, so an agent learns the unit from the tool alone": a duration in milliseconds was weighed against a bare step count and taken, because a step's size is the app's and the library names no app. This chunk states the verb's shape; the wiring is "Act by id".
