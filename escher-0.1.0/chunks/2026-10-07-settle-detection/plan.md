## Goal
Give a held headless instance one call that runs every piece of work that is due now and then says, as a typed
value, whether anything is still outstanding — so a step taken through the driver's session returns with its
consequences already on the screen, and no check sleeps, waits or pumps on its own (intent §5; working-route.md:58).

Two layers, both additive. The harness gains `settle`: a bounded loop of the same poll-then-resolve pass `pump`
makes, which keeps poll's answer instead of dropping it (research.md §Patterns detected, "Poll's answer is the render
signal"), repeats while a pass still changed something, and ends in `Settled` or in `NotSettled` naming the busy
source class. The driver's session gains `act`: run a caller's step on the held instance, settle, return — the
entry point "Act by id" later addresses by stable id (per architecture §Standard Contracts → Driver session;
test-plan §3 Pump semantics).

"Settled" means **no work is due**. Render and layout are driven to quiet. A load in flight is reported, never
waited on — settle reads no clock, so it cannot wait for the outside world (per security-plan §API Security, "Request
timeout"). A source only time moves — a timer not yet due, a running animation — does not hold settle open and is
not advanced by it: time on a held instance moves when its caller moves it (per test-plan §5 Session ↔ held
instance; design-system §Motion, Animation runtime). No engine crate, no Dioxus-bridge file and no stand source is
edited (research.md §Files to modify).

## Implementation Steps
1. **Outcome types** — in the new `packages/blitz-test-harness/src/settle.rs`, define and document:
   - `Busy` — a `Copy + Eq + Debug` enum of the source classes that can hold an instance unsettled: `Render`,
     `Layout`, `Loads`. It names a class only — no node id, element id, name, URL or value (per architecture
     §Standard Contracts → Driver session; security-plan §Threat Model Summary).
   - `Settled { passes: u32, animating: bool }` — how many passes ran, and whether the document's animating reader
     (`BaseDocument::is_animating`, `document.rs:2039-2056`) read true when it returned.
   - `NotSettled { busy: Busy }` — with `Display` (one fixed string per class) and `std::error::Error`.
   - `SETTLE_PASS_LIMIT: u32 = 64` — a public constant; never an env read or an option (per security-plan §Secret
     Management, "Environment values read").
2. **The load counter** — in the same file, a private counting wrapper around a `NetProvider`: it forwards `fetch`
   and `is_noop` to the provider it wraps, counts a request in flight from `fetch` until its handler is consumed by
   `bytes` or dropped unanswered, and keeps a second, only-growing count of handlers finished. It stores counts and
   nothing else — no URL, no request. Every request the engine issues crosses this seam (research.md §Patterns
   detected, "Every request crosses one seam": 7 fetch sites, sweep `net_provider.fetch|network_provider.fetch` over
   `packages/blitz-dom/src`), four of which the document itself does not track.
3. **The harness carries the counter** — in `packages/blitz-test-harness/src/harness.rs`: `HarnessOptions::into_config`
   (`:43-60`) wraps a supplied provider that is not a no-op in the counter and hands the counter back beside the
   config; `Harness` gains one private field holding it (absent for a document built elsewhere and passed to
   `wrap`, and for an offline one); `from_html_with` and `from_vdom` (`:74-94`) store it. `pump`, `tick`,
   `dispatch`, `wrap`'s signature and every input helper stay as they are — `Harness::pump @ harness.rs:123` keeps
   its 44 callers untouched (research.md §Graph impact).
4. **`Harness::settle`** — in `settle.rs`, `pub fn settle(&mut self) -> Result<Settled, NotSettled>` on
   `impl<D: Document> Harness<D>`:
   - One **pass** is `doc.poll(None)` then `inner_mut().resolve(time)` — `pump`'s two calls, in its order, at the
     harness's own clock value. Around a pass it reads the hover node (`get_hover_node_id`, `document.rs:1951`) and
     the counter's finished count.
   - A pass is **quiet** when poll answered `false`, the hover node is the one it was before the pass, and the
     finished count did not move.
   - After a quiet pass: loads are outstanding when the counter has a request in flight or the document reads
     `has_pending_critical_resources()` (`document.rs:1264`) → `Err(NotSettled { busy: Loads })`; otherwise
     `Ok(Settled { passes, animating })`. It returns at once in both cases — it never spins on a load.
   - `SETTLE_PASS_LIMIT` passes with none quiet → `Err`, the class read off the last pass: `Render` when its poll
     answered `true`, else `Loads` when the finished count moved, else `Layout`.
   - It reads neither `has_changes` nor `take_changed_nodes`, logs nothing, and reads no clock but `self.time`.
5. **Exports** — `packages/blitz-test-harness/src/lib.rs`: declare the module, export `Busy`, `NotSettled`,
   `Settled`, `SETTLE_PASS_LIMIT`, and add settle to the crate doc's list beside the pump/tick line.
6. **Unit tests** — a `#[cfg(test)] mod tests` at the end of `settle.rs` (the crate's first; its path carries
   `settle`, which the gate's filter selects), in two groups.
   - *The counter*, over a hand-written inner provider that keeps the handlers it is given: a fetch reads one in
     flight; `bytes` on the wrapped handler reaches the inner handler with the same url and bytes and reads none in
     flight; a handler dropped unanswered reads none in flight; the finished count grows by one each time and never
     falls; `is_noop` is the inner provider's.
   - *The loop's arithmetic*, over a scripted `Document` — a wrapper around an empty `BaseDocument`
     (`BaseDocument::new`, `document.rs:376`) whose `poll` answers from a script and counts its calls: `false` at
     once is one pass; `true` k times then `false` is k + 1 passes; `true` for ever is `NotSettled { busy: Render }`
     after exactly `SETTLE_PASS_LIMIT` polls; a request still in flight after a quiet pass is `Loads` after exactly
     one poll; a handler that finishes inside a pass costs one more pass. The harness for these is built in-crate
     with a counter attached, which the private field allows.
   - Each `NotSettled` message is non-empty, differs per class and holds no `/`.
7. **The driver's outcome** — `packages/escher-driver/src/error.rs`: a twelfth variant `NotSettled(Busy)` — "the
