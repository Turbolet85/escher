## Patterns detected
- **Poll's answer is the render signal, and it is exact for "no work now"** (`dioxus_document.rs:267-276`): with nothing dirty and no task woken, `wait_for_work` is `Pending` and `poll` returns before rendering or delivering a `mounted` event. So a poll on an idle instance is inert, and "poll until it answers `false`" ends.
- **One pass is not always the last** — three places leave work behind: a `mounted` handler runs after the render inside `poll` (`dioxus_document.rs:283`) and anything it writes waits for the next poll; `resolve` returns unstyled while a head stylesheet is pending (`resolve.rs:60-62`); `refresh_hover` runs after damage is cleared and leaves its restyle "for the next resolve pass" (`resolve.rs:131-138`). The equality a settle loop needs: *a pass in which poll answered `false`, no load was answered and the hover node did not move leaves nothing a further pass would change* — the three writers above are the only ones found; the first and third are by code read, not measured.
- **Loads: the document sees three of seven request kinds** — sweep `net_provider.fetch|network_provider.fetch` over `packages/blitz-dom/src`: 7 sites — `mutator.rs:1156` (link stylesheet; tracked as critical only in the head), `mutator.rs:1216` and `layout/damage.rs:511` (images; `pending_images`), `iframe.rs:135` (iframe HTML; `iframe_loads`), `net.rs:225` (`@import`; untracked), `net.rs:503` (`@font-face`; untracked), `document.rs:1114` (stylesheet reload; untracked). A reader over the document's own collections would call an instance settled with a font or an import in flight.
- **Every request crosses one seam** — all seven sites call the document's `net_provider`, and each hands over a boxed handler that is consumed by `bytes` (`blitz-traits/src/net.rs:34-36`) and answers on the calling thread (`net.rs:116-125`). A provider wrapped at `HarnessOptions::into_config` (`harness.rs:44-59`) therefore sees every request issued and every handler answered or dropped, with no engine edit. The equality the loads leg needs: *handlers alive = requests in flight; an answered handler has already put its message on the channel when `bytes` returns, and the next `resolve` applies it* (`resolve.rs:49`).
- **An unanswered head stylesheet blocks layout for good** — a handler dropped without an answer sends nothing, so its id stays in `pending_critical_resources` and every later `resolve` returns early (`document.rs:1268-1269`; `resolve.rs:60-62`). Settle must read that as loads still busy, not as quiet.
- **Time-moved sources cannot be waited out without a clock** — `is_animating` (`document.rs:2039-2056`) is true for a canvas for as long as it exists, and its scrollbar-fade term reads the wall clock (`:1801-1806`); the only loop that waits on it sleeps (`fragment_navigation.rs:31-42`). The stand's styles have no transition, animation or keyframes (0 hits) but do have three scrollable regions (`app.rs:197` · `335`, `crud.rs:181`), so a scroll on the stand starts a wall-clock fade.
- **The stand's only delayed update is delivered ticks** — the Timer coroutine is the one asynchronous source on the four lean tasks, and one poll applies every delivered tick (`stand_timer.rs:41-45`: 151 ticks, one pump). By code read, an input helper's single pump after `deliver` therefore already shows the ticks; a settle check on the Timer is unlikely to be red before the fix. The case one pump does NOT cover has to come from a fixture (a `mounted` handler that writes state).
- **Time on a held session is pinned as caller-driven** — `timer_time_moves_only_with_delivered_ticks` (`stand_session_state.rs:132-169`) asserts a pump with no delivered tick leaves the time where it was.
