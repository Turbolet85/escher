  - **What settle does.** One PASS is `pump`'s two calls in its order — `doc.poll(None)`, then `inner_mut().resolve(time)` at the harness's own clock value — and settle keeps poll's answer, which `pump` drops. Around a pass it reads the hover node (`get_hover_node_id`) and the load counter's finished count. A pass is QUIET when poll answered `false`, the hover node is the one it was before the pass and the finished count did not move. After a quiet pass: a request in flight on the counter, or `has_pending_critical_resources()` true, returns `Err(NotSettled { busy: Loads })` at once; otherwise `Ok(Settled { passes, animating })`. `SETTLE_PASS_LIMIT` passes with none quiet returns `Err`, the class read off the last pass: `Render` when its poll answered `true`, else `Loads` when the finished count moved, else `Layout`.
  - **What "settled" means for the four sources the entry names.** Render and layout are driven to quiet. A load in flight is reported at once and never waited on — settle reads no clock but the harness's own, so it cannot wait for the outside world. A source only time moves — a timer not yet due, a running animation — does not hold settle open and is not advanced by it: time on a held instance moves when its caller moves it (`tick`, or the stand's `TimerTicks`). A running animation is reported through `Settled.animating`. Settle reads neither `has_changes` nor `take_changed_nodes`, logs nothing, starts no thread.
