## Goal
Make the fork's GitHub Actions pipeline run on escher's build branch and give fast feedback without rebuilding the
dependency graph on every push — the founder's concern ("надеюсь ci не будет все это каждый раз пересобирать",
inputs#I1). Today a push to `build/escher-0.1.0` triggers nothing (ci.yml:3-8; 0 runs on the fork), 7 of the
compiling jobs carry no cache, and the one cache that exists never saves off `main` (ci.yml:205) — so every
build-branch run would be fully cold; debuginfo is 82 % of a test binary's bytes (research.md §Measured facts).

The chunk adds the `build/**` trigger; a dependency cache on every compiling job whose save rule covers the build
branch; one workspace `[profile.dev] debug = "line-tables-only"` level shared by host and CI; a fast/slow split
(fmt · clippy · linux workspace test · CI-script tests first, the slower platform and build legs after them);
one leg script that both the workflow and the host run, so every linux leg is host-reproducible by construction;
a per-leg log uploaded on failure; and an upstream-only guard that keeps the signing, WPT, Pages and
upstream-dispatch jobs from firing on any fork ref (per architecture §Infrastructure Patterns → CI/CD,
§Occupied Resources → CI infrastructure; security-plan §Secret Management; test-plan §9 CI Integration;
obs-plan §9).

## Implementation notes
- GitHub's default linux `run:` shell is `bash -e` WITHOUT `pipefail`; the leg script sets its own
  `set -euo pipefail`, and the matrix step that pipes its output declares `shell: bash` (which GitHub runs with
  `-eo pipefail`) so a failing command is not masked by the pipe.
- `Swatinem/rust-cache` keys on the rustc version and the lockfile, so `build-msrv` (1.91) keeps a cache separate
  from the stable jobs by construction. GitHub's per-repository cache budget is 10 GB, evicting least-recently-used
  entries; the cold run creates one entry per compiling job (6 linux + 4 matrix = 10, counted from steps 4-5).
