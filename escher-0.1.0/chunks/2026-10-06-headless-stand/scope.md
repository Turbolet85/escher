## What this chunk builds
The stand gets a headless boot: a check can mount any of the four lean 7GUIs tasks (counter, flight booker, timer, CRUD; intent §Principles "the stand is the proof") inside the stand's own `TaskShell` chrome with no window and no GPU. It can then pump, read and drive the task through `blitz-test-harness`. intent §Principles places this right after "the as-built baseline green on this host and the fork's CI reached": every later capability (stable ids, snapshot, driver, screenshot, cold-agent test) is proven on this boot, so it is the abstraction they rest on.

- **Headless mount in TaskShell** — each of the four tasks can be built headlessly wrapped in the same `TaskShell` (header, back button, title, body) the windowed app shows. A check sees the real stand chrome, not a bare task component. Verified (research.md §Files inspected: `app.rs:6`, `:68`, `:146`): `app()` always starts on `Home`, and `TaskShell` and the `Task` enum are private to `app.rs`. An entry point that starts on a named task is needed, and the windowed app must render the same tree it does today. `app` has no caller beyond `main.rs` and the wasm entry (research.md §Graph impact).
- **No display** — the boot runs through `Harness` (`DioxusDocument`, no winit, no renderer, no `WAYLAND_DISPLAY`), so it runs on the CI runner and in an agent's shell.
- **Fixed viewport** — every check boots at one pinned viewport size, scale and colour scheme, named once and shared by every check, so layout is identical run to run. Verified (`harness.rs:23-33`): `HarnessOptions::default()` is 800×600 · scale 1 · light today. Whether that is the pinned value or a stand-specific one is a P4 decision.
- **Bundled fonts** — text shapes and measures with the stand's bundled `assets/DejaVuSans.woff2` (the font the wasm build already ships), not the host's system fonts. Layout is then the same on the dev host and the CI runner. Verified: `blitz-test-harness` enables `blitz-dom/system-fonts` and `HarnessOptions` has no font-context field (`harness.rs:12-21`). `DocumentConfig.font_ctx` exists (`config.rs:49`), and a supplied context replaces system-font discovery (`document.rs:370-376`). Supplying it headlessly is new harness or stand surface. `[premise-corrected: decode_font_bytes decompresses woff2 only under blitz-dom's woff feature (util.rs:22-37); cargo tree shows woff off for both -p blitz-tests and -p seven_guis]` The bundled `DejaVuSans.woff2` registers no face unless `woff` is on in the build that runs the check. That feature is unified on only by `cargo test --workspace`, through `blitz`, so the stand must enable `woff` itself. Otherwise text has no face and font-dependent assertions pass vacuously.
- **No live network** — the boot never reaches a network. A check uses no net provider, or one that refuses every fetch, so no stand check depends on or emits outbound traffic (security rules §Untrusted input: `blitz-net` has no timeout or size cap).
- **Fresh per check** — each check builds its own document from scratch. No state leaks between checks: no shared `VirtualDom`, no global signal, no reused harness, and check order does not matter.
- **The timer task is deterministic headlessly** — verified (`timer.rs`, `dioxus_document.rs:220-238`, `harness.rs` `tick`): the timer's `use_coroutine` ticks on `futures_timer::Delay`, 100 ms of real wall-clock time from its own timer thread. `Harness::pump` polls with a noop waker, and `Harness::tick` advances only the animation clock passed to `resolve`. No harness knob moves `elapsed`, so a deterministic elapsed advance needs a **stand-side** tick seam (the shape is a P4 fork). Settle detection proper (v010-10) is a later chunk and is out.
- **Proof checks** — at least one check per task boots it headlessly in TaskShell, reads its initial state, and drives one real interaction through the harness's input synthesis. Examples: the counter increments; the flight booker flags an invalid date; CRUD creates an entry; the timer's elapsed state moves. The checks run under the workspace test leg (`ci-leg.sh fast`).
