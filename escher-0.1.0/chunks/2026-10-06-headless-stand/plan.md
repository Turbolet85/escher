## Goal
The 7GUIs stand boots headless. A check calls one stand function to mount counter, flight booker, timer or CRUD inside
the stand's own `TaskShell` chrome. The boot uses no window and no GPU, one pinned viewport, the stand's bundled DejaVu
Sans and no network, and builds a fresh document per call. The check then drives the task through `blitz-test-harness`'s
input helpers. This is the boot every later 0.1.0 capability is proven on: stable ids, snapshot, settle, driver,
screenshot and the cold-agent test (intent §Principles, "infrastructure ahead of the queue"; arch §Design Philosophy
"Headless, measurable, testable").

Research grounded four design facts (research.md §Patterns detected):
- The stand is offline already, because a document with no net provider falls back to `DummyNetProvider`.
- Host fonts cannot leak once a font context is supplied, because `build_single_font_ctx` turns system fonts off.
- The bundled woff2 decodes only under blitz-dom's `woff` feature, which a package-alone build of the stand or its
  checks leaves off today. That would be the vacuous 0×0 trap the design and test plans warn of.
- The timer ticks on wall-clock time the harness cannot reach.

So this chunk adds a font context and an incremental switch to `HarnessOptions`, turns `woff` on for the stand, and
gives the timer a stand-side tick seam. The windowed app's behaviour stays unchanged.

     no `Delay` awaited.

## Constraints & rejected approaches
- `Harness::wrap` over a stand-built `DocumentConfig` — rejected: it duplicates `from_vdom`'s new → initial_build → pump sequence outside the harness. The next chunk would boot through two construction paths.
- A harness-side virtual clock for the timer — rejected: `Harness::tick` feeds only `resolve`'s animation time, and `futures_timer::Delay` runs on its own wall-clock thread (research.md §Patterns detected), so no harness knob reaches it.
- Deferring the timer's elapsed advance to Settle detection — rejected at the P4 fork (above).
- A refusing or recording net provider as the stand default — rejected: `None` already yields `DummyNetProvider` (document.rs:421-423). Recording is a check-local fake injected only in `stand_boot.rs`.
- `seven_guis = { default-features = false }` — impossible: `dioxus-native` compile-errors with no renderer (`dioxus_renderer.rs:27`).
- Do not change any element type, class, id or CSS value of the stand. Do not swap a button for a clickable div (a11y-plan §4; design-system §Color Palette seven_guis rows).
- Do not call `escher_telemetry::init` in a check or in the stand module. It is once per process (obs-plan §3).
- Do not add a `std::env::var` read for stand configuration (security-plan §Secret Management).

- `type_text` appends to the input's current text. The flight booker's start field holds a valid default date, so appending one non-digit invalidates it with no clearing step.
