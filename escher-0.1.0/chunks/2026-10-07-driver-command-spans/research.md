## Patterns detected
- **The sink prints nothing for a span as built** (`packages/escher-telemetry/src/lib.rs:123-126`; `tracing-subscriber-0.3.23/src/fmt/format/mod.rs:1767-1771`): the layer is built with no span-event setting and the default is `FmtSpan::NONE`. A span opened under `escher_driver` is created, entered and closed with no byte written.
- **A span's fields are outside the scrub as built** (`fmt_layer.rs:874-894`; `format.rs:128-155`): they are formatted by the layer's default field formatter into the span's extensions and `EscherFormat` never reads them. They are never printed, and never judged by `decide`. The equality the entry needs — a field of a command's span reaches the writer only after `decide(target, field)` has judged it — holds for no span today.
- **Two ways the record can reach the sink, both reachable from the code as read** — the P4 fork:
  - *The sink prints a closed span.* The layer's own close event (`fmt_layer.rs:978-1015`) already passes through `format_event` with the span's target and level, so the target allowlist applies to it unchanged (an outside target's span close writes nothing, `format.rs:136-138`). What is missing is the span's own fields: a field formatter of the sink's (`fmt_fields`) can write them with the content-named set redacted — it cannot see the target, so the target rule is applied where the line is printed, in `format_event`, which can find the closing span through its context. The close event also brings `time.busy` and `time.idle`, read by the sink's clock: a duration reaches the line with no clock read in the driver.
  - *The driver states the readings on one event inside the span.* An event under `escher_driver` is printed and judged today (`format.rs:148-153`, pinned by `telemetry_scrub.rs:35`, `:59`); the span itself then prints nothing and should carry no field, since a span field would sit outside `decide`. No duration is available without a clock read in the driver, which three recorded clauses forbid (security-plan §Input Validation "reads no clock"; §API Security, the settle row; test-plan §5).
- **What the settle wait can be read as, with no clock** (`settle.rs:32-46`, `:151-186`; `execute.rs:264`): whether the instance went quiet, the busy class when it did not (one of `BUSY_CLASSES`), and the pass count when it did (`Settled.passes` — the harness's own measure of the wait: an idle instance takes one pass, each pass that still changed something costs one more). A not-settled outcome carries no pass count. The pass count is dropped at `execute.rs:264` today, so `settled_step` returns it or the span reads it there.
- **The verb word is the table's, also on a refusal** (`schema.rs:293-295`): `verb(&call.verb)` yields the `'static` row of a known verb — so a `malformed` refusal of a known verb still has its table word — and `None` for an unknown one, which reads no verb. The caller's own bytes are never the field's value. Precedent for the absent verb: the cold-agent stub logs an unknown tool as `tool: null` (obs history, 2026-10-06-cold-agent-run-pipe).
- **A record below `warn` is invisible to an in-process install unless the process's `RUST_LOG` says otherwise** (`lib.rs:119`): the filter is read from the environment at install. The existing answer is the re-exec child with `RUST_LOG` set by the parent (`telemetry_drop.rs:18-22`); the child can install over a captured writer and assert in process, so the readings it compares (the diff a call returned, the cause it returned) never leave it.
- **A span with no subscriber costs nothing and writes nothing**: `tracing`'s macros consult the current dispatcher, and with none installed the call site is disabled. `stand_session_quiet`'s host (no sink) and every existing `stand_act_*` check (no subscriber) therefore read as before; `escher-session` installs the sink and runs no command (`session_host.rs:20`, `:37-49`), so `host_log`'s one line at `trace` is expected unchanged — to be re-measured, not assumed.
- **The lock gains an edge, not a package** (`Cargo.lock:3084-3089`, `:8526-8527`): `escher-driver`'s entry lists two dependencies; `tracing 0.1.44` is already locked for `escher-telemetry`. The diff is one line in that entry.
- **`#[instrument]` fields a function's arguments** (`tracing-attributes-0.1.31/src/lib.rs:99-100`): an argument that is not a `Value` is recorded with `fmt::Debug` unless skipped — on `run` that would be the `Call`. The span is built by hand.
- **The scroll diff claim, spot-checked** (`tests/blitz-tests/tests/stand_act_scroll.rs:118-121`, `:158`): the shifted bounds of a scrolled box are recorded in that check's comment and it reads the list's box before the scroll for that reason; that the scrolled box is among the changed nodes is asserted by no standing check (the check asserts the last row is among them, by `contains`). This chunk does not lean on it: the span reports the counts of the diff the call returned.

## Conventions to follow
- **Emit from the library, install from the caller**: `escher-driver` installs no subscriber; the two binaries do (`examples/seven_guis/src/main.rs:6`, `session_host.rs:20`), and a check installs its own (`telemetry_scrub.rs:28-31`).
- **Hand-written events with fixed words and dotted or plain fixed field names** (`packages/escher-telemetry/src/lib.rs:138`; `panic.rs` — the `tracing::event!` form for dotted names, `.claude/rules/observability.md` Session Additions).
- **Field names outside the content-named set and outside the argument names**: `CONTENT_FIELDS` (`format.rs:48-60`) redacts `url` · `href` · `src` · `html` · `text` · `value` · `attrs` · `path` · `request` · `error` · `panic.payload`; the argument names are `id` · `text` · `key` · `shift` · `ms`. Free names the readings can take: `verb`, `cause`, `settled`, `busy`, `passes`, `added`, `removed`, `changed`.
- **One test-target file per behaviour, `stand_` prefix, both layout modes, no sleep** (`.claude/rules/testing.md`; `scripts/agent-run.sh:182` selects `stand_*.rs`); a re-exec child is an `#[ignore]` test read through `.output()` so its libtest lines never reach the parent's stdout.
- **A check over a call prints a mode, a task and an index** (`stand_act_diff.rs:59-70`); a leak check reports a kind and a count (`host_log.rs:153-158`). With the sink installed the panic hook prints the raw message after the scrubbed event, so a message holds no id, name, value or typed text.
- **Unit tests inline at the end of the source file** (`format.rs:200-375`; `execute.rs:316-346`), a table stated in its test with its row count asserted.
- **Baselines the chunk re-measures** (test-plan history, 2026-10-07-refusal-detection; not re-run here): escher-driver 27 unit tests, escher-telemetry 10 (9 in `format.rs`), `run stand` 107 passed over 29 files, workspace 647 passed · 8 ignored over 153 result lines.
