## Goal
Every driver command leaves one span, and what that span says reaches a log only through escher's scrub. A
call handed to `Session::run` opens one span under the target `escher_driver`; the span carries, as its own
fields, which verb ran, how the settle wait went, how large the returned diff is and — for a refused call —
the cause's name (per obs-plan §4 Span / Trace Coverage). Each field is a fixed word or a number: nothing of
a call's arguments and nothing of an outcome's content is fielded (per security-plan §Input Validation;
architecture §Standard Contracts → Driver session).

As built the sink cannot show any of it: it prints events only, a span writes no line, and a span's fields
never pass the scrub (research.md §Patterns detected). So the chunk has a second half, decided at the P4
forks (`inputs#I1`): **escher's sink learns to print a closed span** — one line per closed span of an
admitted target, every field of it judged by the same `decide(target, field)` that judges an event's, with the
sink's own timing of the span. The driver therefore reads no clock, and every later escher span prints by the
same rule with no call site of its own (per obs-plan §8 PII Scrubbing & Compliance → Scrubbing; §6 Log
Coverage → Log format).

That second half admits a new record class to the sink — the playbook's "Boundary widening" pattern
(`.andromeda/playbook.md:36-38`). It is recorded **PROVISIONAL**: the answer that chose it is not the
founder's own word (`inputs#I1`), so it is listed for the founder's batch at the Epoch 4 boundary, which this
chunk's wrap closes, and named in the handoff.

The proof is a stand check: driver commands run on stand tasks with the real sink installed over a captured
writer; one line per command; each reading held against what the call returned; and none of the ids, names,
typed text or values the commands handled anywhere in what the sink wrote (per test-plan §5 → Session ↔ held
instance; §5 → Session host ↔ what it writes).

### 2. The span on `Session::run`
In `packages/escher-driver/src/execute.rs`, `Session::run` (`:82-141`) opens one span per call and holds it
entered from before `validate(call)` (`:83`) until `run` returns, so a refusal `validate` returns is inside
it. `run`'s signature and what it returns for any call are unchanged (`run @
tests/blitz-tests/tests/session_common/mod.rs:151`, `:194` and seven direct test call sites —
research.md §Graph impact — see no difference).

- **Identity:** target `escher_driver`, name `command`, level INFO.
- **Fields — exactly eight, their names stated once in the module as a private table:** `verb` · `cause` ·
  `settled` · `busy` · `passes` · `added` · `removed` · `changed`. A field that does not apply to a call is
  left unrecorded, so it does not print.
  - `verb` — the table's own word for the call's verb: the `name` of the row `schema::verb(&call.verb)`
    returns (`packages/escher-driver/src/schema.rs:293-295`). Unrecorded when the table has no such verb. The
    caller's own text is never the value.
  - `cause` — on a refusal, `Cause::name()` of the refusal `run` returns
    (`packages/escher-driver/src/refusal.rs:43`), recorded at one site for every `Err` whichever of the two
    sources returned it. Unrecorded on a call that ran.
  - `settled` — for an acting verb that ran (`click` · `type` · `press` · `advance` · `scroll`): whether
    the instance went quiet.
  - `busy` — when it did not: the class word, one of `BUSY_CLASSES`
    (`packages/escher-driver/src/schema.rs:30`), mapped from the `Busy` class by a private function of the
    module.
  - `passes` — when it did: `Settled.passes` (`packages/blitz-test-harness/src/settle.rs:32-39`), read where
    the settle's answer is read, `settled_step` (`execute.rs:257-267`, the one `harness.settle()` at `:264`,
    which keeps only the error half today). `Outcome` gains no field for it.
  - `added` · `removed` · `changed` — the lengths of the three lists of the diff the call returns.
  - `snapshot` records `verb` alone.
- **Nothing else is fielded:** not `in_view`, not `advanced_ms`, not the screen text or its length, not the
  session's label, not the record of ids or its size.
- **The span code reads only the call's verb and what the call returns.** It adds no snapshot, no settle, no
  pass and no dispatch; reads no document, no changed set and no clock; and puts nothing on `Session`.
- **Unit tests** in the module's `mod tests` (`execute.rs:316-346`), tables stated in the test with their row

### 4. The sink prints a closed span
In `packages/escher-telemetry/src/lib.rs` and `packages/escher-telemetry/src/format.rs`.

- **The layer.** The sink's one fmt layer (`lib.rs:123-126`) turns the span-close record on — close only: no
  line when a span is created, entered or exited — and takes a field formatter of the sink's own in place of
  the default. The layer's construction is stated once and used by `init_with_writer` and by the unit
  tests' scoped subscriber (`format.rs:285-296` builds its own copy today), so the tests exercise the layer
  the binaries install.
- **The line.** For a closed span whose target the allowlist admits: the same head an event's line has
  (`{time} {LEVEL} {target} service.name=… service.version=…`), then `span` = the span's name, then the
  span's own fields, then the close record's own fields (`message`, `time.busy`, `time.idle` — the two
  timings are read by the layer's clock, `tracing-subscriber-0.3.23/src/fmt/fmt_layer.rs:938`, `:962`,
  `:990`). Every `name=value` pair on it, the `span` pair included, is printed as `decide(target, name)`
  says (`format.rs:93-107`): the value, or `[redacted]`. A value is spelled as an event's is (`format.rs:164-198`).
- **An outside target's span writes nothing** — at creation, on a recorded value, on enter, on exit and on
  close — as an outside target's event does (`format.rs:136-138`).
- **The mechanism the line rests on.** The layer hands a span's fields to its field formatter without the
  span's target (`tracing-subscriber-0.3.23/src/fmt/format/mod.rs:235-244`), so the judgment by target is
  made where the line is printed, `format_event` (`format.rs:128-155`), which reaches the closing span's
  stored fields through its context — the route the stock formatter takes (`format/mod.rs:985-995`); the
  close record arrives there with the span's own metadata (`fmt_layer.rs:851-865`, `:978-1015`). Two
  consequences bind the stored form: it keeps each field's name separable from its value whatever the value
  holds (a space, an `=`, a line break), and a content-named field's value (`CONTENT_FIELDS`,
  `format.rs:48-60`) is replaced before it is stored — that redaction needs only the name.
- **Events are unchanged.** An event's line reads as it does today, including an event emitted inside a
  span: it gains no span name and no span field.
- **Unit tests** in `format.rs`'s `mod tests`, through the scoped subscriber: (a) an escher-target span
  closes into exactly one line holding `span=`, its printable fields and both timings, and nothing is
  written before it closes; (b) a content-named span field — one given at creation, one recorded later —
  prints `[redacted]` and its value is nowhere in the output, and a printable field whose value holds a
  space, an `=` and a line break stays one pair on one line; (c) an outside-target span with fields writes
  no byte; (d) an engine-target span prints only safe fields and redacts the rest, `span` included; (e) an
  event inside an escher span prints exactly what it prints outside one.
- **Docs.** The crate doc (`lib.rs:1-18`) and `EscherFormat`'s doc (`format.rs:109-112`) say one line per
  printed event and one per closed span. `packages/escher-telemetry/Cargo.toml` and `src/panic.rs` are not
  edited.

### 5. The stand check
New file `tests/blitz-tests/tests/stand_act_spans.rs`, opening with a `//!` doc naming the behaviour. It
declares `mod common;` and `mod session_common;` and keeps its capture writer in the file (the form of

**Form.** The sink's level filter is read from the process's `RUST_LOG` at install
(`packages/escher-telemetry/src/lib.rs:119`), and the span is INFO, below the default. So each reading is
made in a child: the test binary re-run on one `#[ignore]` test with `RUST_LOG` set or removed by its parent
(the form of `tests/blitz-tests/tests/telemetry_drop.rs:18-22`, not `cfg(unix)`-gated). The child installs
the real sink once over its capture (`escher_telemetry::init_with_writer`), drives the commands in both
layout modes and asserts in its own process; the parent reads it through `.output()` and asserts it
succeeded. Two parents, two children:

- **At `RUST_LOG=info` — the records.** In each layout mode the child drives, through
  `session_common`'s builders:
  - on **CRUD**: a `snapshot`; a `type` of the file's synthetic `SECRET` into `crud-name`; a `press` of a
    non-deleting key; twelve `click`s on `crud-create` (the count `stand_act_scroll.rs:24` uses), which put
    a row past the list box; a `click` on `crud-delete` while no row is selected, refused `disabled`; a
    `click` on the row past the list, refused `off-screen`; a `scroll` to it; a `click` on it, which
    selects it; a `click` on `crud-delete`, which removes it, then a `click` on the removed row's id,
    refused `stale`; a `click` on an id no screen read, refused `not-found`; a call whose verb is not in
    the table, refused `unknown-verb`; a `click` with no `id`, refused `malformed`; an `advance`, refused
    `time-unavailable` — in that order;
  - on **Timer** (held with its time step): an `advance` that moves time;
  - on **a minimal in-file fixture** booted with the stand's options — one button under one positioned
    overlay, the first pair of `stand_act_obstructed.rs:26-47`: a `click` refused `covered`, the case the
    stand lacks.

  For every call, by index: the capture grows by exactly one line; that line is at INFO under
  `escher_driver`, carries the service identity and `span` reading `command`; its `verb` is the table's word
  (absent for the unknown verb); and
  - a call that ran as an acting verb carries `settled`, with `passes` when settled, and `added` ·
    `removed` · `changed` equal to the list lengths of the diff the call returned — which the check first
    holds equal to its own `before.diff(&after)` (the form of `stand_act_diff.rs:54-66`) — and no `cause`;
  - a refused call carries `cause` equal to `Cause::name()` of the refusal it returned, and none of
    `settled` · `busy` · `passes` · `added` · `removed` · `changed`;
  - the `snapshot` carries none of those seven;
  - every line carries both timings, by presence only — no value of a timing is read or compared.

  All eight cause names are read back, each from its own refused call. Then, over the whole capture of
  that layout mode:
  - **field names** — every field name on every `escher_driver` line is one of `span` · the eight · `message`
    · `time.busy` · `time.idle`, and no value reads `[redacted]`;
  - **content** — zero occurrences of each needle: every stable id the driven screens read (from
    `element_ids` after the creates, so run-time `crud-person-…` ids are among them — the shared `rendered`
    table lists the boot screen only), every row's text and every label's text (the method of
    `examples/seven_guis/tests/host_log.rs:42-60`), the fixture's ids, and `SECRET`; the needle lists are
    asserted non-empty and the capture non-empty first, so a zero is not vacuous.
- **With `RUST_LOG` removed — the default level.** The child drives one `click` and one refused call on a
  stand task in each layout mode and the capture holds no `escher_driver` line; both calls return what they
  return with no sink.

**Rules of the file.** No sleep, no clock read, no pass or tick of its own; no deleting key. A failure
message carries a layout mode, a task and a call index, or a kind and a count — never an id, a name, a
value, typed text or a captured line: with the sink installed the panic hook prints the raw message after
the scrubbed event (`packages/escher-telemetry/src/panic.rs`). The children print nothing of their own, and
no test name holds an id.
