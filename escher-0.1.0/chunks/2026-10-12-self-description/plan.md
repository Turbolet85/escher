## Goal
The tool serves its own description, from the one table, on both surfaces: the verb list, each verb's help, the
argument and result shapes, a help per node key, the refusal causes with their remedies, the exit statuses with
their meanings, and the session errors with their remedies. This is v010-14's "help and schemas served by the tool
itself" (requirements.md:20).

Today the command line serves one usage line. MCP serves each verb's help and its argument schemas. Neither serves a
result field, a cause, an exit status or a session error (research.md, Files inspected). The table already holds
most of the text: every argument and every result field has its `help`, and every cause has its meaning and remedy
(schema.rs, refusal.rs). What it lacks is:
- a help per node key (CARRY 5);
- the exit statuses' meanings, which live only in a doc comment (cli.rs:60-71);
- a remedy per session error (CARRY 3).

One writer, `describe`, turns the table into one JSON document; the command line answers it to `escher-session help`
and the MCP server answers it to a `help` tool call. The table stays the one source (architecture §Standard Contracts
→ Driver session; security-plan §Error Handling).

The chunk also takes the measured costs of the first live agent trial:
- `state-dir-too-long` states its byte bound and every session error names a remedy (CARRY 3).
- A changed diff node names the keys whose reading differs (CARRY 4). At P3 all eight changed nodes of the flight
  booker's Book step had only moved.
- The server speaks `2025-11-25`, the revision the trial's client asked for (CARRY 6).

It runs the two owed checks that ride an MCP-touching chunk: a password typed through MCP reads the mask (CARRY 7),
and every cause the stand provokes is read with its remedy on its served form.

## Constraints & rejected approaches
- An MCP `outputSchema` per tool — rejected. The specification makes a server that declares one "MUST provide
  structured results that conform to this schema" (research.md, Platform issues consulted). That would put a
  `structuredContent` into every result, which the ratified result form excludes.
- Help text written in `cli.rs` or `mcp.rs` — banned. Every served text is read from the table (architecture §Standard
  Contracts → Driver session).
- Exposing `unkeyed_actionable` as a command — not built (founder fork 3A, `inputs#I3`; it would leave a `NodeId`
  behind).
- Answering `server/discover` or speaking `2026-07-28` — not built (founder fork 4A, `inputs#I3`). The current revision is
  stateless and drops `initialize`.
- Computing `differs` in the driver from two snapshots — rejected. `Snapshot::diff` is the one site that decides
  `changed`, and a second comparison could disagree with it.
- A per-verb `help --verb x` argument — not built. One document answers everything, and no argument means no new
  argument kind to validate.
- Any new span field, or a log line on `help` or on `initialize` — banned (obs-plan §4).
