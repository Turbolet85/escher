- **Five causes, named per action** — a driver action aimed at a target that cannot take it returns a `Refusal` whose `Cause` is the one that holds: `not-found` · `stale` · `disabled` · `covered` · `off-screen`.
- **Which actions** — the two verbs that name a target by id, `click` and `type` (`execute.rs:65-75`); `press` acts on what holds focus and `advance` names no element, so neither has a target to refuse on. ## Two decisions the entry reserves (asked at P4, with research's findings)
Both are stated by CARRY 2 as "Two decisions for this entry"; neither is leaned here.

1. **Telling `stale` from `not-found`.** The cause's stated meaning is "the id read an element earlier in this session and no element reads it now" (`refusal.rs:61-63`). CARRY 2's mechanism, kept verbatim: "telling `stale` from `not-found` needs the session to remember the ids it has read (it holds a label, the harness and an optional time step, and looks an id up anew on every call)". Re-read at the take-up: `Session` holds `label`, `harness` and `time` (`packages/escher-driver/src/session.rs:27-31`), and the lookup is made per call (`execute.rs:125-134`). What bears on it:

   - a standing check pins today's answer: the id of a row the driver has just deleted is refused `not-found` (`stand_act_refused.rs:19`, `:38`, `:69-76`); under `stale` detection that row's expectation changes;
   - what "read" means — an id a `snapshot` returned, an id a diff returned, an id an action was accepted on — and how long the memory lives, are part of the same decision.
   **Decided (the operator, 2026-10-07, at the P4 forks — `inputs#I2`): the session remembers ids.** The option chosen, as asked: the session records the id text of every screen it reads to answer a call (the snapshots `run` already takes); an id in that record that nothing reads now is `stale`, otherwise `not-found`; text ids only, never a `NodeId`, session lifetime, a stated cap. It re-opens the security `id` row and amends "the session keeps no id between calls"; `stand_act_refused`'s deleted row becomes `stale`.
2. **The `off-screen` remedy against a verb table with no scroll.** The remedy reads "the element is outside the viewport: bring it into view, then act again" (`refusal.rs:93-95`), and the table's five verbs are `snapshot` · `click` · `type` · `press` · `advance` (`schema.rs`).    - a sixth verb changes the one verb table three later entries carry as a CARRY ("one verb table", working-route.md:71 · 73 · 77) and every master that states "five verbs";
   - an action that scrolls its target into view by itself makes `off-screen` a cause no call can receive, while the requirement names it as one of five refusals;
   - "a cause's texts are reworded only with a recorded reason" (CARRY 2).
   **Decided (the founder's ruling, 2026-10-07, given by dialog in the overseer session and relayed by the overseer at the P4 forks — `inputs#I2`): a sixth verb `scroll` joins the table now.** In the relay's words it is "his own word for the widening of the verb table from five to six, so it is not provisional", and "The remedy of off-screen then names the verb" — the recorded reason for rewording that one text.
