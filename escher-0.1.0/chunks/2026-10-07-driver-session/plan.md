## Goal
Build the driver's first piece: a **session** — one process that boots one headless app instance and holds it while
commands arrive. Today every stand check builds a fresh document (`seven_guis::stand::boot`); nothing holds one across
calls, and nothing a second process could reach exists. The chunk has two homes (the P5 review, `inputs#I2`):

- **The library, `packages/escher-driver`** — app-agnostic. `Session` holds an instance its CALLER boots; `serve` hosts
  one `Session` for the life of a process; `start`, `attach` and `stop` are the lifecycle another process drives, each
  edge with one named, typed outcome (per architecture §Conventions → Error handling). It depends on the harness and on
  the Dioxus document type, and on no app: no `seven_guis`, no stand type.
- **The stand binding, in the stand's own crate** — a second binary of `examples/seven_guis`, `escher-session`, is the one
  place a lean task, the stand's boot and options and the timer's tick handle meet a `Session`. The app hosts its own
  session through the library, so the new dependency runs example → package, as every other edge of the workspace does.

`attach` crosses a process boundary, and the project had none to extend. **The founder chose the crossing** (2026-10-07,
`inputs#I1`): a std-only Unix-domain socket in an owner-only session state directory, with lifecycle messages only. No
id, accessible name or control value crosses it in this chunk; the snapshot text's first exit stays the Driver CLI
entry's question (security-plan §Input Validation, the `id` and masked-value rows; working-route.md:69). Windows has no
std local socket, so there the lifecycle returns a typed `Unsupported` in 0.1.0.

What the chunk proves, and where: the DOCUMENT's state held across commands is proven in process on a `Session` booted
through the stand (state, focus, ids, CRUD rows, timer time, and that a held instance reads as a fresh boot); the PROCESS
held across commands is proven over the socket by content-free facts (the same pid answers, its served count rises);
`stop` leaving nothing is an observed absence. "One headless stand instance" holds for everything a check boots. No
verb set, no settle, no act-by-id, no CLI JSON and no MCP tool is built here — those are the next entries'. No
capability of the matrix becomes fully verifiable; none is claimed.

2. **`src/session.rs` — the held instance.**
   `Session::start(label: &str, boot: impl FnOnce() -> Harness<DioxusDocument>) -> Result<Session, SessionError>`. The
   label is the caller's short name for what it boots; it is validated FIRST — 1 to 32 bytes of `a-z`, `0-9` and `-` —
   and a label outside that set returns `InvalidLabel` without `boot` being called. Then `boot` runs once, on the
   calling thread, and the session owns what it returned. It offers `label()`, `harness()` and `harness_mut()`. It holds
   no `NodeId`, sets no viewport, font or scheme, installs no subscriber, and neither reads nor drains the changed set.
   Dropping it ends the instance. Anything else the app must keep alive beside the instance (the stand's `TimerTicks`)
   stays the caller's to hold.
3. **`src/error.rs` — one outcome type.** `SessionError`, an enum with exactly these variants: `AlreadyRunning`,
   `NoSession`, `Dead`, `HostExited(Option<i32>)`, `Timeout`, `Protocol`, `InvalidLabel`, `StateDirTooLong`,
   `StateDirNotPrivate`, `Unsupported`, `Io(std::io::ErrorKind)`. It implements `Display` and `std::error::Error`; every
   message is a fixed string (the `Io` arm adds the kind's name) and none interpolates a path, a label, an id or a
   value.
4. **`src/wire.rs` — the lifecycle line protocol, crate-private.** One request line and one reply line per connection,
   ASCII, `\n`-terminated. Requests: `hello v1`, `stop v1`. Replies: `ok v1 pid={pid} label={label} served={n}` to
   `hello`; `ok v1 stopping` to `stop`; `refused version` to a known word with another version; `refused malformed` to
   anything else, a line over 64 bytes included. `{label}` is the session's own validated label; `{n}` is the number of
   requests the host answered before this one. The module is `pub(crate)`: it is this chunk's lifecycle plumbing, not
   the driver's command vocabulary.
5. **`src/host.rs` — `serve(state_dir: &Path, session: Session) -> Result<(), SessionError>`, `cfg(unix)`.** In order:
   (a) the state directory — create it with mode `0700` when absent (its parent must exist); when present, refuse with
   `StateDirNotPrivate` if its mode grants group or other any bit; (b) bind a `UnixListener` at
   `{state_dir}/session.sock` and set the socket file to `0600` — a path the platform refuses as too long is
   `StateDirTooLong`; on `AddrInUse`, connect once: answered → `AlreadyRunning`; `ConnectionRefused` → remove that one
   stale socket file and bind again; (c) serve connections one at a time on the calling thread, each with a 2 s read
   and write bound, answering per step 4 — a `refused` reply and a broken connection change nothing in the session;
   (d) on `stop`: reply, leave the loop, remove `session.sock`, then `remove_dir(state_dir)` — non-recursive, an error
   from it ignored. `serve` deletes nothing but that one socket file and that one empty directory. On non-unix targets
   `serve` exists and returns `Unsupported`.
6. **`src/client.rs` — the lifecycle another process drives.** `attach(state_dir) -> Result<Hello, SessionError>`: one
   connection, `hello v1`; no socket file → `NoSession`; `ConnectionRefused` → `Dead`; an unparsable reply → `Protocol`;
   `Hello { pid: u32, label: String, served: u64 }`. `stop(state_dir) -> Result<(), SessionError>`: `stop v1`, then
   poll until `state_dir` no longer exists, bounded at 5 s (`Timeout` past it); the same `NoSession` / `Dead` reading as
   `attach`. `start(state_dir, host: Command, ready: Duration) -> Result<Started, SessionError>`: first `attach` —
   answered → `AlreadyRunning`, with no process spawned; then spawn `host` exactly as the caller configured it, and poll
   `attach` every 25 ms until it answers (`Started { child, hello }`), the child has exited (`HostExited(code)`) or
   `ready` has passed (`Timeout`, after killing and reaping the child it spawned). `Dead` state does not block `start`:
   the host's own bind replaces the stale socket (step 5b). On non-unix targets all three return `Unsupported`.
7. **`src/lib.rs`.** A `//!` crate doc stating what the session is, that the caller supplies the boot, what crosses

   `stop`. `///` on every public item; internals `pub(crate)`. The doc names the listener type in `host.rs` only.

## Constraints & rejected approaches
- A library that depends on `seven_guis`, re-exports `LeanTask` or names `TimerTicks` — rejected at the P5 review
  (`inputs#I2`): it inverts the workspace layering and welds the driver to one app.
- Stdio-child-only and library-only sessions — rejected by the founder's choice (`inputs#I1`): separate CLI invocations
  must reach one held instance.
- A TCP or UDP loopback port — rejected: a network listener needs an auth surface the version rules out
  (security-history `2026-10-06-founder-rulings`).
- A third-party IPC, named-pipe, pid-file or daemonizing crate to cover windows — rejected: std only, no new audit
  surface; windows reads `Unsupported` in 0.1.0.
- No request beyond `hello` and `stop`, and no reply field beyond pid, label and served count: nothing of the screen
  crosses the socket. The label is a caller-chosen name from a closed character set, never text read from the
  document. The first command that carries an id, a name, a value, snapshot text or a diff is another entry's, asked of
  the operator then.
- `serve` never deletes recursively and never deletes a path it was not given: one socket file, one empty directory.
- No env var is read and no default state location exists in the library; the binary takes its state dir as argv.
- No idle expiry: a session lives until `stop` or its process dies (lean 4, kept by the review; the owed answer is the
  route pin under Implementation notes).
- No edit to the stand's sources (`app.rs`, `lib.rs`, `main.rs`, `stand.rs`, `tasks/`, `assets/`), to
  `packages/blitz-test-harness`, any engine crate, `scripts/`, `.github/` or an existing check.
- No `tracing` dependency, span or event in the library; it is silent, and the binary's only output is its own stderr
  error line and what `escher_telemetry::init` prints.
- No `dioxus-native-dom` feature named by the library in this chunk: it reads no snapshot, and a feature named there
  would reach the windowed stand binary's own build through the stand crate's new dependency.
- No call to `has_changes` or `take_changed_nodes`: the changed-set contract is PROVISIONAL and a held headless
  instance is not its caller; what a settled command does with the set is the Settle detection entry's.
- No panic, `expect` or assertion message that interpolates a state path, an id, a name or a value.
- The wire names and the binary's exit codes are this chunk's plumbing: the Command and refusal schema entry and the
  Driver CLI entry own the driver's vocabulary, its JSON and its accepted/refused exit grammar, and may replace both.

## Implementation notes
- **Path length.** A Unix socket path is bounded (108 bytes on Linux, 104 on macOS — `sun_path`): keep each check's
  state dir name short (the workspace `target/tmp/` prefix is 44 bytes on this host, `pwd` + `/target/tmp`), and the
  library names the refusal `StateDirTooLong` rather than a raw I/O error.
- **A test's cwd is its package** (`tests/blitz-tests/`, `examples/seven_guis/`): every state dir in a check is built
  from `env!("CARGO_TARGET_TMPDIR")`, never from a relative path. A parent and its re-executed child derive the same
  directory from the same constant — libtest takes no extra argument and the chunk sets no env var for it.
