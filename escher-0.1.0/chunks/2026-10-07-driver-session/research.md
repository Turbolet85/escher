## Patterns detected
- **The instance is single-threaded for life** (`dioxus_document.rs:70`, `timer.rs:10`): the document and the tick handle are both `Rc`-based, so `Harness<DioxusDocument>` is neither `Send` nor `Sync`. Whatever thread boots the instance serves every command on it; a session takes one command at a time by construction, not by a lock.
- **The re-exec child IS a process the test controls** (`telemetry_stdout_silent.rs:10-13`, `stand_id_persistence.rs:291-298`): a blitz-tests file starts a second process by re-running its own test binary on one `#[ignore]` child. A child whose body is the session's host loop is the session process, driven from the same file. This is the only way a blitz-tests check can own a session process: `CARGO_BIN_EXE_{name}` is set only for integration tests of the package that defines the binary, and no file in the tree uses it (`grep -rn -E "CARGO_BIN_EXE|CARGO_TARGET_TMPDIR" --include=*.rs --include=*.toml packages apps examples tests wpt` → 0).
- **A test's working directory is its package** — `cargo test` runs a test binary with cwd at the package root (`tests/blitz-tests/`), not the workspace root. A session state area addressed relative to cwd would land under `tests/blitz-tests/target/` in a check and under `target/` from the repository root. The state location is therefore a parameter of the session's entry points, and a check passes a per-test directory (`env!("CARGO_TARGET_TMPDIR")`, set for integration tests at compile time).
- **No crossing exists to extend** — `grep -rn -E "UnixListener|UnixStream|TcpListener|TcpStream|named_pipe|mkfifo|process_group|setsid" --include=*.rs packages apps examples tests wpt` → 0 hits. The two registered crossings are the cold-agent pipe's stdio-only child (arch :148) and the two test re-execs (same line). An `attach` from a second process is new in kind.
- **What std gives without a dependency** — `std::os::unix::net::{UnixListener, UnixStream}` and `std::os::unix::process::CommandExt` exist on every unix target the matrix builds (linux, macos, ios, android) and not on windows; std has no local-socket or named-pipe type for windows. A cross-process `attach` built on std is unix-only and compiles on windows only behind `cfg(unix)`, with a typed "unsupported" outcome on the other side. No crate in our own code gates on `cfg(unix)` / `cfg(windows)` today (`grep -rn -E "cfg\((unix|windows|target_family)" --include=*.rs packages/escher-telemetry packages/blitz-test-harness examples/seven_guis tests/blitz-tests packages/dioxus-native-dom` → 0).
- **The changed set is nobody's on a held headless instance** — the one drain is `View::poll` (`packages/blitz-shell/src/window.rs:376`); `Harness::pump` drains nothing (`harness.rs:123-126`); the snapshot, its text and its diff never read it (`grep -c -E "changed_nodes|has_changes|take_changed" snapshot.rs snapshot_diff.rs snapshot_text.rs` → 0 · 0 · 0). An undrained set on a held instance grows by node id and distorts no snapshot reading. `stand_diff.rs:101-103` is the only non-shell reader.

- **Where the stand's manifest is cited** (read after the P5 review, `inputs#I2`) — the seven masters cite `examples/seven_guis/Cargo.toml` at lines 2, 4, 8-10, 25-27 and 29-34 (architecture), 22 and 31 (a11y-plan), 31 (design-system) and 31 (test-plan) — a `re.findall` of `examples/seven_guis/Cargo\.toml:[0-9]+(-[0-9]+)?` over `.andromeda/*.md`; the file has 42 lines and its native-target block is 29-34. A dependency added as that block's last line and a `[[bin]]` table appended at the file's end move no cited line. The crate has no `tests/` directory, no second binary and no `autobins` / `autotests` / `[dev-dependencies]` key (`ls examples/seven_guis`; `grep -n -E "autobins|autotests|\[dev-dependencies\]"` → 0); `main.rs:4-13` is the house form for a binary of this crate (a native `main`, an empty wasm `main`). An integration test of this package sees its normal dependencies and `CARGO_BIN_EXE_{its own binary}`.

## Conventions to follow
- **Escher-owned crate shape** (`packages/escher-telemetry/Cargo.toml:1-16`): `publish = false`, every package field `*.workspace = true`, every dependency `{ workspace = true }`; a workspace member line (root `Cargo.toml:2-30`) and a `[workspace.dependencies]` path entry beside `Cargo.toml:59-61`.
- **Telemetry install belongs to a binary's `main`, never to a library path** (`examples/seven_guis/src/main.rs:6-8`; obs-plan §3 Logging stack): a session driven in-process by a check installs nothing; a second install in one process is `AlreadyInstalled`, not an error.
- **One behaviour per integration file, `//!` header, `mod common;`** (`tests/blitz-tests/tests/common/mod.rs:1-4`; `.claude/rules/testing.md`); a `stand_`-prefixed file joins `run stand` with no script change (`.claude/rules/verification-harness.md`).
- **Both layout modes where layout, bounds or a snapshot is asserted** (`for incremental in [false, true]`; `common::boot(task, incremental)`, `common/mod.rs:99`).
- **Typed outcomes, no panic on an input path** (`packages/escher-telemetry/src/lib.rs:58-70` — `InitOutcome` / `InitError` is the house form for a lifecycle with named edges).
