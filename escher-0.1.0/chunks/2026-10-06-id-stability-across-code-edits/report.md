  - **The id grammar changed** (basis `packages/dioxus-native-dom/src/element_id.rs@75f12a09`, `element_ids` 159-195 and `place_children` 198-242; no signature changed — `DioxusDocument::element_id` / `element_ids` and the crate-private `element_id::{element_id, element_ids}` keep their shapes, and all 13 + 19 call sites are untouched). An element's id is now, in order of precedence, one of FOUR tiers:
    1. the **author key** — unchanged: the HTML `id`, verbatim, when non-empty, `/`-free and the first in document pre-order to claim it;
    2. the **anchored path** (NEW) — for an element under an element of its own component instance that reads an author key: `{key}//{segment}`, then `/{segment}` per further DOM level (`box//p:0/b:0`). The nearest such keyed element anchors. Mechanism: when an element reads its author key, `element_ids` passes `{key}/` instead of the element's own path as the base its children extend (element_id.rs:181-187), so a child that continues its parent's path reads `{key}/` + `/{segment}`; a segment is still `{tag}[{key}]` for a template root of a Dioxus-keyed VNode, else `{tag}:{n}`;
    3. the **component path** — unchanged in form. A template root owned by ANOTHER component instance still restarts at that component's chain (element_id.rs:231-234), so the anchor acts inside one component only: `div#slot { Item {} }` leaves Item's root at `Item/b:0`, and `TaskShell/Counter/div:0` is unchanged under the keyed `main#task-body`;
    4. the **document path** — unchanged.
    An `id` that fails the author-key predicate (empty, `/`-bearing, a later duplicate) anchors nothing. The skeleton's `main` reads its key and anchors nothing in a Dioxus app, because its children are template roots of another owner.
    Uniqueness argument, now three-way: an author key holds no `/`; an anchored path is the only id holding `//` — a component path is a chain of non-empty names and non-empty segments, and a document or app-root path starts with one `/` and has no empty segment after it; so no id of one tier equals an id of another. A key spelled like a component name stays distinct: `div#Item { b {} }` beside `Item {}` reads `Item//b:0` and `Item/b:0` (unit test `a_key_spelled_like_a_component_stays_distinct`). Ids stay computed on demand, written to neither tree, and free of `NodeId`, `ElementId`, `ScopeId` and pointers. Ratified by the founder at /andromeda-phase (inputs I1 · I2): both rules, the `key//segment` spelling, and the one-component reach.
