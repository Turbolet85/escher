## Goal

v010-04 ("readable whole in one tool result"). `Snapshot::to_text()` turns the model built by
`DioxusDocument::snapshot` into one compact text: one line per node, nested by indent, each line carrying the
node's role, name, id, state and bounds (per architecture §Standard Contracts → Dioxus DOM bridge; a11y-plan §7

## Implementation Steps
1. **The serializer** — new module `packages/dioxus-native-dom/src/snapshot_text.rs`, opening with a `//!` doc.
   It adds one inherent method, `Snapshot::to_text(&self) -> String`, a pure function of the `Snapshot`: no document
   access, no failure path, no panic on any content, no log or print. It walks the roots and their children
   depth-first in the stored order — the order `Snapshot::nodes()` yields — and writes exactly one line per node,
   each ended by `\n`; a snapshot with no roots is the empty string. The line, left to right:
   - indent: two spaces per depth (a root is depth 0);
   - role: the model's `role` in its `Debug` spelling (`Button`, `TextInput`, `GenericContainer`) — no table;
   - one space, then the name as a quoted string: `"`, the name through `str::escape_debug`, `"` — `""` when empty;
   - ` id=` and the id quoted the same way;
   - state, each token preceded by one space, in this fixed order, a token absent when the model holds nothing
     for it: `enabled` / `disabled` for `enabled` `Some(true)` / `Some(false)`; `checked` / `unchecked` for
     `checked` `Some(true)` / `Some(false)`; `value=` and the value quoted the same way for `Some(v)` (so
     `Some("")` writes `value=""`); `focused` when `focused` is true;
   - ` @{x},{y} {width}x{height}`: the four bounds numbers, each written with `f64`'s `Display` (`8`, `12.5`,
     `12.515625`, `-4`).
   Every value comes from the `SnapshotNode` it is given; nothing is read from a control. There is no `Display`
   impl and no second entry point.
2. **The budget** — in the same module, `pub const SNAPSHOT_TEXT_BUDGET: usize = 10_000;` with a `///` doc that
   states the unit (bytes of `to_text`'s result) and the rationale: the agent client warns above 10,000 tokens,
   caps a tool result at 25,000 tokens and saves one over 50,000 characters to a file; a text of N bytes holds at
   most N characters and at most N tokens, so a text inside the budget is inside all three whatever the tokenizer.
   `to_text` never truncates or pages — the budget is a ceiling a caller compares against, not a behaviour.
   `to_text`'s own doc states the line grammar and shows a small example in a `text` fence (a synthetic snapshot,
   not compiled as a doc-test).
3. **The crate root** — `packages/dioxus-native-dom/src/lib.rs`: declare `mod snapshot_text;` under
   `#[cfg(feature = "accessibility")]` directly after `mod snapshot;`, re-export `SNAPSHOT_TEXT_BUDGET` under the
   same gate directly after the `pub use snapshot::…` line, and name the text form in the `accessibility` line of
   the feature-flag doc (:7-9).
4. **The file-input mask** — `packages/dioxus-native-dom/src/snapshot.rs`, in `value` (:184-208): an `input` whose
   `type` is `file` (compared ASCII-case-insensitively, as `password` is at :193) is masked exactly as a password
   is — a non-empty value reads `MASKED_VALUE`, an empty or absent one reads as it does today. Reword the two doc
   comments that state the mask (`MASKED_VALUE`, :11-12; `NodeState::value`, :55-57) to name both types. No field
   is added and no type changes.
5. **Unit tests** — one in `snapshot.rs`'s `mod tests`: `a_file_input_reads_a_masked_value` (an input authored
   with `type: "file"` and a synthetic path as `value` reads `Some(MASKED_VALUE)`; the path occurs in no id, name
   or value of any node; a file input with no `value` reads `None`). Seven in `snapshot_text.rs`'s own
   `#[cfg(test)] mod tests`, the first six over hand-built `Snapshot` values with inline expected literals:
   `a_node_writes_role_name_id_and_bounds` · `state_tokens_follow_the_model` (each token, the fixed order, and one
   node that is both `disabled` and `focused`) · `children_are_indented_in_pre_order` (two roots, three depths) ·
   `strings_are_quoted_and_escaped` (a quote, a backslash, a line break and a tab in a name, an id and a value stay
   on one line; an id holding `/`, `//`, `:`, `[`, `]` and a space is written whole; `MASKED_VALUE` passes
   unchanged; `Some("")` writes `value=""`) · `bounds_print_the_shortest_decimal` (an integral, a 1/64 multiple, a
   negative) · `an_empty_snapshot_is_the_empty_text` · and `the_text_of_a_document_has_one_line_per_node` (a
   document built with the unit helper of snapshot.rs:216-221, copied into this module: line count equals
   `nodes().count()`, two calls are equal).
6. **The stand check** — new file `tests/blitz-tests/tests/stand_snapshot_text.rs`, opening with a `//!` doc,
   booting through `stand::boot(task, stand::options(incremental))` for every `LeanTask::ALL` in both layout
   modes. Six tests:
   - `every_node_is_one_line_with_its_five_fields` — the text has as many lines as the snapshot has nodes; the
     i-th line belongs to the i-th node of `nodes()`: it is indented two spaces per the node's depth, opens with
     the node's role spelling, and holds the node's quoted name, `id=` with its quoted id, and the bounds token
     built from `node.bounds`; every id occurs on exactly one line; each author id `stand_snapshot`'s `rendered`
     list names for the task (stand_snapshot.rs:61-98 — copied into this file, since one test file imports nothing
     from another) is among them, and CRUD's three `crud-person-{0,1,2}` lines sit deeper than, and after,
     `crud-list`'s.
   - `state_reads_as_the_model_holds_it` — at boot no line holds the `focused` token; on the flight booker
     `flight-return-date`'s line holds `disabled`, `flight-start`'s holds `enabled` and `value=` with the fixture's
     date; after `press(Key::Tab)` on a fresh boot exactly one line holds `focused` and it is `back-btn`'s; after a
     click on `counter-increment` the `counter-value` line's name reads `"1"`.
   - `the_text_is_deterministic` — two calls on one document, the two layout modes, and a second boot of the same
     task each give the same text.
   - `every_screen_fits_the_budget` — each screen's byte length is at most its recorded ceiling (an in-file table,
     one entry per lean task) and each ceiling is at most `SNAPSHOT_TEXT_BUDGET`; CRUD after one click on
     `crud-create` is longer than at boot and still inside the budget. The failure message names the task, the
     mode, the measured length and the ceiling — numbers only.
   - `a_masked_password_stays_masked_in_the_text` — on an in-file fixture (a labelled password input, booted with
     the stand's options) an empty password's line holds `value=""`; after a click and `type_text` of a synthetic
     literal the line holds `value=` with `MASKED_VALUE` quoted, and the literal occurs nowhere in the text.
   - `a_masked_file_input_stays_masked_in_the_text` — on an in-file fixture whose file input is authored with a
     synthetic path as `value`, its line holds the quoted mask and the path occurs nowhere in the text.
   The crossing rule binds this file: the serialized text is bound only to variables whose names start `text`, no
   format string interpolates one, the file uses `assert!` with an authored message throughout and never
   `assert_eq!` / `assert_ne!` (both print their operands), and it prints nothing.
7. **The size record** — before the ceilings are written, run the budget test once with every ceiling at `0` and
   read each screen's length from the failure messages (numbers only); record the readings, per task and mode, in

   larger of its two readings rounded down to a multiple of 256, plus 512, and re-run green. The red run is also
   the control that the assertion bites.

## Implementation notes
- **Mechanisms, with their producing frames.** The order: `to_text` descends `roots` then each `children` in
  stored order, the same sequence `Snapshot::nodes()` produces (snapshot.rs:64-71), so line i is node i. The
  escaping: `str::escape_debug` escapes `"`, `\`, line breaks, tabs and other control characters and leaves
  printable non-ASCII as is — `MASKED_VALUE`'s eight U+2022 (snapshot.rs:13) pass unchanged, 24 bytes. The role:
  `accesskit::Role` derives `Debug` on a fieldless enum (accesskit-0.25.0 `src/lib.rs:47`, `:62`), so `{:?}` is the
  variant name. The numbers: bounds are snapped to 1/64 px (packages/blitz-dom/src/document.rs:2733-2735), and
  `f64`'s `Display` prints the shortest text that round-trips — `8` for `8.0`. The file mask: an input with
  `type="file"` enters the `"input"` arm of `value` as value-bearing (snapshot.rs:188-192 excludes six other
  types), gets no text editor (packages/blitz-dom/src/layout/construct.rs:451 gives one to `text | password |
  email | number | search | tel | url` and to no type), so `text_input_data` is `None` and the `value` attribute is
  returned (snapshot.rs:200-203) — the return step 4 masks at :204-207. The budget: a token spans at least one
  byte and a character at least one byte, so `len() <= 10_000` bounds both counts. Control for the two std
  behaviours (measured on rustc 1.99.0, a session scratch program, 2026-10-06): a string holding two U+2022, a
  quote, a backslash, a line break and a tab prints through `escape_debug` as `"•• a\"b\\c\nd\te"` on one line;

  bytes.
