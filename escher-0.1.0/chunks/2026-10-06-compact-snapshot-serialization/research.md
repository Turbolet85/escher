## Patterns detected
- **One line per node, indented by depth** (packages/blitz-test-harness/src/inspect.rs:117-131): the harness's `dom_string` already serializes a tree this way, text escaped with `{:?}`. A snapshot text in that shape needs no dependency.
- **String escaping is needed and std supplies it** (snapshot.rs:33, :57; element_id history): an author key is any non-empty `/`-free string, a name is parsed text (trimmed, inner whitespace kept), a `textarea`'s value can hold a line break. `str`'s `Debug` form (`{:?}`) quotes the string and escapes `"`, `\`, line breaks and control characters while leaving printable non-ASCII — the mask's U+2022 included — as is; a quoted field can therefore never read as a second field or line.
- **Role spelling without a second mapping** (accesskit-0.25.0 `src/lib.rs:62`): `Role` offers only `Debug`; writing `{:?}` (`Button`, `TextInput`, `GenericContainer`) is a one-to-one rewrite of the model's value with no table in the serializer. It ties the spelling to the accesskit pin — the same pin the model's `role` field already exposes.
- **The size is small against every limit** (estimate, not a measurement): the lean tasks declare 5 · 11 · 12 · 18 rsx elements (`grep -c -E '^\s*[a-z][a-z0-9]*\s*\{' examples/seven_guis/src/tasks/{counter,flight_booker,timer,crud}.rs`), the shell and skeleton add about eight nodes, and CRUD renders three rows — roughly 13 to 30 nodes a screen. At about 100 bytes a line that is 1.5–3 KB a screen, against 50,000 characters and 10,000 tokens. The real figures are measured by the check, not carried from here.
- **File-input reach** (snapshot.rs:184-208; pointer.rs:768-777): `type="file"` is not among the six excluded input types, so the reader returns the `value` attribute, which the click branch fills with a host path. The feature is off for `cargo test -p blitz-tests` and on under `cargo test --workspace` (`cargo tree --locked --offline --workspace -e features -i blitz-dom` lists `blitz-dom feature "file-input"` under `feature "default" (command-line)`; the `-p blitz-tests` tree has no such line). No headless run yields a path (the default dialog returns no file); an authored `value` on a file input is read as written under either build — the equality a fix is provable on: `input { r#type: "file", value: "/x/y.txt" }` reads `Some("/x/y.txt")` today.
- **Stand checks print nothing** (`grep -n -E 'println!|eprintln!|dbg!' tests/blitz-tests/tests/stand_*.rs packages/dioxus-native-dom/src/snapshot.rs` → 2 hits, both `stand_id_persistence.rs:315, :318`, the registered re-exec child): a check that prints a serialized screen would be the second exception to obs-plan §3's headless-stand bullet.
- **Assertion messages are an exit** (stand_snapshot.rs:109, snapshot.rs:227): the existing helpers already format ids — and, in the unit helper, a whole `{snapshot:#?}` — into panic messages; a failing `assert_eq!` on two serialized texts prints both into `target/agent-run/run.log` and, in CI, the per-leg failure log artifact.

## Conventions to follow
- **Unit tests inline, at the end of the source file** (snapshot.rs:210-221): `#[cfg(test)] mod tests` with the `build` helper; a sibling module carries its own copy of the helper or builds `Snapshot` values by hand — the serializer is a pure function of a `Snapshot`, so most cases need no document at all.
- **Stand check shape** (stand_snapshot.rs:1-5, :100-110, :156-178): a `//!` doc naming the behaviour, `boot(task, incremental)`, `#[track_caller]` helpers, the fixture's own condition asserted first, both layout modes.
- **Public items documented, constants with their rationale** (snapshot.rs:11-13): `MASKED_VALUE` is the precedent for a public re-exported constant; `ci-leg.sh doc` runs rustdoc `-D warnings`.
- **MSRV 1.91 std only** (Cargo.toml:41): the host compiles on a newer stable; the `msrv` CI leg is outside `ci-leg.sh fast`.
- **No platform-bound key in a stand check** (.claude/rules/testing.md, Session Additions): typed characters and clicks only.
