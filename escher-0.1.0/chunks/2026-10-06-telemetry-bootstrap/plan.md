## Goal
escher gets one telemetry bootstrap, a new library crate `escher-telemetry`, that every escher binary installs at
start. The stand (`seven_guis_native`) adopts it in this chunk. The driver CLI and MCP server adopt it when their
entries land. One init call installs a global `tracing` subscriber with these properties:
- it writes to **stderr, never stdout**, since stdout is reserved for the driver CLI's JSON and MCP's stdio;
- every line it writes carries the binary's **service identity** (`service.name` / `service.version`);
- a **panic hook** logs each panic as a `tracing` error event and then chains the previous hook;
- the **scrub** is an allowlist applied in the formatter. Events from engine targets keep only their level, target,
  location and known non-content fields, and content-named fields of any target are redacted.

This discharges obs-plan §3 Bootstrap phases `pii-scrubbing-wire` and security-plan §Bootstrap phases
`logging-redaction-wire`, and replaces the per-app stdout `fmt::init()` pattern for escher's own binaries (per
obs-plan §3 Logging stack, §7 Panic hooks, §8 PII Scrubbing; security-plan §Logging & Monitoring, §Error Handling).

**The working entry's "opt-in OTel export" is DEFERRED** (overseer, under the founder's standing delegation of
technical forks, 2026-10-06; scope.md). The exporter would add outbound egress, and it reads
`OTEL_EXPORTER_OTLP_HEADERS` unconditionally (opentelemetry-otlp 0.33.0 `exporter/http/mod.rs:293-297`, research.md).
That is a boundary widening (playbook "Boundary widening", verdict escalate), so it reaches the founder before it
ships. This chunk adds **no** OTel crate, no network egress and no credential path. `otel-sdk-install` rides a route
CARRY to "Driver command spans" (§Implementation notes). The identity keys are the OTel resource keys, so a later
exporter reuses them unchanged.

     - add `escher-telemetry = { path = "./packages/escher-telemetry" }` to `[workspace.dependencies]` beside
       `blitz-test-harness` (Cargo.toml:58), per architecture §Conventions → Manifests;
     - if `tracing-log` is a direct dependency, add a `tracing-log = "0.2"` entry to `[workspace.dependencies]`;
     - run `cargo update -p escher-telemetry --offline` or a plain build, so `Cargo.lock` records the path crate and
       nothing else changes (no registry version moves).
   - `src/lib.rs` carries `//!` crate docs, `///` on every public item, and `#![deny(missing_docs)]`. The `doc` leg
     denies warnings over every library crate.
2. **Service identity** (`src/lib.rs`):
   - a `ServiceIdentity { name: &'static str, version: &'static str }`;
   - a declarative macro `escher_telemetry::service_identity!()` expanding to
     `ServiceIdentity { name: env!("CARGO_PKG_NAME"), version: env!("CARGO_PKG_VERSION") }`. It expands in the
     CALLER's crate, so the values come from the binary's own manifest and are never hand-typed.
3. **Init API** (`src/lib.rs`):
   - `pub fn init(identity: ServiceIdentity) -> Result<InitOutcome, InitError>` installs the default sink, stderr.
   - `pub fn init_with_writer<W>(identity, writer: W) -> Result<InitOutcome, InitError>` takes a
     `tracing_subscriber::fmt::MakeWriter` for tests, or a caller that names a file it opened.
   - Both build a `Registry` with:
     - an `EnvFilter` from `RUST_LOG`, defaulting to `warn` when unset or unparsable;
     - one `fmt` layer using the formatter of step 5, `with_ansi(false)`, and the given writer.

     They call `set_global_default`, install `tracing_log::LogTracer` so `log`-facade records (e.g. `js_console`)
     reach the same scrubbed formatter, and install the panic hook of step 4.
   - Idempotence: a process-wide `OnceLock<ServiceIdentity>` records the first successful init.
     - A second call returns `Ok(InitOutcome::AlreadyInstalled)` without touching the subscriber or the hook.
     - A call that finds a global subscriber someone ELSE installed returns
       `Err(InitError::ForeignSubscriber)`.
     - `InitError` is an enum with `Display` and `std::error::Error`, per architecture §Conventions → Error
       handling, and never panics.
   - The first line written after a successful init is an `info` event at target `escher_telemetry` that reports
     the identity. It carries no argv, no path and no URL.
4. **Panic hook** (`src/panic.rs`):
   - `install()` takes the previous hook with `std::panic::take_hook()` and sets a new hook that:
     1. emits ONE `tracing::error!` event at target `escher_telemetry::panic`, with fields `panic.file`,
        `panic.line`, `panic.column` (from `PanicHookInfo::location`) and `panic.payload` (the `&str`/`String`
        payload, the shape `wpt/runner/src/panic_backtrace.rs:22-28` reads);
     2. then calls the previous hook with the same info.
   - The default hook's stderr output and the process exit code are unchanged.
   - `panic.payload` is a content field (step 5), so the sink shows its redaction marker. The chained default hook
     still prints the raw message to stderr: that is std's own output, not a log event.
   - Installed once, inside the idempotent init.
5. **Formatter and allowlist scrub** (`src/format.rs`):
   - A `FormatEvent` implementation writes one line per event: `{RFC 3339 UTC time} {LEVEL} {target}
     service.name={name} service.version={version} {fields}`.
   - A field visitor decides per field:
     - **(a) Engine target.** The event's target, or its `log.target` for a bridged `log` record, starts with one of
       the engine prefixes: `blitz`, `dioxus_native`, `stylo_taffy`, `accesskit_xplat`, `debug_timer`,
       `js_console`. Then only fields in the safe set print their value: `node_id`, `status`, `waiting_nodes`,
       `property`, `log.module_path`, `log.file`, `log.line`. Every other field, `message` included, prints as
       `{name}=[redacted]`.
     - **(b) Content field of any target.** For any target, a field whose name is in the content set prints as
       `{name}=[redacted]`. The content set: `url`, `href`, `src`, `html`, `text`, `value`, `attrs`, `path`,
       `request`, `error`, `panic.payload`.
     - **(c) Everything else** prints normally.
   - The two sets and the prefix list are `pub const` slices with `///` docs, so a reviewer reads them in one
     place. Their derivation is research.md §Patterns detected (the named-field sites) and obs-plan §8 "Values
     logged as-is".
6. **Stand adoption:**
   - `examples/seven_guis/Cargo.toml`: add `escher-telemetry = { workspace = true }` under the existing
     `[target.'cfg(not(target_arch = "wasm32"))'.dependencies]`.
   - `examples/seven_guis/src/main.rs`: inside the native `main`, BEFORE `dioxus_native::launch` (the one call site
     of `launch @ examples/seven_guis/src/main.rs:6` this chunk touches — research.md §Graph impact), call
     `escher_telemetry::init(escher_telemetry::service_identity!())`.

       stand.

       `--ignored --exact child_emits --nocapture`. The child `#[test] #[ignore] fn child_emits` calls `init` with
       the stderr sink and emits a `warn!` carrying the sentinel in an escher-owned target's non-content field. The
       parent asserts that the child exited 0, that its stderr contains the sentinel and
       `service.name=blitz-tests`, and that its stdout does NOT contain the sentinel. libtest's own harness lines
       are on stdout, so the assertion is "the sentinel is absent from stdout", not "stdout is empty".
     - `telemetry_scrub.rs` — `init_with_writer` with an in-memory `MakeWriter` (a hand-written recording writer,
       test-plan §8 pattern). It emits:
       - an event at target `blitz_dom::mutator` whose message interpolates the sentinel;
       - an event at target `blitz_net` with `url = sentinel` and `status = 404`;
       - an event at an escher target with `html = sentinel`;
       - a `log::debug!(target: "js_console", …)` record carrying the sentinel.

       It asserts that the captured output contains none of the sentinels, contains `[redacted]` for each, and
       still contains `status=404`. The filter is `RUST_LOG` unset → `warn`, so the test emits at `warn` or above;
       the `js_console` record is emitted at `warn` for the test.
     - `telemetry_panic_hook.rs` — install a sentinel previous hook first, which sets a static `AtomicBool`, then
       `init_with_writer` with a recording writer, then `std::panic::catch_unwind` around a `panic!("{sentinel}")`.
       It asserts:
       - exactly one captured line at target `escher_telemetry::panic`, with `panic.file` and `panic.line`
         present;
       - `panic.payload=[redacted]`, and the sentinel absent from the captured output;
       - the `AtomicBool` set, so the previous hook ran.
     - `telemetry_init_idempotent.rs` — the first `init_with_writer` returns `Ok(Installed)` and the second returns
       `Ok(AlreadyInstalled)`; neither panics. After the second call, an emitted event appears exactly once in the
       capture (no doubled subscriber).
8. **Unit tests** inline in `#[cfg(test)] mod tests` (architecture §Conventions → Tests):

## Implementation notes
- `set_global_default` succeeds once per process. That is why each process-global behaviour is its own test binary, and why `init` tells "ours, already installed" (`OnceLock`) apart from "someone else's" (`ForeignSubscriber`).
- `LogTracer::init()` also fails if a `log` logger is already set. Treat that like the subscriber case: `ForeignSubscriber` only when our `OnceLock` is unset.
- Panic payload shapes: `&'static str` for literal panics, `String` for formatted ones (`wpt/runner/src/panic_backtrace.rs:25-26`).
- Bridged `log` records arrive with the callsite target `log`; the real target travels in the `log.target` field. Step 5's engine-target test must therefore read `NormalizeEvent::normalized_metadata()` (or the `log.target` field), never `event.metadata().target()` alone. Measured in tracing-log 0.2.0 `src/lib.rs:173-187` (dispatch with the level callsite's metadata and `keys.target` = `record.target()`) and `:469-476` (`normalized_metadata` rebuilds the metadata from those fields). A payload of any other type prints `panic.payload=[redacted]` all the same.
- **Stdout reach outside the subscriber.** `Node::print_tree` and `debug_log_node` write with `println!` (obs-plan §6). In the stand they are reachable only from blitz-shell's devtools keyboard shortcuts (Alt+T prints the taffy tree, `packages/blitz-shell/src/window.rs:652-686`, architecture §Occupied Resources → Keyboard shortcuts). The bootstrap governs only the subscriber's writer. Stdout cleanliness for the driver is the "Driver CLI" entry's own acceptance ("uncoloured JSON on stdout, diagnostics on stderr").
- **Route CARRY (wrap route-resolve):** `otel-sdk-install` (obs-plan §3 Bootstrap phases) → the markerless entry "Driver command spans" (Epoch 4). It names the two founder decisions (export transport http-only vs TLS; the `OTEL_EXPORTER_OTLP_HEADERS` credential path) and the research facts (opentelemetry 0.33 family, MSRV 1.75, fits reqwest 0.13.4 / http 1.5.0 / tracing-subscriber 0.3.23, no coupled pin).
- **FOR THE FOUNDER (handoff):** the OTel export deferral and its two open decisions, as above. The scrub-reach allowlist was decided by the overseer delegate under the standing delegation, and the founder's later word supersedes it.
