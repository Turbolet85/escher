## What this chunk builds
A snapshot that reads three more states of a control — selected, pressed and invalid — from what the app states in its markup, proven on the stand.

- **The engine reads the three ARIA states.** The accessibility builder reads `aria-selected`, `aria-pressed` (or `aria-checked` for toggles) and `aria-invalid` — the option as it was read to the founder (`inputs#I2`). The change is made in the builder's own file, `packages/blitz-dom/src/accessibility.rs` (CARRY 3).
- **A snapshot carries the three states.** A snapshot node's state today is four fields — `enabled`, `checked`, `value`, `focused` (`packages/dioxus-native-dom/src/snapshot.rs:46-60`); the three join it.
- **The stand's tasks state all three.** The flight booker's two mode buttons, the CRUD's rows and the flight booker's two date inputs state their state in markup, where today a CSS class alone carries it.
- **Checks through real input, in both layout modes** (`incremental` false and true — CLAUDE.md §Critical Warnings): the active flight mode reads pressed and the other not, the selected CRUD row reads selected and no other row, an invalid date reads invalid and a valid one not; each reading follows the app's state when it changes, and the step that changes it returns that node in its diff (v010-17's acceptance, `matrix.py show --id v010-17`).
- **Measured first** — "so each state is seen absent before it is seen read" (CARRY 2). Taken at P3 on HEAD `f0cb9dd7` through the stand's own binary: the two mode-button lines read byte for byte the same in both flight modes; a start date's line differs between an invalid and a valid date in its value alone; the three row lines read the same before and after a row is selected, and that step's diff names no row (research.md §Measured first).
- **The text form carries them.** `Snapshot::to_text` writes a node's state as tokens in a fixed order — `enabled` or `disabled`, `checked` or `unchecked`, `value=`, `focused` (`packages/dioxus-native-dom/src/snapshot_text.rs:48-76`); the text is what a `snapshot` call answers, so a state the model holds and the text does not write would not reach an agent. Every stand screen stays under its in-file ceiling and `SNAPSHOT_TEXT_BUDGET` with the new tokens (boot today: 1269 bytes of 1536 on the flight booker, 2034 of 2304 on the CRUD). Which tokens, and whether a false reading is written, is decision 3.
- **The diff needs no new rule to name such a node `changed`.** `Snapshot::diff` compares a node's whole `state` (`packages/dioxus-native-dom/src/snapshot_diff.rs:76-81`), and a `DiffNode` carries the whole `NodeState` (`:44`). What a diff calls `changed` is decision 4.

- **The engine change reaches every document, and the platform tree.** The builder has one caller, `build_accessibility_tree`; that tree is the trait's default `accessibility_tree`, the Dioxus override's base, and what the shell hands the platform adapter (`packages/blitz-shell/src/accessibility.rs:45`, `packages/blitz-shell/src/application.rs:82`; research.md §Graph impact).
