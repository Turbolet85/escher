## Goal
A snapshot reads which control is selected, pressed or invalid, from what the app states in its markup, and the
stand's tasks state all three — the founder's ruling of 2026-10-10 (`inputs#I2`), which brings the three states into
0.1.0 as their own chunk ahead of "MCP surface". Measured at P3 on the engine as built: the two flight-mode buttons
read byte for byte the same in both modes, a date's line differs between an invalid and a valid date in its value
alone, and the CRUD's row lines are the same before and after a row is selected (research.md §Measured first). An
agent reads each of the three only from a side effect today.

The change runs through four existing units and adds none (per architecture §Existing Scopes). The engine's
accessibility builder reads `aria-selected`, `aria-pressed` and `aria-invalid` on every element, by value, and writes
AccessKit's `selected`, `toggled` and `invalid` on the element's node — a direct change in the builder's own file, for
every document, flagged upstreamable (per architecture §Established Decisions → Scrolling and input, the precedent
form). The snapshot reads the three from that node, as it reads role, name and focus (per a11y-plan §7), into three
new fields of `NodeState`; its text form writes them as bare words and its diff names a node whose reading moved with
no new rule. The driver's one table gains three node keys and two of its help texts say the state words and the two
limits of the boolean model, so an agent learns them from the tool (per architecture §Standard Contracts → Driver
session). The stand states the three by attribute alone: the flight mode buttons as toggle buttons, the CRUD rows as
options of a listbox, the two date inputs as invalid or not (per layout-templates §Surface: desktop-native → Primary
screens).

How each fork was decided is scope.md §Decisions owed: the operator's answers at P4 are `inputs#I3` and `inputs#I4`.
Two boundary forks are the founder's and are written whole in
`.andromeda/runs/2026-10-10T16-12-10-phase/p4-founder-forks.md`; the plan takes the recommended option of each and
records both as the operator's reading awaiting the founder's word, never as his (`inputs#I4`).

## Constraints & rejected approaches
- **The snapshot parsing the element's attributes itself** — rejected: the builder writes the states, so a second
  parser could disagree with the tree; the snapshot maps nothing the tree already reads (a11y-plan §7).
- **A role table per attribute in the engine** — rejected by the operator (`inputs#I3`): an attribute is read on every
  element by value, as `aria-label` and `aria-hidden` are; the role-override TODO stays upstream's.
- **Reading `aria-checked`** — not in this chunk (`inputs#I3`): AccessKit holds one `toggled` for pressed and checked,
  so reading both would need a role list in the snapshot; `checked` stays the native reader and v010-05 stays as
  worded. Do not fold an `aria-checked` reading into `checked` or `pressed`.
- **A tri-state `pressed` or a kind on `invalid` in the model** — rejected by the operator (`inputs#I3`): the model is
  boolean, the node keeps the full value, the served text says the limit. No new public type enters.
- **A help per node key** — not here (`inputs#I4`): `NODE_FIELDS` stays a list of names; the two result-field helps
  carry the words. It is pinned at the wrap on "Self-description".
- **A token between `enabled` and `value=`** — rejected: it breaks `examples/seven_guis/tests/flows/flight.sh:29`;
  the three tokens follow `value=`.
- **Making the flight mode a radio group or tabs** — not taken: the mode would read checked or selected, which
  changes what v010-17 says and is the founder's.
- **A `tabindex` on the rows, or any focusability change** — do not: it moves the Tab order a11y-plan §5 pins; the
  unfocusable option is stated in the report and owned by "Stand keyboard harness".
- **Adding a name to the bridge's `BOOLEAN_ATTRIBUTES`** — do not: the list is the founder-ratified copy of Dioxus's
  own; the three attributes are read by value and a false one is written as the text `false`.
- **Removing or renaming the three classes** — do not: they are the style hooks and the subjects of standing checks.
- **Touching Cells** — not here: no headless check can read it, and it holds no key discipline (decision 6).
- **Adding the engine's new check to the `a11y` CI leg** — not here: the leg stays three files, on the precedent of
  `accessibility_names`; a fourth is a CI-contract change with its own pins (decision 7).
- **A log site, a span field or a `Debug` print of a state, a node or an `Outcome`** — do not (obs-plan §4).
- **An upstream pull request** — none is opened (CARRY 3).

## Implementation notes
- **The by-value trap, as an equality:** `aria_pressed: "false"` written by the stand reaches the builder as
  `attr(local_name!("aria-pressed")) == Some("false")`, because `set_attribute_inner` clears a falsy value only for a
  name in `BOOLEAN_ATTRIBUTES` and no `aria-*` name is in it (`packages/dioxus-native-dom/src/mutation_writer.rs:14-42`,
  `:439-445`). A presence read would read every mode button pressed and every row selected. The stand writes the
  literal texts `"true"` and `"false"`; step 5's unit test also pins a Dioxus `bool` arriving as that text.
- **The atoms exist:** `local_name!("aria-selected")`, `("aria-pressed")` and `("aria-invalid")` compile as
  `("aria-label")` does — web_atoms 0.3.0 `local_names.txt:112`, `:102`, `:89`.
- **AccessKit's getters, as read at the locked 0.25.1:** `is_selected()` returns `Option<bool>`, `toggled()`
  `Option<Toggled>`, `invalid()` `Option<Invalid>` (`src/lib.rs:2449`, `:2467`, `:2457`); `invalid` has no value for
  "valid", which is why the model's `invalid` is a plain flag.
- **Nothing else writes `toggled`:** the builder sets it nowhere today (the file was read whole), so with
  `aria-checked` unread the node's `toggled` is exactly the `aria-pressed` reading.
- **`NodeState` literals:** 13 struct-literal sites (`grep -rn 'NodeState {' --include=*.rs packages tests examples`);
  the definition and the one full literal at `snapshot.rs:140` change, the eleven in `snapshot_text.rs` close with
  `..state()` or `..NodeState::default()` and compile unchanged.
- **The row's role reads `ListBoxOption` and the list's `ListBox`** (`role_from_name`, `accessibility.rs:142`, `:156`);
  both are in the actionable-key check's interactive list and both elements are keyed, so the library still returns
  nothing. `stand_actionable_keys`' own reader names `Button`, `TextInput` and `Slider` only and pins no count
  against the library's; its gate reading decides.
- **A click on a mode button or a row leaves nothing focused** (a11y-plan §5, measured at the last chunk), so those
  steps' diffs carry no `focused` change beside the state change.
- **`flight-return-date` under a one-way flight** reads not invalid whatever it holds: `return_valid` is true whenever
  the flight is one-way (`flight_booker.rs:52`).
- **Case and whitespace of a value are leans, not specification:** WAI-ARIA 1.2 as read at P3 states no case rule for
  a state's value; the builder compares in lower case as it compares `aria-hidden`, and trims as it trims
  `aria-label`. An upper-case `TRUE` therefore reads unrecognized: nothing for the first two attributes, invalid for
  the third. Step 1 pins it; the report states it as chosen, not measured against a browser.
