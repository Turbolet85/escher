## What this chunk builds
An agent gets one fixed, documented way to drive the stand checks and blitz-tests without knowing cargo's or the test harness's details: five commands (boot, run, status, cleanup, logs) whose outputs and exits are machine-readable, with JSON-line logs. This is the "5-command discipline" test-plan §3 records as NOT YET MEASURED, and `.claude/rules/verification-harness.md` and `.claude/docs/tests-summary.md` assign it to this entry. It is also the harness health check 13 reports missing, since Development Style is agent-driven and `scripts/agent-run.{sh,ps1}` do not exist (new-session dashboard, 2026-10-06).

- **boot** — makes the stand ready to run headlessly: whatever has to exist before a check runs (built test binaries, a fresh per-invocation temp area) exists, and it reports ready or not-ready with a non-zero exit on failure. The headless stand is in-process: `seven_guis::stand::boot` runs over `Harness` with no daemon, socket or window, and `stand.rs` has 0 `escher_telemetry|env::var|println` hits (research.md §Files inspected). So "boot" cannot mean "start a daemon and poll its status endpoint", which is what the setup template's skeleton assumes. Concretely, boot builds the test binaries and opens the state area; P4 fixes the details.
- **run** — runs a named selection: the stand checks (`tests/blitz-tests/tests/stand_*.rs`, 5 files), one blitz-tests file, or the whole blitz-tests suite. It returns an exit that distinguishes pass from fail and emits per-test outcomes an agent can parse. On stable, libtest's `--format json` exits 101 with "only accepted on the nightly compiler with -Z unstable-options" (measured at P3, research.md §Patterns). libtest's pretty output — `Running tests/{file}.rs`, `test {name} ... ok|FAILED|ignored`, `test result: …` — is the per-test channel, recorded at `evidence/p3-stand-run.log`. No test-runner crate is needed.
- **status** — reports whether a boot is ready and the state of the last run (running / passed / failed, with counts) without re-running anything. Non-zero when nothing is booted (the template's validation check 1).
- **cleanup** — removes everything boot and run created (temp area, status/PID files, any stray child process) and is idempotent: it succeeds on an already-clean tree.
- **logs** — returns the run's log as JSON lines, one object per line. escher's only sink writes a one-line TEXT format to stderr (obs-plan §3). The headless stand installs no subscriber: verified, `stand.rs` has 0 `escher_telemetry` hits, and arch §Standard Contracts → Headless stand requires that it keep installing none. So no escher sink is present in a stand-check process for a JSON format to reach. The JSON-line log is harness-level: the script writes one JSON event per test and per command. Its schema is P4's, its field names stay off the content-named scrub set, and it carries no captured test output (CLAUDE.md: add no new user-content log fields).
- **The script surface** — `scripts/agent-run.sh` (+ `agent-run.ps1`), the five verbs as words in both (health check 13's criterion). `[premise-corrected: setup Phase 4 is only-if-missing and calls the harness project-evolvable — andromeda-setup-project/SKILL.md:220-231]` The scripts are authored by this chunk's implement, not generated: setup preserves an existing `scripts/agent-run.*` and never re-renders over it. The rule's "then the scripts are generated" wording is a wrap amendment of `.claude/rules/verification-harness.md`. The `.ps1`'s form is a P4 fork, because `pwsh` is absent on this host.
