## Goal
An agent gets one fixed, machine-readable way to drive the stand checks and blitz-tests: `scripts/agent-run.sh` with
five verbs, `boot · run · status · cleanup · logs`. Each verb has a closed exit grammar and JSON-line output, and
`scripts/agent-run.ps1` delegates to it on Windows. This is the 5-command discipline that test-plan §3 leaves NOT YET
MEASURED, and the harness that health check 13 reports missing for an agent-driven project. The design follows the
stand as it is built. The stand is an in-process library boot, with no daemon, socket or window (architecture
§Standard Contracts → Headless stand; research.md §Files inspected). So boot builds the test binaries and opens a
state area under `target/`, and nothing is started or polled. Per-test results come from libtest's pretty output,
because its JSON format is nightly-only on this toolchain (measured at P3, research.md §Patterns detected).

The JSON-line log is harness-level. The script writes one event per verb and per test. It never carries captured
test output, and its field names stay off the scrub's content-named set (security-plan §Logging & Monitoring;
obs-plan §8 Scrubbing). The stand installs no escher sink, so no telemetry stream exists in a stand-check process for
it to carry (obs-plan §3 Logging stack). The chunk changes no Rust signature, no `Cargo.lock` and no CI job. Its
contract tests run in the existing `ci-scripts` leg through a cargo shim, the `LegScriptTest` precedent (test-plan §4).

The chunk also discharges its PREREQ. It corrects the `//!` doc of `tests/blitz-tests/tests/dioxus_falsy_disabled.rs`
so that the doc claims only the defect the falsy-`disabled` fix removed: the literal `"false"` matched `:disabled` and
DISABLED state. It drops the focus-order and focusability clauses. Re-verified at HEAD, focusability parses the value
as a bool (`element.rs:629`), and presence keys the state (`element.rs:449`) and the click target (`pointer.rs:330,457`).
The test body asserts no focusability (a11y-plan §5 Keyboard Navigation, §8 Cognitive Accessibility; security-plan

2. **Create `scripts/agent-run.sh`, executable.** It follows `ci-leg.sh`'s shape: `#!/usr/bin/env bash`,
   `set -euo pipefail`, a `VERBS=(boot run status cleanup logs)` array, a `usage()` to stderr, one `case` per verb, and
   it is invoked from the project root (research.md §Patterns detected, `ci-leg.sh:8-64`).
   - State lives in `target/agent-run/` only: `status.json`, `events.jsonl` and `run.log`. It reads no env var of its
     own, and every cargo call carries `--locked`.
   - JSON is produced by a real encoder (`python3` and its `json` module, which the `ci-scripts` leg already requires),
     never by string concatenation (Constraints).
   - It keeps a no-op `ensure_fresh_artifacts` function with a comment, called first in `boot` (setup's hook, read by
     its U10 detector).

   The contract, fixed here because the wrap writes it into test-plan §3:
   - **Exit grammar, every verb:** `0` success · `1` the verb ran and failed (build failure, a failing or empty run) ·
     `2` usage (missing or unknown verb, unknown selection) · `3` a precondition is unmet (not booted, nothing to read).
   - **`boot`** — runs `ensure_fresh_artifacts`. Then it recreates `target/agent-run/` and truncates `events.jsonl`
     and `run.log`. Then it builds every blitz-tests test binary with `cargo test -p blitz-tests --locked --no-run`,
     merged output to `run.log`. It writes `status.json` (`booted`, `boot_ts`, `head` — `git rev-parse HEAD` or null
     outside a repository) and prints and appends one event: `{"event": "boot", "ts", "outcome": "ready"|"failed",
     "cargo_exit", "head"}`. Exit 0 on ready, 1 on failed (a failed boot leaves `booted` false).
   - **`run {selection}`** — requires a ready boot (else exit 3). `{selection}` is one of:
     - `stand` — every `tests/blitz-tests/tests/stand_*.rs` file present, each as `--test {name}`;
     - `all` — the whole blitz-tests package, no `--test`;
     - `{name}` — one blitz-tests file, with `name` matching `^[a-z0-9_]+$` and `tests/blitz-tests/tests/{name}.rs`
       existing.

     Anything else exits 2. It runs `cargo test -p blitz-tests --locked [--test …]`. The merged output is written to
     `run.log`, truncated at the run's start. `status.json`'s run state is `running` during the run and `passed` or
     `failed` after it. It parses libtest's pretty lines (`Running {target} (…)`, `Doc-tests {crate}`,
     `test {name} ... ok|FAILED|ignored`) into events, each printed to stdout and appended to `events.jsonl`:
     - `{"event": "run.start", "ts", "selection", "files": [...]}`;
     - one `{"event": "test", "file", "test", "outcome": "ok"|"failed"|"ignored"}` per test line, where `file` is the
       target's stem (`stand_boot`) or `doc:{crate}`;
     - `{"event": "run.end", "ts", "selection", "passed", "failed", "ignored", "cargo_exit", "outcome": "passed"|"failed"}`.

     `outcome` is `passed` only when cargo exited 0, `failed` is 0 and at least one test event was parsed. Otherwise it
     is `failed` and the verb exits 1: an empty result is never a pass (test-plan history, 2026-10-05-ci-gate-legs,
     where `llvm-cov report` exited 0 on an empty table).
   - **`status`** — prints one JSON object, `{"event": "status", "booted", "boot_ts", "head", "run": {"selection",
     "state": "none"|"running"|"passed"|"failed", "passed", "failed", "ignored"}}`, built from `status.json`. Exit 0
     when booted and 3 when not (no `status.json`, or `booted` false). It never builds or runs anything.
   - **`cleanup`** — removes `target/agent-run/` if present and prints `{"event": "cleanup", "outcome": "done"}`. It is
     idempotent (exit 0 on a clean tree) and never touches anything else under `target/`.
   - **`logs`** — prints `events.jsonl` verbatim, one JSON object per line. Exit 3 when it is absent. Raw cargo output
     stays in `run.log` and is never printed by `logs`.
3. **Create `scripts/agent-run.ps1`, a thin wrapper.** A comment names it as the Windows entry and lists the five
   verbs. It passes every argument unchanged to `bash "$PSScriptRoot/agent-run.sh"` and exits with bash's exit code.
   It contains no contract logic (leaned per the operator's fork answer; Constraints).
4. **Create `.github/scripts/test_agent_run.py`.** It holds stdlib `unittest` contract tests for `scripts/agent-run.sh`
   in the `LegScriptTest` shape (`test_ci_workflows.py:204-260`). Each case uses a temp dir as the cwd, a `cargo` shim
   on PATH that prints a scripted output and exits a scripted status, and fake `tests/blitz-tests/tests/*.rs` files
   where a selection needs them. One case per behaviour:
   - status before boot exits 3; a missing verb and an unknown verb exit 2;
   - boot with the shim at 0 exits 0, status then exits 0 with `booted` true, and the shim saw `test -p blitz-tests
     --locked --no-run`; boot with the shim at 101 exits 1, and status then exits 3;
   - run before boot exits 3; run with an unknown selection, or a name failing the pattern, exits 2;
   - `run stand` over a scripted passing libtest output exits 0. Every stdout line parses as JSON, the test events
     match the scripted lines one for one, and `run.end` carries the counts. The shim saw `--locked` and one `--test`
     per fake `stand_*.rs`;
   - a scripted `FAILED` line plus a `failures:` block holding a panic message, with the shim at 101, exits 1 with
     `failed` = 1. No stdout line and no `events.jsonl` line contains the panic message;
   - a scripted `running 0 tests` with the shim at 0 exits 1 (the empty-run rule);
   - a doc-test line whose name holds spaces, parentheses and a slash still yields one valid JSON event;
   - logs before boot exits 3; after a run it prints exactly the appended events, each valid JSON, and none carries a
     key in the scrub set (`url href src html text value attrs path request error`);
   - cleanup exits 0 twice in a row, and afterwards `target/agent-run/` is absent and status exits 3;
   - `run.log` holds the shim's raw output after a run.
5. **Run the new contract live once** through the gate entries below (cleanup → status → boot → status → run stand →
   logs checks → run all → a11y count → cleanup ×2). Record nothing by hand. The gate tool's trail is the record.

- A daemon, status endpoint, socket or PID-polled boot (the setup template's skeleton) — rejected. The stand is
  in-process, and a listener is an arch §Occupied Resources and security-plan amendment that this chunk has no need for
  (architecture §Occupied Resources → Network ports and listeners).
- `cargo test -- --format json`, `RUSTC_BOOTSTRAP=1` or nightly — rejected. The JSON format is nightly-only (measured at
  P3), and `RUSTC_BOOTSTRAP` is an env-var hack that unlocks unstable features on the stable toolchain.
- cargo-nextest or another runner crate — rejected. It is a new tool and dependency that test-plan §3 records absent,
  and libtest's pretty lines carry every outcome the contract needs.
- A JSON format inside escher-telemetry for this log — rejected. The stand checks run no escher sink (stand.rs: 0
  `escher_telemetry` hits), and the arch stand contract keeps it that way, so the format would reach nothing. It would
  also amend the telemetry line-shape contract for no reader.
- Any env var (`HARNESS_TMPDIR`, `HARNESS_LOGFILE`, …) — rejected. State is the fixed path `target/agent-run/`, per the
  2026-10-05-fork-ci-reached precedent "no new env var, no host/CI divergence".
- A native PowerShell port — rejected on the operator's fork answer. It would be a second, untested implementation.
  `agent-run.ps1` delegates to bash (delegate overseer under the founder's standing delegation, 2026-10-06; gate-contract
  §Scope, *Whose word*).
- A new CI leg for the scripts — rejected. The contract tests ride the existing `ci-scripts` leg, and a new leg would
  add a cache entry to a cache already over its 10 GB budget (arch history, 2026-10-05-ci-gate-legs) and extend the
  pinned CI contract.
- JSON built by bash string concatenation — rejected. Doc-test names carry spaces, parentheses and slashes, and an
  encoder is the only escaping that is correct by construction.
- Copying libtest's `failures:` block, captured stdout or panic text into any event — rejected. These are unscrubbed
  content (obs-plan §8 Values logged as-is). They stay in `run.log` under the gitignored `target/`, like
  `target/ci-logs/`.
- Widening the PREREQ into the other Dioxus boolean attributes — rejected. That is the CARRY on "Snapshot state
  fidelity" (a11y-plan §5 Script and framework exposure: "recorded, not established").

## Implementation notes
- The parser must accept both `running 1 test` and `running {N} tests`. It must also take a doc-test name of the form
  `src/lib.rs - item (line N)`, which `-p blitz-tests` may emit if the crate has doctests. The exact name set is
  whatever libtest prints; parse by the ` ... ` separator and the trailing outcome word.
- libtest's pretty output runs tests in parallel threads but prints each `test {name} ... {outcome}` as one line
  (`evidence/p3-stand-run.log`), so line-wise parsing holds.
- `status.json`'s `running` state is left behind if a run is killed. A later `run` overwrites it. Locking against two
  concurrent runs is out of scope; the contract is one driver at a time.
