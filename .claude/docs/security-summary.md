# Security Summary — escher

_Distilled from `.andromeda/security-plan.md` (adopted reading — current truth, not intent). wrap-session's cascade re-derives it when the plan changes._

## Posture

escher is a native-API engine library with no served network API, no port and no authentication; its one listener is local — the driver session's owner-only Unix-domain socket, which carries the session's lifecycle and, since 2026-10-10-driver-cli, driver calls and their answers (ratified by the founder, 2026-10-10). Its risk is in what it ingests: arbitrary remote HTML/CSS/images/fonts/sub-documents, JavaScript run by `blitz-vibey-script`, and CLI arguments of the examples. The application-level threat model is NOT YET MEASURED.

**Tier:** 0
**Auth approach:** none (observed absent in every slice)

## Threat model highlights (attack surface as measured)
- **Remote web content** → iframe depth cap 10, `@import` depth cap 16, stale iframe responses discarded by request id; snapshotting a never-styled node is skipped (Stylo would panic).
- **Script execution** → default `ScriptFetcher` accepts only `file:` / `data:`; JS `fetch()` is GET/HEAD only through the embedder's fetcher; same-origin / CORS observed absent; every runtime event is `isTrusted`; the browser's JS is behind the non-default `javascript` feature.
- **`file:` reads** → blitz-net reads any `file:` path with no restriction — through `Url::to_file_path` off wasm, a non-path URL a typed `InvalidInput` error; the WPT net provider joins request paths onto the WPT base.
- **Font sources (ratified by the founder, 2026-10-10)** → since the 2026-10-10 upstream merge an `@font-face` source with no format hint and no URL extension (a `data:` URL) is fetched and byte-sniffed where it was skipped — a boundary widening ratified as upstream's behaviour; still owed: no test of ours covers it, and a check of ours is due before 0.1.0 ships (route entry "Quality gates"); escher routes no agent- or user-supplied URL through this path.
- **Outbound HTTP** → 6 concurrent requests per host; no response-size cap, no timeout (observed absent); TLS via reqwest `native-tls`. A harness settle reports a load in flight at once (`NotSettled` naming the class `Loads`) and never waits on one, so the absent timeout cannot hang it; its outcome names a class only. The driver's command schema keeps this: no verb has an argument or a field of a wait, and no driver command waits on a load (the operator, 2026-10-07).
- **CLI input** → examples parse URLs with `Url::parse` (+ `https://` retry), numeric args with defaults; `bump` validates target + semver; `scripts/agent-run.sh` allowlists its verb and admits a run selection only as `stand`, `all` or an existing `^[a-z0-9_]+$` blitz-tests file stem (else exit 2, no cargo call); `scripts/cold-agent.sh` allowlists its verb and the task `counter` (else exit 2, before any precondition or `claude` call).
- **Cold-agent pipe (ratified by the founder, 2026-10-06)** → an operator-host-only `claude -p` session on the operator's own Claude Code login (`apiKeySource` none, no API key, no env read, no CI secret) reaches the model provider; its only tools are a stdlib stdio MCP stub that refuses an unknown id, a disabled button, a press on the display and a malformed argument (`isError`, no state change) and logs no argument value.
- **Local IPC — the driver session socket (the founder's choice, 2026-10-07)** → `escher_driver::serve` binds `session.sock` in a caller-named state directory, created `0700` (a group- or other-open one refused), the socket `0600`: reachable by the owning user only, with no other authentication; the wire is a closed line grammar at `v2` — `hello`, `stop` and, since 2026-10-10-driver-cli, `call v2 <verb> [<name>=<kind>:<value>]…`, percent-escaped and decoded strictly — with a 16,384-byte request bound, a 2 s I/O bound (30 s on a client's read of an answer), refusals running nothing; a lifecycle reply (at most 128 bytes) carries a pid, a label of `a-z0-9-`, a count and the idle expiry, and a call's answer (at most 1,048,576 bytes, `oversize` past it) carries what the screen reads — ids, accessible names, control values (a password's or a file input's as the fixed mask), the snapshot's text and the diff; a call brings an element id and typed text in; no `NodeId` crosses — a second widening, ratified by the founder (2026-10-10); a host with no request answered for its idle expiry (1,800 s) ends as on `stop`; unix only.
- **Command line — `escher-session` (a new external input surface, ratified with the crossing)** → argv is read by `escher_driver::command_line`: a closed reader with its rules in a fixed order, the call checked by `validate` or `validate_session` before the session address is asked for, `--session <dir>` exactly once, no panic path on argv; four endings — accepted, one line of JSON on stdout, status 0; refused, 1; usage, one fixed line on stderr, 2, nothing booted; session error, 3 — none writing back anything the caller typed; `start` re-runs the binary as `serve <task> --session <dir>` with its streams closed and neither kills nor reaps it; the two-argument form `<task> <state-dir>` is gone.
- **Driver command schema (an external-input surface since 2026-10-10-driver-cli)** → `escher_driver::validate` checks a call against a closed table of nine verbs in two levels — six asked of the held instance, `scroll` the sixth, a widening ratified by the founder (2026-10-07), and three asked of the session, `start` · `status` · `stop`, a further widening ratified by the founder (2026-10-10), which `validate` refuses as `unknown-verb` and `validate_session` checks — and six argument kinds with bounds (`id` 1 to 1024 bytes, `text` 0 to 4096, `key` one of twelve names, `flag`, `milliseconds` 1 to 60000, `name` 1 to 32 bytes of `a-z0-9-`) and returns a typed command or a typed `Refusal` in one fixed order, before anything runs and with no panic path on what a call supplies; it receives no `Session`, so a refused call changes nothing; a refusal is one of eight causes with fixed texts and holds nothing of the call. After `validate` the executor refuses with nothing run and the instance unchanged: an id the screen does not read as `stale` or `not-found`, and a `click` or a `type` on a target that cannot take it as `disabled`, then `off-screen`, then `covered`. To tell `stale` from `not-found` the session keeps a record of id text — at most 4096 ids, session-lived, private, never printed or logged, fed from its own snapshots only; the bound counts ids, and an id longer than 1024 bytes is not recorded. Two surfaces reach the schema from outside the process, each through `validate` first — the socket's `call` request, run by a host through `Session::run` and nothing else, and the `escher-session` command line; no MCP tool yet, and that surface is its own crossing question. `Command`, `Call` and `ArgValue` print an id and typed text under `Debug`: never log or field them. A refusal and a session error each have one written form, JSON built from fixed strings, holding nothing a call supplied. The crate's one log record is the command span of `Session::run` — target `escher_driver`, name `command`, eight fields of fixed words, bools and counts (`verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`) — which a sink prints at `info` or below; of a refusal only its cause's fixed name is fielded.
- **rdme markdown** → comrak with `unsafe: true` passes raw HTML through.
- **CI** → post-results workflow checks out trusted scripts from the default branch; `ci.yml` declares a workflow-level `permissions: contents: read` with no job grant, pins every action to a commit SHA and references no secret. The publish (signing), WPT and post-results jobs carry `github.repository == 'DioxusLabs/blitz'`, so no fork ref reaches "Signed Builds", "WPT" or their secrets.

## Data classifications (as measured)
| Class | Examples | Handling |
|---|---|---|
| CI secrets | signing key, Android keystore + passwords, Apple certificate, `WPT_GITHUB_TOKEN`, `GITHUB_TOKEN` | GitHub secrets/vars; written files removed in `always()` steps |
| Local user data (browser app) | history `history.sqlite3`, HTTP cache, cookies, clipboard, chosen file paths | unencrypted on disk; history in-memory on mobile; "Clear history" / "Clear Cache" |
| Snapshot content | stable ids, accessible names, a text control's value — in `DioxusDocument::snapshot`, its text form `Snapshot::to_text` and its diff `Snapshot::diff` | returned to the caller and, since 2026-10-10-driver-cli, carried in a hosted call's answer over the session socket and onto the `escher-session` client's stdout (ratified by the founder, 2026-10-10; until then returned to the caller only, ratified 2026-10-07): no log, event or file of escher's carries any of the three — while the three list lengths of a diff the driver returns (counts only) are recorded on its command span and printed by the sink at `info` or below (ratified by the founder, 2026-10-09: the sentence stands, with the clarification that a diff's content never reaches a log while its three sizes may); since 2026-10-07-act-by-id that caller can be the caller of the driver's `Session::run` — its `snapshot` command returns the text and its acting commands the diff, in process or through the command line, with no MCP command — and since the sink drops every record from a target outside its allowlist, a sink-installing binary's stderr carries no author-key id, no accessible name and no typed text at any `RUST_LOG` level (measured on the `escher-session` host while it runs calls: 0 id needles, 0 name needles and 0 occurrences of a typed sentinel at `trace`, under both builds); a password's and a file input's value read the fixed mask, while the file input's DOM attribute and form submission still hold the host path |
| Logged values | request URLs, cache dir path, attribute values | escher's stderr sink (`seven_guis_native`, `escher-session`) redacts them by a target allowlist — engine targets print only safe fields, escher targets redact content-named fields, and a record from any other target is dropped whole at every level (no element id and no accessible name on stderr at `debug` or `trace`); the upstream apps' `fmt::init()` and the WPT runner's `env_logger` log them as-is |
| Harness test logs | the agent-run contract's JSON-line events; raw cargo/libtest output in `target/agent-run/run.log` | events carry no content-named field and no captured output; `run.log` unscrubbed like `target/ci-logs/`, gitignored, never printed |
| Operator credential (dev host) | the operator's Claude Code claude.ai login, used by the cold-agent live run | held by the `claude` CLI outside the repo (at-rest location unmeasured); no artifact, event or verdict carries it |
| Agent-session transcript | `target/cold-agent/transcript.jsonl` — model output, tool I/O, host paths | raw by design, never printed, gitignored; events and verdict carry counts and identities only; the one committed copy host-path-masked |
