# Security Summary — escher

_Distilled from `.andromeda/security-plan.md` (adopted reading — current truth, not intent). wrap-session's cascade re-derives it when the plan changes._

## Posture

escher is a native-API engine library with no served network API, no port and no authentication; its one listener is local — the driver session's owner-only Unix-domain socket, which carries the session's lifecycle and, since 2026-10-10-driver-cli, driver calls and their answers (ratified by the founder, 2026-10-10); since 2026-10-10-mcp-surface the same calls and answers also cross to an MCP client over the `escher-session mcp` role's own stdio, no listener (ratified by the founder, 2026-10-10). Its risk is in what it ingests: arbitrary remote HTML/CSS/images/fonts/sub-documents, JavaScript run by `blitz-vibey-script`, and CLI arguments of the examples. The application-level threat model is NOT YET MEASURED.

**Tier:** 0
**Auth approach:** none (observed absent in every slice)

since 2026-10-13-stand-keyboard-harness, in every document — remote pages included — `Enter` on a focused `button`, `summary`, submit/reset/button `input` or `a` with `href`, and a released Space on a focused `button`, `summary` or submit/reset/button/checkbox/radio `input`, dispatch a Click (handlers, then `handle_click`: form submission, link navigation, `summary` toggling) only when it is no disabled form control (a `disabled` attribute on a `summary` or an `a` gating neither key), a click on a button focuses it, and `disabled` is read by presence on a form control alone (`button` · `input` · `select` · `textarea`, `ElementData::is_disabled`; `"false"` included; ratified by the founder, 2026-10-18) for focusability, the pointer and click gates and the activation keys, so a `<div disabled tabindex=0>` takes focus and a disabled ancestor `div` does not stop the click walk, the snapshot's `enabled` reading the same presence — closed name and type gates, no log site or panic path, no carrier, verb, key name, field or span added — an engine change for every document and a boundary widening, ratified by the founder (2026-10-13, 2026-10-14); since the 2026-10-17 upstream sync the accessibility builder reads, as upstream wrote them, `aria-labelledby` (its targets' text the computed `label`, outranking a `<label>` and an `aria-label`, inside the ratified name crossing), `aria-expanded` · `aria-disabled` · `aria-level` (closed values inside the states class; `aria-disabled` moves no snapshot reading) and `aria-describedby` · `aria-description` — descriptions, `aria-description` free page text, unbounded, a fourth content class on the platform adapter crossing only (the snapshot reads no description, so no driver or MCP carrier holds it), a boundary widening by upstream merge ratified as upstream's behaviour by the founder (2026-10-17), with no log site, print or panic path; the builder reads the toggle by role (ratified by the founder, 2026-10-18) — `aria-checked` `true` · `false` · `mixed` on the five checkable roles alone (`CheckBox` · `Switch` · `RadioButton` · `MenuItemCheckBox` · `MenuItemRadio`, `role="switch"` now mapped to `Switch`), `aria-pressed` on every other role, a native checkbox or radio reading neither — closed values inside the states class, never the attribute's text; - **Script execution** → default `ScriptFetcher` accepts only `file:` / `data:`; JS `fetch()` is GET/HEAD only through the embedder's fetcher; same-origin / CORS observed absent; every runtime event is `isTrusted`; the browser's JS is behind the non-default `javascript` feature.
- **`file:` reads** → blitz-net reads any `file:` path with no restriction — through `Url::to_file_path` off wasm, a non-path URL a typed `InvalidInput` error; the WPT net provider joins request paths onto the WPT base.
- **Font sources (ratified by the founder, 2026-10-10)** → since the 2026-10-10 upstream merge an `@font-face` source with no format hint and no URL extension (a `data:` URL) is fetched and byte-sniffed where it was skipped — a boundary widening ratified as upstream's behaviour; since 2026-10-14-quality-gates witnessed by blitz-tests' `font_face_sniffed_source` (offline, both layout modes: a hint-less `data:` source answered with a `wOF2` body registers, a body no sniff matches registers nothing); escher routes no agent- or user-supplied URL through this path.
- **Outbound HTTP** → 6 concurrent requests per host; no response-size cap, no timeout (observed absent); TLS via reqwest `native-tls`. A harness settle reports a load in flight at once (`NotSettled` naming the class `Loads`) and never waits on one, so the absent timeout cannot hang it; its outcome names a class only. The driver's command schema keeps this: no verb has an argument or a field of a wait, and no driver command waits on a load (the operator, 2026-10-07).
- **CLI input** → examples parse URLs with `Url::parse` (+ `https://` retry), numeric args with defaults; `scripts/agent-run.sh` allowlists its verb and admits a run selection only as `stand`, `all` or an existing `^[a-z0-9_]+$` blitz-tests file stem (else exit 2, no cargo call); `scripts/cold-agent.sh` allowlists its verb and the task `stand` (since 2026-10-15-cold-agent-test; `run counter` now a usage error; else exit 2, before any precondition or `claude` call), requires an executable `target/debug/escher-session` (else exit 3; the pipe builds nothing) and hands the session only the fixed prompt `STAND_PROMPT`, naming no element id and no app slug.

- **Driver command schema (an external-input surface since 2026-10-10-driver-cli)** → `escher_driver::validate` checks a call against a closed table of eleven verbs in three levels — seven asked of the held instance, `scroll` the sixth, a widening ratified by the founder (2026-10-07), and `screenshot` the seventh since 2026-10-12-headless-screenshot (one optional `id`; result fields `width` and `height`, counts, and `png`, base64 text — the screen's pixels in band, ratified by the founder, 2026-10-12), and three asked of the session, `start` · `status` · `stop`, a further widening ratified by the founder (2026-10-10), and, since 2026-10-12-self-description, one asked of the tool itself, `help` (no argument; its seven result fields fixed table text), a further widening ratified by the founder (2026-10-12), which `validate` refuses as `unknown-verb` and `validate_session` checks — and six argument kinds with bounds (`id` 1 to 1024 bytes, `text` 0 to 4096, `key` one of twelve names, `flag`, `milliseconds` 1 to 60000, `name` 1 to 32 bytes of `a-z0-9-`) and returns a typed command or a typed `Refusal` in one fixed order, before anything runs and with no panic path on what a call supplies; it receives no `Session`, so a refused call changes nothing; a refusal is one of eight causes with fixed texts (ratified by the founder, 2026-10-18; `time-unavailable` gone, `advance` accepted on every session; `fonts-unavailable` since 2026-10-12-headless-screenshot) and holds nothing of the call. To tell `stale` from `not-found` the session keeps a record of id text — at most 4096 ids, session-lived, private, never printed or logged, fed from its own snapshots only; the bound counts ids, and an id longer than 1024 bytes is not recorded. Three surfaces reach the schema from outside the process, each through `validate` first — the socket's `call` request, run by a host through `Session::run` and nothing else, the `escher-session` command line, and since 2026-10-10-mcp-surface an MCP `tools/call`, run by the MCP server through `Session::run` (session verbs and `help` through `validate_session`, answered by the server itself). `Command`, `Call` and `ArgValue` print an id and typed text under `Debug`: never log or field them. A refusal and a session error each have one written form, JSON built from fixed strings, holding nothing a call supplied. The crate's log records are two spans — since 2026-10-10-mcp-surface the `tool_call` span of an MCP tool call, holding `tool` and `ending` only, closed words (ratified by the founder, 2026-10-10), the parent of — the command span of `Session::run` — target `escher_driver`, name `command`, eight fields of fixed words, bools and counts (`verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`) — which a sink prints at `info` or below; of a refusal only its cause's fixed name is fielded, and of a shot never its image, its size or its dimensions (a `screenshot` records `verb` and, refused, `cause`).
