# Security Summary — escher

_Distilled from `.andromeda/security-plan.md` (adopted reading — current truth, not intent). wrap-session's cascade re-derives it when the plan changes._

## Posture

escher is a native-API engine library with no served network API, no port and no authentication; its one listener is local — the driver session's owner-only Unix-domain socket, which carries the session's lifecycle and, since 2026-10-10-driver-cli, driver calls and their answers (ratified by the founder, 2026-10-10); since 2026-10-10-mcp-surface the same calls and answers also cross to an MCP client over the `escher-session mcp` role's own stdio, no listener (ratified by the founder, 2026-10-10). Its risk is in what it ingests: arbitrary remote HTML/CSS/images/fonts/sub-documents, JavaScript run by `blitz-vibey-script`, and CLI arguments of the examples. The application-level threat model is NOT YET MEASURED.

**Tier:** 0
**Auth approach:** none (observed absent in every slice)

## Threat model highlights (attack surface as measured)
- **Remote web content** → iframe depth cap 10, `@import` depth cap 16, stale iframe responses discarded by request id; snapshotting a never-styled node is skipped (Stylo would panic); since 2026-10-13-range-input-interaction an `input type="range"` in every document — remote pages included — keeps a current value from `min` · `max` · `step` · `value` read through `parse_float`, sanitized finite, clamped and on its step grid, moved by the arrows, `Home` · `End` and pointerdown only with no `disabled` attribute, with no log site or panic path — an engine change for every document and a boundary widening, ratified by the founder (2026-10-07, 2026-10-13); since 2026-10-13-stand-keyboard-harness, in every document — remote pages included — `Enter` on a focused `button`, `summary`, submit/reset/button `input` or `a` with `href`, and a released Space on a focused `button`, `summary` or submit/reset/button/checkbox/radio `input`, dispatch a Click (handlers, then `handle_click`: form submission, link navigation, `summary` toggling) only with no `disabled` attribute, a click on a button focuses it, and `disabled` is read by presence for focusability on any element (`"false"` included; a `<div disabled tabindex=0>` not focusable, a known limit owned by a CARRY on "Stand requirement sweep"), the snapshot's `enabled` reading the same presence — closed name and type gates, no log site or panic path, no carrier, verb, key name, field or span added — an engine change for every document and a boundary widening, ratified by the founder (2026-10-13, 2026-10-14).
- **Script execution** → default `ScriptFetcher` accepts only `file:` / `data:`; JS `fetch()` is GET/HEAD only through the embedder's fetcher; same-origin / CORS observed absent; every runtime event is `isTrusted`; the browser's JS is behind the non-default `javascript` feature.
- **`file:` reads** → blitz-net reads any `file:` path with no restriction — through `Url::to_file_path` off wasm, a non-path URL a typed `InvalidInput` error; the WPT net provider joins request paths onto the WPT base.
- **Font sources (ratified by the founder, 2026-10-10)** → since the 2026-10-10 upstream merge an `@font-face` source with no format hint and no URL extension (a `data:` URL) is fetched and byte-sniffed where it was skipped — a boundary widening ratified as upstream's behaviour; still owed: no test of ours covers it, and a check of ours is due before 0.1.0 ships (route entry "Quality gates"); escher routes no agent- or user-supplied URL through this path.
- **Outbound HTTP** → 6 concurrent requests per host; no response-size cap, no timeout (observed absent); TLS via reqwest `native-tls`. A harness settle reports a load in flight at once (`NotSettled` naming the class `Loads`) and never waits on one, so the absent timeout cannot hang it; its outcome names a class only. The driver's command schema keeps this: no verb has an argument or a field of a wait, and no driver command waits on a load (the operator, 2026-10-07).
- **CLI input** → examples parse URLs with `Url::parse` (+ `https://` retry), numeric args with defaults; `bump` validates target + semver; `scripts/agent-run.sh` allowlists its verb and admits a run selection only as `stand`, `all` or an existing `^[a-z0-9_]+$` blitz-tests file stem (else exit 2, no cargo call); `scripts/cold-agent.sh` allowlists its verb and the task `counter` (else exit 2, before any precondition or `claude` call).
- **Cold-agent pipe (ratified by the founder, 2026-10-06)** → an operator-host-only `claude -p` session on the operator's own Claude Code login (`apiKeySource` none, no API key, no env read, no CI secret) reaches the model provider; its only tools are a stdlib stdio MCP stub that refuses an unknown id, a disabled button, a press on the display and a malformed argument (`isError`, no state change) and logs no argument value.
- **Local IPC — the driver session socket (the founder's choice, 2026-10-07)** → `escher_driver::serve` binds `session.sock` in a caller-named state directory, created `0700` (a group- or other-open one refused), the socket `0600`: reachable by the owning user only, with no other authentication; the wire is a closed line grammar at `v2` — `hello`, `stop` and, since 2026-10-10-driver-cli, `call v2 <verb> [<name>=<kind>:<value>]…`, percent-escaped and decoded strictly — with a 16,384-byte request bound, a 2 s I/O bound (30 s on a client's read of an answer), refusals running nothing; a lifecycle reply (at most 128 bytes) carries a pid, a label of `a-z0-9-`, a count and the idle expiry, and a call's answer (at most 1,048,576 bytes, `oversize` past it) carries what the screen reads — ids, accessible names, control values (a password's or a file input's as the fixed mask), the snapshot's text and the diff, which since 2026-10-10-snapshot-states also hold three state readings (selected, pressed, invalid) as closed words and booleans and since 2026-10-12-self-description a changed node's `differs`, a list of closed words, never an attribute's value as typed — inside the ratified crossing, not a further widening (the founder, 2026-10-10, who set the rule with it: a new field of a closed value set inside an already ratified carrier is not a widening; authored text, an open value set, a new carrier or a new exit still is); since 2026-10-12-headless-screenshot an answer also takes the screen's pixels out — an accepted `screenshot`'s PNG as base64 inside its JSON line, the whole screen or one element's visible part, a password input in it painted masked, under the unchanged 1,048,576-byte bound (the in-band image the founder chose, 2026-10-12); a call brings an element id and typed text in; no `NodeId` crosses — a second widening, ratified by the founder (2026-10-10); a host with no request answered for its idle expiry (1,800 s) ends as on `stop`; unix only.
- **Command line — `escher-session` (a new external input surface, ratified with the crossing)** → argv is read by `escher_driver::command_line`: a closed reader with its rules in a fixed order, the call checked by `validate` or `validate_session` before the session address is asked for, `--session <dir>` exactly once, no panic path on argv; four endings — accepted, one line of JSON on stdout, status 0; refused, 1; usage, one fixed line on stderr, 2, nothing booted; session error, the error object with its fixed `remedy` beside `kind` and `message`, 3 — none writing back anything the caller typed; `start` re-runs the binary as `serve <task> --session <dir>` with its streams closed and neither kills nor reaps it; the two-argument form `<task> <state-dir>` is gone; since 2026-10-12-self-description `help` with no argument and at most one `--session <dir>`, the directory not read, answers fixed table text as one line of JSON on stdout, status 0, reaching no session (`help x` refused `malformed`, status 1); since 2026-10-12-headless-screenshot `screenshot` with an optional `--id` answers one line `{"width":…,"height":…,"png":"<base64>"}` on stdout, status 0 — the image by the ratified in-band crossing — and `--id` on an id the screen does not read exits 1 writing nothing the caller typed; since 2026-10-10-mcp-surface `mcp` alone selects the MCP role (any other shape after it is usage), whose end writes nothing on stdout — status 0, or 3 with a fixed message on stderr.
- **Local stdio — the driver's MCP server (since 2026-10-10-mcp-surface; the crossing ratified by the founder, 2026-10-10, «Ратифицировать как есть»)** → `escher_driver::serve_mcp`, run by `escher-session mcp` as a child an MCP client spawns under the invoking user: newline-delimited JSON-RPC 2.0 on its stdin and stdout, no listener, port, socket or authentication — the trust boundary is the process holding its stdio; a request line at most 65,536 bytes (longer: read, dropped, `-32700`), non-JSON `-32700`, a bad envelope `-32600`, the request `id` echoed only as an integer or a string of at most 128 bytes (the one client-sent value written back), every protocol error a fixed code and message with no `data`, a method outside `initialize` · `ping` · `tools/list` · `tools/call` `-32601`, `initialize`'s revision matched against a closed table of four (`2025-11-25` · `2025-06-18` · `2025-03-26` · `2024-11-05`), any other answered `2025-11-25`, a notification running nothing; a tool argument of the wrong JSON kind refused `malformed` before anything runs, then `validate`; a result at most 1,048,576 bytes (since 2026-10-12-headless-screenshot one that holds an image bounded by its whole written form, a text-only one by its text), carrying ids, names, masked values and the snapshot text by the crossing and, since 2026-10-12-headless-screenshot, the screen as an image — an accepted `screenshot` an `image` block (the base64 PNG, `image/png`) then a text block, the shot's line without `png`, a password input in it painted masked — the pixels in band, ratified by the founder (2026-10-12), what a client does with it, a model provider included, being the client's, and since 2026-10-12-self-description the `help` tool's and the session errors' fixed table text, the program's own `'static` text inside the ratified carrier (ratified by the founder, 2026-10-12) — in the one live trial that content reached the model provider through the client; `serde_json` reads requests and writes nothing; no panic path outside the tests (a probe, count 0).
- **Driver command schema (an external-input surface since 2026-10-10-driver-cli)** → `escher_driver::validate` checks a call against a closed table of eleven verbs in three levels — seven asked of the held instance, `scroll` the sixth, a widening ratified by the founder (2026-10-07), and `screenshot` the seventh since 2026-10-12-headless-screenshot (one optional `id`; result fields `width` and `height`, counts, and `png`, base64 text — the screen's pixels in band, ratified by the founder, 2026-10-12), and three asked of the session, `start` · `status` · `stop`, a further widening ratified by the founder (2026-10-10), and, since 2026-10-12-self-description, one asked of the tool itself, `help` (no argument; its seven result fields fixed table text), a further widening ratified by the founder (2026-10-12), which `validate` refuses as `unknown-verb` and `validate_session` checks — and six argument kinds with bounds (`id` 1 to 1024 bytes, `text` 0 to 4096, `key` one of twelve names, `flag`, `milliseconds` 1 to 60000, `name` 1 to 32 bytes of `a-z0-9-`) and returns a typed command or a typed `Refusal` in one fixed order, before anything runs and with no panic path on what a call supplies; it receives no `Session`, so a refused call changes nothing; a refusal is one of nine causes with fixed texts (the ninth, `fonts-unavailable`, since 2026-10-12-headless-screenshot) and holds nothing of the call. After `validate` the executor refuses with nothing run and the instance unchanged: an id the screen does not read as `stale` or `not-found`, and a `click` or a `type` on a target that cannot take it as `disabled`, then `off-screen`, then `covered`; since 2026-10-12-headless-screenshot a `screenshot` of an app with no font it can paint text with is refused `fonts-unavailable` before anything is painted, and one whose crop to the visible part of its element's bounds holds no pixel is refused `off-screen`, every refused shot leaving the instance unchanged. To tell `stale` from `not-found` the session keeps a record of id text — at most 4096 ids, session-lived, private, never printed or logged, fed from its own snapshots only; the bound counts ids, and an id longer than 1024 bytes is not recorded. Three surfaces reach the schema from outside the process, each through `validate` first — the socket's `call` request, run by a host through `Session::run` and nothing else, the `escher-session` command line, and since 2026-10-10-mcp-surface an MCP `tools/call`, run by the MCP server through `Session::run` (session verbs and `help` through `validate_session`, answered by the server itself). `Command`, `Call` and `ArgValue` print an id and typed text under `Debug`: never log or field them. A refusal and a session error each have one written form, JSON built from fixed strings, holding nothing a call supplied. The crate's log records are two spans — since 2026-10-10-mcp-surface the `tool_call` span of an MCP tool call, holding `tool` and `ending` only, closed words (ratified by the founder, 2026-10-10), the parent of — the command span of `Session::run` — target `escher_driver`, name `command`, eight fields of fixed words, bools and counts (`verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`) — which a sink prints at `info` or below; of a refusal only its cause's fixed name is fielded, and of a shot never its image, its size or its dimensions (a `screenshot` records `verb` and, refused, `cause`).
- **rdme markdown** → comrak with `unsafe: true` passes raw HTML through.
- **CI** → post-results workflow checks out trusted scripts from the default branch; `ci.yml` declares a workflow-level `permissions: contents: read` with no job grant, pins every action to a commit SHA and references no secret. The publish (signing), WPT and post-results jobs carry `github.repository == 'DioxusLabs/blitz'`, so no fork ref reaches "Signed Builds", "WPT" or their secrets.
