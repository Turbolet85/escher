## Harness contract (§3)

- **Tool:** Rust tests in `tests/blitz-tests` over the AccessKit tree — `build_accessibility_tree()` (or `Document::accessibility_tree()`, which a `DioxusDocument` enriches with each element's stable id as `author_id`) after `resolve`, `test_that` matchers on `role()` / `is_hidden()`, `assert_role(html, id, expected)` and `unknown_tags(html)` helpers; since 2026-10-17-upstream-sync-engine-debts two upstream files assert the builder's name and description reads off the built tree with `verify_that!` — `accessibility_label` (10 tests: `aria-label`, `aria-labelledby` and its precedence, fallback and hidden targets) and `accessibility_description` (3: `aria-description`, `aria-describedby` in order, targets outside the tree excluded) — in the workspace test leg and per package, outside the a11y leg's six files; beside them `accessibility_merged_states` (3: the merged `aria-expanded`, `aria-disabled` and `aria-level`, each a stated table with its count asserted), `inert_subtree` (4) and `accessibility_active_descendant_unread` (1) assert the builder off the built tree in both layout modes, in the same legs and outside the a11y leg.
- **Focus harness:** `Harness::focused()` / `hovered()`.
- **Keyboard harness:** a Tab and Shift+Tab key-press focus check exists on the stand, driven through the harness's `press` / `press_with` (`stand_snapshot_state.rs`); since 2026-10-13-range-input-interaction a range-input key and click check runs in both layout modes (`range_input_interaction.rs`: a 7-row keys table and a 5-row clicks table, one `input` per change and none on a no-change Home, the input focused after every click, a disabled range taking neither keys nor a click), and on the stand `stand_act_range.rs` moves the Timer slider through the driver by click and key, an arrow step after two Tabs leaving it focused with role `Slider`, its name and the forward focus sequence unchanged; since 2026-10-13-stand-keyboard-harness `stand_keyboard.rs` drives Tab, Shift+Tab, Enter, Space and the CRUD list's keys headlessly on the four lean tasks through the same `press` / `press_with`, reading the focused node back per step, in both layout modes.
- **Contrast harness:** built since 2026-10-13-stand-contrast-harness — `Harness::text_contrast` (blitz-test-harness, read-only) reads an element's text/background pair and font metrics from computed styles as a `TextContrast` (`ratio` by `contrast_ratio`, the WCAG 2.x formula restating blitz-paint's Chrome-matching helper; `required_ratio` 3.0 for large text, else 4.5); `stand_contrast` states three tables, read by one shared reader and asserted row for row in both layout modes — the 18 control rows beside a painted-pixel witness (pass 14, fail 0, exempt-inactive 3, no-text 1: since 2026-10-14-stand-a11y-assertions the stand's accent is one step darker, the operator's F5, a stand change and no engine change, so the five accent controls read `#ffffff` on `#3a5ce5` at 5.47 where `#4a6cf7` read 4.39 and failed), 14 `TEXT_ROWS` (the CRUD list rows and the text outside the controls, all pass) and 19 `STATE_ROWS` (the colour states reached by input, hover and active included: pass 18, exempt 1) — so SC 1.4.3 is met on every measured non-exempt stand row; it runs in the workspace `test` leg, per package and, since 2026-10-14-stand-a11y-assertions, in the `a11y` leg.

## Engine behaviour (measured)
- Roles: `role` attribute → HTML-AAM mapping → `Role::Unknown`; landmarks, lists, tables, form inputs by `type`, links only with `href`.
- Hidden: `hidden` / `display:none` / `visibility:hidden` exclude the subtree; `aria-hidden` marks hidden; an element carrying `inert` is excluded with its subtree too, and so from the snapshot, and a hit passes through it, removing `inert` restoring the tree and the hit (the `inert` read ratified by the founder, 2026-10-18).
- State (since 2026-10-10-snapshot-states): the builder reads `aria-selected`, `aria-pressed` and `aria-invalid` by value on every element — trimmed, lower-case, exact — onto the node's `selected`, `toggled` (`mixed` kept) and `invalid` (a value outside the list reads True); `aria-pressed` sets `toggled` on every role but the five checkable ones, and `aria-checked` `true` / `false` / `mixed` sets it on a `CheckBox` · `Switch` · `RadioButton` · `MenuItemCheckBox` · `MenuItemRadio` role alone (`role="switch"` mapping to `Switch`), a native `input` of type `checkbox` or `radio` reading neither — the toggle read per role ratified by the founder (2026-10-18), `accessibility_states`' fourth test its pin; each attribute is read once and nothing else writes `toggled`, so the builder writes none from a native checkbox's or radio's own checked state — a measured absence, its fix owned by a `.andromeda/residuals.md` line (target: next). The snapshot takes the three from the tree as `selected` · `pressed` · `invalid`, a boolean model with two limits (a mixed toggle reads not pressed; a grammar or spelling error reads invalid). Ratified by the founder (2026-10-10); what an assistive technology reads is unmeasured, the windowed witness, at an active assistive technology, owned by a `.andromeda/residuals.md` line (target: next) on the founder's F1 (2026-10-14), the headless half — the tree the shell hands the adapter — proven on the stand since 2026-10-14-stand-a11y-assertions. Check: `accessibility_states` (5, both layout modes; outside the `a11y` leg — the fourth reading `aria-checked`'s three values on a checkable role alone and four unchecked natives reading neither attribute, the fifth `aria-pressed` on a checkable role reading nothing). Since 2026-10-17-upstream-sync-engine-debts the builder also holds upstream's six reads, as upstream wrote them: `aria-labelledby` (Names, below), `aria-describedby` (the referenced nodes as `described_by`), `aria-description` (its text into AccessKit's description), `aria-expanded` (a boolean), `aria-disabled` (`true` → `set_disabled`) and `aria-level` (a number, with the tag and role defaults); upstream's own `parse::<bool>` `aria-selected` and unfiltered `aria-label` reads were dropped in the merge, so there is still one read per attribute; the snapshot reads no description and its `enabled` reads the `disabled` attribute, so `aria-disabled` moves no snapshot reading; no stand file states any of the six, and the description and the three new closed values leave only to the platform adapter, which no stand binary builds — what an assistive technology reads of them is not measured (ratified as upstream's behaviour by the founder, 2026-10-17).
- Stand markup (attributes only): the flight booker's mode buttons state `aria-pressed`, its date inputs `aria-invalid`; the CRUD list is a `listbox` and its rows `option`s with `aria-selected`. Since 2026-10-13-stand-keyboard-harness (the operator's decision) the list `crud-list` takes `tabindex="0"` and an `onkeydown` — the third CRUD Tab stop — and, focused, ArrowDown selects the next visible row (the first when none is selected), ArrowUp the previous, Home the first and End the last, as a row's click does. One gap stands open: the rows are not focusable and the tree's focus is the list, never the option — the builder reads no `aria-activedescendant`, so an assistive technology learns the current row only from its `selected` reading; an `aria-activedescendant` read in the builder, or a roving focus, is SC 4.1.2 work outside the tier-0 target, kept unread on the founder's F2 (2026-10-14) and pinned by `accessibility_active_descendant_unread` (ratified by the founder, 2026-10-18). The second, the list's empty accessible name, closed at 2026-10-14-stand-a11y-assertions: the list is named `People` by `aria-label`.
- Focus: Tab / Shift+Tab via `focus_next_node` / `focus_prev_node`; focusability recomputed on `tabindex` / `href` / `disabled`; focus resets to body on removal; since 2026-10-13-stand-keyboard-harness, in every document (ratified by the founder), a pointer click on a `button` (any type) or an `input` of type `submit`, `reset` or `button` focuses it, then submits the form owner when it is a submit button — a disabled form control still stops the walk first, a disabled ancestor `div` not (ratified by the founder, 2026-10-18), and a click on any other element (a CRUD row, the list) still clears focus; two pointer clicks on one point within 500 ms and 2 px are a double click, read on the document's clock — on a harness-built document the harness's `VirtualClock`, so two driver `click`s on one point with no `advance` between them are a double click, selecting a word in a text input — while each still focuses its target as one click does (ratified by the founder, 2026-10-18); `:focus-visible` / `:focus-within` never match. Enter and Space (since 2026-10-13-stand-keyboard-harness, in every document, ratified by the founder): a pressed Enter on the focused node that is no disabled form control (`ElementData::is_disabled`; ratified by the founder, 2026-10-18 — a `disabled` attribute on a `summary` or an `a` gating neither key, as HTML does) dispatches a Click on a `button`, a `summary`, an `input` of type `submit`, `reset` or `button`, or an `a` with `href`; a released Space (`handle_key_up`) dispatches the same Click on a `button`, a `summary`, or an `input` of type `submit`, `reset`, `button`, `checkbox` or `radio` — a link takes no Space, and a text input and a range input take neither key there; the Click (`Node::synthetic_click_event_data`) runs the app's handlers (a Dioxus `onclick`), then `handle_click`. Range input (since 2026-10-13-range-input-interaction, in every document, ratified by the founder): focused and with no `disabled` attribute (read by presence), it steps up on ArrowRight/ArrowUp, down on ArrowLeft/ArrowDown, goes to its minimum on Home and its maximum on End, every other key doing nothing — each change marks the changed set and fires one `input`, a move that changes nothing none; a click focuses it without moving its value, and a main-button pointerdown sets the value from the hit's fraction of the content box, clamped to [0, 1].
- Disabled-ness is keyed one way since 2026-10-13-stand-keyboard-harness (in every document, ratified by the founder): the `DISABLED` state (`:disabled`) reads the attribute's presence, and the pointer-move gate, `ClickTarget::Disabled`, `handle_click`'s walk gate, the Enter and Space activation and focusability read `ElementData::is_disabled` — that presence on a `button`, `input`, `select` or `textarea` alone (ratified by the founder, 2026-10-18) — so `disabled="false"` and a bare `disabled` on a form control match `:disabled` and are not focusable, a bare `disabled` set after creation takes its focusability away, and a `<div disabled tabindex=0>` takes focus. dioxus-native-dom removes a falsy value of its 28 boolean attributes — upstream's `is_bool_attr` predicate since 2026-10-13-upstream-sync-polish-and-ship (`disabled`, `checked`, `hidden`, `inert` among them; a framework-written `inert: false` is removed, while a truthy `inert` (by presence on itself or an ancestor element) takes focusability, hits and the tree away from its subtree (ratified by the founder, 2026-10-18) and Tab reaches the buttons under `inert: false`; HTML's focus fixup is not built, so a node that holds focus when it becomes inert keeps it until focus moves, its fix owned by a `.andromeda/residuals.md` line (target: next)), so a `hidden: false` element stays displayed, in the tree and in the snapshot; an attribute outside the list holding `false` is still written as `"false"`. The snapshot reads `enabled` by presence — the driver's `disabled` refusal cause is stated on the same presence reading ("the element carries the `disabled` attribute, which the snapshot reads as not enabled") and is detected on it and on nothing else: the driver refuses a `click` or a `type` as `disabled` when the snapshot reads the element not enabled, with nothing dispatched and focus as it was, and acts on the same control once it reads enabled (`stand_act_disabled.rs`), and the driver's schema defines no role or name set of its own — `checked` a native checkbox's or radio's state, else, on a checkable role, the node's `toggled` reading (`True` true, `False` and `Mixed` false; ratified by the founder, 2026-10-18), and `value` from the element (a range input's `value` its current value since 2026-10-13-range-input-interaction — `ElementData::range_input_value`, the formatted value a key or a pointerdown moved, while its `value` attribute keeps the boot value; a password or file-input value reads the fixed mask `MASKED_VALUE` — and, since 2026-10-12-headless-screenshot, a password's typed text is in no painted frame either: blitz-paint paints its value as bullets, its caret at the bullet of its caret index, in every document and through every renderer that paints with blitz-paint, windowed included (ratified by the founder, 2026-10-12), two values of one length painting byte-identical frames, focused or not, in both layout modes (`password_painted_masked.rs`); a click inside a field holding a value places the caret by the bullets — `click_password_input` lays out one U+2022 per character through `BaseDocument::layout_as_text_input`, finds the bullet under the point and moves the real editor to that character, so no width of the real characters reaches the caret: two values of one length read one index, in both layout modes (`password_caret_click.rs`; ratified by the founder, 2026-10-18); the windowed paint is not run; a textarea's typed text reads back as its `value`, proven on an in-file fixture where it is named by `aria-label`), and `focused` from the tree — proven after a click, a Tab press and Shift+Tab (`stand_snapshot_state.rs`). The snapshot's text form (`Snapshot::to_text`) reads that model, never the tree or a control: one line per node, its role and name the node's, with no second mapping (`stand_snapshot_text.rs`). The snapshot's diff (`Snapshot::diff`) is one more reader of that model: a text change is reported on the element whose accessible name it changes, by its id and never as a text-run entry, a hidden element leaves and returns with its descendants, and a focus move names exactly the controls whose `focused` reading moved (`stand_diff.rs`). Since 2026-10-10-mcp-surface an MCP tool result is one more reader of that model and of nothing else — a `snapshot` result is `to_text`'s output itself, equal byte for byte to `Session::run`'s screen text in both layout modes (`stand_mcp_tools.rs`), its crossing to an MCP client ratified by the founder (2026-10-10). Since 2026-10-12-self-description a password input typed through an MCP `type` reads `MASKED_VALUE` in the tool result, role `PasswordInput` and a non-empty name, the typed text in neither result, in both layout modes — a test-only element of `stand_mcp_masked.rs`'s fixture, no stand task or app gaining one; and two further readers of the same model state closed words only: the node keys' help that `help` serves (each key's reading, the boolean model's two limits among them) and `DiffNode::differs`, a changed node naming the readings that differ from before the step in node-key order — the Flight Booker's Book names eight nodes — seven that only moved, each `differs` = `[bounds]`, and since 2026-10-13-stand-keyboard-harness `flight-book` itself, which the click now focuses, `differs` = `[focused, bounds]` (`stand_diff.rs`).
