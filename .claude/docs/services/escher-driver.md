# escher-driver

_Crate notes. Primary source: `.andromeda/architecture.md` §Standard Contracts Driver session, §Occupied Resources and [Driver session]; the lifecycle checks' contract is test-plan §3 → Session lifecycle (`.andromeda/registries/contracts/test-plan/session-lifecycle.md`); the schema's input rules are security-plan §Input Validation (the Driver command schema row)._

## Responsibility
The driver's core (unpublished, no `[features]` of its own, no binary): a **session** — one headless app instance held by one process while commands arrive — the **command and refusal schema**, the one definition of what can be asked of the driver and of how it says no, and the **executor** that runs a call on the held instance. It is app-agnostic: the caller supplies the boot and the time step, and the crate names no app and no stand type. A call runs **in process**: `Session::run` validates it, looks its target up on the screen, refuses a target that cannot take the action, runs its verb, settles the instance and returns a typed `Outcome`. Nothing of the schema, of a call or of an outcome crosses the socket. A verb or a settle verb on the socket, CLI JSON and an MCP tool are later route entries.

## Key integrations

### Consumes from
- `blitz-test-harness` (`Harness`, and its re-exports `Key` and `Modifiers` — the crate has no third dependency) and `dioxus-native-dom` (`DioxusDocument`, `SnapshotDiff`) with its `accessibility` feature named, unconditionally: the executor reads the snapshot, which stands behind that feature. Through `seven_guis → escher-driver` both seven_guis binaries therefore compile dioxus-native-dom's accessibility modules; neither builds a platform adapter.
- `std` only for the socket (`std::os::unix::net`), the spawn and the file modes. No `tracing`, no env read, no clock read, no default state location, and no serialization crate — the schema is Rust data; producing JSON from it is the serving surface's step.

### Publishes to
- `Session::start(label, boot)` — the label is 1 to 32 bytes of `a-z`, `0-9`, `-`, checked BEFORE the boot runs (`InvalidLabel`, nothing booted); the boot runs once on the calling thread; `label()`, `harness()`, `harness_mut()`.
- `Session::with_time(step)` — returns the session carrying its caller's time step: a closure handed the held harness and the milliseconds an `advance` asks for, returning the milliseconds the app moved. A session started without it carries none.
- `Session::act(step) -> Result<Settled, SessionError>` — runs the closure on the held instance, then settles it (`Harness::settle`): on `Ok` everything the step made due is on the screen; an instance that does not go quiet is `NotSettled(Busy)`. The step is not rolled back, and no time is advanced. `Busy` and `Settled` are re-exported from blitz-test-harness.
- `Session::run(&Call) -> Result<Outcome, Refusal>` — the one entry point that runs a call. `validate` first: a refused call has run nothing. Then per verb: `snapshot` returns the screen's text (`Snapshot::to_text`) and dispatches nothing; `click`, `type` and `scroll` look their id up on the screen as it reads NOW (the snapshot lists it, and the first `element_ids()` pair with it resolves through `get_node`) — an id that names no element there is refused with nothing run, `stale` when the session's record of ids read holds it, `not-found` when not. A `click` or a `type` on an element that cannot take it is then refused, one answer in a fixed order: `disabled` (the snapshot reads `enabled: Some(false)`), `off-screen` (the centre of its `bounds` is outside `BaseDocument::visible_region` — the viewport and every scrolling box that holds it), `covered` (the hit at that page point never reaches it). Otherwise they click the centre of the element's snapshot `bounds` plus the viewport's scroll, `type` typing after that click; `press` presses its key on what holds focus (shift when asked); `advance` hands its milliseconds to the session's time step — `time-unavailable` when the session carries none; `scroll` applies none of the three checks, scrolls every scrolling box that holds the element and then the viewport, at once (`Harness::scroll_into_view`), and answers `in_view` — false when no scroll could bring it into view; it is never refused for that. Each acting verb is one settled step: snapshot, step, `Harness::settle`, snapshot, diff. A refused call leaves the snapshot and both focus readings as they were.
- `Outcome` — `Screen { text }` · `Acted { settled, busy, diff }` · `Advanced { settled, busy, diff, advanced_ms }` · `Scrolled { settled, busy, diff, in_view }`; `diff` is dioxus-native-dom's `SnapshotDiff`, unchanged. An instance that did not go quiet is a result (`settled: false` with its `Busy` class), never a refusal and never a `SessionError`; the step is not rolled back. `advanced_ms` is the lesser of the step's return and the `ms` asked: the time delivered to the app, not what a counter inside it gained.
- `serve(state_dir, session)` — hosts one session until a `stop` request, on the calling thread (the instance is not `Send`): creates the state directory `0700` (a present one open to group or others is `StateDirNotPrivate`), binds `session.sock` and sets it `0600`, replaces a socket nothing answers on, reads `AlreadyRunning` when one answers, and on `stop` drops the session and removes the socket file and the directory — non-recursively, nothing else.
- `start(state_dir, host, ready)` → `Started { child, hello }` · `attach(state_dir)` → `Hello { pid, label, served }` · `stop(state_dir)` (waits up to 5 s for the directory to go).
- `SessionError`: `AlreadyRunning` · `NoSession` · `Dead` · `HostExited(code)` · `Timeout` · `Protocol` · `InvalidLabel` · `StateDirTooLong` · `StateDirNotPrivate` · `Unsupported` · `Io(kind)` · `NotSettled(Busy)` — fixed messages (the last two append a kind or class name), never a path, label, id or value.
- `VERBS` — the verb table, six verbs in order: `snapshot` (no argument; result `text`), `click` (`id`), `type` (`id`, `text`), `press` (`key`, optional `shift`), `advance` (`ms`), `scroll` (`id`; the sixth, ratified by the founder, 2026-10-07); each a `VerbSpec { name, help, args, fields }`; `verb(name)` finds one by its exact name only. Argument kinds and bounds (`ArgKind`): `id` 1 to `MAX_ID_BYTES` (1024) bytes of text · `text` 0 to `MAX_TEXT_BYTES` (4096) bytes · `key` one of the twelve `KEY_NAMES` · `flag` · `milliseconds` 1 to `MAX_MILLISECONDS` (60000). The acting verbs' result: `settled`, `busy` (one of `BUSY_CLASSES`, only when not settled), `added`, `removed`, `changed` (nodes carry the `NODE_FIELDS`); `advance` adds `advanced_ms`, `scroll` adds `in_view` (always present).
- `validate(call: &Call) -> Result<Command, Refusal>` — a `Call` is a verb name and named `ArgValue`s (`Text` · `Number` · `Flag`); it receives no `Session`, so a refused call changes nothing. One answer per call, the first failure in this order: the verb by exact name (`unknown-verb`), then the call's arguments in the order passed (a name the verb lacks, a name passed twice), then the verb's arguments in the schema's order (missing, wrong kind, outside its bound) — the last five are `malformed` with a `Fault` naming the rule. `Command` is `Snapshot` · `Click` · `Type` · `Press` · `Advance`, and `Command::spec()` is its verb's row.
- `Refusal` — a `Cause` and, only beside `malformed`, a `Fault`. `CAUSES` is closed at eight: `unknown-verb` · `malformed` · `not-found` · `stale` · `disabled` · `covered` · `off-screen` · `time-unavailable`, each with a fixed `name()`, `meaning()` and `remedy()`. None of `Cause`, `Fault`, `Refusal` has a `String` field: a refusal holds nothing a call supplied. All eight are returned today — `unknown-verb` and `malformed` by `validate`, the other six by the executor. `off-screen`'s meaning and remedy were reworded at 2026-10-07-refusal-detection, each on a recorded word: the remedy names `scroll`, the meaning covers a scrolling box. On the stand a click is accepted on 70 of the 77 snapshot nodes at boot and refused on 7: the three disabled controls, and each task's `task-header-spacer` as `covered` (a box 0 high; the hit at its centre answers the header).
- Consumed by seven_guis (the `escher-session` host binary, native target only — it hands the Timer's session the stand's time step) and by blitz-tests (dev-dependency), whose nine `stand_act_*` checks drive the schema through `Session::run`.

## Internal conventions
- The wire (`wire.rs`, crate-private, versioned `v1`) is one request line and one reply line per connection: `hello v1` → `ok v1 pid= label= served=`, `stop v1` → `ok v1 stopping`, another version of a known word → `refused version`, anything else → `refused malformed`. Requests are bounded at 64 bytes, replies at 128, each read and write at 2 s. **Nothing of the screen crosses it** — the first request that carries an id, a name, a value, snapshot text or a diff is a new crossing question for the operator.
- `served` counts every request answered, refusals included; a refusal or a broken connection changes nothing; a `stop` takes effect once its reply is written.
- Unix only: on other targets `serve`, `start`, `attach` and `stop` return `Unsupported`; a `Session` held in process works everywhere — `run` included. The schema's three modules (`command`, `refusal`, `schema`) carry no `cfg` gate; `execute` carries the crate's one, the macOS arm of `press`.
- The schema is the one table every later surface reads — the actions, the span's cause field, the CLI, the MCP tools, the self-description: a later entry ADDS its verbs to `VERBS` at its own promotion, never states a second table. A cause's texts are fixed and reworded only with a recorded reason.
- No panic path on anything a call supplies: no `unwrap`, `expect`, `panic!`, `unreachable!` or index in `validate` or in the executor; the executor never calls `Harness::layout_rect_of`, which panics on a node that does not resolve.
- No `NodeId` outlives a call, and no field of `Session`, `Outcome` or `Refusal` holds one. What the session keeps is a record of the ids its screens have read, to tell `stale` from `not-found`: id text only, in a crate-private `SeenIds` bounded at `MAX_SEEN_IDS` (4096 ids — a count, not the 4096 bytes of `MAX_TEXT_BYTES`), least recently read forgotten first, fed from the session's own snapshots, with no public reader; never print, log or field it. Nothing bounds a recorded id's length (owned by a route entry). No step reads or drains the changed set — the diff is two snapshots and `Snapshot::diff`.
- Settling moves no time and waits on no load: time on a held instance moves only by `advance`, through the caller's step; no driver command waits on a load (the operator, 2026-10-07).

## Crate-specific gotchas
- A Unix socket address leaves about a hundred bytes for the whole path (108 on Linux, 104 on macOS): keep a state directory's name short; an over-long one is `StateDirTooLong`.
- There is no idle expiry: a host whose client died without `stop` keeps running (owed by the "Driver CLI" entry).
- `start` does not check that the answering pid is the child it spawned.
- The `Io` message is spelled "input or output" — "I/O" holds a `/`, and the messages are asserted to hold none.
- A test's working directory is its package: build a check's state directory from `env!("CARGO_TARGET_TMPDIR")`, never from a relative path.
- Two `Command`s meet at the crate root: the schema's `Command`, and the `std::process::Command` that `start` takes. A grep for `Command` over the crate reads both.
- `Command`, `Call` and `ArgValue` derive `Debug`, which prints the id and the typed text they hold, and `Outcome` derives it too, printing the ids, accessible names and control values of its diff: never field one with `?` in a span or a log, and never field an argument by its schema name (of the names only `text` is in the sink's scrub set).
- In `command.rs` an assertion over a call carries a row index only (`assert!(a == b, "row {row}")`), never `assert_eq!` on a call or a command — a failing leg's log is uploaded as a CI artifact. The `stand_act_*` checks keep the same rule: a message names a layout mode, a task and an index.
- `type` focuses by a click at the centre of the control, so in a text input that already holds text the caret lands where the click falls; what `type` should do to existing text is not decided.
- On macOS the editor's Backspace arm is compiled out — a window delivers the delete as a standard key binding — so `press backspace` also dispatches `deleteBackward:` there (`Harness::apple_keybinding`). The macOS CI leg is that arm's one witness.
- A click on a range input is accepted and does not focus it, and no key moves its value: through the six verbs a range input cannot be changed (measured on the stand's Timer; a route entry owns the engine's range interaction model).
- With the settle removed only `advance` reads wrong on the stand: `click`, `type` and `press` each ride an input helper's own pump. The settle's second-pass cases are `stand_settle`'s.

## Tests
- 26 unit tests (`wire.rs` 8 · `session.rs` 2 · `error.rs` 3 · `refusal.rs` 3 · `schema.rs` 4 · `command.rs` 5 · `execute.rs` 1) — they need no app, and for that reason none builds a held instance: the executor's unit test is its key table. The schema's twelve state every table in the test and assert its row count; four mutation controls are recorded in `escher-0.1.0/chunks/2026-10-07-command-and-refusal-schema/evidence/controls.md`.
- The executor, over the stand, in blitz-tests — nine files, 27 tests, both layout modes: `stand_act_ids` (one id read by the snapshot, the accessibility tree and the driver, a click accepted on 70 nodes and refused on the 7 stated; an id-addressed click equal to a selector click on a twin), `stand_act_diff` (the returned diff of a step; the masked password), `stand_act_timer` (`advance`, the settled Timer flow, `time-unavailable`, the clamp), `stand_act_refused` (a refused call changes nothing; `stale` told from `not-found`), `stand_act_keys` (focus moves; the one deleting-key check), `stand_act_range` (the range input's measured reading), `stand_act_disabled` (a control refused while not enabled, acted on once enabled), `stand_act_obstructed` (`covered` and `off-screen` on in-file fixtures; the order where two causes hold) and `stand_act_scroll` (a CRUD row past its list refused, scrolled into view, clicked; a fixture no scroll can reach). Mutation controls are recorded in `escher-0.1.0/chunks/2026-10-07-act-by-id/evidence/controls.md` (five) and `escher-0.1.0/chunks/2026-10-07-refusal-detection/evidence/controls.md` (nine).
- The session, over the stand: `stand_session_state` · `_ids` · `_fresh` (a session held in process), `stand_settle` (`act`: a Timer step returning with its delayed update present, an idle step changing nothing, `NotSettled(Render)` at the bound) and `stand_session_lifecycle` · `_quiet` (a host process: the test binary re-run on an `#[ignore]` child); seven_guis' `host_binary` drives the real `escher-session` binary on `counter`, and `host_log` reads its stderr on `crud` at `RUST_LOG=trace`. No standing check boots the host on `timer`, the one task whose session carries a time step. `stand_session_quiet`'s host installs no log sink, so it proves nothing about a host that does — `host_log` is the check that does.
