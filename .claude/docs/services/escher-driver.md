# escher-driver

_Crate notes. Primary source: `.andromeda/architecture.md` §Standard Contracts Driver session and CLIs, §Occupied Resources and [Driver session]; the lifecycle checks' contract is test-plan §3 → Session lifecycle (`.andromeda/registries/contracts/test-plan/session-lifecycle.md`); the schema's and the command line's input rules are security-plan §Input Validation (the Driver command schema, Driver session socket and CLI arguments rows)._

## Responsibility
The driver's core (unpublished, no `[features]` of its own, no binary): a **session** — one headless app instance held by one process while commands arrive — the **command and refusal schema**, the one definition of what can be asked of the driver and of how it says no, the **executor** that runs a call on the held instance, since 2026-10-10-driver-cli the **command line** that carries a call out of the process, and since 2026-10-10-mcp-surface the **MCP server** that serves the eleven verbs as MCP tools over a caller's reader and writer (the `escher-session mcp` role), and since 2026-10-12-self-description the **self-description** (`describe`) that `help` answers on both surfaces. It is app-agnostic: the caller supplies the boot and the time step, and the crate names no app and no stand type. `Session::run` validates a call, looks its target up on the screen, refuses a target that cannot take the action, runs its verb, settles the instance and returns a typed `Outcome` — for a call made in process, and for one a host decoded from its socket. A call and its answer cross the socket (ratified by the founder, 2026-10-10), and an MCP client's stdio (ratified by the founder, 2026-10-10, «Ратифицировать как есть»). A settle verb on the socket is a later route entry.

## Key integrations

### Consumes from
- `blitz-test-harness` (`Harness`, and its re-exports `Key`, `Modifiers` and, since the 2026-10-17 upstream sync's keyboard-types 0.8, `NamedKey` — `keyboard_key` maps each of the 11 named keys to `Key::Named(NamedKey::…)`, Space staying `Character(" ")`, and the macOS `ACTION_MODIFIER` reads `Modifiers::META`; the key types are no dependency of their own), `dioxus-native-dom` (`DioxusDocument`, `SnapshotDiff`) with its `accessibility` feature named, unconditionally: the executor reads the snapshot, which stands behind that feature — `tracing` (the workspace's, no feature, no `[features]` table), for the `command` span and, since 2026-10-10-mcp-surface, the `tool_call` span — and, the fourth dependency since 2026-10-10-mcp-surface, `serde_json` (the workspace's, no feature), the reader of MCP requests only (the founder, 2026-10-10, «serde_json, только чтение»); it was already in both graphs through dioxus-html, so the lock changed by one line and no package — and, the fifth since 2026-10-12-headless-screenshot, `png` (the workspace's, no feature, resolved 0.18.1, already in the graph — no package entered `Cargo.lock`), the encoder of a shot, its base64 written by hand with no crate taken for it. Through `seven_guis → escher-driver` both seven_guis binaries therefore compile dioxus-native-dom's accessibility modules; neither builds a platform adapter.
- `std` only for the socket (`std::os::unix::net`), the spawn (`std::env::current_exe()` for the `start` command), the file modes and the host's idle clock. No env read and no default state location; the schema is Rust data and every answer's JSON is written by hand in `json.rs` — `serde_json` reads MCP requests and writes nothing. The executor, the session, the schema, the validation, the JSON writer and, since 2026-10-12-headless-screenshot, the private `image` encoder read no clock or environment and print nothing; the host reads one for its idle expiry, and the MCP server one when a request arrives with a session held.

### Publishes to
- `Session::start(label, boot)` — the label is 1 to 32 bytes of `a-z`, `0-9`, `-`, checked BEFORE the boot runs (`InvalidLabel`, nothing booted); the boot runs once on the calling thread; `label()`, `harness()`, `harness_mut()`.
- `Session::with_time(step)` — returns the session carrying its caller's time step: a closure handed the held harness and the milliseconds an `advance` asks for, returning the milliseconds the app moved. A session started without it carries none.
- `Session::act(step) -> Result<Settled, SessionError>` — runs the closure on the held instance, then settles it (`Harness::settle`): on `Ok` everything the step made due is on the screen; an instance that does not go quiet is `NotSettled(Busy)`. The step is not rolled back, and no time is advanced. In process only. `Busy` and `Settled` are re-exported from blitz-test-harness.
- `Session::run(&Call) -> Result<Outcome, Refusal>` — the one entry point that runs a call. `validate` first: a refused call has run nothing, and a session-level verb (`start`, `status`, `stop`) is refused `unknown-verb`. Then per verb: `snapshot` returns the screen's text (`Snapshot::to_text`) and dispatches nothing; `click`, `type`, `scroll` and, since 2026-10-12-headless-screenshot, a `screenshot` given an `id` look their id up on the screen as it reads NOW (the snapshot lists it, and the first `element_ids()` pair with it resolves through `get_node`) — an id that names no element there is refused with nothing run, `stale` when the session's record of ids read holds it, `not-found` when not. A `click` or a `type` on an element that cannot take it is then refused, one answer in a fixed order: `disabled` (the snapshot reads `enabled: Some(false)`), `off-screen` (the centre of its `bounds` is outside `BaseDocument::visible_region` — the viewport and every scrolling box that holds it), `covered` (the hit at that page point never reaches it). Otherwise they click the centre of the element's snapshot `bounds` plus the viewport's scroll; `type` then replaces what the control holds — where the snapshot reads a `value` for the target (an empty text input reads one) it presses the engine's select-all (`a` with Control, Super on macOS) and types, and with an empty text deletes the selection, so an empty text clears; `press` presses its key on what holds focus (shift when asked) — since 2026-10-13-stand-keyboard-harness a pressed `enter`, or a `space`, on a focused button with no `disabled` attribute dispatches its click (the engine's keyboard activation, [Scrolling and input]); `advance` hands its milliseconds to the session's time step — `time-unavailable` when the session carries none; `scroll` applies none of the three checks, scrolls every scrolling box that holds the element and then the viewport, at once (`Harness::scroll_into_view`), and answers `in_view` — false when no scroll could bring it into view; it is never refused for that; `screenshot` (since 2026-10-12-headless-screenshot) dispatches nothing and is no step — with no `id` it returns the whole screen, with an `id` it crops the frame to the part of the element's bounds that can be seen, rounded outward to whole pixels, a crop of no pixel refused `off-screen`; an app whose font context resolves no `sans-serif` family (`BaseDocument::can_paint_text` false) is refused `fonts-unavailable` with nothing painted; the frame is the harness's `screenshot`, written as a PNG by the private `image::png`, and a shot changes nothing (`has_changes` stays false, focus and the next snapshot unchanged). Each acting verb is one settled step: snapshot, step, `Harness::settle`, snapshot, diff. A refused call leaves the snapshot and both focus readings as they were.
- `Outcome` — `Screen { text }` · `Acted { settled, busy, diff }` · `Advanced { settled, busy, diff, advanced_ms }` · `Scrolled { settled, busy, diff, in_view }` · `Shot { width, height, png }` (the last since 2026-10-12-headless-screenshot); `diff` is dioxus-native-dom's `SnapshotDiff`, unchanged. An instance that did not go quiet is a result (`settled: false` with its `Busy` class), never a refusal and never a `SessionError`; the step is not rolled back. `advanced_ms` is the lesser of the step's return and the `ms` asked: the time delivered to the app, not what a counter inside it gained.
- Written forms — `Outcome::to_json`, `Refusal::to_json`, `SessionError::to_json`: one line of JSON each, keyed by the schema's own words, output only. An outcome is an object keyed by its verb's result fields in the table's order (`busy` only when not settled); a node is keyed by `NODE_FIELDS` in order — thirteen keys: `id` · `parent` · `role` · `name` · `enabled` · `checked` · `value` · `selected` · `pressed` · `invalid` · `focused` · `bounds` · `differs` (since 2026-10-12-self-description; written on a changed node only, after `bounds`: the node-key words whose reading differs from before the step, a node that only moved reading `bounds` alone, an added node written without it) — with `parent`, `enabled`, `checked`, `value`, `selected` and `pressed` left out when absent, `invalid` always written, `bounds` four numbers; a refusal is `{"refused":{"cause","meaning","remedy"[,"fault"]}}`; a session error `{"error":{"kind","message","remedy"}}` (the remedy since 2026-10-12-self-description); a `screenshot`'s outcome `{"width":…,"height":…,"png":"<base64>"}` (since 2026-10-12-headless-screenshot), the PNG's base64 written by hand in the private `image::base64` (RFC 4648 §4, padded) — no base64 crate taken; `start` answers `label`, `pid`, `idle_expiry_s`, `status` adds `served`, `stop` answers `{"stopped":true}`.
- `serve(state_dir, session, idle_expiry)` — hosts one session until a `stop` request or until no request has been answered for `idle_expiry` (`IDLE_EXPIRY`, 1,800 s, is what a command line's host serves under), on the calling thread (the instance is not `Send`): creates the state directory `0700` (a present one open to group or others is `StateDirNotPrivate`), binds `session.sock` and sets it `0600`, replaces a socket nothing answers on, reads `AlreadyRunning` when one answers, runs a `call` request through `Session::run` and nothing else, and at the end drops the session and removes the socket file and the directory — non-recursively, nothing else.
- `start(state_dir, host, ready)` → `Started { child, hello }` · `attach(state_dir)` → `Hello { pid, label, served, idle_expiry_s }` · `stop(state_dir)` (waits up to 5 s for the directory to go) · `call(state_dir, &Call)` → `Answer { accepted, json }` — it validates first, so a call the schema refuses is answered there and reaches no session; the answer is read under 30 s per read (`Timeout` past it; pinned since 2026-10-14-quality-gates by the unix-only unit test `client::imp::tests::an_answer_read_past_its_bound_is_a_timeout`, which reads the bound equal to `wire::ANSWER_BOUND` and a read past a shortened bound on a listener that never answers as `Timeout`).
- `SessionError`, thirteen: `AlreadyRunning` · `NoSession` · `Dead` · `HostExited(code)` · `Timeout` · `Protocol` · `InvalidLabel` · `StateDirTooLong` · `StateDirNotPrivate` · `Unsupported` · `Io(kind)` · `NotSettled(Busy)` · `AnswerTooLarge` (a call's answer over the socket's bound — the call ran) — fixed messages (`Io` and `NotSettled` append a kind or class name), never a path, label, id or value; `kind()` is one fixed kebab-case word per variant and, since 2026-10-12-self-description, `remedy()` a fixed remedy: each variant's kind, meaning and remedy are one row of the crate-private `SESSION_ERRORS: [ErrorSpec; 13]` (`ErrorSpec { kind, meaning, remedy, repeats }`, `repeats` not served), which `kind()`, `remedy()` and `Display` read; `dead` repeats `no-session`'s remedy and `answer-too-large` `not-settled`'s; `StateDirTooLong`'s message states its bound as a figure — at most 94 bytes as given on Linux, 90 on every other target — and its remedy is a shorter path for the state directory, or a relative one.
- `VERBS` — the verb table, eleven verbs in three levels (`Level::Instance` · `Level::Session` · `Level::Tool`, the third since 2026-10-12-self-description): `snapshot` (no argument; result `text`), `click` (`id`), `type` (`id`, `text`), `press` (`key`, optional `shift`), `advance` (`ms`), `scroll` (`id`; the sixth, ratified by the founder, 2026-10-07), `screenshot` (one optional `id`; result `width` (count), `height` (count) and `png` (`FieldKind::Png`, base64 text), all always present; the seventh, since 2026-10-12-headless-screenshot, its help stating two measured limits — an element shot is cropped to the part of its bounds that can be seen, and in a build that paints overlay scrollbars a thumb painted within 0.7 s of a scroll fades by wall time), then `start` (`app`), `status` and `stop` (session-level; ratified by the founder, 2026-10-10), then `help` (tool-level, no argument; result `verbs` · `node_keys` · `key_names` · `busy_classes` · `causes` · `exit_statuses` · `session_errors`, each field with its help; since 2026-10-12-self-description, ratified by the founder, 2026-10-12); each a `VerbSpec { name, level, help, args, fields }`; `verb(name)` finds one by its exact name only. Argument kinds and bounds (`ArgKind`): `id` 1 to `MAX_ID_BYTES` (1024) bytes of text · `text` 0 to `MAX_TEXT_BYTES` (4096) bytes · `key` one of the twelve `KEY_NAMES` · `flag` · `milliseconds` 1 to `MAX_MILLISECONDS` (60000) · `name` 1 to 32 bytes of `a-z`, `0-9`, `-`. The acting verbs' result: `settled`, `busy` (one of `BUSY_CLASSES`, only when not settled), `added`, `removed`, `changed` (nodes carry the `NODE_FIELDS`); `advance` adds `advanced_ms`, `scroll` adds `in_view` (always present); `help`'s fields are of the kinds `Words` · `Entries`, and `screenshot`'s `png` of `Png` (base64 text, since 2026-10-12-headless-screenshot) — ten `FieldKind`s. Since 2026-10-12-self-description the command line's four exit statuses are the schema's `EXIT_STATUSES: [ExitStatus; 4]` (`ExitStatus { status, name, meaning }`: `0` `accepted` · `1` `refused` · `2` `usage` · `3` `session-error`), which the command line's status constants read and `help` serves, and `describe() -> String` writes the tool's self-description, `help`'s answer, as one line of JSON from the tables alone — 11 verbs, 13 node keys, 12 key names, 3 busy classes, 9 causes and 13 session errors with their remedies, 4 exit statuses (10 verbs and 8 causes until 2026-10-12-headless-screenshot) — reading no environment and printing nothing; the command line's `help` and the MCP `help` tool serve the same bytes. The help of `changed` and of `snapshot`'s `text` say the state words and the two limits of the boolean model — a mixed toggle reads unpressed (`pressed` false), a grammar or spelling error reads invalid — so an agent learns them from the tool; since 2026-10-12-self-description `NODE_FIELDS` is `[NodeFieldSpec; 13]`, each row `NodeFieldSpec { name, help }` whose help states the key's reading — the two limits among them — and the crate docs' one sentence says each limit is stated in its node key's help and that a changed node names the keys whose reading differs (`differs`).
- `validate(call: &Call) -> Result<Command, Refusal>` — a `Call` is a verb name and named `ArgValue`s (`Text` · `Number` · `Flag`); it receives no `Session`, so a refused call changes nothing. One answer per call, the first failure in this order: the verb by exact name (`unknown-verb`; a session-level verb and, since 2026-10-12-self-description, the tool-level `help` too), then the call's arguments in the order passed (a name the verb lacks, a name passed twice), then the verb's arguments in the schema's order (missing, wrong kind, outside its bound) — the last five are `malformed` with a `Fault` naming the rule. `Command` is `Snapshot` · `Click` · `Type` · `Press` · `Advance` · `Scroll` · `Screenshot { id: Option<String> }` (the last since 2026-10-12-headless-screenshot), and `Command::spec()` is its verb's row. `validate_session(&Call) -> Result<SessionCommand, Refusal>` is the same check over the three session-level rows and, since 2026-10-12-self-description, the tool-level `help` — an instance-level verb `unknown-verb` there, an argument to `help` `malformed` with `Fault::Unnamed` (`SessionCommand`: `Start { app }` · `Status` · `Stop` · `Help`, `Help`'s spec `HELP`).
- `Refusal` — a `Cause` and, only beside `malformed`, a `Fault`. `CAUSES` is closed at nine: `unknown-verb` · `malformed` · `not-found` · `stale` · `disabled` · `covered` · `off-screen` · `time-unavailable` · `fonts-unavailable` (the ninth since 2026-10-12-headless-screenshot: meaning "the app this session holds has no font it can paint text with", remedy "boot the app with a font it can decode"), each with a fixed `name()`, `meaning()` and `remedy()`. None of `Cause`, `Fault`, `Refusal` has a `String` field: a refusal holds nothing a call supplied. All nine are returned today — `unknown-verb` and `malformed` by `validate`, the other seven by the executor, `fonts-unavailable` from `screenshot` alone, checked before anything is painted. On the stand a click is accepted on 70 of the 77 snapshot nodes at boot and refused on 7: the three disabled controls, and each task's `task-header-spacer` as `covered` (a box 0 high; the hit at its centre answers the header).
- `serve_mcp(input, output, apps, boot, idle_expiry) -> Result<(), SessionError>` (since 2026-10-10-mcp-surface) — newline-delimited JSON-RPC 2.0 in the handshake revisions `2025-11-25` · `2025-06-18` · `2025-03-26` · `2024-11-05` (`PROTOCOL_VERSIONS`; the first since 2026-10-12-self-description) on the `BufRead` and `Write` it is handed, holding at most one session in its own process. `initialize` answers the asked revision when it is one of the four, else `LATEST_VERSION`, `2025-11-25` (until 2026-10-12-self-description one of three, else `2025-06-18`; the current revision `2026-07-28` is answered so and not taken up, the founder's ruling of 2026-10-12) (`capabilities {"tools":{}}`, `serverInfo {name: "escher", version}`); `ping` → `{}`; `tools/list` → the eleven verbs of `VERBS` in order (`screenshot` after `scroll` since 2026-10-12-headless-screenshot), `help` last, each with a `description` — its help, then, since 2026-10-12-self-description, `. Returns: ` and each result field as `{name} ({kind}): {help}` joined by `; ` (the listing 2,984 → 8,844 bytes) — and an `inputSchema` (`additionalProperties: false`, `start`'s `app` an `enum` of the apps); `tools/call`; any other method, `server/discover` included, `-32601`; a request with no `id` is a notification — no reply, nothing runs. Bounds (ratified with the crossing): a request line ≤ 65,536 bytes (longer → read to its end, dropped, `-32700`), an `id` echoed only as an i64 or a string ≤ 128 bytes (else `-32600`, `id: null`), a result's text ≤ 1,048,576 bytes (past it `AnswerTooLarge`'s result) — since 2026-10-12-headless-screenshot a result that holds an image bounded by its whole written form instead, a text-only result by its text as before (`ToolResult::bounded`). Protocol errors: a fixed code and message, no `data`. A tool call's arguments become a `Call` (string → text, i64 → number, bool → flag, any other refused `malformed`; members in key order, so a repeated key collapses to its last value); an instance verb runs through `Session::run` on the held session (none held: validated first, else `no-session`); `start` (an app outside `apps` refused `malformed`; `AlreadyRunning` when held), `status`, `stop` and, since 2026-10-12-self-description, `help` are answered by the server — `help` held session or not, its text `describe()`'s line, accepted, and counted in a held session's `served` as every tool call is. A result is `{content:[…], isError}` — an accepted `snapshot` one text block, the screen text itself; since 2026-10-12-headless-screenshot an accepted `screenshot` two blocks, an `image` block (`data` the PNG's base64, `mimeType` `image/png`) then a text block holding the shot's line without `png` (private `json::shot_without_image`), `isError` false; any other accepted call one text block, its JSON line; a refusal, a refused shot included, or a session error one text block, its JSON with `isError: true`; no `structuredContent`. The idle expiry is checked when a request arrives — no timer, no thread. Since 2026-10-16-file-splits the `mcp` module has three private children, each widened to `pub(super)` and no further — `framing` (the request reader, the id, the protocol errors and the reply writers), `listing` (the handshake and the tool listing) and `result` (a tool call's arguments read into a call, its result and its written form) — and its tests in `mcp_tests.rs`.
- `command_line(args, apps, boot) -> ExitCode` — the whole command line of a binary that boots apps (`boot` an `FnMut` since 2026-10-10-mcp-surface); it installs no subscriber and reads no environment variable. The reader's rules, in order: no first word → usage; `serve <app> --session <dir>` in exactly that shape, else usage; `mcp` alone, else usage (since 2026-10-10-mcp-surface); `help` with no argument and at most one `--session <dir>`, which is not read, answers `describe()`'s line on stdout, status `0`, reaching no session — `help` with an argument is refused `malformed`, `1`, and `--session` with no directory or given twice is usage, `2` (since 2026-10-12-self-description); a first word the verb table does not hold → the refusal `unknown-verb`; the call the remaining words spell (flags as the schema spells them — `--id`, `--text`, `--key`, `--ms` each with one value, `--shift` bare; `start`'s app as one plain word) is checked by `validate` or `validate_session` before the session address is asked for; then `--session <dir>` exactly once, else usage; `start` on an app the binary does not boot → usage. Four endings: accepted — the answer on stdout, status `0`; refused — the refusal on stdout, `1`; usage — one fixed line on stderr built from `VERBS` and the app names, `2`; session error — the error object on stdout and its message on stderr, `3`; the host role ends quiet, status `0`; the `mcp` role hands stdin and stdout to `serve_mcp` with `IDLE_EXPIRY` and writes nothing on stdout at its end — `0` on `Ok`, `3` with the error's fixed message on stderr on `Err` — and the usage line names it (`; mcp role: mcp`). No command's ending writes back anything the caller typed. `start` spawns the running binary again as `serve <app> --session <dir>`, its streams closed, waits up to 30 s for it to answer, and neither kills nor reaps it.
- Consumed by seven_guis (the `escher-session` binary, native target only — its `main` hands argv and the stand's boot to `command_line`, the Timer's session carrying the stand's time step) and by blitz-tests (dev-dependency), whose thirteen `stand_act_*` checks drive the schema through `Session::run`; since 2026-10-15-cold-agent-test the binary's `mcp` role is also the cold-agent pipe's MCP server (`bash scripts/cold-agent.sh run stand`: one isolated `claude -p` session allowed `mcp__escher` alone, the agent's JSON check replayed on fresh `escher-session mcp` children), a `run` precondition the operator builds, never the pipe.

## Internal conventions
- The wire (`wire.rs`, crate-private, versioned `v2`) is one request line and one reply line per connection: `hello v2` → `ok v2 pid= label= served= idle_expiry_s=`, `stop v2` → `ok v2 stopping`, `call v2 <verb> [<name>=<kind>:<value>]…` → `ok v2 accepted <json>` · `ok v2 refused <json>` · `ok v2 oversize`, another version of a known word → `refused version`, anything else → `refused malformed`. Kinds are `t` text · `n` whole number · `f` flag; the verb, the names and a text value are percent-escaped byte for byte and decoded strictly. A request is bounded at 16,384 bytes, a lifecycle reply at 128, an answer at 1,048,576 on its JSON line; each read and write at 2 s, a client's read of an answer at 30 s. **What the screen reads crosses it in an answer** — ids, accessible names, control values (a password's or a file input's as the mask), the snapshot's text and the diff — and an element id and typed text cross in (ratified by the founder, 2026-10-10); no `NodeId` crosses. Inside the text and the diff an element that states one also reads selected, pressed or invalid — closed words in the text, booleans in a diff node, never an attribute's value as typed: an inventory fact of the ratified crossing, not a further widening (the founder, 2026-10-10), who set the rule with it — a new field of a closed value set inside an already ratified carrier is not a widening; authored text, an open value set, a new carrier or a new exit still is. The MCP surface was that next crossing question: since 2026-10-10-mcp-surface the same content crosses to an MCP client in tool results over the `mcp` role's stdio, the request-id echo and the bounds above ratified by the founder with it (2026-10-10, «Ратифицировать как есть»); the next surface that carries any of it is a new crossing question — since 2026-10-15-cold-agent-test the operator-driven live cold-agent run carries the stand's screen (element ids, accessible names and control values in snapshot texts and diffs, from this MCP server) on to the model provider, one run, on the founder's «Один запуск, до $3 (Рекомендую)» and «JSON-проверка с повтором (Рекомендую)» (2026-10-15). Since 2026-10-12-self-description the command line's stdout and the `mcp` role's stdio also carry the program's own fixed text, held as `'static` data of the one table — the `help` self-description, a session error's remedy and each tool's description with its result fields — riding those ratified carriers, and a changed node's `differs` crosses as a closed set by the rule of 2026-10-10 (ratified by the founder, 2026-10-12); text from a page, a call or a screen, a new carrier or a new exit still widens. Since 2026-10-12-headless-screenshot a shot's pixels cross in band on those carriers — its PNG as base64 inside the answer on the session socket and the command line's stdout, and as an MCP `image` block on the `mcp` role's stdio — screen content and no closed value set, with no new carrier, exit or path argument and the 1,048,576-byte bounds unchanged, a bigger image ending `oversize` / `AnswerTooLarge`: a boundary widening ratified by the founder (2026-10-12).
- `served` counts every request answered, refusals included, and each one starts the idle count again — an `attach` or a `status` keeps a host alive; a refusal or a broken connection changes nothing; a `stop` takes effect once its reply is written; an `oversize` reply is no refusal — the call ran.
- Unix only: on other targets `serve`, `start`, `attach`, `stop` and `call` return `Unsupported`; a `Session` held in process works everywhere — `run` included. The schema's three modules (`command`, `refusal`, `schema`) carry no `cfg` gate; `execute` carries two macOS ones, the backward-delete arm of `press` and the select-all's modifier. Since 2026-10-16-file-splits `schema` holds its six shape types `ArgKind`, `ArgSpec`, `FieldKind`, `FieldSpec`, `Level` and `VerbSpec` in its private child `spec`, re-exported, and its tests in `schema_tests.rs`.
- The schema is the one table every surface reads — the actions, the span's cause field, the command line and its usage line, the MCP tools, the self-description: a later entry ADDS its verbs to `VERBS` at its own promotion, never states a second table. A cause's texts are fixed and reworded only with a recorded reason; two of the tool's own texts say measured limits — `covered`'s meaning, two readings — the `contain: paint` one and, since 2026-10-14-stand-requirement-sweep, a box clipped on one axis stopping a hit at its whole padding box, so an element lying outside it along the axis it does not clip can read `covered` though it shows, and, since 2026-10-12-headless-screenshot, `screenshot`'s help, two: an element shot is cropped to the part of its bounds that can be seen, and in a build that paints overlay scrollbars a thumb painted within 0.7 s of a scroll fades by wall time; the help of `changed` and of `snapshot`'s `text` state none since 2026-10-10-scrolling-box-bounds-and-hit, which fixed the two limits they named.
- No panic path on anything a call or a command line supplies: no `unwrap`, `expect`, `panic!`, `unreachable!` or index in `validate`, in the executor or in the argv reader; the executor never calls `Harness::layout_rect_of`, which panics on a node that does not resolve; a write to a closed pipe is dropped, not a panic — pinned since 2026-10-14-quality-gates by `cli_commands`' `a_closed_stdout_drops_the_answer_and_keeps_the_ending` (with its stdout's read end closed, `help` exits 0 and `snapshot` with no session 3, neither printing a panic).
- No `NodeId` outlives a call, and no field of `Session`, `Outcome` or `Refusal` holds one. What the session keeps is a record of the ids its screens have read, to tell `stale` from `not-found`: id text only, in a crate-private `SeenIds` bounded at `MAX_SEEN_IDS` (4096 ids — a count, not the 4096 bytes of `MAX_TEXT_BYTES`), least recently read forgotten first, an id longer than `MAX_ID_BYTES` not recorded, fed from the session's own snapshots, with no public reader; never print, log or field it. No step reads or drains the changed set — the diff is two snapshots and `Snapshot::diff`.
- Settling moves no time and waits on no load: time on a held instance moves only by `advance`, through the caller's step; no driver command waits on a load (the operator, 2026-10-07).
- What a command prints is its answer, never a log line: an `Outcome` is written by `to_json` alone — as a command's answer, and as an MCP tool result's text; an accepted `screenshot` over MCP as an `image` block and its line without `png` (`json::shot_without_image`), since 2026-10-12-headless-screenshot — and nothing of it goes into a span or a log field.

## Crate-specific gotchas
- A Unix socket address leaves about a hundred bytes for the whole path (108 on Linux, 104 on macOS): keep a state directory's name short — a long scratch path cannot hold a session; an over-long one is `StateDirTooLong` (status `3`), whose message states the bound — at most 94 bytes as given on Linux, 90 on every other target — and whose remedy is a shorter path, or a relative one, which counts only its own bytes.
- A host ends by itself after its idle expiry, exactly as on `stop`. A watcher that polls `attach` or `status` restarts the count and keeps the host alive: watch the state directory instead.
- `start` does not check that the answering pid is the child it spawned.
- The `Io` message is spelled "input or output" — "I/O" holds a `/`, and the messages are asserted to hold none.
- A test's working directory is its package: build a check's state directory from `env!("CARGO_TARGET_TMPDIR")`, never from a relative path. The one exception, since 2026-10-14-quality-gates, is the unix-only client unit test `client::imp::tests::an_answer_read_past_its_bound_is_a_timeout`: it binds a test-only `UnixListener` in `eab-{pid}` under the system temporary directory (`std::env::temp_dir()`, reading `TMPDIR` on unix — test code only), a short name so the socket's path fits, accepts one connection, never answers and removes the directory; no binary serves it and no caller reaches it, so it is no crossing (the operator, 2026-10-15).
- Two `Command`s meet at the crate root: the schema's `Command`, and the `std::process::Command` that `start` takes. A grep for `Command` over the crate reads both.
- `Command`, `Call` and `ArgValue` derive `Debug`, which prints the id and the typed text they hold, and `Outcome` derives it too, printing the ids, accessible names, control values and state readings of its diff: never field one with `?` in a span or a log, and never field an argument by its schema name (of the names only `text` is in the sink's scrub set).
- The command span: every call handed to `Session::run` leaves one `tracing` span — target `escher_driver`, name `command`, INFO, built by hand with `tracing::info_span!` (no `#[instrument]`), entered before `validate` and held until `run` returns. Its eight fields are each created unrecorded and recorded only where they apply: `verb` (the verb table's own word, never the caller's text — a session-level verb's and, since 2026-10-12-self-description, the tool-level `help`'s too, beside `unknown-verb`), `cause` (`Cause::name()` of the returned refusal), `settled`, `busy` (the schema's busy-class word), `passes`, and `added` · `removed` · `changed` (the lengths of the returned diff). `snapshot` and, since 2026-10-12-headless-screenshot, an accepted `screenshot` record `verb` alone; a refused call `verb` and `cause` only. Never fielded: `in_view`, `advanced_ms`, the screen text or its length, a shot's image, its size or its dimensions, the label, the record of ids, any argument, any `Command`, `Call`, `ArgValue`, `Outcome`, `Refusal` or `Fault`. The crate installs no subscriber: with none the span is disabled; under escher's sink it is one line per call at `info` or below, none at the default `warn` — an `escher-session` host writes it for every hosted call. A call the schema refuses on the command line or in `client::call` reaches no session and opens no span; an idle expiry writes no record.
- The `tool_call` span (since 2026-10-10-mcp-surface; the founder, 2026-10-10, «Span с tool и ending»): one per MCP `tools/call` request, target `escher_driver`, INFO, opened and entered before its params are read and held until its reply is written; two fields only — `tool` (the table's word, unrecorded for an unknown tool) and `ending` (`accepted` · `refused` · `error`); the `command` span of an instance verb is its child by nesting, while `start` · `status` · `stop` and, since 2026-10-12-self-description, `help` leave a `tool_call` with no child. `serve_mcp` itself and the rest of its protocol write no record. A check that installs a scoped subscriber with `with_default` reads no span when another test thread reached the same callsites with no subscriber first (`tracing`'s callsite interest is process-global): give each test its own recorder.
- In `command.rs` an assertion over a call carries a row index only (`assert!(a == b, "row {row}")`), never `assert_eq!` on a call or a command — a failing leg's log is uploaded as a CI artifact. The `stand_act_*` checks keep the same rule: a message names a layout mode, a task and an index.
- Fixed in the engine at 2026-10-10-scrolling-box-bounds-and-hit: a box that is itself scrolled reads its `bounds` where it stands — a step that scrolls it does not name it among the changed nodes, and a `click` or a `type` naming the box lands at its centre (`stand_act_scroll`).
- Measured limit, unfixed: the engine's hit reaches content clipped by `contain: paint` beside a `visible` `overflow`, so a control lying where such content extends reads `covered` though nothing shows over it — `covered`'s meaning says so. Measured limit, unfixed, since 2026-10-14-stand-requirement-sweep: a box clipped on one axis stops a hit at its whole padding box while `visible_region` narrows it on its clipped axis only, so a target lying beside it along the axis it does not clip reads in view and is refused `covered` with the instance unchanged, in both layout modes (`stand_act_obstructed`) — `covered`'s meaning says that too. Fixed at 2026-10-10-scrolling-box-bounds-and-hit: a hit stops at the padding box of a box that clips by `overflow`, so a control lying where a scrolling box's scrolled-out row extends is clicked as itself, and since 2026-10-13-stand-keyboard-harness the clicked button reads `focused` after the accepted click, a click focusing a button in every document (`stand_act_obstructed`).
- On macOS the editor's Backspace arm is compiled out — a window delivers the delete as a standard key binding — so `press backspace`, and a `type` with an empty text, also dispatch `deleteBackward:` there (`Harness::apple_keybinding`). The macOS CI leg is that arm's one witness, and of the select-all's Super modifier.
- Since 2026-10-13-range-input-interaction the instance verbs move a range input (the engine's range interaction model, [Scrolling and input]): a `click` sets its value from the hit's fraction of its content box and focuses it, and once focused `press` `arrow-right` / `arrow-up` steps it up, `arrow-left` / `arrow-down` down, `home` / `end` to its minimum and maximum — the diff names the change on the slider (`value`) and on its display (`name`); until then a click did not focus it and no key moved its value (measured at 2026-10-07-act-by-id on the stand's Timer).
- With the settle removed only `advance` reads wrong on the stand: `click`, `type` and `press` each ride an input helper's own pump. The settle's second-pass cases are `stand_settle`'s.
- `Role` and `BoundingRect` are not re-exported by dioxus-native-dom, so this crate cannot build a `DiffNode` in a unit test: the JSON writer's node rows are tested over plain parts, and real nodes by the integration checks.
