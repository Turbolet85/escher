# escher-driver

_Crate notes. Primary source: `.andromeda/architecture.md` §Standard Contracts Driver session and CLIs, §Occupied Resources and [Driver session]; the lifecycle checks' contract is test-plan §3 → Session lifecycle (`.andromeda/registries/contracts/test-plan/session-lifecycle.md`); the schema's and the command line's input rules are security-plan §Input Validation (the Driver command schema, Driver session socket and CLI arguments rows)._

## Responsibility
The driver's core (unpublished, no `[features]` of its own, no binary): a **session** — one headless app instance held by one process while commands arrive — the **command and refusal schema**, the one definition of what can be asked of the driver and of how it says no, the **executor** that runs a call on the held instance, since 2026-10-10-driver-cli the **command line** that carries a call out of the process, and since 2026-10-10-mcp-surface the **MCP server** that serves the nine verbs as MCP tools over a caller's reader and writer (the `escher-session mcp` role). It is app-agnostic: the caller supplies the boot and the time step, and the crate names no app and no stand type. `Session::run` validates a call, looks its target up on the screen, refuses a target that cannot take the action, runs its verb, settles the instance and returns a typed `Outcome` — for a call made in process, and for one a host decoded from its socket. A call and its answer cross the socket (ratified by the founder, 2026-10-10), and an MCP client's stdio (ratified by the founder, 2026-10-10, «Ратифицировать как есть»). A settle verb on the socket is a later route entry.

## Key integrations

### Consumes from
- `blitz-test-harness` (`Harness`, and its re-exports `Key` and `Modifiers` — the key types are no dependency of their own), `dioxus-native-dom` (`DioxusDocument`, `SnapshotDiff`) with its `accessibility` feature named, unconditionally: the executor reads the snapshot, which stands behind that feature — `tracing` (the workspace's, no feature, no `[features]` table), for the `command` span and, since 2026-10-10-mcp-surface, the `tool_call` span — and, the fourth dependency since 2026-10-10-mcp-surface, `serde_json` (the workspace's, no feature), the reader of MCP requests only (the founder, 2026-10-10, «serde_json, только чтение»); it was already in both graphs through dioxus-html, so the lock changed by one line and no package. Through `seven_guis → escher-driver` both seven_guis binaries therefore compile dioxus-native-dom's accessibility modules; neither builds a platform adapter.
- `std` only for the socket (`std::os::unix::net`), the spawn (`std::env::current_exe()` for the `start` command), the file modes and the host's idle clock. No env read and no default state location; the schema is Rust data and every answer's JSON is written by hand in `json.rs` — `serde_json` reads MCP requests and writes nothing. The executor, the session, the schema, the validation and the JSON writer read no clock and print nothing; the host reads one for its idle expiry, and the MCP server one when a request arrives with a session held.

### Publishes to
- `Session::start(label, boot)` — the label is 1 to 32 bytes of `a-z`, `0-9`, `-`, checked BEFORE the boot runs (`InvalidLabel`, nothing booted); the boot runs once on the calling thread; `label()`, `harness()`, `harness_mut()`.
- `Session::with_time(step)` — returns the session carrying its caller's time step: a closure handed the held harness and the milliseconds an `advance` asks for, returning the milliseconds the app moved. A session started without it carries none.
- `Session::act(step) -> Result<Settled, SessionError>` — runs the closure on the held instance, then settles it (`Harness::settle`): on `Ok` everything the step made due is on the screen; an instance that does not go quiet is `NotSettled(Busy)`. The step is not rolled back, and no time is advanced. In process only. `Busy` and `Settled` are re-exported from blitz-test-harness.
- `Session::run(&Call) -> Result<Outcome, Refusal>` — the one entry point that runs a call. `validate` first: a refused call has run nothing, and a session-level verb (`start`, `status`, `stop`) is refused `unknown-verb`. Then per verb: `snapshot` returns the screen's text (`Snapshot::to_text`) and dispatches nothing; `click`, `type` and `scroll` look their id up on the screen as it reads NOW (the snapshot lists it, and the first `element_ids()` pair with it resolves through `get_node`) — an id that names no element there is refused with nothing run, `stale` when the session's record of ids read holds it, `not-found` when not. A `click` or a `type` on an element that cannot take it is then refused, one answer in a fixed order: `disabled` (the snapshot reads `enabled: Some(false)`), `off-screen` (the centre of its `bounds` is outside `BaseDocument::visible_region` — the viewport and every scrolling box that holds it), `covered` (the hit at that page point never reaches it). Otherwise they click the centre of the element's snapshot `bounds` plus the viewport's scroll; `type` then replaces what the control holds — where the snapshot reads a `value` for the target (an empty text input reads one) it presses the engine's select-all (`a` with Control, Super on macOS) and types, and with an empty text deletes the selection, so an empty text clears; `press` presses its key on what holds focus (shift when asked); `advance` hands its milliseconds to the session's time step — `time-unavailable` when the session carries none; `scroll` applies none of the three checks, scrolls every scrolling box that holds the element and then the viewport, at once (`Harness::scroll_into_view`), and answers `in_view` — false when no scroll could bring it into view; it is never refused for that. Each acting verb is one settled step: snapshot, step, `Harness::settle`, snapshot, diff. A refused call leaves the snapshot and both focus readings as they were.
- `Outcome` — `Screen { text }` · `Acted { settled, busy, diff }` · `Advanced { settled, busy, diff, advanced_ms }` · `Scrolled { settled, busy, diff, in_view }`; `diff` is dioxus-native-dom's `SnapshotDiff`, unchanged. An instance that did not go quiet is a result (`settled: false` with its `Busy` class), never a refusal and never a `SessionError`; the step is not rolled back. `advanced_ms` is the lesser of the step's return and the `ms` asked: the time delivered to the app, not what a counter inside it gained.
- Written forms — `Outcome::to_json`, `Refusal::to_json`, `SessionError::to_json`: one line of JSON each, keyed by the schema's own words, output only. An outcome is an object keyed by its verb's result fields in the table's order (`busy` only when not settled); a node is keyed by `NODE_FIELDS` in order — twelve words: `id` · `parent` · `role` · `name` · `enabled` · `checked` · `value` · `selected` · `pressed` · `invalid` · `focused` · `bounds` — with `parent`, `enabled`, `checked`, `value`, `selected` and `pressed` left out when absent, `invalid` always written, `bounds` four numbers; a refusal is `{"refused":{"cause","meaning","remedy"[,"fault"]}}`; a session error `{"error":{"kind","message"}}`; `start` answers `label`, `pid`, `idle_expiry_s`, `status` adds `served`, `stop` answers `{"stopped":true}`.
- `serve(state_dir, session, idle_expiry)` — hosts one session until a `stop` request or until no request has been answered for `idle_expiry` (`IDLE_EXPIRY`, 1,800 s, is what a command line's host serves under), on the calling thread (the instance is not `Send`): creates the state directory `0700` (a present one open to group or others is `StateDirNotPrivate`), binds `session.sock` and sets it `0600`, replaces a socket nothing answers on, reads `AlreadyRunning` when one answers, runs a `call` request through `Session::run` and nothing else, and at the end drops the session and removes the socket file and the directory — non-recursively, nothing else.
- `start(state_dir, host, ready)` → `Started { child, hello }` · `attach(state_dir)` → `Hello { pid, label, served, idle_expiry_s }` · `stop(state_dir)` (waits up to 5 s for the directory to go) · `call(state_dir, &Call)` → `Answer { accepted, json }` — it validates first, so a call the schema refuses is answered there and reaches no session; the answer is read under 30 s per read.
- `SessionError`, thirteen: `AlreadyRunning` · `NoSession` · `Dead` · `HostExited(code)` · `Timeout` · `Protocol` · `InvalidLabel` · `StateDirTooLong` · `StateDirNotPrivate` · `Unsupported` · `Io(kind)` · `NotSettled(Busy)` · `AnswerTooLarge` (a call's answer over the socket's bound — the call ran) — fixed messages (`Io` and `NotSettled` append a kind or class name), never a path, label, id or value; `kind()` is one fixed kebab-case word per variant. A session error carries no remedy, and `state-dir-too-long` states no bound.
- `VERBS` — the verb table, nine verbs in two levels (`Level::Instance` · `Level::Session`): `snapshot` (no argument; result `text`), `click` (`id`), `type` (`id`, `text`), `press` (`key`, optional `shift`), `advance` (`ms`), `scroll` (`id`; the sixth, ratified by the founder, 2026-10-07), then `start` (`app`), `status` and `stop` (session-level; ratified by the founder, 2026-10-10); each a `VerbSpec { name, level, help, args, fields }`; `verb(name)` finds one by its exact name only. Argument kinds and bounds (`ArgKind`): `id` 1 to `MAX_ID_BYTES` (1024) bytes of text · `text` 0 to `MAX_TEXT_BYTES` (4096) bytes · `key` one of the twelve `KEY_NAMES` · `flag` · `milliseconds` 1 to `MAX_MILLISECONDS` (60000) · `name` 1 to 32 bytes of `a-z`, `0-9`, `-`. The acting verbs' result: `settled`, `busy` (one of `BUSY_CLASSES`, only when not settled), `added`, `removed`, `changed` (nodes carry the `NODE_FIELDS`); `advance` adds `advanced_ms`, `scroll` adds `in_view` (always present). The help of `changed` and of `snapshot`'s `text` say the state words and the two limits of the boolean model — a mixed toggle reads unpressed (`pressed` false), a grammar or spelling error reads invalid — so an agent learns them from the tool; the crate docs say the same in one sentence.
- `validate(call: &Call) -> Result<Command, Refusal>` — a `Call` is a verb name and named `ArgValue`s (`Text` · `Number` · `Flag`); it receives no `Session`, so a refused call changes nothing. One answer per call, the first failure in this order: the verb by exact name (`unknown-verb`; a session-level verb too), then the call's arguments in the order passed (a name the verb lacks, a name passed twice), then the verb's arguments in the schema's order (missing, wrong kind, outside its bound) — the last five are `malformed` with a `Fault` naming the rule. `Command` is `Snapshot` · `Click` · `Type` · `Press` · `Advance` · `Scroll`, and `Command::spec()` is its verb's row. `validate_session(&Call) -> Result<SessionCommand, Refusal>` is the same check over the three session-level rows (`SessionCommand`: `Start { app }` · `Status` · `Stop`).
- `Refusal` — a `Cause` and, only beside `malformed`, a `Fault`. `CAUSES` is closed at eight: `unknown-verb` · `malformed` · `not-found` · `stale` · `disabled` · `covered` · `off-screen` · `time-unavailable`, each with a fixed `name()`, `meaning()` and `remedy()`. None of `Cause`, `Fault`, `Refusal` has a `String` field: a refusal holds nothing a call supplied. All eight are returned today — `unknown-verb` and `malformed` by `validate`, the other six by the executor. On the stand a click is accepted on 70 of the 77 snapshot nodes at boot and refused on 7: the three disabled controls, and each task's `task-header-spacer` as `covered` (a box 0 high; the hit at its centre answers the header).
- `serve_mcp(input, output, apps, boot, idle_expiry) -> Result<(), SessionError>` (since 2026-10-10-mcp-surface) — newline-delimited JSON-RPC 2.0 in the handshake revisions `2025-06-18` · `2025-03-26` · `2024-11-05` on the `BufRead` and `Write` it is handed, holding at most one session in its own process. `initialize` answers the asked revision when it is one of the three, else `2025-06-18` (`capabilities {"tools":{}}`, `serverInfo {name: "escher", version}`); `ping` → `{}`; `tools/list` → the nine verbs of `VERBS` in order, each with an `inputSchema` (`additionalProperties: false`, `start`'s `app` an `enum` of the apps); `tools/call`; any other method, `server/discover` included, `-32601`; a request with no `id` is a notification — no reply, nothing runs. Bounds (ratified with the crossing): a request line ≤ 65,536 bytes (longer → read to its end, dropped, `-32700`), an `id` echoed only as an i64 or a string ≤ 128 bytes (else `-32600`, `id: null`), a result's text ≤ 1,048,576 bytes (past it `AnswerTooLarge`'s result). Protocol errors: a fixed code and message, no `data`. A tool call's arguments become a `Call` (string → text, i64 → number, bool → flag, any other refused `malformed`; members in key order, so a repeated key collapses to its last value); an instance verb runs through `Session::run` on the held session (none held: validated first, else `no-session`); `start` (an app outside `apps` refused `malformed`; `AlreadyRunning` when held), `status` and `stop` are answered by the server. A result is `{content:[{type:"text",text}], isError}` — `snapshot` the screen text itself, any other accepted call its JSON line, a refusal or a session error its JSON with `isError: true`; no `structuredContent`. The idle expiry is checked when a request arrives — no timer, no thread.
- `command_line(args, apps, boot) -> ExitCode` — the whole command line of a binary that boots apps (`boot` an `FnMut` since 2026-10-10-mcp-surface); it installs no subscriber and reads no environment variable. The reader's rules, in order: no first word → usage; `serve <app> --session <dir>` in exactly that shape, else usage; `mcp` alone, else usage (since 2026-10-10-mcp-surface); a first word the verb table does not hold → the refusal `unknown-verb`; the call the remaining words spell (flags as the schema spells them — `--id`, `--text`, `--key`, `--ms` each with one value, `--shift` bare; `start`'s app as one plain word) is checked by `validate` or `validate_session` before the session address is asked for; then `--session <dir>` exactly once, else usage; `start` on an app the binary does not boot → usage. Four endings: accepted — the answer on stdout, status `0`; refused — the refusal on stdout, `1`; usage — one fixed line on stderr built from `VERBS` and the app names, `2`; session error — the error object on stdout and its message on stderr, `3`; the host role ends quiet, status `0`; the `mcp` role hands stdin and stdout to `serve_mcp` with `IDLE_EXPIRY` and writes nothing on stdout at its end — `0` on `Ok`, `3` with the error's fixed message on stderr on `Err` — and the usage line names it (`; mcp role: mcp`). No command's ending writes back anything the caller typed. `start` spawns the running binary again as `serve <app> --session <dir>`, its streams closed, waits up to 30 s for it to answer, and neither kills nor reaps it.
- Consumed by seven_guis (the `escher-session` binary, native target only — its `main` hands argv and the stand's boot to `command_line`, the Timer's session carrying the stand's time step) and by blitz-tests (dev-dependency), whose twelve `stand_act_*` checks drive the schema through `Session::run`.

## Internal conventions
- The wire (`wire.rs`, crate-private, versioned `v2`) is one request line and one reply line per connection: `hello v2` → `ok v2 pid= label= served= idle_expiry_s=`, `stop v2` → `ok v2 stopping`, `call v2 <verb> [<name>=<kind>:<value>]…` → `ok v2 accepted <json>` · `ok v2 refused <json>` · `ok v2 oversize`, another version of a known word → `refused version`, anything else → `refused malformed`. Kinds are `t` text · `n` whole number · `f` flag; the verb, the names and a text value are percent-escaped byte for byte and decoded strictly. A request is bounded at 16,384 bytes, a lifecycle reply at 128, an answer at 1,048,576 on its JSON line; each read and write at 2 s, a client's read of an answer at 30 s. **What the screen reads crosses it in an answer** — ids, accessible names, control values (a password's or a file input's as the mask), the snapshot's text and the diff — and an element id and typed text cross in (ratified by the founder, 2026-10-10); no `NodeId` crosses. Inside the text and the diff an element that states one also reads selected, pressed or invalid — closed words in the text, booleans in a diff node, never an attribute's value as typed: an inventory fact of the ratified crossing, not a further widening (the founder, 2026-10-10), who set the rule with it — a new field of a closed value set inside an already ratified carrier is not a widening; authored text, an open value set, a new carrier or a new exit still is. The MCP surface was that next crossing question: since 2026-10-10-mcp-surface the same content crosses to an MCP client in tool results over the `mcp` role's stdio, the request-id echo and the bounds above ratified by the founder with it (2026-10-10, «Ратифицировать как есть»); the next surface that carries any of it is a new crossing question.
- `served` counts every request answered, refusals included, and each one starts the idle count again — an `attach` or a `status` keeps a host alive; a refusal or a broken connection changes nothing; a `stop` takes effect once its reply is written; an `oversize` reply is no refusal — the call ran.
- Unix only: on other targets `serve`, `start`, `attach`, `stop` and `call` return `Unsupported`; a `Session` held in process works everywhere — `run` included. The schema's three modules (`command`, `refusal`, `schema`) carry no `cfg` gate; `execute` carries two macOS ones, the backward-delete arm of `press` and the select-all's modifier.
- The schema is the one table every surface reads — the actions, the span's cause field, the command line and its usage line, the MCP tools, the self-description: a later entry ADDS its verbs to `VERBS` at its own promotion, never states a second table. A cause's texts are fixed and reworded only with a recorded reason; one of the tool's own texts says a measured limit — `covered`'s meaning, the `contain: paint` reading; the help of `changed` and of `snapshot`'s `text` state none since 2026-10-10-scrolling-box-bounds-and-hit, which fixed the two limits they named.
- No panic path on anything a call or a command line supplies: no `unwrap`, `expect`, `panic!`, `unreachable!` or index in `validate`, in the executor or in the argv reader; the executor never calls `Harness::layout_rect_of`, which panics on a node that does not resolve; a write to a closed pipe is dropped.
- No `NodeId` outlives a call, and no field of `Session`, `Outcome` or `Refusal` holds one. What the session keeps is a record of the ids its screens have read, to tell `stale` from `not-found`: id text only, in a crate-private `SeenIds` bounded at `MAX_SEEN_IDS` (4096 ids — a count, not the 4096 bytes of `MAX_TEXT_BYTES`), least recently read forgotten first, an id longer than `MAX_ID_BYTES` not recorded, fed from the session's own snapshots, with no public reader; never print, log or field it. No step reads or drains the changed set — the diff is two snapshots and `Snapshot::diff`.
- Settling moves no time and waits on no load: time on a held instance moves only by `advance`, through the caller's step; no driver command waits on a load (the operator, 2026-10-07).
- What a command prints is its answer, never a log line: an `Outcome` is written by `to_json` alone — as a command's answer, and as an MCP tool result's text — and nothing of it goes into a span or a log field.

## Crate-specific gotchas
- A Unix socket address leaves about a hundred bytes for the whole path (108 on Linux, 104 on macOS): keep a state directory's name short — a long scratch path cannot hold a session; an over-long one is `StateDirTooLong` (status `3`), and the message states no bound.
- A host ends by itself after its idle expiry, exactly as on `stop`. A watcher that polls `attach` or `status` restarts the count and keeps the host alive: watch the state directory instead.
- `start` does not check that the answering pid is the child it spawned.
- The `Io` message is spelled "input or output" — "I/O" holds a `/`, and the messages are asserted to hold none.
- A test's working directory is its package: build a check's state directory from `env!("CARGO_TARGET_TMPDIR")`, never from a relative path.
- Two `Command`s meet at the crate root: the schema's `Command`, and the `std::process::Command` that `start` takes. A grep for `Command` over the crate reads both.
- `Command`, `Call` and `ArgValue` derive `Debug`, which prints the id and the typed text they hold, and `Outcome` derives it too, printing the ids, accessible names, control values and state readings of its diff: never field one with `?` in a span or a log, and never field an argument by its schema name (of the names only `text` is in the sink's scrub set).
- The command span: every call handed to `Session::run` leaves one `tracing` span — target `escher_driver`, name `command`, INFO, built by hand with `tracing::info_span!` (no `#[instrument]`), entered before `validate` and held until `run` returns. Its eight fields are each created unrecorded and recorded only where they apply: `verb` (the verb table's own word, never the caller's text — a session-level verb's too, beside `unknown-verb`), `cause` (`Cause::name()` of the returned refusal), `settled`, `busy` (the schema's busy-class word), `passes`, and `added` · `removed` · `changed` (the lengths of the returned diff). `snapshot` records `verb` alone; a refused call `verb` and `cause` only. Never fielded: `in_view`, `advanced_ms`, the screen text or its length, the label, the record of ids, any argument, any `Command`, `Call`, `ArgValue`, `Outcome`, `Refusal` or `Fault`. The crate installs no subscriber: with none the span is disabled; under escher's sink it is one line per call at `info` or below, none at the default `warn` — an `escher-session` host writes it for every hosted call. A call the schema refuses on the command line or in `client::call` reaches no session and opens no span; an idle expiry writes no record.
- The `tool_call` span (since 2026-10-10-mcp-surface; the founder, 2026-10-10, «Span с tool и ending»): one per MCP `tools/call` request, target `escher_driver`, INFO, opened and entered before its params are read and held until its reply is written; two fields only — `tool` (the table's word, unrecorded for an unknown tool) and `ending` (`accepted` · `refused` · `error`); the `command` span of an instance verb is its child by nesting, while `start` · `status` · `stop` leave a `tool_call` with no child. `serve_mcp` itself and the rest of its protocol write no record. A check that installs a scoped subscriber with `with_default` reads no span when another test thread reached the same callsites with no subscriber first (`tracing`'s callsite interest is process-global): give each test its own recorder.
- In `command.rs` an assertion over a call carries a row index only (`assert!(a == b, "row {row}")`), never `assert_eq!` on a call or a command — a failing leg's log is uploaded as a CI artifact. The `stand_act_*` checks keep the same rule: a message names a layout mode, a task and an index.
- Fixed in the engine at 2026-10-10-scrolling-box-bounds-and-hit: a box that is itself scrolled reads its `bounds` where it stands — a step that scrolls it does not name it among the changed nodes, and a `click` or a `type` naming the box lands at its centre (`stand_act_scroll`).
- Measured limit, unfixed: the engine's hit reaches content clipped by `contain: paint` beside a `visible` `overflow`, so a control lying where such content extends reads `covered` though nothing shows over it — `covered`'s meaning says so. Fixed at 2026-10-10-scrolling-box-bounds-and-hit: a hit stops at the padding box of a box that clips by `overflow`, so a control lying where a scrolling box's scrolled-out row extends is clicked as itself (`stand_act_obstructed`).
- On macOS the editor's Backspace arm is compiled out — a window delivers the delete as a standard key binding — so `press backspace`, and a `type` with an empty text, also dispatch `deleteBackward:` there (`Harness::apple_keybinding`). The macOS CI leg is that arm's one witness, and of the select-all's Super modifier.
- A click on a range input is accepted and does not focus it, and no key moves its value: through the six instance verbs a range input cannot be changed (measured on the stand's Timer; a route entry owns the engine's range interaction model).
- With the settle removed only `advance` reads wrong on the stand: `click`, `type` and `press` each ride an input helper's own pump. The settle's second-pass cases are `stand_settle`'s.
- `Role` and `BoundingRect` are not re-exported by dioxus-native-dom, so this crate cannot build a `DiffNode` in a unit test: the JSON writer's node rows are tested over plain parts, and real nodes by the integration checks.
