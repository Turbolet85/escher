# dioxus-native-dom

_Crate notes. Primary source: `.andromeda/architecture.md` §Standard Contracts Dioxus DOM bridge._

## Responsibility
The headless Dioxus renderer on blitz: `DioxusDocument` integrates `BaseDocument` with a `VirtualDom`, writes vdom mutations into the DOM and routes DOM events back to vdom handlers. The windowed `dioxus-native` crate builds on it; the seven_guis stand runs through it.

## Key integrations

### Consumes from
- blitz-dom (shared as `Rc<RefCell<BaseDocument>>`), dioxus-core / dioxus-html 0.7.3.

### Publishes to
- `DioxusDocument` (`vdom`, `inner`, `initial_build`, `poll`, `handle_ui_event`, `vdom_state.try_element_to_node_id(ElementId)`), `NodeHandle` backing `MountedData`.
- Stable element ids: `element_id(NodeId) -> Option<String>` and `element_ids() -> Vec<(NodeId, String)>` (document pre-order, pairwise distinct), computed on demand and written to neither the DOM nor the vdom; under the `accessibility` feature (which enables an optional `accesskit` and is forwarded from dioxus-native's) `DioxusDocument`'s `Document::accessibility_tree` override carries each one as its element node's AccessKit `author_id`, never on a `TextRun`, the document root or the `Window` node — four tiers: author key (the HTML `id`: non-empty, `/`-free, first in document order) → anchored path (`{key}//{segment}`, e.g. `box//p:0/b:0`, for an element under an element of its own component instance that reads an author key; the nearest one anchors) → component path (`TaskShell/Counter/div:0`; `{tag}[{key}]` for a Dioxus-keyed root; a component's template root always restarts here, so an anchor acts inside one component only) → document path (`/html:0/body:0`). An unusable `id` (empty, `/`-bearing, a later duplicate) neither keys nor anchors, and an anchored path is the only id holding `//`. Proven persistent on the stand: the same id across a re-render, a remount (fresh `NodeId`s for every element bar the `html`/`head`/`body`/`#main` skeleton, which lives outside the VirtualDom) and a second process (`stand_id_persistence`), and across edits of the code around an element — a keyed element under every edit, an anchored one under an edit outside its keyed element, any element under a behaviour edit; an earlier same-tag sibling or a wrapper inside the subtree a path starts at still renames an unkeyed element (`stand_id_edits`).
- Actionable-key check (under `accessibility` only): `DioxusDocument::unkeyed_actionable() -> Vec<UnkeyedActionable>` returns every actionable element whose id is a positional path, in document pre-order — actionable meaning focusable (`Node::is_focussable()`), or an interactive role on its accessibility node, or a listener (`data-dioxus-id`), so a disabled control is held by its role and a hidden one by the other two. `UnkeyedActionable` carries `node` (a process-local `NodeId`), `id`, `tag`, `role: Option<Role>`, `focusable`, `interactive_role`, `listener` and `remedy()`; never text, a name or an attribute value. Read-only, logs nothing; no wire form and no driver command yet. The stand reads it empty on the four lean tasks and Home; the three other tasks read 2 · 3 · 676 (`stand_actionable_keys`).
- Snapshot model (under `accessibility` only): `DioxusDocument::snapshot() -> Snapshot`, a read-only tree built from the `accessibility_tree` override. `Snapshot { roots }` with `nodes()` (pre-order) and `get(id)`; a `SnapshotNode` carries `id` (the `author_id`), `role` (`accesskit::Role`), `name` (the node's `label`, else its `labelled_by` targets' names, trimmed), `state` (`NodeState { enabled, checked, value, focused }`), `bounds` (`get_client_bounding_rect` — viewport-relative, except that a box that is itself scrolled reads shifted by its own scroll offset: measured on the stand's `crud-list`, unfixed, owned by a route entry) and `children`. A node is every element the accessibility tree keeps, generic containers included; `TextRun`s, the document root and the `Window` are not nodes. State is read from the element, since the tree gives an element no value: `enabled` follows the PRESENCE of `disabled` on an element that can be disabled (a `disabled="false"` and a bare `disabled` read `Some(false)` while both stay focusable), `checked` is the checkbox or radio state, `value` is the editor's text else the `value` attribute — and a password or file `input` reads the public constant `MASKED_VALUE` (eight U+2022) where it holds a non-empty value and `""` where that value is empty, never the text, its length or a file's host path (the DOM attribute and form submission still hold the path); `focused` is the tree's focus. No field holds a `NodeId`, tree id, `ElementId`, `ScopeId` or pointer; its one serialized form is the text below, and no driver command exposes either yet (`stand_snapshot`, `stand_snapshot_state`).
- Snapshot text (under `accessibility` only, module `snapshot_text`): `Snapshot::to_text() -> String`, a pure function of the model — one line per node in `nodes()` order, each ended by a line break, a child indented two spaces deeper. A line reads `Role "name" id="id"`, then the state tokens the model holds in the fixed order `enabled`/`disabled` · `checked`/`unchecked` · `value="…"` · `focused`, then `@x,y widthxheight` (`TextInput "Name:" id="who" enabled value="Ada" focused @8,8 200x24`). The role is its `Debug` spelling; strings are in `str`'s `Debug` form, so a field never holds a line break or a bare `"` and an apostrophe stays as it is; numbers are `f64`'s `Display`. No `Display` impl, no parser, no JSON form, no truncation. `SNAPSHOT_TEXT_BUDGET` (10,000 bytes, re-exported) is the ceiling one screen's text stays under — compared by the caller, never enforced; the lean stand screens read 755 · 1269 · 1259 · 2034 bytes. The text is content (ids, names, a text control's value): it leaves the process through the returned value only — never log, print or write it (ratified by the founder, 2026-10-07) (`stand_snapshot_text`).
- Snapshot diff (under `accessibility` only, module `snapshot_diff`): `Snapshot::diff(&self, after: &Snapshot) -> SnapshotDiff`, a pure comparison of two snapshots by stable element id. `SnapshotDiff { added, removed, changed }` with `is_empty()`; `added` and `changed` hold `DiffNode { id, parent, role, name, state, bounds }` — the node's reading AFTER the step, flat, `parent` its parent snapshot node's id (`None` for a root) — and `removed` holds ids. Added = in `after` only; removed = in `self` only; changed = in both and role, name, state, bounds or parent's id differ; a node is never named because a descendant changed. `added` and `changed` follow `after`'s pre-order, `removed` follows `self`'s; where two nodes carry one id the first in pre-order stands for it, as `Snapshot::get` reads it. Values come from the snapshots only, so a password's or file input's value is `MASKED_VALUE`; no field holds a `NodeId`, `ElementId`, `ScopeId`, tree id or pointer. It is NOT derived from blitz-dom's changed set (`has_changes` / `take_changed_nodes` — "something was written since the last drain"): the flag can read true beside an empty diff, and bounds-only movement shows in the diff without marking the set. No text form, `Display`, JSON, parser, `DioxusDocument` entry point or driver command; a diff is content and leaves the process through the returned value only (ratified by the founder, 2026-10-07) (`stand_diff`) — while the three list lengths of a diff the driver returns, counts only, are recorded on escher-driver's command span and printed by the sink at `info` or below (ratified by the founder, 2026-10-09: the sentence stands, with the clarification that a diff's content never reaches a log while its three sizes may).

## Internal conventions
- DOM events route to the vdom via the nearest `data-dioxus-id` attribute (parsed as `usize`); listener registration sets a `"<rust func>"` placeholder.
- `style`-namespace attributes become style properties; `dangerous_inner_html` sets inner HTML; a falsy value (Bool false, `"false"`, 0, None) of one of the 27 boolean attributes of `BOOLEAN_ATTRIBUTES` (`mutation_writer.rs` — the `isBoolAttr` list of Dioxus 0.7.10's web interpreter: `checked`, `disabled`, `hidden`, `readonly`, `required`, `multiple`, `selected`, `open`, `autofocus` and 18 more) clears the attribute, on the dynamic and the static template path alike.
- Every document starts as `<html><head></head><body><main id="main"></main></body></html>` with `DEFAULT_CSS`; base URL `dioxus://index.html`.
- `mounted` listeners fire after `initial_build` and each `poll`; event kinds with zero handlers are skipped.
- A crate-local `trace!` macro expands to `tracing::debug!` under `tracing` (its 4-argument arm passes only the first two items).

## Crate-specific gotchas
- `mutation_writer.rs` has a "WARNING: DO NOT REORDER" block.
- Twelve event-data conversions call `unimplemented!()`; IME events are not handled; `NativeFormData::valid` always returns true.
- `element_to_node_id` unwraps; `NodeHandle::node` panics if the node is gone.
- `VComponent.name` is the component's full type path (`crate::module::Name`, generics included), and the user root sits under dioxus-core's RootScopeWrapper → SuspenseBoundary → ErrorBoundary scopes — the id walk strips the path and skips those four scopes.
- A node a re-render removes is only DETACHED (parent `None`) and keeps resolving until its ElementId is reassigned; `element_id` reads `None` for it, but `get_node` still returns it.
- A `key:` on an element inside an `if` within a `for` body does not key the list: the `for` items are the unkeyed `if` wrappers, diffed by position, and a changed inner key replaces the node — put the filter in the iterator so each `for` item is the keyed element.
- An attribute outside the 27-name boolean list is written with its stringified value even when falsy (`aria-hidden`, a `data-` attribute holding `false` reads `"false"`) — blitz-dom keys element state and click targeting on presence, so a boolean attribute missing from the list would read as set.

## Testing this crate
- `cargo test -p dioxus-native-dom` (55 unit tests in eight files: `keyed_nodes_do_not_crash`, two touch tests, six `bridge_tests` — a Dioxus key that is empty or holds `/` reading a positional segment, `create_head_element`, `mounted` delivery after the build and after a poll, `Document::id`, a handled event's cancel and stop — in `dioxus_document_tests.rs`, a `cfg(test)` child module of `dioxus_document` so they reach the private `DioxusEventHandler`; thirteen `element_id` tests — seven of them on the anchored tier — and, under `accessibility`, four `actionable` tests, fourteen `snapshot` tests, seven `snapshot_text` tests and eight `snapshot_diff` tests — the first two groups call `resolve(0.0)` after `initial_build`, the last two build `Snapshot` values by hand; the unit `build` helper has no HTML parser, so `dangerous_inner_html` renders nothing there and the `disabled` reader pin writes its attributes through `DocumentMutator`); Dioxus integration in `tests/blitz-tests` via `Harness::from_component` / `from_vdom`; `dioxus_falsy_disabled.rs` pins the falsy-`disabled` clearing and `dioxus_falsy_boolean_attrs.rs` the 27-name list.
