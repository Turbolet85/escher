# dioxus-native-dom

_Crate notes. Primary source: `.andromeda/architecture.md` §Standard Contracts Dioxus DOM bridge._

## Responsibility
The headless Dioxus renderer on blitz: `DioxusDocument` integrates `BaseDocument` with a `VirtualDom`, writes vdom mutations into the DOM and routes DOM events back to vdom handlers. The windowed `dioxus-native` crate builds on it; the seven_guis stand runs through it.

## Key integrations

### Consumes from
- blitz-dom (shared as `Rc<RefCell<BaseDocument>>`), dioxus-core / dioxus-html 0.7.3.

### Publishes to
- `DioxusDocument` (`vdom`, `inner`, `initial_build`, `poll`, `handle_ui_event`, `vdom_state.try_element_to_node_id(ElementId)`), `NodeHandle` backing `MountedData`.
- Stable element ids: `element_id(NodeId) -> Option<String>` and `element_ids() -> Vec<(NodeId, String)>` (document pre-order, pairwise distinct), computed on demand and written to neither the DOM nor the vdom; under the `accessibility` feature (which enables an optional `accesskit` and is forwarded from dioxus-native's) `DioxusDocument`'s `Document::accessibility_tree` override carries each one as its element node's AccessKit `author_id`, never on a `TextRun`, the document root or the `Window` node — four tiers: author key (the HTML `id`: non-empty, `/`-free, first in document order) → anchored path (`{key}//{segment}`, e.g. `box//p:0/b:0`, for an element under an element of its own component instance that reads an author key; the nearest one anchors) → component path (`TaskShell/Counter/div:0`; `{tag}[{key}]` for a Dioxus-keyed root; a component's template root always restarts here, so an anchor acts inside one component only) → document path (`/html:0/body:0`). An unusable `id` (empty, `/`-bearing, a later duplicate) neither keys nor anchors, and an anchored path is the only id holding `//`. Proven persistent on the stand: the same id across a re-render, a remount (fresh `NodeId`s for every element bar the `html`/`head`/`body`/`#main` skeleton, which lives outside the VirtualDom) and a second process (`stand_id_persistence`), and across edits of the code around an element — a keyed element under every edit, an anchored one under an edit outside its keyed element, any element under a behaviour edit; an earlier same-tag sibling or a wrapper inside the subtree a path starts at still renames an unkeyed element (`stand_id_edits`).
- Actionable-key check (under `accessibility` only): `DioxusDocument::unkeyed_actionable() -> Vec<UnkeyedActionable>` returns every actionable element whose id is a positional path, in document pre-order — actionable meaning focusable (`Node::is_focussable()`), or an interactive role on its accessibility node, or a listener (`data-dioxus-id`), so a disabled control is held by its role and a hidden one by the other two. `UnkeyedActionable` carries `node` (a process-local `NodeId`), `id`, `tag`, `role: Option<Role>`, `focusable`, `interactive_role`, `listener` and `remedy()`; never text, a name or an attribute value. Read-only, logs nothing; no wire form and no driver command yet. The stand reads it empty on the four lean tasks and Home and, since 2026-10-14-stand-requirement-sweep, on Temperature Converter, Circle Drawer (its dialog open included) and Cells too (2 · 3 · 676 until then), and on the load page `stand::boot_load` mounts, its two elements keyed `load-fetch` · `load-done` — empty on all six served tasks (`stand_load_page`), keyed by author ids added as `id:` lines alone (`stand_actionable_keys`, `stand_non_lean_tasks`).
- Snapshot model (under `accessibility` only): `DioxusDocument::snapshot() -> Snapshot`, a read-only tree built from the `accessibility_tree` override. `Snapshot { roots }` with `nodes()` (pre-order) and `get(id)`; a `SnapshotNode` carries `id` (the `author_id`), `role` (`accesskit::Role`), `name` (the node's `label`, else its `labelled_by` targets' names, trimmed — since the 2026-10-17 upstream sync the `label` is also the computed text of an element's `aria-labelledby` targets, which outranks a `<label>`, while the snapshot reads no description and `aria-disabled` moves no snapshot reading, `enabled` still reading the `disabled` attribute), `state` (`NodeState { enabled, checked, value, selected, pressed, invalid, focused }` — seven fields; a struct literal without a spread names all seven), `bounds` (`get_client_bounding_rect` — viewport-relative, for every element, an option of a closed select, under an `optgroup` too, reading its select's client rect (the public, re-exported `closed_select_of`, called by the snapshot's builder and escher-driver's `lint.rs`, over the public, re-exported `is_multiple_select`, also read by `execute.rs` `locate`, and `BaseDocument::select_of`), so a select's options are its children in the snapshot, a group's its group's, named by their labels, a `multiple` select's rows and groups reading client rects of their own: an element under a transform read where its transforms move it (ratified by the founder, 2026-10-18), so a driver `click` on a translated button is accepted and lands; a box that is itself scrolled reads where it stands since 2026-10-10-scrolling-box-bounds-and-hit, the same before and after its content is scrolled) and `children`. A node is every element the accessibility tree keeps, generic containers included; `TextRun`s, the document root and the `Window` are not nodes. State is read from the element, since the tree gives an element no value: `enabled` follows the PRESENCE of `disabled` on an element that can be disabled (a `disabled="false"` and a bare `disabled` read `Some(false)` and, since 2026-10-13-stand-keyboard-harness, are not focusable either — the engine's focusability reader keys on presence too), `checked` is a native checkbox's or radio's own state, else, for a node whose tree role is one of the five checkable roles, `toggled == Toggled::True` — `None` where the role states nothing, a mixed one `Some(false)` (ratified by the founder, 2026-10-18), `value` is a `select`'s chosen option's value, a `multiple` select's first chosen option in tree order (`BaseDocument::select_value`, the reader taking the document and the node, no mask applying), else the editor's text, else — for a range `input`, since 2026-10-13-range-input-interaction — its current value `range_input_value()` (the formatted value a key or a pointerdown moved, while its `value` attribute keeps what the markup wrote), else the `value` attribute — and a password or file `input` — the public `is_masked_input(&ElementData) -> bool`, re-exported beside `MASKED_VALUE`, true for an `input` whose `type` reads `password` or `file` (ASCII case-insensitive), the test this reader calls and the one escher-driver's recorder reads to keep a masked `type` as its stand-in — reads the public constant `MASKED_VALUE` (eight U+2022) where it holds a non-empty value and `""` where that value is empty, never the text, its length or a file's host path (the DOM attribute and form submission still hold the path); `selected`, `pressed` and `invalid` are the exception — the accessibility node holds them (blitz-dom's builder writes them from `aria-selected`, `aria-pressed` (or `aria-checked` on a checkable role) and `aria-invalid`, and on a native checkable control from neither, writing `toggled` from `checkbox_input_checked()` under a checkable role and nothing under any other, so `pressed` never reads on one), so the snapshot takes them from the tree and never parses the element a second time: `selected` is `is_selected()` (a select's option's is its chosen state, which the builder writes with no `aria-selected` read, so a single select's choice names the old and the new option with `selected` in `differs` and a `multiple` select's names each row whose chosen state moved), `pressed` is `toggled()` off the five checkable roles, with only `Toggled::True` reading `Some(true)` (a mixed toggle reads not pressed), `invalid` is `invalid().is_some()` (a grammar or spelling error reads invalid); `focused` is the tree's focus. No field holds a `NodeId`, tree id, `ElementId`, `ScopeId` or pointer; its one serialized form is the text below, which the driver's `snapshot` command returns (`stand_snapshot`, `stand_snapshot_state` — the selected and invalid readings each asserted equal to the accessibility node's — the flight type's chosen option, the selected CRUD row, a date field holding no date — the stand stating no `aria-pressed`, so `accessibility_states` pins the pressed reading on a fixture).
- Snapshot text (under `accessibility` only, module `snapshot_text`): `Snapshot::to_text() -> String`, a pure function of the model — one line per node in `nodes()` order, each ended by a line break, a child indented two spaces deeper. A line reads `Role "name" id="id"`, then the state tokens the model holds in the fixed order `enabled`/`disabled` · `checked`/`unchecked` · `value="…"` · `selected`/`unselected` · `pressed`/`unpressed` · `invalid` (only when true) · `focused`, then `@x,y widthxheight` (`TextInput "Name:" id="who" enabled value="Ada" focused @8,8 200x24`). The role is its `Debug` spelling; strings are in `str`'s `Debug` form, so a field never holds a line break or a bare `"` and an apostrophe stays as it is; numbers are `f64`'s `Display`. No `Display` impl, no parser, no JSON form, and `to_text` itself never truncates or pages; beside it `Snapshot::text_parts(&self, budget: usize) -> Vec<TextPart>` (`TextPart { text: String, ids: Vec<String> }`, re-exported beside the budget) cuts that text into parts — consecutive pre-order lines while a part stays within `budget` bytes, never splitting a line, a line longer than `budget` a part alone, an empty snapshot one empty part — the parts concatenated being `to_text()`, with no document access, failure path, log or print; its one caller outside the tests is escher-driver's executor, which for a screen over the budget or a `part` asked returns one part of `text_parts(SNAPSHOT_TEXT_BUDGET)` as `Outcome::Part` (written with the counts `part` and `parts`, over MCP its JSON line), a whole screen still `Outcome::Screen`. `SNAPSHOT_TEXT_BUDGET` (10,000 bytes, re-exported) is the ceiling one screen's text stays under — compared by the caller, never enforced; the lean stand screens read 755 · 1295 · 1259 · 2055 bytes. The text is content (ids, names, a text control's value): this crate hands it to its caller and nothing else — never log, print or write it here (ratified by the founder, 2026-10-07); since 2026-10-10-driver-cli escher-driver carries it out of the process as a hosted `snapshot`'s answer, over the session socket and onto the command line's stdout (ratified by the founder, 2026-10-10), and since 2026-10-10-mcp-surface as the `snapshot` tool's result to an MCP client on the `escher-session mcp` role's stdout (ratified by the founder, 2026-10-10); a kept check holds it at rest — each kept answer whole, a `snapshot`'s text and an acting verb's diff included — in an owner-only file never logged, the two committed checks under `tests/blitz-tests/checks/` the one exception to owner-only (`stand_snapshot_text`, `stand_mcp_tools`).
- Snapshot diff (under `accessibility` only, module `snapshot_diff`): `Snapshot::diff(&self, after: &Snapshot) -> SnapshotDiff`, a pure comparison of two snapshots by stable element id. `SnapshotDiff { added, removed, changed }` with `is_empty()`; `added` and `changed` hold `DiffNode { id, parent, role, name, state, bounds, differs }` — the node's reading AFTER the step, flat, `parent` its parent snapshot node's id (`None` for a root), and, since 2026-10-12-self-description, `differs` the readings that differ from before the step in node-key order (`Reading::ALL`), empty for an added node, a node that only moved reading `[Bounds]` — and `removed` holds ids; `pub enum Reading` (eleven variants, `Parent` · `Role` · `Name` · `Enabled` · `Checked` · `Value` · `Selected` · `Pressed` · `Invalid` · `Focused` · `Bounds`, with `Reading::ALL`) is re-exported beside them. Added = in `after` only; removed = in `self` only; changed = in both and role, name, state, bounds or parent's id differ; a node is never named because a descendant changed. `added` and `changed` follow `after`'s pre-order, `removed` follows `self`'s; where two nodes carry one id the first in pre-order stands for it, as `Snapshot::get` reads it. Values come from the snapshots only, so a password's or file input's value is `MASKED_VALUE`; no field holds a `NodeId`, `ElementId`, `ScopeId`, tree id or pointer. It is NOT derived from blitz-dom's changed set (`has_changes` / `take_changed_nodes` — "something was written since the last drain"): the flag can read true beside an empty diff, and bounds-only movement shows in the diff without marking the set. No text form, `Display`, JSON, parser or `DioxusDocument` entry point in this crate; a diff is content, and this crate hands it to its caller only (ratified by the founder, 2026-10-07) — since 2026-10-10-driver-cli escher-driver writes a returned diff as JSON and carries it out of the process in a hosted call's answer (ratified by the founder, 2026-10-10), and since 2026-10-10-mcp-surface in an acting MCP tool call's result (ratified by the founder, 2026-10-10) (`stand_diff`); no log or event carries a diff, and a file only as a kept check's kept answer, owner-only and never logged, the two committed checks the one exception — while the three list lengths of a diff the driver returns, counts only, are recorded on escher-driver's command span and printed by the sink at `info` or below (ratified by the founder, 2026-10-09: the sentence stands, with the clarification that a diff's content never reaches a log while its three sizes may).

## Internal conventions
- DOM events route to the vdom via the nearest `data-dioxus-id` attribute (parsed as `usize`); listener registration sets a `"<rust func>"` placeholder; `Input | Change` reach the app as `NativeFormData { value }`, `multiple_select_values` filling `values` with one `(name, FormValue::Text(value))` per chosen option of a `multiple` select so `evt.values()` reads the set while `value` stays `select_value`, so a select's `onchange` handler fires — and since Dioxus writes a dynamic `selected` again on each re-render, a controlled app writes `selected` from its `input` event's value or a choice reverts.
- `style`-namespace attributes become style properties; `dangerous_inner_html` sets inner HTML; a falsy value (Bool false, `"false"`, 0, None) of one of the 28 names of upstream's private predicate `is_bool_attr` (`mutation_writer.rs`, a closed `matches!` set: `checked`, `disabled`, `hidden`, `readonly`, `required`, `multiple`, `selected`, `open`, `autofocus`, `inert` and 18 more — escher's own 27-name `BOOLEAN_ATTRIBUTES` list retired for it at 2026-10-13-upstream-sync-polish-and-ship, upstream #1188; a framework-written `inert: false` is cleared and leaves content as it was, while a truthy `inert` makes its subtree inert — not focusable, not hit, out of the accessibility tree and the snapshot) clears the attribute, on the dynamic and the static template path alike.
- Every document starts as `<html><head></head><body><main id="main"></main></body></html>`; `DioxusDocument::new` adds no stylesheet of its own — the default user-agent sheet arrives once through `DocumentConfig::default()`, and a config that sets `ua_stylesheets` is used as given (upstream #1189, since 2026-10-13-upstream-sync-polish-and-ship; until then `DEFAULT_CSS` was always added); base URL `dioxus://index.html`.
- `mounted` listeners fire after `initial_build` and each `poll`; event kinds with zero handlers are skipped.
- A crate-local `trace!` macro expands to `tracing::debug!` under `tracing` (its 4-argument arm passes only the first two items).

## Crate-specific gotchas
- `mutation_writer.rs` has a "WARNING: DO NOT REORDER" block.
- Twelve event-data conversions call `unimplemented!()`; IME events are not handled; `NativeFormData::valid` always returns true.
- `element_to_node_id` unwraps; `NodeHandle::node` panics if the node is gone. A task spawned from a key handler that writes a signal is first polled inside `render_immediate`, which holds the document's `RefCell`, so a `MountedData` call in it panics at `events.rs:162` (`RefCell already borrowed`) — a measured hazard any app meets, no engine change; Cells calls its handles synchronously.
- `VComponent.name` is the component's full type path (`crate::module::Name`, generics included), and the user root sits under dioxus-core's RootScopeWrapper → SuspenseBoundary → ErrorBoundary scopes — the id walk strips the path and skips those four scopes.
- A node a re-render removes is dropped with its descendants by the crate-private `remove_and_drop_node` / `replace_and_drop_node`, its `element_id_mapping` / `node_id_mapping` entries cleared, so it no longer resolves — `get_node` `None`, `element_id` `None`, no pair in `element_ids()` (upstream #1185, since 2026-10-13-upstream-sync-polish-and-ship; until then it was only DETACHED and kept resolving until its ElementId was reassigned).
- A `key:` on an element inside an `if` within a `for` body does not key the list: the `for` items are the unkeyed `if` wrappers, diffed by position, and a changed inner key replaces the node — put the filter in the iterator so each `for` item is the keyed element.
- An attribute outside the 28-name `is_bool_attr` set is written with its stringified value even when falsy (`aria-hidden`, a `data-` attribute holding `false` reads `"false"`) — blitz-dom keys element state and click targeting on presence, so a boolean attribute missing from the list would read as set.
