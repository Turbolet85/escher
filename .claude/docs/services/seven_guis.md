# seven_guis (the stand)

_Crate notes. Primary sources: `.andromeda/architecture.md` §Existing Scopes, `.andromeda/layout-templates.md` desktop-native, the active `escher-X.Y.Z/intent.md`._

## Responsibility
The 7GUIs benchmark app ("Seven benchmark tasks for GUI frameworks") in Dioxus — tasks counter, temp_converter, flight_booker, timer, crud, circle_drawer, cells. escher's internal stand: every 0.1.0 capability (stable ids, snapshot, driver, screenshots, a11y) is proven on it headlessly, with a minimal fixture beside it where the tasks lack a case (an element covered by another is one).

## Key integrations

### Consumes from
- escher-driver (native target only): the second binary, `escher-session <verb> [arguments] --session <dir>` (`src/session_host.rs`), is the driver's command line over the four lean tasks and the one place a lean task, the stand's boot and the timer's tick handle meet a driver `Session` — `main` installs the telemetry sink first, then hands argv, the four slugs `counter` · `flight-booker` · `timer` · `crud` and the stand's boot to `escher_driver::command_line`; the boot starts a session through `stand` only and hands the timer's session its time step (`stand::timer_step` over the tick handle, through `Session::with_time`; the other three carry none). `start <task>` spawns the same binary in its host role, `serve <task> --session <dir>`, which serves until `stop` or its 30-minute idle expiry and writes nothing to stdout; every other command is one client run that answers one line of JSON on stdout (exit `0` accepted · `1` refused · `2` usage · `3` session error). The former two-argument form `<task> <state-dir>` is gone. Five test targets spawn it, sharing `tests/common/mod.rs`: `tests/host_binary.rs` is the host role's smoke (on `counter`); `tests/host_log.rs` checks that at `RUST_LOG=trace` a host running three calls writes one command-span line per call and no stable id, no accessible name and no typed text to stderr (on `crud`, per package and under the workspace build); `tests/host_timer.rs` boots the timer host and moves it by a hosted `advance`; `tests/cli_commands.rs` runs every driver command as a process on the four tasks; `tests/cli_flow.rs` runs the two POSIX `sh` flows of `tests/flows/` (`counter.sh`, `flight.sh`).
- dioxus-native (native binary `seven_guis_native`) or a wasm32 cdylib (`--no-default-features --features hybrid`, `console_error_panic_hook`).
- escher-telemetry (native target only): `main` calls `escher_telemetry::init(escher_telemetry::service_identity!())` before `launch` — stderr log lines carry `service.name=seven_guis`; an init `Err` is `eprintln!`ed and the stand still launches. The engine `tracing` features stay off in a `-p seven_guis` build; a workspace-wide build turns blitz-dom's on, and with it blitz-dom's `writing-mode`, which selects the body of the bounds reader that every snapshot `bounds` and `visible_region` read through (test-plan §9 → Engine features by runner).

- On the native target only, escher-telemetry, blitz-test-harness and blitz-traits (the headless stand) and escher-driver (the session its `escher-session` binary hosts), with `dioxus-native` features `system-fonts` + `woff` — `woff` decodes the bundled DejaVu woff2 in every build that includes the stand. seven_guis is a `[workspace.dependencies]` path entry with default features (dioxus-native refuses to compile with no renderer); blitz-tests consumes it as a dev-dependency.

### Publishes to
- Screens: Home (centered 640px column of task cards with description and tag, inside a box that scrolls — at the stand's 800 × 600 viewport that box is 600 high and the seventh card, Cells, lies below it until scrolled into view) and TaskShell (header with back button, title, spacer over a scrolling body).
- The headless stand `seven_guis::stand` (native only): `LeanTask { Counter, FlightBooker, Timer, Crud }`; pinned `VIEWPORT_WIDTH 800` · `VIEWPORT_HEIGHT 600` · `HIDPI_SCALE 1.0` · `COLOR_SCHEME Light`; `font_ctx()` (bundled DejaVu Sans, system fonts off); `options(incremental) -> HarnessOptions` (offline: `net_provider: None`); `boot(LeanTask, options) -> Harness<DioxusDocument>` and `boot_timer(options) -> (Harness, TimerTicks)` — each a fresh `VirtualDom` mounting the task in TaskShell (no Home) with a no-op Back; `TIMER_TICK_MS` (100) and `timer_step(TimerTicks)`, the Timer's time step for a driver session (`Session::with_time`): it delivers the whole ticks the milliseconds asked hold, returns the milliseconds those ticks stand for, drops the remainder per call and leaves the harness's animation clock alone. It installs no telemetry, reads no env var, names no `blitz_net`.
- `app::Task` (pub) and `app::task_in_shell(Task, EventHandler<()>)` — the windowed `app()` and the stand render through the same mapping; `TaskShell` stays private. `DEJAVU_SANS` — the crate-root woff2 bytes, shared by the wasm entry and the stand.
- `tasks::timer::TimerTicks` — the timer's tick seam: absent from context, the timer runs its 100 ms `futures_timer::Delay`; present, each `deliver(n)` tick is one 0.1 s step capped at the duration, applied on the next pass — a pump, an input helper's own pump, or a settle (`Harness::settle`, `Session::act`, each acting verb of `Session::run`), so a delivery made after an input helper waits for a later pass. Every stand boot provides one, so an undriven timer holds 0.0 s.

## Internal conventions
- Example CSS in `const CSS: &str` raw strings; accent `#4a6cf7` on `#f5f5f5`, text `#1a1a1a`; invalid `#e53e3e` family, success `#ebf8ee` family.
- Inputs replace the focus outline with a border colour or box-shadow on focus.
- `idna_adapter = "=1.0.0"` pin disables unicode URL support.

## Stand-relevant behaviour
- Flight booker validates `dd.mm.yyyy` with month range and leap years; return not before start; invalid dates get an `invalid` class and disable Book.
- Cells: tokenizer rejects unknown characters, reference cycles read `#CYCLE`, division by zero is an error; commits on Enter or blur.
- Circle drawer clamps diameter 5–100.

## Testing this crate
- Stand checks live in `tests/blitz-tests/tests/stand_{boot,counter,flight_booker,timer,crud,element_ids,id_persistence,accessibility_ids,snapshot,snapshot_state,snapshot_text,diff,id_edits,actionable_keys}.rs`, each building its own harness through `stand::boot` (or `Harness::from_vdom` with `stand::options` for Home, the edit fixtures, the state fixture — a checkbox, two radios and a password input the lean tasks lack — the text check's two fixtures, a password input and a file input, and the diff check's three — a panel hidden by attribute, a password input and a label a button rewrites) and driving it with the harness input helpers: `cargo test -p blitz-tests --test stand_boot` (etc.). They assert unconditionally under the bundled font — no font skip, no sleep, no `dispatch_recorded`. Each lean task's controls and value displays carry author `id`s (`counter-value`, `flight-book`, `timer-reset`, `crud-delete` …) that are their stable element ids — select them by `#id`; the pre-id checks still select by class and by structural selectors under `.crud-root`. Each CRUD row carries the Dioxus key `{person.id}`, its person's model-assigned `u64`, set on the `for` item itself with the filter in the iterator (a `key:` inside an `if` within the `for` would not key the list), and beside it the author `id` `crud-person-{person.id}` — so a row's id is `crud-person-0` · `-1` · `-2` on the fixture, Create from `crud-person-3`, and follows its person under filter, Create and Delete. Home's seven task cards carry `task-card-{slug}` (`counter`, `temp-converter`, `flight-booker`, `timer`, `crud`, `circle-drawer`, `cells`) — open a task with `#task-card-timer`. Every element an agent can act on must read an author key: `stand_actionable_keys` asserts `unkeyed_actionable()` empty on the four lean tasks and Home, so a new control there needs an `id`; the temp converter, circle drawer and cells are not keyed yet (2 · 3 · 676 pinned). The six task inputs are named by attributes alone — `r#for` on the existing labels of `timer-duration` / `crud-filter` / `crud-name` / `crud-surname`, `aria_label` on `flight-start` ("Departure date") and `flight-return-date` ("Return date"). seven_guis takes dioxus-native with no `accessibility` feature, so `just seven_guis` builds no AccessKit adapter; since 2026-10-07-act-by-id it gets dioxus-native-dom's `accessibility` through its `escher-driver` edge, so both its binaries compile the `accessibility_tree` override and the snapshot modules — still with no adapter to hand a tree to. The driver-action checks `stand_act_{ids,diff,timer,refused,keys,range}.rs` drive a held stand session through `escher_driver::Session::run`, by stable id.
- `type_text` into a Dioxus controlled input reaches its `oninput` (the flight-booker and CRUD checks witness it).
- Run windowed: `just seven_guis` (`RUST_LOG=info` shows the telemetry lines on stderr).
- Boot smoke (windowed, needs `WAYLAND_DISPLAY`): `RUST_LOG=info timeout 10 target/debug/seven_guis_native` — exit 124 (still up when stopped) and `service.name=seven_guis` in the log.
