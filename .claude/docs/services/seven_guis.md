# seven_guis (the stand)

_Crate notes. Primary sources: `.andromeda/architecture.md` §Existing Scopes, `.andromeda/layout-templates.md` desktop-native, the active `escher-X.Y.Z/intent.md`._

## Responsibility
The 7GUIs benchmark app ("Seven benchmark tasks for GUI frameworks") in Dioxus — tasks counter, temp_converter, flight_booker, timer, crud, circle_drawer, cells. escher's internal stand: every 0.1.0 capability (stable ids, snapshot, driver, screenshots, a11y) is proven on it headlessly, with a minimal fixture beside it where the tasks lack a case (an element covered by another is one).

## Key integrations

### Consumes from
- escher-driver (native target only): the second binary, `escher-session <verb> [arguments] --session <dir>` (`src/session_host.rs`), is the driver's command line over six served tasks — the four lean ones, Cells and the load page — and the one place a served task, the stand's boot and the timer's tick handle meet a driver `Session` — `main` installs the telemetry sink first, then hands argv, the six slugs `counter` · `flight-booker` · `timer` · `crud` · `cells` · `load` (a private `TASKS` table, from which the usage line's `apps:` and the MCP `start` tool's `enum` are written) and the stand's boot to `escher_driver::command_line`; the boot starts a session through `stand` only (Cells through `stand::boot_cells`, the load page through `stand::boot_load`) and hands the timer's session its time step (`stand::timer_step` over the tick handle, through `Session::with_time`; the other five carry none and still take `advance`, which moves their session's clock alone (ratified by the founder, 2026-10-18)). `start <task> [--record <dir>]` checks its recording directory itself before it spawns, then spawns the same binary in its host role, `serve <task> --session <dir> [--record <dir>]` (passing `--record` to the host); since 2026-10-19-session-recording `--record <dir>`, taken at most once on `start`, the host role and the `mcp` role, keeps the session as one owner-only replayable check — `check-{n}.json` (`0600`, never replacing a file) in a `0700` directory whose parent must exist, never removed by escher, holding per call its verb, arguments, acceptance, the answer's digest and, since 2026-10-19-recorded-check-replay, the answer itself as an `answer` key — the line the driver wrote, masked as on every carrier, a shot's kept as `{"width":…,"height":…}` without its `png` — read back and replayed by `Check::replay` (ratified by the founder, 2026-10-19: F1 A · F2 B, F3 B) — a directory open to its group or others refused as the session error `record-dir-not-private` (exit 3, `start` spawning nothing), a recording that ends answering `recording-failed` (exit 3; over MCP `isError`); the host serves until `stop` or its 30-minute idle expiry and writes nothing to stdout; every other command is one client run that answers one line of JSON on stdout (exit `0` accepted · `1` refused · `2` usage · `3` session error — the four read from `EXIT_STATUSES` and served by `help`), save `help` (since 2026-10-12-self-description), which needs no `--session` — it admits at most one and reads it not — and answers the tool's self-description with status `0`, reaching no session; the `mcp` role lists it as its twelfth tool, last, after `lint`. Since 2026-10-12-headless-screenshot the seventh instance verb, `screenshot [--id <id>] --session <dir>`, answers one uncoloured line `{"width":…,"height":…,"png":"<base64>"}` on stdout, exit 0 — the whole screen, or with `--id` the element cropped to the part of its bounds that can be seen — an app with no font it can paint text with refused `fonts-unavailable` and an element shot that crops to no pixel `off-screen`, exit 1; over the `mcp` role an accepted shot is an `image` block (`image/png`, base64) then a text block, the line without `png`. The eighth instance verb, `lint --session <dir>`, takes no argument (one named refused `malformed`) and answers one uncoloured line `{"findings":[…]}` on stdout, exit 0, each finding keyed `id` · `defect` · `bounds` then its reason's keys — ids, closed words and numbers only — an app with no font it can paint text with refused `fonts-unavailable`, exit 1, a `lint` step kept under `--record` like every instance verb; over the `mcp` role an accepted `lint` answers its JSON line of findings as one text block. The first instance verb, `snapshot [--part <part>] --session <dir>`, takes an optional `--part` (a whole number, 1 to 1000) and answers one uncoloured line on stdout, exit 0 — `{"text":…}` for a whole screen, `{"text":…,"part":n,"parts":m}` for a screen read in parts, from part 1 without `--part`, a part past the last the empty text with the same `parts`, a `--part` outside its bound refused `malformed`, exit 1; over the `mcp` role a paged `snapshot` answers its JSON line `{"text","part","parts"}` as one text block, a whole screen still the bare screen text. The former two-argument form `<task> <state-dir>` is gone. Since 2026-10-10-mcp-surface its `mcp` role, `escher-session mcp [--record <dir>]` (the `--record` since 2026-10-19-session-recording), is an MCP server over its standard streams (`escher_driver::serve_mcp`): its `start` tool, its `enum` naming the six, boots one of the six served tasks through the same boot and holds it in process, adding no markup; it writes protocol lines only on stdout and ends with nothing there. ### Publishes to
- Screens: Home (centered 640px column of task cards with description and tag, inside a box that scrolls — at the stand's 800 × 600 viewport that box is 600 high and the seventh card, Cells, lies below it until scrolled into view) and TaskShell (header with back button, title, spacer over a scrolling body); headless only, two screens beside the lean four, each by a boot of its own — Cells (`boot_cells`) and the load page (`boot_load`: TaskShell titled "Load" over the button `load-fetch` "Load", white on `#3a5ce5`, hover `#2a4cd3`, active `#1f3fc1`, and the paragraph `load-done` "Loaded", `display: none` until the stylesheet the click links lands, no CSS selecting by id).
- The headless stand `seven_guis::stand` (native only): `LeanTask { Counter, FlightBooker, Timer, Crud }`; pinned `VIEWPORT_WIDTH 800` · `VIEWPORT_HEIGHT 600` · `HIDPI_SCALE 1.0` · `COLOR_SCHEME Light`; `font_ctx()` (bundled DejaVu Sans, system fonts off); `options(incremental) -> HarnessOptions` (offline: `net_provider: None`); `boot(LeanTask, options) -> Harness<DioxusDocument>` and `boot_timer(options) -> (Harness, TimerTicks)` — each a fresh `VirtualDom` mounting the task in TaskShell (no Home) with a no-op Back; `boot_cells(options)`, Cells in TaskShell, no `LeanTask`, its screen past the snapshot text's budget and read in parts; `boot_load(options)`, the load page in TaskShell, its `net_provider` replaced by the private `LoadNet` — each `fetch` answering the fixed `LOADED_CSS` for the fixed `LOAD_URL` `http://stand.test/load.css` from a thread of its own after `LOAD_ANSWER_DELAY` (200 ms), no `is_noop` override, so the harness counts its load — every other boot offline; `TIMER_TICK_MS` (100) and `timer_step(TimerTicks)`, the Timer's time step for a driver session (`Session::with_time`): it delivers the whole ticks the milliseconds asked hold, carrying the remainder below one tick across calls (250 then 250 deliver 2 then 3 ticks), and returns nothing — the session, not the step, moves the harness's clock (ratified by the founder, 2026-10-18). It installs no telemetry, reads no env var, names no `blitz_net`.
- `app::Task` (pub) and `app::task_in_shell(Task, EventHandler<()>)` — the windowed `app()` and the stand render through the same mapping; `pub fn TaskShell` — the shell a test-local variant of a task mounts in so its unkeyed ids read as the task's. `DEJAVU_SANS` — the crate-root woff2 bytes, shared by the wasm entry and the stand.
- `tasks::timer::TimerTicks` — the timer's tick seam: absent from context, the timer runs its 100 ms `futures_timer::Delay`; present, each `deliver(n)` tick is one 0.1 s step capped at the duration, applied on the next pass — a pump, an input helper's own pump, or a settle (`Harness::settle`, `Session::act`, each acting verb of `Session::run`), so a delivery made after an input helper waits for a later pass. Every stand boot provides one, so an undriven timer holds 0.0 s.

## Internal conventions
- Example CSS in `const CSS: &str` raw strings; accent `#3a5ce5` on `#f5f5f5` (one step darker since 2026-10-14-stand-a11y-assertions, `#4a6cf7` until then; white button text on it 5.47), text `#1a1a1a`; invalid `#e53e3e` family, success `#ebf8ee` family.
- Inputs replace the focus outline with a border colour or box-shadow on focus.
- `idna_adapter = "=1.0.0"` pin disables unicode URL support.

## Stand-relevant behaviour
- Flight booker validates `dd.mm.yyyy` with month range and leap years; return not before start; invalid dates get an `invalid` class and disable Book.
- Two states are stated in markup, by attribute alone (2026-10-10-snapshot-states; no element, class, style, key, id or order moved): the flight booker's date inputs `flight-start` / `flight-return-date` state `aria-invalid`, `crud-list` is a `listbox` and each CRUD row an `option` with `aria-selected` — always the literal texts `"true"` and `"false"`. A snapshot reads them as `invalid` and `selected`. The stand states no `aria-pressed`: the flight booker's mode is one `select#flight-type` (class `type-select`, named by `aria-label` "Flight type" alone) holding `option#flight-type-one-way` (value `one-way`) and `option#flight-type-return` (value `return`), each `selected` from the `flight_type` signal — the snapshot reading it at boot `ComboBox "Flight type"` with value `one-way` and two `ListBoxOption`s, each at the select's client rect. Since 2026-10-13-stand-keyboard-harness the CRUD list is a keyboard region — `crud-list` takes `tabindex="0"` and an `onkeydown`: ArrowDown selects the next visible row (the first when none is selected), ArrowUp the previous, Home the first and End the last, each filling `crud-name` and `crud-surname` as a row's click does, a key at the list's end or ArrowUp with no row selected changing nothing — so CRUD's Tab sequence reads `back-btn` · `crud-filter` · `crud-list` · `crud-name` · `crud-surname` · `crud-create` (six stops); no element, class, style, wrapper or row added, and the tree's focus is the list, never the row (no `aria-activedescendant` read). Since 2026-10-14-stand-a11y-assertions the list is named by an attribute alone — `aria-label="People"`, its accessible name `People` in the tree and the snapshot — adding no element, class, style, wrapper, id or order. Cells states no selected cell; stating it (`aria-selected` under a grid role) is owned by a `.andromeda/residuals.md` line (target: next) on the operator's "Key all three; C8 deferred" (2026-10-14).
- Cells: it calls its `MountedData` handles synchronously, such a call in a signal-writing task spawned from a key handler panicking at `events.rs:162` (`RefCell already borrowed`); tokenizer rejects unknown characters, reference cycles read `#CYCLE`, division by zero is an error; commits on Enter or blur. Since 2026-10-31-engine-debts `cells-grid` is a keyboard region and one Tab stop — `id`, `tabindex` 0, `aria_label` Cells and an `onkeydown`, with no role: arrows move `current`, clamped, into view through a synchronous `MountedData::scroll_to(ScrollBehavior::Instant)`, one `onmounted` per data cell holding the handles; Enter opens the editor on `current`, focused, and its Enter commits, stops propagation and returns focus to the grid; a click inside an open editor returns early and keeps its typed text; `.cells-grid:focus .cell.current` draws the accent outline, `2px solid #3a5ce5`; the Tab sequence is the one `CELLS_TAB_ORDER` states.
- Circle drawer clamps diameter 5–100.
