## Harness contract (§3)

- **In-process harness (measured):** `blitz-test-harness::Harness` — construct (`from_html`, `from_component`, `from_vdom`; `HarnessOptions` also takes `font_ctx` and `incremental`), `pump`/`tick`, `settle` (that pass repeated until no work is due: `Settled`, or `NotSettled` naming the busy class — `Render` · `Layout` at the 64-pass bound, `Loads` at once; no clock read, no time advanced, no load waited on), input helpers that pump, inspection (`query`, `layout_rect`, `text_content`, `focused`, `hit`, `dom_string`), and since 2026-10-12-headless-screenshot a paint with no display — `screenshot` / `screenshot_rect` into `VelloCpuImageRenderer`, composited over opaque white, at the harness's own time with no tick or pump, a document with no font refused `FontsUnavailable`; and since 2026-10-13-stand-contrast-harness a contrast reader — `text_contrast(node_id) -> Option<TextContrast>`, reading and changing nothing (no mutation, input, pump or settle): the text-bearing element's computed `color`, font size and weight over the background composited source-over from its ancestors' `background-color`s onto the root-else-`body` canvas over opaque white, `None` with no text or where an element on the walk has `opacity` below 1, a filter or a background image, and `contrast_ratio` the WCAG 2.x ratio. See `.claude/rules/verification-harness.md`.
- **Headless stand (measured):** `seven_guis::stand::boot(LeanTask, options)` / `boot_timer(options)` mount counter, flight booker, timer or CRUD in TaskShell — fresh `VirtualDom` per boot, pinned 800×600 · scale 1 · Light, bundled DejaVu Sans with system fonts off, offline (`net_provider: None`); the timer advances only through its `TimerTicks` handle (`deliver(n)`, applied on the next pass — a `pump`, an input helper's own pump, or a settle; a delivery made after an input helper waits for a later pass); a driver session moves it by `advance`, through `stand::timer_step` handed to the session with `Session::with_time` — whole ticks of `TIMER_TICK_MS` (100), the remainder dropped per call, `advanced_ms` the time delivered and never more than asked, the harness clock untouched.
- **5-command discipline (measured):** `bash scripts/agent-run.sh {boot | run {stand|all|name} | status | cleanup | logs}` from the repository root (`scripts/agent-run.ps1` passes through to it on Windows). Exit `0` success · `1` failed (an empty run is never a pass) · `2` usage (checked first) · `3` precondition unmet. `boot` builds every blitz-tests binary; `run` drives `cargo test -p blitz-tests --locked`; `status` reads `status.json`; `cleanup` is idempotent; `logs` prints `events.jsonl`. Stdout is JSON lines only (`boot`, `run.start`, `test`, `run.end`, `status`, `cleanup`), never captured test output; state in `target/agent-run/{status.json, events.jsonl, run.log}`. The script starts no daemon and has no PID file, status endpoint, port or env var; the stand checks boot in process, bar the two session process checks, which start and stop their own host and socket (the "Session lifecycle" key, `.andromeda/registries/contracts/test-plan/session-lifecycle.md`). See `.claude/rules/verification-harness.md`.
- **Cold-agent run pipe (measured):** `bash scripts/cold-agent.sh {run counter | status | cleanup | logs}` — same exit grammar; `run` starts one isolated `claude -p` session (a per-run `mktemp -d` cwd, only the stdlib stdio MCP stub's `list`/`read`/`press`) and writes `target/cold-agent/verdict.json`: `passed` only on positive evidence (client exit 0, a successful `result`, `isolated`, `counts_agree`, ≥ 1 tool call, the stub's own count at 3); `wrong_calls` recorded, never deciding. Proof: `test_cold_agent.py` under a `claude` shim + one recorded live run (passed, 5 calls, 0 wrong). The live run is never in CI.
- **Stand log format (measured):** seven_guis' two binaries, `seven_guis_native` and `escher-session`, write stderr only, one `{RFC 3339 UTC} {LEVEL} {target} service.name=… service.version=… {field}={value}…` line per printed event and — ratified by the founder, 2026-10-09 (obs-plan §6) — one per closed span of an admitted target (the same prefix, then `span={name}`, the span's fields and `message="close"` · `time.busy` · `time.idle`; since 2026-10-10-driver-cli the `escher-session` host writes one `command` span line per call it runs, and since 2026-10-10-mcp-surface its `mcp` role one `tool_call` line per tool call — `tool` and `ending` only, the parent of the call's `command` line, and since 2026-10-12-self-description a `help` call, answered by the server, one `tool_call` line with no `command` line beneath it; since 2026-10-12-headless-screenshot `screenshot` a word of the same two closed sets, no span field added — a shot's `command` line records `verb` (and `cause` when refused), never the image, its size or its dimensions, and the host's and the `mcp` role's stderr at `trace` hold 0 occurrences of a shot's first 64 base64 characters under both builds — 9 lines over one CRUD flow at `info` built alone, 10 with the workspace; the windowed binary still none), behind escher-telemetry's target allowlist — engine and escher targets scrubbed, every other target's record dropped (bound to obs-plan §3); exercised by the five `telemetry_*` integration files, seven_guis' `host_binary` and `host_log` (no id, no name and no typed text on a host's stderr at `trace` while three hosted calls run, under both builds), a command's stdout — its answer and nothing else, one line of JSON, no ESC byte — by `cli_commands`, the `mcp` role's stdout — protocol lines only — and stderr by `mcp_server` and `mcp_log`, the span line by escher-telemetry's five span unit tests and `stand_act_spans`, and a 10 s boot smoke (exit 124 + `service.name=seven_guis`).
