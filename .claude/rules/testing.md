# Testing Rules

Path-scoped rules for test files. Source: `.andromeda/test-plan.md` §2 §4 §5 §7 §8 (test tier 0) and arch §Conventions.

## Framework
- **Unit:** Rust built-in harness — `#[cfg(test)] mod tests` at the end of the source file (eight modules sit in files of their own, each declared `#[cfg(test)]` with `#[path]` at its parent — `recording::off_unix_tests` `#[cfg(all(test, not(unix)))]`, `recording::tests` `#[cfg(all(test, unix))]` —: dioxus-native-dom's `bridge_tests`, a child of `dioxus_document`, so it reaches that module's private fields, and, moved out whole with their test paths unchanged, since 2026-10-16-file-splits blitz-dom's `document::changed_set_tests` and `document::font_reading_tests` and escher-driver's `mcp::tests` and `schema::tests`, and since 2026-10-19-test-splits escher-driver's `cli::tests` in `cli_tests.rs`, `recording::off_unix_tests` in `recording_off_unix_tests.rs` and `recording::tests` in `recording_tests.rs`); `#[tokio::test]` for async workers.
- **Integration:** `tests/blitz-tests/tests/*.rs`, one file per behaviour, depending only on dev-dependencies; the stand checks read the tables and helpers they share from `tests/common/mod.rs` (`mod common;`) and the checks that hold a session — the session checks, `stand_settle`, the fifteen driver-action checks `stand_act_*`, `stand_mcp_tools`, `stand_screenshot_repeat`, `stand_requirement_sweep`, `stand_virtual_clock`, since 2026-10-19-session-recording `stand_session_recording` and, since 2026-10-19-recorded-check-replay, `stand_replay` and, since 2026-10-19-visual-lint, `stand_lint` and, since 2026-10-20-load-wait, `stand_load_wait` and, since 2026-10-20-large-screen-in-parts, `stand_snapshot_parts` and the two served-page checks `stand_cells_served` and `stand_load_page` (31 readers, `stand_cells_served` and `stand_load_page` the thirtieth and thirty-first; `stand_mcp_masked`, `password_painted_masked`, `stand_non_lean_tasks` and `password_caret_click` declare none) — what they share from `tests/session_common/mod.rs` (`mod session_common;`: the held session, the driver's call builders `click` · `type_into` · `press` · `advance` · `scroll` · `snapshot` · `screenshot` · `screenshot_of` · `lint` · `snapshot_part`, the outcome reader `act`, the part reader `part` (a paged snapshot's text, part and count), the shot reader `shot`, the lint reader `linted` (a lint's findings), the refusal readers `refused` and `refused_unchanged`, since 2026-10-19-session-recording the recording readers `kept` and the unix-only `mode`, and since 2026-10-19-recorded-check-replay `shot_prefix` (the first 64 base64 characters of a whole-screen shot) — its `replay` removed then for the replay `Check::replay`); and, since 2026-10-19-shared-fixtures, what 28 checks — 22 `stand_*` files (`stand_snapshot_parts` since 2026-10-20-large-screen-in-parts, `stand_act_select`, `stand_load_wait` since 2026-10-20-load-wait, `stand_lint` since 2026-10-19-visual-lint), `font_face_sniffed_source`, `select_interaction`, `inert_subtree`, `accessibility_states`, `checkable_change_event` and `text_range_no_change_event` — share from `tests/fixtures/mod.rs` (`mod fixtures;`, `#![allow(dead_code)]`: the fixture boot `boot(app, incremental)` with the stand's options `stand::options(incremental)`, `hold(label, app, incremental)` over it, the pages more than one check reads — `password_labelled`, `password_named`, `covered` and `many_items` with its `ITEMS` (read by `stand_snapshot_parts` and `stand_act_spans`) — and the held network stand-in `HeldNet`); none is a test target. Every other file is its own target: `tests/all.rs` is upstream's single-binary target, kept in the manifest at `test = false` and never built — add no `autotests = false` and no second `[[test]]` table (`BlitzTestsTargetsTest`, in the `ci-scripts` leg, pins it). A check that needs a session process starts and stops its own host (its test binary re-run on one `#[ignore]` child, or the package's binary through `CARGO_BIN_EXE_*`), bounds every wait, guards the host with kill-and-reap and, holding a session over the socket, is `cfg(unix)`-gated — a check that drives the `escher-session mcp` stdio child (`mcp_server`, `mcp_log`) does it through the shared `Speaker` (piped stdin, stdout read line by line on a thread under a 30 s bound, kill-and-reap in its `Drop`) and is not unix-gated but `mcp_server`'s two command-line comparisons; since 2026-10-19-session-recording a check that records is `cfg(unix)`-gated item by item, in-process and `mcp` stdio ones included (`mcp_log`'s recorded test), beside an off-unix check that a recording is refused `Unsupported`, which the windows job alone runs; a host ends by itself after its idle expiry, so a check that waits for one watches the state directory — an `attach` or a `status` is an answered request and starts the count again. The seven_guis checks also run the `escher-session` binary once per command as a client and read its stdout, stderr and exit status (`0` · `1` · `2` · `3`) through `tests/common/mod.rs`, which since 2026-10-19-test-splits also states the log checks' fragment once — `Needles` and `stand_needles` (the CRUD stand's id and name needles), `stamped_lines`, `found`, `occurrences`, the unix-only `recorded_needles` and `cells_needles(part)` (part `part`'s author keys of the in-process Cells screen and the middle column-A cell it holds) — called by `host_log` and `mcp_log` alone; the two flows under `tests/flows/` are POSIX `sh` scripts run by the Rust target `cli_flow` and, since 2026-10-19-recorded-check-replay, a third, `record_checks.sh`, by seven_guis `recording`'s unix-gated `the_committed_checks_are_what_the_binary_records` — assets of a `cargo test` target, not a runner of their own.
- **Headless E2E:** `blitz_test_harness::Harness` over `HtmlDocument` / `DioxusDocument`; WPT via `cargo run -rp wpt css svg` (needs `WPT_DIR`).
- **CI scripts:** `python3 -m unittest discover -s .github/scripts` (the `ci-scripts` leg; PyYAML for the workflow tests), one `TestCase` per function.
- No mocking library, property-test or snapshot crate is used (blitz-tests carries the assertion crate test-that 0.6.0 with test-that-macro 0.6.0 as dev-dependencies, 0.5.2 until 2026-10-17-upstream-sync-engine-debts, whose `verify_that!` and `TestResult<()>` upstream's merged `accessibility_label` and `accessibility_description` checks assert through under the same `#[test]` harness) — stand-ins are hand-written fakes (`RecordingNetProvider` and `ManualNetProvider`, upstream's; escher's one held network stand-in `fixtures::HeldNet`; since 2026-10-20-load-wait `stand_load_wait`'s in-file self-answering `LateNet`, whose `fetch` answers each request from its own thread after a 200 ms sleep; the stand's own `LoadNet`, private to `examples/seven_guis/src/stand.rs`, which `stand::boot_load` puts in its options' `net_provider` and which answers the fixed `http://stand.test/load.css` from a thread of its own after `LOAD_ANSWER_DELAY` (200 ms), `is_noop` not overridden; `RecordingShell`, blitz-shell's test-local `CountedWakes`, `NoopEventHandler`, probe widgets). A check decodes a PNG through blitz-tests' `png` dev-dependency, or, in seven_guis, which has none, by a hand base64 reader and the PNG header.

## File and naming conventions
- Each integration file opens with a `//!` doc naming the behaviour and any guarded bug; regression tests cite the upstream issue/PR URL and the real page that exposed it. `docs/capabilities.md` ends on `## Where each claim is proven`, naming the check behind each claim it makes — the stand checks among them — and only its names and counts are pinned, so a check renamed or moved changes that section by hand.
- Descriptive snake_case test names; `#[track_caller]` on assertion helpers.
- Assert first that the fixture produces the condition under test, then the behaviour.

## Determinism
- Build documents with `HtmlDocument::from_html` + a `DocumentConfig` carrying a fixed viewport (800×600 or 400×300, scale 1.0, `ColorScheme::Light`) and `HtmlProvider`, then `resolve(0.0)`.
- Run pipeline scenarios in both layout modes: `for incremental in [false, true]` (upstream's `pseudo_element_flow_classification` among them, `incremental_oracle` the layout-identity witness).
- Drive pure-restyle paths through `:hover`, not attribute mutation — a mutation inserts full damage and masks under-damaging bugs.
- Randomized stress uses a seeded LCG, never an unseeded RNG.
- The pre-existing font-dependent tests skip with `eprintln!` when no usable font exists (`system-fonts` is on when testing the workspace); this skip is a known gap, not a pattern to copy. Stand checks boot through `seven_guis::stand::boot(task, stand::options(incremental))` — the served pages through `stand::boot_cells` and `stand::boot_load` — pinned 800×600 · scale 1 · Light, the bundled DejaVu Sans with system fonts off, offline but for the load page, whose `net_provider` is the stand's `LoadNet`, every other field kept — and assert unconditionally: no font skip, no sleep (drive the timer through its `TimerTicks` handle; two recorded exceptions whose subject is wall time: `stand_virtual_clock`'s 800 ms sleep, taken so a shot after a scroll is read to repeat across wall time until `advance` moves the fade, and, since 2026-10-20-load-wait, `stand_load_wait`, which reads `Instant::now()` around its call to measure the load wait against `LOAD_WAIT` and whose in-file `LateNet` answers from its own thread after a 200 ms sleep; the 200 ms sleep of the stand's own `LoadNet` is the stand's, not a check's, `stand_load_page` waiting it out through the driver's load wait with no sleep or clock read of its own), no `dispatch_recorded`.
- A harness check that needs a font or a layout mode sets `HarnessOptions.font_ctx` / `.incremental`. A harness-built document reads the harness's `VirtualClock`: move its time with `tick(dt)` or `advance_time(Duration)` (`screenshot`, `screenshot_rect`, `text_contrast` and `settle` never move it), while `wrap(doc)` gives the harness a fresh clock and the wrapped document keeps the one its own config gave it (ratified by the founder, 2026-10-18).

## Fixtures
- Inline HTML string constants or `format!`-built pages; a fixture page more than one check reads is stated once as an `rsx!` component in `tests/fixtures/mod.rs` (`password_labelled`, `password_named`, `covered`, `many_items` — `ITEMS`, 400 buttons whose screen passes `SNAPSHOT_TEXT_BUDGET`) and booted through `fixtures::boot`, while a page with one reader, or whose ids differ, stays in its check's file; image loads injected as `ImageData` with `Status::Ok`; blitz-vibey-script's two `file:`-load tests write their sibling files at test time under `std::env::temp_dir()` (`temp_dir_with_files`), test data on disk beside the in-code seeds; test URLs use the `.test` TLD or `example.com`.
- Blitz-dom unit tests build DOM by hand through `DocumentMutator` — blitz-html would be a circular dev-dependency.
- Two recorded Counter sessions are committed as test data under `tests/blitz-tests/checks/` (`counter-cli.json`, `counter-mcp.json`, no target): `stand_replay` replays them through `Check::replay`, and seven_guis `recording` compares them byte for byte with what `record_checks.sh` records through the binary — re-record them with that script, never edit them by hand, and keep the scripts free of a `screenshot` step (a shot's PNG bytes differ by OS).

## Running tests
- **One file:** `cargo test -p blitz-tests --test {name}`
- **One crate:** `cargo test -p {crate}`
- **Agent-driven (stand checks · blitz-tests):** `bash scripts/agent-run.sh boot`, then `run stand` · `run all` · `run {name}` — JSON-line results, exit `0`/`1`/`2`/`3` (test-plan §3; `.claude/rules/verification-harness.md`)
- **Cold-agent pipe (one live model session — operator host only, never in CI):** `bash scripts/cold-agent.sh run stand` (after `cargo build --locked -p seven_guis --bin escher-session` — the pipe builds nothing; `run counter` a usage error) → `target/cold-agent/verdict.json`; its contract tests run in the `ci-scripts` leg under a `claude` shim and a fake `target/debug/escher-session` (`.github/scripts/test_cold_agent.py`)
- **Whole workspace (CI leg):** `cargo test --workspace --locked` — or `bash .github/scripts/ci-leg.sh test`, exactly as CI runs it
- **Before a push:** `bash .github/scripts/ci-leg.sh fast` (fmt → clippy → test → CI scripts)
- **Benchmarks (ignored):** `cargo test -p blitz-tests --release --test paint_tree_bench -- --ignored --nocapture`

## Not yet measured
- A performance budget (§10) is not set. Since 2026-10-14-quality-gates the `coverage` leg (`bash .github/scripts/ci-leg.sh coverage`, cargo-llvm-cov) ends with per-crate line floors — escher-driver 97 %, dioxus-native-dom 83 %, blitz-test-harness 90 %, by `.github/scripts/coverage_floor.py` (a `*_tests.rs` `#[path]` test-child file is no record of the per-crate reading, so a test module moved out of line moves its crate's reading with no line of code changed: since 2026-10-19-test-splits escher-driver read 4266/4350 = 98.07 %, since 2026-10-19-visual-lint, which added lint.rs, 4634/4732 = 97.93 %, since 2026-10-20-load-wait 4695/4794 = 97.93 %, and read now under the same floors it reads 4950/5049 = 98.04 % (dioxus-native-dom 2786/3235 = 86.12 %, blitz-test-harness 956/1008 = 94.84 %), the 97 % floor holding, 3 of 3 crates still at or above their floors) — and the stand checks hold a zero-failure flakiness budget (`ci-leg.sh stand-repeat`: the `stand_*.rs` files, the fifteen named blitz-tests targets of its `--test` list and seven_guis' eight process checks, three rounds, no retry). Since 2026-10-16-fast-failing-mutants a mutation run (dev host only, never in CI — cargo-mutants 27.1.0 and cargo-nextest 0.9.146 are host tools) is cargo-mutants `--test-tool nextest --baseline=skip` under the root `.config/nextest.toml`'s `mutants` profile (`NEXTEST_PROFILE=mutants`: fail-fast at one failure, terminated immediately, the default profile untouched), each unit's test command (`NEXTEST_PROFILE=mutants cargo nextest run --locked`, a `-p` per package, then `--lib` and its `--test=` targets) first read green on the unmutated tree — never under plain `cargo test`, which runs the hung blitz-tests integration binaries before the library tests and reads their mutants `timeout`. The Epoch 5 code audit's cognitive-complexity ceiling of 15 is read on the dev host alone (rust-code-analysis-cli 0.0.25, a host tool; no CI leg runs it and it is no ceiling on every function), test functions counted — a closure or a nested `fn` keeps its branches counted in its enclosing function, so only splitting a function into module-level sibling items lowers its reading.

## Session Additions
_This section is owned by `/andromeda-wrap-session`. setup-project preserves content added here on re-run._
- 2026-10-06: In a `.github/scripts` unittest file, never give a helper method a `test_` prefix — `unittest` collects it as a test case; name helpers without it and check the run's `Ran N tests` against the cases written.
- 2026-10-06: Never drive a stand or harness check with a deleting or other platform-bound key through the harness's `press` — the editor's `Key::Backspace` arm is compiled out on macOS (the delete arrives there as an Apple standard key binding, which `press` does not send; `Harness::apple_keybinding` does, and the driver's `press backspace` adds it on macOS), so a bare press does nothing on the macOS CI leg while the Linux host reads green; prove a state change with clicks and typed characters — the one deleting-key check is `stand_act_keys`, through the driver — and read the `#[cfg]` lines above a `match` arm before trusting a grep hit of it on every platform. [corrected 2026-10-07: the harness synthesizes the binding since `apple_keybinding`, and the driver's backspace deletes on the macOS CI leg]
- 2026-10-07: In a hand-built blitz-dom unit test create elements with `qual_name!("div", html)` — the one-argument `qual_name!("div")` gives an element in no namespace, which the default stylesheet's type selectors do not match, so `body` and `div` lay out inline and a fixture that needs block layout (an anonymous block, a box with a height) builds none without failing; assert the layout condition the test rests on before the behaviour.
- 2026-10-09: In a hand mutation control, save the file's bytes before the mutation, restore by writing them back and compare sha256 — a restore made by a second edit can miss without an error — and run the restore check before taking the green reading, never after.
- 2026-10-09: Count the result lines of a red `cargo test` run only under `--no-fail-fast` — by default cargo stops at the first failing target, so a red run prints fewer result lines than a green one and the two counts are not comparable.
- 2026-10-10: A script that attributes `cargo test` results to a test target runs cargo with stderr merged into stdout and parses the one stream — `Running tests/{name}.rs` is stderr and the `test … ok|FAILED` lines stdout, so two captured streams attribute nothing; print one mutation's per-target table before the full batch.
- 2026-10-10: Before calling a standing check unaffected by a change to data it could pin — a row of `escher_driver::VERBS`, what a verb does to a control — search `tests/` and `examples/*/tests/` for the table's name and for the call builders (`type_into`, `click`, `press`): a check that reads the table back or pins the old behaviour is on no plan's files-to-modify list and turns red at the first full gate pass. Extended 2026-10-18: search the owning crate's own `src/` too — an inline `#[cfg(test)]` module beside the table (a JSON writer's or a self-description's) can pin its length. Extended 2026-10-25: a change to the stand's control set also reaches pins that name no id — a control count (`checked.len()`), a per-task lint finding count and `stand_requirement_sweep`'s `include_str!` source table — so search for what they count, not only for the ids.
- 2026-10-15: In a contract test whose expected total follows from a table the test itself holds (expectations per app, steps per case), assert the table's computed sum, never a hand-typed literal beside it — a literal drifts from its own table and reads red against a correct implementation.
- 2026-10-19: Code compiled only off unix is unverified on this linux host until a non-unix build reads it — after adding or moving a `#[cfg(unix)]` gate (a file-wide `#![cfg(unix)]` split into per-item gates included), run `cargo check --tests --locked --target x86_64-pc-windows-gnu -p {crate}` before pushing: a helper left calling a gated item compiles here and breaks only the windows job, and `cfg_attr(…, allow(dead_code))` cannot excuse a call to an item configured out.
