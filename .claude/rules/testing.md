# Testing Rules

Path-scoped rules for test files. Source: `.andromeda/test-plan.md` §2 §4 §5 §7 §8 (test tier 0) and arch §Conventions.

## Framework
- **Unit:** Rust built-in harness — `#[cfg(test)] mod tests` at the end of the source file (some modules sit out of line in a sibling file with the `_tests` suffix, each declared `#[cfg(test)]` with `#[path]` at its parent, fixture builders allowed in a child module of that test module — `recording::off_unix_tests` `#[cfg(all(test, not(unix)))]`, `recording::tests` `#[cfg(all(test, unix))]` —: dioxus-native-dom's `bridge_tests`, a child of `dioxus_document`, so it reaches that module's private fields, and, moved out whole with their test paths unchanged, since 2026-10-16-file-splits blitz-dom's `document::changed_set_tests` and `document::font_reading_tests` and escher-driver's `mcp::tests` and `schema::tests`, and since 2026-10-19-test-splits escher-driver's `cli::tests` in `cli_tests.rs`, `recording::off_unix_tests` in `recording_off_unix_tests.rs` and `recording::tests` in `recording_tests.rs`); `#[tokio::test]` for async workers.
- **Integration:** `tests/blitz-tests/tests/*.rs`, one file per behaviour, depending only on dev-dependencies; the stand checks read the tables and helpers they share from `tests/common/mod.rs` (`mod common;`; a helper whose body or failure message differs from the shared one stays in its check) and the checks that hold a session — the session checks, `stand_settle`, the sixteen driver-action checks `stand_act_*`, `stand_mcp_tools`, `stand_screenshot_repeat`, `stand_requirement_sweep`, `stand_virtual_clock`, since 2026-10-19-session-recording `stand_session_recording` and, since 2026-10-19-recorded-check-replay, `stand_replay` and, since 2026-10-19-visual-lint, `stand_lint` and, since 2026-10-20-load-wait, `stand_load_wait` and, since 2026-10-20-large-screen-in-parts, `stand_snapshot_parts` and the two served-page checks `stand_cells_served` and `stand_load_page` (`stand_act_popup`, `stand_graph`, `stand_actions`, `stand_handler_coverage` and `stand_seeded_randomness` among them; `stand_mcp_masked`, `password_painted_masked`, `stand_non_lean_tasks` and `password_caret_click` declare none) — what they share from `tests/session_common/mod.rs` (`mod session_common;`: the held session, the driver's call builders `click` · `type_into` · `press` · `advance` · `scroll` · `snapshot` · `screenshot` · `screenshot_of` · `lint` · `graph` · `snapshot_part`, the outcome reader `act`, the part reader `part` (a paged snapshot's text, part and count), the shot reader `shot`, the lint reader `linted` (a lint's findings), the graph reader `graphed` (a graph's `UiGraph`), the refusal readers `refused` and `refused_unchanged`, since 2026-10-19-session-recording the recording readers `kept` and the unix-only `mode`, and since 2026-10-19-recorded-check-replay `shot_prefix` (the first 64 base64 characters of a whole-screen shot) — its `replay` removed then for the replay `Check::replay`); and, since 2026-10-19-shared-fixtures, what the checks declaring `mod fixtures;` — `stand_*` files (`stand_snapshot_parts` since 2026-10-20-large-screen-in-parts, `stand_act_select`, `stand_load_wait` since 2026-10-20-load-wait, `stand_lint` since 2026-10-19-visual-lint, `stand_act_popup`, `stand_actions`), `font_face_sniffed_source`, `select_interaction`, `select_popup`, `select_popup_painted`, `inert_subtree`, `accessibility_states`, `checkable_change_event` and `text_range_no_change_event` — share from `tests/fixtures/mod.rs` (`mod fixtures;`, `#![allow(dead_code)]`: the fixture boot `boot(app, incremental)` with the stand's options `stand::options(incremental)`, `hold(label, app, incremental)` over it, the pages more than one check reads — `password_labelled`, `password_named`, `covered` and `many_items` with its `ITEMS` (read by `stand_snapshot_parts` and `stand_act_spans`) — and the held network stand-in `HeldNet`); none is a test target. Every other file is its own target: `tests/all.rs` is upstream's single-binary target, kept in the manifest at `test = false` and never built — add no `autotests = false` and no second `[[test]]` table (`BlitzTestsTargetsTest`, in the `ci-scripts` leg, pins it). A check that needs a session process starts and stops its own host (its test binary re-run on one `#[ignore]` child, or the package's binary through `CARGO_BIN_EXE_*`), bounds every wait, guards the host with kill-and-reap, sends the child's streams to null unless it reads them (so the child's libtest lines never reach agent-run's count) and, holding a session over the socket, is `cfg(unix)`-gated — a check that drives the `escher-session mcp` stdio child (`mcp_server`, `mcp_log`) does it through the shared `Speaker` (piped stdin, stdout read line by line on a thread under a 30 s bound, kill-and-reap in its `Drop`) and is not unix-gated but `mcp_server`'s two command-line comparisons, and a check comparing an MCP tool result against the in-process answer decodes the result's JSON string whole through the one shared session-check helper (un-escaping quotes alone leaves a Windows path's backslashes doubled); since 2026-10-19-session-recording a check that records is `cfg(unix)`-gated item by item, in-process and `mcp` stdio ones included (`mcp_log`'s recorded test), beside an off-unix check that a recording is refused `Unsupported`, which the windows job alone runs; a host ends by itself after its idle expiry, so a check that waits for one watches the state directory — an `attach` or a `status` is an answered request and starts the count again. The seven_guis checks also run the `escher-session` binary once per command as a client and read its stdout, stderr and exit status (`0` · `1` · `2` · `3`) through `tests/common/mod.rs` (a check capturing a host that installs escher's sink drains its pipes on threads from the spawn on, or captures to a file, and never waits for exit before reading), which since 2026-10-19-test-splits also states the log checks' fragment once — `Needles` and `stand_needles` (the CRUD stand's id and name needles), `stamped_lines`, `found`, `occurrences`, the unix-only `recorded_needles` and `cells_needles(part)` (part `part`'s author keys of the in-process Cells screen and the middle column-A cell it holds) — called by `host_log` and `mcp_log` alone, `option_needles()` (the needle list of a select's options read from a snapshot), called by the same two, and `graph_needles()` (the component and state names of the UI graph as needles), called by the same two, and `actions_needles()` (the CRUD screen's listed author-key ids holding a `-` as needles), called by the same two, and `coverage_needles()` (the CRUD screen's UI-graph ids and names as needles), called by `host_log` alone; the two flows under `tests/flows/` are POSIX `sh` scripts run by the Rust target `cli_flow` and, since 2026-10-19-recorded-check-replay, a third, `record_checks.sh`, by seven_guis `recording`'s unix-gated `the_committed_checks_are_what_the_binary_records` — assets of a `cargo test` target, not a runner of their own.
- **Headless E2E:** `blitz_test_harness::Harness` over `HtmlDocument` / `DioxusDocument` (a test task that waits for a later render on the Dioxus bridge leaves its waker for the producer to wake and never wakes its own waker while it waits — doing so livelocks inside the buffered render); WPT via `cargo run -rp wpt css svg` (needs `WPT_DIR`).
- **CI scripts:** `python3 -m unittest discover -s .github/scripts` (the `ci-scripts` leg; PyYAML for the workflow tests), one `TestCase` per function.
- No mocking library, property-test or snapshot crate is used (blitz-tests carries the assertion crate test-that 0.6.0 with test-that-macro 0.6.0 as dev-dependencies, 0.5.2 until 2026-10-17-upstream-sync-engine-debts, whose `verify_that!` and `TestResult<()>` upstream's merged checks that use them assert through under the same `#[test]` harness) — stand-ins are hand-written fakes (`RecordingNetProvider` and `ManualNetProvider`, upstream's; escher's one held network stand-in `fixtures::HeldNet`; since 2026-10-20-load-wait `stand_load_wait`'s in-file self-answering `LateNet`, whose `fetch` answers each request from its own thread after a 200 ms sleep; the stand's own `LoadNet`, private to `examples/seven_guis/src/stand.rs`, which `stand::boot_load` puts in its options' `net_provider` and which answers the fixed `http://stand.test/load.css` from a thread of its own after `LOAD_ANSWER_DELAY` (200 ms), `is_noop` not overridden; the error-text check's failing page's `FailingNet`, which fails its fetch; a blitz-tests check's hand-written stand-in that reads `file:` loads through blitz-net's real provider, blocking on a current-thread tokio runtime it owns, with blitz-net and tokio taken as blitz-tests dev-dependencies for it (`a_remote_page_reads_no_local_file_and_a_file_page_reads_them_all`); `RecordingShell`, `select_popup`'s own `CountingShell`, blitz-shell's test-local `CountedWakes`, `NoopEventHandler`, probe widgets). A check decodes or encodes a PNG through blitz-tests' `png` dev-dependency, or, in seven_guis, which has none, by a hand base64 reader and the PNG header.

## File and naming conventions
- Each integration file opens with a `//!` doc naming the behaviour and any guarded bug; regression tests cite the upstream issue/PR URL and the real page that exposed it. `docs/capabilities.md` ends on `## Where each claim is proven`, naming the check behind each claim it makes — the stand checks among them — and stating each limit as pinned by its check or as asserted by no check; and only its names and counts are pinned, the names and schema counts, and the README's count of MCP tools, to the driver schema's tables and the a11y leg's file count and `stand-repeat`'s named-target count to the CI leg script, so a check renamed or moved changes that section by hand.
- Descriptive snake_case test names; `#[track_caller]` on assertion helpers. A test rename sweeps the old name held as a string literal (a requirement's witness among them), and a change of the driver's verb count or of a CI leg's file count sweeps the tests, examples and CI-script tests for pins of that count held as a literal; a test name holding a count word that another check pins as a witness string is kept by a count sweep, the name searched before any rename.
- Assert first that the fixture produces the condition under test, then the behaviour; a focus test pins the node focus lands on, never only that a hidden control is not focused (the post-layout focus fixup makes that hold with or without the change under test); a new check is controlled — a named mutation of what it guards turns it red, a case it leaves green widened until it does, and the restored tree reads green; a check never derives its expected value from the constant its mutation control changes, but pins the measured value as a literal (a pixel-row pin that font-embolden moves is pinned as a stated band with its reason in a comment where the test crate cannot see the feature, its wholly-inside assertions kept exact); a control that removes a bound loosens it to twice the budget rather than removing it, so the mutated run stays bounded; a control of a read that must change nothing gives the read pending work that a pass would apply, so a read that ran a pass would be seen (a pump on a settled screen is invisible); a control whose case lies in the later of two test targets named by one gate entry with no fail-fast override needs an edit that leaves the earlier target green (Cargo runs the targets in name order and stops at the first red one, so the named case would go unrun).

## Determinism
- Build documents with `HtmlDocument::from_html` + a `DocumentConfig` carrying a fixed viewport (800×600 or 400×300, scale 1.0, `ColorScheme::Light`) and `HtmlProvider`, then `resolve(0.0)`.
- Run pipeline scenarios in both layout modes: `for incremental in [false, true]` (upstream's `pseudo_element_flow_classification` among them, `incremental_oracle` the layout-identity witness); upstream integration targets taken in a sync are kept as written, and those that run one layout mode stand as named exceptions.
- Drive pure-restyle paths through `:hover`, not attribute mutation — a mutation inserts full damage and masks under-damaging bugs.
- Randomized stress uses a seeded LCG, never an unseeded RNG.
- The pre-existing font-dependent tests skip with `eprintln!` when no usable font exists (`system-fonts` is on when testing the workspace); this skip is a known gap, not a pattern to copy. Stand checks boot through `seven_guis::stand::boot(task, stand::options(incremental))` — the served pages through `stand::boot_cells`, `stand::boot_load` and `stand::boot_order`, and Circle Drawer, in process only and served by no escher-session role, through `stand::boot_circle_drawer` — pinned 800×600 · scale 1 · Light, the bundled DejaVu Sans with system fonts off, offline but for the load page, whose `net_provider` is the stand's `LoadNet`, and the error-text check's failing page, whose `FailingNet` stand-in fails its fetch, every other field kept — and assert unconditionally but engine-sourced caused items, asserted only on a build with the engine's tracing compiled in, read through the engine's own constant, the check running on both builds: no font skip, no sleep (drive the timer through its `TimerTicks` handle; four recorded exceptions whose subject is wall time (`stand_session_lifecycle`'s wait on the host's idle expiry and `stand_contrast`'s bound on a load's answer beside the two below): `stand_virtual_clock`'s 800 ms sleep, taken so a shot after a scroll is read to repeat across wall time until `advance` moves the fade, and, since 2026-10-20-load-wait, `stand_load_wait`, which reads `Instant::now()` around its call to measure the load wait against `LOAD_WAIT` and whose in-file `LateNet` answers from its own thread after a 200 ms sleep; the 200 ms sleep of the stand's own `LoadNet` is the stand's, not a check's, `stand_load_page` waiting it out through the driver's load wait with no sleep or clock read of its own), no `dispatch_recorded`.
- A harness check that needs a font or a layout mode sets `HarnessOptions.font_ctx` / `.incremental`. A harness-built document reads the harness's `VirtualClock`: move its time with `tick(dt)` or `advance_time(Duration)` (`screenshot`, `screenshot_rect`, `text_contrast` and `settle` never move it), while `wrap(doc)` gives the harness a fresh clock and the wrapped document keeps the one its own config gave it (ratified by the founder, 2026-10-18).

## Fixtures
- Inline HTML string constants or `format!`-built pages; a fixture page more than one check reads is stated once as an `rsx!` component in `tests/fixtures/mod.rs` (`password_labelled`, `password_named`, `covered`, `many_items` — `ITEMS`, 400 buttons whose screen passes `SNAPSHOT_TEXT_BUDGET`) and booted through `fixtures::boot`, while a page with one reader, or whose ids differ, stays in its check's file; image loads injected as `ImageData` with `Status::Ok`; blitz-vibey-script's two `file:`-load tests write their sibling files at test time under `std::env::temp_dir()` (`temp_dir_with_files`), test data on disk beside the in-code seeds; test URLs use the `.test` TLD or `example.com`, while blitz-net's `delivers_network_and_bad_url_errors` and `http_error_body_is_not_delivered_as_css` each bind a `std::net::TcpListener` on `127.0.0.1:0`, test-only TCP on loopback, served by no binary and reached by no caller, beside the module's test-local `Handler`.
- Blitz-dom unit tests build DOM by hand through `DocumentMutator` — blitz-html would be a circular dev-dependency. A Dioxus fixture select whose choice a check moves is written as a controlled select (a fixture's `selected` literal is re-written on any re-render of its component, re-seeding the choice).
- Two recorded Counter sessions are committed as test data under `tests/blitz-tests/checks/` (`counter-cli.json`, `counter-mcp.json`, no target): `stand_replay` replays them through `Check::replay`, and seven_guis `recording` compares them byte for byte with what `record_checks.sh` records through the binary — re-record them with that script, never edit them by hand, and keep the scripts free of a `screenshot` step (a shot holding document text differs in its PNG bytes by OS). The seven served tasks are read on every CI OS by one stand check, `stand_cross_os_readings`, which compares the driver's answer digests for snapshot (every part), lint and actions, at boot and after one acting step in both layout modes, to one committed table, with no shot and no kept check file; a shot of a canvas alone is the one shot compared across OSes, by `stand_canvas_cross_os`: three canvas-alone fixtures (a solid fill, an antialiased edge, canvas glyphs), each shot whole and as its element, and Circle Drawer's canvas shot as its element, in both layout modes, their answer digests held byte-equal on linux x86_64, windows x86_64 and macOS aarch64 to committed tables, no pixels committed, and Circle Drawer's canvas draw commands are read in process by `stand_canvas_commands`, in both layout modes, at boot, after a click and at 12 and 100 circles, as summary, full dump and parts, into one committed table, each answer held equal by size and digest on the same three hosts, while a shot holding document text stays out of every cross-OS byte check; text an app paints on a canvas such a comparison holds (Circle Drawer's diameter label) is drawn with its glyph origins on whole device pixels.

## Running tests
- **One file:** `cargo test -p blitz-tests --test {name}`
- **One crate:** `cargo test -p {crate}`
- **Agent-driven (stand checks · blitz-tests):** `bash scripts/agent-run.sh boot`, then `run stand` · `run all` · `run {name}`, or `run session` (`cargo test -p seven_guis --locked --test cli_flow`, the session binary's flows) — JSON-line results, exit `0`/`1`/`2`/`3` (test-plan §3; `.claude/rules/verification-harness.md`)
- **Cold-agent pipe (one live model session — operator host only, never in CI):** `bash scripts/cold-agent.sh run stand` (after `cargo build --locked -p seven_guis --bin escher-session` — the pipe builds nothing; `run counter` a usage error) → `target/cold-agent/verdict.json`; its contract tests run in the `ci-scripts` leg under a `claude` shim and a fake `target/debug/escher-session` (`.github/scripts/test_cold_agent.py`)
- **Whole workspace (CI leg):** `cargo test --workspace --locked` — or `bash .github/scripts/ci-leg.sh test`, exactly as CI runs it
- **Before a push:** `bash .github/scripts/ci-leg.sh fast` (fmt → clippy → test → CI scripts → embolden, stopping at the first red; on a dev host with CI unset a green fast leg ends with the target sweep, whose refusal or failure never reddens the leg, and a red leg calls none; it runs no rustdoc, so a chunk that edits a public doc comment lists the doc leg in its local gate block too); a paint change under the OS-gated `blitz-paint/font-embolden` has its local witness in `embolden`, `cargo test -p blitz-tests --locked --no-fail-fast --features blitz-paint/font-embolden --test select_popup_painted`, a leg with no CI job of its own, macOS exercising the feature there
- **Benchmarks (ignored):** `cargo test -p blitz-tests --release --test paint_tree_bench -- --ignored --nocapture`
