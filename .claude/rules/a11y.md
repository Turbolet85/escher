# Accessibility Rules

Path-scoped rules for the accessibility tree, keyboard/focus handling, painted colours and the stand.
Source: `.andromeda/a11y-plan.md` — tier 0, target SC 2.1.1 (keyboard) · 1.4.3 (contrast) · 2.4.3 (focus order).

## Accessibility tree
- `build_accessibility_tree` returns an AccessKit `TreeUpdate`; the root is a `Window` node with id `u64::MAX`, the focused DOM node is tree focus, AccessKit ids are `NodeId::as_u64()`.
- Role = `role` attribute, else HTML-AAM element mapping, else `Role::Unknown`; only `<html>` and `<body>` should map to `Unknown` on a semantic page. Known gap: strong native semantics can be overridden by `role` (contrary to WAI-ARIA 1.2).
- `hidden`, `display: none`, `visibility: hidden` exclude a node and its children; `aria-hidden="true"` keeps it, marked hidden.
- State = three ARIA attributes read by value on every element, whatever its role (trimmed, lower-case, exact): `aria-selected` `true`/`false` → `selected`; `aria-pressed` `true`/`false`/`mixed` → `toggled`; `aria-invalid` `true`/`grammar`/`spelling` → `invalid`, absent, empty or `false` → nothing, any other value → `Invalid::True`. `aria-checked` is not read — do not fold it into `checked` or `pressed`. A Dioxus `bool` attribute arrives as the text `"false"`, so state the literal texts `"true"` and `"false"`: a presence read would read every control pressed. The snapshot takes the three from the tree node, never from the element; since 2026-10-12-self-description the driver's served node-key help (`help`) states the boolean model's two limits (a mixed toggle reads `pressed` false, a grammar or spelling error reads `invalid` true). Ratified by the founder (2026-10-10); what an assistive technology reads of them is unmeasured (windowed witness owed).
- Text nodes become `TextRun` nodes and label their parent; an `aria-label` non-empty after trimming sets `label`; a `<label>` is pushed onto its bound `<input>`'s `labelled_by` (`for`-target, else first nested input) after the whole tree is built.
- `Document::accessibility_tree` (gated `accessibility`) is what the shell builds — on InitialTreeRequested and, on a poll that reported work, when the document's changed set taken by that poll was non-empty (ratified by the founder, 2026-10-07, its windowed witness still owed; before 2026-10-07 the poll-time refresh never ran); a `DioxusDocument` overrides it to set each element node's `author_id` to its stable element id — none on `TextRun`, document-root or `Window` nodes. The workspace pins the Dioxus crates `default-features = false`: the override — and the snapshot model built on it (`DioxusDocument::snapshot`, which takes role, name and focus from this tree, never a second mapping; its text form `Snapshot::to_text` and its diff `Snapshot::diff` read that model and map nothing again) — exists only where a crate names `dioxus-native-dom/accessibility` or depends on one that does (blitz-tests and escher-driver name it; seven_guis names none and gets it through escher-driver, so both its binaries compile these modules — with no platform adapter, so the stand binary still gives no assistive technology a tree).
- Every element an agent can act on — focusable, or an interactive role, or a listener — reads an author key (an HTML `id`); under the same feature `DioxusDocument::unkeyed_actionable()` returns the ones that read a positional path, each with its `remedy()`. `stand_actionable_keys` asserts it empty on the four lean tasks and Home, so a new control there needs an `id` — never a `tabindex`, role or focusability change made to satisfy the check.

## Keyboard and focus (SC 2.1.1 · 2.4.3)
- Focusable = holds a sub-document, or `disabled` does not parse as `true` and `tabindex >= 0`, or (no tabindex) `<a>/<area href>`, `button`, `input`, `select`, `textarea`, `frame`, `iframe`, `summary`. Cached focusability is recomputed on `tabindex`/`href`/`disabled` changes — keep that hook when adding focus-affecting attributes.
- `disabled` is keyed two ways: the `DISABLED` state (`:disabled`) and click targeting on PRESENCE, focusability on the PARSED bool — `disabled="false"` reads disabled to a presence check yet stays focusable. dioxus-native-dom removes a falsy value of its 28 boolean attributes — upstream's private `is_bool_attr` predicate, a closed set, since 2026-10-13-upstream-sync-polish-and-ship (`disabled`, `checked`, `hidden`, `readonly`, `required`, `multiple`, `selected`, `open`, `autofocus`, `inert` among them; a framework-written `inert: false` is removed, so it no longer makes content inert), so a `hidden: false` element stays displayed and in the tree; an attribute outside that list holding `false` is still written as `"false"`. The snapshot's `enabled` follows the presence reading.
- Tab/Shift+Tab move through `focus_next_node` / `focus_prev_node`; removing the focused node resets focus to body and runs blur side effects.
- `:focus-visible` and `:focus-within` never match — a stand style that relies on them shows no focus ring.
- A Tab / Shift+Tab key-press focus check exists on the stand (`stand_snapshot_state`, through the harness's `press` / `press_with`; `stand_accessibility_ids` pins the lean tasks' `focus_next_node` sequence); the headless keyboard harness is owned by the working route's "Stand keyboard harness" chunk.

## Contrast (SC 1.4.3)
- `blitz-paint` carries a Chrome-matching WCAG contrast-ratio helper (`color.rs`); since 2026-10-13-stand-contrast-harness `Harness::text_contrast` in blitz-test-harness (read-only) reads a control's text/background pair as a `TextContrast` (`contrast_ratio`, the WCAG 2.x ratio; `required_ratio` 3.0 for large text, else 4.5), and `stand_contrast` asserts the 18 stand control rows in both layout modes — SC 1.4.3 is not met on the five accent buttons (`#ffffff` on `#4a6cf7`, 4.39 against 4.5); the check records and gates nothing and runs in the workspace `test` leg, not the `a11y` leg; the re-colouring, the unmeasured colour-changing states, the CRUD list rows and the text outside the controls are owned by "Stand a11y assertions".

## Tests
- Assert over `build_accessibility_tree()` after `resolve`, matching `role()` / `is_hidden()` (`accessibility_hidden.rs`, `accessibility_roles.rs` patterns); for a Dioxus document's ids read `doc.accessibility_tree()` and `author_id()` (`stand_accessibility_ids.rs`).
- The a11y CI leg runs the existing accessibility tests (`bash .github/scripts/ci-leg.sh a11y` — `accessibility_hidden`, `accessibility_roles`, `focusability_updates`); `accessibility_states` (the three state attributes, one stated table per attribute with its row count asserted) and `accessibility_names` ride the workspace test leg, not this one; SC assertions on stand controls gating merges are owned by "Stand a11y assertions".
