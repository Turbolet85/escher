# Verification Harness Rules

Path-scoped rules for the agent-driven verification harness. Source: `.andromeda/test-plan.md` §3.
Development Style is agent-driven — escher's own driver is meant to become the harness.

## The 5-command contract (measured — `scripts/agent-run.sh`)
- Run from the repository root: `bash scripts/agent-run.sh boot`, then `run stand` · `run all` · `run {blitz-tests file}`, `status`, `logs`, `cleanup`. `scripts/agent-run.ps1` only forwards to it (Windows; untested here — no `pwsh`). The scripts are project-authored: setup preserves them, never re-renders them.
- Exit grammar, every verb: `0` success · `1` the verb ran and failed — a build failure, a failing run, or an EMPTY run (cargo 0 with no test line parsed is never a pass) · `2` usage, checked before · `3` a precondition is unmet (not booted; `logs` with nothing to read).
- `{name}` must match `^[a-z0-9_]+$` and name an existing `tests/blitz-tests/tests/{name}.rs`; `run stand` with no `stand_*.rs` files is an empty run (exit 1, no cargo call); under `all`, `run.start.files` is `[]`.
- Stdout is JSON lines only — `boot`, `run.start`, one `test {file, test, outcome}` per libtest line, `run.end {passed, failed, ignored, cargo_exit, outcome}`, `status`, `cleanup` — encoded by python3's `json`, never by bash string building. No event carries captured test output or a panic message, and no field takes a scrub-set name (`url href src html text value attrs path request error`); raw cargo output stays in `target/agent-run/run.log`.
- State lives in `target/agent-run/{status.json, events.jsonl, run.log}` only — the script itself starts no daemon and has no PID file, socket, port or env var (adding one is an arch §Occupied Resources registration); the stand checks boot in process, bar `stand_session_lifecycle` and `stand_session_quiet`, which start and stop their own session host and its Unix-domain socket under `target/tmp/`. One driver at a time: a killed run leaves `running`, the next `run` overwrites it.
- libtest's `--format json` is nightly-only, so the parser reads the pretty lines (`Running …`, `Doc-tests …`, `test … ... ok|FAILED|ignored`); the contract tests are `.github/scripts/test_agent_run.py` (a `cargo` shim, run by the `ci-scripts` leg).
- Test-data bootstrap: nothing is seeded — the fixtures are code (`tests/blitz-tests/tests/fixtures/mod.rs` and the one-reader pages in their checks' own files), compiled into each target by `boot` (`cargo test --no-run`), so `boot` is the bootstrap; `run stand` runs the 20 `stand_*` readers of the shared module, `run font_face_sniffed_source` its one non-stand reader, and there is no `run fixtures` selection.

## The cold-agent run pipe (measured — `scripts/cold-agent.sh`)
- Run from the repository root: `bash scripts/cold-agent.sh run stand` (`run counter` a usage error), then `status` · `logs` · `cleanup`; `scripts/cold-agent.ps1` only forwards. Same exit grammar as agent-run (`0` · `1` a `failed` verdict · `2` usage, checked first · `3` precondition — `claude`/`python3` absent, `target/debug/escher-session` absent or not executable (the pipe builds nothing: `cargo build --locked -p seven_guis --bin escher-session` first), no verdict, no events).
- `run` starts ONE live model session (`claude -p`, the operator's own login; ratified by the founder, 2026-10-06) from a per-run `mktemp -d` dir whose path names nothing, holding only an `mcp.json` naming one stdio server `escher`, the driver's own `escher-session mcp` (the eleven verbs; its stderr at `RUST_LOG=info` in `server.log`, counted by `tool_call` span lines, never printed or copied), with a fixed prompt asking for the four lean apps one at a time and a JSON check as the reply's last fenced json block (`--model claude-opus-5-5 --max-budget-usd 3`) — never fire it in CI or in a loop; the contract tests (`.github/scripts/test_cold_agent.py`) use a `claude` shim and a fake `target/debug/escher-session`.
- The verdict (`target/cold-agent/verdict.json`) reads `passed` only on positive evidence — client exit 0, a successful `result`, `isolated` (exactly the eleven `mcp__escher__*` tools, one server `escher`), `counts_agree` (the server's `tool_call` span lines against the transcript's escher tool uses, its refused + error lines against the results marked `is_error`), ≥ 1 tool call, all four lean apps in `tasks_met` (read from a `snapshot` answer while the app is the latest accepted `start`'s, never the agent's reply), and the agent's check — at most 400 steps, never replayed when malformed — replayed green on a fresh `escher-session mcp` child (`check_passed`) and failing with its acting steps left out (`check_can_fail`); `wrong_calls` is recorded, never deciding. Events carry counts and identities only — no transcript text, tool argument, tool result, reply or check text.
- State lives in `target/cold-agent/{verdict.json, events.jsonl, transcript.jsonl, client.log, server.log, check.json}` only (`cleanup` touches nothing else; `server.log` counted by span name and `check.json` written as parsed, neither ever printed or copied); `transcript.jsonl` is raw (host paths included) — a copy committed as evidence is host-path-masked first (`gate.py hygiene` refuses an unmasked one).

## In-process `Harness` (measured — `packages/blitz-test-harness`)
- Constructors `from_html`, `from_html_with(html, HarnessOptions)`, `from_component`, `from_vdom` pump once; `wrap` does not.
- `pump` polls with no waker and resolves at harness time — a `VirtualClock` its documents read, advanced by `tick(dt)` (a negative or non-finite `dt` moving nothing) and by exactly the duration by `advance_time(Duration)`, each then pumping, and never moved by `screenshot`, `screenshot_rect`, `text_contrast` or `settle` (ratified by the founder, 2026-10-18); `dispatch` / `dispatch_recorded` do NOT pump. Input helpers (`click`, `type_text`, `press`, `tap`, `wheel_at`, `drag`, `apple_keybinding`, `scroll_into_view`, `ime`, …) pump after dispatch; the crate re-exports keyboard-types 0.8's `Key`, `Modifiers` and, since 2026-10-17-upstream-sync-engine-debts, `NamedKey` — the two types `press_with` takes and the named-key enum a 0.8 `Key::Named` holds.
- `settle` repeats that pass until no work is due and returns `Settled { passes, animating }`, or `NotSettled { busy }` — `Loads` at once after a quiet pass for a load in flight, and `Render`, `Loads` or `Layout`, read off the last pass, when none of 64 passes (`SETTLE_PASS_LIMIT`) is quiet; it reads no clock but the harness's, advances no time, waits on no load and neither reads nor drains the changed set. `escher_driver::Session::act(step)` runs a step on a held instance and settles it — since 2026-10-20-load-wait waiting for a load in flight up to `LOAD_WAIT` (5 s of wall time, settled again every 10 ms, no time moving), one still loading at the bound `NotSettled(Loads)` — and `Session::run(&Call)` runs a driver call — validated first, each acting verb one settled step returning the diff of the snapshots before and after. No input helper settles.
- `dispatch_recorded` drives the underlying `BaseDocument` and bypasses Dioxus VirtualDom forwarding — use input helpers for Dioxus behaviour.
- Synthesized pointer events set page, screen and client coordinates equal; `key_event` uses `Code::Unidentified` and fills text only for pressed character keys.
- `HarnessOptions` defaults: 800×600, scale 1, light scheme, no `font_ctx` (system fonts) and no `incremental` override; harness documents always use `HtmlProvider`; `HarnessOptions::into_config(self, &VirtualClock)` puts a clone of the harness's clock in `DocumentConfig.clock`, so documents built by `from_html_with` and `from_vdom` (and through them `from_html` and `from_component`) read the harness's time, while `wrap(doc)` gives the harness a fresh `VirtualClock` and the wrapped document keeps the clock its own config gave it.
- The headless stand boots through `seven_guis::stand::{boot, boot_timer}` over `from_vdom` with `stand::options(incremental)` (bundled DejaVu Sans, system fonts off, offline); the timer advances only via its `TimerTicks` handle — `deliver(n)`, applied on the next pass (a `pump`, an input helper's own pump, or a settle); a driver session moves it by `advance`, through `stand::timer_step` handed over with `Session::with_time` (whole 100 ms ticks, the remainder below one tick carried across calls; `advance` first moves the session's clock — the harness's `VirtualClock` — by exactly `ms`, and `advanced_ms` reads exactly `ms`, ratified by the founder, 2026-10-18).
- `dom_string()` is a stable one-node-per-line serialization with geometry (`<div #box .a .b> @ (20,10) 100x50`) — the snapshot-style assertion surface. Since 2026-10-12-headless-screenshot `screenshot()` and `screenshot_rect(PixelRect)` return a `Raster` or a `ScreenshotError` (`FontsUnavailable`, `EmptyRect`): each resolves at the harness's own time (no tick, no pump), paints the viewport at its scale and device size into `VelloCpuImageRenderer` over opaque white, clips a rectangle to the viewport (an empty one `EmptyRect`), and refuses a document whose `can_paint_text` reads false with nothing painted. Since 2026-10-13-stand-contrast-harness `text_contrast(NodeId)` returns `Option<TextContrast>` (`text`, `background`, `ratio`, `font_size_px`, `font_weight`; `required_ratio` 3.0 for large text, else 4.5), reading and changing nothing (no mutation, input, pump or settle): the text-bearing element's computed `color`, font size and weight over the background composited source-over from its ancestors' `background-color`s onto the root-else-`body` canvas over opaque white, `None` with no text or where an element on the walk has `opacity` below 1, a filter or a background image; `contrast_ratio` is the WCAG 2.x ratio.
