# Security Rules

Universal security rules for escher. No `paths:` frontmatter — this file loads on every turn, so it stays lean.
Source: `.andromeda/security-plan.md` (security tier 0; application threat model NOT YET MEASURED).

## Secrets
- Secrets live only in GitHub Actions secrets/vars (macOS signing key, Android keystore + passwords, Apple certificate, `WPT_GITHUB_TOKEN`, `GITHUB_TOKEN`); signing material written to disk in CI is removed in an `always()` step — keep that pairing. The jobs that reach them (publish, WPT, post-results) run only in `DioxusLabs/blitz` — keep the `github.repository` guard; a ref-only `if:` re-arms them on the fork.
- On the dev host only, the cold-agent live run (`scripts/cold-agent.sh run`) authenticates with the operator's own Claude Code login, held by the `claude` CLI outside the repo (`apiKeySource` none; ratified by the founder, 2026-10-06) — no API key, no CI secret, and no copy in code, fixtures, events or committed evidence. The MCP surface's one live trial (2026-10-10-mcp-surface, `evidence/live-trial.py`) used the same login on the founder's word for that trial — no new secret source.
- Source reads no secret: env reads are `WPT_DIR`, `PAINT_TREE_BENCH_HTML`, `HOME`, `CARGO_MANIFEST_DIR`, `RUST_LOG` (escher-telemetry's filter) and `MULTI_DOC_N` · `MULTI_DOC_SEQ` · `MULTI_DOC_FLAT` (the root example `multi_doc` alone) only — and, at build time in the session checks, `CARGO_BIN_EXE_escher-session` and `CARGO_TARGET_TMPDIR` — plus `TMPDIR` through `std::env::temp_dir()` in escher-driver's unix-only client unit test (test code only, not secret). Never commit `.env*`.

## Untrusted input (remote content, scripts, CLI)
- Remote HTML/CSS/images/fonts/sub-documents are untrusted: keep the recursion caps (`MAX_SUBDOCUMENT_DEPTH = 10`, `MAX_IMPORT_DEPTH = 16`) and the stale-iframe-response discard by request id.
- `blitz-net` reads `file:` URLs from disk with no path restriction and has no response-size cap or request timeout — do not route agent- or user-supplied URLs through it without a decision recorded in the security plan.
- A boundary widening that arrived with the 2026-10-10 upstream merge, ratified by the founder (2026-10-10) as upstream's behaviour: an `@font-face` source with no format hint and no URL extension (a `data:` URL) is fetched and its format sniffed from its bytes, where it was skipped. Since 2026-10-14-quality-gates blitz-tests' `font_face_sniffed_source` covers it — offline, both layout modes: a hint-less `data:` source answered with a `wOF2` body registers, a body no sniff matches registers nothing. escher routes no agent- or user-supplied URL through this path — keep it so.
- The default `ScriptFetcher` accepts only `file:` and `data:`; same-origin/CORS checks are absent and every runtime event has `isTrusted = true`.
- HTML is parsed with scripting disabled; invalid CSS declarations are dropped, not errors — keep parse failures as typed `Result`s, never panics, on new input paths.
- The accessibility builder reads `aria-selected` · `aria-pressed` · `aria-checked` · `aria-invalid` from any document's markup (the toggle by role, ratified by the founder (2026-10-18): `aria-checked` on the five checkable roles alone — `CheckBox` · `Switch` · `RadioButton` · `MenuItemCheckBox` · `MenuItemRadio`, `role="switch"` now mapped to `Switch` — `aria-pressed` on every other role, a native checkbox or radio reading neither) — remote HTML included — by a closed-set match on the trimmed, lower-case value, with no log site and no panic path, and writes closed enums and booleans on the node, never the attribute's text. The readings exit two ways: the platform accessibility adapter (a third content class on that crossing, states — ratified by the founder, 2026-10-10; unmeasured at an assistive technology until a windowed check, that witness owned by a `.andromeda/residuals.md` line (target: next) on the founder's F1 «Пока нет, перенести (Рекомендую)» (2026-10-14), the headless half — the tree the shell hands the adapter — proven since 2026-10-14-stand-a11y-assertions) and the snapshot. Since the 2026-10-17 upstream sync the builder also reads, as upstream wrote them, `aria-labelledby` (its targets' text the computed `label`, outranking a `<label>` and an `aria-label`, inside the ratified name crossing), `aria-expanded` · `aria-disabled` · `aria-level` (closed values inside the states class; `aria-disabled` moves no snapshot reading) and `aria-describedby` · `aria-description` — descriptions, `aria-description` free page text, unbounded, a fourth content class on the adapter crossing only (the snapshot reads no description, so no driver or MCP carrier, field, log field or span holds it), a boundary widening by upstream merge ratified as upstream's behaviour by the founder (2026-10-17). Keep any other new attribute read to the closed shape: a closed set, no text carried out. `inert` is read by its presence on an element or an ancestor (ratified by the founder, 2026-10-18), remote pages included: an inert node is not focusable, takes no hit and leaves the accessibility tree and the snapshot — no value read, no text carried out, no print, log site, env read or panic path, and no carrier, verb, key name, field, log field or span added; HTML's focus fixup is not built, so a node that holds focus when it becomes inert keeps it until focus moves, its fix owned by a `.andromeda/residuals.md` line (target: next). Since 2026-10-13-range-input-interaction an `input type="range"` in every document — remote pages included — reads `min` · `max` · `step` · `value` through `parse_float` (a parse error, NaN or an infinity reading absent) into a current value kept finite, clamped to `[min, max]` and on its step grid; its arrows, `Home` · `End`, pointerdown and click act only with no `disabled` attribute; no print, log site, panic path or env read; the value leaves only as form submission's entry, the `input` event's value and the snapshot's `value`, with no carrier, verb, field, log field or span added — an engine change for every document and a boundary widening, ratified by the founder (2026-10-07, 2026-10-13). Since 2026-10-13-stand-keyboard-harness, in every document — remote pages included — a pressed `Enter` on the focused `button`, `summary`, `input` of type `submit` · `reset` · `button` or `a` with `href`, and a released Space on the focused `button`, `summary` or `input` of type `submit` · `reset` · `button` · `checkbox` · `radio`, dispatch a Click (the app's handlers, then `handle_click` — so form submission, link navigation and `summary` toggling) only when it is no disabled form control (a `disabled` attribute on a `summary` or an `a` gating neither key), and a click on a button focuses it; `disabled` is read by its presence — bare, `"false"` or `"true"` — on a form control alone (`button` · `input` · `select` · `textarea`, `ElementData::is_disabled`; ratified by the founder, 2026-10-18) for focusability, the pointer and click gates and the activation keys, so a `<div disabled tabindex=0>` takes focus and a disabled ancestor `div` does not stop the click walk; the gates are a closed element-name and type match and the presence check on a form control, with no print, log site, env read or panic path, and no carrier, verb, key name, field, log field or span added — an engine change for every document and a boundary widening, ratified by the founder (2026-10-13, 2026-10-14). Since 2026-10-20-select-by-id a `select` without `multiple` in every document — remote pages included — holds its choice as its options' `CHECKED` state; focused and not `ElementData::is_disabled`, `ArrowDown` · `ArrowUp` · `Home` · `End` move it and a `Key::Character` with no Ctrl, Alt or Meta is typeahead — a closed key match, the typed text kept in the private `select_typeahead` buffer for at most 1 s of the document's clock and never carried out; a click on a select focuses it; the choice leaves only as form submission's entries, the `input` and `change` events' value, the snapshot's `value` (the chosen option's value, no mask applying) and the options' accessibility nodes (an option's `selected` its chosen state, no `aria-selected` read) — inside the ratified name and control-value crossings, the driver's `type` on a select the same typeahead; no print, log site, env read or panic path in the rules module, and no carrier, verb, argument, key name, result field, cause, session error, exit, log field or span added — an engine change for every document and a boundary widening, ratified.

## Surfaces
- No served network API, port or auth exists. A new socket, port, IPC endpoint or credential path is an arch §Occupied Resources + security-plan amendment first.
- The one listener is registered (the founder's choice, 2026-10-07): the driver session's Unix-domain socket `session.sock` in a caller-named state directory (`0700`, socket `0600`, a group- or other-open directory refused) — owner-only by file mode, no other authentication. Its wire (`v3`, `v2` until 2026-10-19-session-recording) carries `hello`, `stop` and, since 2026-10-10-driver-cli, `call`: a call brings an element id and typed text in, and its answer takes ids, accessible names, control values (a password's or a file input's as the fixed mask), the snapshot's text and the diff out — a second widening, ratified by the founder (2026-10-10) — and, since 2026-10-12-headless-screenshot, the screen's pixels: an accepted `screenshot`'s PNG as base64 inside its JSON line, the whole screen or one element's visible part, a password input in it painted masked, under the unchanged answer bound (the in-band image the founder chose, 2026-10-12); inside the text and the diff three state readings (selected, pressed, invalid) and, since 2026-10-12-self-description, a changed node's `differs` cross as closed words and booleans — inside the ratified crossing, on his ruling of 2026-10-10, which set the rule: a new field of a closed value set inside an already ratified carrier is not a widening, while authored text, an open value set, a new carrier or a new exit still is; no `NodeId` crosses. The MCP surface was the next such crossing, ratified by the founder (2026-10-10): the `escher-session mcp` role (`escher_driver::serve_mcp`) carries the same content — and, since 2026-10-12-headless-screenshot, the screen as an MCP `image` block (a PNG, base64, a password input in it painted masked; the in-band image the founder chose, 2026-10-12), and, since 2026-10-12-self-description, `help`'s and the session errors' fixed table text, the program's own `'static` text inside the ratified carrier (ratified by the founder, 2026-10-12) — to the MCP client that spawned it, over its own stdin and stdout — no listener, port or socket, no authentication beyond holding its stdio — a request line at most 65,536 bytes (longer: read, dropped, `-32700`), the request `id` echoed only as an integer or a string of at most 128 bytes, a result at most 1,048,576 bytes (one that holds an image measured by its whole written form, a text-only one by its text), every protocol error a fixed code and message with no `data`, and a notification running nothing; `serde_json` reads its requests and writes nothing. Since 2026-10-19-session-recording a kept check carries call content at rest (ratified by the founder, 2026-10-19, F1 A · F2 B): under `--record <dir>` (`start`, the host role, the `mcp` role) or `Session::recording_into`, one `check-{n}.json` (`0600`, `create_new`, never replaced) per recorded session in a `0700` launcher-named directory (a group- or other-open one refused `record-dir-not-private`, status 3, nothing written or spawned) — per answered call its verb, arguments (the ids named, `press` keys, `advance` ms, text typed into unmasked controls; a masked or unresolved `type`'s text as `MASKED_STAND_IN`, never the text, its length or a digest of it), acceptance, an FNV-1a 64 digest of its answer and, since 2026-10-19-recorded-check-replay, the answer itself as `answer` — the line the driver wrote, masked as on every carrier (a password's or file input's value as `MASKED_VALUE`), a shot's as `{"width","height"}` with no `png` — so the screens' readings (ids, names, values, snapshot text, diffs) at rest, never a pixel (each answer kept whole, ratified by the founder, 2026-10-19, F3 B); never logged, no tool call, verb, argument or field names the directory; the one exception to a kept check's owner-only medium is the two committed stand-Counter checks `tests/blitz-tests/checks/counter-cli.json` and `counter-mcp.json` (git mode `100644`, written by `examples/seven_guis/tests/flows/record_checks.sh`; no typed text, host path, name or secret and no `screenshot` step), a boundary widening ratified by the founder (2026-10-19, F1 A) — a check of any other session stays owner-only and is never committed; a failed write or a passed bound (400 records, 1,048,576 bytes) ends the recording, its check removed; a kept check's bytes are untrusted, read by the strict `Check::from_bytes` (closed keys, `tool` one of the eight instance verbs, since 2026-10-19-recorded-check-replay `answer` required and a JSON object, else `malformed` holding nothing of the file, no panic path), each step still validated inside `Session::run`; `Check::replay` runs each kept step's call through `Session::run` alone, nothing on a session of another app, and stops at the first step whose acceptance or kept answer differs, its `Replay` and `Change` holding bools, counts and closed schema words only. The next surface that carries any of it is a new crossing question. A request line over 16,384 bytes or outside the grammar is refused and runs nothing; an answer is bounded at 1,048,576 bytes (`oversize` past it — the call ran and is not rolled back), and a call after which the host's recording ended is answered the fixed `ok v3 recording-failed` in place of its answer, the call having run. A host that has answered no request for its idle expiry (1,800 s) ends as on `stop`; every answered request — an `attach` or a `status` included — starts the count again.
- A driver call is checked by `escher_driver::validate` — a session-level one (`start` · `status` · `stop`) or the tool-level `help` by `validate_session` — before anything runs: a closed verb table of twelve verbs in three levels (`screenshot`, the seventh asked of the held instance, since 2026-10-12-headless-screenshot, and `lint`, the eighth, since 2026-10-19-visual-lint: no argument, one result field `findings`, running no step), seven argument kinds with bounds (`part`, the seventh since 2026-10-20-large-screen-in-parts, `snapshot`'s one optional argument, a whole number from 1 to 1000, `MAX_PART`), one fixed refusal order, no panic path on what a call supplies, and no `Session` in its signature — so a refused call changes nothing. A refusal is one of eight causes with fixed texts (ratified by the founder, 2026-10-18; `fonts-unavailable` since 2026-10-12-headless-screenshot) and holds nothing of the call; keep it that way (no id, name, value or call-supplied argument name in a `Refusal`, a `Fault`, a test name or an assertion message). The schema is executed by `escher_driver::Session::run`, which validates first, and since 2026-10-10-driver-cli it is reached from outside the process by three surfaces, each through `validate` before anything is sent or run: the socket's `call` request, which a host runs through `Session::run` and nothing else, since 2026-10-10-mcp-surface an MCP `tools/call`, whose arguments of the wrong JSON kind are refused `malformed` before the server runs it through `Session::run` (session verbs through `validate_session`), and the `escher-session` command line (`escher_driver::command_line`) — a closed argv reader whose usage line, refusals and session errors write back nothing the caller typed, and whose stdout is the command's answer (ids, names, values and, since 2026-10-12-headless-screenshot, a shot's base64 PNG by the ratified crossing), never a log line; an acting driver command waits on a load in flight for at most `LOAD_WAIT` (5 s of wall time, re-settling every 10 ms, moving no time on the held instance, then `settled: false` with its busy class; since 2026-10-20-load-wait), and `snapshot`, `screenshot` and `lint` wait on none. After `validate` the executor refuses with nothing run and the instance unchanged — an id the screen does not read as `stale` or `not-found`, a `click` or a `type` on a target that cannot take it as `disabled`, `off-screen` or `covered`, in that order; a `screenshot` of an app with no font it can paint text with as `fonts-unavailable` before anything is painted, and a `lint` of one before anything is read, and one whose crop to the visible part of its element's bounds holds no pixel as `off-screen`, every refused shot leaving the instance unchanged. The session keeps a record of id text to tell `stale` from `not-found` (at most 4096 ids, none longer than `MAX_ID_BYTES`, session-lived, private): never a `NodeId` in it, never print, log or field it. Since 2026-10-19-visual-lint `Session::lint` also feeds it from its own snapshot; it takes no argument and returns `Finding`s holding ids, closed defect words and numbers only (no `NodeId`, page text, colour or control value) and crosses as the `lint` verb's answer (`Command::Lint` → `Outcome::Linted`, written `{"findings":[…]}`) on every ratified carrier — the socket's `call`, the command line, MCP and a kept check, kept whole — a ratified boundary widening, with no log site, print, span or field carrying a finding and `VERBS` holding twelve. An `Outcome` holds ids, names and values and, since 2026-10-12-headless-screenshot, a shot's PNG bytes (`Outcome::Shot`) and a lint's findings (`Outcome::Linted { findings }`: stable ids, closed defect words and numbers only) and a screen's part (`Outcome::Part { text, part, parts }`, the snapshot text's own lines, written `{"text":…,"part":n,"parts":m}`), prints them under `Debug` and is written as JSON by `to_json` alone — as a command's answer, or as an MCP tool result's text — never log or field one. The driver's log records are two spans: the command span of `Session::run` (`escher_driver` / `command`), eight fields of fixed schema words, bools and counts, of a refusal its cause's name only, and since 2026-10-10-mcp-surface the `tool_call` span of an MCP tool call, its parent, holding `tool` and `ending` only, both closed words (ratified by the founder, 2026-10-10) — add no field that holds what a call supplied or a screen reads — the screen text or its length, a part's number or the part count, a shot's image, its size or its dimensions, a lint's findings or their count included (a `screenshot`, a `lint` or a part read records `verb` and, refused, `cause`).
- The cold-agent pipe's crossings are registered (ratified by the founder, 2026-10-06): a spawned `claude` client, the driver's own MCP server as its tools (`mcp__escher`, stdio, no port — the stub deleted since 2026-10-15-cold-agent-test), and the model provider reached on the live run only — since 2026-10-15-cold-agent-test a second carriage of the stand's screen (ids, names, values in snapshot texts and diffs) to it, a boundary widening on the founder's «Один запуск, до $3 (Рекомендую)» (2026-10-15). The model's reply is untrusted input, the agent-written check (the founder's «JSON-проверка с повтором (Рекомендую)», 2026-10-15): only its last fenced json block, at most 65,536 bytes, a JSON array of at most 400 steps with closed keys and `tool` one of the twelve verbs, else `no-check` / `check-failed` and never replayed; a valid check is replayed on fresh `escher-session mcp` children, every step validated again by the server, 30 s per reply, each child killed and reaped; `check.json`, `server.log` and the transcript are never printed; each committed transcript is host-path-masked (`gate.py hygiene` P1).

## Dependencies
- The dependency audit is cargo-deny (`bash .github/scripts/ci-leg.sh audit`, config `deny.toml`): an advisory it fires on is fixed by a semver-compatible update, or ignored by ID with a written reason — never a blanket allow, never `unmaintained`/`unsound` set to none. Since 2026-10-14-quality-gates it checks advisories and licences over the whole workspace's graph (`--workspace --all-features`): paste (RUSTSEC-2024-0436) reaches it and is ignored by ID, its drop owned by a `.andromeda/residuals.md` line; zip 2.4.2's RUSTSEC-2026-0367 · RUSTSEC-2026-0368 · RUSTSEC-2026-0369 (fixed only in zip 9.0, reached only through `anyrender_serialize 0.8.0` ← `browser`, no fixed release reachable) are ignored by ID on the founder's «Игнор по ID (Рекомендую)» (2026-10-17), their drop owned by a `.andromeda/residuals.md` line; zvariant 5.15.0's RUSTSEC-2026-0370, zbus_names 4.3.4's RUSTSEC-2026-0371 and zvariant_derive 5.15.0's RUSTSEC-2026-0372 (unmaintained, folded into zbus 6.0.0, reached only through zbus 5.19 + atspi 0.29 under accesskit_unix 0.24.0 ← accesskit_xplat ← blitz-shell, no fix reachable) are ignored by ID on the operator's word under the playbook's External decay pattern (2026-10-17), dropped when accesskit_unix moves to zbus 6, owned by a `.andromeda/residuals.md` line; memmap2 (unsound) is kept out by the `unsound` default, a measured limit owned by a `.andromeda/residuals.md` line — still review new crates by hand.
- `deny.toml` also holds upstream's `[licenses]` table, which the audit leg runs on every push since 2026-10-14-quality-gates over the whole workspace's graph (`licenses ok`) — the fork gates on licences, decided by the founder (2026-10-14).
- `Cargo.lock` is committed; no git dependency is left in the root manifest (taffy, the one there was, a crates.io registry version since 2026-10-13-upstream-sync-polish-and-ship); builds pass `--locked` — keep both.
