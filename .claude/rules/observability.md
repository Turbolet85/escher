# Observability Rules

Path-scoped rules for telemetry, logging and timing code. Source: `.andromeda/obs-plan.md` (obs tier 0).

## Logging (as built)
- **escher binaries:** install `escher_telemetry::init(escher_telemetry::service_identity!())` at start (today the two binaries of seven_guis — `seven_guis_native`, before `launch`, and the session host `escher-session` (its command line, host role and, since 2026-10-10-mcp-surface, `mcp` role), first thing in `main` — both stamping `service.name=seven_guis`; an `Err` is `eprintln!`ed and the binary continues; the in-process headless stand `seven_guis::stand`, the driver library `escher-driver` — its session and its command schema — and their checks install none, save `stand_act_spans`'s two re-run children, which install the sink over an in-memory capture, and `stand_mcp_tools`, which installs a hand-written in-process recorder that prints nothing) — stderr only, never stdout; filter from `RUST_LOG`, default `warn`; one line per printed event, `{RFC 3339 UTC} {LEVEL} {target} service.name=… service.version=… {field}={value}…`, and — a boundary widening ratified by the founder, 2026-10-09 (obs-plan §6) — one per closed span of an admitted target, the same prefix then `span={name}`, the span's fields and the layer's `message` · `time.busy` · `time.idle`, nothing before the span closes; `log` records bridged into the same formatter. A second `init` is `AlreadyInstalled`; a foreign subscriber is `InitError::ForeignSubscriber`, never a panic.
- **Engine and upstream crates:** `tracing` 0.1 events compiled only with each crate's `tracing` cargo feature; every call site is `#[cfg(feature = "tracing")]` with a `#[cfg(not(feature = "tracing"))] let _ = …;` fallback — keep the gate (the engine features stay off in a package-alone build; a workspace-wide build turns blitz-dom's on).
- The `tracing` feature forwards down the crate chain (dioxus-native → dioxus-native-dom, blitz-shell, blitz-dom, blitz-html, blitz-net); `blitz` turns it on by default, `blitz-vibey-script` does not.
- Upstream subscribers: `tracing_subscriber::fmt::init()` (stdout) in the apps under `tracing`; `tracing_wasm` on wasm; the WPT runner uses the `log` facade with `env_logger`.
- JS console output goes to the `log` crate at debug level, target `js_console`, keeping stdout/stderr clean; embedders drain JS errors with `take_js_errors` (≤256 retained between drains).
- Panics: escher-telemetry's hook logs one ERROR at target `escher_telemetry::panic` (`panic.payload` redacted) and chains the previous hook.
- Two spans exist, both escher-driver's, built by hand with `tracing::info_span!` at INFO under the target `escher_driver`: the command span — every call handed to `escher_driver::Session::run` leaves one, name `command`, its eight fields (`verb` · `cause` · `settled` · `busy` · `passes` · `added` · `removed` · `changed`) each recorded only where it applies and holding a fixed word of the schema, a bool or a count — and, since 2026-10-10-mcp-surface (ratified by the founder, 2026-10-10), the `tool_call` span — one per MCP `tools/call` request, its two fields `tool` (the table's word) and `ending` (`accepted` · `refused` · `error`), the parent of the call's `command` span — the session verbs `start` · `status` · `stop` and, since 2026-10-12-self-description, `help`, answered by the server, leave a `tool_call` with no `command` child. Add no field to either that holds what a call supplied or a screen reads: never field a `Command`, `Call`, `ArgValue`, `Outcome`, `Refusal` or `Fault`, nor an argument by its schema name — they print an id, typed text, an accessible name or a control's value, and of the argument names only `text` is scrubbed. The crate installs no subscriber. No `#[instrument]`, metrics or OTel exist (observed absent), and the settle loop `Harness::settle`, the driver's load wait over it (`settle_waiting`, bounded by `LOAD_WAIT`, run inside the call's `command` span, its eight fields as they are), `Session::act` and, since 2026-10-12-headless-screenshot, `Harness::screenshot` / `screenshot_rect` and the driver's private `image` encoder and, since 2026-10-13-stand-contrast-harness, the harness's contrast reader `Harness::text_contrast` (which reads and changes nothing in the document) carry no span of their own, nor does the recording (`Session::recording_into`, `Session::recording_failed`, the recorder, `Check::from_bytes`, the replay `Check::replay` — each replayed step writing its own `command` span through `Session::run`, the replay adding none —, the wire's `recording-failed` reply), nor `Session::lint` itself, which the `lint` verb reaches inside its call's `command` span, opening none of its own, with blitz-dom's read-only `BaseDocument::text_extent`, and dioxus-native-dom's `Snapshot::text_parts`, the part read's cut, which open no span, emit no event and record no field, escher-driver keeping its 2 `info_span!` sites — and nothing logs, fields or prints a lint `Finding` or `Reason`, which derive `Debug` and hold stable ids; the command span keeps its eight fields a recording held or not, and an MCP call after which the recording ended is answered `isError` as `RecordingFailed`, its `tool_call` ending `error` with `tool` and `ending` alone; a `screenshot` or `lint` call's or a part read's (`Outcome::Part`) command span records `verb` (and `cause` when refused) alone — never a shot's image, its byte size or its `width` / `height`, nor a lint's findings or their count, nor a part's number or the part count. `docs/capabilities.md` restates both spans and the scrub's limits, and its pin `.github/scripts/test_capability_statement.py` reads none of these claims — a change to the span set or to the scrub's limits is made in that document by hand.
- The agent-run test contract (`scripts/agent-run.sh`) writes JSON-line harness events to stdout and `target/agent-run/events.jsonl` — harness metadata, not a telemetry sink and not escher's line format; its rules live in `.claude/rules/verification-harness.md`.
- The cold-agent pipe (`scripts/cold-agent.sh`) writes JSON-line run events (`run.start`, `run.end`, `status`, `cleanup`) to stdout, `run.start` and `run.end` also appended to `target/cold-agent/events.jsonl` — counts, booleans and closed words only, never transcript text, a tool argument, a tool answer, a reply or the agent's check; its raw session transcript stays in `target/cold-agent/transcript.jsonl`, the agent's check in `check.json` and the live session's kept checks in the owner-only `target/cold-agent/record/` (`mkdir -m 700`), none printed or copied; since 2026-10-15-cold-agent-test its one MCP server is `escher-session mcp --record <abs target/cold-agent/record>` spawned with `RUST_LOG=info` on that child only, so escher's sink writes its closed `tool_call` / `command` span lines to `target/cold-agent/server.log`, which the pipe reads only to count ` span="tool_call" ` lines, their ` ending="refused" ` / ` ending="error" ` and the accepted lines of each counted verb (`lint` · `screenshot` · `advance`, `span_counts`), never printing or copying it; a judged check is replayed on two further `escher-session mcp` children without `--record`, stderr to `/dev/null` (test-plan §3).

## Timing
- Phase timing is opt-in: `log-phase-times` (→ `debug_timer/enable`) and `log-frame-times`; `debug_timer` swaps in a zero-cost dummy when `enable` is off and prints to stdout when on.

## PII
- escher's sink applies an allowlist of targets in the formatter (obs-plan §8): engine targets (`blitz*`, `dioxus_native*`, `stylo_taffy`, `accesskit_xplat`, `debug_timer`, `js_console`) print only `node_id` · `status` · `waiting_nodes` · `property` · `log.module_path` · `log.file` · `log.line`; escher's own targets (`escher_*`) print every field except `url` · `href` · `src` · `html` · `text` · `value` · `attrs` · `path` · `request` · `error` · `panic.payload`, which are redacted; a record from any other target (Stylo's `style::*`, `selectors::matching`, `dioxus_core::*`; on the windowed stand also `naga::*`, `wgpu_*`, `winit_wayland::*`) is dropped whole, at every level and whatever `RUST_LOG` names — a third-party WARN or ERROR included. A closed span's every pair — its name under `span`, its fields, the layer's close fields — is judged by the same rule as an event's field, and an outside target's span writes nothing. A sink-installing binary's stderr holds no id and no name at any level (measured on `escher-session` and on the windowed stand, before and after the drop; typed text measured on the `escher-session` host while it runs calls — 0 occurrences of a typed sentinel at `trace`, under both builds, with one command-span line per hosted call — and, since 2026-10-14-quality-gates, on the windowed stand, where no command runs, built with the workspace and on the host's display — 0 needles at every level; a shot's image, since 2026-10-12-headless-screenshot, measured on the `escher-session` host and its `mcp` role — 0 occurrences of its first 64 base64 characters at `trace`, under both builds; a lint's `command` line holds no finding, id, bound or count — `host_log` and `mcp_log` each drive one `lint` at `trace` with 0 needles; a part read's `command` line, `verb="snapshot"`, holds no part number, count, size or text — `host_log` and `mcp_log` each drive one part read at `trace` with 0 needles); what `escher-session` prints on stdout is a command's answer — ids, names, values and state readings by the ratified crossing, and since 2026-10-12-headless-screenshot a shot's PNG as a command's answer — never a log line, and none of it goes into a log field; a recording's kept check (`check-{n}.json`, `0600`) holds each answered call's arguments — unmasked typed text included —, its `accepted`, its answer's FNV-1a 64 digest and the answer itself as `answer` (a shot's without `png`) at rest, written through the crate's `json` writer, never a log line, field or print (`host_log` and `mcp_log` read 0 of the recording needles at `trace`, the span counts unchanged) — and a "nothing in the logs" check must still run against a host that installs the sink (seven_guis' `host_log` does), since a zero from one that does not proves nothing. A new field carrying user content takes a name in the content set — or is not logged.
- The upstream apps' `fmt::init()` and the WPT runner's `env_logger` still log URLs, attribute values, text-node contents and outer HTML as-is.
